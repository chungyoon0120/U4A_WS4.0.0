# cdp-auto-test — 화면 전환 반복 시험 도구

이미 **켜져 있고 로그인까지 끝난** U4A Workspace 에 붙어서,
앱 검색 화면(WS10) ↔ 디자인 화면(WS20) 을 **0.1초마다 계속 오가게** 만들고
그 사이에 앱이 뱉는 오류를 지켜본다.

오류가 하나라도 나오면 **그 자리서 멈추고** 증거를 챙긴 뒤
**텔레그램과 노션으로 알린다.**

> 이 문서는 **만드는 쪽(개발)** 용이다.
> 받아서 쓰기만 하실 분은 `dist/HOWTO.md` 를 보시면 된다(dist 를 말 때 자동으로 만들어진다).

---

## 1. 준비

**받을 꾸러미가 없다.** 노드만 있으면 그대로 돈다.

창에 붙을 때 쓰는 소켓은 두 갈래를 다 받아들인다([lib/cdp-client.js](lib/cdp-client.js)):

| 순서 | 무엇 | 언제 |
|---|---|---|
| ① | `ws` 꾸러미 | 깔려 있으면 이것을 쓴다 — 노드가 낮은 PC 도 돈다 |
| ② | 노드에 들어 있는 것 | `ws` 가 없을 때. 노드 v22 이상이어야 있다 |
| ③ | 둘 다 없으면 | **시작하자마자 그 이유만 말하고 끝낸다.** 창을 찾으러 가지 않는다 |

> ★ 2026-09-09 에 `ws` 를 아예 걷어냈다가, 노드가 낮은 다른 PC 에서
> 시작하자마자 죽는 일이 있었다(2026-09-10 실측). 그래서 둘 다 받아들이도록 되돌렸다.

---

## 2. 앱 쪽 준비

1. 앱을 **원격 디버그 포트를 켠 채로** 실행 (기본 9222, 다르면 `--port`)
2. 로그인까지 마치고 **앱 검색 화면(WS10)** 에 둔다
3. 편집 진입은 **개발자 계정**일 때만 단축키가 먹는다. 편집할 앱을 미리 골라 두고 뜬 팝업은 닫아 둔다

**핀(항상 위 고정)을 걸어 둔 창은 시험에서 뺀다** — 장군님이 보고 계신 창이라 건드리지 않는다.

---

## 3. 돌리기

```bash
node probe.js              # 붙는지 먼저 확인
node edit-back-loop.js     # 반복 시험 시작
node edit-back-loop.js --help
```

실행 시점에 떠 있는 **앱 검색 화면인 창을 전부 찾아 창마다 동시에** 돌린다
(개수를 미리 정하지 않는다). 실행 뒤에 새로 뜨는 창은 안 들어간다.

기록은 화면과 `logs/run_<PC이름>_날짜_시각.log` 에 같이 남고, 창마다 `[win1]` 처럼 번호를 붙인다.

**어느 PC 에서 돌린 것인지 다음 네 곳에 다 남는다**(장군님 지시 2026-09-10) —
여러 PC 에서 동시에 돌리므로 기록만 보고 확인하러 갈 자리를 찾을 수 있어야 한다.

| 어디 | 어떻게 |
|---|---|
| 로그 파일 이름 | `run_YOON_20260911_105618.log` |
| 로그 첫 줄 | `host=YOON user=socce node=v24.13.0 os=Windows_NT 10.0.26200` |
| 사고 보고서 `SUMMARY.md` | `- **host** : YOON (user socce)` |
| telegram · notion | 메시지 윗줄 `host : YOON (user socce)` / notion DB `PC` 칸 |

PC 이름은 `process.env.COMPUTERNAME` 을 먼저 보고, 없으면 `os.hostname()` 을 쓴다
([lib/machine.js](lib/machine.js)). `process.COMPUTERNAME` 은 없는 값이다.

### 자주 쓰는 값

| 값 | 뜻 | 기본 |
|---|---|---|
| `--intervalMs` | 키 누르는 간격 | 100 (0.1초) |
| `--cdpTimeoutMs` | 창에 물어보고 기다리는 한계 | 300000 (5분) |
| `--busyStuckMs` | 처리중 표시가 안 꺼질 때 멈추는 한계 | 300000 (5분) |
| `--quietMissing` | 화면이 멀쩡한데 이 키가 몇 바퀴 연속 안 걸려 있으면 오류로 볼지 | 10 |
| `--keepGoing` | 첫 오류에서 안 멈추고 끝까지 | 꺼짐 |

> 시간이 아니라 **바퀴 수**로 센다 — 자동 돌리는 PC 사양이 제각각이라 시간으로 재면 답이 달라진다.

## 4. 오류가 났을 때

**첫 오류에서 멈춘다.** 0.1초마다 도는 시험이라 한 번 고장 나면 뒤따라오는 오류가
수천 줄씩 쌓여 정작 맨 처음 터진 곳이 파묻히기 때문이다.

`logs/incident_날짜_시각_종류/` 폴더가 생기고 그 안에 네 가지가 담긴다:

| 파일 | 무엇 |
|---|---|
| `SUMMARY.md` | **먼저 볼 것.** what · when · **host(어느 PC)** · window · cycle · page |
| `screenshot.png` | 그 순간 화면 모습 (못 찍었으면 `screenshot-failed.txt`) |
| `log-tail.log` | 터지기 직전 300줄 |
| `raw.json` | 오류 원문 — stack · 파일 · 줄번호 |

그다음 **노션에 먼저** 기록하고, 그 페이지 주소를 담아 **텔레그램으로** 보낸다.
노션이 실패해도 텔레그램은 보낸다.

### 무엇을 오류로 보나

| 종류 | 판정 |
|---|---|
| 앱이 뱉은 콘솔 오류·스크립트 오류 | 오류 |
| 창이 사라짐(화면 크래시) | 오류 |
| 처리중 표시가 5분간 안 꺼짐 | 오류 |
| 창에 물어봤는데 5분간 대답 없음 | 오류 |
| **단축키가 안 걸려 있음** | **화면이 바뀌는 중이면 오류 아님.** 앱이 스스로 알려주는 두 가지(처리중 표시·화면이동중 표시)를 보고 판단하고, 둘 다 꺼진 채로 10바퀴 연속이면 그때 오류 |
| 붙기 전에 이미 있던 오류 | 무시 |

## 5. 알림 설정

`env/config.json` (깃에 안 올라감). 본보기는 `env/config.sample.json`.

```bash

```

## 6. 남에게 넘기기

```bash
node make-dist.js              # dist 폴더 + zip 파일
node make-dist.js --noSecrets  # 토큰이 든 설정은 빼고
```

- `dist/` 에 필요한 것만 모으고, 같은 자리에 `cdp-auto-test_날짜_시각.zip` 도 만든다
- 받는 쪽 안내문 `HOWTO.md` 는 이때 자동으로 만들어진다
- 지난 시험 기록(`logs`)·백업(`_` 로 시작)·도구 자체 시험 파일은 안 담는다
- 받는 쪽은 `run/install.bat` 을 한 번 두 번 누르면 준비가 끝난다

> ★ **기본은 `env/config.json` 도 같이 담는다.** 그 안에 봇 토큰과 노션 토큰이 들어 있어,
> 받는 사람은 그 봇·그 노션에 그대로 접근할 수 있다. 아무에게나 주지 말 것.
