|---|---|
| **무엇이 문제인가** | 서버에서 예외가 나면 화면에 **「이 서버는 그 기능을 지원하지 않습니다 — U4A 팀에 문의」** 가 뜬다. 이 문구는 원래 **「부르려는 기능이 서버에 없다」** 는 뜻인데, **기능은 있고 그 안에서 터진 경우에도 같은 문구**가 뜬다 |
| **왜 그렇게 되나** | 그 서브루틴 안에 예외를 받는 `TRY`·`CATCH` 가 **0개**라, 예외가 그대로 바깥 공통 자리까지 올라간다. 거기 문구가 「기능 없음」용 하나뿐이다 |
| **처리 자체는 괜찮나** | 괜찮다. 처리중 표시가 풀리고, 통신 실패 기록이 남고, 오류창까지 정상으로 뜬다. **문구만** 어긋난다 |
| **제 생각** | **보고만.** 동작이 아니라 안내 문구 문제이고 고칠 자리가 SAP 쪽 ABAP 이다 |

### 43번 — 창 닫을 때 서버가 최대 약 120초 머무는 것 + 그 결과를 아무도 안 받는 것

| 항목 | 내용 |
|---|---|
| **무엇이 문제인가** | 편집 화면에서 앞 화면으로 나갈 때 서버가 버전 모으기·임시 앱 지우기를 한다. 그 안에 **기다리는 자리가 두 군데**(각각 최대 60초) 있어 **한 번에 최대 약 120초** 걸릴 수 있다 |
| **화면은 그동안 어떻게 되나** | 통신 제한이 600초라 끊기지는 않지만 **그동안 처리중 표시가 계속 켜져 있다**(조작 못 함) |
| **더 나쁜 것** | 그 작업이 **성공했는지 실패했는지 받는 자리가 없다.** 실패해도 화면에도 기록에도 **아무것도 안 남는다** |
| **제 생각** | **보고만.** 두 자리 다 SAP 쪽 ABAP 이다. 다만 **실제로 몇 초 걸리는지 한 번은 재 볼 가치가 있다** — 재는 것은 앱 쪽에서 가능하다(나가는 시각·돌아온 시각 기록) |

### 44번 — 창 닫기 경로가 고객 시스템의 `Z` class 3개에 매달려 있는 것

| 항목 | 내용 |
|---|---|
| **무엇이 문제인가** | 창 닫을 때 도는 코드가 **class·method 이름을 글자로 적어 부른다.** 그중 3곳의 대상이 **`Z` 로 시작하는, U4A 소유가 아닌 고객 시스템 쪽 class** 다 |
| **없으면 어떻게 되나** | 그 class 가 없거나 inactive 인 시스템에서는 **창 닫을 때마다 오류창**이 뜬다(43번의 그 어긋난 문구로) |
| **UHA 는 괜찮나** | 괜찮다. **3곳 다 있고 active 이고, method 이름·인자 이름까지 호출과 맞는 것**을 조회로 확인했다 |
| **제 생각** | **보고만.** 고객사에 설치할 때 그 class 가 있는지 보는 점검 항목으로 쓰는 것이 맞다고 본다 |
