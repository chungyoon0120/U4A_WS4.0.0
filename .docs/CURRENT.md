## 지금 일하는 방식 — 오류 목록 두 개를 다루는 법

**오류 목록은 두 곳에 있고, 구글 스프레드시트가 먼저다**(장군님 지시 2026-10-15).

| | 구글 스프레드시트 (1부) | 노션 (2부) |
|---|---|---|
| 어디 | 「U4A 4.0 테스트」 > 「테스트 목록」 탭 | 「U4A WS3.0 -> U4A WS4.0 검증」 밑 대분류별 「기능 목록」 15개 |
| 몇 건 | 18건(유형 `오류`·`동작`) + 개선사항 2건 | 69건(「확인 구분」 = `오류`) |
| 끝내면 | 문서의 상태를 `끝남` 으로 | 그 항목 페이지의 **「확인 구분」** 칸을 **`수정완료`** 로 |
| 연결 이름 | — | `ws4.0` (기본 연결은 `u4a` 이니 **반드시 `--as ws4.0`**) |

★**칸 이름도 값도 거기 적힌 글자 그대로 쓴다.** 내 말로 바꾸면 장군님이 두 문서를
머릿속으로 맞춰 봐야 한다(상태 칸에 「손 안 댐」이라고 지어냈다가 지적받았다).

### 노션·구글시트를 읽는 법 (그냥 하면 막힌다)

- **노션 DB 가 data source 2개 이상이면** `db`·`query` 가 막힌다
  → `NOTION_VERSION=2025-09-03` 을 앞에 붙이고, `raw GET /v1/databases/<id>` 로
  `data_sources` 를 얻어 `raw POST /v1/data_sources/<ds_id>/query` 로 읽는다.
  **도구는 고치지 않는다 — 환경변수만 준다.**
- **Git Bash 가 `/v1/...` 을 윈도우 경로로 바꿔 버린다** → `raw` 는 **PowerShell 로 `yoon-notion.cmd`**.
  본문은 `--body` 말고 **`--body-file`**.
- **구글 시트는 브라우저로 열면 표가 안 읽힌다** → `export?format=csv&gid=<gid>` 로 받는다.
  머리줄이 **3번째 줄**이라 python `csv` 로 읽고 `rows[2]` 를 머리줄로 본다.
- **시트 칸에 달린 링크는 CSV·xlsx·화면 긁기 어느 쪽으로도 안 나온다.**
  gid 목록은 `htmlview` 에서 `grep -o "gid=[0-9]*"`, 그다음 **gid 마다 CSV 를 받아
  첫머리의 「이미지 및 로그 - No. N」 을 읽어** 번호와 이어 붙였다.

| 5 | **이 프로그램은 AI 가 로그만 보고 운영·수정한다.** 로그 없는 신규 로직은 완료가 아니다. 로그 글은 전부 영어. 표준 = `.works/DEV_STANDARD_로그.md` |
| 6 | **서버에 다녀오는 일·저장은 시작 전에 busy 를 켠다.** 겹치면 깊이를 세어 0일 때만 끈다 |
| 6-1 | **busy 는 예외 없이 공통 busy 만 쓴다 — 모든 화면·영역·별창**(장군님 지시 2026-10-16). 메인 창 = `parent.setBusy`, 별창 = `<head>` 에 `theme/u4a-busy.js` 로드 후 `U4ABusy.show()/hide()`. 자체 스피너·`aria-busy`·z-index div **금지** — `showModal()` 팝업이 top layer 라 그 뒤로 숨는다. SSOT = `.analy/16` §2.10 |
| 7 | **`window.confirm` · `alert` · `prompt` 금지.** 공통 확인창만 쓴다. 공통이 없으면 fallback 을 만들지 말고 오류코드로 표면화 + 진행 중단 |
| 8 | 예측 못 한 오류는 **삼키지 말고 `접두-번호` 코드로 표면화.** 표준 = `.works/DEV_STANDARD_오류처리.md` |
| 9 | **지시 범위를 넘지 않는다.** "이 문장을 철회하라" 면 그 문장만 고친다. 같이 고쳐야 맞다고 보이면 **보고만 하고 지시를 기다린다** |
