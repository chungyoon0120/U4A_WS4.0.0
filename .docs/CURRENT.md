## 먼저 알아야 할 것 — 틀리면 일을 그르친다

| # | 사실 |
|---|---|
| 1 | **정답은 원본(as-is) + `.analy` 문서.** 원본에 없는 UX·동작·옵션을 만들어 넣지 않는다. 이상하면 고치지 말고 보고만 한다 |
| 2 | **원본 소스는 다른 폴더에 있고 읽기 전용이다.** 위치는 `.analy/18_원본소스_위치_SSOT.md`. **작업 폴더 `www/` 는 원본이 아니다** — 이미 173개가 고쳐져 섞여 있다 |
| 3 | **작업 폴더 안은 사본 폴더까지 전부 고쳐도 된다.** 원본이 바뀌어도 통째로 옮기지 않는다. 목표는 소스 동기화가 아니라 **기능이 같으면 성공** |
| 4 | **남이 만든 라이브러리는 한 글자도 안 고친다.** 문제가 있으면 버전을 올린다. 폴더 이름만으로 판단하지 말고 파일 앞머리 저작권 표시를 본다 |
| 5 | **이 프로그램은 AI 가 로그만 보고 운영·수정한다.** 로그 없는 신규 로직은 완료가 아니다. 로그 글은 전부 영어. 표준 = `.works/DEV_STANDARD_로그.md` |
| 6 | **서버에 다녀오는 일·저장은 시작 전에 busy 를 켠다.** 겹치면 깊이를 세어 0일 때만 끈다 |
| 7 | **`window.confirm` · `alert` · `prompt` 금지.** 공통 확인창만 쓴다. 공통이 없으면 fallback 을 만들지 말고 오류코드로 표면화 + 진행 중단 |
| 8 | 예측 못 한 오류는 **삼키지 말고 `접두-번호` 코드로 표면화.** 표준 = `.works/DEV_STANDARD_오류처리.md` |

## 프로젝트가 무엇인가

SAP U4A Workspace 를 **UI5 → HTML5(순수 DOM + 공통 컴포넌트)** 로 1:1 이식하는 Electron 앱.
변환이 끝나면 **배포 후 운영(버그·오류·SR·신규 기능)을 AI 가 맡는다.**

## 일하는 순서

1. **`.docs/history/` 에서 건드릴 화면 이름으로 지난 이력을 찾아 읽는다** (전체를 다 읽지 말 것)
2. 그 영역의 `.works/<영역>/00_현황판.md` 에서 남은 테스트를 본다
3. 화면·UX 작업이면 `.analy/16_공통_화면UX_표준.md` + 해당 기능 문서를 읽는다
4. 고친다 — 로그를 같이 넣는다
5. `node --check` 로 문법을 본다
6. **이력을 남긴다.** 안 남기면 답변이 안 끝난다 (`.docs/README.md` 참고)
7. 이 문서에서 바뀐 것을 반영한다
