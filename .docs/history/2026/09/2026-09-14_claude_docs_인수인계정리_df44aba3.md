## 변경 이유

이 대화창이 길어져 다른 창으로 넘긴다. **새 창이 CURRENT.md 한 장만 읽고도 이어받을 수 있어야 한다.**
CURRENT.md 는 「영역 이름과 다음에 할 것만」 적는 규칙이라, 인수인계 상세는 각 영역 현황판 맨 위에 뒀다.

## 영향 범위

- 문서만. 실행 동작 변화 없음.
- 다음 대화창은 `.docs/CURRENT.md` → 해당 현황판 「이어받는 창에게」 순으로 읽으면 된다.

## 검증

- 세 문서를 고친 뒤 다시 읽어 확인.
- 도구 작업(Claude 설정 전역화)의 테스트가 실제로 다 통과했는지 그 현황판에서 확인 —
  **"작업·테스트 전부 통과, 남은 것은 정해 주실 것뿐"** 으로 적혀 있다(2026-09-14).

## 참고 사항 — 이어받는 창이 놓치기 쉬운 것

- **별창 busy 는 앱 실행 확인이 0 이다.** 코드가 다 들어갔다고 끝난 것이 아니다.
- **가장 위험한 변경은 창을 「숨겨서 만들었다가 보여주기」로 바꾼 것**이다. 프레임리스 창 드래그가
  깨질 수 있다고 소스 주석이 경고하던 자리다. 실패하면 그 변경만 되돌린다(되돌릴 파일 2곳을 현황판에 적어 뒀다).
- **백업 파일은 지우지 마라.** 장군님 지시가 있어야 한다.
- **커밋하지 마라.** 지시가 있을 때만 한다.
