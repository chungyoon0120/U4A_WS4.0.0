## 요청

장군님 지시 — 단축키 수정계획서의 **1번 항목부터 착수**.
1번 = A-1(Ctrl+F8 누르면 창이 닫힘) + A-2(Shift+F11 어플리케이션 복사가 아예 안 됨).
이 둘은 **따로 고치면 안 되고 반드시 같이** 고쳐야 한다(아래 "변경 이유" 참조).

## 변경 내용

### ① 전체화면 키(F11)가 보정키를 보게 함 — `electron/main.js`

`before-input-event` 의 F11 처리에 **보정키(Shift/Ctrl/Alt/Meta)가 하나도 안 눌린 경우만** 전체화면
토글하도록 조건 추가. 보정키가 붙은 F11 은 `event.preventDefault()` 하지 않고 그대로 통과시켜
화면(renderer)이 받게 한다. 통과시킬 때 `WsMainLog.writeLog('INFO', "GUARD_EXIT | F11 with modifier ...")`
로 어떤 보정키였는지 남긴다.

### ② `Ctrl+F8` 흡수용 등록 — `www/ws30/ws10_20/js/ws_common.js` (`fnSetCommonShortcut`)

아무 동작도 하지 않고 `e.stopImmediatePropagation()` 만 하는 항목을 **새 창(Ctrl+N)·창 닫기(Ctrl+W)
등록보다 앞줄**에 추가. 기존 `Ctrl+F4`(저장키) 막이와 동일한 방식.
`U4ALOG.warn("GUARD_EXIT", "Ctrl+F8", "absorbed: ...")` 로그 포함.

### ③ `Ctrl+Shift+F11` 흡수용 등록 — 같은 파일 (WS20 단축키 목록)

동일한 형태의 항목(`VISIBLE: false`)을 **`Ctrl+Shift+Z`(Undo) 항목 바로 앞**에 추가.
`U4ALOG.warn("GUARD_EXIT", "Ctrl+Shift+F11", "absorbed: ...")` 로그 포함.

## 변경 이유

**뿌리 원인**: 단축키 라이브러리(`www/js/shortcut.js`, 외부 라이브러리 — BSD, Binny V A)가
키 번호를 그대로 글자로 바꿔(`String.fromCharCode`, 46행) 비교한다(167행).
- F8 키 번호 119 → 글자 `'w'` → **`Ctrl+F8` 이 `Ctrl+W`(창 닫기)로 인식** → 작업 중이던 창이 닫힘
- F11 키 번호 122 → 글자 `'z'` → **`Ctrl+Shift+F11` 이 `Ctrl+Shift+Z`(Undo)로 인식**

**라이브러리는 남이 만든 것이라 한 글자도 고치지 않는다**(장군님 지시 2026-09-08).
그래서 앱 쪽에서 같은 조합을 "아무 동작 없는 흡수용"으로 **먼저** 등록해 이벤트를 삼킨다.
이 방식은 이 프로젝트에 이미 `Ctrl+F4`(저장키) 막이로 쓰이고 있어 새로 만든 패턴이 아니다.

**A-2(복사)를 왜 같이 고치나**: `electron/main.js` 가 보정키 상관없이 F11 을 전부 가로채고
`preventDefault()` 했기 때문에 `Shift+F11`(어플리케이션 복사)이 화면까지 도달하지 못했다
(화면 안내·버튼 설명글에는 Shift+F11 로 표기돼 있음).
**이걸 고치면 `Ctrl+Shift+F11` 도 화면까지 도달하게 되어 Undo 가 잘못 실행된다.**
그래서 ①과 ③은 반드시 한 묶음이다. 따로 넣으면 새 버그가 생긴다.

## 영향 범위

- **전 화면**: `Ctrl+F8` 이 앞으로 **아무 일도 하지 않는다**(그게 의도한 동작). 창 닫기 `Ctrl+W` 는 그대로.
- **편집 화면(WS20)**: `Ctrl+Shift+F11` 이 앞으로 **아무 일도 하지 않는다**. Undo(`Ctrl+Shift+Z`) 는 그대로.
- **앱 본체**: 보정키 없는 F11 전체화면 토글은 종전과 동일. 보정키 붙은 F11 은 이제 화면으로 내려간다
  → `Shift+F11` 어플리케이션 복사가 동작하게 된다.
- 숫자패드 관련 오작동 3건(`Ctrl+숫자패드6` 찾기 / `Ctrl+Shift+숫자패드6` 텍스트 검색 / `Ctrl+숫자패드.` 새 창)은
  라이브러리가 숫자패드 이름을 몰라 **키 번호로 직접 잡아야 하므로 이번 범위에서 제외**(별도 지시 대기).

## 검증

**한 것**
- `node --check electron/main.js` → 통과
- `node --check www/ws30/ws10_20/js/ws_common.js` → 통과
- **고치기 전 전제 3가지를 소스로 확인**(안 맞으면 고쳐도 효과가 없는 방식이라 필수):
  1. 라이브러리가 F8=119 · F11=122 를 특수키 표에 갖고 있고(118·125·128행), 특수키는 **키 번호로 정확히 비교**한다(161행)
     → 흡수용 등록이 실제로 매칭된다
  2. `oAPP.common.setShortCut`(2588행)이 목록을 **배열 앞에서부터 순서대로** `add` 한다(2595~2601행)
     → Undo 앞에 넣은 항목이 먼저 등록된다
  3. Undo 가 실제로 `Ctrl+Shift+Z` 로 등록돼 있다 → F11→`'z'` 오인식과 일치
- `fnSetCommonShortcut` 안에서 흡수용이 새 창·창 닫기 등록보다 **앞줄**임을 눈으로 확인

**안 한 것 (미검증)**
- **실제 키 입력 테스트를 못 했다.** 키보드 조작이라 자동 검증 수단이 없다.
  → 장군님 수동 테스트 대기. 항목은 `.works/단축키생명주기/00_현황판.md` 맨 위 「0. 지금 테스트할 것」
  (SC1 · SC1-1 · SC1-2 · SC2 · SC2-1 · SC16 · SC3) — **전부 미테스트(☐) 상태**
- 앱 재시작이 필요하다(코드 반영 = 앱 재시작).
