# 데이터 모니터 — tree view 보완 · 용어 정리 · circular 판정 수정

## 요청

1. tree view 에서 값 변경이 반영 안 됨 → 고쳐라
2. snapshot 을 매번 통째로 받지 말고 **처음 한 번만 받고 그 뒤엔 바뀐 값만 반영**해라
3. tree view 이름 cell 아무 데나 눌러도 접었다 폈다 되게 해라
4. `생김` 인데 무엇이 생겼는지 안 보인다 → 값 보여라
5. tree 는 접으면 하위도 같이 접혀야 한다(공통 표준)
6. `oAPP.attr.prev` 안 UI object 는 **우리가 만든 필드만** 봐라. `oAPP.attr.ui` 도 같이
7. `없어짐` 은 두 view 모두 화면에 띄우지 마라
8. 리스트 뷰 column 폭 넓혀라 (`전..` 으로 잘림)
9. tree view search 는 **이름만**, 걸린 node 아래는 전부 보여라
10. tree cell 에 mouse over tooltip 안 뜬다
11. **IT 용어는 영어 그대로 써라. 한글 번역 금지** (반복 지적)

## 변경 내용

### tree view

- **값 변경 미반영 수정** — batch 가 와도 tree 를 다시 그리지 않았음. batch 수신 시 tree 갱신.
- **snapshot 은 처음 한 번만** — 부모가 각 change 에 `조각`(path 조각 배열) + `실값`(줄이지 않은 real value)을
  같이 실어 보내고, popup 이 보유 중인 snapshot 에 그 자리만 덮어쓴다.
  통째로 다시 받는 경우는 둘뿐 — change 목록이 잘렸을 때(500건 초과) / 값을 창끼리 못 넘겼을 때.
- **이름 cell 전체 클릭으로 toggle** — cell box 높이가 글자 높이(20px)뿐이라 row(40px) 위아래 여백이
  cell 밖이었다. `align-self: stretch` 로 row 높이만큼 늘림.
- **접으면 하위도 접힘** — 공통 tree 는 expand map 을 화면이 소유하면 descendant collapse 를 화면에 위임한다
  (u4a-ui.js 의 virtual toggle 주석). 화면 쪽에 `_setExpand()` 추가.
- **`생김` 값 표시** — 자식이 있는 node 라도 이번에 바뀐 것이면 `현재 값` 에 내용을 적는다.
- **종류 filter 세분화** — `바뀐 것만` 하나였던 것을 `전체 데이터 / 바뀐 것만 / 바뀜 / 생김` 으로.
  `전체` 가 list view 의 `전체` 와 뜻이 달라 `전체 데이터` 로 이름 구분.
- **search = 이름만** — 값 검색 제거. 이름이 걸린 node 는 **하위 전체가 딸려 나오고 전부 펼쳐진다.**
- **cell tooltip** — 공통 tooltip 은 `.u4a-table` cell 만 자동으로 잡는다. tree cell 에 `data-tip` 배선 추가.

### 감시 범위

- **UI5 control 은 우리가 만든 field 만** — `_T_0015` `_MODEL` `_BIND_AGGR` `_OBJID` `__PARENT`
  `_EMBED_AGGR` `__UIFND`. 판별 = `getMetadata` + own `mProperties` + own `mAggregations`.
  model 은 이 조건에 안 걸려 `oData` 안은 그대로 다 본다(실측 확인).
  `prev` 뿐 아니라 `ui` 등 **어디에 있든** 적용된다.
- **circular 판정 수정** — 전에는 "이번 snapshot 에서 한 번이라도 지나온 object" 를 전부 끊어서,
  같은 object 가 다른 path 에도 있으면(`oAPP.attr.oServerInfo` = `oAPP.attr.metadata.SERVERINFO`)
  나중 것이 통째로 가려졌다. **자기 조상 chain 에 자기가 또 나올 때만** 끊도록 변경.

### 없어짐

- 두 view 모두 화면에 **안 띄운다.** list view 종류 filter 에서도 뺐다.
- 단 **snapshot 에는 그대로 반영**한다 — 안 빼면 tree 가 지워진 값을 계속 들고 있어 어긋난다.

## 변경 이유

이 도구의 목적은 **내부 데이터 무결성 감시**다. 화면 출력·조작·핸들링 대부분이 내부 데이터를 읽어 돌아가므로,
그 데이터가 화면과 어긋나면 그걸 참고하는 모든 곳이 같이 틀어진다.
서버 저장 누락은 그 결과 중 하나일 뿐 목적이 아니다.

## 영향 범위

데이터 모니터 창 안에서만. 공통 자산(`u4a-ui.js` · `shell.css`)은 **안 건드렸다** — 필요한 건 화면 쪽에서 덮었다.
앱 데이터도 안 건드린다(snapshot 은 복사본).

## 참고 사항

### 폐기한 안 (다음 agent 가 반복하지 말 것)

세션 중 전략을 3번 냈고 **3번 다 사용자가 반례를 대서 폐기**했다. 전부 검증 없이 낸 안이었다.

**규칙은 IT 용어에 적용되는 것이지, 코드 안 변수 경로를 화면에 노출하라는 뜻이 아니다.**

# 이어서 (18:10) — tree 접기가 자손까지 안 먹던 문제 · 용어 정리

## 요청

1. tree 에서 접었다 펴면 **자손이 통째로 다시 펼쳐진다** — 공통 표준(접으면 하위도 접힘)이 안 먹는다
2. 용어를 시스템에 맞게 — `바뀜` → **변경**, `생김` → **추가**

## 변경 내용

### ① 접기가 자손까지 안 먹던 원인 = 두 개

**원인 A — 접힘을 "이미 적어 둔 자리"에만 썼다.**
펼침 상태를 화면이 들고 있고, 아직 한 번도 안 건드린 자리는 기본값으로 판단한다.
그런데 종류 filter 나 이름 찾기가 켜져 있으면 그 기본값이 **전부 펼침**이다.
접을 때 이미 적어 둔 자리에만 "접힘"을 쓰니, 안 적어 둔 자손은 다시 펴는 순간 기본값(펼침)으로 돌아왔다.

- **실측 재현**(수정 전, filter `생김` 상태): 37줄 → 뿌리 접기 → 뿌리 다시 펴기 → **37줄 그대로**(자손 펼쳐진 채)
- **고침**: 접은 자리를 따로 기록해 두고, 기본값을 정할 때 **위로 몇 단계만 거슬러 보며**
  "한 번이라도 접힌 윗자리가 있으면 저절로 펼치지 않는다" 로 판단.
- 처음엔 자손 전부에 "접힘"을 적는 방법으로 만들었다가 **되돌렸다** — 이 화면 데이터에서
  뿌리 하나가 **2만 자리를 넘어서**(실측: 상한 20,000 에 걸림) 한 번 누를 때마다 그만큼 쓰게 된다.
  느린 PC 에서 그대로 멎는다. 지금 방식은 깊이만큼(대개 10단계 이하)만 본다.

**원인 B — 줄 요소를 다시 쓰는데 클릭 처리기를 그릴 때마다 새로 붙였다.**
가상 스크롤은 줄 요소를 재사용한다(실측 확인: 다시 그려도 같은 요소).
그릴 때마다 이름 칸에 클릭 처리기를 붙이니 한 요소에 여러 개가 쌓여,
한 번 눌러도 접었다 폈다를 거듭해 **제자리로 돌아왔다**(눌러도 아무 일도 안 일어나는 것처럼 보임).

- **고침**: 처리기는 요소당 한 번만 붙이고, 지금 그 줄이 무엇인지는 요소에 적어 둔 값을 읽는다.
  자식 없는 줄로 재사용되면 적어 둔 값을 비워 엉뚱한 자리가 접히지 않게 한다.
- ★ 이건 **원래 있던 결함**이다. 앞선 검증에서 "이름 칸 클릭 정상"으로 통과했던 것은
  그때 쌓인 처리기 수가 홀수였던 것뿐이다 — **운이었다.**

**곁가지 — 화살표 클릭이 깊은 자리에서 반대로 먹던 것.**
공통 tree 는 화살표를 누를 때 depth 를 0 으로 넘긴다. 그 값을 그대로 믿으면 깊은 자리도
"펼쳐진 것"으로 판단해 화살표가 반대로 먹는다. 노드에 depth 를 직접 달아 그것을 본다.
(소스로 확인. 화면 실측은 못 했다 — 위 A·B 를 고치고 나니 재현 조건을 못 만들었다.)

### ② 용어

| 전 | 후 |
|---|---|
| `바뀜` | `변경` |
| `생김` | `추가` |
| `없어짐` | `삭제` |
| filter `바뀐 것만` | `변경분만` |
| `바뀐 것이 없습니다.` / `생긴 것이 없습니다.` | `변경된 것이 없습니다.` / `추가된 것이 없습니다.` |

`없어짐` → `삭제` 는 **지시에 없었지만 같이 바꿨다** — 같은 목록 안에서 셋만 말투가 달라지면
더 이상하고, 이 값은 화면에 안 띄우므로 위험이 없다. 되돌리길 원하시면 한 줄이다.

| `node --check` (두 파일) | 통과 |

**미검증:**
- **종류 filter 를 켠 상태**에서의 접기 — 확인하려는데 **팝업 창이 닫혀** 실측 못 함
- 화살표 클릭 depth 문제 — 소스로만 확인
- 바뀐 용어(`변경`/`추가`)가 화면에 제대로 나오는지 — 감시 engine 은 앱 시작 때 읽히므로 **앱 재시작 후** 확인 필요

## 참고 사항

- **"고쳤다"고 보고한 것이 운이었던 사례가 나왔다**(원인 B). 한 번 눌러 보고 통과로 적으면
  이렇게 된다. 다음부터 토글류는 **접기·펴기를 왕복시켜 처음 상태로 돌아오는지**까지 본다.

# 이어서 (18:35) — list view 의 path 를 누르면 tree view 의 그 자리로 점프

## 요청

list view `path` 칸을 누르면 tree view 에서 그 자리로 **스크롤까지 해서** 가게 해 달라.
걸러내기가 걸려 있으면 **풀고 점프**한다(장군님 결정).

## 변경 내용

- **path 칸을 누르면 tree view 로 넘어가 그 자리에 선다.** 손 모양 커서 + 마우스 올리면 밑줄로
  누를 수 있다는 것을 알린다. 글자를 끌어 블럭 잡는 것은 그대로 된다(끌어 놓고 뗀 것은 누른 것으로 안 침).
- **처리기는 표 본문에 하나만** 둔다(줄이 2000개까지 쌓이므로 줄마다 달지 않는다).
- **걸러내기(종류 고르기 · 이름 찾기)는 점프할 때 푼다.** 안 풀면 가려는 자리가 tree 에 아예 없어
  점프해도 아무 데도 못 선다.
- **가는 길(윗자리)을 전부 펼친 뒤** 공통 tree 의 "key 로 찾아 그 줄까지 스크롤" 기능을 부른다.
- **path 쪼개기** — 뿌리 이름 자체에 점이 들어가므로(`oAPP.attr`) 점으로 그냥 쪼개면 없는 자리가 나온다.
  뿌리는 **가진 데이터의 키와 대조**해서 자르고, 그 뒤를 `.이름` / `[번호]` 로 훑는다.
- **그 뒤에 지워진 자리**를 눌렀을 때는 아무 반응 없이 두지 않고 **남아 있는 가장 가까운 윗자리**에
  세운다(로그로 어디까지 갔는지 남긴다).
- tree view 를 열면 데이터를 다시 받아 오므로, **데이터가 도착한 뒤에 점프**가 돌게 예약해 두었다.
  이미 가진 데이터가 있으면 기다리지 않고 바로 간다(길이 끊겨도 동작하게).

# 이어서 (20:10) — 듣는 event 를 4개 → 30개로 (dropdown 값 변경을 통째로 놓치던 문제)

## 요청

WS20 속성 영역 dropdown 에서 값을 바꿨는데 **아무것도 수집되지 않았다.**
듣는 event 가 4개뿐이니 **전부 걸어라**(장군님 지시).

## 원인 (소스로 확인)

공통 dropdown 은 **목록 항목의 `mousedown` 에서 값을 확정**하고, 그 자리에서 목록을 없앤다
(`theme/u4a-ui.js` 의 값 고르기 배선). 그래서 **그 항목에서는 `click` 이 뜨지 않는다.**
감시 engine 은 `change / click / keyup / drop` 네 가지만 듣고 있었고 `mousedown` 이 없었다.
→ 값은 바뀌었는데 **비교가 예약조차 되지 않았다.** 다음에 다른 곳을 누를 때까지 안 잡힌다.

## 변경 내용

듣는 event 를 **30가지**로 넓혔다. UI5 가 거는 것과 같은 폭 + 우리에게 필요한 두 개.

| 묶음 | event |
|---|---|
| 누르기 | click, dblclick, contextmenu, auxclick, mousedown, mouseup, mouseover, mouseout |
| 글쇠 | keydown, keypress, keyup |
| 값 입력 | input, change, **compositionend**(한글처럼 조합해 넣는 글자의 마무리) |
| 자리 옮김 | focusin, focusout |
| 고르기 | select, selectstart |
| 끌어 놓기 | dragstart, dragenter, dragover, dragleave, dragend, drop |
| 잘라내기·붙여넣기 | cut, paste |
| 손가락 | touchstart, touchend, touchmove, touchcancel |

- 여전히 **bubble 단계**로 듣는다(앱이 먼저 처리한 뒤 우리가 본다).
- hover·drag 도중 event 도 그대로 걸었다. 비교는 **마지막 event 로부터 200ms 뒤에만** 돌기 때문에
  그 사이엔 예약이 미뤄질 뿐 여러 번 돌지 않는다(끌어 놓는 도중에 비교 안 하는 것은 의도한 것).
- **부작용 하나**: 마우스를 계속 움직이면 그동안 비교가 미뤄진다. 멈추면 바로 돈다.
  느리게 느껴지면 hover 두 개(mouseover · mouseout)만 빼면 된다.

### 곁들여 확인한 것

WS20 본화면은 **iframe 이 아니라 본문서**에 있다(본문서의 iframe 자리는 주석 처리됨;
iframe 은 미리보기·팝업·편집기에서만 쓴다). 그래서 본문서에 거는 것으로 속성 영역까지 잡힌다.
