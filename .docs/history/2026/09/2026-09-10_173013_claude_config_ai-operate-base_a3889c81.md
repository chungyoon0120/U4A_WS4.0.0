# AI 자동 운영 기반 만들기 — .docs 구조

## 요청

배포 후 운영(버그·오류·SR·신규 기능)을 AI 가 맡을 예정이다.
어떤 agent 가 와도 **이전 히스토리를 읽고 이어서 작업**할 수 있는 환경을 만들라는 지시.
지금은 그중 일부(기반 구조)를 만드는 단계.

## 변경 내용

1. `.docs/` 폴더를 만들고 이력 구조를 세웠다
2. codex 쪽에 답변끝 hook 을 걸어 두었다 (막기 되는지 확인용, 장군님 승인 대기)
3. 확인 시험 3건을 실제로 돌려 결과를 얻었다

### 확인한 것 (실측)

| 확인한 것 | 결과 |
|---|---|
| 세션 도중 스킬을 만들면 그 세션이 바로 아나 | **바로 안다.** 재시작 필요 없음 |
| Claude 답변끝 hook 이 턴 종료를 막을 수 있나 | **막는다.** hook 이 적은 지시문이 그대로 돌아옴 |
| 세션 도중 설정을 바꿔도 hook 이 먹히나 | **먹힌다** |
| codex 프로젝트 로컬 hook 이 그냥 도나 | **안 돈다.** hook 마다 지문을 떠서 승인해야 하고, 승인은 codex 화면에서만 된다 |
| 이 프로젝트가 codex 신뢰 목록에 있나 | **있다** |

## 변경 파일

- 추가:
  - `.docs/README.md` — 이력 작성 규칙
  - `.docs/CURRENT.md` — 지금 상태 (지금 할 것 · 진행 중 · 미해결 · 결정 사항 · 다음 작업 · 주요 위치)
  - `.docs/history/2026/09/` — 이력 폴더
  - `.codex/hooks/stop_block_check.py` — codex 답변끝 hook (막기 확인용, 1회만 막고 스스로 풀림)
- 변경:
  - `.codex/hooks.json` — 답변끝 hook 항목 추가 (백업 `_hooks.json.20260910.stop추가전.bak`)
- 삭제: 없음

## 변경 이유

지금은 이력이 여섯 군데로 흩어져 있고, 그중 **기억 파일 229개는 Claude 만 읽는다.**
codex·antigravity 가 오면 "왜 이렇게 돼 있나"를 전혀 모른다.

또 규칙이 `CLAUDE.md`(83줄)와 `AGENTS.md`(40줄)로 갈라져 있는데,
`AGENTS.md` 에는 원본 위치·busy·로그·대화상자 금지 같은 핵심이 **빠져 있다.**
다른 agent 를 붙이면 그 규칙들을 다 어긴다.

## 영향 범위

- 새로 만든 폴더뿐. **기존 파일은 하나도 지우거나 옮기지 않았다**
- `.works/` 46개 폴더, `.analy/` 22개는 그대로 두고 `.docs/CURRENT.md` 에서 **링크만** 걸었다
- 전역 설정(Claude·codex)은 **건드리지 않았다** — 프로젝트 안에만 넣었다

## 검증

- Claude 답변끝 hook 막기 — 시험용 hook 을 걸고 실제로 턴을 끝내 보았고, 막혔다.
  흔적 파일에 `FIRED` → `BLOCK_ISSUED` 두 줄이 찍혔다. 시험 후 설정·파일 전부 되돌렸다
- codex — 프로젝트 폴더에서 실제로 돌렸으나 내 hook 은 안 불렸고 흔적 파일도 안 생겼다.
  화면에 찍힌 `hook: Stop Failed` 는 **전역 hook** 이 실패한 것이었다(파일이 없어서)
- 스킬 즉시 인식 — 임시 스킬을 만들어 이 세션에서 바로 불러 확인했고, 확인 후 지웠다

## 참고 사항

### 아직 안 된 것

- codex 답변끝 hook 은 **장군님이 codex 를 화면으로 켜서 승인**해야 작동한다.
  승인 뒤 답변 맨 끝에 `CODEX_BLOCK_WORKED` 가 붙으면 성공이다.
  다시 시험하려면 `.codex/hooks/stop_block_check.marker` 를 지운다
- 이력 안 남기면 답변 못 끝내게 막는 **진짜 hook 은 아직 안 만들었다** (다음 작업)
- `AGENTS.md` 를 `CLAUDE.md` 수준으로 채우는 것도 아직이다

### 알아둘 것 (다음 agent 를 위해)

- 이력 파일 이름의 화면 이름은 **소스 폴더 이름과 같게** 쓴다. 나중에 이름으로 찾기 위한 것이다
- 화면별 요약 파일이나 목록 파일은 **일부러 안 만들었다.** 손으로 관리하면 뒤처지고,
  경로에서 화면 이름이 바로 나오므로 목록이 필요 없다. 이력이 쌓여 읽기가 무거워지면 그때 만든다
- codex 전역 hook 2개가 없는 파일을 가리켜 **매번 실패**하고 있다. 전역이라 손대지 않았다

# 이어서 (2026-09-10 17:40) — 이력 게이트 hook 완성 · CURRENT.md 를 AI 용으로 다시 씀

## 요청

1. 이력 안 남기면 답변 못 끝내게 하는 hook 을 만들라
2. `CURRENT.md` 는 사람이 아니라 **AI 가 읽는 문서**다
3. **이 프로그램 운영은 AI 가 한다** — 명심할 것

## 변경 내용

### 이력 게이트 hook

**무엇을 「고쳤다」로 보나** — 도구 종류와 무관하게 잡히는 방법을 골랐다.
`.docs/history` 안 **가장 최근 이력 파일의 시각**을 기준선으로 두고,
그보다 뒤에 손댄 파일이 있으면 "고쳤는데 안 남겼다" 로 본다.
Edit 로 고쳤든 Bash 로 고쳤든 상관없이 걸린다.

바뀐 파일은 `git status --porcelain --untracked-files=all` 로 얻는다.

**세지 않는 것**: `.docs` 자신 · `.git` · `node_modules` · `dist` · `logs` ·
`_` 로 시작하는 백업 파일 · `.log` `.marker` `.bak` `.zip` 같은 부산물

**안전장치 4겹** (세션이 갇히면 안 된다):
1. 이미 이어가는 중(`stop_hook_active`)이면 통과
2. 같은 대화에서 **3번** 막으면 그다음은 통과 (로그를 남기고)
3. 어떤 예외가 나도 통과 (fail-open) — 막는 쪽이 위험하다
4. 무슨 일이 있어도 흔적은 남긴다

**codex 도 같은 파일을 가리키게** 했다. hook 은 agent 를 가리지 않으므로 파일을 하나만 둔다.

### CURRENT.md 를 AI 용으로 다시 씀

사람 보고용 표현("장군님이 확인해 주실 것")을 걷어내고, **AI 가 일을 그르치지 않으려면
반드시 알아야 할 8가지**를 맨 위에 두었다 — 원본 우선 · 원본 위치 · 사본 수정 허용 ·
라이브러리 불가침 · 로그 · busy · 브라우저 대화상자 금지 · 오류 표면화.
「일하는 순서」 7단계도 넣었다.

| 3번 막으면 그다음은 통과하나 | 1회 block · 2회 block · 3회 block · **4회 통과** |
| 흔적이 남나 | 남음. 몇 번째 막았는지, 어느 이력 파일 기준인지까지 |

- 게이트는 **파일 시각**을 본다. 파일을 만들어만 두고 내용을 안 채우면 그대로 통과한다.
