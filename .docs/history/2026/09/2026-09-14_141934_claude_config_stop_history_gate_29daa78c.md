### 1. `.docs/README.md` — 이전 지시 철회

| 이전 | 지금 |

부가로 두 가지를 규칙에 추가했다.

  게이트가 그 줄로 이력 유무를 판정하므로, 안 덧붙이면 계속 막힌다.

### 2. `.claude/hooks/python/stop_history_gate.py` — 판정 기준 교체

| | 이전 | 지금 |
|---|---|---|
| 판정 근거 | `git status --porcelain` + `.docs/history` 최신 파일 mtime 기준선 | **session_id 앞 8자리**가 `.docs/history` 에 있는지 |
| 통과 조건 | 기준선보다 뒤에 손댄 파일이 0개 | 이 대화의 이력 파일이 있음 |
| 질문만 한 대화 | 통과 (이력 안 남겨도 됨) | **막음** (이력을 남겨야 끝남) |
| 외부 프로세스 | `git` subprocess 호출 | 없음 (파일 이름·앞부분 읽기만) |

찾는 방법 2단계:
1. 파일 이름에 8자리가 있으면 통과 (이름 규칙 `..._<session8>.md`)
2. 없으면 **최근 2개 월 폴더**의 `.md` **앞 4096 바이트**만 읽어 본문에서 찾는다

`git status` 기반 판정에 딸려 있던 코드는 전부 지웠다 — `changed_files()` ·
`newest_history_mtime()` · `skipped()` · 검사 제외 목록(`SKIP_DIR_PARTS` · `SKIP_SUFFIX`) ·
`subprocess` import.

안전장치는 그대로 두고 하나 늘렸다.

| | 조건 | 동작 |
|---|---|---|
| 1 | `stop_hook_active` 가 true | 통과 |
| 2 | **session_id 를 못 받음 (새로 추가)** | 통과 — 어느 이력이 이 대화 것인지 판정할 근거가 없다 |
| 3 | `.docs/history` 폴더 없음 | 통과 |
| 4 | 같은 대화에서 3번 막음 | 그다음부터 통과 |
| 5 | 어떤 예외든 | 통과 (fail-open) |

## 변경 이유

장군님 말씀 그대로 — **히스토리는 소스 diff 를 남기는 곳이 아니다.**
다음 agent 에게는 *무엇을 조사했고 무엇을 결정했는지* 가 소스 변경만큼 중요하다.
소스 기준으로 판정하면 "조사만 하고 결론 낸 대화" 가 통째로 사라진다.

곁들여 이전 방식의 실제 약점 하나도 없어졌다 — `git status` 기준이라
**커밋 안 한 옛 변경이 남은 상태**에서 그 파일의 mtime 만 갱신돼도 대상이 됐다.
즉 "이번 대화에서 고친 것" 이 아니라 "미커밋 변경 중 mtime 이 늦은 것" 을 보고 있었다.

## 영향 범위

- Claude Stop hook (`.claude/settings.json`) · Codex hook (`.codex/hooks.json`) 둘 다 같은 파일을
  물고 있어 **양쪽 다** 새 기준으로 돈다.
- 이제 **모든 대화가 이력 파일 1개를 요구한다.** 인사 한마디만 한 대화도 해당된다.
  (막히는 횟수 상한 3회는 그대로라 대화가 갇히지는 않는다)
- 기존 이력 파일 27개는 손대지 않았다. 파일 이름에 이미 session 8자리가 있어 그대로 인식된다.

hook 을 직접 실행해 6개 분기를 확인했다 (실측 2026-09-14 14:1x).

장군님 지시. 세션 시작 hook 이 안 도는 것이 확인됐으므로,
**실제로 매 턴 도는 자리**에 넣어야 다른 대화창에서도 돌아간다.

건수를 뺀 이유 — 이 게이트를 만들 때 이력에 이미 적혀 있던 우려가 그대로 일어났다:
> "손으로 관리하면 뒤처지고..."
나흘 만에 260 → 330 으로 70건 벌어져 있었다. **틀린 숫자보다 없는 편이 낫다.**

## 영향 범위

- **모든 대화창**에 매 턴 이 한 줄이 들어간다 (이 프로젝트 안에서만 — 전역 도구는 안 건드렸다)
- 세션 시작 hook 은 **그대로 두었다.** 옛 문구("단순 질의엔 이력 만들지 마라")도 그대로다 — 장군님 지시
- `CURRENT.md` 의 지난 내용은 백업에 남아 있다. 지운 것이 아니다

## 검증

- 매 턴 주입 hook 을 직접 실행해, 주입문에 `CURRENT.md` 가 **실제로 들어가는 것 확인** (실측)
- 세션 시작 hook 발동 기록 — 마지막 2026-09-10, **오늘 0건** (실측)
- `AGENTS.md` 줄 수 — **208줄** (미해결에 적혀 있던 "40줄뿐" 은 이미 해결된 것이라 뺐다)
- 현황판 44개 · 남은 테스트 ☐ 330건 · 통과 ✅ 101건 (실측 — 문서에는 안 적었다)

**미검증**: 새 대화창을 열었을 때 다른 agent 가 실제로 `CURRENT.md` 를 갱신하는지는
대화창을 새로 열어 봐야 안다.

## 참고 사항

- 「지금 하는 일」 표에 지금은 **한 줄**뿐이다(이 작업). 비어 보이는 것이 정상이다 —
  오늘부터 쌓기로 한 것이지 지난 것을 끌어모으기로 한 것이 아니다
- 세션 시작 hook 이 왜 안 도는지는 **아직 원인을 못 찾았다.** 전역·프로젝트 양쪽에 등록돼 있다
