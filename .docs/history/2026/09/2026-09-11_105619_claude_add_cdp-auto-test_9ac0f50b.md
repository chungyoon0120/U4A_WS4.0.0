# 자동 시험 오류 기록에 「상태」 칸 추가 + 처리 사이클 확정

## 요청
장군님: "노션에 컬럼 하나 만들어서 상태 확인 여부 하나 있으면 좋겠다. 오류가 발생해서 어딘가에서
노션에 업데이트 하면 여기서 해당 노션을 확인해서 원인 분석 후 조치 까지 하면 해당 내용을 지금처럼
본문 하단에 경계선을 만들어서 빨간색 굵은 글씨로 분석된 내용 및 조치 내용을 적어주는 일련의 사이클로
해서 상태를 관리하는 컬럼이 있었으면 좋겠어"

## 변경 내용
### 1) 노션 — 오류 기록 DB 에 `상태` 칸(select) 추가
개인 노션(`me`) "cdp 자동화 > WS10 <--> WS20 테스트 > 오류 기록" DB
(`3d6a2d4a-ab9f-81bf-8eea-c1820636a24c`) 에 select 속성 `상태` 신설. 값 5개:

| 값 | 색 | 뜻 |
|---|---|---|
| 미확인 | gray | 자동 시험이 남긴 직후. **도구가 새 줄에 넣는 기본값** |
| 분석중 | blue | 붙잡고 원인을 보는 중 |
| 조치완료 | green | 원인 밝혀 고치고 본문 하단에 적었음 |
| 원인미확정 | yellow | 고쳤으나 원인 확정 못 함 |
| 재발생 | red | 조치 후 또 남 |

기존 1건(2026-09-11 09:50 `PREV-ERR-00`)은 **원인미확정** 으로 설정.
실제로 src 미부착인지 로드 지연인지 확정하지 못했으므로 조치완료로 올리지 않았다.

### 2) 자동 시험 도구 배선 — 새 줄이 「미확인」 으로 생기게
- `test/cdp-auto-test/env/config.json`
  - `notion.properties.status = "상태"` 추가
  - `notion.statusNewValue = "미확인"` 추가 (값 이름을 코드에서 지어내지 않도록 설정으로 뺐다)
- `test/cdp-auto-test/lib/notify-notion.js` `buildProperties`
  - `oMap.status` 가 있으면 `{ select: { name: statusNewValue } }` 를 넣는다
  - 매핑이 없으면 `console.warn('[notion] WARN GUARD_EXIT - properties.status is not mapped, status column stays empty')`
    → 조용히 비어 있지 않게 했다

### 3) 사이클을 노션에 문서화
"cdp 자동화" 페이지(`3d6a2d4a-ab9f-8114-9c3b-cfd5d12ff9e5`) 본문 끝에
빈 줄 → 구분선 → 빈 줄 → **빨간 굵은 제목 「상태 관리 사이클」** 로 블록 26개 추가.
값 뜻 5개 · 돌아가는 순서 6단계 · 배선된 자리(config / notify-notion.js) 기재.
순서 4단계에 **"빈 줄 → 구분선 → 빈 줄 + 빨간색 굵은 제목 「확인 및 조치 내용」"** 을 규칙으로 못 박았다.

## 변경 파일
- 추가: 없음
- 변경: `test/cdp-auto-test/env/config.json` · `test/cdp-auto-test/lib/notify-notion.js`
- 삭제: 없음
- 노션(소스 아님): 오류 기록 DB 스키마 / 기존 1건 상태 / cdp 자동화 페이지 본문

## 변경 이유
오류가 자동으로 쌓이기만 하고 "어디까지 봤는지" 표시가 없었다. 상태 칸이 없으면
다음 사람/AI 가 이미 조치한 줄을 또 파거나, 안 본 줄을 놓친다.

## 영향 범위
- 자동 시험이 노션에 새 줄을 남길 때 `상태` 칸이 함께 채워진다. 다른 동작 변화 없음.
- 노션 select 에 없는 값을 보내면 노션이 400 을 주고, 그 사유는 기존 코드가
  `notion page create failed: <서버가 준 문장>` 으로 그대로 돌려준다(삼키지 않음).

## 검증
- `node --check test/cdp-auto-test/lib/notify-notion.js` → 통과
- `buildProperties` 를 실제 config 로 **dry run** → `상태 = {"select":{"name":"미확인"}}`,
  전체 칸 = 이름 / 종류 / 화면 / 바퀴 / 창 / 발생시각 / 상태 **확인됨**
  (노션에 쓰레기 행을 만들지 않으려고 `notify-test.js` 실제 전송은 **안 돌렸다**)
- DB 스키마 조회로 `상태` select 값 5개 등록 확인
- 기존 1건 `update` 후 응답으로 반영 확인
- cdp 자동화 페이지를 다시 `get` 해서 추가 내용 전체 확인
- **실제 오류 발생 시 새 줄이 「미확인」 으로 생기는지는 미검증** — 다음 자동 시험 회차에서 확인 필요

## 참고 사항
★ 작업 중 다른 세션이 같은 `notify-notion.js` 에 `pc` 칸(어느 PC 에서 났는지)을 추가했다.
  내가 넣은 status 블록과 충돌 없이 공존한다. 이 파일은 **편집 직전에 다시 읽을 것.**

★ `dist/lib/notify-notion.js` 는 `npm run dist` 로 만드는 배포 사본이다.
  **이번에 다시 만들지 않았다** — 배포본을 쓰는 경로가 있으면 `npm run dist` 를 한 번 돌려야
  상태 칸이 반영된다.

★ 값 이름(미확인/분석중/…)은 **노션 select 와 config 두 곳이 같아야** 한다. 한쪽만 바꾸면
  새 줄 만들기가 400 으로 실패한다(로그에 사유 남음).

★ 아직 안 한 것: 시간 못 박은 곳 전수조사(후보 164건까지 뽑고 중단),
  다른 세션의 일괄 치환 사고 2건(`레지스tree` · `디자인tree`) 수정 — 둘 다 장군님 지시 대기.
