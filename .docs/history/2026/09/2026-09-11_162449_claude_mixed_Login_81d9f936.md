## 요청

세션(81d9f936) 동안 장군님이 순서대로 요청한 것 (모두 로그인 화면):

1. 로그인 시 네트워크가 pending 상태로 멈추면 busy 스피너가 무한히 도는 문제 — 타임아웃 로직 추가.
2. 로그인 성공 후 이어지는 후속 XHR 요청들도 같은 문제 있는지 확인 후 전부 적용.
3. busy 팝업 안에 타임아웃까지 남은 시간(초) 카운트다운 표시.
4. (스크린샷 신고) 타임아웃 시 정상 안내창 아래에 원인불명 빈 네이티브 팝업이 겹쳐 뜨는 버그 수정.
5. busy 카운트다운 UX를 `ServerList_v2`(서버리스트) 종료 대기 팝업과 동일하게 통일.
6. 로그인 입력칸(CLIENT/ID/PASSWORD/LANGUAGE) 중 공통 value-state 메시지가 안 뜨는 부분 확인/수정.
7. (스크린샷 첨부) 로그인 실패 다이얼로그의 "점검사항" 버튼으로 열리는 별도 창(오류 확인 메뉴얼)을 프로젝트 공통 별창 UX(frameless + `.u4a-titlebar`)로 조정.
8. (스크린샷 첨부) busy 카운트다운에 "몇 초"만 있고 무엇을 기다리는지 안내문구가 없다는 지적 — 서버리스트처럼 "문구… (Ns)" 형태로 통일.
9. 로그인 시 메이저·패치 업데이트 체크를 임시로 건너뛰게 해 달라는 요청.

## 변경 이유

- 1~4: 실제 장애 재현(네트워크 pending) 시 busy 스피너가 무한히 도는 것을 장군님이 스크린샷으로 신고 — 로그인 관련 XHR/fetch 4곳 전수 점검해 타임아웃 배선.
- 3, 5, 8: busy 카운트다운은 장군님이 단계적으로 요구사항을 구체화(표시 → 지연 시작 → 서버리스트와 완전 동일 UX)한 결과. 8번은 "숫자만 있고 성의 없다"는 재지적 — 원인은 안내문구 누락이었고, 메시지 DB 조회로 근거 있는 키(656번)를 찾아 적용.
- 6: 공통 UX 표준(`.analy/16`, value-state 메시지)이 로그인 화면에서만 깨져 있던 걸 장군님이 직접 지적.
- 7: "점검사항" 별창이 프로젝트 공통 별창 UX(프레임리스+공통 헤더)와 다르게 네이티브 프레임으로 떠 있던 것을 통일 요청.
- 9: 장군님이 로그인 시 업데이트 체크를 임시로 막아 달라고 명시 요청(테스트/개발 편의 목적으로 추정 — 소스로 확인된 사유는 아님, 미확인).

## 참고 사항

- `SKIP_UPDATE_CHECK_TEMP` 는 이름 그대로 **임시 스위치**다. 운영 배포 전 반드시 `false` 로 되돌려야 한다(현재 코드에 그 사실을 알리는 자동 경고는 없음 — 배포 체크리스트에 수동으로 추가 필요).
- busy 카운트다운 안내문구(656번 "대기 중")는 서버리스트의 951번("종료 중")과 다른 상황이라 그대로 재사용하지 않고, 메시지 DB 를 조회해 범용 키를 새로 찾아 썼다. 로그인 상황에 더 맞는 전용 키가 나중에 추가된다면 656번 대신 교체 검토.
- 이번 세션 전체(위 9개 요청) 동안 `.docs` 이력이 한 번도 남지 않았던 것을 Stop hook 이 뒤늦게 지적해 이 파일을 한꺼번에 작성함 — **앞으로는 각 요청 단위로 끝날 때마다 바로 이력을 남길 것**(다음부터는 새 요청이 들어오면 이 파일에 이어쓰지 말고 새 파일로 분리).
