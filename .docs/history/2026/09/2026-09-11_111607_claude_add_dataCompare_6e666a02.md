# 3.0 ↔ 4.0 내부 데이터 비교 — 1단계 (8888 받기 + 좌우 JSON viewer)

## 요청

장군님 지시(2026-09-11, 5차에 걸쳐 나눠 받음).

- 두 프로그램이 각각 관리하는 **데이터 구조가 같은지 다른지만** 본다. 값이 같든 다르든 비교는 하되
  다른 자리는 **filter 로 골라 볼 수 있게** 한다.
- **3.0 소스는 고치지 않고 파일도 만들지 않는다.** 실행 중인 3.0 화면에서 감지 코드를 그 자리에 돌려
  수집한 뒤, **보내기 단추**를 만들어 HTTP 로 4.0 에 보내기만 한다.
- **4.0** 은 데이터 모니터 창을 열 때 **express 로 8888 을 열고**, 받은 것을 비교해 **화면에 보여주기만** 한다.
- 1단계는 **좌우로 나눠 JSON viewer 로 출력**까지. 나머지는 장군님이 화면을 직접 보고 정한다
  ("한번에 요구사항을 다 적어서 하는거보단 난 직접 하나씩 눈으로 보고 판단하고 싶다").

## 변경 내용

### `js/ws_html5_datamon.js` — 데이터 구조를 한 벌 돌려주는 문 하나 추가

- `oAPP.datamon.snapshot()` 추가. 안에서 이미 쓰던 snapshot 뜨는 함수를 그대로 부른다.
- 왜 필요한가: 3.0 에서 이 파일을 실행 중인 화면에 붙여 돌린 뒤, 그 결과를 4.0 의 8888 로 보내야 한다.
  비교하려는 것이 **구조**라서 달라진 것만이 아니라 **전체**가 필요하다. 감시를 켜지 않아도 부를 수 있다.
- 실패하면 `DMON-009` 로 드러내고 `null` 을 준다(보내는 쪽이 "빈 것"으로 착각하지 않게 로그를 남긴다).
- 그 외 로직은 한 줄도 안 건드렸다.

### `Popups/dataMonitor/Popup/index.html` — 비교 뷰 자리

- 뷰 전환 줄에 **비교 뷰** 단추 추가(리스트 뷰 / 트리 뷰 옆).
- 비교 뷰 전용 조작 묶음 추가 — **4.0 지금 담기** 단추, **다른 것만** 체크, 상태 글.
- 좌우 두 쪽 + 가운데 분할 바 추가. 분할 바는 공통(`U4AUI.wireSplitter`)이 맡는다.

### `Popups/dataMonitor/Popup/js/index.js` — 8888 열기 + 비교 그리기

- 창이 뜰 때 **express 로 127.0.0.1:8888** 을 연다. 창을 닫을 때 닫는다.
  - `GET /ping` = 살아 있는지 확인, `POST /snapshot` = 3.0 이 보낸 데이터 구조 받기.
  - 받는 한도를 크게 잡았다(데이터 구조 한 벌이 통째로 온다 — 실측 48만자).
  - 다른 프로그램이 보내므로 출처 제한을 열어 두었다(받기 전용).
- 3.0 것이 들어오면 **4.0 것도 그 자리에서 같이 담아** 나란히 놓는다.
- **어긋난 자리 찾기** — 두 구조를 함께 훑어 `다름` / `3.0만` / `4.0만` 로 표시하고,
  거기까지 가는 윗자리도 기억해 둔다(걸러 볼 때 길이 막히지 않게).
- **좌우 트리** — 공통 컬럼 트리를 좌우 각각 하나씩. 칸은 [이름] [값].
  - 펼침 상태는 **좌우가 같은 것**을 본다 — 같은 자리를 함께 펼쳐야 맞대 볼 수 있다.
  - 어긋난 줄은 색으로 구분(값 다름 / 한쪽에만 있음).
- **다른 것만** 을 켜면 어긋난 자리와 거기까지 가는 길만 남는다.

### `Popups/dataMonitor/Popup/css/index.css` — 비교 뷰 모양

- 좌우 두 쪽·머리줄·어긋난 줄 색. 색은 전부 의미 토큰만 썼다(하드코딩 없음, 고정 px 폭 없음).
- **원래 있던 결함 하나를 같이 고쳤다** — 아래 「참고 사항」 참조.

### `.works/데이터모니터/02_3.0에서_보내기.md` (신규)

3.0 에서 그 자리에 붙여 돌릴 코드 두 덩이(감지 코드 싣기 / 보내기 단추 만들기)와 하는 순서.

## 변경 이유

3.0 과 4.0 이 같은 조작에서 같은 내부 구조를 만드는지 눈으로 확인할 방법이 없었다.
두 앱은 서로 다른 process 라 지금 쓰는 창끼리 주고받는 길로는 못 잇는다 —
그래서 4.0 이 자리를 하나 열고 3.0 이 보내는 쪽이 된다(장군님 지정: 8888).

## 영향 범위

- **4.0 데이터 모니터 창 안에서만.** 리스트 뷰·트리 뷰 동작은 건드리지 않았다.
- 감지 파일에는 **읽기만 하는 문 하나**를 더했을 뿐, 감시 로직은 그대로다.
- 창이 떠 있는 동안 **8888 을 붙잡는다.** 창을 닫으면 놓는다.

## 검증

| 항목 | 결과 |
|---|---|
| `node --check` (감지 파일 · 별창 화면 파일) | 통과 |
| 화면에 적은 id 와 코드가 찾는 id 가 맞는지 (11개) | 전부 1:1 일치 |
| express 로 받는 방식이 실제로 도는지 (따로 띄워 보냄 → 받음) | **통과** (200, 뿌리 2개 인식) |
| 쓴 색 이름이 실제로 정의돼 있는지 | 확인함 (정의 안 된 이름 2개는 피해서 씀 — 아래 참고) |
| **실제 화면에서 비교 뷰가 뜨는지** | **미검증** — 앱을 다시 띄워야 확인된다 |
| **3.0 에서 감지 코드가 도는지 · 보내기가 닿는지** | **미검증** |

**CDP 실측은 하지 않았다**(장군님 지시 2026-09-10 — 지시가 있을 때만).

## 참고 사항

- **원래 있던 결함 하나를 같이 고쳤다** — 트리 뷰 전용 조작 줄이 `display:flex` 만 걸려 있어
  **숨김 표시가 안 먹었다**(브라우저 기본 숨김 규칙을 화면 규칙이 이겨 버린다). 리스트 뷰에서도
  트리 뷰 조작 줄이 그대로 보이고 있었을 것이다. 비교 뷰가 생기면서 세 뷰의 조작 줄이 한꺼번에
  보이게 되므로 같이 막았다. 같은 처리는 공통 자산에도 이미 두 곳 쓰여 있다.
- **보고만 하고 안 고친 것** — 이 창의 스타일 파일이 **정의돼 있지 않은 색 이름 두 개**를 쓰고 있다.
  그 자리는 색이 아예 안 먹는다. 내가 새로 쓴 부분은 정의된 이름만 골라 썼고, 기존 자리는 손대지 않았다.
  **장군님 판단이 필요하다.**
- 1단계에 **일부러 안 넣은 것** — 차이 강조 손질, 양쪽 스크롤 맞물리기, 3.0 것과 4.0 것 짝짓기 규칙,
  값 감추기. 장군님이 화면을 보고 정하신 뒤에 얹는다(장군님 지시 2026-09-11).
