# 3.0 ↔ 4.0 내부 데이터 비교 — 1단계 (8888 받기 + 좌우 JSON viewer)

## 요청

장군님 지시(2026-09-11, 5차에 걸쳐 나눠 받음).

- 두 프로그램이 각각 관리하는 **데이터 구조가 같은지 다른지만** 본다. 값이 같든 다르든 비교는 하되
  다른 자리는 **filter 로 골라 볼 수 있게** 한다.
- **3.0 소스는 고치지 않고 파일도 만들지 않는다.** 실행 중인 3.0 화면에서 감지 코드를 그 자리에 돌려
  수집한 뒤, **보내기 단추**를 만들어 HTTP 로 4.0 에 보내기만 한다.
- **4.0** 은 데이터 모니터 창을 열 때 **express 로 8888 을 열고**, 받은 것을 비교해 **화면에 보여주기만** 한다.
- 1단계는 **좌우로 나눠 JSON viewer 로 출력**까지. 나머지는 장군님이 화면을 직접 보고 정한다
  ("한번에 요구사항을 다 적어서 하는거보단 난 직접 하나씩 눈으로 보고 판단하고 싶다").

### `js/ws_html5_datamon.js` — 데이터 구조를 한 벌 돌려주는 문 하나 추가

- 왜 필요한가: 3.0 에서 이 파일을 실행 중인 화면에 붙여 돌린 뒤, 그 결과를 4.0 의 8888 로 보내야 한다.
  비교하려는 것이 **구조**라서 달라진 것만이 아니라 **전체**가 필요하다. 감시를 켜지 않아도 부를 수 있다.
- 실패하면 `DMON-009` 로 드러내고 `null` 을 준다(보내는 쪽이 "빈 것"으로 착각하지 않게 로그를 남긴다).

- 그래서 express 를 지우자 `qs` 도 같이 지워졌고, 앱이 뜨자마자 터졌다.

같은 방식으로 **적어 두지 않은 채 우연히 깔려 있던 것**이 또 있을 수 있다.
`npm` 으로 무언가를 지울 때마다 같은 일이 날 수 있다. 전수 점검은 지시가 있을 때 하겠다.

두 칸 폭의 합이 한쪽 자리보다 넓어서 옆으로 밀렸고, 가운데 안내 문구는
**밀려난 넓이의 한가운데**에 놓이는 바람에 보이는 자리 밖으로 나갔다.

이미 같은 일로 지적받고 기억해 둔 것이 있었는데(좁은 자리에서는 칸 폭을 다 못 박지 말 것),
**이번에 그대로 되풀이했다.**

## 어떻게 고쳤나

공통이 이미 주고 있는 **마지막 칸 채우기** 방식으로 바꿨다.

- [이름] 칸만 폭을 두고, [값] 칸은 **남는 자리를 채운다.**
- 이렇게 하면 폭이 자리에 맞춰져 **옆으로 안 밀리고**, 안내 문구도 제자리에 온다.
- 같은 화면의 다른 곳(소스 목록·MIME 목록)이 이미 쓰는 방식이라 새로 만든 것이 아니다.

# [이어서 · 2026-09-11] 비교 뷰에 트리 동작이 빠져 있던 것 + 오른쪽 칸 · 자리 번호

## 지적받은 것 (장군님, 같은 지적 2회)

1. **트리 뷰에서 이미 만든 동작을 비교 뷰에 안 넣었다.** 접으면 그 아래도 접히기 · 이름 칸 아무 데나 눌러 접었다 폈다 · 잘린 글자 보여주기 — 셋 다 빠져 있었다.
2. **"접으면 하위도 접힌다"는 공통 아니냐. 아니면 공통에 명확히 명시해라. 두 번 말하게 하지 마라.**
3. **오른쪽 칸이 여전히 잘려 보인다.**
4. 자리 번호를 **8888 → 9999** 로 바꿔라.

## 원인

### 1·2 — 왜 빠졌나 (소스로 확인)

공통 트리의 표준은 **"접기 = 자손까지 재귀 접힘"** 이 맞다(`.analy/16` §3.2).
그런데 **펼침 상태를 바깥에서 들고 있는 방식**으로 쓰면 공통이 그 처리를 쓰는 쪽에 넘긴다
(공통 소스의 가상 트리 토글 주석에 그렇게 적혀 있다 — 자손 접기는 `onToggle` 을 **안 준** 갈래에만 있다).

이 화면은 데이터가 커서 그 방식을 쓴다. 트리 뷰에는 이미 구현해 뒀는데,
**비교 뷰를 새로 만들면서 그 동작을 옮기지 않았다.** 같은 지적을 두 번 받은 이유다.

### 3 — 오른쪽 칸

# [이어서 · 2026-09-11] 「4.0 지금 담기」가 지금을 안 뜨던 것 + 쓰는 법 정리

## 장군님 질문

"화면 어떻게 쓰라는거야? 용도가?"
"비교뷰에서도 난 우선 4.0에서 감지할때 감시 시작 버튼 누르고 해야되는거야?"

## 답 (소스로 확인)

- **비교 뷰는 감시 시작이 필요 없다.** 감시는 "조작할 때마다 뭐가 바뀌었나"를 쌓는 것이라
  리스트 뷰·트리 뷰용이다. 비교 뷰는 **누른 그 순간의 데이터 구조**를 통째로 떠서 맞대 본다.
- **[4.0 지금 담기]** 를 쓰는 것이 맞다. 3.0 쪽은 **[3.0 → 4.0 보내기]**.
  3.0 것이 도착하면 4.0 것도 자동으로 같이 담기므로, 보통은 보내기만 눌러도 된다.

**[4.0 지금 담기] 가 "지금"을 안 뜨고 있었다.**

**고침**: 비교 뷰 전용으로 "지금 이 순간을 새로 떠 달라"는 길을 따로 만들었다.
이제 담기는 감시가 켜져 있든 꺼져 있든 **항상 지금**을 뜬다. 트리 뷰가 쓰던 길은 그대로 두었다

- 걸린 자리와 **거기까지 가는 길**이 남고, **걸린 자리 아래는 통째로** 보인다.
- **다른 것만** 과 같이 켜면 **둘 다 만족하는 자리**만 남는다.
- 칸 오른쪽 **X** 는 공통 지우기를 그대로 쓴다.
- 찾는 것이 없으면 **찾는 것이 없습니다.** 라고 뜬다.
- 걸러서 자식이 전부 빠지면 **펼침 화살표를 안 그린다**(눌러도 안 나오는 화살표를 없앤다).

한 쪽만 다시 그린다 — 어긋난 자리는 그대로라 다시 세지 않는다.
