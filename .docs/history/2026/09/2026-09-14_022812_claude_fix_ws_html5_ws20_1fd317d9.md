## 조사 결과
- BR45 = UI 추가 팝업으로 FileUploader 계열 추가 시 `uploaderUrl` 예외처리(`attrUploadUrlException`) 누락. 노션 상태 `🔁 재오픈`(최종편집 2026-09-09).
- **이전 수정(삽입 루프 호출 배선)은 정상·유실 아님**: `ws_html5_ws20_edit.js:1674` 존재, HEAD 커밋에도 포함, 워킹트리 clean. BR40 같은 유실 사례가 아니다.
- **재오픈 사유**(노션 본문 "수정 후 재테스트 결과"): 직접 추가 경로는 정상 확인됐으나 **Copy 복사·붙여넣기**와 **My pattern(개인화) 추가** 경로에서 uploadUrl 이 현재 앱 기준으로 안 바뀜. 증거: 현재 앱 `YESP_TEST1543` 인데 값은 `/zu4a_srs/yesp_test1532`.
- **근본 원인**: `attrUploadUrlException` 기존행 보정 분기 2곳이 값칸 `UIATV` 가 아니라 **존재하지 않는 칸 `UIAT`** 에 대입 → 보정 로직이 통째로 무효. 신규행 생성 분기만 `UIATV` 라서 "직접 추가만 정상"이었다. (2026-08-18 코덱스·안티 공통 P1 지적 그대로 현실화.)
- **★원본이 이미 정정됨**: 읽기전용 원본 2곳(`U4A_WS_DESIGN`·`U4A_WS3.0.0`) `design/js/uiAttributeArea.js` 에서 작성자 `pes` 가 2026-08-18 16:01/16:12 주석과 함께 옛 줄을 주석 처리하고 `UIATV` 로 정정(7053·7054 / 7091·7092). `/zu4a_srs/` 시작 판정도 대소문자 무시(`startsWith`)로 변경(7065~7075). → 이번 수정은 임의 창작이 아니라 **원본 추종(1:1)**.

## 변경 이유
원작자가 원본에서 오탈자를 고쳤으므로 원본 1:1 규칙에 따라 사본 로직을 맞춤. 이로써 Copy 복붙·My pattern 경로에서도 uploadUrl 이 현재 APPID 로 보정된다(BR45 재오픈 사유 해소).

## 영향 범위
- `sap.ui.unified.FileUploader`(UO01180) · `sap.m.UploadCollection`(UO00469) **두 UI 에만** 적용(함수 첫 줄에서 그 외는 즉시 return) → 다른 UI 무영향.
- 영향 경로: UI 추가 팝업 삽입 / 드롭·붙여넣기 `_rebuild` / `updateAttrList`(선택 시) — 모두 같은 함수를 호출하므로 함께 정상화.
- 대소문자 무시 판정으로 바뀌면서, 값이 `/ZU4A_SRS/...` 처럼 대문자로 들어온 경우도 이제 보정 대상이 된다(원본과 동일한 의도). `startsWith` 는 Chromium 93 지원.
- 바인딩 처리된 값(`ISBND === "X"`)·외부 URL 은 기존대로 early return 유지.
