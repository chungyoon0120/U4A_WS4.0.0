### 왜 zoom 인가
그림의 숫자(크기·좌표·박자)는 시안 세션이 넘긴 값이다. 하나하나 키우면 입자 12개 좌표까지
다시 맞춰야 하고 시안과 값이 갈려 다음에 또 어긋난다. `zoom` 한 줄이면 **입자 좌표까지 같은 비율로**
커지고, 되돌릴 때 그 한 줄만 지운다. Electron 45 = Chromium 156 이라 `zoom` 이 레이아웃까지 적용된다.

### 함정
- **테두리 빛 원뿔 판은 카드 대각선보다 커야 한다.** 작으면 모서리에서 빛이 끊긴다.
  카드 `max-width` 를 또 키우면 이 판(지금 900px)도 같이 키운다.
- **두께는 정수 px.** 1.4배인 4.2px 은 쓰지 않았다 — 소수면 카드가 반 픽셀 자리에 놓일 때
  좌우만 얇아 보인다(2026-10-29 장군님 지적).
- **AI 모드 테두리 빛 규칙은 지우지 않고 `display: block` 으로 되살렸다.** 다시 끄려면 `none` 으로
  한 글자만 바꾼다. 시안 쪽 CSS 와 다른 **유일한 한 줄**이다 — 시안을 다시 받아 붙이면 이 줄이 덮인다.

### 정정 — 커지는 것은 AI 모드만 (장군님 지시 2026-10-30)
> 「공통 busy만 겁나 커졌는데 공통 busy는 원래 크기로 원복하고 ai busy만 지금 상태로 해줘.

| 선택자 | 무엇 |
|---|---|
| `[data-u4a-busy-mode="ai"] .u4aWsBusyCard` | gap 24 / min-width 420 / max-width 600 / padding 40px 48px 36px |
| `[data-u4a-busy-mode="ai"] .u4aWsBusyEdge` | 두께 4px |
| `[data-u4a-busy-mode="ai"] .u4aWsBusyEdge i` | 원뿔 판 900px (margin -450px) |
| `.u4aWsBusyAi` | `zoom: 1.6` (AI 모드에서만 보이는 요소라 선택자 하나로 충분) |

이 덩어리는 **AI 전용 CSS(「40안 01」) 밖**에 두었다 — 그 덩어리는 시안에서 통째로 받아 덮어쓰는
자리라, 밖에 두면 다시 받아 붙여도 크기 설정이 살아남는다.

### 함정 (실제로 한 번 덮였다)
**같은 특이도면 뒤에 오는 규칙이 이긴다.** 시안에서 받은 CSS 안에
`[data-u4a-busy-mode="ai"] .u4aWsBusyCard { min-width: 220px }` (시안 폭에 맞추려고 넣은 줄)이
내 블록보다 **뒤에** 있어서 `min-width: 420px` 를 **220px 로 덮었다.** 그 줄을 지우고 왜 지웠는지
주석을 남겼다. 시안 CSS 를 다시 받아 붙이면 그 줄이 되살아나므로 **붙인 뒤 이 자리를 다시 본다.**

### 다시 정정 — 크기는 카드 `zoom` 두 줄로 끝냈다 (장군님 지시 2026-10-30)
> 「ai busy 에서 desc 폰트만 좀 키웠으면 좋겠다」 → 「공통 busy도 같이 키워줘라 약 zoom으로 했을때 1.2 정도?」

항목마다 따로 적던 것(카드 폭·`padding`·`gap`·테두리 두께·원뿔 판·`desc` 글자·그림 `zoom`)을
**전부 지우고** 카드 하나에 `zoom` 을 거는 것으로 바꿨다.

```
.u4aWsBusyCard { zoom: 1.2; }                                          /* 공통 */
[data-u4a-busy-mode="ai"] .u4aWsBusyCard { zoom: 1.5; }                /* AI 전용 */
```

- 카드에 `zoom` 을 걸면 안의 **전부**가 같은 비율로 커진다 — 비례가 저절로 맞아서
  테두리 빛 두께·원뿔 판을 따로 키울 필요가 없고 **모서리에서 빛이 끊기는 일도 없다.**
- `zoom` 은 **겹치지 않는다** — 같은 요소의 같은 속성이라 AI 값이 공통 값을 덮는다.
- 그래서 규칙이 7개 → 2개가 됐다. 장군님 말씀(「대표 css 클래스로 분기하면 변경할 것도 많이 없잖아」) 그대로.

★AI 쪽은 종전(카드 1.4배 + 그림 1.6배 + desc 17px)과 **미세하게 달라진다** — 전부 1.5배로 통일됐다.
  카드 폭 450~660px · 그림 1.5배 · desc 19.5px.

함정: 시안 CSS 안의 `[ai] .u4aWsBusyCard { min-width: 220px }` 를 뺀 것은 **그대로 유효**하다.
그 줄이 되살아나면 `zoom` 과 무관하게 AI 카드가 좁아진다.

### 최종 — 크기는 공통과 똑같이 (장군님 확인 2026-10-30)
> 「공통 busy가 지금 딱 이쁘게 잘 나오는 사이즈 잖아 busy dialog 크기도 그렇고 그 안에 아이콘도 그렇고」

배율을 키웠다 줄였다 네 번 했다(카드 1.4 → zoom 1.5 → 1.35 → 1.15 → 없앰). 장군님이 화면을 보시고
「왜이렇게 극과 극이야 … 적당히 키워」 · 「적당히 안할래?」 두 번 지적하셨다.
**숫자를 혼자 정하지 말고, 이미 좋다고 하신 것이 있으면 거기에 맞춘다.**

최종 CSS = 세 줄이다.

```
.u4aWsBusyCard { zoom: 1.2; }                                       /* 카드 — 공통·AI 공용 */
.u4aWsBusyApi, .u4aWsBusyAi { zoom: 1.15; }                         /* 그림 — 공통·AI 공용 */
[data-u4a-busy-mode="ai"] .u4aWsBusyCard { min-height: 120px; justify-content: center; }
```

AI 전용은 **높이 하나뿐**이다. AI 그림은 가운데 한 줄(「AI」 — 선 — 로고)이라 공통 그림(높이 60px)보다
납작해서, 아무것도 안 하면 카드가 공통보다 얇아진다. 120px = 공통 카드 안쪽 높이.

## 후속 — AI 모드일 때 화면 전체 효과 (2026-10-30, 장군님 지시 · 확인 「좋다」)

> 「AI busy일때는 busydialog 켤때 배경에 마치 computer use 애니메이션 효과를 배경 전체에 블러처리까지 해줘」
> → 「이게 시발 computer use 애니메이션이냐?」 → 「너네 computer use 키면 모니터 테두리에 효과주잖아」

| 무엇 | 어떻게 |
|---|---|
| 뒤 화면 | `backdrop-filter: blur(6px)` + 강조색 6% 덮개 (dialog 자신에 건다) |
| 화면 테두리 | 테두리를 따라 빛줄기가 4초에 한 바퀴 — 3200px 원뿔 판을 `rotate`, 테두리 모양 mask 로 가림 |

마크업 1개 추가(`u4a-busy.js` `_create()` 의 dialog 직속 `<span class="u4aWsBusyAura"><i></i></span>`),
CSS 는 `u4a-busy.css`. 평소에는 `display: none`, AI 모드에서만 보인다.

### 내가 틀린 것
처음에 「가장자리에서 안쪽으로 번지는 빛이 깜빡임」(`box-shadow: inset` + opacity 애니메이션)으로
만들었다가 지적받고 다시 만들었다. **computer use 효과 = 테두리를 따라 흐르는 띠**다.
모르는 것을 제 해석으로 만들어 보여 드리기 전에, 무엇을 말하는지부터 맞췄어야 했다.

### 함정
- **`backdrop-filter` 는 요소 뒤만 흐리게 한다** — 자식인 카드는 또렷하게 남는다. 카드까지 흐려질까 봐
  따로 손댈 필요가 없다.
- **원뿔 판은 화면 대각선보다 커야 한다.** 3200px 은 2560×1440(대각선 약 2938px)까지 덮는다.
  더 큰 화면을 쓰게 되면 이 숫자를 키운다 — 안 키우면 모서리에서 띠가 끊긴다.
- 판을 `<span>` 안에 넣는 구조가 필요하다. `::before` 하나로는 안 된다 — `transform: rotate` 가
  mask 까지 같이 돌려서 테두리 모양이 무너진다.

## 후속 — AI 모드 화면 전체 효과 (2026-10-30, 확정 「딱좋다」)

최종 = **화면 가운데에서 바깥으로 퍼지는 빛 하나**. 경계선이 없다.

```
dialog[data-u4a-busy-mode="ai"]  → backdrop-filter: blur(1.5px) + 강조색 7% 덮개
.u4aWsBusyAura i                 → radial-gradient(ellipse at center,
                                      transparent 0 58%, accent 14% 78%, accent 30% 92%, accent-2 46% 100%)
                                   mix-blend-mode: screen
                                   animation: u4aWsBusyAuraBreath 2.6s (opacity 0.5 ↔ 1)
```
마크업 = `u4a-busy.js` `_create()` 의 dialog 직속 `<span class="u4aWsBusyAura"><i></i></span>`.

### 버린 방법 (전부 장군님이 퇴짜)
| 시도 | 왜 버렸나 |
|---|---|
| 테두리를 따라 도는 빛(conic + rotate) | 「저 테두리 돌아가는 효과는 빼고」 |
| 네 변 그라데이션 mask 를 add | **모서리에서 두 변이 다 옅어져 빛이 끊긴다**(실측) |
| `clip-path: inset(0 round …)` | 바깥 모서리를 깎는 것 — 「바깥쪽 말고 안쪽으로」 |
| 안쪽을 타원으로 뚫기(mask) | 빛이 화면 밖으로 밀려 **아예 안 보였다** |
| 둥근 네모 + `box-shadow` 세 겹 | 「너무 정직하게 네모」 |
| 안쪽을 둥근 사각형으로 뚫기(padding + xor mask) | 같은 이유 |

### 함정 — 두 번 크게 헛돌았다
1. **Electron 은 한 번 읽은 CSS 를 다시 읽지 않는다.** 파일을 고쳐도 떠 있는 앱은 옛 CSS 다.
   CDP 로 `link[href*=u4a-busy.css]` 의 href 에 `?v=<시각>` 을 붙여 **강제로 다시 읽혀야** 한다.
   이것을 모르고 한참 동안 「고쳤는데 안 바뀐다」를 반복했다.
2. **시안 비교하려고 요소에 직접 넣은 inline style 이 그대로 남아 CSS 를 덮고 있었다.**
   그래서 무엇을 고쳐도 화면이 안 바뀌었다. 장군님이 「변경이 안되고 똑같잖아」로 짚어 주셔야 드러났다.
   → 시안 비교는 **요소 style 이 아니라 `<style>` 를 끼웠다 빼는 방식**으로 한다(장군님 지시).
3. **캡처를 찍어 놓고 보지 않은 채 「됐습니다」라고 보고했다.** 장군님이 두 번 지적하셨다.
   고친 뒤에는 **반드시 캡처를 열어 눈으로 보고**, 이상하면 다시 고친다.

카드가 커져도 입자는 로고 둘레에만 몰렸다.

### 두 번 고쳤다 — 실측이 둘 다 잡아냈다
**1차**: 출발 자리를 **카드 크기 × 비율**(`--fx`·`--fy`)로 바꾸고, 카드 크기를 `_syncAiSpread()` 가
CSS 변수(`--u4aWsAiW`·`--u4aWsAiH`)로 넣게 했다. → 실측하니 **위로 쏠렸다.**

| desc | 위 여백 | 아래 여백 | 카드 밖 입자 |
|---|---|---|---|
| 여덟 줄 | **-64px**(카드 밖) | **+127px**(텅 빔) | 6개 |

까닭: 입자는 로고 칸(`.lg`) 안에 있어 **로고 가운데**가 기준인데, desc 가 길면 로고가 카드 위쪽으로
올라가고 가로로도 오른쪽에 치우친다. 카드 높이로 퍼뜨리니 위로 넘치고 아래가 비었다.

**2차**: **로고 가운데 → 카드 가운데** 오프셋(`--u4aWsAiOX`·`--u4aWsAiOY`)을 더해 기준을 카드
한가운데로 옮겼다. 비율도 ±0.45(카드 끝 가까이)로 다시 잡았다.

### 최종 실측 (`.works/ws40-work-order/measure-ai-dots.js`)
| desc | 카드 | 가로 덮음 | 세로 덮음 | 여백 상/하/좌/우 | 카드 밖 |
|---|---|---|---|---|---|
| 없음 | 338×135 | 94% | 92% | 5/5/8/12 | 0 |
| 한 줄 | 360×157 | 88% | 87% | 10/10/19/23 | 0 |

카드 높이가 135 → 310 으로 2.3배가 돼도 세로 덮음이 87~92% 로 유지되고, **위아래 여백이 같다.**

### 시간으로 기다리지 않는다
`u4a-busy.js` 에는 시간이 하나도 없다 — `ResizeObserver` 로 카드가 커지는 것을 보고 따라간다.
측정 스크립트의 `setTimeout` 도 **전부 없앴다**(장군님 지적 「불분명한 시간 재기는 넣지마」).
조건이 참이 될 때까지 `requestAnimationFrame` 으로 지켜본다 — 실제로 25ms · 1ms · 0ms 면 끝났다.
내가 넣었던 0.9초 · 1.5초는 근거 없는 낭비였다.

### 함정
- **`--x` 는 `calc(...)` 문자열이라 `parseFloat` 로 못 읽는다.** 처음 실측에서 전부 0 이 나왔다.
  비율(`--fx`)과 카드 크기 변수로 **직접 계산**해야 한다.
- **측정은 켠 뒤·끄기 전에** 한다. 처음엔 켜기 전에 재고 끈 뒤에 찍어서 전부 0 이었다.
- **앱은 고친 `u4a-busy.js` 를 다시 읽지 않는다.** 실측하려면 ① busy DOM 을 지우고
  ② 파일 내용을 `Runtime.evaluate` 로 평가해 함수를 새로 설치하고 ③ CSS 링크를 다시 읽힌다.
  `measure-ai-dots.js` 가 그 셋을 다 한다.
- **`setAIBusy` 를 CDP 로 부를 때 줄바꿈은 `\n` 으로** 넘긴다. `\n` 이면 문자열 안에 생 개행이
  들어가 **문법 오류로 호출 자체가 죽는다**(조용히 안 켜진다).
