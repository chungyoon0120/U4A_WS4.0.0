# 공통 스플리터 — 숨겨진 영역을 붙잡아 바가 안 움직이던 것 수정

- 때: 2026-10-22
- 누가: Claude (세션 06836675) · 지시 = 장군님(「① 공통 스플리터를 고친다」)
- 고친 파일: `www/ws30/ws10_20/theme/u4a-ui.js`

## 현상 (장군님 보고 + 화면 3장)

바인딩 팝업 → 위쪽 「화면 커스터마이징」 → **DESIGN TREE 를 숨김** 으로 두고 확인.
남은 세로 바가 보이기는 하는데 **끌어도 아무것도 안 움직인다.**

## 원인 (소스로 확인)

`theme/u4a-ui.js` 의 공통 스플리터는 바를 끌 때 양옆 영역을 **「바로 옆 형제」로만** 찾았다
(`_splitPrevPane` / `_splitNextPane` — 바만 건너뛰고 **숨김 여부는 안 봤다**).

바인딩 팝업은 커스터마이징에서 끈 영역을 **지우지 않고 `display:none` 으로 숨긴다**
(`Popups/bindPopup/layoutCustomizing/layoutCustomizing.js` `applyBindLayout`).
그래서 가운데를 숨기면 바(중|우)의 「왼쪽 이웃」이 **숨어 있는 가운데 영역**이 되어

1. 진짜 왼쪽(바인딩 필드)은 **아예 안 잡힌다**
2. 오른쪽은 남은 폭을 채우라고 `.u4aBwpFill { flex: 1 1 auto !important }` 가 걸려 있어
   스플리터가 쓴 인라인 값이 **무시된다**

→ 양쪽 다 안 움직여 바가 죽은 것처럼 보였다.

★같은 파일 안에서 **창 크기 변경 때 폭을 다시 맞추는 쪽(`_splitReclampOne`)은
숨김 패널을 이미 빼고 센다.** 드래그 쪽만 빠져 있던, 한쪽만 고쳐진 상태였다.

★원본 UI5 에는 이 상황이 없다 — 원본은 커스터마이징 때 **활성 영역만으로
`sap.ui.layout.Splitter` 를 다시 만든다**(숨은 패널이 남지 않는다).

## 고친 것

- `_splitIsHidden` · `_splitSkip` 신설 → `_splitPrevPane` / `_splitNextPane` 가
  **바와 숨은 패널을 모두 건너뛴다.**
- 바 양옆에 보이는 패널이 하나도 없으면 `U4ALOG.warn("GUARD_EXIT", …)` 남기고 드래그 무시.
- 쓰이는 곳은 드래그 시작(mousedown) 한 곳뿐이라 `getComputedStyle` 추가 호출은 드래그당 2회.
- `node --check` 통과.

고친 뒤 흐름: 바(중|우) → 왼쪽 = **바인딩 필드**(폭 고정) · 오른쪽 = **채움** →
공통의 「한쪽만 고정일 때」 갈래를 타서 **왼쪽만 px 로 바뀌고 오른쪽은 남은 폭을 채운다.**
`!important` 가 걸린 채움 영역에는 값을 쓰지 않으므로 위 2번 함정도 같이 비켜간다.

## ★또 밟을 함정

- **영역을 숨기는 화면을 만들 때, 숨긴 영역을 DOM 에 남기면 스플리터가 그것을 이웃으로 본다.**
  이제 공통이 걸러 주지만, 폭 계산을 화면에서 따로 하는 코드가 있으면 거기도 같은 함정이 있다.
- **채움 영역에 `!important` 를 걸면 스플리터가 그 영역을 못 바꾼다.** 채움은 한 영역에만 두고,
  드래그로 조절할 영역에는 `!important` 를 걸지 않는다.

## 후속 — 같은 뿌리로 더블클릭 복귀도 먹통이었다 (장군님 지적, 같은 날)

내 1차 수정은 **반쪽이었다.** 드래그가 옆 패널을 찾는 자리만 고치고,
**더블클릭으로 처음 폭에 돌아가는 쪽(`_installGlobalSplitterReset` 의 `_sides`)은 그대로 두었다.**

`_sides` 는 바의 **바로 옆 형제**를 그대로 썼다. 그래서 DESIGN TREE 를 숨기면

- 드래그 시작 때 **숨어 있는 가운데 영역**에 「처음 폭」을 적어 두고,
- 정작 폭이 바뀌는 **바인딩 필드(왼쪽)** 에는 아무것도 안 적는다.
- → 더블클릭하면 숨은 영역만 되돌려 **화면에는 아무 변화가 없다.**

고친 것: `_sides` 가 드래그와 **같은 기준**(`_splitPrevPane` / `_splitNextPane`)을 쓰게 했다.
바가 연달아 있을 때 **바 자체를 「처음 폭」 대상으로 잡던 것**도 같이 없어졌다.

★교훈: **같은 파일 안에서 「옆 패널 찾기」를 하는 자리가 세 곳이었다**
(드래그 · 더블클릭 복귀 · 창 크기 재조정). 한 곳만 고치면 반쪽이다.
앞으로 이 셋은 **같은 함수를 쓰게** 둔다.
