# 텔레그램 전송을 전부 막음 (배포 전 안전조치)

- 시각: 2026-10-13 16:15

## 무엇을 했나

`electron/lib/log/ws_telegram.js` 한 파일만 고쳤다. 맨 위에 차단 스위치(`BLOCK_ALL_SEND = true`)를
두고 들어오는 길 세 곳을 모두 맨 첫 줄에서 막았다.

| 자리 | 막은 효과 |
|---|---|
| `install()` | 설정 파일을 읽지 않고, 화면 쪽 통로 `ipcMain.on("u4a-log:send-error")` 를 **등록하지 않는다** |
| `sendError()` | 호출처 3곳(`ws_main_log.js:509` 화면 오류 · `ws_crash_report.js:683`·`:808` 앱 뻗음)이 전부 그대로 반환 — 대기열에도 안 쌓인다 |
| `isEnabled()` | 늘 `false` |

로그는 차단 안내를 **한 번만** 남긴다 — `TGSD-006`(전송 차단) · `TGSD-007`(설치 건너뜀). 전부 영어.
파일 머리 주석에도 「현재 전송은 전부 막혀 있다」를 적었다.

## 왜 이 방식인가

- 설정 파일(`telegram_token.json`)의 `enabled` 를 `false` 로 두는 길도 있지만, **그 파일은 설치 폴더에
  있고 메모장으로 고칠 수 있다** — 코드가 아니라 설정이라 배포본에서 누가/무엇이 바꿀 수 있다.
  그래서 **코드에서 막았다.**
- `main.js` 의 `install(app)` 호출을 지우는 길도 있었으나, **지우지 않았다.** 호출은 그대로 두고
  함수 안에서 막으면 되돌리기가 한 글자(`true`→`false`)이고, 호출 구조가 안 바뀐다.
- 전송 함수 자체를 지우거나 파일을 빼는 길은 **안 골랐다.** 되돌릴 때 다시 써야 하고,
  장군님은 「우선 막아라」 라고 하셨다 — 없애라는 지시가 아니다.

## 확인한 것

- 이 파일 밖에서 전송을 부르는 곳은 위 3곳뿐이다(전수 grep).
- 통신 함수(`_postDocument`)·대기열(`_drainQueue`)은 이 파일 안에서만 불린다.
- 화면 쪽(`www/ws30/ws10_20/js/ws_trycatch.js:100`)이 통로로 던지는 코드는 그대로 남아 있지만,
  **받는 쪽을 등록하지 않으므로 아무 일도 일어나지 않는다.** 화면 코드는 손대지 않았다(지시 범위 밖).
- `node --check` 통과.

## 아직 확인 못 한 것

- **앱으로 돌려 본 것이 없다.** 다만 이 전송은 포장한 설치본에서만 돌던 것이라 개발 실행으로는
  원래 확인되지 않는다(`install()` 이 `app.isPackaged` 가 아니면 전부터 바로 반환했다).
- (해결) `package.json` 의 포장 설정 — 아래 「후속」 참고.
