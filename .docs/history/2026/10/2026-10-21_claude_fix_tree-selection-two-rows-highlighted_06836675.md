# UI 트리에 파란 줄이 두 개 남던 것 — 선택 표시를 어느 갈래든 반드시 지나게

  ROOT의 파란색 표시가 없어져야 하는데 남아있는 현상」 → 「디자인 트리가 가상 dom 기반으로 그려져서

- 되돌릴 지점 = 커밋 `997ecb07`

## 1. 증상 (장군님 실측 · 스크린샷 2장)

좌측 UI 트리에서 `ROOT` 를 접고 그 줄을 고른 뒤, 미리보기에서 다른 UI 를 고르면
**`ROOT` 줄과 새로 고른 줄이 둘 다 파랗다.** 트리가 펼쳐지며 스크롤 이동하는 경우도 같았다.
**이미 펼쳐져 있는 UI 를 연달아 고를 때는 멀쩡했다**(장군님 지적 — 「무조건 안 지우는 게 아니다」).

## 2. 원인 — 선택 표시를 들고 있는 곳이 둘

| # | 어디 | 무엇을 보고 붙이나 | 남의 것을 지우나 |
|---|---|---|---|
| ① | 공통 트리의 가상 스크롤 `theme/u4a-ui.js` 2322 | 자기가 기억한 선택 키(`selKey`) | 아니오 |
| ② | WS20 트리 `ws_html5_ws20_tree.js` 738 | `oAPP.attr.ws20SelectedObjid` | 아니오 |

①을 갱신하는 것은 `fnWs20TreeMarkSelected` → `selectByKey`(u4a-ui.js 1789) 뿐이고,
그 함수만이 **나머지 줄의 `aria-selected` 를 지운다**(1794~1795).

`ws_html5_ws20_attr.js` 3717 의 갈래가 문제였다 —
- 펼침 **안 바뀜** → `fnWs20TreeMarkSelected` → ①②가 같아진다 → **정상**
- 펼침 **바뀜** → `fnRenderDesignTree` 만 → ①은 옛 줄(ROOT), ②는 새 줄 → **둘 다 파랗다**

`ROOT` 를 접어 두면 조상을 펼쳐야 하므로 **반드시 아래 갈래**를 탄다. 증상과 일치.

★**가상 스크롤 자체가 원인이 아니다.** 가상 스크롤이 자기 선택 키를 따로 들고 있는데
WS20 이 그것을 안 맞춰 준 것이다.

## 3. 원본과의 차이

원본 `U4A_WS_DESIGN/design/js/uiDesignArea.js` 2528~2546:
```
2528: 펼침 처리 (lf_expand)
2546: oAPP.attr.ui.oLTree1.setSelectedIndex(l_cnt);   ← 선택은 이 한 줄
```
`sap.ui.table.TreeTable` 의 선택은 **줄 번호 하나**다. 새 번호를 넣으면 UI5 가 이전 선택을 지운다.
원본에는 **갈래가 없고** 펼치든 안 펼치든 늘 이 한 줄을 지난다.

그 갈래는 2026-10-20 에 **속도 때문에 내가 넣은 것**이다(다시 그리면 줄마다 ＋·삭제 버튼 제목을
메인 프로세스에서 꺼내 와 886ms). 갈래는 유지하되 선택 표시는 원본처럼 **늘 한 번** 지나게 했다.

## 4. 고친 내용 — 한 자리

`www/ws30/ws10_20/js/ws_html5_ws20_attr.js` 3717~3723:
`if (펼침 바뀜) { 다시 그리기 } else { 선택 표시 }` →
`if (펼침 바뀜) { 다시 그리기 }` 뒤에 **`fnWs20TreeMarkSelected(OBJID)` 를 갈래 밖으로** 빼서 늘 부른다.

- `fnWs20TreeMarkSelected` 는 줄을 새로 만들지 않는다(강조만 바꾼다) → 속도에 영향 없음.
- 다시 그린 **직후**라 새 줄이 DOM 에 있다. 줄이 화면 밖이면 `findRow` 가 null 이지만
  `_vs.setSel` 로 키는 갱신되고, 그 뒤 3733 의 줄 이동(스크롤)에서 다시 그려질 때 붙는다.
- 그 함수는 공통 트리가 없으면 `[W20T-001]` 로 던지는데, 호출 자리가 이미 `try/catch`(3725 `[W20A-005]`)
  안이라 뒷단계(속성 갱신·줄 이동·바인딩 팝업)는 종전대로 이어진다.

## 5. 아직 안 본 것 · 또 밟을 함정

- **앱에서 확인하지 않았다**(장군님이 직접 돌리신다). `node --check` 만 통과. 테스트 = TODO 1D-4 · 1D-5.
- **★선택 상태를 두 곳에 두지 마라.** 공통 부품이 자기 선택 키를 들고 있으면, 화면 쪽이 같은 것을
  또 들고 「붙이기만」 하는 순간 둘이 어긋나 **표시가 둘 남는다.** 붙이는 곳이 둘이어도
  **지우는 곳이 하나면** 그 하나를 반드시 지나가게 해야 한다.
- **★속도 때문에 갈래를 칠 때는 「그 갈래가 원본의 어느 줄을 건너뛰는지」를 적어라.**
  2026-10-20 에 친 갈래가 원본의 `setSelectedIndex` 를 통째로 건너뛰고 있었다.
- 내 판정이 두 번 흔들렸다: ① 처음에 「무조건 안 지운다」고 써서 장군님께 정정받았다(실제는 갈래 하나만)
  ② `setDomBusy` 건과 마찬가지로 **겉면만 보고 아래쪽 함수를 안 읽은 것**이 원인이다.
