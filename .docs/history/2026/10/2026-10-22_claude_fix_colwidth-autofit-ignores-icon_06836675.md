# 컬럼 자동 폭이 아이콘을 안 세서 「...」 이 남던 것 수정

- 때: 2026-10-22
- 누가: Claude (세션 06836675) · 지시 = 장군님(「... 이 나오면 안되잔항」)
- 고친 파일: `www/ws30/ws10_20/theme/u4a-ui.js` (공통 컬럼 트리 `makeColumnTree`)

## 현상

바인딩 팝업 왼쪽 표 — **「유형」과 「설명」 사이 경계선을 더블클릭**(그 칸 내용에 맞춰 자동 폭)해도
유형 글자가 **`...` 로 잘린 채** 남았다. 장군님 추정 = 「아이콘 크기를 계산 안 하는 것 같다」 → **맞았다.**

## 원인 (소스로 확인)

자동 폭을 재는 `_cellNatW` 의 이름 칸이 아닌 갈래는 이렇게 쟀다.

1. 칸 전체 글자를 `measureText` 로 한 번 재고
2. 자식 중 **「글자가 없는 것」만** 골라 `getBoundingClientRect().width` 를 더한다

그런데 「유형」 칸은 화면이 **아이콘과 글자를 한 덩어리로 감싸서** 넣는다
(`Popups/bindPopup/modelFieldArea/modelFieldArea.js` `cell()` → `c2` = 감싼 span 하나).
그 덩어리에는 **글자가 있으므로** 2번에서 건너뛰고, 1번은 글자만 잰다.

→ **아이콘 폭 + 아이콘과 글자 사이 간격(`gap: 0.375rem` = 6px)** 이 통째로 빠진다. 대략 20px 모자랐다.

## 고친 것

- `_natW(el)` 신설 — 요소 하나의 자연폭을 **자식 안쪽까지 들어가** 더한다.
  글자 있는 요소는 `measureText`, **글자 없는 요소(아이콘)만** `rect` 로 잰다.
  각 단계의 padding · border · margin · `gap` 을 함께 더하고, 자식 사이에 낀 맨 글자도 더한다.
- 자식이 없는 평범한 글자 칸은 **예전과 똑같은 빠른 길**로 간다(값도 동일).
- `node --check` 통과.

★왜 글자를 `rect` 로 재면 안 되나: 그 칸은 이미 `overflow:hidden` + 말줄임이라
**rect 가 「잘린 폭」**이다. 그걸 쓰면 자동 맞춤이 잘린 폭에 그대로 맞춰 영영 안 풀린다.

## ★또 밟을 함정

- **아이콘과 글자를 한 덩어리로 감싸 칸에 넣는 화면은 전부 같은 함정이었다.**
  이제 공통이 안쪽까지 재지만, 폭을 스스로 재는 코드를 새로 쓸 때 같은 실수를 하기 쉽다.
- 자동 폭은 **넓어지는 쪽으로만** 바뀐다 — 아이콘 없는 칸의 값은 예전과 같다.

## 안 고친 것 (지시 밖이라 보고만)

**표(`makeTable`) 쪽에도 같은 결함이 있다.** 그쪽 `_cellNatW` 는 콤보·입력칸만 따로 처리하고
나머지는 **칸 글자만** 잰다 — 아이콘이 든 칸이면 역시 모자란 폭이 나온다.
실제로 아이콘이 든 표 칸이 있는지는 **확인 안 함.**
