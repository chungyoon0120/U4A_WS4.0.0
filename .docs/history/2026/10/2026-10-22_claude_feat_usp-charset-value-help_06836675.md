# USP 파일 속성 「문자세트」 칸에 값도움(F4) 추가 — 구글시트 개선사항 7번

- 때: 2026-10-22
- 누가: Claude (세션 06836675) · 지시 = 장군님(화면 2장 첨부)
- 고친 파일: `www/ws30/ws10_20/js/usp/ws_html5_usp.js`

## 지시

> ws30(usp) 화면에서 파일 선택 시 우측 파일 속성 패널의 문자세트 입력칸에 F4 아이콘을 추가.
> 기능은 **WS20 에서 좌측 UI 트리 ROOT 선택 시 우측 속성의 Code Page F4 와 동일하게.**

시트 원문(개선사항 7번, 김인규) = 「USP 20번 페이지 문자세트 INPUT에 서치헬프 추가 요청」.

## 어떻게 했나

WS20 쪽 길(`js/ws_html5_ws20_attr.js` ROOT 속성 F4) 과 **같은 순서**로 맞췄다.
원본 UI5 는 `design/js/uiAttributeArea.js` 의 `attrCallValueHelpDOC`(3843) 이다.

1. 코드마스터 `UA003` 에서 Code Page 속성(`DH001040`) 줄의 `SHLPNAME`(= `FLD05`) 를 얻는다.
2. 그 이름으로 `oAPP.fn.fnF4SearchHelpOpen({ shlpname, onPick })` 을 연다.
3. 고른 줄의 `CPATTR` 를 값으로 넣고 `_onUspFieldChange("CODPG", …)` 로 변경 처리.

덧붙인 것:
- **읽기 모드에서는 돋보기를 숨긴다.** 공통 CSS 가 숨겨 주는 것은 지우기(X) 뿐이라 화면에서 직접 토글한다.
  (패널은 한 번 만들고 값만 갈아 끼우므로, 토글은 파일을 고를 때마다 도는 렌더 쪽에 넣었다.)
- 폴더를 고르면 그 줄 자체가 숨는다 — 기존 동작 그대로.
- 자동 테스트 식별값(.analy/21): 칸 `USP_PROP_CODPG` · 찾기 단추 `USP_PROP_CODPG_F4`.
- `node --check` 통과.

★원본 USP 화면에는 이 값도움이 **없다.** 새로 붙이는 것이고(개선 요청), 동작만 WS20 과 같게 맞췄다.

## ★또 밟을 함정 — 코드마스터는 WS20 에서 받아 온다

`UA003` 는 **WS20 진입 파이프라인**에서 받아 `oAPP.attr.S_CODE` 에 담긴다.
USP 쪽 코드에는 그것을 받아 오는 호출이 **한 군데도 없다**(검색 결과 0건).

→ **USP 앱만 열고 화면 편집 화면을 한 번도 안 거치면 비어 있을 수 있고, 그러면 찾기 창이 안 열린다.**
  그 경우 값을 지어내지 않고 `GUARD_EXIT` 기록만 남긴다(fail-closed).
  테스트 5K-3 이 바로 이것을 보는 항목이다. 안 열리면 **코드마스터를 USP 진입에서도 받아 오게** 하거나,
  그 한 줄만 따로 받아 오는 길을 만들어야 한다.

※ 두 화면의 js 는 **같은 창에 함께 로드**된다(`js/library-preload.js`). 그래서 함수는 공유되고,
  문제는 **데이터를 언제 받아 오느냐**뿐이다.
