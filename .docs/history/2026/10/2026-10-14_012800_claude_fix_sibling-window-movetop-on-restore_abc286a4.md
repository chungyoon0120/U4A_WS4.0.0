# 별창이 되살아나도 메인 창 뒤에 깔리던 것 — 되돌릴 때 맨 위로 (2026-10-14)

## 요청

장군님 「별창이 떠있는 상태에서 ws20 화면에서 메시지 박스가 뜨면 별창이 숨는건 알겠는데,
메시지 박스가 사라지면 별창이 나타나긴 하는데 ws20화면보다 뒤에 있어」

## 무엇이 문제였나

별창을 숨겼다 되살리는 공통 함수 `oAPP.fn.fnChildWindowShow(bShow)`(`ws_fn_02.js`)는
**`hide()` 가 아니라 투명도 0** 으로 안 보이게 하고, 되돌릴 때 **투명도만 1** 로 돌린다
(이 방식은 **원본 WS3.0 과 동일** — `hide()` 는 원본에서도 주석으로 막혀 있다).

투명도만 돌리면 창은 제자리에 그대로 있다. 그 사이 메인 창이 앞으로 와 있으면
**메인 뒤에 깔린 채로 다시 보이게** 된다. parent 를 뗀 뒤로는 「자식 창은 늘 부모 위」라는
OS 보장도 없어서 그대로 뒤에 남는다.

## 고친 것

`www/ws30/ws10_20/js/ws_fn_02.js` — 투명도를 1 로 되돌린 **바로 뒤에 `moveTop()`** 한 줄.
`focus()` 는 주지 않는다(메인에서 하던 입력을 뺏지 않게). `moveTop` 은 z-order 만 바꾼다.

## 검증 (CDP + Windows z-order 실측, 2026-10-14 01:2x)

「찾기」 별창을 띄우고 숨김 → 메인 창 focus → 되살림. 창 쌓임 순서를 OS 에서 직접 읽었다.

| | 되살린 뒤 맨 앞 | 「찾기」 창 자리 |
|---|---|---|
| 고치기 전 | WS20 | **2번 (메인 뒤)** |
| `moveTop()` 만 따로 호출 | 찾기 | 1번 |
| 고친 뒤 (앱 재시작) | 찾기 | **1번 (맨 앞)** |

## ★ 또 밟을 함정 (새 창이 알아야 할 것)

- **별창을 숨기는 길은 두 가지고, 서로 다른 함수다.**
  `fnIsChildWindowShow`(`ws_common.js`)는 **부모-자식 목록 + `hide()/show()`** 라
  **parent 를 뗀 창에는 아무 일도 안 한다.** 실제로 도는 쪽은 `fnChildWindowShow`(`ws_fn_02.js`)로
  **같은 browserkey 별창 전체 + 투명도** 다. 「숨기는 로직은 하나」라고 보면 틀린다.
- **투명도로 숨기면 z-order 가 그대로다.** 되돌릴 때 올려 주지 않으면 뒤에 깔린다.
- **z-order 는 Electron API 로 못 읽는다.** Windows 의 창 쌓임 순서를 직접 읽어야 한다
  (`GetTopWindow` + `GetWindow`, `GetWindowText` 는 `CharSet.Unicode` 로 선언해야 제목이 깨지지 않는다).
