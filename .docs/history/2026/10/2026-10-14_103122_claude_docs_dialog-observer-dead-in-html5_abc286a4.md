# 확인창이 뜨면 별창을 숨기던 자동 감지가 WS4.0 에서 죽어 있다 (2026-10-14 · 코드 안 고침)

## 어디서 나왔나

장군님 「busy 를 돌면 오류 메시지 팝업은 hide 가 안 되네?」 → 제가 「busy 때 별창을 숨기는 공통 로직은
원본에도 없다」고 답했고, 장군님 「원본에서는 mutation observer 로 감지하는 로직이 있어 확인해봐」.
**장군님 말씀이 맞았다.**

## 원본(U4A_WS3.0.0)에 있는 것

`js/ws_fn_03.js` 의 Dialog 감시(앱 켤 때 `ws_main.js` 가 한 번 건다):

- UI5 가 모달을 담는 `sap-ui-static` 영역을 `MutationObserver` 로 본다(`childList` 만).
- 그 안에 열린 UI5 Dialog(`.sapMDialogOpen`)가 **하나라도 생기면** 별창 전부 숨김,
  **하나도 없으면** 전부 되살림. 창에 예외 표시(`MUTATION_EXCEP`)가 붙은 Dialog 는 건너뛴다.
- 만든 까닭이 주석에 적혀 있다 — 별창이 여러 개 떠 있으면 메시지 팝업이 그 뒤에 가려 사용자가 못 본다.

## WS4.0 에서 왜 안 도나

`www/ws30/ws10_20/js/ws_fn_03.js` 에 그 코드가 **그대로 복사돼 있고 호출도 된다**(`ws_main.js` 에서
try/catch 로 부른다). 그런데 함수 첫 줄이

```js
var oSapUiStatic = document.getElementById("sap-ui-static");
if (oSapUiStatic == null) { return; }
```

이고, **WS4.0 은 UI5 를 띄우지 않아 그 요소가 아예 없다**(실측: WS10/WS20 화면 파일에 UI5 부트스트랩 0건,
`sap-ui-static` 을 만드는 코드 0건). 그래서 **감시가 시작조차 안 된다.**
로그도 없이 조용히 return 하므로 아무도 몰랐다.

판정 근거로 본 것: 원본 감시 함수 본문 · 원본 예외 함수 본문 · 원본 호출 자리 ·
WS4.0 의 같은 함수 본문과 호출 자리 · WS4.0 화면 파일의 UI5 부트스트랩 유무 · `sap-ui-static` 전체 grep.

## 그래서 지금 무엇이 안 되나

확인창·메시지박스가 떴다 사라질 때 **별창 전부**가 숨었다 되살아나지 않는다. 오류 메시지 팝업만의
문제가 아니다. 지금 숨기기는 **자리마다 직접 부르는 곳**(Activate · Save · USP 몇 곳 · 네트워크 끊김 ·
아이콘 미리보기)에서만 돈다.

## ★ 또 밟을 함정

- **UI5 를 전제로 한 코드가 WS4.0 에 남아 있으면 「있는데 안 도는」 상태가 된다.**
  `sap-ui-static` · `.sapMDialogOpen` · `sap.ui.getCore()` 를 쓰는 코드는 **호출돼도 조용히 빠져나간다.**
  옮겨온 코드가 「돈다」고 판정하기 전에 **그 코드가 찾는 DOM 요소가 WS4.0 에 실제로 있는지** 본다.
- **조용한 early return 에는 로그가 없어 안 돈다는 사실조차 안 보인다.** 되살릴 때는 값이 없어
  그만두는 자리에 `U4ALOG.warn("GUARD_EXIT", …)` 를 같이 넣는다.
- HTML5 에서 되살릴 때 볼 기준은 `<dialog open>` 이다(확인창·메시지박스·값도움·busy 가 전부 그것).
  단 **busy 도 `<dialog>`** 라서 그대로 감시하면 busy 가 켜질 때마다 별창이 숨는다 — 어디까지를
  「가리는 창」으로 볼지 먼저 정해야 한다.

## 1. 「먼저 정해야 한다」던 기준 — 원본이 이미 정해 두고 있었다

위에서 **새로 설계해야 한다**고 적었는데 **틀렸다.** 원본을 더 읽으니 답이 나와 있었다.

- 원본 감시는 열린 UI5 Dialog 전부를 보되 `MUTATION_EXCEP="X"` 가 붙은 것만 건너뛴다.
- 그 표시가 붙는 곳을 원본 전체에서 grep → **3건, 그중 현행은 `js/ws_main.js` 889 하나.**
  그 하나가 **직접 만든 BusyDialog** 다(「UI5 BusyDialog가 거지 같아서 내가 그냥 직접 만든」 주석).
  나머지 2건은 `_` 계열 사본이라 현행이 아니다.
- 게다가 원본 busy 는 평소 화면에 박힌 `<div id="u4aWsBusyIndicator">` 라(원본 index.html 50)
  애초에 Dialog 가 아니었다.

→ **원본 규칙 = 「busy 를 뺀 Dialog 가 하나라도 열려 있으면 별창을 숨긴다」.** 설계가 아니라 이식이다.

## 2. 한 일 — `www/ws30/ws10_20/js/ws_fn_03.js`

| 무엇 | 전 | 후 |
|---|---|---|
| 감시 대상 | `sap-ui-static` (WS4.0 엔 없음 → 조용히 return) | `document.body` |
| 가리는 창 기준 | `.sapMDialogOpen` | `dialog[open]:not(.u4aWsBusyIndicator), .sapMDialogOpen` |
| 예외 판정 | `sap.ui.getCore()` 로 `MUTATION_EXCEP` 조회 (죽은 코드) | 셀렉터에서 busy 를 바로 뺀다 → 함수 삭제 |
| 감시자 | 1개 (`childList`) | **2개** — ① `{childList:true}` ② `{attributes:true, attributeFilter:["open"], subtree:true}` |
| 로그 | 없음 | 상태가 바뀔 때 1줄 + `GUARD_EXIT` 2곳 |

- **감시자를 2개 건 까닭**: 팝업 `<dialog>` 54개는 전부 `document.body` 직속에 만들었다 지운다(실측
  `document.body.appendChild(oDlg)` 53 + `oBody.appendChild(oDlg)` 1) → ①로 잡힌다.
  반면 화면에 박아 둔 채 `showModal()`/`close()` 만 하는 창(네트워크 끊김 창 `u4a_neterr` 등)은
  **`open` 속성 변화뿐이라 ①로 안 잡힌다** → ②가 필요하다.
- **`subtree` 를 ①에 안 켠 까닭**: 켜면 화면을 그릴 때마다 콜백이 쏟아진다. ②는 `subtree` 가 필요하지만
  `attributeFilter` 를 `open` 하나로 묶어 다른 속성 변화에는 안 불린다.
- **상태 비교(`bChildHidden`)를 넣었다**: 원본은 UI5 모달 전용 영역 하나만 봐서 콜백이 드물었는데,
  WS4.0 은 `<body>` 를 봐야 해서 자주 불린다. 상태가 안 바뀌면 건너뛴다 — **동작은 원본과 같고 횟수만 준다.**
- 토스트는 `<div class="u4a-toast">` 라 `<dialog>` 가 아니다(실측) → 애초에 안 걸린다.
- `node --check` 통과.

## 3. 또 밟을 함정 (추가)

1. **busy 를 셀렉터에서 빼지 않으면 busy 가 켜질 때마다 별창이 전부 사라졌다 돌아온다.**
   WS4.0 busy 는 top-layer 때문에 `<dialog>`+showModal 로 바뀐 것이라(theme/u4a-busy.js)
   원본엔 없던 함정이다. busy 의 class 이름을 바꾸면 이 예외가 조용히 풀린다.
2. **직접 부르는 자리와 겹친다 — 그리고 원본도 그랬다.** Activate·Save 는 시작에서 직접
   `fnChildWindowShow(false)` 로 숨기고 끝에서 되살린다. 그 사이에 확인창이 떴다 닫히면 감시가
   **중간에 별창을 되살린다.** 원본 감시도 「열린 Dialog 가 없으면 무조건 되살린다」였으므로
   **원본과 같은 동작이다.** 고치고 싶어지면 그건 원본과 달라지는 것이니 지시를 받고 한다.
3. **`<dialog>` 를 `<body>` 가 아닌 곳에 붙이는 팝업을 새로 만들면 ①에 안 잡힌다.**
   지금은 54개 전부 `<body>` 직속이라 성립한다. 새 팝업은 `document.body` 에 붙인다.

## 4. 같은 턴 후속 — 릴리즈 노트 창이 별창 목록에서 통째로 빠져 있었다

장군님이 화면을 보여 주시며 「릴리즈 노트 팝업은 못잡는거야?」 → 확인 결과 **못 잡는다.**
다만 감시 탓이 아니다. 그 창은 「가리는 창」이 아니라 **숨겨져야 할 쪽**인데 목록에 아예 없었다.

- 공통 `getSiblingWindows`(js/ws_common.js 2857·2858)는 `webPreferences` 에 **OBJTY 가 있고
  browserkey 가 같은** 창만 모은다. 릴리즈 노트 창(`Popups/relese_notes/index.js` 71)은 **둘 다 없었다.**
- **원본도 같다**(원본 같은 파일에 parent·OBJTY·browserkey 전부 없음) → 원본에서도 안 숨었다.
- 장군님 지시 「달아줘」(2026-10-15)로 달았다.

★**경로가 두 갈래다 — 이걸 모르면 엉뚱한 데를 고친다.**
`fnReleaseNotePopupOpener`(js/fnDialogPopupOpener.js 3531)가 라이선스(`checkWLOList`)를 보고 갈린다.
**옛 창(`RELNOTEPOP`)은 식별값을 이미 제대로 달고 있다.** 없는 것은 **새 창(V2)** 뿐이라 거기만 고쳤다.

| 파일 | 한 일 |
|---|---|
| `js/fnDialogPopupOpener.js` (V2 호출부) | `open()` 인자에 `objty: "RELNOTEPOPV2"` · `browserkey: parent.getBrowserKey()` 추가 |
| `Popups/relese_notes/index.js` | `webPreferences` 에 `OBJTY` · `browserkey` 를 받아 넣음 + 값이 비면 `GUARD_EXIT` 로그 |

- OBJTY 를 옛 창과 **일부러 다르게** 뒀다 — 같은 이름이면 옛 경로의
  `getCheckAlreadyOpenWindow("RELNOTEPOP")` 가 V2 창을 「이미 열림」으로 잘못 집을 수 있다.
- 숨기기 예외 목록(`fnCheckPopupHideException`)에는 **넣지 않았다** — 숨어야 하므로.
- 이로써 **뒤로가기 일괄 닫기에도 같이 잡힌다**(같은 함수를 쓴다). 그 창은 `close` 이벤트에서
  자기 보관 변수를 비우므로 다시 열기도 깨지지 않는다(소스 확인).
- `node --check` 통과.
