  다른 별창에서 전송하면 busy를 키는 로직이 빠져있는거 같아 확인해」 → 「고치고 혹시 다른 팝업에

## 1. 확인한 것

- `Popups/mimeRepository/` 파일 4개 전부에 `BroadcastChannel` **0건** — 받는 쪽이 아예 없었다.
- **보내는 쪽은 있었다** — 창이 뜨면 `if-send-action-<browserkey>` 로 `BROAD_BUSY / BUSY_OFF` 를
  한 번 쏜다(`frame.js` 451). 즉 **짝이 안 맞는 상태**였다.
- 다른 별창(오류 페이지 에디터 창 등)은 뜰 때
  `new BroadcastChannel("broadcast-to-child-window_" + BROWSKEY)` 를 구독해 `BUSY_ON/BUSY_OFF` 를 받는다.
- 중계 경로(메인이 받아서 형제 창 전부에 뿌리는 부분)는 정상이다
  (`js/ipc/assist/send_action_assist.js` 의 `BROAD_BUSY`).

## 2. 한 일 — `Popups/mimeRepository/frame.js`

| 번호 | 한 일 |
|---:|---|
| 1 | 뜰 때 방송 채널 구독(`initBroadcast`) · 창이 닫힐 때 해제(`closeBroadcast`) |
| 2 | **방송 바쁨을 자기 바쁨과 따로** 기억(`oAPP.attr.isBroadBusy`), 둘 중 하나라도 켜지면 표시 |
| 3 | 화면에 반영하는 부분을 `_applyBusyUi` 로 빼서 두 곳이 같이 쓰게 함 |
| 4 | `browserkey` 가 없으면 `GUARD_EXIT` 로그 · 구독 실패는 `[MIMF-003]` 으로 표면화 |

- **섞지 않은 까닭**: 한 변수로 쓰면 방송 바쁨이 켜진 동안 이 창의 일이 끝나면서 바쁨을 끄면
  메인은 아직 바쁜데 이 창만 조작이 열린다. 그 반대도 마찬가지로 영영 안 풀린다.
- `getBusy()` 는 **자기 바쁨만** 돌려준다 — 창 닫기 차단(`onbeforeunload`)이 이 값을 보므로
  방송 바쁨을 섞으면 메인이 바쁜 동안 창을 못 닫게 되어 동작이 달라진다.
- `node --check` 통과. **앱으로 확인한 것은 없다.**

## 4. 또 밟을 함정

1. **보내는 쪽만 있고 받는 쪽이 없어도 아무 오류가 안 난다.** 방송은 받는 사람이 없으면 조용히 사라진다.
   별창을 새로 만들 때 「보낸다」 와 「받는다」 를 **쌍으로** 확인한다.
2. **방송 바쁨과 자기 바쁨을 한 변수에 담지 말 것.** 짝이 어긋나 영영 안 풀리거나 너무 일찍 풀린다.
3. **닫기 차단이 보는 값에 방송 바쁨을 섞지 말 것.** 메인이 바쁠 때 창을 못 닫게 되어 동작이 달라진다.


## 5. ★ 조사 대상에서 **빼야 하는 것** (장군님 지적 2026-10-15)

> 「내부 데이터 모니터 <-- 이건 테스트 용도로 만든거니까 포함시키지 말라고 몇번을 말하냐」

**내부 데이터 모니터 창은 테스트 용도**다. 운영 기능이 아니므로 **조사·개선 대상에 넣지 않는다.**
처음 뽑은 목록에 넣었다가 지적받고 뺐다 — **같은 지적이 여러 번 반복됐다.** 기억에 박았다.

**USP 새로 만들기 창도 뺀다** (장군님 지적 2026-10-15): 「소스만 있고 화면에 안 보이는거라고 좀 제발..
별창 항목에서 빼」. 소스는 남아 있지만 **화면에서 도달할 수 없는 창**이다. 조사 목록에 넣지 않는다.

→ 받는 쪽 없는 별창 = **13곳**(내부 데이터 모니터 · USP 새로 만들기 제외).

## 8. ★ 어디에 넣을지의 기준 — 장군님 결정 (2026-10-15)

> 「61~66은 단순 정보성이고 저장, 수정, 삭제 기능이 없는 팝업이라 제외한다. 70은 말 그대로 녹화니까 제외한다」

**기준 = 그 창이 저장·수정·삭제를 하는가.** 보여 주기만 하는 창은 다른 창이 바쁘다고 잠글 이유가 없다.

그 기준을 남은 4곳(UI5 미리 정의된 CSS 옛판 · 아이콘 목록 · 일러스트 메시지 · 창 숨기기 슬라이더)에
대어 보니 **넷 다 서버에 다녀오는 코드가 0건**이다(실측: 각 폴더에서 `sendAjax` 0건).
→ 전부 같은 성격이라 **제외가 맞다고 보고 여쭈었다.**

**이 기준이 뜻하는 것** — 바쁨 방송을 받아야 하는 창은 **서버에 쓰는 창**이다.
MIME 리포지토리 창이 그에 해당해서 고쳤다. 앞으로 별창을 만들 때도 이 기준으로 가른다.

## 10. 아이콘 목록 창에도 받는 쪽을 넣었다 (TODO 60/68, 2026-10-15)

**왜 이 창인가** (장군님): 「단순히 아이콘 목록을 보여주는 것도 있지만, ws20의 속성 영역에서 icon 관련
