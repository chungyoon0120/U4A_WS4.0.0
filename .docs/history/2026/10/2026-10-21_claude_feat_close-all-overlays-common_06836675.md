# 페이지를 떠날 때 떠 있는 것을 전부 닫는 공통 함수 — 신규

- 시각: 2026-10-21
- 지시: 장군님 「ws20에서 dropdown 펼쳐놓은 후 F3으로 뒤로 가기 누르면 … dropdown 목록이 남아있어.
  이거 공통 함수라도 만들어서, F3 뒤로가기 같은거 페이지 이동할때, 현재 떠있는 메뉴, 팝오버 등등
  전체 종료하는 공통 함수가 있어야 할거 같은데? 이거 앞으로 또 추가될거 같아」

## 증상

속성 영역의 **UI Theme 펼침 목록**을 펼친 채 `F3` 으로 뒤로 가면, 첫 화면으로 넘어간 뒤에도
**그 목록만 화면 위에 그대로 남아 있었다**(장군님 캡처 2장).

## 왜 남았나

바로 앞 작업에서 공통 가드에 넣은 것은 `fnCloseMenuPopover()` 인데, 그것은
`.u4a-menu`(메뉴바 드롭다운·툴바 오버플로·표 컬럼 메뉴)만 닫는다.
펼침 목록은 **`.u4a-combo__list`** 라 대상이 아니었다.

## 만든 것 — `oAPP.common.fnCloseAllOverlays()` (`ws_common.js`)

떠 있는 것을 전부 닫는다: 메뉴 · 펼침 목록 · 툴팁 · 표 컬럼 메뉴.

방식은 **`document.body` 에 `mousedown` 1회 합성**이다. 실측으로 확인한 근거:

| 떠 있는 것 | 닫는 길 | `theme/u4a-ui.js` |
|---|---|---|
| 펼침 목록(콤보) | document mousedown 바깥클릭 | 198 · 403 |
| 펼침 목록(제안) | 〃 | 403 |
| 메뉴 | 〃 (capture) | 684 |
| 툴팁 | 〃 (capture) | 904 |
| 표 컬럼 메뉴 | 〃 (capture) | 2213 |

직접 `remove()` 하지 않는 까닭: 콤보의 `_close()` 는 `oList` 변수·리스너까지 정리하는데,
DOM 만 지우면 그 변수가 남아 **다음에 열 때 어긋난다.**

### 다른 mousedown 리스너에 영향 없음 (확인함)

`document` 에 걸린 나머지 mousedown 은 다이얼로그 헤더 끌기(1073)와 스플릿바(1140) 둘뿐이고,
**둘 다 `e.target.closest(...)` 로 자기 것이 아니면 즉시 빠진다.**
`body` 에 보내면 target 이 `body` 라 전부 그냥 빠진다 — 끌기는 시작되지 않는다.
같은 방법을 미리보기 영역 클릭 때 이미 쓰고 있다(u4a-ui.js 1856).

## 또 밟을 함정

- **「메뉴」와 「펼침 목록」은 다른 것이다.** `.u4a-menu` 만 닫는 코드를 「전부 닫는다」로 읽지 말 것.
- **새 오버레이를 만들면 바깥클릭(document mousedown) 닫기를 반드시 넣는다.**
  그래야 이 공통에 자동으로 걸린다. 자기만의 닫기 방식을 쓰면 또 남는다.

| 길 | 거치는 자리 | 닫히나 |
|---|---|---|
| WS30 뒤로가기 **버튼** | `_uspBack`(`ws_html5_usp.js` 329 click → 484) → `fnNaviLock()` 499 | O |
| WS30 **F3** | `_scGuard` 1968 → `fnRunShortCut` (3) → 공통, 그 뒤 `_uspBack` 에서 한 번 더 | O |
| WS20 뒤로가기 | `fnMoveToWs10`(`ws_fn_02.js` 520) → `fnNaviLock()` 557 | O |

`fnNaviLock()` 을 부르는 자리는 코드 전체에서 **이 2곳뿐**이고 둘 다 물려 있다.
WS30 은 `_uspBack` 과 `fnMoveToWs10` 을 거쳐 두 번 불리지만, 닫을 것이 없으면 아무 일도 안 하므로 해가 없다.

**첫 화면 → 편집/소스 편집으로 들어가는 길에는 안 넣었다** — 그쪽은 버튼을 마우스로 누르는 길이라
진짜 바깥클릭이 발생해 저절로 닫힌다. 단축키로 들어갈 때는 공통 가드가 닫는다.
