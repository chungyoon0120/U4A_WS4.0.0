## ★★★ 크게 틀린 것 — 내 조사 도구가 가짜 registry 값을 줬다

**Bash · PowerShell 도구로 읽은 registry 값은 실제 값이 아니다**(샌드박스를 꺼도 동일).
`run_in_terminal` 로 장군님 터미널에서 읽으니 전혀 다른(진짜) 값이 나왔다.

이 가짜 값 때문에 아래 결론을 차례로 내놓았고 **전부 틀렸다**:

1. 「`cSession` 에 값이 0개다」 → 실제로는 값이 있었다
2. 「WMI 로 읽으면 보이고 Win32 로 읽으면 안 보인다 → 윈도우 쪽이 깨졌다」 → 둘 다 내 도구라 둘 다 가짜였다
3. 「유령 값이 남아 있다 → `Winmgmt` 서비스 재시작하라」
4. 「그 key 를 통째로 지워라」 → 장군님이 "껐다 켜면 자동으로 지운다"고 지적, 내 제안이 틀림
5. 「registry 에 적은 키와 VBS 로 넘긴 키가 다르다 → 클라이언트가 두 값을 쓴다」 → **가장 큰 오판.** 실제로는 같았다
6. 「메인 창이 두 개일 것이다」 → 장군님 확인 결과 한 개

**메모리 등록**: `registry-reads-by-my-tools-are-stale` — registry 는 앞으로 `run_in_terminal` 로만 읽는다.
(같은 날 다른 세션 17bf184f 에서도 같은 현상을 확인해 이력을 남겼다.)
