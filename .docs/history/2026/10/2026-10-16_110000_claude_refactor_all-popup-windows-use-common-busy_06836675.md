## 요청

「모든 화면, 영역에는 반드시 공통 busy 를 사용해야 한다.. 반드시!!」
「공통 busy 를 사용해야 나중에 busy 를 바꾸더라도 **한 군데만 바꾸면 전체가 자동으로 바뀌게** 설계해놔야 함」

## 바꾼 것

창마다 **두 가지**씩: ① `<head>` 에 `theme/u4a-busy.css` + `theme/u4a-busy.js` 로드
② busy 켜고 끄는 **그 창의 함수 안에서** `U4ABusy.show()` / `U4ABusy.hide()` 호출.
호출부 시그니처(`_setBusy(bOn, oOpt)` 등)와 닫기 차단·형제창 방송은 **그대로 뒀다** — 바꾼 것은 오버레이뿐.

| 종전 방식 | 창 |
|---|---|
| 겹침 `div`(모달 뒤로 숨던 것) 11곳 | 앱 기술 문서 · 편집기 · 오류 페이지 편집기 · Find(본문·호스트 2파일) · 글꼴 마법사 · 아이콘 미리보기 · 일러스트 메시지 · 소스 패턴 · Runtime Class Navigator · UI5 미리정의 CSS · 버전 관리 |
| 자체 `<dialog>` 4곳 | 쇼컷링크 생성 · MIME 리포지토리 · Monaco 스니펫 디자이너 · Monaco 테마 디자이너 |
| 이미 공통 | 바인딩 창(같은 날 먼저 교체) |

- 공통 모듈이 안 올라온 경우를 대비해 **옛 방식 폴백 + `U4ALOG.warn("GUARD_EXIT", …)`** 를 남겼다.
  옛 busy 마크업도 그 폴백용으로 **지우지 않았다.**
- 버전 관리 창의 안내 문구(DESC)는 공통 busy 안의 글자 자리에 넣도록 옮겼다.
- 전수 재확인: 별창 16곳 모두 `css:O js:O call:O`.

## 이 설계가 주는 것

busy 모양·동작을 바꿀 때 고칠 파일은 **`theme/u4a-busy.js` · `theme/u4a-busy.css` 두 개뿐**이다.
메인 창의 `setDomBusy` 도 이미 그 모듈로 넘기기만 한다.

## 또 밟을 함정

- **Find 창과 UI5 미리정의 CSS 창은 공통과 똑같은 id(`u4aWsBusyIndicator`)를 붙인 평범한 `div`** 였다
  (UI5 시절 마크업 복사, `data-sap-ui-popup` 속성까지 남아 있었다). **이름만 보고 "공통이네" 하면 틀린다** —
  `<dialog>` 인지, `u4a-busy.js` 를 로드하는지까지 본다.
- 공통 busy 는 `<dialog>.showModal()` 이라 **ESC 로 닫히지 않게 막혀 있고**, 창마다 있던 ESC 차단 코드는
  이제 폴백 쪽에만 남는다.

## 회귀 1건 — 「아이콘 목록 창 busy 가 안 꺼진다」 (장군님 지적 2026-10-16)

- 증상: 아이콘 목록 창을 열면 처리중 표시가 끝까지 안 꺼진다.
- 원인: 이 창은 **옛 겹침 표시를 html 에서 `data-busy="true"`(켜진 상태)로 시작**한다
  (창이 뜨는 순간부터 보이게 하려고). 공통 busy 로 바꾸면서 **그 옛 표시를 끄는 코드가 사라져**
  공통은 꺼지는데 옛 것이 화면에 남았다. **내가 이 턴에 만든 회귀다.**
- 고친 것: 공통 busy 를 쓸 때 **옛 표시도 함께 끄는 한 줄** 추가 — 아이콘 목록 · 일러스트 메시지 **2곳**.
  (창이 막 뜨는 순간에는 옛 표시가 보이고, 스크립트가 돌면 공통으로 교체되며 옛 것은 꺼진다.)

### 전수 재점검 (고치기 전에 16곳 전부)

| 본 것 | 결과 |

| 끄는 경로가 실제로 불리나 | 아이콘 목록 = 안쪽 화면(runtime.js) + 부모 두 길 · 일러스트 = 부모 1길. 모두 같은 함수를 타므로 적용된다 |

### 또 밟을 함정

## ★ 어제 「16곳 전수」는 전수가 아니었다 — 재조사 2026-10-16 (장군님 지적)

### 왜 빠졌나

나는 **CSS 클래스 `u4a-busy` 를 쓰면 「이미 공통」으로 치고** 넘어갔다. 규칙이 요구하는 것은
**공통 모듈(`theme/u4a-busy.js` = `U4ABusy.show()/hide()`)** 인데, 겉모양(클래스)만 같고
모듈은 안 쓰는 창이 그대로 남았다. 어제 이 파일에 「이름만 보고 공통이네 하면 틀린다」고
적어 놓고도 **클래스 이름으로 판정**했다.

### 조사 방법 (이번에는 이렇게 했다)

1. `www/ws30/resources/pathInfo.js` = 별창 경로 SSOT. 거기 등록된 창을 기준으로 잡는다.
2. 각 html 이 `u4a-busy.js` 를 **로드하는지**로 판정한다(클래스 이름이 아니라).
3. opener 가 **실제 코드인지 주석인지** 확인한다.

## 남은 5곳 전환 (장군님 지시 「바꿔라」 2026-10-16)

| 화면 | 바꾼 것 |
|---|---|
| 옵션 창 | 코드가 만들던 오버레이 → 공통 |
| 오류 목록 창 | 자체 오버레이 → 공통 |
| OTR Manager | 자체 오버레이 → 공통 |
| UI Attribute 개인화 항목 창 | 자체 오버레이 → 공통 |
| 서버 리스트 화면(로그인 쪽) | 자체 오버레이 → 공통 |

- 각 화면 `<head>` 에 `theme/u4a-busy.css` + `theme/u4a-busy.js` 를 넣고, busy 토글 함수에서
  `U4ABusy.show()/hide()` 를 쓴다. 공통이 못 올라온 경우의 폴백과 `GUARD_EXIT` 로그는 남겼다.
- 공통으로 바꾼 뒤 **옛 표시를 같이 끄는 한 줄**을 넣었다(아이콘 목록 회귀와 같은 사고 방지).

### ★ 서버 리스트 화면 — id 충돌을 먼저 풀어야 했다

이 화면의 옛 오버레이는 **공통과 똑같은 id(`u4aWsBusyIndicator`)를 쓴 `div`** 였다.
공통 모듈은 그 id 를 **먼저 찾아 쓰므로**, 그대로 두면 공통을 로드해도 자기 `<dialog>` 를 만들지 않고
그 `div` 를 집어 써서 **모달 위로 뜨지 못한다.** 그래서 옛 것의 id 를 `…Legacy` 로 바꿔 폴백으로만 남겼다.

**또 밟을 함정**: 공통으로 바꿀 때 **옛 마크업의 id 가 공통과 같은지**를 반드시 본다. 같으면 공통이
무력화된다 — 로드했는데도 모달 뒤로 숨으면 이것부터 의심한다.
