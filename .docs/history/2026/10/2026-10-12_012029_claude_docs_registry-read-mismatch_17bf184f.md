## 변경 이유

내 Bash/PowerShell 도구가 돌려주는 레지스트리 값이 이 PC 의 실제 값이 아니다.
그대로 두면 레지스트리가 근거인 조사·판정이 전부 틀린 전제 위에 쌓인다.

## 영향 범위

- 레지스트리를 근거로 한 모든 조사·판정. 앞으로는 장군님 터미널 실행 결과만 근거로 쓴다.
- 과거 대화에서 내가 내 도구로 읽어 보고한 레지스트리 값들은 **전부 다시 의심해야 한다**(어느 것이
  틀렸는지는 확인 안 함).

## 검증

| 읽은 방법 | 결과 |
|---|---|
| 내 도구 — 샌드박스 켠 채 (`Get-ItemProperty`) | `...025` 로 끝나는 값 |
| 내 도구 — `dangerouslyDisableSandbox: true` | 같은 값 |
| 내 도구 — `reg.exe query` | 같은 값 |
| 내 도구 — .NET `Registry.CurrentUser.OpenSubKey` | 같은 값 |
| **장군님 터미널 — 스크립트 1회차** | **`...024` 로 끝나는 다른 값** |
| **장군님 터미널 — 스크립트 2회차** | **같은 `...024`** |

- 계정·SID 동일 확인: `YOON\socce` / `S-1-5-21-...-1001`.
- **결정적 증거**: `HKCU\SOFTWARE\U4A\WS\cSession` 아래 subkey 이름이 장군님 쪽 값의 마지막 칸과
  일치했다. 내 쪽 값의 마지막 칸과는 안 맞는다 → 장군님 값이 실제.

## 참고 사항

### 버린 것 · 틀렸던 것
- 처음에 값의 마지막 칸을 「토큰처럼 보인다」고 보고했는데 **소스로 확인 안 한 추측**이었다. 취소함.
- 처음 `reg query` 를 Bash 로 돌렸다가 `/s` 가 경로로 바뀌어 실패 — Git Bash 의 인자 변환. 이후
  PowerShell 로 돌림.
- 「샌드박스를 끄면 실제 값이 나올 것」이라 보고 `dangerouslyDisableSandbox: true` 로 돌렸으나
  **값이 같았다.** 즉 그 플래그로는 이 현상을 못 피한다.

### 아직 모르는 것 (미확인)
- 샌드박스가 어떤 방식으로 레지스트리를 가로채는지 **구조는 확인 못 했다.** 「옛 snapshot 을
  돌려준다」는 관찰에서 나온 짐작일 뿐이다.
- 값이 왜 하필 `024` → `025` 처럼 한 칸 차이인지 모른다.
- **파일 읽기도 같은 문제인지 확인 안 했다** — TODO 7번으로 올려 지시 대기.

### 비밀 값
- 이 값에는 세션 문자열로 보이는 칸이 있어 **전체 값은 이 문서에 적지 않았다.**

### 해법을 찾았다 — 터미널 도구로 읽으면 실제 값이 나온다

장군님 지시 「다시 읽어봐 내 터미널에서」 에 따라 `mcp__terminal__run_in_terminal` 로 같은 스크립트를
장군님 터미널에서 직접 돌렸다. **결과가 장군님이 손수 돌린 값과 일치** (`...024` 로 끝나는 값).

| 읽는 방법 | 실제 값인가 |
|---|---|
| `Bash` · `PowerShell` 도구 (샌드박스 on/off 무관) | ❌ 가짜 |
| `mcp__terminal__run_in_terminal` + `read_terminal` | ⭕ 실제 |

→ 앞으로 레지스트리는 **내가 터미널 도구로 읽는다.** 장군님께 스크립트를 드려 손수 돌리게 하지 않는다.

### 걸린 것 — 터미널 도구는 명령줄에 ASCII 만 받는다

`.works/레지스트리확인/` 처럼 한글이 섞인 경로를 명령줄에 넣으니 거부됐다(look-alike 글자 방지).
스크립트를 **`.works/regcheck/`** 로 옮겨 해결. 앞으로 터미널 도구로 부를 스크립트는 **영문 경로**에 둔다.
