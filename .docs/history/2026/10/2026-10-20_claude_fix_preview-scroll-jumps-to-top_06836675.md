## 1. 증상

편집 화면에서 **이미 미리보기에 보이고 있는 UI** 를 골라도 미리보기가 그 UI 를 **화면 맨 위에 붙이려고** 스크롤을 올려 버린다. 보던 자리가 매번 사라진다.

## 2. 원인

미리보기 선택 표시 함수 `oWS.sMark.fn_mark`(`www/ws30/ws10_20/design/preview/index.js` 3012행) 안:

```js
oDom.scrollIntoView(true);
```

`scrollIntoView(true)` = `block: "start"` — **보이든 안 보이든 대상을 화면 맨 위에 붙인다.** 「안 보일 때만 움직여라」가 아니다.

## 3. ★이건 원본에도 있다 (내가 넣은 것이 아니다)

원본 디자인 영역 `C:\Users\socce\Documents\Github\U4A_WS_DESIGN\design\preview\index.js` **2992행 `fn_mark`** 에 같은 코드가 있고, 원본 저자(PES)가 **2026-10-20 13:26 에 넣었다.** 원본 주석의 까닭:

> 미리보기 UI 선택시 해당 UI의 DOM 위치로 이동하기 위해 focus를 사용 하였으나, dialog dom으로 구성된 busy에서 UI 위치 이동을 위한 focus 호출시 dialog dom이 focus를 가져가서 UI 위치 이동이 되지 않는 문제 발생. 이에따라 scrollIntoView를 사용하여 UI 위치 이동 처리하도록 로직 보완

즉 **원본 WS3.0 에서도 같은 불편이 난다.** 장군님께 그 사실을 먼저 보고하고 지시를 받은 뒤 고쳤다.

## 4. 고친 내용 (한 줄)

`www/ws30/ws10_20/design/preview/index.js` 3026~3037행:

```js
oDom.scrollIntoView({ block: "nearest", inline: "nearest" });
```

| | 전(원본) | 후 |
|---|---|---|
| 이미 보일 때 | 맨 위로 끌어올림 | **안 움직임** |
| 가려져 있을 때 | 맨 위로 | 보이는 데까지만 최소로 |

`node --check` 통과. 선택 표시·`focus()`·Promise 흐름은 **원본 그대로** 두었다 — 바뀐 것은 이 한 줄뿐이다.

## 5. 버린 방법

- **블록 통째 삭제 후 `focus()` 만 두기** — 쓰지 않았다. 원본 주석대로 처리중 표시(`<dialog>.showModal()`)가 focus 를 가져가므로, 가려진 UI 를 골랐을 때 **아예 안 움직이게** 된다. 고치려던 것의 반대가 된다.

## 6. 또 밟을 함정

- **`scrollIntoView(true)` 와 `scrollIntoView({block:"nearest"})` 는 전혀 다르다.** `true` 는 "맨 위에 붙여라" 고정이고, `nearest` 만이 "이미 보이면 가만 둬라" 다. 인자 없는 `scrollIntoView()` 도 `start` 가 기본이라 같은 문제가 난다.
- **원본과 달라진 자리다.** 원본 저자가 오늘 넣은 코드라, 다음에 원본을 참고할 때 이 한 줄이 다르다는 것을 알고 봐야 한다. 주석에 그 사실을 적어 두었다.
- 미리보기 iframe 안(`design/preview/index.js`)은 **사본이라 수정 가능**하다(장군님 지시 2026-09-01). 읽기 전용인 것은 `U4A_WS_DESIGN` · `U4A_WS3.0.0` 두 폴더뿐이다.
- `design/_preview/index.js`(언더바 폴더)에도 같은 함수가 있으나 **백업·구버전이라 손대지 않았다**(탐색 제외 규칙).
