# 새 Workspace 창 열기 — Critical Error (노션 오류 70)

- 날짜: 2026-10-27
- 세션: 06836675
- 지시: 장군님 — 「70번 … 해라」 → 「우선 주석처리만 해」

## 증상

UX 디자인 화면(WS20)에서 **새 Workspace 창 열기**를 실행하면
「Please contact the solution team」 오류 창이 뜬다. 같은 조작으로 매번 재현.

```
TypeError: Cannot read properties of undefined (reading 'SYSID')
  at fnGetRememberCheck → fnOnInitModelBinding → _onViewReady → fnInit
```

## 원인 — 0.6초 타이머 폴백 (`www/ws30/ws10_20/index.js`)

새 창이 뜨는 순서는 이렇다.

1. 메인이 새 BrowserWindow 를 만들고 화면 파일을 로드한다.
2. 새 창에서 **`DOMContentLoaded` 가 먼저** 일어나고, 거기서 **0.6초 타이머**가 돈다.
3. 메인은 새 창의 **로드가 끝난 뒤**(`did-finish-load`) 메타정보를 보낸다 — 늘 타이머보다 **늦게 출발**한다.
4. 0.6초 안에 못 오면 폴백이 **서버 정보 없이** 초기화한다 → 로그인 화면 경로 →
   접속 서버를 묻는 자리가 `undefined` → `.SYSID` 에서 터진다.

**no-build 에서는 새 창마다 개발자 도구를 자동으로 연다**(`ws30/resources/index.js`). 그게 0.6초를
쉽게 먹는다. 보고자가 **중단점을 걸었더니 반드시 재현된** 것도 같은 이유다. 느린 PC 에서도 같다.

## 조치 — 그 13줄을 **통째로 주석 처리**(삭제는 나중에)

장군님 지시로 지우지 않고 주석만 달았다. 되돌릴 때 주의할 점까지 주석에 적어 두었다.

### 없애도 되는 근거 (소스로 확인)

이 화면을 띄우는 곳은 **3곳**이고, **전부 로드가 끝나는 그 자리에서 바로** 메타정보를 보낸다.
「로드는 됐는데 정보만 안 오는」 경우가 없다. 로드 자체가 실패하면 화면이 안 뜨므로 폴백도
의미가 없고, 세 곳 다 실패 처리가 따로 있다.

| 띄우는 곳 | 창에 실어 보내는 것 | 메타정보 | 주석 처리 후 |
|---|---|---|---|
| 앱 시작(로그인 전) `intro.js` | 세션 키 | 보낸다 | 기다린다 — 정상 |
| 서버 목록에서 접속 `ServerList_v2/ServerList.js` | 세션 키 · SYSID | 보낸다 | 기다린다 — 정상 |
| 새 Workspace 창 열기 `ws30/resources/index.js` | 세션 키 · SYSID · USERINFO | 보낸다 | 기다린다 — 정상 |
| 화면 파일 단독 열기(개발 수동) | 없음 | 안 온다 | **빈 화면** (사라지는 것은 이 개발 편의뿐) |

★`_ServerList_ui5.js` 는 `_` 접두라 탐색 대상이 아니다.

## 또 밟을 함정

- **「N초 뒤에 하면 되겠지」로 못 박은 폴백은 운영에서도 탄다.** 이 코드는 주석에
  `[DEV]` 라고 적혀 있었는데 **포장본 제외 가드가 없어** 고객사 포장본에서도 돈다.
  테스트·개발 편의 코드는 **반드시 `app.isPackaged` 가드**를 건다(`.claude/rules` 표준).
- 새 창에 무언가를 보낼 때 **받는 쪽은 `DOMContentLoaded` 가 먼저**다. 보내는 쪽의
  `did-finish-load` 는 그보다 **항상 늦다.** 받는 쪽에 시간 기반 폴백을 두면 깨진다.
- 개발자 도구 자동 열기(`openDevTools`)는 새 창 초기화를 눈에 띄게 늦춘다.
  타이밍 문제를 조사할 때 이 변수를 먼저 떠올릴 것.
