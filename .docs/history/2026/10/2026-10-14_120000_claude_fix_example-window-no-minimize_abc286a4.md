# 예제 열기 창(모달)에서 최소화 버튼 제거 — 별창 parent 제거 22번 (2026-10-14)

## 요청

장군님 「22번은 오히려 모달로 가는게 맞는데 최소화 버튼을 없애야 될거 같아」 →
「원본은 모달인데도 최소화 버튼이 있긴 한데, **사용자 실수로 최소화를 누르면 모달이니까
화면이 클릭이 안되는걸로 착각을 할 수있어**」.

## 확인한 것

| 확인 | 결과 |
|---|---|
| 지금(WS4.0) 예제 열기 창 | **이미 모달 + parent** (`ws_events.js` 의 `ev_AppExam`). 그래서 parent 제거 대상이 아니다 |
| 제목줄 | 공용 화면 `extopen.html` 의 공통 타이틀바 — 최소화·최대화·닫기 |
| ★그 화면을 쓰는 창 | **예제 열기 · 아이콘 목록 · 속성 도움말 셋이 같이 쓴다**(`fnExternalOpen`). 버튼을 그냥 지우면 나머지 둘도 최소화를 잃는다 |

## 고친 것

`extopen.js` **한 곳** — 제목줄의 최소화 버튼을, **창 종류가 예제 열기일 때만** 뗀다.
나머지 두 창(아이콘 목록·속성 도움말)은 종전대로 최소화가 된다. `node --check` 통과.

### 처음에 잘못 고쳤다 (장군님 지적 「지금 커스텀 헤더잖아」)

처음에는 창 옵션(`minimizable = false`)을 주고 화면이 그 값을 읽어 버튼을 빼게 했다. **틀렸다.**
이 창은 **커스텀 헤더**라 제목줄 버튼을 우리가 직접 그린다 — **버튼만 빼면 최소화 경로가 없어진다.**
OS 창 옵션은 네이티브 제목줄이 있을 때 쓰는 것이라 여기서는 쓸 자리가 아니다.
→ 창 옵션은 되돌리고, 화면에서 버튼을 바로 뺐다.

## 검증

**아직 안 했다** — 장군님 테스트 대기.

## ★ 또 밟을 함정

- **`extopen.html` 은 창 3개가 공유하는 화면이다.** 거기서 버튼을 지우거나 동작을 바꾸면 **셋 다** 바뀐다.
  창마다 달라야 하는 것은 **창 옵션(minimizable 등)으로 갈라서** 화면이 그 값을 읽게 한다.
- **커스텀 헤더 창에서 버튼을 없애는 일은 화면에서 한다.** 창 옵션(`minimizable` 등)은 네이티브
  제목줄이 있을 때 쓰는 것이다 — 우리가 그린 버튼은 **그 버튼을 빼면 끝**이다.
- **모달 창에 최소화 버튼을 두면 안 된다.** 최소화하면 창은 사라지는데 부모 화면은 모달이라 클릭이 안 돼
  사용자가 「먹통」으로 착각한다. 원본에 버튼이 있더라도 이 경우는 빼는 쪽이 맞다(장군님 판단).
