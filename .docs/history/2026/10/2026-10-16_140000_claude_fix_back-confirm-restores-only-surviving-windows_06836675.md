# 뒤로가기 저장 확인창 — 닫힐 별창이 떴다가 꺼지던 깜빡임

- 날짜 2026-10-16 · 세션 06836675 · type=fix · 장군님 지시(확인 후 진행)

## 요청

20번 페이지 편집 모드에서 값을 고쳐 「바뀜」 상태로 별창을 여러 개 띄운 뒤 뒤로가기 →
「앱이 변경되었습니다. 저장하시겠습니까?」 확인창이 뜨며 별창이 숨겨진다.
**예·아니오를 눌러도 숨겼던 별창이 다시 떴다가 닫혀서** 깜빡인다.
원본 WS3.0 은 **닫을 창을 되살리지 않고 바로 종료**시킨다.

## 원인 — 2026-10-15 에 내가 넣은 코드가 범인이다

`ws_fn_02.js` `fnMoveToWs10` 맨 앞에서 **별창을 전부 되살리고** 있었다.
그때 목적은 「도움말 문서·릴리즈 노트처럼 **안 닫는 창**이 투명도 0 인 채 WS10 까지 따라오는 것」을
막는 것이었는데, **닫힐 창까지 같이 되살려** 이번 깜빡임을 만들었다.

확인창 콜백(`ws_events.js` `ev_pageBack_MsgCallBack`) 자체는 **취소에서만** 되살리고 있어 이미 맞았다.

## 고친 것

- `oAPP.fn.fnChildWindowShow(bShow, oOpt)` 에 옵션 하나 추가 — `ONLYCLOSEEXCEPT: true` 면
  **뒤로가기 때 닫지 않는 창(`fnCheckPopupCloseException`)만** 대상으로 한다. 기존 호출부는 그대로.
- `fnMoveToWs10` 의 되살리기를 `fnChildWindowShow(true, { ONLYCLOSEEXCEPT: true })` 로 바꿨다.

| 누른 버튼 | 닫을 별창 | 안 닫는 예외 창 |
|---|---|---|
| 취소 | 되살린다(머무르므로) | 되살린다 |
| 예 / 아니오 | **안 되살리고 그대로 닫는다** | 되살린다 |

## 같이 확인한 것 (안 건드렸다)

- 「예」(저장) 경로: 저장 성공 → `ISBACK=="X"` 분기가 **되살리기 코드보다 먼저** `fnMoveToWs10()` 로
  빠진다(`ws_events.js` 2345). 그래서 저장 경로에도 깜빡임이 없다.
- 저장 **실패** 분기의 전체 되살리기는 화면에 머무르는 경우라 그대로 둔다.

## 또 밟을 함정

- **숨기기 예외 목록과 닫기 예외 목록은 다른 목록이다.**
  `fnCheckPopupHideException`(확인창 떠도 안 숨는 창) ≠ `fnCheckPopupCloseException`(뒤로가기 때 안 닫는 창).
  「되살려야 하는 창」은 **닫기 예외** 쪽이다 — 숨었는데 안 닫히는 창이기 때문이다.

## 검증

- `node --check` 통과. **앱으로는 안 돌려 봤다** — 장군님 테스트 대기.

## 후속 — 위 수정은 반쪽이었다 (장군님 지적 2026-10-16, U4AOTRPOP 창)

### 증상

고친 뒤에도 **OTR Manager 창(`U4AOTRPOP`)이 떴다가 꺼졌다.** 장군님 지적:
「선별적으로 하는게 아니라 … 닫아야 하는 팝업에 대해서만 생각하면 되는데 이게 뭐가 어렵다고
케이스 바이 케이스가 나와」.

### 진짜 원인 — 되살리는 길이 **두 군데**인데 한 곳만 고쳤다

| 되살리는 길 | 1차 수정에서 | 결과 |
|---|---|---|
| `ws_fn_02.js` `fnMoveToWs10` | 고쳤다(예외 창만) | 깜빡임 없음 |
| **`ws_fn_03.js` `_syncChildWindowByDialog`** (dialog 감시) | **안 고쳤다** | 확인창이 사라지는 순간 `fnChildWindowShow(true)` 로 **전부** 되살림 → 깜빡임 |

원본 WS3.0 도 이 감시는 확인창이 닫히면 전부 되살린다(`ws_fn_03.js:430`). 차이는 **타이밍**이다 —
원본 확인창은 UI5 Dialog 라 닫기 애니메이션 뒤에 DOM 에서 빠져 **콜백이 먼저** 돌았고,
WS4.0 은 `<dialog>.close()` 가 즉시라 **감시가 먼저** 돌아 되살아난 뒤 닫혔다.

### 고친 것 (2차) — 조건을 덧대지 않고 **순서를 바꿨다**

- **`ws_events.js` `ev_pageBack_MsgCallBack`** — 「예」·「아니오」면 맨 앞에서 `fnChildWindowClose()`.
  닫고 나면 되살릴 때 남는 것은 닫기 예외 창뿐이라 깜빡일 것이 없다. (오류코드 `USP` 아님 — `WSEV-020`)
- **`ws_html5_usp.js` `_uspModeMsgCb`** (WS30 usp 모드 전환) — 같은 모양이었다. 같은 순서로 바꿨다(`USP-002`).
  종전에는 콜백 첫 줄에서 무조건 전부 되살린 뒤 조회 모드 전환 끝에 닫았다.
- **`ws_fn_02.js` `fnChildWindowShow`** — 1차에서 내가 추가한 `ONLYCLOSEEXCEPT` 파라미터를 **뺐다.**
  원본은 `fnChildWindowShow(bShow)` 파라미터 하나뿐이다(원본 `ws_fn_02.js:2120`) —
  **원본에 없는 파라미터를 만든 것 자체가 규칙 위반**이었다. `fnMoveToWs10` 호출부도 인자 없이 되돌렸다.

### 또 밟을 함정

- **숨기기/되살리기를 부르는 자리는 여러 곳이다.** 한 곳만 고치면 다른 길이 그대로 되살린다.
  고칠 때 `grep fnChildWindowShow` 로 **호출부 전부**를 보고 시작한다.
- **조건을 덧대지 말고 순서를 바꾼다.** 「떠나기로 했으면 먼저 닫는다」로 가면 창 이름을 보는
  조건이 아예 필요 없다. 닫는 기준은 이미 `fnCheckPopupCloseException` 한 곳에 있다.
- 2026-10-16 번역 지적도 같이 받았다 — 코드 안 함수·파라미터는 **영어 이름 그대로** 적는다
  (「살아남는 창만 옵션」·「선택지」로 바꿔 쓰는 바람에 장군님이 세 번 되물으셨다).

### 검증

- `node --check` 3개 파일 통과. **앱으로는 안 돌려 봤다** — 장군님 테스트 대기.
