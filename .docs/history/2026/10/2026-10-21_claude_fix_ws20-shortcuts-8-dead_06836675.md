## 1. 증상과 원인 (소스 확정)

구글시트 3번 「단축키 안됨」(최선호). 단축키 목록 화면에는 보이는데 눌러도 아무 일이 없었다.

원인 = 그 8종의 `fn` 이 **원본(UI5) 코드 그대로**다. UI5 버튼을 `sap.ui.getCore().byId(...)` 로 찾아
`firePress()` 하는데, HTML5 변환으로 UI5 를 뺐으므로 `byId` 는 늘 `null` 을 돌려준다.
바로 다음 줄의 `if (!버튼 || !getEnabled() || !getVisible()) { return; }` 에 걸려 **조용히 빠져나갔다.**

★**터지지 않는다** — `window.sap` 이 스텁으로 있어(`ws_html5_shell.js` 45~109) `byId` 가 `null` 을 돌려줄 뿐이다.
그래서 오류 로그조차 없었고, 장군님 눈에는 「눌러도 아무 일이 없다」로만 보였다.

예 = `ws_common.js` 1300~1303 (Ctrl+F2).

- `DEV_BROWSER` 는 패키징(운영)본에서 `disabled: true` 가 된다(253행) → F12 도 거기서는 그만둔다(원본과 같음).

# [후속 2026-10-21] 검사가 두 번 돌던 것 — 원본대로 한 번으로

- 지시: 장군님 「이게 왜 두번 호출되?」 → 「무슨 근거로 니 맘데로 검사를 두번 하냐고?」 → 「원본대로 해라」
- 되돌릴 지점 = 커밋 `095770c7`

## 1. 증상 · 원인

콘솔에 `shortcut allowed` 가 **두 줄**. 실행 가능 여부 검사(`fnShortCutExeAvaliableCheck`)가 두 번 돈 것이다.

| 화면 | 공통 가드 | 동작 함수가 또 | 합계 |
|---|:---:|:---:|:---:|
| WS10 | 1 | — | 1 |
| **WS20** | 1 | **1** | **2** |
| WS30 | 1 | — | 1 |

**원본은 단축키 하나당 1번**(각 fn 안에서). 공통 가드(`fnRunShortCut`)는 **원본에 없다** — 내가
2026-06-23 커밋 `c69b9c3b` 에서 새로 만들었다. 그러면서 **같은 커밋에 동작 함수에도 같은 검사를 넣어**
처음부터 두 번이었다. **근거는 없었다.**

## 2. 두 번째 어긋남 — 메뉴 닫기 순서

원본 F3(뒤로가기, 변환 전 1070~1094행) 순서:

```
이벤트 전파 막기 → 꾹 누름 → (UI5 락) → 메뉴 팝오버 닫기 → 실행 가능 여부 검사 → 버튼 확인
```

**메뉴를 닫고 검사한다.** 검사가 「메뉴 열림」을 보고 막기 때문이다. 내 공통 가드는 **안 닫고 검사**해서,
메뉴를 열어 둔 채 F3 을 누르면 원본과 달리 아무 일도 안 일어났다.

★**원본에서 메뉴 닫기를 가진 단축키는 F3 하나뿐이다**(원본 WS20 목록 전체에서 1곳).
 처음에 이걸 공통 가드에 **무조건** 넣었다가, 그러면 모든 단축키가 메뉴를 닫게 돼 원본과 달라져 되돌렸다.

## 3. 고친 내용

| 파일 | 무엇 |
|---|---|
| `js/ws_common.js` | 공통 가드에 **네 번째 인자**(검사 앞에서 할 일)를 받게 함. 안 넘기면 아무 일도 안 한다 |
| `js/ws_html5_ws20.js` | 동작 함수 5개 + 내가 만든 앞머리 함수에서 **메뉴 닫기·검사를 전부 제거**(공통 가드가 한다). **F3 만** 네 번째 인자로 메뉴 닫기를 넘긴다 |

- 같은 판정을 쓰던 Undo/Redo 의 편집 모드 확인은 작은 함수 하나로 뺐다.
- 압축해서 쓴 줄은 전부 풀어썼다(2026-10-21 규칙).

**확인 결과**: 검사 호출 — WS20 0 · WS10 0 · WS30 0(주석뿐) → **전부 공통 가드 한 번.**
메뉴 닫기 — F3 에 넘기는 한 곳뿐.

## 4. 또 밟을 함정

- ★**공통 함수를 새로 만들 때, 기존 자리에 같은 일이 남아 있는지 반드시 본다.** 이번엔 같은 커밋에
  둘 다 넣어 처음부터 두 번이었다. 「새로 만들었다」로 끝내지 말고 **옛 자리를 지웠는지** 확인한다.
- ★**원본에서 한 곳에만 있는 단계를 공통으로 올리지 마라.** 메뉴 닫기는 원본에서 F3 하나뿐인데
  공통에 넣으면 모든 단축키의 동작이 바뀐다. 「좋아 보여서」가 근거가 될 수 없다.
- ★**순서가 뜻을 가진다.** 메뉴 닫기는 검사 **앞**이어야 한다 — 뒤로 가면 메뉴가 열린 동안 단축키가 죽는다.
