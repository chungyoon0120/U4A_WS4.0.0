| 창 | 함수 | 열 때 가운데 배치가 있는 자리 |
|---|---|---|
| Icon List | `fnIconListPopupOpener` | `ready-to-show` · `did-finish-load` |

**`try`/`catch` 로 감싼 까닭**: Property Help 분기는 이 호출 뒤에 busy 를 끄는 줄이 있다.
자리 잡기에서 예외가 나면 busy 가 영영 안 풀린다.

**`focus()` / `restore()` 는 넣지 않았다** — 49번은 자리 문제다. 이 3개 창은 parent 가 붙어 있어
항상 부모 위에 뜨고, 범위를 넘는 변경은 지시 대상이다.

## 4. 또 밟을 함정

1. **「이미 열림」 분기만 보고 판정하면 틀린다.** 반드시 **창 생성부까지** 읽어 처음 뜰 때 자리를
   어떻게 정하는지 본다. 실제 사고: Text Search 창을 대상으로 올렸다가 장군님께 지적받았다
   (「이건 일부러 위치 고정시킨건데?」).
2. **전수를 세고 「이미 된 것」을 빼야 한다.** 처음에 32곳이라고 보고했는데 실제로는 3곳이었다.
   28곳은 이미 들어가 있었다.
3. **UI5 Predefined CSS 는 창이 두 벌이다.** 서버가 3.4.2-sp2 이상(`checkWLOList("C","UHAK900788")`)
   이면 새 창(V2 = `fnUI5PreCssPopupOpener`)이 뜨고, **V2 는 이미 자리 재배치가 되어 있었다.**
   고친 V1 은 구버전 서버에서만 돈다 → **최신 서버에서는 눌러도 V1 이 안 뜬다.**
4. **Property Help 는 WS4.0 에서 아직 띄울 수 없다.** 원본은 속성 줄의 도움말 아이콘
   (`uiAttributeArea.js` 의 `attrIcon2Proc` → `attrPropHelpPopup`)에서 부르는데,
   HTML5 쪽 아이콘 클릭 처리(`ws_html5_ws20_attr.js`)에 **그 분기가 없다** — 「미변환」 안내만 뜬다.
   고친 코드는 유효하지만 **그 아이콘이 이식될 때까지 확인할 수 없다.**
