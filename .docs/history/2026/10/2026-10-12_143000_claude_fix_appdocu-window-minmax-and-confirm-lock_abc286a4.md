## 원본에서 확인한 사실

| 항목 | 원본 (`U4A_WS3.0.0`) |
|---|---|
| 창 옵션 | parent 지정 있음, 제목줄 설정 없음 = **OS 기본 제목줄** → 최소화·최대화 버튼이 원래 있었다 |
| 삭제 버튼 | 확인창을 띄운 **직후** 다른 창에 BUSY_ON 방송 · 취소면 onClose 에서 BUSY_OFF · 확인이면 화면에서 지우고 끝에 BUSY_OFF |
| 저장 버튼 | 확인창 직후 BUSY_ON · 취소면 BUSY_OFF · 확인이면 서버 저장 함수가 다시 ON 하고 응답에서 OFF (**중간에 OFF 를 안 끼운다**) |
| 창 닫기 | 창 닫히는 길목에서 로딩 중이거나 **열린 확인창이 있으면** BUSY_OFF 방송 |
| 확인창 동안 이 창 자신 | 로딩 표시를 켜지 않는다 — 확인창 자체가 뒤를 막는다 |

## 어떻게 만들었나 (버린 방법 포함)

- **버린 방법**: 확인창 전후에 이 창의 공통 로딩 함수(`_setBusy`)를 쓰는 것.
  그 함수는 **이 창 자신의 로딩 덮개까지** 켠다. 원본은 자기 창을 안 켜므로 쓰면 원본과 달라진다.
  → 방송만 하는 작은 함수를 따로 만들고, 확인창이 열려 있는지 기억하는 플래그를 그 안에서 같이 관리했다.
- 확인 눌러 서버로 가는 경로에서는 **일부러 잠금을 풀지 않았다** — 바로 서버 저장이 다시 잠그므로
  중간에 풀면 한 번 깜빡인다. 원본 저장 버튼과 같은 순서다.
- 삭제도 HTML5 에서는 서버 저장을 한 번 다녀오므로(서버에 개별 삭제 API 가 없어 전체를 덮어쓴다)
  저장과 같은 흐름이 된다.

## 미검증 · 아직 안 한 것

- **확인창이 열린 채 창이 닫히는 경로**: 확인창이 모달이라 그 창 자신의 닫기 버튼은 못 누른다.
  밖에서 강제로 닫을 때(로그오프·뒤로가기 일괄 닫기)만 타는데, 창을 즉시 없애는 방식이면
  창 닫기 길목이 안 불릴 수 있다. **원본도 같은 구조**라 원본 1:1 로 두었다.
- 원본 저장 버튼에 있는 **「저장할 데이터가 없습니다」** 처리가 HTML5 저장 버튼에 없다. 지시 없어 안 고침(보고만).
