## 변경 이유

도구가 단추를 집으려면 **변하지 않는 식별값**이 하나 있어야 한다. `class` 는 CSS 를 손보면 깨지고,
줄 순서는 줄 하나만 끼면 깨진다. 특히 위험한 자리가 둘 있었다 —
**앱 생성 옵션 창**은 「로컬 앱 생성」과 「앱 생성」이 60px 떨어져 나란히 있고 둘 다 글자가 없어

### 요청자 부탁과 다르게 한 것 1가지
CTS 번호 찾기 단추를 `REQNR_F4` 가 아니라 **`CREATE_REQNR_F4`** 로 했다.
데이터 세트 탭에도 같은 찾기 단추가 있고 **두 탭은 동시에 DOM 에 있다**(안 보이는 쪽은 `hidden` 만
걸린다) — 접두가 없으면 안 보이는 탭의 단추가 잡힌다. 요청자에게 까닭까지 알렸고,
요청자도 "접두 붙이는 쪽이 맞습니다. 그게 결정적입니다" 로 수락했다.

### 시도했다 버린 것 / 헤맨 것
- **「공통 콤보는 못 건드린다」로 두 선택지를 만들어 물었다가 질책받았다.** 장군님:

  모양·동작이 안 바뀌는 속성 추가이고, 공통 한 곳에 넣는 것이 맞았다.
- **「화면 글자로 찾는다」를 제 말처럼 끌고 와 설명했다가 질책받았다.** 그건 요청서에 적힌 말이고,
  목적은 「도구가 미리 재어 기억해 두고 다시 재면 같은 네모라고 알아보게 하는 것」뿐이다.
- 작업 중 `python` 안에서 한글을 `\uXXXX` 로 직접 escape 했다가 **주석에 오타가 여러 번 들어갔다**

  들어간 오타는 전부 고쳤다.
- `_actBtn` 호출 끝을 `old[:-3]` 로 잘라 인자를 붙였다가 **들여쓰기 공백까지 남아 문법이 깨졌다**

## 변경 이유

★**확인 팝업이 가장 위험했다.** 삭제·생성·복사 확인창이 다 거기로 뜨는데, 버튼이 2개일 때는
**아이콘만** 남아 글자가 없다. 그쪽 도구는 「Yes」 라는 **글자**로 집고 있었다 —
화면 언어를 바꾸면 확인을 못 눌러 **앱을 지우다 만 상태로 멈춘다.** 되돌릴 수 없는 자리다.

나머지 4곳은 CSS class 로만 집히던 자리라 CSS 를 손대면 조용히 어긋난다.

## 영향 범위

- 확인 팝업은 **공통 한 곳**(`U4AUI.confirm`)이다. 소스로 확인했다 — 셸의 확인창 래퍼와 별창 전부가
  이 한 곳을 쓴다. 자체 구현을 따로 가진 화면은 없다. → **모든 확인 팝업이 한꺼번에** 덮였다.
- 반반 버튼 오른쪽은 **왼쪽에 준 이름 + `_MENU`** 라 WS20 실행 버튼에 이름을 주면 그쪽은
  저절로 갈린다. `data-menu-anchor="split"` 은 원래 있던 것이라 **그대로 남겼다.**
- 화면 동작·모양 변화 없음.

## 검증

- 고친 파일 4개 전부 `node --check` 통과.
- **제가 화면으로 확인하지 못했다 — 미확인.** 요청자가 다시 재서 알려 준다.
- 확인 팝업이 한 곳인지는 **소스 전수 grep 으로 확인**했다(`U4AUI.confirm` / `fnConfirmBox` 사용처
  20여 곳 전부 공통을 부른다, 자체 `yesLabel/noLabel` 구현은 공통 외에 없다).

## 참고 사항

- 확인 팝업 쪽은 **이름을 새로 짓지 않았다** — 그 창이 원래부터 버튼마다 역할 이름을 들고 있었고,
  그것을 화면으로 내보낸 것뿐이다.
- 요청자가 전한 장군님 기준: 「**화면에서 눌러서 동작하는 모든게 기준이다**」.
  그래서 「지금 쓰는 것만」이 아니라 눌리는 것 전부를 센다.
- **별창 parent 작업은 6번에서 멈춰 있다** — 그쪽 판단을 받으면 이어서 간다.
