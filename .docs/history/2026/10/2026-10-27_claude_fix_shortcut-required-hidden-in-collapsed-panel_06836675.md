# 쇼컷링크 생성 창 — 필수 입력 오류가 접힌 패널 안에 숨던 문제

- 날짜: 2026-10-27
- 세션: 06836675
- 지시: 장군님 「패널을 다 접은 상태에서 필수 입력하지 않은 채 … **「쇼컷 링크 저장」** 을 누르면
  오류가 어디서 발생했는지, 필수 입력 체크가 된 건지 메시지 처리도 없고 해당 패널이 접어져 있어서 알 수 없다」
  → 분석 보고 후 **「고쳐라」** 로 수정.

## 무엇이 문제였나

필수 입력 검사 자체는 **돌고 있었다.** 빨간 테두리와 안내 글까지 붙이고, 첫 오류 칸으로 포커스도 보낸다.
문제는 그 결과가 **전부 패널 안**에 있다는 것이다.

| 사실 | 근거 |
|---|---|
| 접힌 패널은 본문이 통째로 사라진다 | `theme/shell.css:1359` `.u4a-panel[data-collapsed="X"] .u4a-panel__body { display: none; }` |
| 그래서 빨간 테두리도 안내 글도 안 보인다 | 값 상태는 그 칸 DOM 에 붙는다(공통 `createField.setValueState`) |
| 포커스도 안 먹는다 | `display:none` 요소는 `focus()` 가 조용히 실패한다 → 화면이 꿈쩍도 안 한다 |
| 따로 띄우는 확인창·토스트가 없다 | `fn_Check_required` 는 값 상태만 세우고 끝난다 |

→ **패널을 다 접고 저장을 누르면 화면에 아무 반응이 없다.** 장군님 지적이 그대로 맞다.

## 원본(UI5)은 어땠나 — 접히지 않았다

`U4A_WS3.0.0/www/ws30/ws10_20/Popups/ShortCutCreator/js/frame.js`

- `sap.m.Panel` 을 쓰는데 **`expandable` 을 안 준다**(기본값 false) → 전수 검색해도 `expandable`·`expanded` 가 **0건**.
- 원본 `fn_Check_required` 는 `setValueState('Error')` 만 하고 `setValueStateText` 조차 없다(안내 글 없음).

→ **접기는 WS4.0 이 공통 접이식 패널을 쓰면서 생긴 기능**이고, 그 때문에 원본엔 없던 사각지대가 생겼다.
   (HTML5 쪽이 안내 글까지 붙여 원본보다 친절해진 상태였는데, 접히면 그게 다 가려졌다.)

## 어떻게 고쳤나 — `Popups/ShortCutCreator/js/index.js` 한 파일, 3자리

1. **`_revealField(oField)` 신설** — 그 칸이 든 패널이 접혀 있으면 펼친다.
   - 칸 → `closest(".u4a-panel")` 로 제 패널을 찾는다. 필드↔패널 짝 표를 따로 두지 않아 칸이 늘어도 그대로 돈다.
   - **속성을 직접 쓰지 않고 그 패널의 접기 버튼을 누른다.** 공통의 `setCollapsed` 를 타야
     `aria-expanded` 와 `onToggle` 이 같이 맞춰진다. 공통 파일은 한 글자도 안 건드렸다.
   - 칸 DOM 이 없거나 접기 버튼을 못 찾으면 `U4ALOG.warn("값이 없어 그만둠", …)` 로 남긴다.
2. **`_refocus()` 가 맨 먼저 `_revealField()` 를 부른다** — 포커스 전에 펼쳐야 focus 가 먹는다.
   이 한 줄로 **서버 앱ID 검증 실패 경로**(같은 함수를 쓴다)도 같이 덮였다.
3. **`fn_Check_required()` 가 첫 오류 하나가 아니라 오류 난 칸을 전부 모은다**
   (`oFirstBad` → `aBad` 배열) → `aBad.forEach(_revealField)` 로 **관련 패널을 모두** 펼치고,
   `aBad[0]` 로 포커스. 하나만 펼치면 다른 패널의 오류가 접힌 채 남는다.

`node --check` 통과. 줄 끝은 CRLF 그대로 유지.

## 안 한 것 · 미검증

- **확인창이나 토스트는 안 붙였다.** 원본에 없다 — 임의 추가 금지. 패널이 펼쳐지면 빨간 테두리로 충분하다고 보고 멈췄다.
  필요하면 지시를 받고 붙인다.
- **다른 창은 안 봤다.** 공통 접이식 패널을 쓰는 창이 더 있다
  (값도움 검색조건 · 앱 값도움 · 이미지 압축 · MIME · 동일 속성 · 웹 보안 · 오류 페이지 편집기 ·
  글 조각 디자이너 · 테마 디자이너 · OTR 값도움 · 바인딩 동기화 · USP).
  그 창들도 **접히는 패널 안에 필수 입력이 있는지**는 확인하지 않았다 — 같은 사각지대일 수 있다.

## 또 밟을 함정

1. **공통 접이식 패널 안에 필수 입력 칸을 두면, 접힌 순간 검증 결과가 통째로 사라진다.**
   `display:none` 이라 테두리·안내 글·포커스가 전부 죽는다. 검증 실패 처리에는 **펼치기**가 같이 가야 한다.
2. **`focus()` 가 실패해도 예외가 안 난다.** 조용히 아무 일도 안 일어나므로 로그로도 안 잡힌다 —
   「포커스를 보냈다」는 「보인다」가 아니다.
3. **이 파일은 줄 끝이 CRLF 다.** 스크립트로 고칠 때 LF 로 읽고 비교하면 문자열을 못 찾는다
   (이번에도 첫 시도가 「못 찾음」으로 멈췄다). 읽은 뒤 LF 로 바꿔 치환하고 저장할 때 CRLF 로 되돌린다.
