# 쇼컷링크 생성 창 — 필수 입력 오류가 접힌 패널 안에 숨던 문제

- 날짜: 2026-10-27
- 세션: 06836675
- 지시: 장군님 「패널을 다 접은 상태에서 필수 입력하지 않은 채 … **「쇼컷 링크 저장」** 을 누르면
  오류가 어디서 발생했는지, 필수 입력 체크가 된 건지 메시지 처리도 없고 해당 패널이 접어져 있어서 알 수 없다」
  → 분석 보고 후 **「고쳐라」** 로 수정.

## 무엇이 문제였나

필수 입력 검사 자체는 **돌고 있었다.** 빨간 테두리와 안내 글까지 붙이고, 첫 오류 칸으로 포커스도 보낸다.
문제는 그 결과가 **전부 패널 안**에 있다는 것이다.

| 사실 | 근거 |
|---|---|
| 접힌 패널은 본문이 통째로 사라진다 | `theme/shell.css:1359` `.u4a-panel[data-collapsed="X"] .u4a-panel__body { display: none; }` |
| 그래서 빨간 테두리도 안내 글도 안 보인다 | 값 상태는 그 칸 DOM 에 붙는다(공통 `createField.setValueState`) |
| 포커스도 안 먹는다 | `display:none` 요소는 `focus()` 가 조용히 실패한다 → 화면이 꿈쩍도 안 한다 |
| 따로 띄우는 확인창·토스트가 없다 | `fn_Check_required` 는 값 상태만 세우고 끝난다 |

→ **패널을 다 접고 저장을 누르면 화면에 아무 반응이 없다.** 장군님 지적이 그대로 맞다.

## 원본(UI5)은 어땠나 — 접히지 않았다

`U4A_WS3.0.0/www/ws30/ws10_20/Popups/ShortCutCreator/js/frame.js`

- `sap.m.Panel` 을 쓰는데 **`expandable` 을 안 준다**(기본값 false) → 전수 검색해도 `expandable`·`expanded` 가 **0건**.
- 원본 `fn_Check_required` 는 `setValueState('Error')` 만 하고 `setValueStateText` 조차 없다(안내 글 없음).

→ **접기는 WS4.0 이 공통 접이식 패널을 쓰면서 생긴 기능**이고, 그 때문에 원본엔 없던 사각지대가 생겼다.
   (HTML5 쪽이 안내 글까지 붙여 원본보다 친절해진 상태였는데, 접히면 그게 다 가려졌다.)

## 어떻게 고쳤나 — `Popups/ShortCutCreator/js/index.js` 한 파일, 3자리

1. **`_revealField(oField)` 신설** — 그 칸이 든 패널이 접혀 있으면 펼친다.
   - 칸 → `closest(".u4a-panel")` 로 제 패널을 찾는다. 필드↔패널 짝 표를 따로 두지 않아 칸이 늘어도 그대로 돈다.
   - **속성을 직접 쓰지 않고 그 패널의 접기 버튼을 누른다.** 공통의 `setCollapsed` 를 타야
     `aria-expanded` 와 `onToggle` 이 같이 맞춰진다. 공통 파일은 한 글자도 안 건드렸다.
   - 칸 DOM 이 없거나 접기 버튼을 못 찾으면 `U4ALOG.warn("값이 없어 그만둠", …)` 로 남긴다.
2. **`_refocus()` 가 맨 먼저 `_revealField()` 를 부른다** — 포커스 전에 펼쳐야 focus 가 먹는다.
   이 한 줄로 **서버 앱ID 검증 실패 경로**(같은 함수를 쓴다)도 같이 덮였다.
3. **`fn_Check_required()` 가 첫 오류 하나가 아니라 오류 난 칸을 전부 모은다**
   (`oFirstBad` → `aBad` 배열) → `aBad.forEach(_revealField)` 로 **관련 패널을 모두** 펼치고,
   `aBad[0]` 로 포커스. 하나만 펼치면 다른 패널의 오류가 접힌 채 남는다.

`node --check` 통과. 줄 끝은 CRLF 그대로 유지.

## 안 한 것 · 미검증

- **확인창이나 토스트는 안 붙였다.** 원본에 없다 — 임의 추가 금지. 패널이 펼쳐지면 빨간 테두리로 충분하다고 보고 멈췄다.
  필요하면 지시를 받고 붙인다.
- **다른 창은 안 봤다.** 공통 접이식 패널을 쓰는 창이 더 있다
  (값도움 검색조건 · 앱 값도움 · 이미지 압축 · MIME · 동일 속성 · 웹 보안 · 오류 페이지 편집기 ·
  글 조각 디자이너 · 테마 디자이너 · OTR 값도움 · 바인딩 동기화 · USP).
  그 창들도 **접히는 패널 안에 필수 입력이 있는지**는 확인하지 않았다 — 같은 사각지대일 수 있다.
- 실제로 눌러 본 적 없다. TODO 🧪 에 테스트 1건 올렸다.

## 또 밟을 함정

1. **공통 접이식 패널 안에 필수 입력 칸을 두면, 접힌 순간 검증 결과가 통째로 사라진다.**
   `display:none` 이라 테두리·안내 글·포커스가 전부 죽는다. 검증 실패 처리에는 **펼치기**가 같이 가야 한다.
2. **`focus()` 가 실패해도 예외가 안 난다.** 조용히 아무 일도 안 일어나므로 로그로도 안 잡힌다 —
   「포커스를 보냈다」는 「보인다」가 아니다.
3. **이 파일은 줄 끝이 CRLF 다.** 스크립트로 고칠 때 LF 로 읽고 비교하면 문자열을 못 찾는다
   (이번에도 첫 시도가 「못 찾음」으로 멈췄다). 읽은 뒤 LF 로 바꿔 치환하고 저장할 때 CRLF 로 되돌린다.

# (이어서) 같은 창 — 저장을 눌러도 확인 팝업이 안 뜨던 문제

- 날짜: 2026-10-27
- 지시: 장군님 「잘못된 앱 ID 로 오류가 난 상태에서 정상 앱 ID 를 입력하자마자 바로 **「쇼컷 링크 저장」** 을 누르면
  **「바로가기 만들기를 진행하시겠습니까」** 질문 팝업이 나오지 않고 … busy 만 돌면서 앱 Name 에 값만 채우고
  생성 여부 질문은 하지 않음」 → 분석 보고 후 **안 2** 로 수정.

## 한 번의 클릭 안에서 벌어지던 일

| 순서 | 일어나는 일 |
|---|---|
| ① 마우스를 누름(mousedown) | 앱 ID 칸에서 포커스가 빠짐 → `change` 발생 |
| ② | 그 자리에서 `fn_CheckAppId()` → `fn_setBusy(true)` → 처리중 표시 **켜짐(동기)** |
| ③ | 공통 busy 는 `<dialog>` + `showModal()` → **top-layer 라 화면 맨 위를 덮는다** |
| ④ 마우스를 뗌(mouseup) | 뗀 곳이 버튼이 아니라 처리중 표시 |
| ⑤ | 누른 곳과 뗀 곳이 달라 **`click` 이 아예 만들어지지 않는다** → 확인 팝업 없음 |

**저장만이 아니다** — 취소와 창 닫기(X)도 `click` 으로 걸려 있어 같은 상황에서 통째로 안 먹는다.

## 원본(UI5)은 왜 멀쩡했나

`U4A_WS3.0.0/.../ShortCutCreator/js/frame.js` 의 앱 ID 칸(`sap.m.Input`)에는
**`change` 이벤트가 아예 없다** — `liveChange`(대문자 변환)와 `valueHelpRequest`(값도움)뿐이다.
포커스가 빠져도 서버에 안 가니 처리중 표시가 안 뜨고, 클릭이 그대로 들어간다.
서버 검사는 저장을 누른 뒤 `fn_Check_value` → `fn_CheckAppId` 에서만 한다.

→ **HTML5 가 「ID 치고 빠지면 앱 이름 채우기」를 새로 넣으면서 생긴 사고다.**

## 고친 방법 — 안 2(편의는 두고 사고만 막기), 장군님이 고르심

`_bindFooterButton(sId, fnOnClick)` 을 만들어 **저장·취소·창닫기 세 버튼**을 묶었다.
`mousedown` 에서 `preventDefault()` → **포커스가 빠지지 않는다** → `change` 도 처리중 표시도 안 뜬다 → 클릭 정상.

- **앱 ID 검사는 빠지지 않는다.** 저장 흐름의 `fn_Check_value()` 가 **맨 첫 줄에서** `await fn_CheckAppId()` 를
  다시 부른다. 오히려 서버 왕복이 한 번 줄어든다.
- 버튼을 못 찾으면 `U4ALOG.warn("값이 없어 그만둠", …)`.
- `node --check` 통과.

### 영향도
- 고친 자리: 이 파일 안 **함수 1개 신설 + 묶는 줄 3개 치환**. 다른 파일 0.
- 달라지는 것: 마우스로 그 세 버튼을 눌러도 **버튼이 포커스를 받지 않는다**(키보드 Tab·Enter 는 그대로).
- 저장을 눌렀을 때의 결과(앱 ID 검사 → 확인 팝업)는 **원본과 같다.**

## 안 한 것 — 같은 사고에 걸리는 버튼이 더 있다

같은 창의 **최대화 버튼 · 「행 추가」 · 「행 삭제」** 도 `click` 으로만 걸려 있어,
앱 ID 칸에 커서를 둔 채 누르면 같은 식으로 클릭이 증발한다. **지시 범위 밖이라 안 건드렸다 — 보고만.**

## 또 밟을 함정

1. **서버에 다녀오는 처리를 `blur`(change)에 걸면, 그 옆 버튼의 클릭이 통째로 증발한다.**
   `showModal()` 로 뜨는 busy 가 top-layer 라 mouseup 을 가로채기 때문이다.
   그런 칸 옆의 버튼은 `mousedown` 에서 `preventDefault()` 로 포커스 이동을 막아야 한다.
2. **증상이 「아무 일도 안 일어남」이라 로그에도 안 남는다** — click 핸들러가 시작조차 안 하므로
   「저장을 눌렀다」는 기록이 없다. 버튼을 눌렀는데 로그가 비어 있으면 이 함정을 먼저 의심한다.

## (이어서) 같은 창 — 오류 칸으로 스크롤·포커스가 **전혀 안 먹던** 문제 (2026-10-27)

장군님 지적: 「오류 위치에 맞게 스크롤 이동 한다며?」
(저장 경로가 빨간 테두리인데 화면은 맨 위 그대로, 커서는 앱 ID 칸, 빨간 안내 글도 없음)

### 원인 둘 — 둘 다 내가 이 창에 넣은 코드의 결함이다

**① 맨 위로 올리고 있었다.** `mainArea.scrollTo({ top: 0 })` — 「오류 위치로」가 아니라 그냥 맨 위다.
저장 경로가 두 번째 칸이라 우연히 보였을 뿐, 아래쪽 패널의 오류는 화면 밖에 그대로 남는다.

**② busy 가 켜진 채로 `focus()` 를 걸어서 포커스가 통째로 날아갔다.** 이것이 더 큰 원인이다.

- `fn_CreateShortcut` 은 **첫 줄에서 busy 를 켠다.** 필수 입력 검사는 그 안에서 돈다.
- 공통 busy 는 `<dialog>` + `showModal()` 이라 **그 바깥 요소는 inert** — `focus()` 를 불러도 안 먹는다.
  예외도 안 난다.
- 게다가 `<dialog>` 가 닫힐 때 브라우저는 **열기 전 커서가 있던 요소로 포커스를 되돌린다.**
  저장 버튼은 누를 때 커서가 빠지지 않게 막아 뒀으므로(이 파일 앞 절), 그 요소가 **앱 ID 칸**이었다.
- 공통 `U4ABusy.hide()` 는 화면이 조용해질 때까지 기다렸다 닫는다 — **최소 300ms.**
  그래서 `fn_setBusy(false)` 바로 뒤의 `setTimeout 0` focus 는 **아직 busy 가 열려 있을 때** 실행된다.
- 포커스가 저장 경로에 없으니 **빨간 안내 글도 안 떴다** — 안내 글은 그 줄에 커서가 있을 때만 보인다
  (`shell.css` 의 `.u4a-form__row:focus-within` 조건).

### 고친 자리 — `Popups/ShortCutCreator/js/index.js` 한 파일

| 무엇 | 어떻게 |
|---|---|
| `fn_setBusy` | 옵션에 `ONDONE` 을 받아 **busy 가 실제로 다 꺼진 뒤** 부른다. 공통 `U4ABusy.hide(fnDone)` 의 콜백을 그대로 쓴다. 상태 변화가 없어 일찍 return 하는 길과 공통 busy 가 없을 때의 길에서도 빠짐없이 부른다 |
| 필수 입력 검사 | 패널 펼치기만 그대로 하고, **첫 오류 칸만 기억**한다. 스크롤·포커스는 여기서 하지 않는다 |
| 새 `_goToFirstBadField` | 커서를 두고, **한 박자 뒤에** 그 칸을 화면 **가운데**로 올린다 |
| 저장 핸들러 | `fn_setBusy(false, { ONDONE: _goToFirstBadField })` |

★가운데 맞추기를 **focus 보다 뒤**에 둔 것이 중요하다. `focus()` 는 요소를 보이게 하려고 스스로
스크롤하므로, 먼저 가운데로 맞춰 두면 그 스크롤이 나중에 덮어쓴다.

### 또 밟을 함정 (다른 창에서도 똑같다)

- **busy 가 켜진 동안 건 `focus()` 는 먹지 않는다.** 공통 busy 가 `showModal()` 이라 바깥이 inert 다.
  오류 칸으로 커서를 보내려면 **busy 를 끄는 호출에 완료 콜백을 달아 그 뒤에** 해야 한다.
- **`U4ABusy.hide()` 는 즉시 닫지 않는다.** 화면이 조용해질 때까지 기다린다(최소 300ms).
  「`fn_setBusy(false)` 다음 줄이니 이미 꺼졌겠지」는 틀렸다.
- **`<dialog>` 가 닫히면 포커스가 열기 전 자리로 되돌아간다.** 닫히기 전에 다른 곳으로 옮겨 봐야 소용없다.
- 빨간 안내 글이 안 보이면 **그 줄에 커서가 없는 것**이다(테두리는 커서와 무관하게 늘 빨갛다).
  안내 글 CSS 를 의심하기 전에 포커스부터 본다.

같은 파일의 **서버 앱 ID 오류** 자리도 `scrollTo({ top: 0 })` 를 쓴다. 그 자리는 비동기 콜백이라
busy 상태가 다르고, 앱 ID 칸이 맨 위라 결과가 같다. **이번 지시 범위가 아니라 건드리지 않았다.**
