# 테두리만 남은 빈 창 — 「내가 숨긴 창만 되살린다」로 고침

- 날짜 2026-10-16 · 세션 c015f13b · type=fix · 장군님 지시 「커밋했다 고쳐」
- 제보·측정: 자동 테스트 쪽 대화창(요청서 `D:\workspace\u4a-ws4-mcp\.docs\request\2026-10-16_iconprev-busy-stuck.md`, 측정값 `test\out\ghost.json`)

## 증상

아이콘 목록 창을 닫은(X) 뒤 **화면 안 창(단축키 목록 등)을 여닫으면** 그 창이
**테두리만 있고 속은 빈 채로** 화면에 되살아난다. 세 시점 실측(자동 테스트 쪽):

| 시점 | OS 보임 | 투명도 | 문서 가시성 | 내용 |
|---|---|---|---|---|
| 열어 둔 직후 | true | (겹창 아님) | visible | 206줄 |
| 그 창의 X 를 누른 뒤 | false | — | hidden | 206줄 |
| 화면 안 창을 여닫은 뒤 | **true** | **1.0** | **hidden** | 206줄 |

## 원인

`ws_fn_03.js` 의 「가리는 창 유무에 맞춰 별창을 숨기거나 되살리는」 처리가
`fnChildWindowShow(!bBlocking)` 을 부른다(`ws_fn_02.js`). 그 되살리기가
**「내가 숨긴 창」과 「사용자가 닫아 숨긴 창」을 구분하지 않았다.**

- 숨기기 = `setOpacity(0)` (창은 제자리, OS 로는 계속 보임, 문서는 visible 유지)
- 아이콘 목록 창의 닫기(X) = `CURRWIN.hide()` (OS 로 사라지고 Chromium 이 문서를 hidden 으로)
- 되살리기 = `setOpacity(1)` + `moveTop()` → **hide 된 창에까지 걸리면 OS 창만 올라오고
  Chromium 에는 「보여라」가 안 간다** → 테두리만 남는다.

## 고친 것 — `ws_fn_02.js` `fnChildWindowShow` 한 함수

1. **숨길 때 그 창 id 를 적어 둔다.** 단, **지금 보이는 창만** 적는다(이미 안 보이는 창은 제외).
2. **되살릴 때 적어 둔 창만** 되살린다. 목록에 없으면 건드리지 않는다.
3. 적어 둔 창이라도 그 사이 **사용자가 X 로 닫았으면 되살리지 않는다** — 투명도만 돌리면 빈 창이
   되고, `show()` 로 깨우면 사용자가 닫은 창을 억지로 되살리는 셈이다. 그 자리에 로그 한 줄.
4. 되살리기가 끝나면 목록을 비운다. **단 뒤로가기 길목(`ONLYCLOSEEXCEPT`)은 일부만 되살리는
   모드라 비우지 않는다** — 비우면 아직 투명한 창을 되살릴 길이 없어진다.

`node --check` 통과. 호출부(`ws_fn_03.js` 등)는 고치지 않았다 — 함수 안에서만 끝난다.

## 또 밟을 함정

- **숨기기는 `setOpacity(0)`, 창 닫기는 `hide()`** — 둘은 다른 상태다. 「안 보인다」로 묶어
  한꺼번에 되살리면 이 사고가 난다. 되살릴 때는 **누가 숨겼는지**를 반드시 가린다.
- 창 id 로 기억한다. 선례 = `ws_common.js` 의 같은 방식(메인 창 제외 판정).
- ★**내가 한 번 「그런 처리는 없다」고 단정했다가 틀렸다.** 찾은 결과를 앞부분만 보고 전수로
  착각했다(`head` 로 잘린 출력). **전수 확인은 건수를 세거나 끝까지 봐야** 한다.
