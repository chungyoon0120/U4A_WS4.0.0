## 3. 또 밟을 함정

1. **자기 폴더 안에서 창을 만드는 별창은 공통이 해 주는 것을 전부 놓친다** — 자리·식별값·숨기기·일괄 닫기.
   `www/help/` 나 `Popups/<이름>/index.js` 처럼 **공통 오프너를 안 거치는 창**을 새로 만들면 이 네 가지를 직접 챙긴다.
2. **식별값과 자리 잡기는 한 쌍이다.** 창을 찾는 길(OBJTY)이 없으면 바깥에서 자리를 잡아 줄 수도 없다.
3. **이 두 창은 이제 「뒤로가기」 때 같이 닫힌다** — 별창 목록에 들어갔으므로. 다른 별창과 같은 동작이지만
   **종전과 달라지는 점**이라 적어 둔다(릴리즈 노트는 44-4 로 이미 통과 확인).

## 5. ★★ 56-1 이 안 됐다 — browserkey 가 **늘 빈 값**이었다 (2026-10-15 재수정)

장군님 「56-1 이건 여전히 안되고 있어」.

**뿌리 (소스로 확인)**

```js
// helpViewer.js — 종전
const { width, height, helpSiteRoot, parent = undefined } = options;   // ← parent 는 여기서 undefined
...
if (typeof parent !== "undefined" && typeof parent.getBrowserKey === "function") { ... }  // ← 항상 false
```

- 이 `parent` 는 **`options.parent` 를 꺼낸 지역 변수**라, 화면(renderer)의 전역 `parent`
  (= WS 셸 창, `getBrowserKey()` 가 있는 곳)를 **가려 버린다.**
- 부르는 쪽(`help/u4a_helpdoc/main.js` 의 `_zipDocuOpen`)도 `parent` 를 **안 넘긴다**(실측 확인).
- 따라서 `browserkey: ""` 로 창이 만들어졌고, 공통 `getSiblingWindows`(`js/ws_common.js` 2858)가
  `oPref.browserkey !== sCurrKey` 로 **건너뛰었다** → 숨기기·뒤로가기 닫기 둘 다 비켜 간다.
- 55-1(자리 잡기)은 이 값이 필요 없어서 **통과했다** — 그래서 한 건만 안 됐다.

**고친 방법** — 공통 `getSiblingWindows` 와 **같은 방법**으로 창 자신에게서 읽는다.

```js
remote.getCurrentWindow().webContents.getWebPreferences().browserkey
```

전역 `parent` 에 의존하지 않으므로 지역 변수에 가려도 안전하다. 실패 시 `[HLPV-002]`.

## 6. 이미 열려 있을 때 다시 눌러도 창이 안 움직였다

장군님 「한번 열린 상태에서 또 누르면 왜 창이 이동이 안되 … 다른 팝업좀 참고해서 해」.

- 도움말 문서 창은 **이미 열려 있는지 보는 분기가 아예 없었다**(helpViewer.js 의 「이미
  열려있으면 포커스만」 대목은 **주석 처리**돼 있었고, `helpWindow` 는 함수 안 지역 변수라
  다음 호출에 남지 않는다). 여는 길은 `main.js` 649 한 군데뿐이고 거기도 검사가 없다.
- 다른 별창의 방식(`js/fnDialogPopupOpener.js` 의 「이미 열린 창이면 새로 띄우지 말고
  포커스만」 분기, 124~143)을 그대로 가져왔다 — OBJTY + browserkey 로 찾아
  ① 최소화면 되살리고 ② 숨어 있으면 보이고 ③ 호출한 창 가운데로 다시 놓고 ④ 포커스.
- ★**busy 함정** — 부르는 쪽(`main.js` 의 `openHelpDocViewer`)은 `once("load-finish")` 를 기다렸다가
  busy 를 푸는데, 창을 새로 안 만들면 **그 신호가 영영 안 온다.** 그래서 재사용 분기에서
  `setTimeout(…, 0)` 으로 `load-finish` 를 한 번 보낸다(실패 시 `[HLPV-004]`).
- 릴리즈 노트 창도 **같은 결함**이 있어(이미 열려 있으면 `show()`+`focus()` 만) 같은 처리를 넣었다
  — 57번 「호출한 창 가운데」 의 일부로 봤다.

## 10. ★ 뒤로가기로 WS10 에 와도 도움말 창이 안 나타난다 (2026-10-15 장군님 실측)

증상: 뒤로가기 → 확인창이 뜨면서 도움말 창이 숨는 것까지는 맞는데, 「예」 를 눌러 WS10 으로
와도 **영영 안 나타난다.**

**뿌리 (소스로 확인)** — `js/ws_events.js` 의 뒤로가기 처리:

- 확인창을 띄우기 **전에** `fnChildWindowShow(false)` 로 별창을 숨긴다(1265).
- 되살리는 `fnChildWindowShow(true)` 는 **「취소」 분기에만** 있다(1292).
  「예」(저장 후 이동) · 「아니오」(그냥 이동) 분기에는 **없다** — 이동만 한다(1322).
- 종전에는 이동하면서 `fnChildWindowClose()` 가 별창을 **전부 닫아** 버려 이 구멍이 안 보였다.
- 2026-10-15 에 도움말 문서 창 · 릴리즈 노트 창을 **닫기 예외**로 뺀 순간, 그 두 창만
  **투명도 0 인 채로 살아남아** WS10 에서도 안 보이게 됐다.

**고친 자리** — `js/ws_fn_02.js` 의 `fnMoveToWs10` 맨 앞에서 한 번 되살린다(실패 시 `[WSFN2-001]`).
이동하는 모든 길이 이 함수를 지나므로 분기마다 넣지 않는다. 닫히는 창들은 바로 닫히므로 영향 없다.

**또 밟을 함정**

6. **숨김은 `setTimeout` 0 뒤에 실행되고, 되살리기는 즉시 실행된다**(`fnChildWindowShow`, 원본도 같다).
   한 묶음 안에서 「숨김 → 되살리기」 순으로 부르면 **실제 실행은 뒤집혀 숨은 채로 남는다.**
   숨기는 코드와 되살리는 코드가 가까이 있으면 이것부터 의심한다.
7. **「안 닫는 창」을 만들면 「닫아서 덮여 있던 구멍」이 드러난다.** 닫기 예외에 창을 넣을 때는
   그 창이 **살아남은 뒤의 상태**(투명도 · 자리 · 테마)를 누가 되돌려 주는지 같이 확인한다.
