# 돋보기가 있는 입력칸에 키보드 F4 추가 — 구글시트 5번

- 시각: 2026-10-22
- 지시: 장군님 「input 에 돋보기 아이콘 누르면 검색 팝업 나오는 경우는 해당 input 에 커서를 대고
  F4 단축키를 누르면 검색 팝업이 나오게 전체 조사해서 작업해줘 … 앞으로 신규 Input 추가 시
  개발 표준으로 F4 단축키를 추가하게 문서에 기록해줘」
- 구글시트 5번 = 「인풋 UI에서 키보드 F4를 누를 시 기능이 동작하지 않음」(홍성은)

## 만든 것 — `U4AUI.attachF4(oInput, oVhBtn)` (`theme/u4a-ui.js`)

입력칸에서 `F4` 를 누르면 그 칸의 값도움(돋보기) 버튼을 클릭한다.
꾹 누름은 한 번만 / 버튼이 `disabled` 면 안 열림 / `preventDefault` + `stopPropagation`.

`createField({ f4: fn })` 안에서 **자동으로 건다** — 공통을 쓰는 화면은 손댈 것이 없다.

## 전수 조사 결과

| 구분 | 자리 | 처리 |
|---|---|---|
| 공통 `createField({f4})` | `fnSameAttrSyncPopupOpen.js` · `ws10_html.js` · `ws_html5_ws20_attr.js` · `Popups/ShortCutCreator/js/index.js`(3칸) | **자동** |
| 손으로 만든 값도움 | `WS10/WS10.js`(앱 이름 칸) · `js/fnAppCopyPopupOpen.js`(패키지 칸) | `attachF4` 직접 호출 |
| 대상 아님 | 검색 팝업 안의 「검색」 실행 버튼(`fnAppF4PopupOpen`·`fnF4SearchHelpPopup`·`OTRF4HelpPopup`) · 목록을 걸러내는 검색칸의 **장식 돋보기**(`fnStyleClassPopupOpen` — `span`, 누르는 버튼이 아님) · 확대 비율·메뉴·트리 아이콘 | 손대지 않음 |

`F4` 는 WS10·WS20·WS30 단축키 목록 어디에도 없다 — **충돌 없음**(실측).

`Popups/ShortCutCreator/js/_index_prev_20260709_1120.js` 는 `_` 로 시작하는 백업이라 제외(탐색 규칙).

### 코드 — 공통이 두 모양 다 자동으로 건다

`createField` 가 아이콘 값에 `magnifying-glass` **또는 `clone`** 이 들어 있으면 `attachF4` 를 자동으로 붙인다.
그래서 **다른 AI 가 공통 팩토리만 쓰면 저절로 지켜진다.**

그에 따라 어제(=앞 절) 화면 2곳에 직접 넣었던 `attachF4` 호출은 **중복이라 걷어냈다**
(`ws_html5_ws20_attr.js` · `fnSameAttrSyncPopupOpen.js`).
공통을 안 쓰고 단추를 손으로 만든 앱 복사 팝업 패키지 칸만 직접 호출을 남겼다.

## 확인 — 「동일 속성 동기화」 창의 아이콘 값도움은 **아직 변환 안 됨** (2026-10-22)

장군님이 그 창의 `icon` 값 칸에서 `F4` 를 눌러 **안 열린다**고 하셨다. 콘솔 로그로 확인:

```
[W4+ pending] same-property sync icon F4 (callIconListPopup) not converted: icon
```

**F4 배선은 정상이다** — 누를 때마다 값도움 함수가 불린다.
그 함수(`_callInputF4Help`, `fnSameAttrSyncPopupOpen.js`)가 **아이콘 쪽은 미변환**이라 경고만 찍는다.
소스 주석: 「콜백형 아이콘 선택기는 HTML5 미변환(`fnIconListPopupOpener` 는 콜백 없는 외부창).
임의 대체 금지(원본에 없는 행위 방지) — 행의 미변환 F4 와 동일하게 경고만.」

**마우스로 그 단추를 눌러도 똑같이 경고만 난다** — F4 와 무관한, 원래 있던 미변환 자리다.

그 창의 값도움은 **아이콘 · 색 두 가지뿐**이고, **색 쪽만 변환돼 있다**(`fnColorPickerOpen`).
→ 테스트 항목을 **색 속성**(속성 이름에 `Color` 가 들어간 것)으로 고쳤다.

**미확인** — 어느 UI 에 `Color` 속성이 있는지는 서버 데이터라 확인하지 않았다.

## 후속 — 「동일 속성 동기화」 창의 아이콘 값도움 연결 (2026-10-22)

지시: 장군님 「icon 속성에 대한 동일 속성 동기화에서 F4 눌렀을 때 아이콘 팝업을 만들어줘」
→ 이어서 「**그냥 기존 아이콘 팝업 띄우고**, 아이콘 팝업 띄우는 게 두 가지잖아.
**콜백이 있는 거랑 없는 거랑** 차이 알아?」

### ★내가 틀렸던 것

앞서 이 자리에 **「콜백 없는 외부창이라 쓸 수 없다」** 고 소스 주석에까지 적어 두고 미변환으로 남겼다.
**함수 본문을 안 읽고 단정한 것이다.**

실제 `fnIconPreviewPopupOpener(fnCallback)`(`fnDialogPopupOpener.js` 1996행)는 **한 함수로 두 가지로 쓴다**:

| 부르는 법 | 무엇이 되나 | 쓰는 곳 |
|---|---|---|
| 콜백을 넘긴다 | 고른 아이콘을 `RTDATA` 로 돌려준다(값도움). 다른 자식창을 숨겨 아이콘 고르기부터 끝내게 한다 | 속성 영역 아이콘 F4 |
| 안 넘긴다 | 보여 주기만 한다 | 메뉴의 아이콘 미리보기 |

속성 영역(`ws_html5_ws20_attr.js`)은 **이미 콜백 모드로 쓰고 있었다.** 여기만 빠져 있었다.

### 고친 것 — `fnSameAttrSyncPopupOpen.js` 한 곳

`_callInputF4Help` 의 아이콘 갈래를 경고 한 줄에서 **콜백 모드 호출**로 바꿨다.
속성 영역과 같은 모양이다 — 아이콘 속성인지 확인 → 서버 허용 게이트(`UHAK900630`) →
busy 켜고 팝업 → 콜백에서 busy 끄고, 취소(`RETCD === "C"`)·빈 값이면 그대로 두고,
아이콘을 받으면 값 칸에 넣고 검증(`_onChangeValue`)을 태운다.

- 게이트를 둔 까닭: 그 화면이 없는 옛 서버가 있다(속성 영역 원본 4061행과 같은 조건).
  게이트에 걸리면 `GUARD_EXIT` 로그만 남고 아무 창도 안 뜬다 — 지금까지와 같다.
- `node --check` 통과.

### 버린 방법 — 원본 창을 그대로 옮기기

원본은 `design/js/callIconListPopup.js`(253줄, 인앱 팝업)를 쓴다.
그대로 옮기려면 **메인 화면에 SAP 아이콘 글꼴이 없어서**(로컬에 글꼴 파일 0건, 서버에서 받아야 함)
즐겨찾기 아이콘 창처럼 **iframe 을 끼워야** 했다 — 새 파일 4개.
장군님이 **이미 있는 창을 쓰라**고 하셔서 껍데기 1개만 만들고 멈춘 뒤 지웠다.

### 함정

**「콜백이 없다」고 적기 전에 그 함수 본문을 읽을 것.** 이 프로젝트의 팝업 여는 함수들은
`fnCallback` 유무로 동작이 갈리는 것이 여럿이다(`fnClientEditorPopupOpener`·`fnPackgSchpPopupOpener`·
`fnBindPopupOpener`·`fnIconPreviewPopupOpener`). 이름만 보고 「보여 주기 전용」으로 단정하면
멀쩡히 있는 기능을 새로 만들게 된다.

### 테스트 결과 — 통과 (2026-10-22)

장군님 테스트 `5G-3` **통과**. 「동일 속성 동기화」 창의 값 변경 칸에서 `F4` →
아이콘 고르는 별창이 뜨고, 고른 아이콘이 값 칸에 들어간다.

## 후속 2 — 「동일 속성 동기화」 창에 styleClass 값도움 **추가** (2026-10-22)

지시: 장군님 「속성에서 styleClass 도 F4 기능이 있는데, 동일속성 팝업에서는 F4 가 없냐?」
→ 원본 확인 보고 뒤 「**원본은 없는 게 맞다 우리는 추가해라**」.

### 원본은 어떤가 (확인 결과)

- 원본은 그 창의 값 칸 단추를 **속성 영역과 같은 기준**(`showF4`)으로 켠다.
  그 기준에는 `styleClass` 도 들어 있다(`uiAttributeArea.js` 5356행, 2026-04-20 추가분).
  → **원본에서도 단추는 뜬다.**
- 그런데 그 창의 F4 처리(`callSetSameAttrPopup.js` 398행 `callInputF4Help`)는
  **색과 아이콘 두 갈래뿐**이다. `styleClass` 는 어느 갈래도 안 탄다.
  → **원본은 단추만 뜨고 눌러도 아무 일이 없다.**

내 쪽은 단추조차 안 띄우고 있었다(아이콘·색일 때만 켰다). 그래서 **더하는 쪽**으로 갔다.

### 고친 것 — 파일 2개

**1. `fnStyleClassPopupOpen.js` — 값을 돌려주는 길을 냈다**

`fnStyleClassPopupOpen(is_attr, opts)` 로 두 번째 인자를 받는다.
`opts.onChange` 가 있으면 **속성에 쓰지 않고 바뀐 값만 돌려준다**.

- 왜 필요한가: 지금까지는 고른 클래스를 그 자리에서 `UIATV` 에 쓰고 커밋했다.
  동일 속성 동기화 창은 **「확인」을 눌러야** 고른 줄들에 한꺼번에 반영되는 구조라,
  그대로 쓰면 **확인 전에 UI 하나의 값이 먼저 바뀐다.**
- 속성 행을 건드리지 않게 **임시 값 그릇**으로 바꿔 끼웠다. 이 파일이 쓰는 칸은
  `UIATV` 와 `ISBND` 둘뿐이다(파일 안 전수 확인).
- **기존 호출처는 한 줄도 안 고쳤다** — 속성 영역은 두 번째 인자 없이 부르므로 전과 같다(실측 1곳).

**2. `fnSameAttrSyncPopupOpen.js` — 단추를 켜고 갈래를 더했다**

- 값도움 단추 조건에 `styleClass` 추가.
- F4 갈래에 `styleClass` 를 **색·아이콘보다 먼저** 넣었다 — 아이콘 검사에서 먼저 걸러지면
  거기서 끝나 버리기 때문이다.
- 고른 값은 「값 변경」 칸에만 넣고 검증(`_onChangeValue`)을 태운다. 반영은 「확인」이 한다.

`node --check` 둘 다 통과.

### 겹침 걱정은 없다

CSS 클래스 고르기 창도 `showModal()` 이다 — top layer 안에서는 **나중에 연 것이 위**라
「Propery 모두 바꾸기」 창 위에 제대로 뜬다(같은 날 색 고르기에서 겪은 top layer 함정과 다르다).

## 후속 3 — 「미리 정의된 CSS 사용」 창을 **확인 방식**으로 (2026-10-22)

지시: 장군님 「css 를 선택하자마자 콜백을 해서 속성에 값을 넣고 있는데, 그렇게 하지 말고,
css 를 선택하면 팝업 하단에 표시되면서 팝업 하단에 **확인 버튼**을 추가해서,
확인 버튼 누를 때만 선택한 css 정보를 콜백해 주는 방식으로 해줘」.

### 전에는 어땠나

클래스를 하나 고를 때마다 **그 자리에서** 속성값에 쓰고 커밋했다
(`_commit` → `fnWs20AttrChange`). 그래서 고르는 족족 미리보기가 다시 그려지고
**undo 에도 한 번씩** 쌓였다. 빼는 것도 마찬가지였다.

### 고친 것 — `fnStyleClassPopupOpen.js` 한 파일

1. **고르는 동안에는 아무 데도 쓰지 않는다.**
   `_commit` 을 `_applyLocal` 로 바꿨다 — **임시 값 그릇**만 고치고 화면을 다시 그린다.
   화면에서 고치는 값은 **언제나 임시 그릇**에 담는다(진짜 속성 행은 `oCtx.src` 에 따로 둔다).
   그 그릇에서 쓰는 칸은 `UIATV` 와 `ISBND` 둘뿐이다(파일 안 전수 확인).
2. **고른 것은 창 아래 값 바에 쌓여 보인다** — 이미 있던 칩 바가 임시 값을 보므로 그대로 동작한다.
3. **푸터에 「확인」을 더했다**(`A40`, 다른 창들과 같은 키). 「닫기」는 그대로 — **반영 없이** 닫는다.
4. `_confirm()` 신설 — 확인 때 **한 번에** 내보낸다.
   · 값을 돌려주는 모드 → 콜백에 값만 넘기고 닫는다.
   · 그냥 쓰는 모드 → 진짜 속성 행에 넣고 `fnWs20AttrChange` 커밋(실패 시 값 롤백) 후 닫는다.
5. 조회 모드이거나 바인딩 표현식이면 확인은 **그냥 닫기**다(값 바도 원래 숨어 있다).

덤: 미리보기 다시 그리기와 undo 가 **확인 한 번에 한 번만** 일어난다.

`node --check` 통과. `_commit` 잔여 0건.

### 내가 정한 것 (지시에 없던 부분)

**확인을 누르면 창을 닫는다.** 지시에는 닫는다는 말이 없었지만,
아이콘 창·색 고르기와 같은 결로 맞췄다. 닫지 말아야 하면 한 줄만 주시면 된다.

### 함정

이 창은 「동일 속성 동기화」 창에서도 쓴다(같은 날 추가). 거기서는 **확인이 두 번**이다 —
이 창의 확인은 「값 변경」 칸에 넣기만 하고, 실제 반영은 그 창의 확인이 한다.

### 테스트 결과 — 통과 (2026-10-22)

장군님 테스트 `5H-1` · `5H-2` · `5H-3` **전부 통과**.

- 클래스를 골라도 바로 반영되지 않고 창 아래에 쌓이며, **「확인」을 눌러야** 반영된다.
- **「닫기」** 로 나가면 반영되지 않는다.
- 「동일 속성 동기화」 창에서도 `styleClass` 값도움이 뜨고, 고른 값이 「값 변경」 칸에 들어간다.
