# 바인딩 창 parent 제거 — 원본이 이미 떼어 둔 구조를 이식

- 날짜: 2026-10-14
- 작업: 별창 parent 제거 26번(마지막)
- 대상: `www/ws30/ws10_20/js/fnDialogPopupOpener.js` `fnBindWindowPopupOpener`

## 무엇을 알게 됐나 — **원본이 우리보다 앞서 있었다**

원본 `U4A_WS3.0.0`(v3.6.4-3, 2026-06-12, PES)이 **이미 `oBrowserOptions.parent` 를 주석 처리**해
독립 창으로 띄우고 있었다. 까닭도 적혀 있다 — **바인딩 창 안에서 dialog 를 띄우면 호출한 창의
제목줄·툴바 드래그가 막힌다.** WS4.0 은 아직 `parent = CURRWIN` 이라 **뒤처져 있던 쪽이 우리였다.**

## 원본이 parent 를 빼면서 같이 넣은 것 3가지 (전부 이식)

| # | 무엇 | 왜 필요한가 |
|---|---|---|
| 1 | 호출한 창 id 로 **창 참조를 직접 보관** | 공통 `getCheckAlreadyOpenWindow` 는 `getChildWindows()` 기반이라 parent 를 떼면 못 찾는다 → 누를 때마다 창이 새로 뜬다 |
| 2 | 최소화·숨김이면 **되살린 뒤 focus** | parent 가 없으면 자동으로 안 올라온다 |
| 3 | 호출한 창이 **앱 이름 넣는 첫 화면으로 돌아가거나 사라질 때 직접 닫기** | parent 가 있을 땐 Electron 이 같이 닫아 줬다. 이제 아무도 안 닫는다 |

3번은 원본이 UI5 `NavContainer.attachAfterNavigate` 를 썼는데 HTML5 에는 그 이벤트가 없다.
화면 전환이 전부 `oAPP.fn.fnNavTo`(ws10_html.js) 한 곳을 지나므로 **그 함수를 한 번만 감쌌다.**
호출한 창이 사라질 때는 `pagehide` 로 닫는다(원본과 동일).

## 원본에 없는데 넣은 것 1가지 (장군님 지시 2026-10-14)

**되살릴 때 호출한 창 가운데로 자리를 다시 잡는다.** 원본은 처음 띄울 때만 가운데를 잡는다.
그러면 창을 구석으로 끌어 놓거나 메인 창을 다른 모니터로 옮긴 뒤 다시 부르면 **엉뚱한 자리에서 나타난다.**
→ `.analy/16` §2.6.3(별도 창은 늘 호출한 창 가운데) 적용.

## ★ 또 밟을 함정

- **원본이 더 앞서 있을 수 있다.** 「WS4.0 이 원본을 이식한다」는 전제로만 보면, 원본이 나중에 고친 것을
  놓친다. parent 관련은 **원본 쪽 주석의 날짜·버전(`@since`, `@version`)을 반드시 본다.**
- **parent 를 떼면 「이미 열림」 판정이 조용히 깨진다.** `getChildWindows()` 기반 공통 함수는 못 찾는다
  → 창이 계속 쌓인다. 창 참조를 직접 보관하거나 OBJTY 로 찾는 방식으로 **반드시 같이 바꾼다.**
- **parent 를 떼면 「부모 닫힐 때 같이 닫힘」도 사라진다.** 닫는 길을 직접 만들어 둬야 유령 창이 안 남는다.
