## 마지막 1건이 어떻게 풀렸나 (장군님 지적 — 「보내는 쪽 프론트 로직을 보라」)

응답 JSON 의 날짜·시각 칸에 따옴표가 붙는지를 두 번이나 「못 가린다」로 보고했다.
JSON 을 만드는 것이 method 가 아니라 **macro** 이고(살아 있는 줄은 macro, method 부르는 줄은 주석),
그 macro 가 든 자리를 **주소 6가지를 다 시도해도 이 도구로 못 읽었다**(404 / 500).

**안 읽어도 되는 길이 있었다** — 같은 JSON 만드는 자리를 쓰는 **다른 endpoint 의 원본(as-is) 프론트 코드**:

| 단계 | 확인한 것 | 자리 |
|---|---|---|
| 1 | 릴리즈 노트 endpoint 가 내려보내는 구조에 `ERDAT`(DATS 8) · `ERTIM`(TIMS 6) 이 있다 | `/U4A/WS000006` 139~140행 · 타입 = `DD03L` 조회 |
| 2 | **`init_prc` 와 똑같은 JSON 만드는 자리**를 쓴다 (`__SERIALIZE` macro = `/U4A/CL_JSON_HANDLE=>SERIALIZE`) | `/U4A/WS000006` 207·269행, macro 22~32행 (`/U4A/WS000001` 205~215행과 글자까지 같음) |
| 3 | 보내는 방법도 같다 | `/U4A/WS000006` 210·272행 → `/U4A/WS000001` 9195행 |
| 4 | **원본(as-is) 프론트가 그 값에 `substr` 를 쓴다** = 글자로 다룬다 | 원본 폴더 `www/ws30/ws10_20/Popups/releaseNotePopup/js/main.js` 275~280행 |
| 5 | 다른 화면도 같다 | 원본 폴더 `www/ws30/ws10_20/Popups/webDynConversionLog/Popup/views/vw_main/control.js` 514·516·658행 |

→ 따옴표가 없으면 그 값이 숫자가 되고 숫자에는 `substr` 가 없어 **그 자리에서 터진다.**
  두 기능은 지금 돌아간다 → **macro 는 따옴표를 붙인다.**

덧붙여 **보내는 쪽(프론트 → 서버)도 글자**임을 확인했다:
사본 폴더 `design/js/main.js` 137~140행(네 칸이 빈 글자) → `js/ws_events.js` 1418행(`JSON.stringify`)
→ `/U4A/WS000002` 1613~1625행(서버가 DATS·TIMS 칸이 든 구조로 읽는다).

## 버린 길 · 실패한 것

| 무엇 | 왜 버렸나 |

| class 의 Macros include 를 도구로 읽기 | 주소 6가지(`oo/classes/…/includes/macros`, `programs/includes/…CCMAC`, `programs/programs/…CCMAC`, 표준 SAP 쪽 같은 class) 전부 404 / 500. **이 도구로는 못 읽는다** |
