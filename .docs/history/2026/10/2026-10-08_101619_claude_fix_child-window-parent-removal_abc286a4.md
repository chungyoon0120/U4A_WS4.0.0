## 변경 내용

### 공통 — parent 에 기대던 세 가지를 브라우저키 비교로 갈아 끼움 (26곳 전체가 쓴다)

- `js/ws_common.js`: **같은 브라우저키의 별창 목록을 돌려주는 공통 함수**를 새로 넣었다.
  전체 창 중 브라우저키가 같고 **자기 자신이 아니고** 별창 종류 이름이 있는 것만 돌려준다.
  브라우저키가 없으면 로그를 남기고 빈 배열(값이 없어 그만둠).
- `js/ws_common.js`: 전체 창 기준 「이미 열린 창 찾기」에서 **주석 처리돼 있던 브라우저키 비교를
  살렸다** — 종류 이름만 보면 다른 메인 창의 같은 종류 팝업을 잘못 집는다.
- `js/ws_fn_02.js`: 뒤로가기 일괄 닫기 · busy 중 숨겼다 되살리기를 **자식 창 목록 대신
  브라우저키 비교**로 바꿨다. 메인 창의 자식창 맵 방식은 쓰지 않는다(두 갈래가 섞이면 못 찾는다).
- `js/ws_fn_02.js`: 뒤로가기에 안 닫히는 **예외 목록에 옵션 창·아이콘 목록을 추가**(장군님 지시).
- `js/ws_fn_02.js`: 예외 목록 비교가 **이름이 똑같을 때만** 걸러서 아이콘 목록이 안 걸렸다.
  실제 종류 이름이 `<이름>_<SYSID>` 형태였다 → **이름 뒤에 `_` 가 붙은 것도 같은 창으로** 본다.

## 변경 이유

**원본 WS3.0 은 별창 제목줄이 OS 기본이라 `parent` 지정이 맞았다.** 최소화해도 작업표시줄에서
다시 띄울 수 있었다. **WS4.0 은 모든 창을 커스텀 헤더(`frame:false` / `titleBarStyle:"hidden"`)로
바꿨다** — `parent` 를 두면 작업표시줄에 안 뜨고 제목줄도 없어서 **최소화한 창을 되살릴 길이 없다.**

★**이 영역은 「원본 1:1」 규칙의 예외다**(장군님 2026-10-08 확인). 별창 컨셉 자체가 달라졌다.
다른 영역은 원칙 그대로다.

**모달 창은 `parent` 를 남긴다** — 제목줄에 닫기만 있어 최소화 문제가 안 생긴다(전략1-② 결정).

## 영향 범위

- 뒤로가기 일괄 닫기 · busy 중 숨기기/되살리기 판단이 **parent 기준에서 브라우저키 기준으로** 바뀌었다
  → 26곳 전부가 이 공통 함수를 탄다.
- 「지금 이 창에서 연 별창만」 이 기준이다. **세션키(Electron `partition`, 로그인 단위)가 아니라
  브라우저키(메인 창 하나 단위)** 로 비교한다.
- 옵션 창은 뒤로가기에도 안 닫힌다(장군님 지시로 예외 목록에 넣었다).

## 참고 사항

장군님: "부모 지정이 빠져있다고해서 뒤로 가기 할때 안죽는게 정상이 아니야 **원본 버그였다**".

### 제가 틀렸던 것
1. **「모달인 별창은 모니터 선택 창 하나뿐」 — 틀렸다.** grep 패턴이 `modal:` 만 봐서
   `oBrowserOptions.modal = true` 형태를 놓쳤다. 다시 훑어 **6곳을 더 찾았다**(앱 가져오기/내보내기 ·
   U4A 정보 · 런타임 클래스 · 숏컷 링크 · 예제 열기 · 창 흐리게 보기). 진행현황에 정정 기록.
2. **아이콘 목록이 예외 목록에 안 걸렸다** — 실제 종류 이름에 `_<SYSID>` 가 붙어 있었다.
   비교를 prefix 허용으로 고쳐 해결.
3. **4번 비고에 「제목줄에 최소화·최대화·닫기 다 있음」이라 적었는데 틀렸다** — 값도움 모드에서는
   최소화 버튼을 숨긴다. 장군님 지적 후 정정.
4. **「옛 방식」이라고 썼다가 질책받았다.** 장군님: "그건 옛날께 아니라 실행처가 다른것 뿐이야".
   메뉴에서 누르는 아이콘 목록과 WS20 속성 값도움에서 누르는 것은 **같은 팝업이지만 동작이 다르다.**
5. **「결함표」라는 말을 지어냈다** → 질책. `결함` 으로 되돌렸다.
