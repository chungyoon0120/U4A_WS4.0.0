# 안티그래비티(agy)로 코딩 위임 — 지침서만 넘긴다

## 핵심 원칙 (이 스킬의 존재 이유)

- **Claude 는 소스 파일 내용을 읽어 로직을 분석하지 않는다.** 그건 전적으로 agy 의 몫이다.
- Claude 가 하는 일은 오직 **지침서(브리핑) 작성 + 위임 + 결과 검토**다.
  지침서에는 "**무엇을 만들지 + 어디를 참고하라(파일 경로·문서 절·차용할 기존 화면)**"만 담는다.
- agy 가 지침서를 받아 **참고 파일을 직접 열어 분석**하고, 트리를 그려야 하면 공통 UX 문서와
  기존 WS20 트리를 스스로 참고해서 **설계·코딩까지 완주**한다.
- 즉 **Claude=지도 제작자, agy=현장 굴착기.** Claude 는 땅을 파지 않는다.

## 언제 실행하나

- **사용자가 안티에게 위임하라고 명시할 때에만.**
  발동 문구: "안티야 …… 시켜/코딩해줘", "안티그래비티로 짜줘", "안티한테 시켜", "agy 로 해".
- 일반 코딩 요청(안티 언급 없음)에는 쓰지 않는다. Claude 가 직접 한다.

## 지침서(브리핑) 작성 방법 — Claude 가 할 일

지침서는 **참고 대상의 "위치"만** 집어준다. 그 위치를 **소스 내용 분석 없이** 알아내는 근거:

- **CLAUDE.md** — .analy 문서 목록, 프로젝트 규칙(공통 자산·토큰·반응형·`_`폴더 제외).
- **MEMORY.md 포인터** — "트리=`createTree`/`.u4a-tree`, 공통UX §3.7", "WS20 …" 등 위치 지표가 이미 다수.
- **`analy_index` / `analy_search` (MCP)** — 어떤 .analy 문서/절을 봐야 하는지 목록·절 번호를 얻는다.
- **Glob / 디렉터리 목록** — 기존 화면·원본(as-is) 소스 **파일 경로**를 찾는다(경로만, 내용 분석 X).

> 규칙: **경로·문서 절을 "찾아 인용"만** 하고, 구현 소스를 **열어 로직을 분석하지 않는다.**
> 분석이 필요하면 그 파일 경로를 지침서에 적어 agy 에게 시킨다.

### 지침서 템플릿 (scratchpad 에 `.md` 로 저장)

```markdown
# 안티 작업 지침서: <작업명>

## 1. 작업 목표
- 원본(as-is) 기능: <무엇을 변환/구현>
- 산출물(to-be): <어디에 만들지 — 파일/폴더 경로>

## 2. 반드시 먼저 읽을 표준 문서 (SSOT)
- .analy/00_개요_및_컨버전전략.md — 문서 인덱스
- .analy/13_AI_작업지시_가이드.md — 작업 방식·가드레일
- .analy/16_공통_화면UX_표준.md — 공통 표준 (해당 절: 예 §3.7 트리, §2.9 텍스트선택)
- .analy/<기능문서>.md — <절 번호>
- CLAUDE.md — 프로젝트 작업 규칙

## 3. 차용할 기존 소스 (동작하는 패턴 베끼기)
- 트리: 공통 `createTree`/`.u4a-tree`, 기존 WS20 트리 구현 <경로>
- <컴포넌트>: <경로>

## 4. 원본(변환 전) 소스 — SSOT
- <as-is UI5 소스 경로> — 속성 단위로 1:1 보존, 캡처는 샘플일 뿐

## 5. 지켜야 할 제약 (위반 금지)
- 공통 자산 소비(shell.css/bootstrap-skin.css/u4a-ui.js/tokens.css) — 새로 만들지 말 것
- 색은 tokens.css 의미 토큰만, hex 하드코딩 금지 / 문구는 메시지 키
- 반응형 필수(고정 px 폭 금지)
- `_` 로 시작하는 폴더는 백업·폐기 → 현행으로 인용 금지
- 잘리는 텍스트 툴팁, 오버레이/토스트는 공통 시스템 사용

## 6. 산출물 (만들/고칠 파일)
- <경로들만 명시. 그 외 파일 건드리지 말 것>

## 7. 완료 기준
- 기능 인벤토리 누락 0, 모든 설계 결정은 문서 절 번호로 근거
```

## 실행 방법

프로젝트 루트에서 러너를 실행한다. 러너가 지침서 경로를 프롬프트로 감싸 agy 에게
"이 지침서를 읽고 참고 파일을 직접 분석해 수행하라"고 지시한다.

```bash
node .claude/skills/antigravity-code/anti-code.cjs --brief "<지침서.md 경로>"
```

| 명령 | 동작 |
|------|------|
| `... --brief <지침서.md>` | 지침서 읽고 **계획만**(plan) — 기본 |
| `... --brief <지침서.md> --go` | 지침서 읽고 **실제 코딩**(accept-edits) |
| `... --brief <지침서.md> "추가 지시"` | 지침서 + 보충 한 줄 |
| `... "<짧은 지시>"` | 지침서 없이 즉석 지시(간단할 때만) |
| `... --go --yolo --brief <지침서.md>` | 편집 + 터미널 명령 무확인 |
| `... --model "<모델>" ...` | 모델 지정 |
| `... --add-dir "<경로>" ...` | 워크스페이스에 참고 폴더 추가(반복 가능) |
| `... --timeout 45m ...` | print 대기 타임아웃(기본 30m) |

모델(예): `Gemini 3.5 Flash (High)`, `Gemini 3.1 Pro (High)`,
`Claude Sonnet 4.6 (Thinking)`, `Claude Opus 4.6 (Thinking)`. 최신: `agy models`.

## 절차

1. **지침서 작성** — 위 근거(CLAUDE.md·MEMORY·analy_index·Glob)로 참고 위치를 모아
   scratchpad 에 `.md` 로 저장한다. **소스 내용은 분석하지 않는다.**
2. **계획 위임(기본)** — `--brief` 로 실행(=plan). agy 가 참고 파일을 직접 분석해 계획을 낸다.
   그 계획을 사용자에게 요약 보고한다.
3. **코딩 위임** — 사용자가 승인/요청하면 `--go` 를 붙여 재실행. agy 가 실제 편집한다.
4. **결과 검토** — `git status`/diff 로 변경을 확인하고, 무엇을 바꿨는지 요약한다.
   프로젝트 규칙 위반이 보이면 **맹목 수용하지 말고** 사용자에게 알린다.
   (agy 산출물이라도 공통 자산·토큰·반응형·`_`폴더 규칙 위반은 걸러낸다.)

## 안전 기본값

- 기본 `--mode plan` — 편집 안 함. 실제 편집은 `--go` 명시 시에만.
- `--yolo`(--dangerously-skip-permissions)는 터미널 명령까지 무확인 → 사용자가 콕 집을 때만.

## 사전 조건

- Antigravity CLI(`agy`) 설치·로그인. 러너는 `%LOCALAPPDATA%\agy\bin\agy.exe`,
  없으면 PATH 의 `agy` 를 자동 탐색한다.
- 반드시 **프로젝트 루트에서 실행** — agy 가 현재 디렉터리를 워크스페이스(분석 대상)로 잡는다.
