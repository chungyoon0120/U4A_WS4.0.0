# 노션 기록 (U4A WS4.0 UI5→HTML5)

이 프로젝트의 작업 내용을 노션에 정리·기록한다. **모든 대상은 상위 페이지
"U4A WS4.0 (UI5→HTML5) 프로젝트"(`394a2d4a-ab9f-8189-8670-edf3bd9aa570`) 밑에 이미 존재**한다.
새 상위 구조를 만들지 말고 아래 지정된 곳에만 기록한다.

## 도구

노션 MCP 서버 prefix = `mcp__5507cab0-049c-4195-98cd-a95e03aee563__`
- `notion-fetch` — 페이지/DB 읽기(기록 전 현재 상태 확인)
- `notion-create-pages` — DB에 행(page) 추가, 또는 하위 페이지 생성
- `notion-update-page` — 기존 페이지 본문/속성 갱신
- `notion-query-data-sources` — DB에서 기존 행 검색(중복 방지)

날짜는 오늘 날짜(시스템 `currentDate`)를 쓰고, 문구는 한국어로 작성한다.

## 1. 작업일지 (커밋·푸시 시)

`작업일지` DB(`collection://f079c722-dd23-4ad8-b569-09a5af95a61e`)에 **하루 = 한 행(페이지)**.

1. `git log`로 이번에 커밋/푸시한 커밋들(해시 짧게 + 메시지)과 날짜를 확보한다.
2. `notion-query-data-sources`로 오늘 날짜(`작업일` = `작업일지 YYYY-MM-DD`) 행이 이미 있는지 확인.
   - **있으면** `notion-update-page`로 본문에 오늘 커밋을 이어 붙이고 `커밋 수`를 갱신.
   - **없으면** `notion-create-pages`로 새 행 생성.
3. 속성:
   - `작업일` (title) = `작업일지 YYYY-MM-DD`
   - `date:날짜:start` = `YYYY-MM-DD` (single date, `is_datetime`=0)
   - `커밋 수` (number) = 이번 날짜 커밋 개수
   - `주요 분류` (multi_select, 해당되는 것만) = `로그인/서버리스트` · `공통 컴포넌트` · `WS20 디자인` · `USP 에디터` · `팝업` · `문서` · `안정화`
4. 본문 형식(기존 페이지 관례를 따른다):
   ```
   > 프로젝트: U4A WS4.0 — UI5→HTML5 컨버전
   > 커밋 N건
   ## 1. <주제>
   - <한 일 요약>
   ### 커밋 요약
   | 커밋 | 메시지 |
   | `해시` | 커밋 메시지 |
   ```

## 2. 개선 아이디어 / 기능 제안 (DB)

`collection://d3e0cc0d-565d-49d2-a5fa-d1c9f7fb5f0b`에 `notion-create-pages`로 행 추가. 속성:
- `아이디어` (title) = 한 줄 제목
- `분류` (select) = `신규 기능` · `기능 개선` · `UX/편의` · `성능` · `기타`
- `상태` (select) = 기본 `제안` (그 외 `검토중`·`채택`·`진행중`·`작업완료`·`보류`·`반려`)
- `우선순위` (select) = `높음` · `중간` · `낮음` (불명확하면 비워두거나 `중간`)
- `관련 화면·모듈` (text) = 예: `WS20 속성 편집기`, `공통 트리`
- `date:제안일:start` = 오늘 (single date)
- `상세` (text) = 배경·제안 내용. 길면 본문에 상세 서술.

## 3. UI5 레거시 잠재 버그 (DB)

기존 원본(UI5) 소스의 버그·이상 동작 언급 시 `collection://81bf4299-b54b-44d8-b7ef-3bc2ec15d81b`에
`notion-create-pages`로 행 추가. 속성:
- `현상` (title) = 증상 한 줄
- `재현·상세` (text) = 재현 절차·상세
- `화면·모듈` (text) = 예: `WS20 디자인`, `바인딩 팝업`
- `원본 위치` (text) = 파일 경로·함수명 등 근거 위치
- `심각도` (select) = `높음` · `중간` · `낮음`
- `컨버전 처리` (select) = 기본 `미확인` (그 외 `그대로 이관`·`컨버전 시 수정`·`추후 수정 예정`·`해당없음(HTML5 무관)`)
- `date:발견일:start` = 오늘 (single date)
- `비고` (text) = 부가 메모

> 이 DB는 **원본(as-is) 버그** 전용이다. HTML5 전환 중 새로 생긴 버그는 여기 넣지 말고,
> 필요하면 개선 아이디어/작업일지로 구분한다.

## 4. UI5→HTML5 전환 현황 (페이지 갱신)

진척·남은 작업·완료 항목 변동은 `397a2d4a-ab9f-8121-a1d6-dbf47aef3000` 페이지를 **갱신**한다.
1. `notion-fetch`로 현재 본문을 읽어 구조(남은 작업 표·체크리스트·착수 순서)를 파악한다.
2. `notion-update-page`로 바뀐 부분만 반영한다:
   - 상단 요약(재검증 날짜, 남은 작업 건수)
   - "남은 작업 한눈에" 표의 건수
   - 완료된 항목은 체크리스트 `- [ ]` → `- [x]`, 필요 시 완료 목록으로 이동
3. 이 페이지는 관리용 미러다. **상세 근거의 SSOT는 GitHub `.report/status/` 보고서**이므로,
   현황 수치는 그 보고서/실제 소스와 어긋나지 않게 맞춘다.
