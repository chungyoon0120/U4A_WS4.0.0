# 코드(.js 등) 저장 직전 체크

- **원본(as-is) 1:1**. 원본에 없는 UX·동작·옵션 임의 추가 금지. 이상하면 보고만.
- **★★작업 폴더 안은 전부 고쳐도 된다 — 사본 폴더 포함**(장군님 지시 2026-09-01, 08-18·08-31 지시 대체). 진짜 원본은 **다른 폴더·다른 깃**으로 관리하므로 현재 프로젝트 폴더(`U4A_WS4.0.0`) 안은 **사본 폴더(`www/ws30/ws10_20/design/`)든 밖이든 수정 가능**. 진짜 원본 폴더 2곳만 **읽기 전용**.
- **★진짜 원본이 바뀌어도 통째로 옮기지 않는다.** 소스 동기화가 아니라 **「기능이 같으면 성공」** — 진짜 원본을 참고해 사본 폴더 로직을 고친다. 사본도 지금 실행·참조되고 이미 고친 데가 있어 무차별 교체 금지.
- 새 로직은 되도록 내 파일(`js/ws_html5_*.js` 계열)에 두되, **사본 폴더 안을 고쳐야 하면 고친다.** 원본 함수를 바꾸는 방법은 자유 — 사본 직접 수정 / 내 파일에서 같은 이름 재대입(원본 로드 뒤 재설치) 중 상황에 맞게 고른다.
- **★★★★한 줄에 한 문장 — 압축해서 짜지 말 것**(장군님 지시 2026-10-21 「인라인으로 좀 짜지 말고 가독성있게
  짜라고 했잖아 … compress 하냐?」 · 「말 안하면 또 개판이네」 — 2026-10-21 하루에 두 번 지적받았다).
  **저장 직전에 내가 쓴 줄을 다시 보고, 아래에 하나라도 걸리면 풀어쓴 뒤 저장한다.**
  1. `try { ... } catch (e) { ... }` 를 **한 줄에** 쓰지 않는다 — `try` · 본문 · `catch` · 본문을 줄로 나눈다.
  2. `if (조건) { return x; }` 처럼 **중괄호 안에 문장을 넣어 한 줄로** 만들지 않는다. 줄을 나눈다.
  3. **중첩 함수를 한 줄에** 넣지 않는다(`fn(e, function () { g(a, b, c); })` ← 금지).
  4. **같은 모양이 3줄 넘게 되풀이되면 표(객체)로 빼고 반복으로 채운다.** 줄마다 복붙하지 않는다.
  5. 같은 `catch` 안 내용이 되풀이되면 **작은 함수 하나로 뺀다.**
  ★예외 없다. 기존 소스가 그렇게 돼 있어도 **내가 새로 쓰거나 고치는 줄**은 풀어쓴다.
- **★★★★항상 처리 순서를 먼저 정하고, 그 순서대로 프로세스를 짠다**(장군님 지시 2026-10-27).
  **코드를 쓰기 전에 「무엇을 어떤 차례로 하는가」를 번호로 적는다.** 그 번호가 곧 코드의 차례다.
  1. **순서의 기준은 사용자가 보는 차례다** — 화면이면 **칸이 놓인 위아래 순서**, 흐름이면 **사용자가 겪는 차례**.
     내 코드 안의 묶음(검사 종류별·파일별·함수별)으로 묶지 않는다.
  2. **한 줄기로 간다.** 같은 일을 종류별로 쪼개 두 번 돌리지 않는다 — 쪼개면 순서가 깨진다.
  3. **첫 오류에서 멈춘다.** 전부 검사해 전부 표시하고 그중 하나를 고르면, 사용자가 보는 차례와 어긋난다.
  4. **고친 뒤 그 번호대로 다시 읽어** 차례가 맞는지 확인한다.
  ★실제 사고(2026-10-27, 쇼컷링크 생성 창): 입력 검사를 **「빈 칸인가」 전부 → 「서버에 있나」** 두 단계로
  쪼개 놨다. 맨 윗칸(앱 ID)에 **없는 앱 ID** 를 넣으면 값은 있으니 1단계를 통과해, **아래쪽 저장 경로**가
  첫 오류로 잡혀 커서가 거기로 갔다. 장군님 지적 — 「오류 체크는 위에서부터 순차적으로 해서 체크가
  성공하면 그 다음을 순차적으로 체크해서 오류 발생되면 커서를 주면 되잖아」.
- **★★★★고치기 전에 영향도부터 — 영향도 분석 없이는 바꾸지 않는다**(장군님 지시 2026-10-26
  「지금 무조건 바꾸는거보단 **영향도를 반드시 최우선으로 고려**해야된다」).
  **구조가 잘못된 것을 알아냈다고 바로 고치는 것이 아니다.** 고칠 자리를 여러 곳에서 부르고 있으면,
  **부르는 곳 전부를 한 줄씩 읽어 만든 표를 먼저 내고 보고**한다. 표가 없으면 고칠 수 없다.
  1. 부르는 곳을 **전수**로 뽑는다 — 범위는 `www` 전체다(`js/` 내 것 · `design/` 원본 사본 · `Popups/` 별창).
  2. 표에 **자리마다** ① 지금 무엇을 하나 ② 바꾸면 무엇이 달라지나 ③ 그 자리에 그것이 필요한가 를 적는다.
  3. **「전수」라고 말하기 전에 모든 줄을 눈으로 분류**한다 — 건수(`grep -c`·`wc -l`)만 세면 주석·정의가 호출로 섞인다.
     실제 사고(2026-10-23): 같은 전수 조사를 세 번 해서 28 → 33 → 31 로 수치가 두 번 바뀌었다.
  4. **무엇으로 확인할지(테스트 항목)를 고치기 전에 먼저 적는다.**
  ★영향도가 큰 것과 작은 것이 섞여 있으면 **작고 영향도 0 인 것부터 따로 떼어** 한 덩어리씩 보고하고 지시를 받는다.
  ★판정이 한 번 바뀌면 그건 1·3 을 안 지킨 것이다. 무엇을 안 보고 말했는지 같이 밝힌다.
- **★★★★기존 소스를 고칠 때 지킬 절차**(장군님 지적 2026-10-20 「신규 로직은 잘 짜는데 **수정은 진짜 못하더라** —
  영향도 검사도 안 하고 소스를 대충 보고 끝까지 확인 안 하고, 대충 추측해서, **함수 이름만 보고 유추해서** 작업한다」).
  1. **고칠 함수의 선언 줄과 본문 전체를 눈으로 읽는다** — 이름·인자 이름·`async` 여부·`return` 값.
     ★함수 이름으로 무엇을 하는지 판단하지 말 것(실제 사고: 이름에 `createUIInstance` 가 들어 있다는 것만 보고
     미리보기를 바꾸는 자리로 넣었는데, 실제는 글자를 만들어 `return` 하는 함수였다).
  2. **그 함수를 부르는 곳을 전부 찾아 한 줄씩 읽는다** — 반환값을 쓰나 · `try/catch` 로 감쌌나 ·
     **루프 안인가** · **연달아 두 번 부르나** · 뒤에 오는 코드가 완료를 전제하나.
  3. **일괄 치환(정규식)은 건수를 세어 예상과 맞는지 확인**한다. 안 맞으면 멈추고 어디가 더 잡혔는지 본다.
  4. **가정·추측 방어 로직을 넣지 않는다** — 안 타는 분기는 죽은 코드다(실제 사고: async 함수에
     「혹시 동기 반환이면」 분기를 넣었다).
  5. `node --check` 는 **최소 조건**이다 — 문법이 맞아도 동작은 깨진다.
  ★동기 함수를 `async` 로 바꿀 때 특히: **호출처의 `try/catch` 는 async 예외를 못 잡고**,
   루프·연속 호출은 재진입 가드에 걸려 **두 번째부터 값이 누락**된다.
- **★★백업 파일을 만들지 말 것**(장군님 지시 2026-10-06, 앞의 「고치기 전 백업(`_` 접두)」 지시를 **대체**).
  **git 이 백업이다** — 잘못되면 커밋에서 되돌리면 된다. `_` 접두 사본을 만들면 폴더가 지저분해지고
  그걸 안 올리려고 `.gitignore` 에 확장자를 하나씩 예외 넣는 짓까지 따라붙는다. 전부 하지 않는다.
  대신 **고치기 전에 커밋이 깨끗한지 확인**하고, **왜 고쳤는지 주석**은 그대로 남긴다.
- **★★★UI 추가·변경·삭제 프로세스의 "마지막 로직"은 항상 이것이다**(장군님 지시 2026-10-20):
  **① 미리보기에 반영 → ② 미리보기 렌더링 종료 감지(`setAfterRendering` await) → ③ busy off.**
  예외 없다. ②를 빼고 ③을 먼저 하면 다 안 그려진 화면에 조작이 열린다. ①②③ 사이에 다른 로직을 끼우지 않는다.
- **★★★미리보기를 바꿨으면 다 그려진 뒤에 busy 를 끈다**(장군님 지시 2026-10-20).
  미리보기를 바꾸는 호출 8종(`previewUIsetProp`·`addUIObjPreView`·`prevRemoveUiObject`·`moveUIObjPreView`·
  `createUIInstance`·`reCreateUIObjInstance`·`destroyExcepChild`·`redrawUIScript`) 중 하나라도 쓰면
  **`getTargetAfterRenderingUI` → `getDomRef()` 확인 → `setAfterRendering` 등록 → 바꾸기 → `rerender()` →
  `await` → `renderingRichTextEditor` 묶음 `await` → 그 뒤에 busy off** 순서를 반드시 넣는다.
  `getDomRef()` 확인을 빼면 영영 안 끝난다. 기다릴 대상은 **부모**다(고른 UI 자신에 걸면 신호가 안 온다).
  원본 모듈 `design/js/previewRender/setOnAfterRender.js` **수정 금지**. SSOT=`.analy/05_디자인영역.md` §4-3.

- **★★★★busy 는 예외 없이 공통 busy 만 쓴다 — 모든 화면 · 모든 영역 · 모든 별창**(장군님 지시 2026-10-16
  「바인딩창 뿐만 아니라 모든 화면, 영역에는 반드시 공통 busy 를 사용해야한다.. 반드시!!」).
  - 메인 창 안 = `parent.setBusy("X")` / `parent.setBusy("")`.
  - **별창(BrowserWindow) 도 예외가 아니다** — `<head>` 에 `theme/u4a-busy.css` + `theme/u4a-busy.js` 를 로드하고
    **`U4ABusy.show()` / `U4ABusy.hide()`**.
  - **금지**: 자체 스피너 · `aria-busy` 흐리기 · `position:fixed`+z-index 겹침 div · 화면마다 다른 busy 이름.
    부득이할 때도 **반드시 `<dialog>` + `showModal()`**. 평범한 `div` 는 **절대 금지** —
    `showModal()` 팝업이 top layer 라 **busy 가 그 뒤로 숨는다**(2026-10-16 바인딩 창 실제 사고).
  - **왜**: busy 모양·동작을 바꿀 때 **`theme/u4a-busy.js` · `u4a-busy.css` 두 개만 고치면 전체가 바뀌게** 하려는 설계다
    (장군님 2026-10-16). 창마다 자기 busy 를 두면 바꿀 때마다 창 수만큼 고쳐야 하고 빠뜨린 창이 생긴다.
  - SSOT = `.analy/16_공통_화면UX_표준.md` §2.10.
- **★★★★시간이 지났다고 busy 를 강제로 끄지 않는다 — fail-closed**(장군님 결정 2026-10-22
  「차라리 오류가 나서 busy 가 안 꺼지는 게 더 낫지, 괜히 일정 시간 지났다고 강제로 껐다가
  다른 액션에서 꼬이거나 데이터 잘못되면 책임 누가 질 건데?」 · 「제일 리스크는 잘못된 데이터가
  저장되버리면 이거 복구하기도 힘들잖아 매번 백업하는 전략이 있는것도 아니고」).
  - busy 의 목적 = **하나의 요청이 끝날 때까지 중복 요청을 막아 프로세스가 꼬이지 않게** 하는 것.
    **화면 그리기도 그 요청의 일부**다 — 다 안 그려졌는데 끄면 목적이 깨진다.
  - **멈춘 것처럼 보이는 편이 잘못된 데이터가 저장되는 것보다 낫다.** 못 끝내면 **켠 채로 둔다.**
  - 시간 상한은 **끄는 기준이 아니라 「너무 오래 걸린다」고 한 번 알리는 기준**으로만 쓴다
    (`theme/u4a-busy.js` `SLOW_WARN_MS`). 타이머로 busy 를 푸는 폴백을 만들지 말 것.
- **★★★모든 처리 로직은 시작 맨 위에서 busy 부터 켜고, 중간에 끄는 코드는 없고, 최종 완료에서만 끈다**(장군님 지시 2026-09-15). 새창·팝업·서버 호출만이 아니라 **어떤 처리 과정이든** 조작부터 막고 시작한다. ① 증상 자리가 아니라 **그 처리의 시작점·끝점(성공 끝·실패 끝·조기 return 전부)을 소스로 먼저 찾는다** ② 시작점 첫 줄에서 켠다 ③ 시작~끝 사이에 불리는 함수 안의 busy 끄기 = **중간 해제 → 없애고 끝점으로 몬다** ④ 끝점마다 끈다. 실제 사고: 새창 busy 를 흐름이 안 지나는 곳·중간 자리에 넣고, 첫 화면 그리기 도중 busy 를 끄는 코드를 못 봤다(2026-09-15). - **★팝업은 뜨자마자 무조건 busy 부터 켜고 시작, 준비 완료되면 프로세스 가장 마지막에 끈다**(장군님 지시 2026-09-09). 중간에 끄지 말 것 — 응답 오자마자 끄면 값 채우기·오류 표시·확인창 뜨는 동안 조작이 열린다. **겹치는 처리는 깊이(개수)를 세어** 깊이 0 일 때만 실제로 끈다(안쪽이 끝났다고 바깥 도중에 풀리면 안 됨). 부모 창이 방송으로 알려오는 바쁨은 깊이와 **섞지 말고 따로** 기억(짝 안 맞으면 영영 안 풀림). `sendAjax` 는 **실패용 콜백(7번째 인자)을 반드시** 넘길 것 — 안 넘기면 통신 실패 시 성공 콜백이 안 와서 busy 가 안 풀린다. **busy 켠 채 모달 팝업을 열면 팝업이 busy 위로 올라가므로**(top-layer=showModal 호출 순서) 연 직후 busy 를 껐다 켜서 맨 위로 올린다.
