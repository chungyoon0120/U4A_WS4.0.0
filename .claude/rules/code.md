# 코드(.js 등) 저장 직전 체크

- **원본(as-is) 1:1**. 원본에 없는 UX·동작·옵션 임의 추가 금지. 이상하면 보고만.
- **★★작업 폴더 안은 전부 고쳐도 된다 — 사본 폴더 포함**(장군님 지시 2026-09-01, 08-18·08-31 지시 대체). 진짜 원본은 **다른 폴더·다른 깃**으로 관리하므로 현재 프로젝트 폴더(`U4A_WS4.0.0`) 안은 **사본 폴더(`www/ws30/ws10_20/design/`)든 밖이든 수정 가능**. 진짜 원본 폴더 2곳만 **읽기 전용**.
- **★진짜 원본이 바뀌어도 통째로 옮기지 않는다.** 소스 동기화가 아니라 **「기능이 같으면 성공」** — 진짜 원본을 참고해 사본 폴더 로직을 고친다. 사본도 지금 실행·참조되고 이미 고친 데가 있어 무차별 교체 금지.
- 새 로직은 되도록 내 파일(`js/ws_html5_*.js` 계열)에 두되, **사본 폴더 안을 고쳐야 하면 고친다.** 원본 함수를 바꾸는 방법은 자유 — 사본 직접 수정 / 내 파일에서 같은 이름 재대입(원본 로드 뒤 재설치) 중 상황에 맞게 고른다.
- 어느 쪽이든 **고치기 전 백업**(`_` 접두)과 **왜 고쳤는지 주석**을 남긴다.
- **★팝업은 뜨자마자 무조건 busy 부터 켜고 시작, 준비 완료되면 프로세스 가장 마지막에 끈다**(장군님 지시 2026-09-09). 중간에 끄지 말 것 — 응답 오자마자 끄면 값 채우기·오류 표시·확인창 뜨는 동안 조작이 열린다. **겹치는 처리는 깊이(개수)를 세어** 깊이 0 일 때만 실제로 끈다(안쪽이 끝났다고 바깥 도중에 풀리면 안 됨). 부모 창이 방송으로 알려오는 바쁨은 깊이와 **섞지 말고 따로** 기억(짝 안 맞으면 영영 안 풀림). `sendAjax` 는 **실패용 콜백(7번째 인자)을 반드시** 넘길 것 — 안 넘기면 통신 실패 시 성공 콜백이 안 와서 busy 가 안 풀린다. **busy 켠 채 모달 팝업을 열면 팝업이 busy 위로 올라가므로**(top-layer=showModal 호출 순서) 연 직후 busy 를 껐다 켜서 맨 위로 올린다.
- **★서버에 다녀오는 모든 행위·저장하는 행위 등 중요한 항목은 시작 전에 반드시 busy 를 켠다**(장군님 지시 2026-09-09). 처리 도중 사용자 조작을 막아 버리는 것이 가장 단순한 로직 — 연타·중복요청·중간상태 꼬임을 개별 플래그로 막는 것보다 안전하다. **자식창(별도 BrowserWindow)이 공통 부품을 쓸 땐 특히** 공통 이름(`oAPP.common.fnSetBusyLock`)을 자기 busy 로 이어 주는 한 줄을 반드시 둘 것 — 안 두면 호출이 조용히 실패해 busy 가 아예 안 뜬다(쇼컷링크 생성 창 앱 검색 도움말 사례).
- **busy**: on 걸면 모든 종료 분기(early return/취소/에러)에서 off 짝 필수. 성공은 WS20 왕복이 해제(자기해제 금지). 닫기버튼=`_setBusy` 대칭.
- **★비동기·화면전환은 WP1 방식으로**(장군님 필수 지시 2026-08-10, 반드시 준수): ① **로딩표시(busy)는 화면 렌더·데이터 구성·전환 애니메이션이 완전히 끝난 뒤에 끈다.** 중간에 미리 끄면 그 틈에 버튼 연타가 들어와 상태가 꼬인다(백지 등). ② **예약한 뒷정리 타이머(setTimeout 등)는 핸들을 저장**하고, 다음 동작 시작 시 **먼저 clearTimeout** 해 겹침을 막는다(직렬화). ③ **화면 전환은 완료를 콜백/Promise로 알리고**, 후속(잠금해제·busy off·복원)은 그 **완료 후**에만 실행. 원본 UI5의 afterNavigate/NavContainer 직렬화를 HTML5에서 명시 재현.
- **★`window.confirm` · `window.alert` · `window.prompt` 절대 금지**(장군님 지시 2026-09-02). 브라우저 기본 대화상자는 테마·다국어·드래그가 안 먹고 모달창 위에도 딸판으로 뜨며 앱 전체를 멈춰 세운다. 확인창은 **공통 `U4AUI.confirm` / `fnConfirmBox` 만** 쓴다. 공통이 없거나 `<dialog>.showModal()` 이 실패하면 **fallback 을 만들지 말고** `접두-번호` 오류코드로 표면화 + **fail-closed**(진행하지 않음 = NO/CANCEL)로 종료한다.
- **★★남이 만든 라이브러리는 한 글자도 고치지 말 것**(장군님 지시 2026-09-08). 글꼴 아이콘·글 편집기·암호 처리·내려받기 도구 등 **바깥에서 받아온 것 전부.** 거기에 문제가 있으면 **버전을 올리거나 다른 판을 받는 것이 답**이지, 내가 그 안을 고치는 것은 월권이다. 그 코드가 왜 그렇게 돼 있는지 나는 모른다.
  - **판별은 폴더 이름만으로 하지 말 것** — 실제로 그렇게 하다가 글꼴 아이콘 14개·글 편집기 6개·암호 처리 1개·내려받기 도구 1개를 건드렸다(2026-09-08). **파일 앞머리의 저작권 표시**와 **줄여 놓은 배포용 파일(`.min.js`)** 인지까지 반드시 확인한다.
  - **여러 파일을 한꺼번에 자동으로 고치는 작업은 대상 목록을 먼저 뽑아 보고**한 뒤에 실행한다. 훑어서 바로 고치지 않는다.
- 공통 자산(shell/bootstrap-skin/u4a-ui/tokens) **직접 수정 금지** → 스코프 override.
- **팝업(`<dialog>`) 만들면 공통 3종 세트 항상 같이**: `makeDialogDraggable`(헤더드래그) + `makeDialogRecenter`(헤더 더블클릭 중앙복귀) + `makeDialogResizable`(우하단 grip). 원스톱 생성기 없음—각자 붙이므로 하나 빠뜨리기 쉬움(S5에서 recenter 누락). 비모달 `show()`면 z-index+배경+fixed중앙도 세트.
- 하드코딩 hex 금지, `color-mix` 금지(Chromium 93).
- 메시지: 기존은 **원본(as-is) 키 참조**, 원본에 없고 지시 없으면 `ZMSG_WS_COMMON_001`(포화 임박→추후 `_002`). 임의 문구·키 생성 금지, 필요 키 보고.
- **메시지 DB(`MESSAGE_CLASS.db`) 직접 INSERT·수정 금지** — 문구는 **장군님이 직접** 넣는다. 나는 메시지 함수(`getWsMsgClsTxt`/`fnGetMsgClsText`)로 **키(번호)만 배선**. 승인 선택지에 "등록 포함"이라 적혀 있어도 DB 파일 쓰기는 월권.
- **공통 메시지 함수를 화면 래퍼로 감싸도 원본 동작 그대로** — `_wsC`/`_msgM` 등은 결과 그대로 통과(미등록/실패=`ZMSG_WS_COMMON_001|번호`). "`|`" 감지해 번호만 남기는 등 임의 가공 금지(원본과 달라지면 장군님이 인지 못 함).
- 저장 후 **`node --check`**. 오류 삼킴·조용한 catch 금지(오류코드+표면화).
- **★예외처리 표준 준수**(SSOT=`.analy/19_예외처리_크리티컬오류_표준.md`, 실무규약=`.works/DEV_STANDARD_오류처리.md`): 예측 가능한 입력·유효성 오류 → 안내 메시지+정상 return / 예측 불가 시스템 오류(catch 구간·필수 의존성 없음) → **삼키지 말고 `접두-번호` 내부 오류 코드**로 표면화. 콘솔엔 `[코드] 어느 자리 + 예외 원문`, 화면엔 `[코드] + 기존 메시지 키 문구`(예외 원문·스택은 화면 노출 금지). 접두는 파일/영역마다 유일, 번호는 그 파일 안에서만 증가(접두 사전=실무규약 문서에서 한 곳 관리, 파일 상단에 `// 오류코드 접두: XXX / 다음 번호: NNN`). 저장·실행처럼 반드시 성공해야 하는 프로세스는 전송 前 구간 하나라도 터지면 **서버로 안 보내고 중단**(fail-closed). 전수 개조 금지—신규/수정분부터 점진.
