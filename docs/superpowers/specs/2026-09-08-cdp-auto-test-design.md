# CDP 자동 반복 테스트 (WS10 편집모드 진입→뒤로가기) 설계

- 날짜: 2026-09-08
- 대상: `test/cdp-auto-test/`
- 목적: 이미 켜져 있고 로그인까지 끝난 U4A Workspace 화면(빌드본/개발본 공통)에 CDP로 붙어서,
  "WS10에서 편집모드 진입 → 진입 완료되면 즉시 뒤로가기"를 사람이 단축키를 누른 것과 동일한 방식(키 이벤트 발사)으로
  **무제한 반복**시키고, 그 과정에서 나는 오류를 잡아 로그로 남기는 자동 반복 테스트 도구.

## 1. 전제 조건

- 대상 PC에서 U4A Workspace 앱이 **원격 디버깅 포트가 열린 채로 이미 실행 중**이고,
  **이미 로그인 + WS10 화면**까지 떠 있는 상태다. 앱 실행·로그인은 이 도구의 책임이 아니다.
  (근거: `electron/main.js:142` `configureRemoteDebuggingPort()` — 환경변수 `WS_REMOTE_DEBUG_HOST`가 있어야만
  `remote-debugging-port` 스위치가 켜진다. 이 환경변수 세팅과 앱 실행은 대상 PC에서 별도로 해둔다.)
- 이 도구는 **`test/cdp-auto-test/` 폴더 하나만 복사**해서 다른 PC에서 돌릴 수 있어야 한다.
  그래서 이 폴더 밖의 프로젝트 파일(예: `test/telegram_token.json`, `electron/lib/log/*`)을 참조하지 않는다.
  폴더 안의 모든 경로 참조는 **`__dirname` 기준 상대경로**로만 한다.
- 대상 PC에서 `cd test/cdp-auto-test && npm install` 한 번, 이후 `node edit-back-loop.js`로 실행한다.
  필요 라이브러리(`ws`)는 `test/cdp-auto-test/package.json`에 의존성으로 선언한다(외부 패키지 무의존 재구현 안 함).

## 2. 폴더 구성

```
test/cdp-auto-test/
  package.json           # 의존성: ws
  logs/                  # 실행 로그 파일이 쌓이는 곳 (레포에는 폴더만, 내용물은 git 무시)
  lib/
    cdp-client.js         # 창 찾기, 키 이벤트 발사, 화면 상태 읽기, 콘솔오류/스크립트오류/크래시 감시 — 공용
  probe.js                # ① 실측용 정찰 스크립트 (자동화 아님, 사람이 같이 눌러보며 값 확인)
  edit-back-loop.js       # ② 자동 반복 루프 (무제한)
```

## 3. ① 실측 스크립트 (`probe.js`)

로그인된 창(`/json/list`에서 `#Main` 타이틀 페이지, 기존 `.works/auto-test/login-smoke.js`가 쓰던 방식과 동일)을 찾아 붙어서,
화면 상태(`getCurrPage()`, `getAppInfo()` 등)와 편집모드 진입 단축키 후보를 실제로 눌러보며 콘솔에 찍어 확인하는 용도.
자동화 스크립트가 쓸 정확한 값(단축키, 판정식)을 이 단계에서 실측으로 확정한다. 이 문서 시점에서는 미확정.

## 4. ② 자동 반복 스크립트 (`edit-back-loop.js`)

**★2026-09-08 정정(장군님 지시)**: 창을 하나만 대상으로 하지 않는다. 로그인 후 WS10 화면 상태인
창을 **여러 개(3개·4개 등, 실행마다 개수가 다를 수 있음) 동시에 띄워둔 상태**에서 실행하며,
`edit-back-loop.js` 하나를 실행하면 **그 시점에 떠 있는 `#Main` 창을 전부 찾아, 창마다 각자
독립된 스코프로 CDP에 붙어 같은 반복을 동시에** 돈다. 실행 시작 후 새로 뜨는 창은 이번 범위에 넣지
않는다(시작 시점에 있던 창만 대상).

**흐름 (창마다 독립적으로, 무제한 반복, Ctrl+C로만 정지)**:
1. 그 시점에 떠 있는 `#Main` 창을 **전부** 찾는다(1개~N개)
2. 창마다 각각 CDP로 접속해 아래 사이클을 **동시에** 시작
3. 편집모드 진입 단축키를 **키 이벤트로 발사**(`Input.dispatchKeyEvent` — 내부 함수 직접 호출이 아니라
   실제 사용자가 단축키를 누른 것과 동일하게 재현)
4. 편집모드 진입 완료 판정될 때까지 폴링
5. 뒤로가기 단축키를 키 이벤트로 발사
6. WS10 복귀 판정될 때까지 폴링
7. 3번으로 돌아가 반복(그 창만 반복 — 다른 창에 영향 없음)

로그는 한 파일·한 콘솔에 같이 남기되, 어느 창인지 구분되게 창마다 번호(`[창1]`처럼)를 붙인다.

## 5. 오류 감시 · 로그

다음 세 가지 + 자동화 스크립트 자체의 예외까지, **텔레그램 전송 없이 전부 다음 두 곳에 남긴다**:
- 실행 중인 cmd 창에 콘솔 출력
- `test/cdp-auto-test/logs/`에 파일로 저장(실행 1회당 타임스탬프 붙은 로그 파일 1개, 매 사이클 결과 + 오류 내용 추가)

감시 대상 3가지 (대상 화면 쪽):
- 콘솔오류: CDP `Runtime.consoleAPICalled`(오류 타입)
- 스크립트 오류(처리 안 된 예외): CDP `Runtime.exceptionThrown`
- 화면 크래시: 대상 창이 `/json/list`에서 사라짐 감지

자동화 스크립트 자체 예외(CDP 연결 끊김 등 드라이버 버그)도 같은 로그에 남긴다.

오류가 잡혀도 **반복은 멈추지 않고 계속**한다(무제한 반복이 원칙). 단, 화면 크래시로 창 자체가 사라지면
그 시점 반복은 물리적으로 이어갈 수 없으므로 그 사실을 로그에 남기고 종료한다(재시작 로직은 이번 범위 밖).
