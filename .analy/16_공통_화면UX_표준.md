# 16. 공통 화면 UX 표준

> 모든 화면에 **공통으로 적용**되는 UX 표준(전역 규칙)이다. 특정 기능 문서(02~08)나
> 입력 가이드(15)보다 상위의 "모든 화면 공통" 기준이며, 화면을 새로 만들거나
> U4A WS → HTML5 로 변환할 때 항상 함께 적용한다.
> 관련: [12_테마_컨버전_전략.md](12_테마_컨버전_전략.md)(테마 토큰), [15_공통_입력UX_가이드.md](15_공통_입력UX_가이드.md)(입력칸), [06_팝업.md](06_팝업.md)(팝업 카탈로그), [02_로그인_서버리스트.md](02_로그인_서버리스트.md)(트리 기준)

## 0. TL;DR

1. 모든 화면은 **Bootstrap** 을 기준(베이스) 프레임워크로 사용한다.
2. 색·간격 등 **테마는 `tokens.css` 의미 토큰**으로 입힌다 (Bootstrap CSS 변수에 매핑). 하드코딩 금지.
3. 모든 메시지 박스·모달 팝업의 **헤더/푸터 높이는 각각 48px**.
4. 모달 팝업은 **드래그(이동) + 리사이즈(크기 조절)** 가능해야 한다.
5. 트리는 **공통 베이스 트리 `U4AUI.createTree`(`u4a-ui.js`)** 를 소비한다. 화면마다 재귀 렌더러를 새로 만들지 않는다(소스 단일화).
6. 스플릿바(분할 리사이저)는 **공통 골격 `.u4a-splitter*`(`shell.css`) + 인접 재분배 드래그**를 소비하고, 모양은 **서버리스트 기준(가운데 그립 핸들)** 으로 통일한다.
7. 화면 문구는 **전부 SQLite 메시지 클래스 키 + 공통 추출 함수**로 표시한다(하드코딩 금지). 기존 키가 없는 신규 텍스트는 **임의 생성·임의 키 금지**, 모았다가 **신규 항목만 목록으로 제출** → 사용자가 번역·DB 입력·재실행.
8. 목록/그리드는 **공통 `.u4a-table`** 을 소비하고, **컬럼 헤더 정렬/필터 메뉴는 서버리스트 기준**(필터 input → 오름/내림 정렬 → 필터 초기화)으로 통일한다.
9. 🚫 **공통 자산(`shell.css`·`u4a-ui.js`·`tokens.css`)의 기존 로직/CSS 는 절대 직접 수정하지 않는다.** 화면이 다르게 보여야 하면 **화면 스코프 클래스로 그 위에 "덧대는"(override) CSS** 만 추가한다. 공통 자체를 바꿔야 할 일이면 먼저 **"승격" 여부를 사용자에게 묻고** 진행한다. (→ §0.5)
10. ⚠️ **`showModal()` 모달 위에 뭔가 안 보이면 z-index 말고 top layer 부터 의심.** 모달 위에서 보여야 하는 토스트·busy·툴팁·안내는 자기도 top layer(=`<dialog>.showModal()`)여야 한다. 모달 위 안내는 정보성이라도 `showMessage(...,"W"|"E")` 박스로. (→ §2.10)

## 0.5 공통 자산 불변 원칙 — "고치지 말고 덧대라" (최우선·필수)

> 이 원칙은 본 문서의 모든 항목보다 우선한다. 위반은 회귀(다른 화면 동반 파손)의 가장 흔한 원인이다.

- **공통 자산의 기존 로직/CSS 를 직접 수정 금지.** 대상: `theme/shell.css`(`.u4a-*` 공통 클래스), `theme/u4a-ui.js`(`U4AUI.*` 팩토리·헬퍼), `theme/tokens.css`(의미 토큰), Bootstrap 브리지. 이들은 **전 화면이 공유**하므로 한 줄만 바꿔도 무관한 화면이 깨진다.
- **화면이 다르게 보여야 하면 = 화면 스코프로 "덧댄다".** 공통 규칙을 고치는 대신, **화면 전용 클래스를 앞에 붙인 더 높은 specificity 의 override CSS** 를 화면 쪽(`*.css` 또는 팝업 주입 스타일)에 추가한다.
  - ✅ 예: `.u4aMimeTree .u4a-tree__row[data-u4a-tree-split] { justify-content: flex-start; }` (MIME 트리 안에서만 공통 `space-between` 무력화)
  - ✅ 예: `.u4aWs30Tree .u4a-tree__label { flex: 1 1 0; }` (WS30 트리 컬럼정렬용 덧대기 — 동일 패턴)
  - ❌ 금지: `shell.css` 의 `.u4a-tree__row { … }` / `.u4a-tree__label { … }` 자체를 수정
  - ❌ 금지: `u4a-ui.js` 의 `createTree`/`createField` 등 공통 함수 동작을 화면 요구로 바꾸기
- **공통 함수는 "옵션/슬롯/후크"로 확장**한다(직접 수정 X). `createTree` 의 `slotLead/slotTrailing/rowHook/isExpanded` 등 제공된 확장점만 쓴다(§3.3 / §3.4 / §3.4.1).
- **정말 공통을 바꿔야 한다면 = 먼저 "승격(promotion)"을 사용자에게 묻는다.** 어떤 UX 가 전 화면 공통 가치가 있다고 판단되면, 임의로 공통을 고치지 말고 **(a) 공통에 옵션/클래스로 승격할지 (b) 화면 스코프로만 둘지** 를 사용자에게 확인한 뒤 진행한다. 승격으로 결정되면 그때 공통 + `shell.css` 공통 클래스로 올리고, 본 문서 해당 절의 "적용 현황"을 갱신한다.
- **점검 방법**: 작업 후 `git diff` 로 `shell.css`/`u4a-ui.js`/`tokens.css` 가 내 변경에 포함됐는지 확인한다(포함되면 원칙 위반 — 스코프 override 로 되돌린다). 화면 스코프 클래스(`grep`)가 공통 파일에 새지 않았는지도 확인.

## 1. 기준 프레임워크 — Bootstrap

- **모든 화면은 Bootstrap 을 베이스로 사용한다.** 레이아웃·그리드·버튼·폼 등 표준 컴포넌트는
  Bootstrap 컴포넌트/클래스를 우선 소비하고, 화면마다 새로 만들지 않는다.
- **테마는 토큰으로 입힌다.** `theme/tokens.css` 의 의미 토큰(색/간격)을 **Bootstrap CSS 변수
  (`--bs-*`)에 매핑**하여 적용한다. 색을 직접 hex 로 박지 않는다(드리프트 금지). 테마 단일 출처는
  [12_테마_컨버전_전략.md](12_테마_컨버전_전략.md).
- **공통 컴포넌트는 Bootstrap "위에" 얹는다.** 입력칸의 `.u4a-field`(clear/스피너 제거 등,
  [15번](15_공통_입력UX_가이드.md))과 `shell.css` 의 셸 스타일은 Bootstrap 베이스 위에서 동작하는
  프로젝트 공통 자산으로 유지한다. Bootstrap 과 겹치면 프로젝트 공통 컴포넌트 규칙을 우선한다.

> 주의: `.analy` 다른 문서에서 말하는 "bootstrap"은 대개 제거 대상인 **UI5 로더(`sap-ui-bootstrap`)**
> 를 뜻한다. 본 문서의 "Bootstrap"은 **CSS 프레임워크 Bootstrap** 을 가리키며 서로 다른 개념이다.

### 1.1 버튼 색 변형 · 비활성(disabled) 상태 (필수)

버튼은 공통 `.u4a-btn` 베이스 + **색 변형** 으로만 표현한다(화면별 커스텀 색 금지):
- `.u4a-btn` (중립) = 보조 액션.
- `.u4a-btn--emphasized` (파랑 accent) = 1차/주 액션(Bind/Create/Save/Confirm 등).
- `.u4a-btn--negative` (빨강) = Close/Cancel/Reject(원본 UI5 `ButtonType.Reject` — 정적 빨강 텍스트/테두리, hover 에 빨강 배경 채움 금지).
- `.u4a-btn--accent-outline` (accent 아웃라인) = 툴바/보조 액션(예: 리스트 Add). 투명 배경 + accent 테두리·텍스트·아이콘, hover/active 는 accent 정적 유지 + 중립 하이라이트만(negative 와 동일 컨셉의 파랑 아웃라인 판). 화면 스코프로 색 주지 말 것(=`.u4aWsecAdd` 같은 커스텀 대신 이 변형 소비). 첫 소비=fnWebSecurityPopupOpen White List Add.

**★ 행/트리 안 아이콘 액션(수정·삭제 등)의 색 위계(필수)** — 테이블/트리 행에 붙는 아이콘 버튼은 **파괴적(destructive) 액션만 상시 색**을 준다:
- **삭제(휴지통) = 상시 `var(--error)`**(공통 `--negative` 버튼과 동일 destructive 토큰, 테마대응). hover 도 `--error` 유지(공통 `:hover` 의 중립 `--text` 를 덮어야 함).
- **수정/일반(연필 등) = 중립 `--text-muted`** 유지 → 삭제만 도드라져 실수 방지 위계. hover 배경은 공통 `--hover-bg`.
- 레퍼런스 = WS20 트리 액션 `.u4aWs20TreeActBtn.del { color: var(--ws20-danger) }`, 소비 예 = 소스 패턴 팝업 `.u4aPattActBtn--del`(2026-07-09). ★`--negative` 는 **토큰이 아니라 버튼 클래스** — 색으로 쓰지 말 것(미정의 → 폴백으로 빨강 안 나옴). destructive 색 토큰 SSOT = **`--error`**.

**★ 비활성(disabled) 규칙 — 색 강조 버튼은 "원색 계열 유지 + opacity 로만 흐리게"**(회색으로 죽이거나 "테두리만 색" 남기면 안 됨. 사용자 지적 2026-07-06):
- 공통 `shell.css .u4a-btn:disabled` 는 `background/color` 를 `--disabled-*`(회색)로 덮고 `opacity`(`--disabled-opacity`)를 준다. 그런데 **`border-color` 는 안 덮어서**, 색 변형(`--emphasized`/`--negative`)이 disabled 되면 **채움은 회색인데 테두리만 원색**으로 남는 어색한 모습이 된다.
- **해결(SSOT=`bootstrap-skin.css`)**: 각 색 변형의 `:disabled` 를 두어 **원색(bg/border/color)을 재지정**한다 → 공통 `:disabled` 의 `opacity` 만 그대로 먹어 "흐린 파랑 / 흐린 빨강" 이 된다.
  ```css
  .u4a-btn--emphasized:disabled { background: var(--u4a-accent); border-color: var(--u4a-accent); color:#fff; }
  .u4a-btn--negative:disabled  { background: transparent; border-color: var(--error); color: var(--error); }
  .u4a-btn--accent-outline:disabled { background: transparent; border-color: var(--accent); color: var(--accent); }
  ```
  (rest+hover 는 `shell.css`, `:disabled` 는 `bootstrap-skin.css` — `--emphasized`/`--negative` 와 동일 분담.)
  (공통 `.u4a-btn:disabled` 와 동일 specificity 지만 `bootstrap-skin.css` 가 늦게 로드돼 이긴다. `opacity` 는 재지정하지 않아 공통 값이 적용된다.)
- **★ 새 색 강조 변형을 추가할 때(예: 초록 `--positive`)도 동일하게 그 변형의 `:disabled` 를 함께 추가**해 원색+opacity 를 유지한다. 안 하면 또 "회색 채움 + 원색 테두리" 버그가 재발한다. 비활성 테두리를 `--line`(회색)으로 중립화하는 방향은 **틀림**(원색을 유지해야 함).

### 2.1 헤더·푸터 높이

### 2.1.1 확인 다이얼로그 버튼 = 아이콘만(공통 UX)
- 공통 확인 다이얼로그(`U4AUI.confirm` = `sap.m.MessageBox` 대응, SSOT)의 푸터 버튼은 **아이콘만** 표시한다(텍스트 라벨 금지).
  - **확인 계열(YES/OK/SAVE) = 체크 아이콘**(`fa-check`), **취소·닫기 계열(NO/CANCEL/CLOSE) = X 아이콘**(`fa-xmark`).
  - 라벨(현지화 텍스트)은 `title`/`aria-label` 로 보존(접근성·툴팁). 색은 호출부의 `emphasized`(파랑)/`negative`(빨강) 유지.
- **버튼 3개 이상**(예: 저장/저장안함/취소)은 NO·CANCEL 이 둘 다 X 라 모호 → **텍스트 라벨 유지**(자동 아이콘 미적용). 필요 시 버튼별 `icon`(FA 이름)을 명시하면 개수와 무관하게 그 아이콘 사용.
- 구현: `u4a-ui.js confirm()` 의 footer 렌더가 `act`→아이콘 매핑(2버튼 이하 자동)으로 처리 → 전 팝업·셸(`fnConfirmBox`) 자동 적용. 화면별 버튼 재구현 금지.

### 2.2 드래그 + 리사이즈
- 모달 팝업은 **헤더를 잡고 드래그하여 이동**할 수 있어야 한다. → 전역 자동(`u4a-ui.js _installGlobalDialogDrag`, document 위임 1벌). 클램프: 좌·우·하=뷰포트 안, 위=`.u4a-titlebar` 하단(`_topChromeBottom`). 새 팝업은 `.u4a-dialog`+`.u4a-dialog__header` 구조만 따르면 배선 불필요. **헤더 hover 시 `cursor:move`**(드래그 affordance) — `.u4a-dialog__header` 공통(shell.css), 헤더 안 닫기 X·액션 버튼은 `.u4a-btn-icon/.u4a-btn` 의 pointer 가 이김.
- 모달 팝업은 **우하단 grip(`U4AUI.makeDialogResizable`)으로 리사이즈** 할 수 있어야 한다(좌상단 anchor). ⚠️ CSS 네이티브 `resize:both` 금지(showModal `margin:auto` 라 가운데 기준으로 커짐) — 공통 grip 단일.
- **헤더 더블클릭 = 화면 중앙 복귀**(`makeDialogRecenter`, 드래그 인라인 위치 비움).
- **전체화면(최대화) 토글 = 타이틀바 하단부터 (필수 · 드래그 클램프와 동일 상단 경계)**: 헤더의 전체화면/최대화 버튼(있는 팝업만)은 다이얼로그를 **뷰포트 전체(`0,0 / 100vw,100vh`)로 키우면 안 된다** — 그러면 창 타이틀바(`.u4a-titlebar`)를 덮는다. 반드시 상단을 `_topChromeBottom()`(타이틀바 하단 y, 없으면 0)으로 두고 `position:fixed; left:0; top:<타이틀바하단>; width:100vw; height:calc(100vh − 타이틀바하단)` 으로 채운다. **드래그 클램프(위=`.u4a-titlebar` 하단)와 동일 사상** — 최대화라도 타이틀바만은 침범 금지(메뉴바·툴바 위는 덮어도 됨, §2.1/드래그 규칙과 동일). 복원(restore)은 인라인 `position/margin/left/top/width/height/maxWidth/maxHeight` 를 비워 CSS 기본(중앙 배치)으로 되돌린다. **★최대화 상태에서 창 크기 변화 추종(필수)**: 최대화는 클릭 시점 창 크기로 **px 를 박으므로**, 그대로면 이후 브라우저 창을 키워도(예: 작은 창 → 전체창) 팝업이 안 따라온다 → 최대화 동안 `window resize` 리스너로 새 창 크기에 맞춰 **다시 채운다**(복원/닫기 시 리스너 해제). (레퍼런스: 내 패턴 팝업 `fnP13nDesignPopupOpen.js lf_toggleFull`/`lf_applyMaxSize`/`lf_onWinResizeFull`/`lf_topChromeBottom`. 2026-07-02 추가 — 최대화 버튼 두는 새 팝업은 이 규칙을 따른다.)
- **창 리사이즈 재클램프 (필수, §4.3 스플릿바와 동일 사상)**: 드래그/리사이즈는 다이얼로그에 **인라인 px**(`position:fixed`+`left/top/width/height`)를 박는다. 한번 박히면 창 크기가 변해도 안 따라오므로, **최대화 상태에서 키우거나 옮긴 팝업이 창 restore 후 작은 창을 넘쳐 오른쪽·아래가 잘린다.** → `_installGlobalDialogDrag` 가 **`window resize` 리스너 1벌**로 인라인 px 가 박힌 **열린** `.u4a-dialog` 를 뷰포트 안으로 클램프(`width/height ≤ vw/vh-16`, `left/top` 클램프, 위=`_minTop`). 인라인이 없는(=CSS `vw/vh`+네이티브 중앙정렬) 다이얼로그는 손대지 않는다. (2026-06-23 추가 — 전 `.u4a-dialog` 공통, 새 팝업 배선 불필요.)
- **닫으면 DOM 제거 + 다음 열기 = 새로 build(전역 자동)**: 모달 팝업은 닫을 때 `<dialog>` 를 DOM 에서 제거하고, 다시 열 때 새로 생성해 **기본 상태로 시작**한다(직전 입력·스크롤·선택·검증표시 잔존 금지). → 전역 자동(`u4a-ui.js _installGlobalDialogClose`, document 의 capture 단계 `close` 리스너 1벌 — `close` 는 버블 안 하나 capture 로 잡힘). 모든 `dialog.u4a-dialog` 가 close 시 자동 제거되므로 **새 팝업은 `lf_close()` 에서 `dlg.close()` 만** 하면 되고(직접 remove 불필요), 열기 진입부는 캐시 노드가 detach 됐는지 `document.body.contains(dlg)` 가드로 재-build 한다. **opt-out = `[data-u4a-keep]`**: 닫기=숨김(DOM 유지)으로 상태를 보존하는 싱글톤만 이 속성을 달아 제외한다(예: App F4 검색 팝업). busy(`.u4aWsBusyIndicator`)·`U4AUI.confirm`(자체 remove)·일러스트 대기(`.u4a-dialog` 비대상)는 무관. (attachOverflow/createSelect 공통 1곳에서 처리 → 새 소비처 배선 불필요.)

(`_show` 공통 1곳 처리 → 전 모달 팝업 자동, 새 팝업 배선 불필요. 2026-06-29 추가.)

#### 2.9a 잘리는 텍스트에는 반드시 툴팁 (기본 상식 · 필수)
- **말줄임(ellipsis)·겹침·아이콘화 등으로 전체 텍스트가 안 보일 수 있는 요소에는 반드시 툴팁으로 전체 텍스트를 제공한다.** 라벨을 `…`로 자르거나(overflow ellipsis), 좁을 때 원/칩을 겹치거나(진행바 축소), 텍스트를 숨기고 아이콘/번호만 남기면(컴팩트 네비) — 그 순간 hover 로 원문을 볼 수 있어야 한다. 텍스트를 자르면서 툴팁을 안 다는 건 **미완성**으로 본다.
- **방식(공통 하나만 소비)** — 자체 툴팁 만들지 말고 `initTooltip` 이 읽는 속성만 단다:
  - **"잘릴 때만" 표시(권장)** — 요소에 `data-tip="<전체텍스트>"` + `data-tip-trunc`(자기 자신이 잘릴 때) 또는 `data-tip-trunc-sel="<잘리는 자식 셀렉터>"`(지정 자식이 잘릴 때). `_show` 가 `scrollWidth>clientWidth` 를 검사해 **실제로 잘렸을 때만** 뜬다 → 안 잘리면 조용. (`.u4a-table` 셀·헤더라벨은 이걸 **자동** 적용하므로 배선 불필요.)
  - **항상 표시** — 아이콘 전용/번호만 있는 컴팩트 요소(진행바 축소 원, 아이콘 버튼)는 볼 텍스트가 없으니 그냥 `title`(또는 `data-tip`)만 달면 hover 로 이름을 준다.
  - 여러 줄 요약은 `\n` 으로 연결(예: 접힌 그룹 = 접힌 스텝명 줄바꿈 목록).
- 레퍼런스: `.u4a-table` 자동 셀 툴팁, UI 템플릿 마법사 진행바(full 라벨=`data-tip-trunc-sel`, 축소 원/그룹=`title`). (2026-07-07 추가 — "텍스트 자르면 툴팁"은 화면별 선택이 아니라 공통 필수.)

- ⚠️ **일러스트 SVG 배경은 반드시 투명**이어야 한다. 카드는 테마색(다크=어두움)인데 SVG 에 불투명 `<rect fill="#fff">` 등 배경이 박혀 있으면 다크 테마에서 **흰 블록**으로 떠 어색하다(2026-06-23 사례). 해당 SVG 의 흰 배경 사각형 + 라이트 전용 바닥 타원(`#dff5ff`/`#e9f7ff`)을 제거해 투명화 → 라이트/다크 양쪽에서 카드 위에 자연스럽게 얹힌다. 새 일러스트 추가 시에도 동일(불투명 배경 금지).
- ⚠️ 에셋 경로는 **호스트 문서(`index.html` = `www/ws30/ws10_20/`) 기준 `../../svg/...`** 로 해석한다. `ws_common.js` 는 `<script src>` 가 아니라 **ajax+eval 로 로드**(`library-preload.js`)되어 **DOM 에 스크립트 태그가 없으므로**, 에셋 URL 을 스크립트 src 에서 찾지 말고 `new URL(rel, window.location.href)` 로 만든다.

### 2.4 토스트 (MessageToast 대체) — 공통 `.u4a-toast` (필수)
- **단일 출처 = `theme/shell.css` 의 `.u4a-toast`** (색은 `bootstrap-skin.css`). 화면/팝업마다 토스트 스타일을 새로 만들지 말 것.
- **위치는 반드시 화면 정중앙(상하·좌우 가운데).** `position:fixed; left/top:50%; transform:translate(-50%,-50%)` — shell.css 가 강제. **하단/모서리 토스트 금지**(전 화면 공통 UX). `pointer-events:none` 라 클릭 통과.
- **표시 방식**: 싱글톤 `<div class="u4a-toast" role="alert">` 1개를 만들어(또는 재사용) `textContent` 세팅 후 `dataset.show="true"`, **3초 뒤 `data-show="false"`** 로 자동 숨김(fade 는 CSS). 메인 셸은 `showMessage`/`setMessageToast`(resources/index.js)가, BrowserWindow 팝업은 화면 로컬 `_toast()`(ServerList/optionPopup/editorPopup 동일 패턴)가 이 컴포넌트를 소비.
- **★★ top-layer 필수 (자주 재발하는 고질 함정 — §2.10 연계):** 토스트를 `body` 에 두면 **`<dialog>.showModal()` 모달이 열려 있을 때 모달 top-layer 뒤로 가려져 안 보인다.** `pointer-events:none`·`position:fixed` 라도 z-index 로는 top-layer 를 못 이긴다. → **토스트를 띄울 때마다 열린 모달이 있으면 그 안으로 재배치한다: `(document.querySelector("dialog[open]") || document.body).appendChild(oToast)`** (툴팁·컬럼메뉴가 `closest("dialog[open]")` 로 이미 하는 처리와 동일). 싱글톤이라 매 표시 때 부모만 바꾸면 된다. 새 `_toast()`/토스트 소비처는 **반드시 이 재배치를 포함**할 것. 레퍼런스 = `Popups/bindPopup/frame.js _toast`.
- 문구는 **메시지 클래스 키만**(§5 — 임의 완료문구 금지). 예: 저장 = `MSG_WS 330`(&1 = `CL_WS_COMMON D23`).

### 2.5 다이얼로그 헤더 "선두 상태 아이콘" 색 (필수)
- 모든 팝업 헤더의 **선두 상태 아이콘(`.u4a-dialog__header > i` 직계, 또는 별창 타이틀바 선두 아이콘)은 테마 accent 색**으로 통일한다. **단일 출처 = `shell.css` `.u4a-dialog__header > i { color: var(--accent) }`(기본).** 일반 팝업은 **아무 것도 안 해도 accent** — 화면별로 색을 따로 주거나 `data-type` 을 달지 않는다.
- **예외 = 메시지박스만**: `fnConfirmBox`/`showMessage` 가 헤더에 `data-type`(S/E/W/I/C)을 세팅 → 의미색 override(E=`--state-error` 빨강 / W=`--state-warning` 주황 / S=`--state-success` 초록 / I·C=accent=기본과 동일). 즉 **data-type 은 "메시지 타입 의미색"용이지 "accent 색 얻기"용이 아니다.**
- ⚠️ 닫기 X·액션 버튼 속 아이콘(`button > i`)은 **직계(`> i`)가 아니라서 제외**된다 — 의미색이 X 버튼까지 칠해지면 안 되므로 `> i` 직계 셀렉터를 반드시 지킨다.
- **2026-06-24 전수 통일**: 전엔 기본이 `--icon-muted`(무색)라, 다수 팝업이 accent 를 얻으려 `data-type="I"` 를 따로 달았고(client_editor·ServerInfo·SysNoti·SelectBrowser·Cts·AppF4·AppCopy·createEvent·createApp), 안 단 일부(USP Create·WS20 Insert/MovePosition/ChangeLayout·ServerList 폼·Login 연결·별창 WinHide)는 muted 로 떠 **불일치**했다. → 기본을 accent 로 바꿔 전부 통일 + 중복 `data-type="I"` 제거(메시지박스 빌더만 동적 data-type 유지). 별창 타이틀바 선두 아이콘(`.u4aWinHide__icon` 등)도 accent.
- ⚠️ **별창 타이틀바 선두 = 화면 성격 따라** — 에디터·매니저류 일반 창은 **U4A 로고**(`.u4a-titlebar__logo`, CSS/JS/HTML Editor·OTR Manager·옵션창 동일), 알림/경고성 창만 의미 아이콘(errMsg=triangle-exclamation, WinHide=eye-slash). **임의로 메뉴 아이콘으로 바꾸지 말 것** — 레퍼런스(editorPopup)가 로고면 로고.

### 2.6 별도 BrowserWindow 창 — 첫 페인트 흰 플래시 방지 + 등장 (필수)
별도 창(`REMOTE.BrowserWindow`)으로 뜨는 팝업(에디터·옵션·OTR Manager·에러메시지 등)은 인앱 모달(`.u4a-dialog`)과 **다른 트랙**이다. 다크/유색 테마에서 **창이 뜰 때 흰 배경이 번쩍였다가 테마가 입혀지는 현상**을 다음으로 막는다. 레퍼런스 = `editorPopup`(CSS/JS/HTML 에디터).

- **네이티브 창 opacity 페이드 금지.** opener 에서 `oBrowserOptions.opacity = 0.0` + 페이지에서 `WSUTIL.setBrowserOpacity()`(OS 레벨 0→1 페이드)를 **쓰지 않는다** — OS 리컴포짓이라 무겁고, 그 사이 흰 배경이 보인다. 대신:
  - opener: `oBrowserOptions.backgroundColor = oThemeInfo.BGCOL`(창을 처음부터 테마색 불투명) + `show:false`. 위치(`setParentCenterBounds`)는 `ready-to-show` 에서 잡고, **페이지가 로드되면 `CURRWIN.show()` 로 표시**한다.
- **첫 페인트 전 동기 테마 적용.** 페이지 `<head>` 에서 theme-api 로드 직후, opener 가 넘긴 쿼리 `BGCOL/THEME` 를 첫 페인트 전에 동기로 적용: `document.documentElement.style.setProperty("--boot-bg", BGCOL)` + `U4ATheme.apply(THEME)`. body 배경은 `background: var(--boot-bg, var(--app-bg))`. 테마 적용 후 `--boot-bg` 는 제거([[boot-bg-theme-sync]] 와 동일). **iframe 본문이 있는 2단 구조면 iframe 도** 동일하게 — 부모가 `iframe.src` 에 `?BGCOL=&THEME=` 를 붙이고 iframe `<head>` 에도 같은 boot 스크립트를 둔다(안 하면 iframe 만 흰 번쩍).
- **등장 효과 = 본문 CSS opacity transition.** 네이티브 창 페이드 대신 본문 컨테이너를 `opacity:0; transition:opacity .3s` 로 두고, 준비 완료(로딩/데이터 도착) 시 클래스 토글로 `opacity:1`. GPU 합성이라 가볍고 흰 플래시 없음. `prefers-reduced-motion` 시 transition off. (예: editorPopup `#editorContent.u4aEdShown`, OTR `#otrContent.u4aOtrShown`.)
- 적용: `editorPopup`, `errPageEditorPopup`, `errMsgPopup`, `optionPopup`, `OTRF4HelpPopup`. (창 레벨 공통 UX 전체 체크리스트는 06.팝업 + ServerList 레퍼런스.)

### 2.6.1 별도 창 닫기 — `closable:false` 영구 유지 + 공통 `U4AUI.closeWindow` (필수, SSOT)
frameless 별도 창(커스텀 `.u4a-titlebar`)은 **OS 닫기(Alt+F4 / 시스템메뉴 Close)를 OS 레벨에서 차단**하고, 닫기는 화면 안 **커스텀 X 버튼으로만** 한다.
- **opener 가 `oBrowserOptions.closable = false` 로 연다.** Electron 에서 `closable:false` 면 OS 의 Alt+F4·시스템 Close 가 막힌다(Windows). 이 상태를 **창 수명 내내 유지**한다.
- **❌ busy 토글로 `CURRWIN.closable = true` 주지 말 것.** 흔한 버그: `setBusy` 에서 `closable = !bBusy`(idle 시 true)로 주면 **idle 상태에서 Alt+F4 가 창을 닫는다**. busy 중 닫기 차단은 **"닫기 호출부의 busy 가드 + `onbeforeunload`"** 로 하고, `closable` 은 **항상 false** 로 둔다.
- **정상 닫기 = 공통 `U4AUI.closeWindow(win)`(SSOT).** `theme/u4a-ui.js` — `win.setClosable(true)` 직후 `win.close()`(+`isDestroyed` 가드). 커스텀 X 버튼(`.u4a-winbtn--close` / `[data-action="close"]`) 핸들러는 `if (busy) return; U4AUI.closeWindow(CURRWIN);` 형태. 창이 `closable:false` 라 **직접 `CURRWIN.close()` 는 안 먹으므로** 반드시 이 함수 경유.
- **점검**: `grep "closable\s*=\s*!"` / `"closable\s*=\s*true"` 가 별도창 프레임 `setBusy` 에 있으면 버그(전부 `false` 로). 닫기 핸들러가 `setClosable` 없이 `close()` 만 하면 closable:false 창에선 안 닫힘.
- 적용(2026-06-30 전수): `versionMng`, `OTRF4HelpPopup`, `errMsgPopup`, `mimeRepository`, `docPopup`, `errPageEditorPopup`. 관련 [[browser-window-common-ux]].

### 2.7 확인/메시지 다이얼로그 — 공통 `U4AUI.confirm` (필수, SSOT)
예/아니오·확인 메시지박스(구 sap.m.MessageBox)의 **단일 구현 = `theme/u4a-ui.js` `U4AUI.confirm(opts)`** (공통 `.u4a-dialog` 헤더/본문/푸터 소비 + 네이티브 `<dialog>` 미지원 시 `window.confirm` 폴백). 화면/창마다 confirm 다이얼로그를 새로 만들지 않는다.
- **순수 UI** — 텍스트(제목/메시지/버튼라벨)는 **호출부가 현지화해 넘긴다**(u4a-ui.js 는 메시지클래스 비결합). `opts = { type:S|E|W|I|C(아이콘/색), title, message, buttons:[{act,label,emphasized,negative}](미지정=Yes/No), onClose(sAct) }`.
- **셸(`oAPP.common.fnConfirmBox`)이 이 함수를 소비** — 타입별 제목 메시지키(D86/B93/B89/B86) 현지화만 셸이 하고 다이얼로그 구현은 공통 1곳. **별도 BrowserWindow(예: MIME 리포지토리)는 셸을 안 불러 `fnConfirmBox`가 없으므로 `U4AUI.confirm`을 직접 소비**(창 자체 confirm 확보). 즉 confirm UX 가 "공통이 아니라 셸에만" 있던 것을 u4a-ui.js 로 **승격**(2026-06-29) → 셸·별도창 공유.
- 헤더 `data-type` 의미색은 §2.5 와 동일(E 빨강/W 주황/S 초록/I·C accent).

### 2.9 텍스트 선택 / 복사 정책 (필수, SSOT=shell.css)
앱 전역(`body`)은 `user-select:none` — 버튼/아이콘/드래그(스플릿바·다이얼로그·타이틀바) 오작동 방지(데스크톱 앱 느낌). 하지만 **"데이터로 보여지는 텍스트"는 사용자가 마우스로 드래그해 선택·복사할 수 있어야 한다**(사용자 요청 2026-07-01).
- **데이터 표면에만 `user-select:text` 로 되살린다** — shell.css 공통 1곳: `input, textarea, .u4a-input, .u4a-field__input, .u4a-table tbody td, .u4a-selectable, .u4a-selectable *`. 화면별로 개별 처리 금지(공통 소비).
- **인터랙티브 크롬은 계속 `none`** — 버튼/타이틀바/메뉴/툴바/트리 토글/패널·테이블 헤더(클릭·드래그 전용이라 선택되면 방해).
- 임의 텍스트 블록(라벨·안내문 등)을 선택가능하게 하려면 그 요소에 **`.u4a-selectable`** 을 붙인다(자식까지 전파).
- 테이블 데이터 셀(`tbody td`)은 자동 선택가능 → 전 화면 테이블에서 값 복사 가능(runtimeClassNavigator 등).

### 2.10 top-layer 규칙 — `<dialog>.showModal()` 위에 뜨는 것은 반드시 top-layer (필수, 자주 실수하는 함정)
`<dialog>.showModal()` 로 연 모달은 브라우저 **top layer** 에 렌더된다. top layer 는 **어떤 `z-index` 보다도 위**라, 일반 흐름의 요소(`position:fixed/absolute` + 높은 z-index 여도)는 **모달 뒤에 가려진다**. 따라서 "모달이 떠 있는 동안 그 위에 보여야 하는 것"은 **자기도 top layer(=`<dialog>.showModal()`)여야** 한다.

- **증상**: 모달(생성/가져오기/CTS/확인 등 `.u4a-dialog`) 위에서 토스트·busy·툴팁·안내가 **"안 뜨는 것처럼"** 보임(실은 모달 뒤에 떠 있음).
- **원인 판별**: 렌더가 안 되는 게 아니라 **top layer 밖**이라 가려지는 것. z-index 를 올려도 소용없다 → **top layer 여부부터 의심**.
- **해결(대상별)**:
  - **메시지/검증 안내** — 토스트(`.u4a-toast`, 일반 div)는 모달 뒤로 감. **모달 위에서 알릴 땐 `showMessage(..., "W"|"E", ...)` 로 박스(공통 `U4AUI.confirm` = `showModal`)** 를 쓴다(정보성이라도 모달 위에선 W/E 박스). 정보 토스트는 모달이 없을 때만 확실히 보인다. → [[toast-common-center]]
  - **busy (★절대 규칙 — 자체 busy 금지, 무조건 공통 busy)** — busy 는 **어떤 화면·팝업에서도 자체 오버레이/스피너/`aria-busy`(opacity)/z-index div 를 만들지 말고, 무조건 공통 전역 busy `parent.setBusy("X"/"")`(→ `setDomBusy` → `<dialog id="u4aWsBusyIndicator">.showModal()`) 만 사용**한다(별도창은 프레임 주입 `setBusy` = 자체 `<dialog>` top-layer, 예: `#mimeBusy.u4aMimeBusy`). **이유(아키텍처)**: 공통 busy 는 `<dialog>.showModal()` = **top layer**라 어떤 모달 팝업(showModal) 위에도 자동으로 보인다. 자체 div busy 는 z-index 를 아무리 올려도 top layer 밖이라 **모달 뒤로 가려 안 보인다**(= "전체검색인데 busy 안 켜짐" 류 버그의 근본 원인). **팝업-온-팝업**(모달에서 또 모달 F4/CTS 등)에서 특히 필수 — 자체 busy 를 쓰면 팝업 새로 띄울 때마다 레이어 버그가 재발한다. **점검**: 새 팝업/모듈에 `aria-busy`·`busy` 스타일 div·자체 스피너가 있으면 제거하고 `parent.setBusy` 로 교체. → [[modal-dialog-busy-toplayer]] · [[overlay-layering-use-common-system]]
  - **툴팁** — 공통 툴팁이 모달 위에 있으면 `el.closest("dialog[open]")` 의 그 다이얼로그에 append(top layer 안). → [[tooltip-modal-toplayer]]
- **요지**: "모달 위에 뭔가 안 보이면 z-index 말고 top layer 부터." 새 팝업/검증/오버레이 만들 때 이 규칙 먼저 적용.

### 3.1 단일 출처 (필수)

- **금지**: 화면마다 재귀 렌더러(`_renderNode`/`_renderTreeNode` 류)를 새로 작성하는 것 = 소스 이원화. 과거 3벌 복제로 ARIA·들여쓰기·토글이 화면마다 어긋났던 문제를 막기 위함.

### 3.2 코어 UX 규칙 (베이스가 강제)
- **ARIA role 미부착.** `role="tree/treeitem/group"` 을 붙이지 않는다. 상태는 `aria-expanded`(셰브론 회전)·`aria-selected`(선택 강조)만 사용한다.
- **토글 = WS20식.** 자식은 항상 렌더하고, 펼침=`<ul>.hidden=false`(제자리), 접기=이 노드+**자손까지 재귀 접힘** 후 서브트리 재빌드(다시 펴면 자손은 접힌 상태). USP의 "매 토글 전체 재렌더"는 폐기.
- **Expand/Collapse 툴바 버튼 = "선택한 노드" 기준**(원본 `getSelectedIndex` / USP `fnUspTreeExpand·CollapseSelected`): **Expand = 선택 노드의 서브트리 전체 펼침**(루트 선택이면 트리 전체=구 `expandToLevel(99)`, 공통 `expandSubtree(node)`), **Collapse = 선택 노드만 접음(단일, `setExpanded(node,false)`)**. **선택 없으면 no-op**(전체 펼침/접힘 아님). 로드 직후 첫 루트가 선택돼 있어 기본은 전체. 버튼 툴팁은 메시지키(`C27`/`C28`, `/U4A/CL_WS_COMMON`) — 하드코딩 금지. (자체 렌더 트리도 이 동작을 복제: AppF4 가 처음에 전체펼침/접힘으로 잘못 만들었다가 2026-06-24 선택기준으로 수정.)
- **들여쓰기 표준 1종.** 행에 `--u4a-tree-depth`(=레벨)만 부여하고 padding 은 shell.css 가 계산: `calc(0.375rem + 깊이 × 1rem)`. 좁은 패널은 컨테이너 쿼리가 step(1rem→0.625rem)을 줄인다. **화면별 인라인 들여쓰기 공식 금지.**
- **DOM 계약(외부 코드가 의존하므로 고정).** `<ul class="u4a-tree">` > `<li>` > `:scope > .u4a-tree__row` + `:scope > ul`(자식). 펼침/선택 복원 로직이 이 구조와 `row._nodeData` 에 의존한다. 행 직속 자식 순서는 `[toggle][slotLead][icon][label][slotTrailing]`(별도 RowLeft 래퍼 없음 — 화면이 만든 `*RowLeft` 류는 死코드).
- **행별 가로 구분선(전 트리 공통, 2026-07-10 승격).** 각 행은 하단 경계선 `.u4a-tree__row { border-bottom: 0.0625rem solid var(--line) }`(shell.css 단일 출처)으로 구분한다 — 원본 UI5 TreeTable 의 라인별 격자 느낌. **소비처 = ServerList·USP·MIME·WS20 전 트리 동일**(화면별 재정의/제거 금지, 색은 의미 토큰 `--line` 만). WS20 은 여기에 우측 액션 컬럼 세로선(`.u4aWs20TreeActions` border-left)까지 더해 표 성격.
- **빈 영역까지 격자 연장(가로 행선 + 세로 컬럼선, 선택 적용).** HTML5 트리는 실제 노드만 렌더하므로 노드가 끝난 아래 빈 영역엔 행 border-bottom·컬럼 border-left 가 없다. 원본 UI5 처럼 빈 영역까지 격자를 채우려면 **행과 함께 스크롤되는 트리 ul(`.u4a-tree`) 배경에 격자 그라디언트**를 얹는다(공통 컬럼트리 `.u4aColTreeBody` 와 동일 기법):
  - 가로 행선 = `repeating-linear-gradient(to bottom, ... 주기=행높이)`. ⚠️ **가상 스크롤(`virtual:true`) 트리는 주기를 리터럴(2.5rem)로 박지 말고 `var(--u4a-vsrowh, 2.5rem)` 로 묶는다** — 가상 스크롤은 행 높이를 측정값 `--u4a-vsrowh`(makeVScroller→scroll 컨테이너)로 강제하므로, 리터럴 주기는 실제 행 간격과 미세하게 달라 스크롤 시 배경선과 행 border 가 어긋나 겹쳐 보인다(2026-07-10 실측). 주기=행높이여야 배경 가로선이 각 행 border-bottom 과 포개져 단일선.
  - 세로 컬럼선 = `linear-gradient(var(--line), var(--line))` 1개를 `background-size: 0.0625rem 100%` + `background-position: right <컬럼폭> top` 로 컬럼 경계 x 에 고정(그 x = 해당 컬럼 border-left 위치와 일치하게 계산).
  - ⚠️ **반드시 스크롤 컨테이너(고정배경) 아닌 ul(스크롤됨) 배경에 얹는다** — 고정배경이면 세로 스크롤 시 가로선이 행과 어긋난다. ul 은 `min-height:100%`(빈영역 채움)+패딩 0(첫 행 y=0 정렬)이라야 함. 공통 `.u4a-tree{background:var(--surface)}` 불투명은 이 배경(투명 구간)으로 덮인다.
  - ⚠️ **전제 = 행 높이 고정.** 행 높이가 "노드마다 제각각 늘어나는" 트리에만 금지(배경 라인이 노드와 어긋남). 소비처: WS20(`.u4aWs20TreeScroll .u4aWs20Tree`, 2026-07-10, 가로+세로), **USP/WS30**(`.u4aWs30Tree.u4a-tree`, 2026-07-10, **가로만** 빈영역 채움 — 설명이 2줄이어도 40px 고정행 안 클램프라 적용 OK. ul 을 `min-height:calc(100% - 헤더 2.75rem)` 로 채워 sticky 헤더와 공존. ⚠️ 세로 설명컬럼선은 노드 행마다 `.u4aWs30TreeDesc` border-left 로 이미 풀하이트지만, 설명 컬럼폭이 **%(`--ws30-desc-w:42%`)** 라 배경 그라디언트 %기준(ul폭)이 flex 기준(행 content폭)과 몇 px 어긋나 **빈영역 세로선 연장은 생략**. 빈영역 세로까지 정확히 원하면 고정폭 전환 또는 flex 필러요소 필요). ServerList·MIME 등 고정행 트리도 동일 기법.
    ★ USP 는 들여쓰기를 행 padding 이 아니라 **토글 margin-left** 로 줘 행 content-box 폭이 깊이와 무관하게 일정 → 우측 고정컬럼(설명)·구분선이 깊이 상관없이 정렬(WS20 의 깊이 계단식 밀림이 원래 없는 구조 = 참고 레퍼런스).
  - ⚠️ **우측 액션/버튼이 있는 트리는 그 컬럼을 "고정 컬럼(frozen)"으로**: `position: sticky; right: <행 padding-right>` + `z-index` + **불투명 배경(패널색 + hover/선택 상태 일치 레이어)**. 안 그러면 깊은 들여쓰기(padding-left 누적)·좁은 폭에서 행이 넘쳐 액션이 계단식으로 밀리고 세로선과 어긋난다(2026-07-10 WS20 실측). sticky 로 뷰포트 우측에 클램프 → 원본 UI5 처럼 "이름은 잘려 가려지고 버튼/세로선은 우측 고정". aggr 는 `flex:0 1 auto + overflow:hidden + text-overflow:clip`(공간 충분=전체표시, 부족=점없이 잘림)으로 버튼을 밀지 않게. 세로선 배경 x = 액션 border-left 위치와 일치하게 계산. 소비처 WS20(`.u4aWs20TreeActions`).
- ⚠️ **행 밀도(높이·간격·텍스트 크기)는 shell.css `.u4a-tree*` 단일 출처**다(2026-06-23 통일). 화면별로 다시 정의하지 않는다:
  - 행 높이 = `.u4a-tree__row { min-height: var(--u4a-tree-row-h, 2.5rem) }`(=40px, 내용 많으면 자동 증가)
  - 토글↔아이콘↔라벨 간격 = `.u4a-tree__row { gap: 0.375rem }`
  - 토글(화살표) 박스 = `.u4a-tree__toggle { 1.25rem 정사각 }`(=20px)
  - 노드 텍스트 = `.u4a-tree { font-size: 0.8125rem }`(=13px), `font-family` 는 상속(전 트리 동일)
  - **금지**: 화면 CSS 에서 `height`/`--u4a-tree-row-h`/`gap`/`font-size`/아이콘 `margin` 으로 위 값을 덮는 것. (과거 ServerList .4rem·.85rem / WS20 .25rem·13px·토글28px / USP gap+아이콘 .25rem·row-h 2.5rem / App-F4 .125rem·14px·step1.25 로 4개가 제각각 → 사용자 지적으로 수렴.)
  - **App-F4(트리테이블) 예외**: 다열 테이블이라 **행 높이만 `.u4a-table`(compact) 표준**을 따르고, 토글 간격·들여쓰기 step·텍스트 크기는 위 공통값에 맞춘다.
- **폴더 아이콘 표준(서버리스트 기준 → 공통 승격 2026-07-02, SSOT=shell.css).** 폴더 노드는 `icon` 훅에서 **항상 `fa-folder` 만** 반환한다(파일/더미는 빈값). 나머지는 공통 CSS 가 처리:
  - 색 = `--folder-icon`(tokens.css, 앰버 #e6a93a — 테마별 override 가능), **선택행 = `--accent`**
  - **열림/닫힘 전환 = CSS 글리프 스왑**(`[aria-expanded="true"] > .u4a-tree__icon .fa-folder::before → \f07c`) — JS 로 folder-open 을 직접 렌더하지 말 것(색 규칙이 `.fa-folder` 타깃이라 빠짐 + 로직 이원화). leaf 는 aria-expanded 없어 닫힌 폴더 유지.
  - 화면별 아이콘 색/글리프 재정의 금지(소비처: ServerList·MIME. USP 는 img/SVG 아이콘이라 무영향).

### 3.3 확장 컨셉 — base 위에 화면별 추가기능
- **베이스는 코어 UX 만 공통.** 화면별 추가기능(체크박스, aggregation 배지, 우측 +/삭제 액션 영역, description 컬럼 등)은 베이스가 제공하는 **슬롯/후크로 주입**한다:
  - `slotLead(node,ctx)` — 토글↔아이콘 사이(예: 체크박스)
  - `slotTrailing(node,ctx)` — 라벨 뒤 우측(예: 배지/설명/액션). 반환 시 행이 `[data-u4a-tree-split]`(우측정렬)되어 shell.css 가 `space-between` 처리.
  - `rowHook(row,node,ctx)` — 행 div 직후(줄무늬/커스텀 클래스/`data-*`/`row._nodeData` stash 등)
- **확장 스타일은 현재 각 화면 CSS 가 책임진다**(예: WS20 `ws20.css`, USP `usp.css`). 새 확장 UX가 전 화면 공통 가치가 있다고 판단되면, **그때 base 옵션 + shell.css 공통 클래스로 "승격"** 해 모든 트리가 옵션만 켜서 쓰도록 한다. (승격 여부는 작업 시 결정)
- ⚠️ **선택/상태 "좌측 컬러바"는 반드시 `box-shadow: inset <Npx> 0 0 0 <color>`(좌측 가장자리 flush)로만** 만든다 — `border-left` 로 만들지 말 것. 공통 선택바(shell.css `.u4a-tree__row[aria-selected="true"]` = `inset 0.1875rem(3px) var(--accent)`)가 있는데 행에 `border-left` 를 두면 **그 두께만큼 box-shadow 가 안쪽으로 밀려** 화면마다 선택바 위치·두께가 달라 보이고(레이아웃 시프트도 발생) 사용자가 "선택 인디케이터가 다르다"고 본다(2026-06-22 WS20 트리 `border-left:2px` 사례). WS20 상태바(`hl-Indication02/04/08`)·옵션 팝업 메뉴(`.active`)도 전부 **flush box-shadow inset 3px** 로 통일. 상태바가 선택바를 덮어야 하면 색만 바꾸고 specificity 만 보강(`.u4a-tree__row.<화면클래스>.hl-*`).

### 3.4 API 요약
- `const oCtrl = U4AUI.createTree(cfg)` — cfg 콜백:
  - 데이터: `roots()`, `children(node)`, `key(node)`(고유키), `hasChildren(node)?`
  - 표현: `label(node)`, `icon(node)?`(HTML; 빈값이면 생략), `tip(node)?`(말줄임 툴팁)
  - 슬롯: `slotLead`, `slotTrailing` / 후크: `rowHook`
  - 동작: `onSelect(node,row,ctx)`, `onToggle(node,bExpanded,row)`(펼침 영속화), `initialExpanded(node,level)?`(기본 level<1), `isExpanded(node,level)?`(외부 펼침맵 위임 — §3.4.1), `virtual?`(대용량 가상스크롤 — §3.4.1)
- 컨트롤러: `{ el, render(), expandAll(), collapseAll(), expandToLevel(n), expandSubtree(node), setExpanded(node,b), setSelected(node)/selectByKey(key), scrollToKey(key), findRow(key) }`
- 펼침 상태는 base 내부에 키 기준으로 유지되며 `onToggle` 으로 화면측 영속화(레지스트리/맵)와 동기화한다. **선택 강조는 화면이 소유(onSelect)** 하거나 base(`setSelected`)가 소유하거나 — 화면당 하나만 선택한다(이중 처리 금지).

### 3.4.1 가상스크롤(`virtual`) · 외부 펼침맵 · 다열 정렬 함정 (필수)
대용량 트리(WS30 USP / WS20 디자인트리 / MIME 등)는 `cfg.virtual:true`(보이는 행만 DOM = flat+windowed)로 만든다. 이때 아래 3가지를 어기면 화면이 깨진다(실측 사례: MIME 2026-06-25).

1. **외부 펼침맵(`isExpanded`)을 주면 내장 펼침 헬퍼가 무시된다.** `cfg.isExpanded` 를 제공하면 `_isExpanded` 가 **그 콜백만** 단일 출처로 읽는다 → 내장 `expandAll/collapseAll/expandToLevel/expandSubtree/setExpanded`(베이스 내부 `_expanded` 맵 갱신)는 **반영되지 않는다.** 화면이 소유한 펼침맵을 **직접 조작한 뒤 `render()`** 해야 한다. (가상 모드는 토글=`onToggle`→외부맵 갱신→재플래튼 전제라 보통 `isExpanded`/`onToggle` 을 화면이 소유한다.)

2. **클릭 선택에 `selectByKey`/`scrollToKey` 금지(스크롤 점프).** 가상 모드 `selectByKey(key)` 는 내부적으로 `scrollToKey`(컨테이너 `scrollTop` 재계산=점프)를 호출한다. **사용자가 클릭한 행은 이미 보이므로 스크롤하면 안 된다**(원본 UI5 도 클릭 시 스크롤 안 함). 따라서:
   - **클릭 선택** = `onSelect(node,row,ctx)` 가 넘겨주는 **`row` 에 직접 `aria-selected` 적용**(다른 행 해제). `selectByKey` 호출 ✗.
   - **선택 보존** = 선택키를 화면 상태(또는 노드 플래그, WS30 `ISSEL`)에 두고 **`rowHook` 에서 `aria-selected` 재적용** → 지연로드·펼치기/접기로 가상 재렌더돼도 스크롤 없이 선택이 유지된다.
   - `selectByKey`/`scrollToKey` 는 **화면 밖 노드를 프로그램으로 보여줄 때만**(최초 진입 reveal=구 `setFirstVisibleRow`, 검색 이동 등). 레퍼런스: WS30 `fnUspTreeMarkSelected(node,bScroll)` 주석.

3. **다열(설명 컬럼) 정렬 — `slotTrailing` 만으론 흩뿌려진다.** `slotTrailing` 반환 시 행이 `[data-u4a-tree-split]`(=`space-between`)이 되는데, 라벨이 자연폭이라 토글·아이콘·라벨·설명이 가로로 흩어진다. 컬럼처럼 정렬하려면 화면 CSS 가 전부 덧대야 한다(WS30 `usp.css` / MIME 이식이 레퍼런스):
   - `.u4a-tree__label { flex: 1 1 0; min-width:0; overflow:hidden; text-overflow:ellipsis }` — 라벨이 남는 폭을 채움.
   - `.u4a-tree__row[data-u4a-tree-split] { justify-content: flex-start }` — 공통 `space-between` 무력화 + 설명은 **고정폭 우측 컬럼**(`flex:0 0 <desc-w>` + 좌측 구분선).
   - **들여쓰기를 행 `padding-left` → 토글 `margin-left`(=`calc(depth × step)`)로 이동**, 행은 `padding-left` 고정. 설명 컬럼 폭이 flex-basis(%)라 **행 content-box 폭이 깊이와 무관하게 일정**해야 컬럼/구분선이 헤더와 정렬된다.
   - sticky 컬럼 헤더는 **행과 "동일 콘텐츠 박스"** 를 만들고(설명폭은 단일 변수 `--*-desc-w` 공유), ★헤더 `padding-left` 는 **행 패딩 + 1px** = `calc(0.375rem + 1px)`. 공통 `.u4a-tree`(ul) 좌측에 1px 패딩(선택바 여백)이 있어 행 박스가 헤더보다 1px 안쪽에서 시작하기 때문 — 이 1px 을 빼먹으면 42% 기준폭이 어긋나 **구분선이 0.42px 밀려 헤더/행 라인이 픽셀 단위로 틀어져 보인다**(줌 시 확대. 2026-07-02 MIME 실측 delta 0.42→0.00 확정, usp.css 동일 보정).

4. **표형 격자(행/컬럼 라인 + 빈 영역 채움) = 공통 `createTree({grid:true})` 한 곳에서.** (2026-07-10 통일 — WS20/USP 가 각자 CSS 로 넣던 격자를 공통으로 승격. 화면별 복제 금지.) `grid:true` 를 주면 base 가 ul 에 `.u4a-tree--grid`(shell.css) 를 부여하고 격자를 그린다:
   - **가로 행선 + 빈영역 채움 = 완전 공통.** 각 행 `border-bottom`(공통) + ul 배경 `repeating-linear-gradient`(주기 = 가상스크롤 실제 행높이 `var(--u4a-vsrowh)` — 리터럴 금지, 스크롤 시 어긋남 / 색 = `--line`). ★ 반드시 **행과 함께 스크롤되는 ul** 배경에 얹는다(스크롤 컨테이너 고정배경 금지 — 세로 스크롤 시 가로선이 행과 어긋나 겹침). ★ 빈 영역까지 채우려면 **ul 이 스크롤영역을 채워야** 함 → `min-height` 는 화면 소유(WS20=100% / USP=`calc(100% - sticky헤더 2.75rem)`; 헤더 없는 트리는 100%).
   - **세로 컬럼선 = 배경 방식(고정폭 컬럼 전제)**: 화면이 변수 2개로 위치·색만 지정(공통이 ul 배경으로 렌더). `--u4a-tree-grid-vcolor`(기본 transparent=없음), `--u4a-tree-grid-vx`(background-position-x). 컬럼이 **고정 px/rem** 이면 x 가 상수라 정확·스크롤 무관. 예: WS20 액션컬럼 `right calc(0.5rem + 52px)`, USP 이름컬럼 `left calc(0.375rem + 1px + var(--ws30-name-w))`(리사이즈로 name-w 바뀌면 x 도 따라감). 리사이즈로 컬럼폭을 fixed px 로 만들면(§3.4.2) %컬럼도 이 방식으로 통일된다.
     - ⚠️ **flex 레이어(abs inset:0) 방식은 금지(스크롤 밀림 버그)**: 스크롤 컨테이너 안 `position:absolute; inset:0` 레이어는 콘텐츠와 함께 스크롤돼 **긴 트리를 스크롤하면 뷰포트 밖으로 밀려 세로선이 사라진다**(2026-07-13 안티 리뷰 지적 + 실측: scroll=max 시 레이어 top/bottom 이 뷰포트 위로 −. USP 최초 flex레이어 시도가 이 버그, 배경방식으로 교체). 배경은 x 가 ul box 기준 상수라 스크롤 무관(실측: scroll 0↔max 모두 세로선 x=187px 불변).
   - 소비처: **WS20 디자인트리**(`ws_html5_ws20_tree.js` `grid:true` + `ws20.css` 세로변수), **USP**(`ws_html5_usp_tree.js` `grid:true` + `usp.css` 세로변수 — 이름 고정폭이라 배경방식 적용, 컬럼 리사이즈는 §3.4.2). 앞으로 격자 있는 §3.4.1 트리는 전부 이걸 소비.

### 3.4.2 다열 트리테이블 — 컬럼 리사이즈/가로 스크롤 시 "컬럼은 고정폭"(필수)
§3.4.1 은 **비-리사이즈** 다열 트리(USP/MIME: 세로 스크롤만·설명 고정폭·이름 채움)의 정렬 규칙이다.
컬럼을 **사용자가 리사이즈**하거나 **가로 스크롤**이 필요한 트리테이블(원본 `sap.ui.table.Table/TreeTable`
= 고정폭 컬럼 + HSb)은 아래를 지킨다.

★ **공통 컴포넌트 SSOT = `U4AUI.makeColumnTree(host, cfg)`**(`theme/u4a-ui.js`, 스킨 = `shell.css` `.u4aColTree*`).
3열 그리드 트리테이블(sticky 헤더 + 세로 그리드라인 + 컬럼 리사이즈 가이드 + 가로 스크롤)은 **화면마다 새로 짜지 말고
이 컴포넌트를 소비**한다. cfg: `columns:[{label,width?}×3]`, `roots/children/hasChildren/key/label/tip`, `selectable`,
`icon?`, `slotLead?`, `cell(n)→{c2,c3}`, `rowHook(row,n)?`, `onSelect(n)?`, `emptyText?`. 화면은 **데이터 매핑만** 제공.
소비처: 대형 바인딩 별창(modelField/design), **소형 callBindPopup**(`js/fnBindPopupOpen.js` — 2026-07-08 자체 트리 폐기, 이 컴포넌트로 흡수).
(구 위치 `Popups/bindPopup/bindColumnTree.js` 는 공통 승격으로 폐지.) 리사이즈 없는 다열은 §3.4.1(App-F4 `fnAppF4PopupOpen.js` 등).

- ★ **컬럼 폭 = 고정(px/rem), `%` 금지.** `%` 로 주면 **패널(스플리터) 폭이 바뀔 때 컬럼이 같이 스케일**돼
  어색하다(사용자 지적 2026-07-08). 고정폭이면 스플리터로 패널만 넓/좁아지고 **컬럼은 불변**, 폭 합이
  패널보다 넓으면 **가로 스크롤**로 처리한다.
- **가로 스크롤 배선**: 스크롤 컨테이너 `overflow:auto`. 각 컬럼 셀 = `flex:0 0 var(--col-w)`(헤더/행/그리드라인
  동일 변수). ★ **마지막 컬럼도 `flex:1 1 0`(채움) 대신 고정폭** — 채움으로 두면 그 컬럼만 패널 따라 늘어나
  "컬럼이 움직인다"로 보인다(트레일링 여백은 무방). 헤더는 `position:sticky;top:0`(세로 고정·가로 동행).
- ★ **`<table>` 편집 그리드(트리 아님)도 리사이즈면 "고정폭 컬럼"이어야 한다.** 공통 `.u4a-table` 은
  `table-layout:fixed` 인데, 여기에 **`width:100%`** 를 주면 컬럼이 랩을 채우려 **비례 stretch** 돼 `<col>` 지정폭 ≠ 실제
  렌더폭이 된다 → **리사이즈 그립 가이드가 어긋나고 놓아도 폭이 안 붙는다**(2026-07-08 UI 템플릿 마법사 실측).
  → **채움(trailing filler) 컬럼 1개**: 데이터 `<col>` 은 고정폭, 맨 뒤에 **폭 미지정 `<col>` + 빈 `<th>/<td>`** 를 둔다.
  `table-layout:fixed` 는 폭 지정 컬럼을 고정하고 **남는 폭을 폭 미지정(채움) 컬럼에만** 준다 → 데이터 컬럼 stretch 없이
  격자가 **우측 끝까지 채워진다(원본 UI5 동일)**. `table.width:100%` + `table.minWidth = 데이터폭 합(채움 제외)` →
  랩이 넓으면 채움이 흡수, 좁으면 채움=0 + `overflow-x:auto` 가로 스크롤. (채움 컬럼을 빼고 `width:max-content` 로
  줄이면 우측이 텅 비어 어색 — 사용자 지적 2026-07-08.) 채움 `th/td` = `min-width:0;padding:0`, 우측 구분선은 앞 셀 box-shadow 가 그린다.
  그립 `getWidth` 는 **저장폭이 아니라 헤더 셀 `getBoundingClientRect().width`(실제 렌더폭) 실측**(트리 소비처와 동일).
  리사이즈 그립은 데이터 컬럼 전부(채움 제외)에 — 마지막 데이터 컬럼도 채움과의 경계에서 리사이즈된다.
- ★ **헤더·본문·트리는 "같은 명시적 총폭"으로 묶는다 — 요소별 `width:max-content` 금지.** 요소마다 max-content 를
  주면 헤더(라벨 span)와 행(nameCell+셀+중첩 ul)의 계산값이 **서로 달라 가로 스크롤 시 헤더/본문이 어긋난다**
  (2026-07-08 실측: 스크롤하면 헤더만 짧아짐). → JS 로 총폭 변수(`--*-total-w` = 컬럼폭 합 + 헤더 패딩/gap)를 계산해
  헤더·본문·트리에 **`width: max(100%, var(--*-total-w))` 동일 적용**(리사이즈마다 재계산). `max()`는 Ch93 OK.
- ★ **격자(row/column 라인)는 화면 전체에 — 데이터 없는 아래 영역까지.** 행 라인 = 각 행 `border-bottom` +
  **빈 영역은 본문 배경 `repeating-linear-gradient`**(행 높이 2.5rem 주기). 컬럼 라인 = 헤더/행 셀 `border-left` +
  **빈 영역은 "세로 그리드라인 레이어"**(본문 안 `position:absolute;inset:0`, 헤더와 동일 flex·컬럼폭 변수 공유,
  `pointer-events:none`, `z-index:0`; 트리는 `z-index:1`·배경 투명). 행이 몇 개뿐이어도 영역 전체가 격자로 채워진다
  (사용자 요구 2026-07-08). 구현 = 공통 `U4AUI.makeColumnTree` / `shell.css` `.u4aColTreeGrid`(그리드라인 레이어) + `.u4aColTreeBody` 그라디언트.
- **컬럼 리사이즈** = 각 컬럼 **우측 경계 그립**(absolute, `cursor:col-resize`) 드래그로 그 컬럼의 폭 변수만
  갱신(**최소 ~4rem, 상한 없음** → 넓히면 가로 스크롤). 더블클릭 = 기본폭 복귀. `%↔px 모드 전환` 같은
  중간 상태를 두지 말 것(전환 순간 폭이 점프해 어색 — 2026-07-08). 경계 강조는 `box-shadow inset`(±)로 헤더+그리드라인+행 동시.
- ★ **리사이즈는 "가이드 라인 + 놓을 때 적용"(UI5 sap.ui.table 방식) — 실시간 컬럼 이동 금지.** 드래그 중엔
  마우스를 따라 **세로 가이드 라인**(`position:fixed`, accent 2px, 트리 높이만큼)만 이동시키고, **mouseup 때 한 번만**
  실제 폭 변수를 갱신한다(실시간 갱신은 매 프레임 리플로우로 무겁고 잔상). 드래그 중 헤더 강조는 끄고 가이드만 보인다.
  (사용자 요구 2026-07-08.) 최소 폭 clamp(~4rem).
- ★ **더블클릭 = auto-fit(엑셀/`sap.ui.table` autoResize)** — 그 컬럼 내용(헤더+본문 셀) 중 **최장 폭에 자동 맞춤**.
  소비처가 `getAutoWidth()`(콘텐츠 최장 px 반환)를 넘기면 공통 함수가 더블클릭 시 그 폭으로 setWidth(최소폭 clamp).
  측정은 **`Range.getBoundingClientRect()`(overflow:hidden 무관 콘텐츠 잉크폭) + 패딩 여유**, 헤더 그립(absolute)은 측정서 잠깐 `display:none`,
  채움 컬럼 제외, 상한(예 800px)으로 과확장 방지(사용자 요구 2026-07-09, 첫 소비처=UI 템플릿 마법사 편집표).
  ⚠️ **편집칸(input/커스텀 콤보) 셀은 폭 100% 라 박스 측정이 무의미** → 그 안의 **텍스트(값/placeholder/선택 옵션)를 글자폭 실측**(콤보는 화살표·패딩 가산). Range 는 텍스트 셀에만.
  ★ **글자폭 실측 = `canvas.measureText`(DOM 변형·reflow 0). 오프스크린 span `body.append→getBoundingClientRect→remove` 금지** — 그 DOM 변형이 셀마다 레이아웃을 무효화해 **전 행 순회 auto-fit(비가상 트리=전 행 DOM) 시 셀마다 강제 리플로우** + 루프 내 다른 `getBoundingClientRect` 까지 스래싱 → 수백ms 버벅임. canvas 는 순수 계산이라 리플로우 0. 실측(320행): span 462ms → canvas 2.1ms(**≈220배**), 실제 auto-fit 22ms(2026-07-14). 폰트는 참조요소 `getComputedStyle` 로 `ctx.font` 세팅(letterSpacing 은 통상 0 이라 생략). 소비: `makeColumnTree _measTxt` / 마법사 `_wzMeasTxt` / 디자인트리 `_bwpGlyphW`.
  `getAutoWidth` 미제공 시 더블클릭 = `onReset`(기본폭 복귀) 하위호환.
  ★ **최초 렌더 초기폭도 auto-fit** — 고정 기본폭으로 그리지 말고, 처음 그릴 때 각 데이터 컬럼(체크박스·채움 제외)을 동일 측정으로
  콘텐츠 최장 폭에 맞춘다. 이후 재렌더·수동조절 폭은 보존(사용자 요구 2026-07-09).
  ⚠️ **가시성 타이밍**: 렌더 시점에 테이블이 아직 `hidden`(카드 표시 전 = `offsetParent===null`)이면 측정=0 → **`requestAnimationFrame` 으로 보일 때까지 재시도**(최대 N회) 후 측정. (마법사는 `_wzRenderTable` 이 `_wzSyncSteps`(카드 표시)보다 먼저 불려 최초엔 hidden 이라 스킵되던 버그 — 2026-07-09.)
  ★ **공통 SSOT = `U4AUI.attachColumnResize(grip, {host, getWidth, setWidth, getAutoWidth?, onReset?, hoverEl, hoverClass})`**
  (`theme/u4a-ui.js`) — 가이드/드래그/커서/복귀를 전담. **가이드 라인은 그립이 속한 열린 `<dialog>`(showModal top-layer)
  안에 append**한다 — `document.body` 에 붙이면 모달 뒤로 가려져 안 보인다(§2.10, 2026-07-08 수정).

  즉 host 로 테이블 전체를 넘기든 스크롤 컨테이너를 넘기든 화면 밖까지 뻗지 않는다 — 호출부가 host 를 잘못 넘겨도
  잔상이 깨지지 않도록 공통 함수가 흡수한다(2026-07-08, 위저드에서 host=테이블 전체 넘겨 가이드가 화면 밖까지 뻗던 버그). **컬럼 리사이즈 바가 있는 모든 트리테이블이 이걸 소비**한다
  (그립별 로직 복붙 금지). 소비처: **공통 `U4AUI.makeColumnTree`**(대형 바인딩 별창·소형 callBindPopup 이 이 컴포넌트로 일원화 — 트리테이블은

  - **컬럼은 전부 고정폭 유지**(공통 makeColumnTree 기본) → **전 컬럼 리사이즈 그립이 정상 동작**한다. ★가변 컬럼을 `flex:1 1`(grow)로 채우면 **그 컬럼 그립이 grow 에 흡수돼 무력화**되고 옆 컬럼 리사이즈가 그 컬럼을 늘렸다 줄여 "이상하게" 움직인다 — **채움(flex-grow)은 금지**.

    - ★**자동채움은 "첫화면 1회"만 — 판 리사이즈(스플릿바)마다 재확장 금지**. 팝업이 처음 유효 폭(clientWidth>0)을 가질 때 한 번 맞추고 **관측을 즉시 `disconnect`** 한다. 그 뒤 스플릿바로 판을 넓히면 우측 빈영역, 좁히면 가로스크롤(전 컬럼 고정 = App-F4). 컬럼 폭은 사용자가 **그립으로만** 바꾼다. ResizeObserver 로 **판 리사이즈마다 `_fitCustCols` 를 재호출하면 스플릿바 이동 때마다 컬럼폭이 멋대로 따라 변해** 사용자가 "왜 컬럼이 바뀌냐"고 지적한다(2026-07-10 실측·수정). 여는 순간 폭이 이미 유효하면 옵저버 없이 1회 호출로 끝낸다.
    - ★★**ResizeObserver 를 계속 붙여둬야 하는 경우(예 §7 카드뷰 `data-view` 토글)엔 무한루프 금지**: 관측 콜백 안에서 관측 대상의 폭/CSS 를 **동기적으로** 바꾸면 같은 프레임에 재리사이즈가 통지돼 "ResizeObserver loop limit exceeded" 크리티컬 에러로 터진다. 폭 변화 가드(`if(w===iLast)return`)만으론 **동기 재진입을 못 막는다** → 콜백 본문을 `requestAnimationFrame` 으로 다음 프레임에 미룬다(+재진입 가드). ★단, §3.4.2 자동채움처럼 **1회만 필요하면 rAF 가 아니라 아예 `disconnect`** 가 정답(옵저버를 남기지 않는 게 최선).
  - 수동 그립 리사이즈는 App-F4 표준(공통 `_syncTotal` 이 관리, 초과=가로스크롤·축소=우측 빈영역). "빈영역 없음"은 **여는 순간·판 크기 변화 시**만 보장(수동 축소는 사용자 의도).
  - ★**폐기(오답 이력)**: 첫컬럼 `flex:1 1` 채움✗(그립 무력화·리사이즈 이상 — 사용자 "리사이즈 안 되고 이상") / 빈 띠 가로줄 `background:none`✗ / 본문만 `total-w` 가두고 `border-right` 닫음선✗ / 그냥 100% 방치✗(빈 띠). 스코프(화면 JS)만, 공통 무변경 §0.5.
- **스플리터(패널 리사이즈)는 컬럼 폭을 건드리지 않는다**(별개 관심사). 컬럼 리사이즈는 그립, 패널 리사이즈는 스플릿 바.

## 4. 스플릿바(Splitter) — 공통 `.u4a-splitter*` + 서버리스트 기준 그립

좌우/3분할 패널을 나누는 **분할 리사이저(스플릿바)** 는 화면마다 새로 만들지 않고, 공통 골격
(`shell.css` 의 `.u4a-splitter*`)과 공통 드래그 동작을 소비하며 **모양(그립)은 서버리스트 기준으로
통일**한다. 트리(§3)와 동일한 단일화 원칙이다.

### 4.1 DOM 계약 (필수)
- 컨테이너 `<div class="u4a-splitter">` 안에 **패널과 바를 번갈아** 배치한다.
  - 2분할: `pane · bar · pane`
  - 3분할(마스터-디테일): `pane · bar · pane · bar · pane`
- 패널 `<div class="u4a-splitter__pane">`, 바 `<div class="u4a-splitter__bar" role="separator">`.
- 컨테이너는 `display:flex; width/height:100%; overflow:hidden`(패널 폭 합이 넘쳐도 페이지로 전파하거나
  세로 공간을 침범하지 않게 클립) — `shell.css` 가 소유한다.
- 패널 폭은 **인라인 `flex`** 로 표현한다: 초기엔 비율(예: 좌측 `0 0 30%`, 가운데 축소형 `0 1 34%`),
  **마지막 패널은 `1 1 auto`**(잔여 채움). 드래그하면 고정 패널이 `0 0 <px>px` 로 바뀐다.
- **초기 고정 px 폭 금지**(반응형, [12번](12_테마_컨버전_전략.md) 7장) — 초기 basis 는 %/유동 단위,
  px 폭은 사용자의 드래그 결과로만 생긴다.

### 4.2 시각 표준 — 서버리스트 기준 그립 (필수)
- 바 폭 11px, 표면색 배경 + 좌우 1px 경계.
- **가운데 그립 핸들**(바 `::before`): 5px×36px 알약(radius 4px), 평소 뮤트색(`--icon-muted` 계열) opacity .5.
- **hover**: 바 배경 → **불투명 `--surface` + `--hover-bg` 틴트 오버레이**(`background-color:--surface` +
  `background-image:linear-gradient(--hover-bg,--hover-bg)`), 그립 → **accent 색 + opacity 1 + 높이 50px** 로 강조.
  ⚠️ 바 hover 에 `background: var(--hover-bg)`(반투명 단색)만 주지 말 것 — 반투명이라 surface 가 사라지고
  **바 뒤 컨테이너 배경이 비치는데, 그 컨테이너가 화면마다 달라(WS20=app-bg, 옵션=투명→body 등) 같은
  토큰인데도 hover 색이 화면마다 달라 보인다.** surface 베이스+틴트로 고정해야 전 화면 동일(2026-06-22).
- 커서 `col-resize`. 색은 전부 의미 토큰만 사용(하드코딩 hex 금지). 치수(11/5/36/50px)는 그립 형태값으로 허용한다.
- ⚠️ **바 배경을 화면별로 override 할 땐 `:hover` 도 같은 특이도로 함께 override 한다(필수).** 공통 hover 는
  `.u4a-splitter__bar:hover { background: var(--hover-bg) }`(클래스 특이도 0,2,0). 화면에서 `#id .u4a-splitter__bar { background: … }`(id 특이도 1,1,0)로 **기본 배경만** 바꾸면 그게 공통 `:hover` 를 이겨 **그 화면만
  hover 색이 사라진다.** → 반드시 `#id .u4a-splitter__bar:hover { background: var(--hover-bg) }` 도 같이 준다.
  (WS20·옵션 팝업에서 이 specificity 함정으로 hover 통일이 깨졌던 사례 — 2026-06-22.)

### 4.3 동작 — 인접 재분배 드래그 + 리사이즈 재클램프 (필수)
- **드래그**: 바를 잡으면(`mousedown`) `body` 커서를 `col-resize` 로, `mousemove` 로 **바 양옆 인접 두 패널
  사이에서만** 폭을 주고받는다(나머지 패널은 불변). 각 패널의 `min-width` 이하로는 줄지 않는다.
- **마지막(유연) 패널 보호**: 오른쪽 이웃이 마지막 `1 1 auto` 패널이면 왼쪽만 px 로 두고 오른쪽은 flex 로
  잔여를 채운다 → 마지막 패널(상세 등)이 짜부되어 사라지지 않는다.
- **창 리사이즈 재클램프**: 창이 줄면 `px` 고정 패널 합 + 바 + 유연패널 최소폭이 컨테이너를 넘지 않도록
  **큰 고정 패널부터 min 까지 자동 축소**한다(`overflow:hidden` 에 잘려 마지막 패널/바가 숨는 것 방지).
  유연/% 패널은 CSS `flex`+`min-width` 로 알아서 줄므로 **px 고정분만** 처리한다. 리스너는 **1회만 바인딩**하고,
  뷰 전환으로 스플릿이 새로 그려져도 `querySelector` 로 그 시점의 스플릿을 처리한다.
- min-width 폴백 120px.
- **더블클릭 = 최초 위치 복귀(공통·전역 자동, 승격 완료)**: 바를 더블클릭하면 인접 패널이 **처음(드래그 전) 폭**으로
  돌아간다. `u4a-ui.js _installGlobalSplitterReset()` 가 모듈 로드 시 1회 자동 설치 — 모든 `.u4a-splitter__bar` 에
  **위임 1개**로 적용(화면별 배선 불필요, 다이얼로그 드래그와 동일 패턴). 최초 폭은 각 패널이 "처음 드래그되기
  직전"(document `mousedown` **capture** → 화면별 드래그보다 먼저 실행)의 인라인 `style.flex`(없으면 `""`=CSS
  기본)를 `data-u4aSplitHome` 에 **1회만** 기록(이미 있으면 안 덮음 → 두 바가 공유하는 패널(3분할 가운데)도 최초값
  유지), 더블클릭 시 바의 prev/next 형제(=인접 패널, 클래스 무관)를 그 값으로 복귀. 드래그/재클램프(아직 화면별
  복제)와 달리 **이 동작은 단일 전역 헬퍼로 이미 승격됨** → 새 분할 화면은 바에 `.u4a-splitter__bar` 만 붙이면 자동.

> **필수 엣지 케이스 — 최대화 후 restore 시 바/패널이 숨는 문제**
> 브라우저(창) **최대화 상태에서 스플릿바를 끝까지 드래그**하면 한쪽 패널이 큰 `px` 로 고정된다.
> 이 상태로 창을 **restore(축소)** 하면, 고정 px 합 + 바 폭이 줄어든 컨테이너를 초과해 `overflow:hidden` 에
> 뒤쪽 패널·바가 잘려 **사라진 것처럼 보인다.** → 위 "창 리사이즈 재클램프"가 이를 막는 **필수** 처리다.
> 새 분할 화면은 반드시 이 재클램프를 바인딩한다.
> **★ 세로 스플리터(row-resize)도 100% 동일하게 적용된다** — "폭/좌우/min-width" 를 "높이/상하/min-height,
> `clientHeight`" 로 바꿔 읽는다. 세로판에서는 상단 패널이 큰 `px` 높이로 고정된 뒤 창을 세로로 줄이면
> 하단 패널·바가 밑으로 밀려 잘린다(예: 버전 관리 창 — 스플릿바 최하단 배치 후 창 축소 시 바 사라짐).
> 목록(상단) `px` 를 `컨테이너 clientHeight − 바 높이 − 하단 패널 최소` 로 재클램프한다.
> 레퍼런스(동일 패턴): ServerList `_bindSplitterResizeClamp`(가로), WS20 `_bindWs20SplitResizeClamp`(가로),
> 버전 관리 `versionMngFrame.js _clampSplitV`(**세로**).

> **필수 — iframe 위에서 드래그가 끊기는 문제(공통·전역 자동, 승격 완료)** ★반복 함정★
> 패널 안에 `<iframe>`(미리보기·TinyMCE/Monaco 에디터 등)이 있으면, 스플릿바(또는 다이얼로그 헤더)를
> 드래그하다 마우스가 **그 iframe 위로 들어가는 순간 `mousemove` 가 iframe 자기 문서로 들어가** 부모의
> 드래그 추적이 **끊긴다**(바가 안 따라옴). → 해결: **드래그 동안 모든 iframe 의 `pointer-events` 를 끈다.**
> - 공통 처리(화면별 배선 불필요): `u4a-ui.js` 의 전역 드래그 핸들러(`_installGlobalSplitterReset` /
>   `_installGlobalDialogDrag`)가 드래그 시작 시 `body` 에 **`.u4a-dragging`** 을 붙이고 종료 시 뗀다.
>   `shell.css` 의 **`body.u4a-dragging iframe { pointer-events: none; }`** 가 그동안 모든 iframe 입력을 차단 →
>   `mousemove` 가 부모 document 로 계속 들어와 매끄럽게 드래그된다. **새 분할/드래그 화면은 바에
>   `.u4a-splitter__bar`(또는 헤더에 `.u4a-dialog__header`)만 붙이면 자동 적용** — 화면별 오버레이/배선 금지.
> - 레퍼런스: docPopup(TinyMCE iframe) 스플릿바가 이 공통으로 동작(자체 처리 0).

### 4.3a 드롭존(파일/UI 투입 영역) 강조 표준 (필수)
드래그 데이터를 **받는 영역**(파일 첨부·UI/컨트롤 드롭 등)은 드래그가 위로 올라온 동안 아래 **단일 시각 표준**으로
강조한다. 레퍼런스(SSOT) = 런타임 클래스 탐색기 `.u4aRtmDrop.is-dragover`.

- **트리거**: `dragenter`/`dragover` 에서 강조 클래스 부여(+`preventDefault` — 안 하면 브라우저가 drop 거부),
  `dragleave`(영역을 **완전히** 벗어날 때만 — `relatedTarget` 이 영역 내부면 유지 → 자식 이동 시 깜빡임 방지)·`drop`·
  `dragend` 에서 제거. → **마우스를 뗄 때까지 강조 유지**.
- **시각(색=의미 토큰만, 하드코딩·점선 금지)**: **실선 accent 테두리 `0.125rem solid var(--accent)`** +
  **배경 `var(--state-info-bg)`** + **`transition: background-color 0.15s ease`**(부드러운 전환). 아이콘 있으면 `opacity:1`.
  - **강조는 반드시 "비스크롤 래퍼"에 건다** — 강조 대상이 **스크롤/overflow 요소**(예: `makeColumnTree` 호스트)면
    outline/border 를 그 위에 걸어도 **스크롤·sticky 컬럼헤더·행 배경에 4변이 가려져 "윗부분만/일부만" 보인다**
    (장군님 지적 2026-07-13). → **그 요소의 비스크롤 부모(`position:relative`)에 `::after` 오버레이**로 네모박스를
    콘텐츠 **위(z-index)** 에 덮되 **`pointer-events:none`**(드롭은 아래로 통과)로 처리 → 4변이 항상 온전. 예:
    `bindPopup .u4aBwpDesign::after {position:absolute;inset:0;border:.125rem solid var(--accent);pointer-events:none;z-index:5}`.
    (이미 비스크롤 래퍼면 — mimeRepository `.u4aMimeImpTbWrap`(position:relative) — `outline-offset:0` 만으로도 온전.)
  - ~~점선(dashed)~~ 금지 — 표준은 **실선**.
- **모션(선택 · 권장 리치 변형)**: 오버레이는 **반투명 wash(`::before`, `background:var(--state-info-bg)`+`opacity:0.4`) +
  실선 accent 테두리(`::after`)** 2겹으로 나눠, **테두리 페이드인(0.18s)** + **wash 숨쉬기(opacity 0.3↔0.5, 1.6s 무한)**.
  ★ **반드시 `@media (prefers-reduced-motion: reduce)` 로 애니메이션 끔**(정적 wash+테두리만). 색은 토큰만(color-mix 금지).
  레퍼런스 = bindPopup `.u4aBwpDropZone::before/::after`.
- **소비 현황(2026-07-13)**: runtimeClassNavigator(`.u4aRtmDrop`, 레퍼런스) / bindPopup 디자인 트리
  (`.u4aBwpDropZone`, WS20 디자인 트리 → 가운데 drop, 반투명 wash+숨쉬기 모션) / mimeRepository 파일 첨부
  (`.u4aMimeImpTbWrap.u4aMimeImpDrag`, 동일 wash+숨쉬기 모션).
- 새 드롭존 화면은 이 값을 그대로 소비 — 자체 색/점선/배경 금지.

## 5. 다국어(i18n) / 텍스트

화면에 보이는 **모든 문구는 SQLite 메시지 클래스의 키**에서 가져온다. 문자열을 소스에 직접 적지 않는다
(하드코딩 금지). 컨버전·신규 화면 공통 규칙이며, 메시지 키 사용 원칙은 [02번](02_로그인_서버리스트.md)·
[15번](15_공통_입력UX_가이드.md)과 동일하다.

### 5.1 공통 추출 함수 (필수)
- **저수준**: `WSUTIL.getWsMsgClsTxt(LANGU, MSGCLS, MSGNR, p1, p2, p3, p4)` — SQLite 에서 언어/클래스/번호로
  텍스트를 조회하고 `&1`~`&4`(및 `&`) 플레이스홀더를 `p1`~`p4` 로 치환한다.
- **래퍼**: `fnGetMsgClsText(MSGCLS, MSGNR, p1..p4)` — `LANGU` 를 워크스페이스 언어로 해석한 뒤 위 저수준 함수를
  호출한다. 래퍼 진입점은 화면마다 다를 수 있으나(예: ServerList `MessageClassText.fnGetMsgClsText`,
  WS `oAPP.common.fnGetMsgClsText`) **모두 `WSUTIL.getWsMsgClsTxt` 로 위임**된다 — 새로 만들지 말고 그 화면 래퍼를 쓴다.
- 화면 코드는 위(저수준/래퍼) 중 하나만 쓴다. **리터럴 문자열을 DOM 에 직접 넣지 않는다.**

### 5.2 언어 기준
- 라벨 언어 = **워크스페이스(접속 사용자) 언어** — `parent.process.USERINFO.LANGU`(있으면 최우선),
  WS UI 언어는 `WSUTIL.getWsLanguAsync()`. **백엔드 `serverInfo.LANGU` 가 아니다.**
- 메시지 클래스 예: `ZMSG_WS_COMMON_001`(번호 M0271 등), `/U4A/CL_WS_COMMON`(번호 A68/A69 등).

### 5.3 금지
- 하드코딩 문자열, **영문(또는 임의) 폴백 기본값**, 완료 토스트 등 **임의 문구 생성**, **가짜/추측 키** 사용 금지.
- 기존 키가 있으면 **그대로 재사용**한다(같은 의미의 키 중복 생성 금지).

### 5.4 신규 텍스트가 필요할 때 (작업 흐름)
화면에 **기존 키가 없는 새 문구**가 필요하면:
1. 소스에는 **공통 추출 함수 호출만** 넣는다(하드코딩·자리 임시문구 금지). 그 자리에서 임의 키를 확정하지 않는다.
2. 작업 중 발생한 **신규 텍스트를 모았다가, 작업 끝에 "신규 항목만" 목록으로 제출**한다(아래 양식).
3. 사용자가 그 목록을 **번역하여 SQLite DB 에 추가/업데이트 → 앱 재실행**한다.

**신규 텍스트 제출 양식**(예시):

| # | 메시지클래스(제안) | 번호(제안) | 한국어 원문 | 플레이스홀더 | 사용 위치(파일 · UI) |
|---|---|---|---|---|---|
| 1 | /U4A/CL_WS_COMMON | (신규) | 서버를 선택하세요 | – | ServerList.js · 빈 상태 안내 |
| 2 | /U4A/CL_WS_COMMON | (신규) | &1 개 항목이 선택됨 | `&1`=개수 | (예) 다중선택 푸터 |

- 클래스/번호는 **제안**이며, 최종 확정은 사용자(번역·DB 입력) 몫이다.
- 플레이스홀더가 있으면 `&1`~ 표기와 의미를 함께 적는다.

## 6. 테이블(Table) — 공통 `.u4a-table` + 컬럼 정렬/필터 메뉴 (서버리스트 기준)

목록/그리드는 **공통 테이블 컴포넌트**를 소비한다. 화면마다 표 스타일·정렬·필터를 새로 만들지 않는다.

### 6.1 단일 출처 (필수)
- 마크업: `.u4a-table-wrap > table.u4a-table`(`shell.css`).
- **래퍼(컨테이너) 외형도 공통 단일 출처** — 화면마다 손으로 깔지 말 것(이걸 안 지켜 CSS Link 팝업 테이블이 AppF4/Insert 와 달라 보였던 사례, 2026-06-25):
  - **팝업/다이얼로그 안 테이블 = 액자형 `.u4a-table-wrap.u4a-table-wrap--boxed`**(`shell.css`: `overflow:auto` + `border:var(--line)` + `border-radius:var(--radius)` + `background:var(--surface)` + `flex:1 1 auto;min-height:0`). AppF4 F4팝업·Insert Element 팝업·CSS/JS Link 팝업 모두 **이 한 클래스**로 동일 외형. 화면 CSS 에서 `border`/`radius`/`background` 직접 칠하지 말 것(`--divider`·하드코딩 radius 금지 → 색·굵기 어긋남).
  - **풀페이지 보더리스 테이블(ServerList)** 은 `--boxed` 를 안 붙인다(테두리 없음, 세로 스크롤만). 즉 액자 여부만 모디파이어로 가른다.
- ⚠️ **단독 테이블 모디파이어 `.u4a-table--compact` 는 쓰지 않는다** — 혼자 행이 좁아져 다른 표와 달라 보인다(insert·errMsg 가 붙였다 제거). 화면별로 `height`/`padding` 으로 행높이를 직접 건드리지 말 것.
  - **영역 전체를 밀도있게 하려면 컨테이너 스코프 클래스 `.u4a-compact`(sapUiSizeCompact 사상, `shell.css`)** 를 그 컨테이너(다이얼로그/패널/페이지/폼)에 붙인다. 하위 공통 컨트롤(버튼/입력/셀렉트/콤보)+테이블 행이 **함께** compact 높이로 줄어 일관성이 유지된다(테이블만 외톨이로 좁아지는 §349 문제 없음). **높이만** 축소(폰트/아이콘 글리프 유지), 전역 강제가 아니라 **필요한 영역에만 부분 적용**. 터치(coarse)에선 자동 완화(체크리스트 J). 테이블 행은 토큰(`--control-h`/`--row-h`)만 재정의해 일반·가상스크롤 모두 자동 반영. 화면에서 직접 height 깎지 말고 이 클래스를 소비.
- 헤더 sticky, zebra=행 `data-odd="true"`, hover, **선택=행 `aria-selected="true"`(좌측 accent 바)**, 빈 결과=`tr.u4a-table__nodata`, 포커스 링.
- 카드(타일) 뷰 `.u4a-table-wrap[data-view="card"]`(컨테이너쿼리 미지원 → 화면 JS 가 ResizeObserver 로 `data-view` 토글)는 **옵트인 기능**이다.
  - ⚠️ **카드 반응형은 사용자/원본의 별도 언급 없이는 적용하지 않는다.** 기본값은 `data-view="table"`(가로 스크롤로 대응). "공통 표준에 있으니까" 자동으로 끼워넣지 말 것 — 특히 **인라인 편집 그리드**(입력칸·스위치·체크박스 행)는 카드 뷰가 편집 UX 를 해친다. 필요하면 그때 명시 요청으로만 켠다. (근거: 요청 밖 UX 추가 금지.)
- `.u4a-table*` 는 전부 `shell.css` 공통. 화면별 확장(컬럼 폭·정렬메뉴 헤더 등)만 `.u4a-c-*`/스코프로 얹는다.

### 6.1.1 단일페인 데이터 테이블 렌더 함수 — 공통 `U4AUI.makeDataTable(host, cfg)` (2026-07-13 신설)
`.u4a-table` 은 "스킨"이고, **단일페인 가상 데이터 테이블의 렌더(골격+헤더+행+선택+가상스크롤)를 손으로 반복하던 것**을 공통 함수로 수렴한다(`theme/u4a-ui.js`). 화면마다 `<table>`/`<thead>`/`<tbody>` 마크업 + `buildRow`(컬럼→`<td>`) + `zebra` + 클릭선택/더블클릭확정 + `makeVScroller` 배선을 다시 짜지 말고 이 함수를 소비한다.
- **cfg**: `columns:[{ key, label, width?, align?, cell?(row,idx)→string|Node, className?, cellClass? }]`, `virtual`(기본 true), `zebra`(기본 true), `compact`, `rowKey(row,idx)`(선택키·기본 idx), `onSelect(row,idx)`(단일클릭), `onActivate(row,idx)`(더블클릭 확정), `rowHook(tr,row,idx)`, `emptyText`(0건=공통 `.u4a-table__nodata`), `rowH`, `tableClass`.
- **반환**: `{ el, table, thead, tbody, setColumns(cols), setRows(rows,keepScroll), setSel(key), getSel(), refresh(), renderHead() }`. **컬럼은 생성 시 또는 `setColumns()`로 나중에**(서버 응답 후 동적 컬럼) 지정 — F4/OTR/DynList 처럼 서버가 컬럼을 주는 화면 지원. 내부는 공통 `.u4a-table` 스킨 + `makeVScroller` 조립(재발명 아님).
- **적용(2026-07-13)**: ✅ F4 검색도움(`fnF4SearchHelpPopup.js`)·✅ OTR F4 도움(`OTRF4HelpPopup/index.js`)·✅ 동적리스트(`fnDynListPopup.js`).
- ⚠️ **스코프 경계(억지 통합 금지 — 오버엔지니어링 방지)**:
  - **2페인 고정컬럼(App-F4)** = frozen/scroll 2페인·페인별 독립 `makeVScroller`·hover/선택/가로스크롤 동기라 **bespoke 유지**(공통 `makeVScroller`·`.u4a-table` 만 소비). makeDataTable 대상 아님.
  - **컬럼메뉴(정렬/필터) 데이터그리드(WS20 Insert Element 등)** = `U4AUI.openColumnMenu`(§6.2) 로 컬럼별 필터/정렬하는 그리드는 **bespoke 유지**. makeDataTable 에 필터/정렬을 넣지 말 것(단순 헤더+행+선택만 담당).
  - **정적 소형표** = `.u4a-table` 스킨만으로 충분(렌더 함수 불필요).
  - 판단 기준: **컬럼이 [key,label]만인 단순 단일페인 가상표 = makeDataTable / 고정컬럼·컬럼메뉴 = bespoke**.

### 6.2 컬럼 헤더 정렬/필터 메뉴 — 서버리스트 기준 (필수)
원본 UI5 `sap.ui.table` 의 `sortProperty`/`filterProperty`(헤더 클릭 시 정렬·필터 메뉴)는 **서버리스트 `fnOpenColumnMenu` 패턴으로 통일**한다.
- 정렬·필터 가능한 `th` 에 `.u4a-th--menu`(클릭) + 내부 `.u4a-th__inner`(라벨 `.u4a-th__label` + 표시자 `.u4a-th__ind`).
- 클릭 → 공통 `.u4a-menu.u4a-colmenu`. **구성·순서(서버리스트 동일)**: ① 필터 input(`.u4a-colmenu__filter > .u4a-input`) ② 구분선 ③ 오름차순 정렬 ④ 내림차순 정렬 ⑤ 구분선 ⑥ 필터 초기화(이 컬럼).
- **필터**: 표시 텍스트 기준 contains(대소문자 무시), 여러 컬럼 **AND**, Enter/blur 시 적용. **정렬**: 단일 컬럼 `localeCompare(…,{numeric:true})`, 같은 방향 재클릭 시 해제. 활성 정렬 항목=`.u4a-menu__item[data-active="true"]`.
- **표시자**(`.u4a-th__ind`): 정렬 걸린 컬럼=화살표(arrow-up/down), 필터 걸린 컬럼=깔때기(funnel). 걸린 컬럼만 노출.
- **원본 배열(검색결과 등)은 보존**하고 화면에 그릴 **뷰만 필터→정렬로 파생**(비파괴). 헤더는 매 렌더 재구성(표시자 갱신).
- 메시지 키: 오름/내림 정렬=`ZMSG_WS_COMMON_001` 810/811, 필터 값(placeholder)=`/U4A/CL_WS_COMMON` A68, 필터 초기화=A69.
- ⚠️ `.u4a-th__*`·`.u4a-colmenu*` CSS 는 현재 **서버리스트 전용(`serverlist.css`)** — 다른 창은 스코프로 복제(공통 `.u4a-menu`/`.u4a-menu__item` 은 `shell.css`). **향후 `shell.css` 승격 권장.** showModal 다이얼로그 안 테이블이면 메뉴를 **다이얼로그(top-layer) 안에 append**(밖이면 모달에 가림) + `getBoundingClientRect`+`position:fixed` 로 헤더 아래 배치.
- ⚠️ **메뉴는 컨트롤러로 일반화해 공유**: `_openColMenu(c, th, ctl)` 가 상태를 직접 만지지 말고 컨트롤러(`getFilter/setFilter/getSort/setSort/rerender`)를 받게 한다 → 한 화면에 표가 여럿(예: F4 탭1 결과표 + 탭2 트리표)이면 컨트롤러만 따로 주고 메뉴·표시자·정렬·필터 로직은 1벌 공유. 상태 변수만 표별로 분리.
- ⚠️ **sticky 헤더 hover 배경의 반투명 함정**: `th:hover{background:var(--hover-bg)}` 만 주면 `--hover-bg`(rgba ~.08, 92% 투명)가 불투명 `--surface` 를 덮어 **헤더 뒤로 스크롤되는 데이터가 비쳐 헤더 글자가 "겹쳐" 보인다**. 반드시 `background:linear-gradient(var(--hover-bg),var(--hover-bg)),var(--surface)` 로 불투명 surface 위에 틴트를 얹는다(프로즌 셀·스플릿바 hover 와 동일 레이어 문법, §4.2).
- **정렬·필터 전체 해제 버튼(권장)**: 정렬 가능한 컬럼이 많으면 메뉴로 일일이 끄기 번거로우므로 **결과 테이블 위 툴바**에 한 번에 초기화하는 아이콘 버튼(`filter-circle-xmark`)을 둔다. 걸린 게 없으면 **비활성**(`:disabled`), 툴팁은 per-column 과 같은 의미라 **A69** 재사용. **범위 = 클라이언트 뷰 파생(헤더 메뉴: 정렬+컬럼필터)만 리셋**, 서버 쿼리(검색 폼 입력)는 유지(F4 탭1 기준). 단 그 화면의 검색박스가 클라이언트 필터면(F4 탭2 트리) 같이 초기화한다. F4 탭1·탭2 모두 적용. ⚠️ 툴바 아이콘 버튼은 화면별로 크기 줄이지 말 것 — 공통 `.u4a-btn-icon` 표준 2rem(행 안 액션 버튼만 컴팩트 허용, override 는 `.u4a-table` 스코프로 가둔다).

### 6.2.1 트리 테이블(TreeTable)의 컬럼 정렬/필터 — 트리 의미로 변형
원본 UI5 `TreeTable` 컬럼도 `sortProperty`/`filterProperty` 가 없었다(F4 두 탭 모두). 위 6.2 헤더메뉴를 트리에 이식하되 **트리 의미로 변형**한다(F4 탭2 기준).
- **정렬 = 형제 노드끼리만**(각 부모의 자식 배열을 정렬키로 재정렬, 계층 구조·깊이는 유지 — UI5 TreeTable sorter 동일). **비파괴**(원본 배열 보존, 평탄화 단계에서 정렬뷰 생성). 최상위 배열도 정렬.
- **필터 = 경로 유지 contains**: 노드 자체 매칭 = (상단 검색박스 매칭) **AND** (컬럼필터 매칭). 최상위 컨테이너 노드는 항상 통과. 자손에 매칭이 있으면 **조상 경로를 표시**(트리 끊김 방지). 매칭이 0이면 root 까지 빠져 공통 no-data.
- 컬럼필터 변경/탭 재진입(재조회) 시에도 **매칭 경로 자동 펼침**(검색박스와 동일 규칙) — 필터 활성이면 펼침 모습 유지.
- **전체 해제 버튼**: 컬럼 헤더가 여러 개라 정렬·필터를 일일이 메뉴로 끄기 번거로우므로, 툴바에 **정렬·컬럼필터·검색박스를 한 번에 초기화하는 버튼**(아이콘 `filter-circle-xmark`)을 둔다. 걸린 게 하나도 없으면 **비활성**(`:disabled`). 툴팁은 per-column 초기화와 같은 의미라 메시지키 **A69**(필터 초기화) 재사용. 검색박스도 비울 땐 `input` 이벤트를 디스패치해 clear(X) 글리프까지 동기화.

### 6.3 적용 현황
- 레퍼런스: 서버리스트(`ServerList.js` `fnOpenColumnMenu`/`_buildServerView`).
- 소비: errMsgPopup, App Search Help F4 팝업(탭1 결과 테이블 + **탭2 트리 테이블** = 6.2.1 변형).

## 7. 플로팅 푸터 메시지(Footer) — 공통 `U4AUI.footer*` + `.u4a-footer`

화면 하단에 잠깐 떠오르는 상태/결과 메시지(구 sap.m floatingFooter). **단일 출처 = `U4AUI.footerMarkup/footerShow/footerHide`(u4a-ui.js) + shell.css `.u4a-footer*`.** 화면마다 마크업/show·hide 를 복제하지 않는다.

### 7.1 단일 출처 (필수)
- 마크업: `U4AUI.footerMarkup(sId)` 가 반환하는 문자열을 화면 마크업에 삽입. 구조 `.u4a-footer[data-show][data-type]` > `.u4a-footer__icon` + `.u4a-footer__text` + `.u4a-footer__close`(X, `data-u4a-footer-close`).
- 표시/숨김: `U4AUI.footerShow(elOrId, type, msg, ms)` / `U4AUI.footerHide(elOrId)`. `type` = E/S/W/I(아이콘·색 자동), `ms` 생략=10000, **`ms=0`=자동숨김 없음**(타이머를 호출측 래퍼가 소유할 때).
- **닫기(X)는 전역 위임 1개**(`document` click → `[data-u4a-footer-close]`) — 화면별 `addEventListener` 금지.

### 7.2 코어 UX 규칙 (베이스가 강제)
- 색은 의미 토큰만(`--state-error/success/warning/info`, `--surface`/`--line`/`--popover-shadow`). 하드코딩 금지.
- 노출 시 1회 슬라이드업 `animation`(종료 `transform:none` → 잔여 컴포지팅 레이어 없음 = 프레임리스 타이틀바 드래그영역 무영향). `prefers-reduced-motion` 시 애니메이션 off.
- 문구는 메시지 키만(임의 생성 금지, §5).

### 7.3 적용 현황
- 소비: WS10(통합 `js/ws10_html.js` + 독립 프리뷰 `WS10/WS10.js`), WS20(`ws_html5_ws20.js`), WS30 USP(`js/usp/ws_html5_usp.js`). 각 화면의 `oAPP.{ws10html|ws20html|usphtml}.showFooter/hideFooter` 는 이름 유지하고 내부만 `U4AUI` 위임(셸 `fnShowFloatingFooterMsg` 라우팅 무수정).
- 이관 전: CSS만 `.u4a-ws10__footer`(ws10.css) 공유 + 로직 복제 → WS30 만 닫기(X) 누락이었음(2026-06-23 통일, 구 CSS 제거).

> 참고: 컨텍스트 메뉴 그룹 구분선은 공통 `.u4a-menu__sep`(shell.css). 트리 서브트리 펼침은 `U4AUI.createTree().expandSubtree(node)`.

## 8. 패널(Panel) — 공통 `U4AUI.createPanel` + `.u4a-panel*`

### 8.1 단일 출처 (필수)
- 접이식 조회/속성 영역(원본 `sap.m.Panel` expandable)은 **공통 패널 하나**를 소비한다.
  - **로직**: `theme/u4a-ui.js` 의 `U4AUI.createPanel(cfg)` — 헤더/토글/접힘 상태(`data-collapsed`) 관리.
  - **스타일**: `theme/shell.css` 의 `.u4a-panel*`(토큰만, 하드코딩 0).
- **금지**: 화면마다 패널 골격(섹션+헤더버튼+바디+접힘 토글)을 새로 짜는 것 = 소스 이원화.

### 8.2 구조 / API
- DOM: `<section.u4a-panel[data-collapsed]>` > `.u4a-panel__head`(= `.u4a-panel__toggle`(twisty+제목) + `.u4a-panel__actions` 슬롯) + `.u4a-panel__body`. ★ 헤더에 **검색 버튼 등 액션**을 넣을 수 있게 head 는 `div`, 접기 토글만 `button`(버튼 중첩 회피). twisty 회전은 CSS(`:not([data-collapsed="X"])` → 90°), innerHTML 스왑 안 함.
- 헤더 높이 `min-height:2.75rem`(액션 버튼이 들어가도 균형). **헤더 배경 = `--hover-bg` 상시 틴트**(`.u4a-panel__head`)로 본문과 시각 구분(옛 hover 색을 기본으로 올림), **hover 시 `--active-bg` 로 살짝만 더 강조**(헤더 전체가 한 덩어리 — 검색 버튼도 같은 밴드). 토글만 hover 시키면 좌측만 칠해져 액션 버튼이 분리돼 보였음. 토글은 `align-self:stretch` 로 헤더 높이만큼 클릭(접기) 영역 확보.
- `createPanel({title, collapsed, onToggle})` → `{ el, head, body, actions, toggle, setCollapsed(b), isCollapsed() }`. 화면은 `body`에 내용, `actions`에 헤더 버튼을 append.
- 외부에서 프로그램적 접기: `el` 에 `data-collapsed="X"` 세팅(공통 CSS 가 바디 숨김+twisty 회전 처리) + 필요 시 `.u4a-panel__toggle` aria-expanded 동기. (USP 에디터 전체화면 토글이 이 방식.)

### 8.3 적용 현황
- 소비: **WS30 USP Properties 패널**(`js/usp/ws_html5_usp.js _buildUspPanel`, 화면은 여백/flex만 `.u4aWs30Panel` 로 확장), **AppF4 F4팝업 조회조건 패널**(`fnAppF4PopupOpen.js`, 헤더 actions=검색 버튼, 바디=조회 폼). (2026-06-23 USP 전용 `u4aWs30Panel*` → 공통 이관, F4 신규 소비.)

## 9. 페이지 전환(Navigation) 애니메이션 — 공통 `fnNavTo` + `.u4aWsNav*` (필수)

전체 화면(워크스페이스 스텝) 단위 **페이지 이동은 반드시 공통 전환 애니메이션(슬라이드+페이드)을 거친다.** 즉시 `display` 토글이나 하드 스왑으로 화면을 바꾸지 말 것.

### 9.1 단일 출처 (필수)
- **로직**: `www/ws30/ws10_20/js/ws10_html.js` 의 `oAPP.fn.fnNavTo(sToId)` — 나가는/들어오는 페이지 컨테이너에 방향별 클래스를 부여/정리. 진입점은 `fnOnMoveToPage(sPgNm)`(shell) → `fnNavTo`.
- **스타일**: `www/ws30/ws10_20/WS10/css/ws20.css` 의 `.u4aWsNavInFwd/InBack/OutFwd/OutBack` + `@keyframes` (구 `sap.m.NavContainer` 슬라이드 전환 대체).
- **컨테이너**: `.u4aWsApp`(`position:relative; overflow:hidden` — 슬라이드 중 가로 삐짐 클립) > `.u4aWsPage`(`position:absolute; inset:0`) / 숨김 = `.u4aWsHidden`(`display:none`).
- **금지**: 화면마다 자체 전환 CSS/토글을 새로 짜는 것. 페이지 스텝 이동은 반드시 `fnNavTo`(또는 이를 감싼 `fnOnMoveToPage`) 경유.

### 9.2 사양 (필수 — 값 고정)
- **duration/easing**: `0.26s ease both`(페이지 전환 고정값. `--motion:.15s` 는 버튼 hover/토글용 — 페이지 전환과 구분).
- **모션**: `transform: translateX(±32px)` + `opacity: 0↔1`(슬라이드 + 페이드 병행). 들어오는 페이지 `z-index:2`.
- **방향 판정**: 순서값 `ORDER={WS10:0, WS20:1, WS30:2}`. 큰 값으로 가면 **forward**, 작은 값이면 **back**.
  - forward: 들어오는 화면 우측(+32px)→중앙, 나가는 화면 중앙→좌측(-32px). (`InFwd`/`OutFwd`)
  - back: 들어오는 화면 좌측(-32px)→중앙, 나가는 화면 중앙→우측(+32px). (`InBack`/`OutBack`)

### 9.3 안전장치 (필수)
- **세대 카운터** `oAPP.attr.ui._navGen` — 연타/중첩 이동 시 stale `animationend` 정리 차단.
- **완료 정리** = `animationend` + **400ms 폴백** 타이머 둘 다. 완료 시 나가는 페이지에 `.u4aWsHidden` 부여 + 방향 클래스 제거.
- **`prefers-reduced-motion: reduce`** → `.u4aWsNav*{ animation:none }` (접근성).
- ★**나가는 화면 내용은 애니메이션이 끝난 뒤 정리**한다. 이동 직전에 `removeContent()` 등으로 나가는 화면을 먼저 비우면 **빈 화면이 슬라이드아웃**돼 "날아가는" 것처럼 깨져 보인다(내용 유지→슬라이드→`_done`에서 정리 순서).

### 9.4 적용 현황
- 소비: **워크스페이스 페이지 이동 WS10↔WS20↔WS30**(`fnOnMoveToPage`→`fnNavTo`). 신규로 전체화면 스텝 전환을 추가하는 화면은 이 공통 경로/클래스를 그대로 소비한다(자체 전환 금지).
- **다이얼로그 내부 서브페이지 전환도 같은 `.u4aWsNav*` 클래스를 재사용**한다(팝업 안 `[hidden]` 토글로 페이지를 바꾸던 곳). 예: **UI 개인화 팝업 좌측 패널**(`fnP13nDesignPopupOpen.js lf_showLeftPage`) — 리스트(상위)↔등록/편집(하위) 전환에 `fnNavTo` 구조를 이식(방향 판정+`_navGen`+animationend/400ms 폴백). 전환 중에만 두 페이지를 `position:absolute; inset:0`로 겹쳐 슬라이드(컨테이너는 `overflow:hidden`). ★단, 이때 사용하는 `.u4aWsNav*` 정의(ws20.css)가 그 다이얼로그 문서에 로드돼 있어야 함(WS20 페이지는 이미 로드).

### 9.5 별창(frameless)·ws20.css 미로드 문서의 서브페이지 전환 (필수)
- **별도 BrowserWindow(frameless) 나 ws20.css 를 로드하지 않는 문서** 안에서도 서브페이지가 **`[hidden]`/`display` 즉시 스왑**으로 바뀌면 안 된다 — §9.2 사양의 슬라이드+페이드를 준다.
- **원칙**: `.u4aWsNav*` 정의(ws20.css)가 그 문서에 로드돼 있으면 그 클래스를 재사용하고(9.4), **로드돼 있지 않으면 §9.2 고정 사양을 화면 스코프 CSS 로 그대로 복제**한다. 값은 §9.2 고정 — `0.26s ease both`, `transform: translateX(±32px)` + `opacity 0↔1`, 방향 자동판정(forward=우측+32→중앙/나감 좌측−32, back=반대), **들어오는 페이지 `z-index:2`**, 완료 후 나가는 페이지 정리(`animationend`+400ms 폴백, §9.3), `prefers-reduced-motion:reduce`→`animation:none`.
- **★실제 페이지가 바뀔 때만 애니메이션.** 같은 페이지 내 콘텐츠 교체(예: 코드 뷰어에서 다른 소스로 `setValue`)는 전환을 태우지 않는다. iframe(Monaco/미리보기) 호스트는 **1회 로드 후 재사용**하고(재마운트/재로드 금지), 페이지 전환은 `position:absolute` 로 겹친 두 페이지의 클래스 토글로만 한다.
- 레퍼런스: **소스 패턴 팝업**(`Popups/patternPopup/frame.js` `_navPages` + `frame.css` `.u4aPattNav*`/`@keyframes`) — 빈상태("선택한 패턴 없음")↔코드 뷰어 전환. 원본 `sap.m.NavContainer` 2페이지(RPAGE1/RPAGE2) `.to()/.back()` 슬라이드 대체. (2026-07-08 추가.)

## 11. 헤더/툴바 반응형 오버플로(⋯) — 공통 `U4AUI.attachOverflow` (필수)

**규칙(필수).** 액션 버튼이 있는 **모든 헤더/툴바** — 창 헤더 메뉴바, 스플릿 영역 헤더 툴바, 패널
헤더 액션 행 — 은 **컨테이너(패널/창)가 좁아질 때 버튼이 잘리거나 밖으로 삐져나오면 안 된다.** 폭이
모자라면 **넘치는 액션을 우측 `⋯` 오버플로 메뉴로 접는다.** 화면마다 새로 만들지 말고 공통
`U4AUI.attachOverflow(oBar, opt)` 를 소비한다(ResizeObserver 로 폭 변화에 자동 reflow).

> **왜 필수인가**: 스플릿바로 패널을 좁히거나 창을 축소/줌하면 툴바 버튼이 패널 밖으로 잘려 **누를 수
> 없게** 된다(예: 바인딩 팝업 중앙 패널의 "동일속성 바인딩/멀티 바인딩/바인딩 해제", 우측 "추가 속성
> 바인딩"·도움말이 삐져나옴). 반응형 오버플로는 이 화면들의 **기본 요구사항**이다.

### 11.1 DOM / CSS 전제 (필수)
- **툴바 = 단일 행**: `display:flex; flex-wrap:nowrap; overflow:hidden; min-width:0`.
  줄바꿈(`wrap`)이나 자연폭 확장을 허용하면 `attachOverflow` 의 폭 측정이 오판한다.
- **`[hidden]` 함정 ★반복 함정★**: `attachOverflow` 는 넘치는 버튼에 `el.hidden=true` 를 준다. 그런데
  `.u4a-btn`/`.u4a-btn-icon` 은 `display:inline-flex` 라 UA 기본 `[hidden]{display:none}` 을 **이겨** ⋯ 가
  항상 뜬다 → 툴바 스코프에 **`> [hidden]{ display:none !important; }`** 를 반드시 깔아라
  ([[attachoverflow-needs-hidden-override]] 와 동일).
- **세퍼레이터/스페이서 구분**: `opt.isSep`(구분선), `opt.isSkip`(flex-grow 스페이서 — 측정에서 제외).
  스페이서를 폭 계산에 넣으면 항상 가득 차 **항상 오버플로로 오판**한다. 스페이서로 우측 정렬한 툴바는
  `noOvfAutoMargin:true`(⋯ 를 보이는 버튼 끝에 붙임).
- **초기 reflow**: 스플리터 레이아웃으로 폭이 확정된 뒤 측정한다(`clientWidth>0` 까지 `requestAnimationFrame`
  재시도). 폭 0 시점에 측정하면 전부 접힌다.

### 11.2 기존 참고 구현 (이걸 베껴라 — 새로 만들지 말 것) ★WS20 필참★
동일 패턴이 이미 여러 곳에서 동작한다. **새 분할/패널 화면(특히 WS20 계열)은 반드시 아래를 참고**한다:
- **WS10/WS20/WS30 공통 헤더 메뉴바** — 공유 빌더 `buildMenubar` / `_renderCommonHeader` 가
  `.u4a-ws10__common`(우측 공통 클러스터)에 `attachOverflow`(`noOvfAutoMargin:true`) 부착. 좌측 카테고리는
  고정, **우측만 ⋯ 로 접는다**(03 §공통 헤더 버튼). 극단적으로 좁으면 `.u4a-ws10__menubar{overflow:hidden}`.
- **WS20 미리보기 패널 헤더** `_buildPrevHeader` — 위와 동일 패턴(패널 헤더 툴바의 대표 사례).
- **개인화 미리보기 툴바** `fnP13nDesignPopupOpen.js`(≈831) — 패널 툴바 + 스페이서 케이스의 정석:
  `attachOverflow(oTool,{ noOvfAutoMargin:true, isSep, isSkip:스페이서, menuItem: 콤보는 메뉴 안에 새 콤보 생성 })`.
  **콤보/입력 등 특수 컨트롤은 원본 el 을 옮기지 말고 `menuItem` 으로 메뉴 안에 동일 핸들러의 새 컨트롤을 만든다.**
- **바인딩 팝업(대형 별창) 3영역 헤더** — `Popups/bindPopup/bindShared.js` 의 `oAPP.fn.attachToolOverflow(oTool)`
  가 위 공통 opt(`isSep`=`.u4aBwpToolSep`, `isSkip`=`.u4aBwpToolSpacer`, `noOvfAutoMargin`)를 감싼 얇은 래퍼.
  각 영역(모델필드/디자인/추가속성) 툴바 빌드 끝에서 1줄 호출.

### 11.3 떠다니는 ⋯ 메뉴 경계
오버플로 메뉴는 `body`(또는 `dialog`)에 절대배치된다 → **`.u4a-titlebar` 침범 금지**(§2.2와 동일 사상):
상단은 `_topChromeBottom()`(타이틀바 하단)으로 클램프, 넘치면 위로 플립하거나 내부 스크롤. (공통 함수가
이미 처리 — 소비처는 신경 쓸 것 없음.)
