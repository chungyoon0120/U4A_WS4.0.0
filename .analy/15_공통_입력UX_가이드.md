# 15. 공통 입력(Input) UX 가이드

> 모든 화면의 `<input>` 은 **동일한 UX** 를 따른다. 새 입력칸을 만들 때(또는
> 다른 PC/세션에서 AI 가 작업할 때) 이 문서의 규칙을 그대로 적용한다.
> 단일 출처(SSOT)는 테마의 `shell.css` + `u4a-ui.js` 이며, 화면별로 마크업/스타일을
> 새로 만들지 말고 **공통 컴포넌트를 소비**한다. (UI5 `sap.m.Input` 의
> `showClearIcon` / number 스피너 등을 HTML5 로 대체한 결과물)

---

## 0. TL;DR — 새 입력칸 만들 때 체크리스트

1. 입력은 `.u4a-field` 래퍼로 감싸고, 값이 있을 때만 보이는 **X(clear) 버튼**을 단다.
2. `type="number"` 입력의 **위/아래 스피너는 항상 제거**한다 (CSS 전역 처리됨 — 추가 작업 불필요).
3. 마크업/동작은 직접 구현하지 말고 **공통 헬퍼**(`U4AUI.attachClear`)와
   **공통 클래스**(`.u4a-field`, `.u4a-field__input`, `.u4a-field__clear`)를 사용한다.
4. 트레일링 아이콘 개수에 맞춰 래퍼에 `data-trail="1"`(X만) / `"2"`(X + value-help·비번토글 등)를 준다.
5. **값도움 전용(valueHelpOnly/F4Only)** 입력(직접입력 금지·F4로만)이면 §3.8 — `readOnly`로 막고
   활성 외관 유지 + 입력칸 클릭=F4 오픈. (이벤트 preventDefault 금지 — IME 못 막음.)

### 1.1 입력 생성은 `U4AUI.createField` 로 (필수 권장)
화면마다 `createElement("input")`+클래스+클리어/서제스트를 직접 짜지 말고 **`U4AUI.createField(opts)` 한 번**으로 생성한다(생성+동작 단일화 → 부분수정 두더지잡기 방지).
- `opts`: `type`(text/password/textarea/combo/select)·value·placeholder·id·readOnly·disabled·rows·width·`clear`·`suggest`(+onPick)·`f4`(+f4Icon)·`upper`·onChange/onEnter/onInput·items/onOpen(combo)·className/inputClassName.
- 반환: `{ el, input, getValue, setValue, setReadOnly, setValueState, setItems, focus }`. `el` 을 폼에 붙이고 id/`data-*` 는 `input` 에 직접 부여(렌더 로직이 getElementById/`[data-*]` 로 접근).
- 인라인 행(입력+버튼)에서는 `.u4a-field` 가 flex 자식이므로 그 행 CSS 에 `.u4a-field{ flex:1 1 auto }` 만 더한다(스택형은 불필요).
- 이관 현황: WS30 USP 완료, 나머지 화면 순차 이관(WS20 속성/Find·WS10·Login·ServerList·F4팝업).

화면 스크립트(Login.js, ServerList.js, WS20/WS30 등)는 위 파일을 로드한 뒤 **createField 로 소비만** 한다.

## 2. 클리어(X) 버튼 — "값 있을 때만"

### 2.1 마크업
```html
<div class="u4a-field" data-trail="1">                      <!-- 래퍼(상대좌표) -->
  <input class="u4a-input u4a-field__input" type="text">    <!-- 우측 패딩 자동 -->
  <button type="button" class="u4a-field__clear"
          title="Clear" aria-label="Clear" tabindex="-1">×</button>
</div>
```
- 아이콘은 input "안쪽" 우측에 `absolute` 로 겹친다 (밖에 따로 두지 않는다).
- 버튼 내용은 Font Awesome `xmark` 아이콘 사용 (`ICON.clear = _fa("xmark")`).
- `tabindex="-1"` — Tab 이동 시 건너뛴다.

### 2.2 노출 규칙 (CSS가 처리)
- `.u4a-field__clear` 는 기본 `display:none`.
- 래퍼에 `data-filled="true"` 가 붙은 동안에만 노출 → **값이 있을 때만 X 표시**.
- `data-filled` 토글은 `attachClear` 가 자동으로 해 준다(직접 만지지 않는다).
- **읽기전용/비활성 입력엔 X 를 띄우지 않는다**(공통 CSS `shell.css .u4a-field__input:read-only ~ .u4a-field__clear{ display:none }`). 모드(Display↔Change)로 readonly 가 토글되는 필드는 `createField({ clear:true })` 로 X 를 정적으로 달아두면 readonly 일 때 자동으로 숨겨진다(화면이 모드별로 붙였다 떼지 않는다).

### 2.3 동작 연결 (JS)
```js
window.U4AUI.attachClear(oInput, oClearBtn /*, fnAfterClear */);
```
- 타이핑 등 값 변화(`input` 이벤트)마다 노출 상태를 동기화.
- X 클릭 시: 값 비우기 → `input` 이벤트 재발화(모델/검증/자동완성 동기화) → 입력에 포커스 유지.
- `mousedown` 에서 `preventDefault` 라 클릭해도 포커스가 빠지지 않는다.
- 프로그램으로 값을 set 한 뒤에는 반환된 `_sync()` 를 호출해 노출 상태를 재계산.

### 2.4 트레일링 슬롯이 둘 이상일 때
오른쪽에 value-help(▾)·비밀번호 토글(👁) 같은 아이콘이 더 있으면:
- 래퍼에 `data-trail="2"`.
- value-help/비번토글은 `.u4a-field__vh` / `.u4a-field__pw` (맨 우측).
- X(clear)는 자동으로 그 **왼쪽**에 배치된다(CSS가 위치 계산).

## 3. number 입력 스피너 제거

`type="number"` 의 네이티브 위/아래 스피너는 clear(X)와 겹치고 UX 통일성을 해쳐
**모든 화면에서 제거**한다. `shell.css` 에 전역 규칙이 있으므로 별도 작업이 필요 없다.

```css
.u4a-input[type="number"] {
    appearance: textfield;
    -moz-appearance: textfield;
}
.u4a-input[type="number"]::-webkit-outer-spin-button,
.u4a-input[type="number"]::-webkit-inner-spin-button {
    -webkit-appearance: none;
    margin: 0;
}
```
- 값 증감은 직접 타이핑으로 한다(스피너 미제공).
- 숫자 입력 제한이 필요하면 `maxLength`/`inputmode="numeric"` 등을 병행한다.

## 3.5 ValueState(검증) 메시지 — "포커스일 때만" (UI5 동일)

UI5 `sap.m.Input` 의 `valueState`/`valueStateText` 를 HTML5 로 대체한 규칙.
**오류 테두리(빨강)는 항상 유지**하고, **메시지 팝업은 입력칸에 포커스가 있을 때만**
뜬다(마우스/키보드로 포커스 → 표시, 커서가 빠지면(blur) 즉시 숨김). SAPUI5 와 동일하며
`.u4a-form__row` + 직계 `.u4a-field__msg` 구조인 **모든 팝업에 자동 적용**(별도 배선 불필요).
폼-행이 없는 테이블 셀/프로퍼티 패널은 스코프 규칙 1줄이 필요 → **§3.5.5**.

### 3.5.1 마크업 (행 = `.u4a-form__row`, 메시지는 그 직계 자식)
```html
<div class="u4a-form__row">
  <label class="u4a-label u4a-label--required">메서드 이름:</label>
  <div class="u4a-field" data-trail="1">
    <input class="u4a-input u4a-field__input">
    <button class="u4a-field__clear" tabindex="-1">…</button>
  </div>
  <div class="u4a-field__msg"></div>            <!-- 비어있으면 안 보임 -->
</div>
```

### 3.5.2 노출 규칙 (CSS — `shell.css`, 전역)
- `.u4a-field__msg` 기본 `display:none`.
- `.u4a-form__row:focus-within .u4a-field__msg:not(:empty)` 일 때만 `display:inline-flex`.
  → 행 안의 입력칸/트레일링 버튼에 포커스가 있고, 메시지 텍스트가 있을 때만 노출.
- ⚠️ **커스텀 행(가로 라벨\|입력 등 `.u4a-form__row` 미사용)은 이 노출 규칙이 안 걸려 메시지가 안 뜬다**(빨간 테두리만 보임).
  그 행 클래스에 **동일 규칙을 스코프로 복제**한다: `.xxxRow:focus-within .u4a-field__msg:not(:empty){ display:inline-flex }`.
  (앵커는 `.u4a-field`(position:relative)라 위치는 그대로 입력칸 바로 아래. 소스 패턴 생성/수정 `.u4aPattDlgRow`, 2026-07-09.)
- 빨간 테두리는 `.u4a-input[data-vs="error"]` 가 별개로 **항상 유지(포커스 무관)** 한다.
  - ★함정: 이 규칙(특이도 0,2,0)은 **테마 스코프 활성-테두리 규칙**(예: `[data-theme="horizon_white"] .u4a-input:not(:disabled)…`,
    특이도 0,5,0, `bootstrap-skin.css` = 색 SSOT, shell 뒤 로드)에 **눌려 회색으로 덮인다**(화이트 테마에서 빨간 테두리 실종).
  - 테마마다 `:not([data-vs="error"])` 로 비껴가는 방식은 취약(테마 하나 놓치면 재발) → **`bootstrap-skin.css` 에서
    `!important` 로 한 번에 못박는다**: `.u4a-input[data-vs="error"],.u4a-select[data-vs="error"]{ border-color:var(--state-error)!important }`.
    (콤보는 공통 `[data-vs]` 마커가 없어 화면별 에러클래스(예 `.u4aCapErr`)로 특이도 (0,5,0)+ 또는 !important 로 처리.)
- 메시지는 `position:absolute; top:100%` 로 입력칸 아래에 **떠서** 표시(행 간격 영향 없음).

### 3.5.3 동작 연결 (JS — 화면 코드)
```js
// 오류일 때: 입력에 빨간 테두리 + 메시지 텍스트 채우기. (포커스면 자동으로 메시지가 뜬다)
oInput.setAttribute("data-vs", "error");
oMsg.textContent = "…메시지…";
// 정상으로 되돌릴 때:
oInput.removeAttribute("data-vs");
oMsg.textContent = "";
```
- 검증 실패 직후 메시지를 **바로** 보이게 하려면 그 입력칸에 `focus()` 를 준다
  (포커스가 없으면 빨간 테두리만 보이고 메시지는 다음 포커스 때 뜬다 — UI5 동일). → 자동 포커스 규칙·함정은 **§3.5.4**.
- value-state 메시지와 자동완성(`attachSuggest`)이 동시에 뜨면 **메시지 위 / 제안 목록 아래**로
  자동 스택된다(`attachSuggest` 가 같은 행의 메시지 높이만큼 목록을 내려 겹침 방지).
- `information` 변형(예: 로그인 CapsLock)은 `.u4a-field__msg[data-vs="information"]` 으로
  빨간 X 대신 파란 info 아이콘.

### 3.5.4 검증 오류 = 오류 필드 자동 포커스 (★센스 — 전 경로 동일)
> "값만 입력하고 포커스가 떨어지면 빨간 테두리는 뜨는데 **메시지가 안 나온다**"의 정답.

- **밸류스테이트 오류를 세팅하는 모든 경로**(인라인 `change` 검증 · 서버 응답 콜백 · 제출(Create) 검증 · 하위 팝업 반환)는
  **그 오류 필드에 자동 `focus()`** 를 준다. 메시지는 `:focus-within` 일 때만 뜨므로(§3.5.2), 포커스가 있어야
  사용자가 **빨간 테두리 + 이유(메시지)** 를 함께 본다. (포커스 안 주면 왜 틀렸는지 안 보이는 반쪽 UX.)
- ★ **함정 A — blur/change/click 처리 '도중' 동기 `focus()` 는 무시된다(Chromium93)**: 진행 중인 포커스 이동에
  밀려 안 붙는다(동기 검증 = `change`(blur) 도중이 대표 사례; 비동기 서버 콜백은 blur 밖이라 동기로도 붙음).
  → **다음 틱으로 미뤄** 재포커스하는 공통 헬퍼로 통일:
  ```js
  function _refocus(oEl){ if(oEl && oEl.focus){ setTimeout(function(){ try{ oEl.focus(); }catch(e){} }, 0); } }
  ```
- ★ **함정 B — busy/모달(`showModal`) 이 떠 있으면 `focus()` 가 top-layer 트랩에 막힌다**(배경 필드 inert):
  **busy(`setBusy("")`)/모달을 먼저 닫고** 그 뒤(다음 틱)에 포커스. 제출 검증은 검증함수가 **포커스 대상만 반환**하고
  호출측이 busy 해제 후 `_refocus` 하도록 배선(검증함수 안에서 바로 focus 하면 busy 에 막힘).
- **중복 검증 모달 금지 → 인라인+포커스로 통일**: 같은 오류를 인라인 밸류스테이트 + 모달로 이중 표시하지 않는다.
  인라인(빨간 테두리 + 필드별 메시지)이 더 구체적이므로 요약 모달("입력값 확인" 류)은 제거하고
  **인라인 + 즉시(다음 틱) 포커스**만 남긴다.
- **서버가 구운 오류 텍스트**(RTMSG/ERMSG)를 밸류스테이트/메시지에 그대로 박으면 백엔드 언어(EN)로 뜬다
  → 공통 `WsMsgCls.relocalize(text, beLangu, wsLangu)` 로 워크스페이스 언어 재렌더 후 세팅(.analy/17).
- 소비 레퍼런스 = 생성옵션 팝업 `createApplicationPopup.js`(패키지 · 제출 · DataSet 검증 전부 이 방식).

### 3.5.5 폼-행이 없는 컨텍스트 — 테이블 셀 / 키:값 프로퍼티 패널
> "테이블 안 입력칸인데 `setValueState` 로 메시지를 세팅해도 **영원히 안 뜬다**"의 정답.

- 노출 규칙(§3.5.2)은 조상 **`.u4a-form__row:focus-within`** 에만 걸린다. 그래서 **`.u4a-form__row` 로 감싸지 않은
  입력칸**(테이블 `<td>` 안의 필드, 2열 "속성|값" 프로퍼티 패널 등)에서는 `.u4a-field__msg` 가 절대 안 뜬다.
  (빨간 테두리 `.u4a-input[data-vs="error"]` 는 조상 무관이라 정상 노출 → "테두리는 나오는데 **메시지만 실종**" 증상.)
- **해결 = 공통 `.u4a-field__msg` 요소를 그대로 소비하되(새 마크업/스타일 만들지 말 것) 화면 CSS 에 스코프 규칙만 추가.**
  두 방식을 컨텍스트에 맞게:
  - **① 인라인 always-on (★권장 — 비동기 검증·토스트가 함께 뜨는 프로퍼티 패널)**: 포커스에 의존하지 않고
    **에러 상태(`data-vs="error"`)면 항상** 입력칸 아래 줄에 인라인으로 표시 → 재렌더·토스트·busy 로 포커스가 흔들려도 확실히 뜬다.
    `.u4a-field` 를 flex-wrap 해 메시지를 아래 줄에 '정적' 배치(absolute 플로팅 아님 → 아래 행 안 가림·overflow 클리핑 없음):
    ```css
    .<필드클래스>.u4a-field { flex-wrap: wrap; }
    .<필드클래스>.u4a-field .u4a-field__msg { position: static; flex: 0 0 100%; margin-top: .25rem; box-shadow: none; }
    .<필드클래스>.u4a-field .u4a-input[data-vs="error"] ~ .u4a-field__msg:not(:empty) { display: inline-flex; }
    ```
  - **② 포커스 기반 (폼과 완전 동일 룩 — 검증이 동기이고 포커스가 안정적일 때)**:
    `.<필드클래스>:focus-within .u4a-field__msg:not(:empty){ display:inline-flex }` + 검증 실패 시 `_refocus(field.input)`(§3.5.4).
    단 **재렌더 직후 + 토스트 동시**면 포커스가 안 붙어 메시지가 실종될 수 있다(bind 팝업 MPROP 실패 사례) → 그땐 ①로.
  - 공통: `createField(opts.className)` 은 `.u4a-field` 래퍼(텍스트/textarea)에 붙는다(콤보/셀렉트는 콤보 요소에 붙고 `.u4a-field` 없음)
    → 텍스트 필드만 노리려면 `.<필드클래스>.u4a-field` 로 동시선택. 검증 실패 필드엔 `_refocus`(커서 안착)도 함께. (예: bind 팝업 MPROP `.u4aBindAdditField`.)
- **어느 표면에 메시지를 띄우나 — 표면 성격으로 구분**:
  - **(a) 키:값 프로퍼티 패널**(세로 폼을 2열 테이블로 렌더 — 한 필드씩 세로 나열) = **필드 아래 인라인 메시지 표시**(위 ① 권장).
  - **(b) 동종 행이 반복되는 진짜 데이터그리드**(같은 컬럼이 여러 행) = **빨간 테두리 + 사유는 토스트**(`showMessage`).
    플로팅 메시지가 여러 행 위로 겹쳐 혼란하므로 메시지는 토스트로. 참고 = `fnCssJsLinkAddPopupOpen.js`.
- ★ **오류 메시지를 `data-tip` 으로 달지 말 것**: `data-tip` 은 hover 테마 툴팁(팝오버+화살표)이라 "밸류스테이트가
  툴팁처럼 뜬다"고 보인다. 검증 메시지는 반드시 **focus 기반 `.u4a-field__msg`** 로 표시한다(§3.5.2~3.5.4 그대로).
- ★ **콤보/셀렉트는 밸류스테이트 미지원**: 공통 `createField(type:"select"/"combo")` 의 `setValueState` 는 no-op
  (`createSelect` 위임). 셀렉트에 빨간 테두리/메시지가 필요하면 공통 `createSelect` 에 지원을 추가(공통 승격)해야 한다.

## 3.6 읽기전용/표시전용 필드 — 활성/비활성 시각 구분 (공통)

편집 가능 필드와 비활성 필드는 **한눈에 구분**되어야 한다(전 화면 공통). 화면별로 따로 칠하지 않는다.
**핵심 컨셉**: 둘 다 테두리(필드처럼)는 있되, **활성=올라온 배경+또렷한 테두리 / 비활성=평평 배경+옅은 테두리+muted** 로 강약 구분.

- **편집 가능(활성)**: `.u4a-input`/`.u4a-combo` = `--surface-raised` 배경(패널보다 올라옴) + **또렷한 `--divider` 테두리** + 일반 글자 → "여기 입력".
- **비활성(읽기전용/disabled/--display)**: **평평한 `transparent` 배경** + **옅은 `--line` 테두리** + `color` muted(`--sl-muted`/`--text-muted`) + opacity:1 + hover/포커스 강조 없음 + 기본 커서. 필드로는 보이되 뒤로 물러남 → "편집 불가". (입력은 `disabled`(opacity 흐림) 대신 **`readOnly`** 권장 — 값 선택/복사 가능. 콤보 비활성 화살표는 muted 로 표시.)
- ⚠️ **색·보더 단일 출처 = `bootstrap-skin.css`** (`.u4a-input:disabled,[readonly],.u4a-input--display` / `.u4a-combo[aria-disabled],.is-disabled`) — `shell.css` 보다 **늦게 로드 + 같은 명시도라 이긴다**. 바꾸려면 bootstrap-skin 을 고친다(shell.css 만 고치면 안 먹힘). shell.css 대응 규칙도 같게 맞춰 둠.
- ⚠️ **시행착오(2026-06-23)**: ① 구 `--app-bg` 어두운 박스 readonly → 다크에서 "어두운 박스=입력칸" 직관과 충돌해 readonly 가 활성처럼 보임. ② 그래서 '테두리 0 평문'으로 갔더니 너무 휑하고 활성 테두리(흐린 `--line`)도 약해 활성도 테두리 없어 보임. ③ **정답 = 활성 또렷한 `--divider` + 비활성 옅은 `--line` 유지**(둘 다 테두리, 강약 구분). 비활성 배경은 `--disabled-bg`(다크=`--surface`)·`--sl-surface-2`(hover톤)·`--app-bg`(어두운박스) 셋 다 금지, `transparent`.
- ⚠️ **화이트 테마 예외(2026-07-07)**: 위 구분은 **배경 채널**(활성 흰칸 vs 비활성에 비치는 `--app-bg` 틴트)과 **테두리 채널**(또렷한 `--divider` vs 옅은 `--line`) 두 축에 기댄다. 그런데 **화이트만** ① `--app-bg`(#f5f6f7)≈활성 `--surface-raised`(#fff) 이고 ② `--divider === --line`(#d9d9d9) 이라 **두 채널이 동시에 무너져** 활성/비활성이 거의 안 갈린다(다른 테마는 app-bg 틴트 + divider≠line 로 살아있음). → **화이트 스코프에서만** 두 채널을 복구: **(A) 활성** `.u4a-input/.u4a-combo`(readonly/disabled `:not()` 제외) 테두리를 또렷한 회청색(#b8c0ca)으로, **(B) 비활성** 배경을 회색(#dde1e6)+옅은 테두리(#cbd0d7)로. 개념(활성=올라온+또렷 / 비활성=평평+옅음+muted)은 그대로, 대비만 키운 것. 다른 테마는 손대지 않는다. **★위치=`theme/bootstrap-skin.css`('화이트 테마 전용' 블록) — `themes/horizon_white.css`가 아님**: 기본 테마(horizon_white)는 `theme-api._ensureThemeCss`가 `sKey===DEFAULT_THEME`이면 `themes/horizon_white.css` 링크를 주입하지 않고 return 하므로(":root 기본값이라 불필요") 그 파일에 둔 규칙은 **런타임에 로드되지 않는 죽은 코드**가 된다. `data-theme="horizon_white"`는 `apply()`가 화이트에도 세팅하므로 항상 로드되는 bootstrap-skin(색 SSOT)에 두면 스코프가 정확히 먹는다.
- ⚠️ **나머지 라이트 테마 비활성 틴트(2026-07-07)**: 화이트뿐 아니라 다른 라이트 테마들도 base 비활성 규칙(`background:transparent`)만으론 흰 활성칸(#fff)과 옅은 app-bg 가 비쳐 대비가 약하다. → **다크 제외 전 테마**(7·95·green·purple·red·signature·mac·xp·suse)에 각 테마 hue 를 살린 비활성 배경(app-bg 를 한 단계 진하게)+약간 진한 테두리를 `bootstrap-skin.css`('테마별 비활성 입력 틴트' 블록, `[data-theme="..."]` 스코프)에 추가. **다크는 제외**(--surface-raised>app-bg 라 이미 위계 살아있음). 값은 각 테마 팔레트에 맞춰 하드코딩(테마별 hue 고정값이라 토큰화보다 명시가 명확). Chromium93 이라 color-mix 로 상대 계산 불가 → 정적 hex.

## 3.7 hover / focus 강조 — 편집 가능 input·combo 공통 (전 화면 글로벌)

편집 가능한 `.u4a-input` / `.u4a-select` / `.u4a-combo` 는 **마우스 오버 시 테두리가
`--text-muted` 로 강조**되고, **포커스 시 `--accent` 테두리 + 옅은 halo** 가 뜬다
(UI5 `sap.m.Input` 의 hover/focus 상태 대체). 이 규칙은 `shell.css` **한 곳의 글로벌
셀렉터**(`.u4a-input:hover` / `.u4a-combo:hover` / `:focus-visible`)로만 정의되어,
화면별 분기 없이 전 화면(로그인·팝업·WS10/20/30·ServerList)에 동일 적용된다.

- 화면별 CSS 에서 input/combo 의 `:hover` 테두리를 **따로 정의하거나 무력화하지 않는다**
  (그 순간 화면마다 강조가 달라져 통일이 깨진다). 강조 ON/OFF 는 이 글로벌 규칙에서만 바꾼다.
- 읽기전용/비활성(`:read-only` / `--display` / `[aria-disabled]`)은 hover 강조를 주지 않는다
  (편집 불가 신호 유지 — §3.6).
- 콤보 휴지 배경/테두리도 입력칸과 동일(`--surface-raised` + `--divider`)이라 hover 변화 폭까지
  input 과 똑같이 보인다(콤보만 어둡던 옛 `--sl-bg`/`--surface` 는 폐기).
- 별도 BrowserWindow 팝업(F4 등)에서 강조가 안 보이면 코드 차이가 아니라 그 창의 셸 CSS
  캐시다 — 리로드/재빌드하면 동일하게 적용된다.

## 3.8 valueHelpOnly(값도움 전용) 입력 — 활성인데 직접입력 금지 (UI5 `sap.m.Input valueHelpOnly=true` 대체)

**정의**: 입력칸이 **활성(비활성 아님) 외관**이지만 **키보드 직접 입력은 막고**, 값은 **F4 값도움(value help)
으로만** 설정하는 형태. 원본 UI5 `sap.m.Input({ valueHelpOnly:true, showValueHelp:true })` 에 대응.
현행 소비처 = WS20 속성 패널의 **selectOption3 F4HelpID/F4HelpReturnField**(원본 `is_attr.F4Only=true`,
`valueHelpOnly:"{F4Only}"` 바인딩). ※ selectOption2 는 F4Only 아님(icon 돋보기 F4 + 직접입력 가능) — 원본이
의도적으로 다름. 즉 **F4Only(=valueHelpOnly) 인 속성에만** 이 UX 를 적용한다(임의 확대 금지).

### 3.8.1 동작 규칙 (UI5 valueHelpOnly 동일)
- **직접 타이핑 불가** — 키보드/IME/붙여넣기 전부 막는다.
- **외관은 '편집 가능'** — 올라온 배경 + 또렷한 테두리(§3.6 활성 룩). 비활성처럼 물러나 보이면 안 된다.
- **입력칸 클릭 = F4 오픈** — 타이핑이 안 되므로, 입력칸 아무 곳이나 클릭하면 F4 버튼과 **동일하게** 값도움
  팝업이 열린다(UI5 `valueHelpRequest`). F4 트레일링 버튼 클릭도 물론 동작. 커서 = `pointer`(클릭 가능 신호).
- **clear(X)** 는 편집모드에서 그대로 동작(값 비우기는 입력이 아니므로 허용). **표시(비편집)모드**는 일반
  readonly 평문 룩(§3.6) — 활성 룩/클릭-F4 모두 없음.

### 3.8.2 구현 방법 (★ readOnly 로 막는다 — 이벤트 가로채기 금지)
- **차단은 반드시 DOM `input.readOnly = true`** 로 한다. `keydown/beforeinput preventDefault` 류의
  이벤트 가로채기는 **Chromium93(Electron14) 에서 IME(한글) 조합 입력을 못 막는다**(Monaco `readOnly` 가
  IME 못 막아 `domReadOnly` 동반이 필요했던 것과 **같은 사상**). `disabled` 는 opacity 흐림 + 클릭 이벤트까지
  죽어 금지.
- `readOnly` 를 걸면 공통 readonly 무음영 룩(§3.6)이 먹으므로, **활성 외관을 되살리는 override 클래스**를
  덧댄다(§3.6 활성 값 = `--surface-raised` 배경 + `--divider` 테두리, `cursor:pointer`). 공통 readonly 룩
  (`.u4a-input:read-only` / `[readonly]`, 모두 (0,2,0))을 **로드 순서 무관하게 이기도록 (0,3,0)+ 명시도**로.
- F4 트리거는 **기존 F4 핸들러를 재사용**한다(중복 로직 0). 입력칸 클릭 리스너가 트레일링 F4 버튼
  (`.u4a-field__vh`)을 프로그램적으로 `click()` → 기존 `createField({ f4 })` 핸들러가 그대로 발화.
- ⚠️ **`:focus` 변형에 배경을 넣지 말 것**: 활성 외관 override 에 `…--vho:read-only:focus { background }`
  를 함께 쓰면 특이도가 (0,4,0)이 돼, 값 변경 행(예: WS20 `.changeValue` = 입력 배경 transparent (0,3,0))
  을 **focus 때만** 이겨 클릭 시 배경이 흰색으로 튀고 blur 시 복귀한다. 배경 override 는 non-focus (0,3,0)
  하나로만 두어, 변경행 transparent 규칙에 양보하게 한다(2026-07-07 실동작 버그).

### 3.8.3 소비 방법 (공통 승격 완료)
- ★**공통 1급 옵션으로 승격됨(2026-07-09, 숏컷 팝업 저장/아이콘경로가 두 번째 소비처가 되며 §3.8.3 지침대로 승격)**:
  `U4AUI.createField({ valueHelpOnly:true, f4:fn })` — 팩토리가 `readOnly` 강제 + `.u4a-input--vho` 클래스 부여
  + 입력칸 클릭→트레일링 F4 버튼(`.u4a-field__vh`) 프로그램 클릭 배선을 **내장**한다. vho 활성 외관 CSS 는
  **공통 `shell.css` `.u4a-input--vho:read-only:not(:disabled)`**(0,3,0 명시도로 readonly muted 룩 override)로 이동.
  → 새 화면은 그냥 `valueHelpOnly:true` 만 주면 된다(스코프 클래스 복제 금지).
- WS20 속성패널은 자체 스코프 구현(`.u4aWs20AttrInp--vho` + `_buildValueControl`) 을 **당분간 유지**(변경행 transparent
  상호작용 §3.8.2 검증이 얽혀 있어 리스크). 신규/여유 시 공통 `valueHelpOnly:true` 로 이관 권장.

## 4. 적용 예시 (ServerList 편집 팝업)

`www/ServerList_v2/ServerList.js` 의 `_wrapClear(oInput)` 헬퍼가 이 가이드를
캡슐화한 예시다. 동적으로 input 을 만드는 화면은 이런 헬퍼를 두고 재사용한다.

```js
// 입력을 .u4a-field 래퍼로 감싸고 "값 있을 때만" X(clear) 버튼을 단다.
function _wrapClear(oInput) {
    oInput.classList.add("u4a-field__input");
    const oWrap = _el("div", "u4a-field");
    oWrap.dataset.trail = "1";
    const oClear = _el("button", "u4a-field__clear");
    oClear.type = "button";
    oClear.title = "Clear";
    oClear.setAttribute("aria-label", "Clear");
    oClear.tabIndex = -1;
    oClear.innerHTML = ICON.clear;                 // _fa("xmark")
    oWrap.append(oInput, oClear);
    window.U4AUI.attachClear(oInput, oClear);
    return oWrap;
}
```
정적 HTML 마크업으로 만드는 화면(Login.js)은 위 §2.1 의 마크업을 직접 쓰고
초기화 시 `attachClear` 를 호출한다.

## 5. 원칙 요약

- **모든 입력칸은 동일한 clear(X) UX 를 가진다 — 값이 있을 때만 노출.**
- **검증 메시지(`.u4a-field__msg`)는 포커스일 때만 뜬다(UI5 valueState 동일) — 빨간 테두리는 항상 유지.**
- **number 스피너는 어디서도 보이지 않는다.**
- **valueHelpOnly(F4Only) 입력은 `readOnly`로 직접입력을 막되(IME까지) 활성 외관 유지 + 입력칸 클릭=F4 오픈**(§3.8). 이벤트 가로채기로 막지 않는다.
- 모양/동작은 화면마다 새로 만들지 말고 `shell.css` + `u4a-ui.js` 공통 자산을 소비한다.
- 새 트레일링 아이콘(검색/달력 등)이 필요하면 `.u4a-field__*` 패턴을 확장해
  공통 파일에 추가하고, 화면은 그것을 소비한다.
