# BR20 Codex 검수 결과

## 판정

**수정필요**

원인 진단과 정상 노드의 위임·잠금 해제 경로는 타당하다. 그러나 요청서가 요구한 원본과의 동일 형식 및 안전 fallback을 충족하지 못하며, 복사 저장 실패를 성공처럼 종료할 수 있다.

## 지적

### 1. [중요] 빈 설명을 항상 `_DESC: ""`로 넣어 원본과 다른 `T_DESC` 데이터가 생성된다

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_edit.js:628`
- 소비 위치: `www/ws30/ws10_20/js/ws_html5_ws20_dnd.js:1138~1140`
- 원본 근거: `www/ws30/ws10_20/design/js/callDesignContextMenu.js:652~659`
- 데이터 생성 근거: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js:1338~1359`

원본은 설명이 빈 문자열이면 `_DESC` 속성 자체를 만들지 않는다. 현재 `_copyUI`는 설명이 없거나 `getDesc`가 실패해도 모든 노드에 `_DESC = ""`를 만든다. 붙여넣기 소비부는 값이 아니라 속성의 존재 여부만 검사하여 `setDesc(newObjid, "")`를 호출하고, `setDesc`는 새 `T_DESC` 행과 `DESCPT: [{ LINE: "" }]`를 생성한다. 따라서 요청서의 “동일 형식” 주장은 성립하지 않으며, 설명 없는 모든 복사 노드에 원본에는 없던 빈 설명 데이터가 누적된다.

제안: 원본처럼 `getDesc` 결과가 빈 문자열이 아닐 때만 `_DESC`를 정의한다. 조회 실패는 빈 설명으로 변환하지 말고 실패로 처리하거나 최소한 진단 가능하게 남긴다.

### 2. [중요] 노드 없음 fallback이 안전하지 않고 원래 BR20 예외 경로로 재진입한다

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_prev.js:1292~1295`
- 원본 근거: `www/ws30/ws10_20/design/js/callDesignContextMenu.js:682~689`, `662`, `703~712`

래퍼는 `getTreeData`가 노드를 반환하지 않으면 `_origCopy`를 호출한다. 그러나 원본도 같은 OBJID로 `getTreeData`를 호출한 뒤 결과를 검사하지 않고 `ls_tree.OBJID`를 읽는다. 즉 노드가 정말 없으면 689행에서 예외가 나며 tail 잠금 해제에 도달하지 못한다. 우연히 두 번째 조회에서 노드가 생겨도 이후에는 HTML5에 없는 `getUiClientEvent` 호출로 다시 BR20 예외가 발생한다. 요청서 5번의 “안전 회피” 조건을 충족하지 않는다.

또한 `fnWs20CopyUI`가 없으면 래퍼 자체를 설치하지 않으므로(`ws_html5_ws20_prev.js:1287~1289`) 원본의 깨진 경로가 그대로 남는다. 현재 preload 순서가 `prev.js` 다음 `edit.js`이고 실제 설치는 지연 로드 후 실행되어 정상 기동에서는 대체로 함수가 준비되지만, 요청서가 명시한 결손 fallback 자체는 안전하지 않다.

제안: 노드/위임 함수 결손 시 깨진 원본 복사를 호출하지 말고, 각각의 정리 함수를 독립적으로 실행한 뒤 진단 가능한 오류로 종료한다. 원본 호출을 보존해야 한다면 그 호출도 외부 `try/finally`로 감싸 tail 정리를 보장해야 한다.

### 3. [중요] 복사 직렬화·메타데이터·저장 실패를 삼켜 미완료 복사를 성공처럼 종료한다

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_edit.js:598~599`, `604~628`, `631~635`
- 저장 구현 근거: `www/ws30/ws10_20/js/ws_fn_03.js:111~144`
- 호출 위치: `www/ws30/ws10_20/js/ws_html5_ws20_prev.js:1296~1302`

`_copyUI`는 트리 직렬화 실패 시 조용히 반환하고, `_T_0015`/`_CEVT`/`_DESC` 수집 실패를 빈 값 또는 누락으로 바꾸며, `setCopyData`의 파일 읽기·JSON 파싱·파일 쓰기 오류까지 빈 `catch`로 삼킨다. 래퍼는 이를 성공/실패로 구분할 수 없어 잠금만 해제하고 정상 반환한다. 그 결과 실제 복사가 저장되지 않았는데 이전 클립보드가 남아 다음 붙여넣기에서 오래된 UI가 붙을 수 있고, 일부 메타데이터만 빠진 불완전 복사가 저장될 수도 있다.

tail 정리를 `finally`로 보장하는 방향은 맞지만, 업무 실패까지 숨길 이유는 없다. `_copyUI`가 실패를 반환하거나 예외를 다시 던져 호출자가 오류를 표시할 수 있게 하고, 래퍼의 `finally`는 그대로 정리만 담당해야 한다.

## 요청서 검수 포인트별 결과

| 번호 | 결과 | 근거 |
|---|---|---|
| 1. 원인 정확성 | 통과 | 원본 `callDesignContextMenu.js:662`가 `getUiClientEvent`를 무가드 호출하며, 예외 시 저장 706행과 tail 709~712행에 도달하지 못한다. HTML5 구현에서 해당 함수의 현행 정의는 확인되지 않고 원본 `uiDesignArea.js:2080`에만 존재한다. |
| 2. 위임 자체완결성 | 실패 | `_T_0015`와 `_CEVT`의 정상 수집 구조 및 소비는 맞지만 `_DESC` 존재 조건이 원본과 달라 빈 `T_DESC` 행을 만든다. 메타데이터 실패도 조용히 축소된다. |
| 3. 잠금 대칭성 | 부분 통과 | 정상 노드 위임은 `finally`로 단축키/BUSY 해제를 시도한다. 다만 노드 없음 fallback은 이 `finally` 밖에서 원본을 호출하므로 누수가 재발할 수 있다. |
| 4. 노드 참조 일관성 | 통과 | `/lcmenu/OBJID` 취득 후 `getTreeData`로 라이브 노드를 얻는다. |
| 5. fallback 보존 | 실패 | 노드 없음 시 원본이 같은 결손 노드를 무가드 역참조하며, 정상 노드여도 미정의 `getUiClientEvent` 경로로 돌아간다. 함수 결손 시에는 래퍼 자체가 설치되지 않는다. |
| 6. 멱등/설치 시점 | 통과 | `__ws20CopyDelegate` 가드가 있고, 재진입·기로드·로드 콜백 진입점에서 같은 설치 함수를 호출한다. preload는 `prev.js`→`edit.js` 순서지만 실제 컨텍스트 메뉴 지연 로드 후 설치되어 정상 기동 경로에서는 노출 함수가 준비된다. |
| 7. 원본 무수정 override | 통과 | BR20 처리는 `edit.js` 노출과 `prev.js` 래핑으로 구현되었고 원본 함수 본문을 직접 수정하지 않았다. |
| 8. ROOT/APP 가드 | 통과 | 라이브 노드를 `_copyUI`에 넘기면 ROOT/APP에서 저장 없이 반환하고 래퍼 `finally`가 잠금을 해제한다. |

## 확인 사항

- `node --check www/ws30/ws10_20/js/ws_html5_ws20_edit.js` 통과
- `node --check www/ws30/ws10_20/js/ws_html5_ws20_prev.js` 통과
- 정적 대조 범위: 원본 복사, HTML5 복사 위임, 공통 붙여넣기 `_applyP13nPattern`, 클립보드 저장, 설명 저장, preload/지연 설치 경로
- 실제 Electron/UI 조작 회귀시험 결과는 요청 자료에 없으며 이번 검수에서도 수행하지 않았다. 위 지적은 정적 코드 경로만으로 재현 가능한 데이터·예외 흐름이다.
