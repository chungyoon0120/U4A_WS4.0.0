이 오타는 **내 변환 실수가 아니라 원본(as-is)에 이미 존재**한다. 내 이식본은 원본을 1:1로 그대로 옮긴 것이다.

- 원본 `C:\Users\socce\Documents\Github\U4A_WS_DESIGN\design\js\uiAttributeArea.js`
  - 7032행: `ls_0015.UIAT = "/zu4a_srs/" + ...` (값 없는 기존행 보정)
  - 7047행: `ls_0015.UIAT = "/zu4a_srs/" + ...` (APPID 불일치 보정)
- 원본 `C:\Users\socce\Documents\Github\U4A_WS3.0.0\www\ws30\ws10_20\design\js\uiAttributeArea.js` 도 동일
- 내 파일 `www/ws30/ws10_20/js/ws_html5_ws20_attr.js` 1481·1496행 = 원본과 글자까지 동일(원본 1:1)
- 함수의 **신규행 생성 분기**(내 파일 1515행 / 원본 7052행 상당)는 `ls_0015.UIATV = ...` 로 올바르게 쓴다 → 함수의 의도값은 `UIATV`가 맞음. 기존행 보정 분기 두 곳만 `UIAT` 오타.

## 재현 경로 (검수자 확인, 정상 제품 경로)

1. FileUploader/UploadCollection 의 uploaderUrl 을 개인화(내 패턴) 속성으로 등록.
2. 다른 APPID 에서 UI 추가 팝업을 열고 그 개인화 속성 적용을 선택해 해당 UI 추가.
3. 개인화 프리셋 주입(`_buildPresetT0015`)이 이전 APPID 주소를 가진 값칸을 먼저 만든다(개인화 키에 APPID 없음 — 다른 앱 재사용이 정상 경로).
4. BR45 호출이 예외 함수를 실행하지만, 기존행 보정 분기가 `UIAT`(없는 칸)에만 쓰고 `UIATV`(실제 값칸)는 이전 APPID 주소/빈값 그대로.
5. 저장·런타임 업로드 주소가 현재 앱이 아닌 이전 앱을 가리킬 수 있음.

## 반영 판단 — 장군님 결정 대기

- **원본 1:1 규칙**상 원본과 다르게 고치는 것은 장군님 지시가 있어야 한다(이상하면 보고만).
- 다만 검수 논지: BR45 수용 기준은 "호출 존재"가 아니라 "uploaderUrl 예외처리가 실제 적용"이며, 개인화 적용 경로에서 이 오타가 그 목적을 무력화한다. 함수 자신의 신규행 분기·주석 의도가 `UIATV` 이므로 오타 정정은 "임의 창작"이 아니라 **원래 의도 복원**에 해당한다는 것.
- 위험도: 정정은 `UIAT` → `UIATV` 두 글자, 신규행 분기와 동일해져 저위험. 외부 URL·바인딩 URL early return 계약은 그대로 유지됨.

→ 선택지 A: 오타 2곳 `UIATV`로 정정(BR45 목적 완결, 원본 의도 복원). 원본과 달라지므로 장군님 승인 필요.
→ **선택지 B(★장군님 결정 2026-08-18): 원본 1:1 유지, 미반영.** 원작자에게 원본 버그로 회신(BR39·BR40식). 이 경우 개인화 재사용 경로(다른 APPID 프리셋 적용)에서는 uploaderUrl 예외처리가 적용되지 않음 — 원본과 동일한 한계로 남긴다.

## ★ 최종 결정 (장군님 2026-08-18)

- **P1 = 미반영(반론).** 이 오타는 원본(as-is)에도 동일하게 존재(`uiAttributeArea.js` 7032·7047)하므로, 원본 1:1 유지 규칙에 따라 내 파일에서 임의로 고치지 않는다. 원본 버그로서 원작자에게 회신한다.
- **실제 적용된 BR45 수정 = 호출 배선(삽입 루프)만.** 이 배선으로 개인화 없이 새로 추가하는 일반 경로(신규행 생성 분기 `UIATV`)는 정상 동작한다 → 팝업으로 추가해도 끌어놓기와 동일하게 uploaderUrl 이 현재 APPID 로 채워진다.
- **한계(원본과 동일):** 개인화(내 패턴) 속성으로 등록한 uploaderUrl 을 다른 APPID 에서 적용하는 경우, 오타 때문에 현재 APPID 로 갱신되지 않는다(원본도 동일). 이 경로는 테스트 대상에서 제외.

## 오타 영향 범위 조사 (장군님 지시 2026-08-18 — 소비처 전수)

**결론: 잘못 쓴 칸 `UIAT`(V 없음)는 전 소스에서 read 0건(쓰기 2곳만).** `crtStru0015()` 구조에 `UIAT` 필드 자체가 없어 `moveCorresponding`에서 버려진다. 즉 "옛 APPID → 현재 APPID 보정" 로직 전체가 죽어 있고, 진짜 소비되는 `UIATV`에는 옛 값이 그대로 남는다.

| # | 소비처(동작) | UIATV 읽음 | 오타 영향 | 근거 |
|---|---|---|---|---|
| 1 | **저장** | O | O | `getAttrChangedData`(ws_html5_ws20_prev.js:319~378) → `getSaveData`(419~459) YU4A0015 payload. 옛 앱 주소가 서버까지 저장됨 |
| 2 | 미리보기 렌더 | X | 무관 | preview 어디에도 `setUploadUrl` 호출 0건. uploadUrl은 디자인타임 시각효과 없음(실제 업로드는 런타임만) |
| 3 | **개인화(내 패턴)** | O | O | 프리셋 저장키 `[LIBVER,SYSID,UNAME,UIATK]` APPID 없음(attrPresetPopup/settings/index.js). 조회도 APPID 조건 없음. `_buildPresetT0015`(edit.js)가 옛 UIATV 그대로 복사 → 삽입 시 예외호출 보정 실패 |
| 4 | **복사/붙여넣기** | O | O | `_copyAttr`(dnd.js)가 UIATV 그대로 클론(APPID만 갱신). 같은 앱=무해, 타앱 복붙=옛 주소 유지 |
| 5 | **속성 목록 표시** | O | O | 선택 시 updateAttrList가 수집행 UIATV를 표시행에 복사(attr.js:2944~2953) → 값칸에 옛 주소 표시 |

**영향 발생 조건 = cross-app(다른 앱 얽힘)만:** ① 다른 앱 개인화 프리셋 적용 ② 다른 앱 패턴 복붙 ③ 그 상태로 저장(서버 전파) ④ 선택 시 값칸에 옛 주소 표시. **단일 앱 내 신규 생성/복붙은 최초 세팅 분기(UIATV="")로 정상값 → 무해.**

**자가치유 정정:** updateAttrList(선택 시) 호출도 동일 오타 분기라, 값칸에 옛 주소가 이미 있으면 선택해도 보정 안 됨(신규행=값칸 없음일 때만 정상 세팅). 앞선 "선택하면 채워짐" 판단은 값칸이 비었을 때만 성립.

**결정 영향:** 위 영향은 원본(as-is)에도 동일하게 존재. 장군님 결정(미반영·원본 1:1 유지·원작자 회신) 그대로 두되, 영향 범위를 원작자 회신에 첨부 권장.
