# 02_audit_codex — BR24 UI 속성 영역 서버이벤트 검수

## 판정

**수정필요**

## 지적 사항

### 1. [P1] 서버이벤트 목록 조회 실패가 “현재 값이 목록에 없음”으로 오판된다

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js:442-501`, `4781-4806`
- `getServerEventList()`는 서버 응답 `RETCD !== "S"`와 AJAX 오류 모두에서 빈 항목 하나만 든 `lt_ddlb`를 정상 resolve한다.
- BR24의 `onOpen`은 resolve된 배열을 성공적으로 조회한 목록으로 간주한다. 따라서 기존 `UIATV`가 비어 있지 않으면, 실제 이벤트가 서버에 등록되어 있어도 일시적 통신 오류·세션 오류·백엔드 오류 시 `bHas === false`가 되어 `sAttr.valst = "Error"`와 `.err`가 적용된다.
- 원본은 성공 응답에서만 콜백을 실행하고(`design/js/uiAttributeArea.js:7070-7115`), 그 콜백으로 받은 목록에 대해서만 누락 검사를 수행한다(`design/js/uiAttributeArea.js:1087-1113`). 실패 응답/통신 오류에는 누락 판정을 하지 않는다.
- 영향: 사용자는 정상 등록된 이벤트를 미등록 이벤트로 오인한다. 오류 상태가 `T_ATTR` 실데이터에도 남으므로 재렌더 후에도 빨간 테두리가 지속된다.
- 제안: 조회 API가 성공/실패를 구분해 반환하도록 하거나, BR24 검사 경로에서 성공이 명시된 경우에만 목록 누락 검사를 수행한다. 실패 시 기존 항목과 기존 오류 상태를 보존하고 조회 실패를 “목록 없음”으로 바꾸지 않아야 한다.

### 2. [P2] “오류 문구 없이 빨간 테두리만” 요구와 달리 선택 텍스트도 빨갛게 표시된다

- 위치: `www/ws30/ws10_20/WS10/css/ws20.css:1157-1162`
- 요청서는 원본 `valueState=Error`의 결과를 “빨간 테두리만 표시(메시지/텍스트 없음)”로 한정한다. 주석도 같은 의도를 명시한다.
- 그러나 `.u4aWs20AttrCombo.err .u4a-combo__text { color: var(--error); }`가 선택값의 글자색까지 오류색으로 바꾼다.
- 영향: 원본 대비 시각 표현이 과해지고, BR24 수용 기준의 테두리 전용 오류 표현을 위반한다.
- 제안: 텍스트 색상 규칙을 제거하고 `.u4aWs20AttrCombo.err`의 `border-color`만 유지한다.

## 검증 범위

- `.audit/br24/01_request.md`의 두 이슈 및 수용 기준
- 원본 `www/ws30/ws10_20/design/js/uiAttributeArea.js`의 전체 행 아이콘 바인딩, 이벤트 목록 성공 콜백, 누락 판정 경로
