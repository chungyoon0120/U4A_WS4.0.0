# BR38 검수 결과 반영·해명 (03_response)

두 검수(코덱스·안티)를 모두 읽고 소스로 대조했다.

## 종합 판정

- **코덱스: 통과 / 안티: 통과. 두 검수 모두 필수 지적 0건.**
- **반영할 코드 수정 없음.** 빠졌던 선택 UI 스크롤 이동을 미리보기 선택표시 함수(`fn_mark`)에
  복원했고, "밖일 때만 이동"(`scrollIntoView({block:"nearest"})`)이 이슈 기대결과·반대 방향·원본
  속성영역 패턴(`uiAttributeArea.js:8303`)과 일치함을 두 검수가 확인.
- 안티는 최초 서브에이전트가 "스크롤 연쇄로 WS20 메인 화면 전체가 튈 것"이라며 수정필요(P1)로
  판정했다가, WS20 메인 레이아웃이 겹겹의 `overflow:hidden` 고정 구조라 부모 방향 스크롤이 원천
  차단됨을 확인하고 **오판을 번복해 통과**로 확정.

## 지적 통합 표

| # | 검수자 | 지적/평가 | 판정 | 근거·조치 |

## 잔여 참고 (반영 대상 아님)

1. **실화면 확인 권고(코덱스)**: 미리보기 최상위 문서 + 중첩 스크롤 영역 각각에서 화면 밖 위·아래 UI
   선택, 선택 직후 재렌더되는 컨트롤·`getDomRef()` 늦게 생기는 예외 컨트롤, 빠른 연속 선택 시 마지막
   선택 위치 수렴. → 정적 검수 범위 밖, 실화면 조작으로 검증(아래 테스트).
2. **향후 회귀 주의(코덱스)**: 나중에 WS20 상위 영역을 스크롤 가능(`overflow:auto/scroll`)으로 바꾸면
   메인 화면 튐이 재현될 수 있음 → 그때 대상 스크롤 영역 직접 제어 또는 `container:"nearest"` 재검토.
   현재 구조에서는 결함 아님.
3. **스크롤 대상이 컨트롤 루트 DOM(`getDomRef()`)인 점(코덱스)**: 선택 레이어 대상 함수보다 방어 범위는
   좁으나 현행 렌더 계약에서 실제 실패하는 UI를 특정 못해 필수 결함 아님. 별도 참고로만 남김.
