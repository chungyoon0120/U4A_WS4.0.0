## 1. 팩트체크 완료 (코덱스 리포트 반박)

**[정상] N건(Aggregation) 스크롤 과잉 방어(Over-guarding) 주장은 사실이 아닙니다.**
- **기존 코덱스 주장**: 최근 추가된 `if (nd && nd.enable === true)` 방어 로직 때문에, `enable: false` 인 테이블/폴더 등의 N건 바인딩 시 스크롤 기능 전체가 무력화된다고 지적했습니다.
- **서브에이전트 검증 결과**: 이는 코드를 오독한 **거짓(False)**으로 판명되었습니다. 해당 방어 조건문은 `lf_selRow(nd)` (시각 선택 및 추가속성 패널 오픈)에만 묶여 있으며, **핵심인 `scrollToKey()` 스크롤 로직은 해당 `if` 블록 외부에 완전히 독립적으로 위치**하고 있습니다. 따라서 N건(Aggregation) 바인딩 시 노드가 비활성(`enable: false`)이라도 기존 바인딩 위치로의 스크롤 이동(BR28 본연의 기능)은 완벽하게 정상 동작합니다.

## 2. 실제 결함 (진성 맹점 2가지)

서브에이전트의 팩트체크 결과, 아래 2가지 항목은 실제 운영 환경에서 문제를 일으킬 수 있는 진성 결함으로 확인되었습니다.

**[P1] 미바인딩 속성 재오픈 시 과거 스크롤(scrollTop) 위치 초기화 누락 (고스트 스크롤)**
- **현상**: 미바인딩(빈 값) 상태로 팝업을 열 때(`L_UIATV === ""`), 직전 팝업 세션에서 내려두었던 가상 스크롤의 위치가 최상단으로 리셋되지 않고 붕 뜬 상태로 나타납니다.
- **메커니즘 규명**: 
  1. `u4a-ui.js` 트리 컨트롤러는 렌더링 시 무조건 `_renderVirtual(true)`를 호출하여 **스크롤 유지(`bKeepScroll = true`)**를 강제합니다.
  2. 바인딩이 존재하는 경우엔 `scrollToKey()`가 강제로 발동되어 뷰포트를 덮어씌우지만, **미바인딩 시에는 `scrollToKey()` 로직 자체를 건너뜁니다.**
  3. 엎친 데 덮친 격으로 빈 데이터(`!aRoots.length`) 렌더 시 `_vs.setRows()` 갱신이 누락되어, 팝업 DOM 인스턴스가 가진 이전 `scrollTop` 프로퍼티가 그대로 화면에 복원(유령 스크롤)되는 것입니다.

**[P2] AJAX 비동기 통신 지연에 따른 레이스 컨디션 (Race Condition) 방어 미흡**
- **현상**: `lf_loadData` 진입 시 `cancelAnimationFrame`을 통해 직전 로드의 예약된 스크롤(rAF)을 취소하는 방어막은 존재합니다.
- **맹점**: 하지만 네트워크 지연으로 인해 **이전에 요청한 AJAX 응답이 늦게 도착하는 상황(Race)**을 막을 수 없습니다. 새로운 팝업 세션을 열었는데, 과거 팝업의 늦은 응답 콜백이 뒤늦게 떨어지면 `lf_setSelectTree`를 실행시켜 강제로 엉뚱한 화면 렌더링과 스크롤(rAF)을 다시 예약해버리는 치명적 비동기 충돌이 일어납니다.

## 3. 권장 수정 방안

1. **세션 경계 스크롤 초기화**: 팝업 재사용 시(`fnBindPopupOpen` 진입부 등) 또는 `makeColumnTree.rerender()` 내부에서, 미바인딩(`L_UIATV === ""`) 여부와 무관하게 이전 가상 스크롤러의 잔존 키(`selKey`)와 위치(`scrollTop = 0`)를 완벽히 리셋하는 로직을 삽입하십시오. (BR27의 키 초기화 요구와 일맥상통)
2. **비동기 콜백 토큰 방어**: AJAX 요청 시마다 고유 토큰(Timestamp 또는 Sequence)을 발급하고, 응답 콜백 내에서 최신 토큰과 일치할 때만 트리 렌더링 및 스크롤 예약이 진행되도록 비동기 체인을 직렬화하십시오.

## 4. 종합 평가

코덱스의 치명적 오판(Over-guarding 환각)을 서브에이전트 팩트체크로 완벽히 걷어냈으며, BR28의 스크롤 이동 로직 자체는 흠결 없이 잘 분리되어 있음을 확인했습니다. 다만 미바인딩 상태일 때의 가상 뷰포트 초기화 누락(P1)과 AJAX 레이스 컨디션(P2)이라는 두 가지 맹점은 반드시 보완되어야 하므로 최종 **❌ 수정필요 (Modify)** 로 확정합니다.
