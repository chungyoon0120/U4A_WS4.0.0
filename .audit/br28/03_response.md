# BR28 보완·해명 (03_response)

코덱스·안티 두 검수 결과를 합쳐 정리. 판정은 둘 다 **수정필요**.
소스로 각 지적을 직접 재확인한 뒤 반영/반론을 결정했다.

## 소스 재확인(사실 근거)
- BR28 스크롤 이동(`scrollToKey`)은 `if (nd && nd.enable === true)` **밖**에 있다 —
  `fnBindPopupOpen.js` `lf_setSelectTree`. 활성 노드에서만 실행되는 것은 `lf_selRow`(선택 강조·추가속성 패널)뿐.
  → 안티 팩트체크(“과잉 방어는 거짓”)와 코덱스 재검수(“해소”)가 일치. **열린 지적 아님**.
- 공통 가상 목록 `render()` → `_renderVirtual(true)` → `setRows(..., true)`는 스크롤 유지가 기본 계약이라,
  미바인딩(이동 대상 없음) 재오픈 시 이전 목록 위치가 남는다 — `u4a-ui.js` 가상 스크롤러.
- `lf_loadData`는 진입 시 예약된 스크롤 rAF만 취소하고, 진행 중인 이전 `sendAjax` 응답을 식별/폐기하는
  장치는 없다. 원본 `design/js/callBindPopup.js`의 `lf_openPopup`/서버 콜백에도 요청 세대 토큰은 없다(원본에도 동일 경합 여지).
