# 02_audit_codex — T01 바인딩 집계 드롭 안내

## 판정

**수정필요**

바인딩된 aggregation에 자식이 이미 있는 합성 입력에서 `chkAggrRelation`이 `RETCD="E"`, `RTMSG=ZMSG_WS_COMMON_002/002`, 빈 `T_SEL`을 반환하고, D&D·wizard 호출부가 해당 메시지를 소비하는 핵심 T01 분기는 확인됐다. 다만 반환 계약 변경의 활성 소비처가 누락됐고, 저장소의 현행 원본과 다른 후보 산출 규칙으로 0:1 점유 aggregation까지 선택 후보에 노출된다. 따라서 “호출부 2곳뿐”, “원본 1:1”, “정상 경로 무변화” 수용 기준은 충족하지 못한다.

## 지적

### 1. [P1] 활성 AI 생성 경로가 여전히 배열 계약을 소비하여 후보 없음 사전점검이 무력화됨

- 위치: `www/ws30/ws10_20/design/UAI/parseAiLibraryData.js:408-411`
- 문제: T01은 `oAPP.fn.chkAggrRelation`을 배열에서 `{RETCD, RTMSG, T_SEL}`로 바꿨지만 이 소비처는 반환값의 `.length`를 검사한다. 구조체의 `length`는 `undefined`이므로 후보가 없어도 `undefined === 0`은 거짓이고, 413~421행의 즉시 오류 반환이 절대 실행되지 않는다.
- 사용자 영향: 이 모듈은 현재 HTML5 WS20의 UAI 처리기가 직접 로드한다(`js/uai/PRC_MODULES/WS_20/GEN_U4A_APP/index.js:129-135`). 추가 가능한 aggregation이 없는 AI 생성 요청도 먼저 “AI가 생성한 UI를 추가하겠습니까?” 확인창을 띄운 뒤(`parseAiLibraryData.js:426-453`)에야 두 번째 `aggrSelectPopup` 단계에서 거부된다. 기존의 사전 거부 계약과 UX가 깨진다.
- 근거: 언더바 폴더를 제외한 전수 검색 결과 직접 호출은 6곳이며, 요청서가 센 HTML5 두 곳 외에 `parseAiLibraryData.js` 및 현행 원본 세 곳이 배열 계약을 사용한다. 따라서 “호출부 정확히 2곳”이라는 영향도 분석은 전역 함수 계약 기준으로 불완전하다.

### 2. [P1] 요청서가 지목한 최신 원본이 작업 저장소에 없고, 현행 SSOT와 후보 산출 의미가 다름

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_dnd.js:420-445`
- 문제: 요청서는 `design/js/uiDesignArea.js:1596-1680`의 구조체판을 1:1 이식했다고 하나, 현재 파일의 유일한 `chkAggrRelation` 정의는 1459~1529행의 **배열 반환판**이다. `design/js/aggrSelectPopup.js:22-32`와 `uiDesignArea.js:1302`, `1418`도 `.length`를 소비한다. 로컬·원격을 포함한 모든 Git ref에서도 구조체판이나 `_isModelBind`, `ZMSG_WS_COMMON_002` 이력은 확인되지 않았다.
- 추가 불일치: 현행 원본은 preview getter 존재 확인(1484~1490), `T_0027` 없음 조기 반환(1475~1478), 점유된 0:1 aggregation 제외(1500~1504)를 수행한다. T01 구현은 이 조건들을 제거하고 트리의 바인딩+자식 조건만 제외한다. 따라서 현재 저장소의 as-is를 기준으로는 알림 추가만 한 1:1 변경이 아니라 후보 집합 자체를 넓히는 변경이다.
- 클로버 주장도 현재 자료와 반대다. 현행 `design/js/uiDesignArea.js`가 이 함수를 덮으면 배열판으로 돌아가며, 현행 `design/js/aggrSelectPopup.js`는 배열을 기대한다. 표준 HTML5 preload에서는 즉시 덮이지 않는 것으로 보이지만, 요청서의 “지연 로드되어도 같은 구조체판이라 호환”은 이 저장소로 입증되지 않는다.
- 제안: 실제 기준인 최신 WS_DESIGN 원본을 이 저장소에 동기화하거나 검수 근거로 첨부한 뒤 정확한 diff를 다시 제시한다. 현행 원본을 SSOT로 유지한다면 후보 산출 조건과 모든 전역 소비처를 함께 호환시켜야 한다.

### 3. [P2] 이미 점유된 0:1 aggregation이 선택 가능한 후보로 노출됨

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_dnd.js:435-445`
- 문제: `ISMLB === ""`이고 같은 `UIATK`의 자식이 이미 있어도 `_MODEL` 바인딩만 없으면 `T_SEL`에 push한다. 현행 원본은 이 경우를 명시적으로 제외한다(`design/js/uiDesignArea.js:1500-1504`).
- 재현: 추출 실행에서 점유된 0:1 row와 동일 `UIATK` 자식을 넣었을 때 `{RETCD:"S", T_SEL:[해당 row]}`가 반환됐다. 후보가 하나면 자동 선택되고, 여러 개면 사용 불가능한 aggregation이 선택 팝업에 나타난다. 선택 후 `drop_cb`의 `chkUiCardinality`가 막기는 하지만(`dnd.js:1327`), 사용자는 실패할 항목을 선택한 뒤 다시 드롭해야 하며 종전 후보 필터 동작과 다르다.
- 제안: 최신 원본에 이 변경이 의도된 것인지 먼저 확정한다. 의도가 아니라면 기존의 0:1 점유 제외를 구조체판에도 보존한다. UA050 예외 자식 판정까지 트리 데이터로 동등하게 표현되는지도 함께 검증해야 한다.

## 확인된 정상 항목

- `ws_html5_ws20_dnd.js:420-461`: 합성 실행에서 집계 정의 없음→001, 호환 후보 없음→003, 바인딩+자식→002, 정상 후보→`RETCD="S"`/`T_SEL` 반환을 확인했다.
- `ws_html5_ws20_dnd.js:469-496`: 후보는 `.T_SEL`로 소비하고 후보 0의 메시지는 `RTMSG`가 있을 때 우선하며, 없을 때만 262를 사용한다. 같은 부모·같은 `UIATK`의 `retfunc(undefined, ...)` 분기와 후보 1개 자동선택 순서는 유지된다.
- `ws_html5_ws20_dnd.js:578-600`: 선택 팝업 취소는 `RCODE="01"`, 후보 없음은 `RCODE="02"`이며 지정된 `cancelFunc`에 결과를 전달한다.
- `ws_html5_ws20_wizard.js:123-129`: 구조체판이 유지된다는 전제에서 `RETCD="E"`와 `RTMSG`를 올바르게 소비하고, 메시지가 비었을 때만 280으로 폴백한다.
- 바인딩 안내 키 000/001/002/003은 KO·EN 메시지 DB에 모두 존재한다. 드롭 후보 단계는 002, popup cardinality 단계는 `ws_html5_ws20_edit.js:938`, `1108`의 000을 사용해 요청된 코드 분리를 유지한다.
- 대상 두 파일 모두 `node --check`를 통과했다.
