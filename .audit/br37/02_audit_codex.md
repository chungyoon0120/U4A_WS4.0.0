# BR37 UI 추가 팝업 Generated Cnt 표시조건 검수

## 판정

**통과**

재현 가능한 필수 수정사항은 발견하지 못했다.

## 지적

없음.

## 상세 검수 결과

### 1. 원인과 CSS 수정의 적합성

- `ws20.css:656`의 `.u4aWs20InsRow { display: flex; }`는 작성자 스타일이므로 브라우저 기본 스타일인 `[hidden] { display: none; }`보다 우선할 수 있다. 따라서 DOM의 `hidden` 속성만 바꾸는 기존 JavaScript가 화면에서는 효력을 잃는다는 요청서의 원인 분석이 타당하다.
- 추가된 `ws20.css:659`의 `.u4aWs20InsRow[hidden] { display: none; }`는 같은 작성자 스타일 계층에서 기본 행 선택자보다 구체성이 높고 뒤에 선언되어, `hidden`인 행만 확실히 숨긴다.
- 수정은 표시 계층만 바로잡으며 집계 선택, 생성 개수 계산, UI 생성 로직을 변경하지 않는다.

### 2. 전체 상태 전이와 원본 1:1 정합성

| 상태 | HTML5 동작 | 원본 동작 | 결과 |
|---|---|---|---|
| 최초 진입 | 행에 `hidden`이 있어 숨김 | `visible:false` | 통과 |
| 미선택/공백 | `ISMLB !== "X"`, 숨김 및 count=1 | 숨김 | 통과 |
| 단일 집계 | `ISMLB === ""`, 숨김 및 count=1 | 숨김 | 통과 |
| 다건 집계 | `ISMLB === "X"`, 표시 | 표시 | 통과 |
| 다건에서 미선택/단일로 복귀 | 다시 숨김 및 count=1 복원 | 숨김 및 count=1 복원 | 통과 |

- `ws_html5_ws20_edit.js:1323`은 Generated Cnt 행을 처음부터 `hidden`으로 생성한다.
- `ws_html5_ws20_edit.js:1572-1573`은 다건 집계일 때만 표시하고, 숨길 때 입력값을 1로 복원한다.
- 원본 `design/js/insertUIPopop.js:177-186`도 `ISMLB === "X"`일 때만 표시하고 그 외에는 숨기면서 생성 개수를 1로 되돌린다. 결과 계약이 일치한다.

### 3. 선택 컴포넌트 및 반응형 영향

- 집계 선택 변경은 커스텀 선택 컴포넌트와 native select 경로 모두 기존 `lf_onAgg`로 수렴하므로, 이번 CSS 수정이 어느 한 입력 방식에만 적용되는 문제는 없다.
- 반응형 규칙 `ws20.css:692-693`은 행의 `flex-direction`, 정렬, 간격과 라벨 flex만 바꾸며 `display`를 재선언하지 않는다. 따라서 좁은 화면에서도 `[hidden]` 규칙이 유지된다.
- 선택자는 WS20 삽입 팝업의 `.u4aWs20InsRow` 중 실제 `hidden` 속성이 있는 행에만 적용된다. 다른 집계 행, UI Object 행 및 공통 컴포넌트의 표시 상태에는 영향을 주지 않는다.

### 4. 공통 자산·테마 규칙

- 변경 위치는 WS20 화면 전용 `ws20.css`이며 공통 `shell.css`, `u4a-ui.js`, `tokens.css`를 변경하지 않는다.
- 색상, 고정 폭, 문구 또는 신규 스타일 토큰을 추가하지 않은 구조적 표시 규칙 1건이므로 테마 및 토큰 회귀가 없다.

## 잔여 확인 권고

정적 검수상 결함은 없다. 실제 브라우저에서 최초 진입 → 단일 집계 → 다건 집계 → 단일/공백 복귀 순서로 computed `display`와 count=1 복원을 확인하면 최종 실화면 검증까지 닫을 수 있다.

## 독립 반박 재검수

서브에이전트로 기존 통과 판정을 뒤집는 관점의 독립 재검수를 수행했으며, 결론은 **통과 유지**다.

- 신규 선택자의 특이도는 `(0,2,0)`으로 기본 행 및 반응형 행 선택자의 `(0,1,0)`보다 높다. 후행 규칙을 포함해 이를 뒤집는 해당 `display: ... !important` 선택자도 발견되지 않았다.
- 커스텀 select는 마우스와 키보드 선택이 공통 변경 콜백으로 수렴한다. 같은 값을 다시 선택할 때 콜백을 생략하는 동작은 이미 그 값에 맞는 표시 상태가 적용된 뒤이므로 상태 불일치를 만들지 않는다.
- native select도 `change`에서 같은 `lf_onAgg`를 호출한다.
- 현행 소비처를 전수 검색한 결과 `.u4aWs20InsRow`는 이 팝업의 3개 폼 행에만 쓰이며, 그중 `hidden`을 갖는 것은 Generated Cnt 행뿐이다.
- `display:none` 복원은 시각 레이아웃뿐 아니라 포커스 대상과 접근성 트리에서도 해당 행을 제외하므로 HTML `hidden`의 의미와 일치한다.
- 반박 재검수에서도 재현 가능한 기능·회귀·접근성 결함은 발견되지 않았다.
