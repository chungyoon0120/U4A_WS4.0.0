# BR51 검수 결과 반영·해명 (03)

검수 결과: 코덱스 = **수정필요(P1·P2)** / 안티 = 통과.
→ 코덱스 지적 2건 **모두 반영**(코드 수정). 반론 0건.

## 지적 취합·처리 표

| # | 지적 | 검수자 | 처리 | 내용 |
|---|---|---|---|---|
| 1 | [P1] 점검 실패를 알린 뒤에도 정상 흐름으로 복귀 → 검증 안 된 값이 변경 수집(prev._T_0015)에 들어가 저장 후보가 됨. 원본은 예외가 그대로 전파돼 수집에 도달하지 않음(fail-closed)인데 이식본은 fail-open | 코덱스 | **반영** | catch 에서 표면화 후 `return;` 추가 — 검증 안 된 값의 후속 수집(attrChgAttrVal)·스타일·재렌더·미리보기 반영 전부 중단(원본과 동일 경계). 함수 전체를 감싼 finally 가 busy·단축키·자식창 잠금·재진입 플래그를 원복하므로 잠금 고착 없음(같은 try 안 autoGrowing 조기 return 3823행과 동일 기성 패턴). throw 재전파 대신 return 을 택한 이유: 표면화(콘솔+화면)는 이미 끝났고, 비동기 호출부로 미처리 예외를 흘리는 부수효과 없이 같은 중단 효과를 얻음 |
| 2 | [P2] 화면 안내에 내부 예외 원문(e.message: 경로·모듈명 등)이 노출됨. 메시지 키 미사용 | 코덱스 | **반영** | 화면 안내를 추적 코드 `WS20ATTR-CHK01` 만 표시하도록 변경(내부 원문 제거). 상세는 console.error 에만 남김. 정식 안내 문구 키는 코덱스도 "검수자가 임의로 정하면 안 됨·담당자 지정 필요"라 명시 → **장군님 번호 지정 대기**(지정 시 fnGetMsgClsText 로 키만 배선) |
| 3 | 정상 경로(try 본문) 원본 1:1·무회귀, showMessage null 인자 안전(KIND 10 토스트), finally 잠금 회수, node --check | 코덱스·안티 공통 | 통과 확인 | 변경 없음 |

※ 안티 판정(통과)과 코덱스 판정(수정필요)이 갈렸으나, P1 은 제어 흐름 추적으로 실증된 지적(수집 도달 확정·저장 payload 경로 ws_html5_ws20_prev.js:443)이라 코덱스가 옳다. 안티 검수문 [P4]의 "불량 엔트리 즉시 제거" 서술은 점검이 **성공해 RETCD=E 를 돌려준 경우**의 이야기이고, P1 이 문제 삼은 것은 점검 자체가 **실행되지 못한 경우**라 반박이 되지 않는다.

## 반영 후 코드 (ws_html5_ws20_attr.js catch 블록)

- console.error `[WS20ATTR-CHK01]` + 예외 객체(콘솔에만 상세)
- 화면 안내 = `parent.showMessage(null, 10, "E", "WS20ATTR-CHK01")` (추적 코드만)
- `return;` — 후속 수집 중단(fail-closed, 원본 경계 재현), finally 가 잠금 원복
- node --check 통과
