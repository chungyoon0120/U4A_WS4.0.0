# 03_response — BR35 검수 결과 반영·해명

## 요지
- **안티=통과(Pass)**, **코덱스=수정필요(P1)** 로 판정이 갈렸다.
- 코덱스 P1(점검 함수 부재 시 `typeof` 가드가 fail-open) 은 **타당**하다. 전제(트리 렌더러 `fnRenderDesignTree`
  는 `ws_html5_ws20_tree.js`, UA040 점검 함수 `designChkHiddenAreaUi` 는 `ws_html5_ws20_dnd.js` 로 **서로 다른 파일**)를
  소스로 확인했다. 끌어놓기 파일만 로드 실패하면 트리·팝업은 살아 있고 UA040 만 조용히 건너뛰어 **BR35 결함이 재발**한다.
- 따라서 **fail-closed 로 반영**: 점검 함수가 없으면 그냥 통과시키지 않고 오류를 남기고 **UI 추가를 취소**한다.
  이는 원본(무조건 호출=미정의면 throw=차단)과 같은 계약이고, 붙여넣기 경로가 공용 추가함수 부재 시 취소하는
  기존 방어(`ws_html5_ws20_edit.js` _pasteUI)와도 동일하다.
- 안티의 "fail-open 이 이상적 강등(P4)" 은 **막는 목적의 점검에는 반대로 위험**(점검기가 없을 때 금지 UI 를
  허용) → fail-closed 로 정정. 안티가 통과 판정한 정상 경로(인자·순서·Undo 원자성·busy 대칭)는 그대로 유효하다.
