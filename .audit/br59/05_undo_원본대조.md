# 되돌리기/다시하기 — 원본 전 갈래 대조 조사 (2026-08-21, 장군님 지시)

목적: 하나씩 실화면에서 걸리지 않도록, **되돌리기 전 갈래를 원본과 통째로 대조**해 원본과 다르게 도는 곳을 한 번에 뽑는다.
원본 SSOT = `U4A_WS_DESIGN/design/undoRedo/undoRedo.js` (전 클래스 정독) + 각 클래스가 부르는 실행 함수.

## 0. 근본 구조 차이 (이게 아래 모든 차이의 뿌리)

| | 원본 | 내 HTML5 |
|---|---|---|
| 되돌리는 방식 | **제자리 부분 수정** — 무엇이 바뀌었는지 기록해 두고 그것만 되돌린다 | **통째 되감기** — 편집 직전 트리 전체를 찍어 뒀다가 통째로 갈아끼운다 |
| 미리보기 | 대상 UI만 지우고/만들고 **그 부모만** 다시 그린다 | **미리보기 전체를 다시 그린다**(`drawPreview`) |
| 되돌린 뒤 선택 | 액션별로 **정해진 대상**을 다시 선택 | 갈아끼운 뒤 **무언가를 반드시 다시 선택**해야 함 → 기록해 둔 이름으로 찾음 |

★ 원본 되돌리기에는 **미리보기 전체 다시 그리기 호출이 0건**이다(전수 확인).

## 1. 원본 액션별 계약 (정독 확인)

이력은 **반대 동작으로 저장**된다: UI 추가 → 이력은 "삭제", 삭제 → 이력은 "추가".

| 되돌릴 대상 | 원본이 실행하는 것 | 되돌린 뒤 선택 |
|---|---|---|
| UI 추가 | 삭제 처리 | 현재 선택 유지 → 그게 지워지면 **부모** → 없으면 최상위 |
| 삭제 | 추가 처리 | **되살린 그 UI** |
| 이동(위/아래·위치) | 이동 처리를 반대로 재실행 | **옮긴 그 UI** |
| 이름 변경 | **이름 글자만 제자리에서 교체** | **선택 처리 없음**(줄을 안 건드리므로 선택 그대로 유지) |
| 끌어놓기 | 지우고 다시 넣기 | **끌었던 UI** |
| 속성값 변경/초기화 | **바뀐 속성만** 미리보기에 다시 적용 + 그 부모만 다시 그림 | **그 UI + 그 속성 줄** |
| AI 삽입 | 삭제/추가 | 대상 UI |

## 2. 원본과 다르게 도는 곳 (확인된 것)

| # | 현상 | 왜 그런가 | 원본 근거 | 등급 |
|---|---|---|---|---|
| **A** | **이름 변경 되돌리기 → 선택이 부모(예: PAGE1)로 튄다** | 기록에 남는 "그때 선택돼 있던 이름"이 **바꾼 뒤 새 이름**. 되돌리면 트리는 옛 이름이라 그 이름을 가진 줄이 없어짐 → 대비책인 **부모**가 걸림 | 원본 이름변경 되돌리기는 **선택을 아예 안 건드림** | **높음**(장군님 실화면 확인) |
| **B** | **되돌릴 때마다 미리보기가 통째로 다시 그려진다** — 화면이 한 번 깜빡이고, 보고 있던 위치가 선택된 UI 쪽으로 끌려간다. 화면이 클수록 느리다 | 되감기 방식이라 "무엇이 바뀌었는지"를 몰라 전체를 다시 그림 | 원본 되돌리기에 전체 다시 그리기 **0건**, 대상 부모만 다시 그림 | 중 |
| **C** | **삭제 되돌리기 → 되살린 UI가 아니라 딴 줄이 선택될 수 있다** | 기록에 대상을 안 남겨 "삭제 당시 선택"을 씀. 트리 줄의 **휴지통 버튼**은 선택을 옮기지 않으므로, 딴 줄을 눌러 둔 채 지우면 어긋남 | 원본은 삭제 이력을 "추가"로 저장 → 추가 처리가 **되살린 UI를 선택** | 중 |
| **D** | **속성값 되돌리기도 미리보기를 통째로 다시 그린다** | 위 B와 같은 뿌리 | 원본은 **바뀐 속성만** 다시 적용 | 중 |

## 3. 원본과 같음 (확인, 손댈 것 없음)

- UI 추가 되돌리기 선택(선택 유지 → 부모 → 최상위)
- 이동 되돌리기·다시하기 선택(옮긴 UI) — 방식은 다르나 결과 동일
- 끌어놓기 되돌리기 선택(끌었던 UI)
- 속성값·초기화 되돌리기 선택(그 UI + 그 속성 줄)
- 삭제 방향일 때 확인 창 띄우기
- 잠금(화면·단축키) 짝
- 변경 표시(저장 필요 표시)를 계속 켜 두는 것 = **의도된 차이**(이미 기록됨)

## 4. 수정 계획

### 즉시 (작고 안전 — 각 한 줄)
1. **A** 이름 변경 기록에 대상 UI를 **"되돌린 뒤의 이름"(= 바꾸기 전 옛 이름)** 으로 남긴다.
   - 되돌리기 → 트리에 옛 이름이 있으니 **그 줄 선택 유지**
   - 다시하기 → 옛 이름은 없으므로 대비책(그때 선택 = 새 이름)이 걸려 **같은 줄 선택**
2. **C** 삭제 기록에 **지운 UI**를 대상으로 남긴다.
   - 되돌리기(되살림) → 그 UI가 있으니 **되살린 UI 선택** (원본과 동일)
   - 다시하기(다시 지움) → 그 UI가 없으니 대비책(선택 유지 → 부모) (원본과 동일)
   - 다건 체크 삭제는 **첫 번째로 지운 것**을 대상으로 한다(원본 추가 처리도 대표 1건을 선택).

### 크게 봐야 할 것 (B·D — 지시 필요)
되돌리기의 미리보기 반영을 "전체 다시 그리기"에서 "바뀐 것만 되돌리기"로 바꾸는 일.
전체로 간 이유가 있다: 되감기 방식은 **"무슨 속성이 바뀌었는지" 목록이 없어** 노드별로 되돌릴 수단이 없다(어떤 속성을 처음 바꾼 경우 되돌릴 대상 자체가 없음). 원본은 그 목록을 기록해 두기 때문에 가능하다.

- **(가) 작게** — 지금 구조 유지 + 되돌리기 직전 **미리보기 보던 위치를 기억했다가 복원**. 깜빡임은 남지만 위치 튐은 해소. 위험 낮음.
- **(나) 크게** — 되돌리기를 원본처럼 "바뀐 항목 목록" 기록 방식으로 재설계. 원본과 완전 일치하나 되돌리기 전체를 다시 만드는 큰 작업. 위험 높음.

권고: **1·2 먼저 반영 → 실화면 확인 → B·D 는 (가)부터.**
