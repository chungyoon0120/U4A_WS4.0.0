## 반영 1 — 값 변경 함수가 원본은 둘, HTML5 는 하나였다 (코덱스 P1-2)

### 확인한 사실 (원본 전수 대조)

원본은 값 변경이 **두 함수**로 나뉜다.

| 원본 함수 | 역할 | 전용 예외처리 갈래 |
|---|---|---|
| `attrChange`(uiAttributeArea.js **1781**) | 사용자 편집 진입점. 오류표시 초기화 → autoGrowing/dropAble 게이트 → 되돌리기 이력 → **예외처리 갈래** → 값 반영 호출 | **있음**(1840~1845) |
| `attrChangeProc`(**1929**) | 값 반영 일꾼. 수집·스타일·검증·재렌더만 | **없음** |

전수 grep 결과 원본 호출처는 `attrChange` 27곳 / `attrChangeProc` 23곳이다.
**HTML5 는 이 둘을 `fnWs20AttrChange` 하나로 합쳤다.** 그래서 BR54 갈래를 넣는 순간,
원본이 `attrChangeProc` 를 직접 부르던 23곳까지 갈래를 타게 되어 **원본과 달라진다.**

RESET 이 그중 유일하게 **반복 호출**이라 피해가 가장 크다 —
원본 2206·2219 는 `attrChangeProc` 직접 호출인데, HTML5 는 같은 루프에서 `fnWs20AttrChange` 를
연속으로 부른다(4826행). 중간에 등록 속성이 나오면 재진입 잠금이 비동기 완료까지 걸린 채
즉시 반환되고, **뒤 행들은 메모리 값만 바뀌고 수집·검증·스타일이 전부 누락**된다. 코덱스 지적 그대로다.

### 수정 내용

`fnWs20AttrChange` 에 **다섯 번째 스위치 `bSkipAttrExc`** 를 추가하고(기본값 = 종전대로 갈래 탐),
**원본이 `attrChangeProc` 를 직접 부르던 경로에만** 켰다. 원본 근거를 각 줄 주석에 달았다.

## 해명 1 — 이미지 압축 설정 모듈이 UI5 전용이라는 지적 (코덱스 P1-1 · 안티 P1)

### 사실관계는 동의

`design/attributesArea/imageCompress.js` 는 저장소 안 `attributesArea` 폴더에서
`export default async function(sAttr)` 형태를 가진 **유일한** 모듈이고(40행),
값 컨트롤을 UI5 로 직접 만들며(72행 이후) 적용 시 HTML5 에 없는 `attrChangeProc` 를 부른다(183행).
HTML5 본창에는 UI5 가 없으므로 이 모듈이 실제로 지정되면 **열리지 않는다.** 두 검수 모두 맞다.

### 그래도 BR54 에서 고치지 않는 이유

1. **BR54 의 요구사항은 "갈래(호출) 이식"이다.** 노션 이슈 본문도 "이 호출 자체가 없다"가 현상이다.
   갈래가 부르는 **대상 모듈은 서버 코드마스터가 지정**하며, 그 모듈은 원본 UI5 자산이다.
2. **원본과 결과가 같다.** 원본에서도 이 모듈은 UI5 가 있어야만 돈다. HTML5 에서 안 도는 건
   "그 모듈이 아직 변환 안 됨" 때문이지 이번 배선 때문이 아니다.
   (원본은 실패 시 조용히 죽지만, 이번 배선은 최소한 오류를 남긴다 — 원본보다 낫다.)
3. **UW13 이 정말 이 모듈을 가리키는지 미확정.** 코덱스도 "서버 데이터가 없어 정적으로 확정하지
   못했다"고 조건부로 적었다.
4. 이 모듈을 HTML5 로 새로 만드는 것은 **팝업 하나를 통째로 변환하는 별도 작업**이며,
   지시 없이 착수하면 임의 창작·범위 초과다(`CLAUDE.md` 최우선 규칙).

→ **별건으로 분리 보고.** 장군님 지시가 있으면 별도 코드번호로 "이미지 압축 설정 팝업 HTML5 변환"을
진행하겠다. 그때 적용 커밋 경로도 HTML5 값 변경 함수로 연결한다.

## 해명 2 — 판정 실패 시 fail-open (안티 P2 / 코덱스 철회)

안티가 든 시나리오는 **"패치는 켜졌는데 코드마스터 그룹이 통째로 없는" 경우**다. 이때는

- 그룹이 없다 = **등록된 속성이 0건** 이다.
- 등록된 속성이 0건이면, 사용자가 값을 넣는 그 속성도 등록돼 있지 않다.
- 즉 "특수 속성에 단순 텍스트가 저장돼 오염된다"는 결과가 **성립하지 않는다.** 그 속성은 그냥 일반 속성이다.

판정 함수가 예외를 던지는 경로도, 코덱스가 독립 확인했듯 패치 목록 조회는 배열로 정규화되고
찾기 연산 자체는 던지지 않아 **정상 제품 경로에서 도달하지 않는다**(코덱스 최초 제기 → 철회).
또 원본은 이 상황에서 값 변경 전체가 예외로 끊기고 화면 잠금이 남는다 —
"막고 잠금만 푸는" 새 동작을 만드는 건 원본에 없는 창작이다.

**단, 설치 이상 자체는 숨기면 안 되므로 보강했다** — 패치가 켜져 있는데 코드마스터 그룹이 없으면
`console.error` 로 "설치 상태 확인 필요"를 남기고 정규 처리로 진행한다(`rules/code.md` 오류 삼킴 금지).
**코드 흐름은 그대로, 진단만 추가.**

**정정한 것**: 스킵 주석에 적은 원본 줄번호 4곳이 어긋나 있었다(`attrAppF4Del` 을 5705/5716 으로,
`attrSelOption2F4HelpID` 를 5786/5796 으로 잘못 인용). **기능 매핑은 맞고 인용 줄만 틀린 것**이라
동작에는 영향이 없으나, 근거 추적이 어긋나므로 함수명까지 붙여 정정했다.

**추가 확인**: `attrSetDropAbleException`(원본 3474 = Proc)의 HTML5 이식본은 값 변경 공통 함수를
거치지 않고 수집 함수를 직접 부른다 → 갈래와 무관. **손댈 것 없음.**

## 3. 추가 수정 2건 — 원본과 더 정확히 맞춤

### (1) 전용 모듈 실행을 **원본 모듈에 그대로 위임** (코덱스 참고사항 §8 해소)

앞선 반영에서는 원본 모듈의 로직(경로 조립 + 동적 로드 + 실행)을 내 파일에 옮겨 적었다.
재검토 중 **이게 원본과 달라지는 지점**임을 확인했다.

- 원본에서 전용 모듈을 불러오는 주체는 `design/attributesArea/attrChangeException.js` **자신**이다(42행).
  따라서 코드마스터가 알려준 경로가 상대경로면 **기준 위치 = `design/attributesArea/`** 다.
- 내 파일은 `js/` 에 있으므로, 로직을 옮겨 적으면 **같은 값이라도 다른 곳을 찾는다.**
  코덱스가 "상대 경로면 기준 URL 차이를 추가 검증해야 한다"고 남긴 참고사항이 바로 이것이다.

→ 실행부를 **원본 모듈을 그대로 불러 `attrChangeException(sAttr)` 을 호출**하도록 바꿨다
(원본 attrChange 1840~1843행과 동일한 호출). 이러면

- 전용 모듈을 찾는 기준 위치가 원본과 같아진다(코덱스 참고사항 해소),
- 판정·실행 내용이 옮겨 적은 사본이 아니라 원본 그 자체가 되고,
- 원작 개발자가 원본 폴더를 통째로 갱신해도 자동으로 따라간다.

옮겨 적은 것은 **동기 판정 두 줄만** 남았다(기다릴 수 없는 동기 함수라 "탈지 말지"를 먼저 알아야 함).
그 두 조건은 원본에서도 기다림 없이 끝나는 부분이라 판정 결과가 달라질 수 없다.

### (2) 모듈이 `true` 를 주지 않으면 값 처리를 이어간다 (원본 1843행 `if` 의미 완전 재현)

원본은 `if(await attrChangeException(is_attr)){ return; }` — **`true` 일 때만** 값 처리를 건너뛴다.
앞선 반영은 대상이라고 판정되면 결과와 무관하게 건너뛰었다.
→ 모듈 결과가 `true` 가 아니면 잠금을 푼 뒤 **예외 갈래만 건너뛰고 다시 들어가 값 처리를 이어가도록**
바꿨다(되돌리기 이력·autoGrowing 게이트는 이미 지났으므로 생략).
실패(예외)로 끝난 경우는 원본도 값 처리로 내려가지 않으므로 잠금만 푼다 — 동일.

## 4. 남은 원본과의 차이 (BR54 범위 밖 — 보고만)

원본 `attrChange` 에는 이 갈래보다 **앞**에 조기 종료가 두 개 더 있다.

| 원본 | 줄 | HTML5 현황 | 갈래 영향 |
|---|---|---|---|
| ROOT 문서 속성 처리(`attrDocumentProc`) | 1795 | **미이식**(미리보기 의존, BR54 이전부터) | 그 속성이 코드마스터에 등록되면 원본은 갈래 미도달, HTML5 는 도달 |
| dropAble 처리(`attrChangeDropAbleProp`) | 1815 | 값 처리 **뒤** 부수효과로 이동(BR54 이전부터) | 위와 같음 |

둘 다 **BR54 가 만든 차이가 아니고**, 해당 속성이 코드마스터에 등록돼야만 드러난다(서버 설정 → 실측 불가).
해당 함수 주석에 남겨 두었다. 조치가 필요하면 별도 코드번호로 진행하겠다.
