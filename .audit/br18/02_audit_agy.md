# 02_audit_agy — BR18 미리보기 우클릭 "위치 이동" 팝업

## 판정

**수정필요**

메인 호스트 창에 로드되지 않는 UI5 의존성을 전면 걷어내고, 자매 팝업과 동일한 HTML5 `<dialog>` 골격 및 공통 UX 기능을 바르게 이식하여 1:1 계약에 맞게 설계되었습니다. 팝업 오픈 직후 로컬 Busy 및 단축키 잠금을 해제하는 흐름도 올바르게 배치되었습니다.
다만, 다이얼로그 노출 시점의 예외 처리와 관련하여 락 잔류 가능성이 1건 식별되어 보완을 권장합니다.

## 지적

### 1. `oDlg.showModal()` 호출 예외 발생 시 잠금 해제 누락 위험

- **위치**: `www/ws30/ws10_20/design/js/uiMovePosition.js:135`
- **문제**: 다이얼로그를 모달로 띄우는 `oDlg.showModal()` 코드가 별도의 예외 보호 장치 없이 노출되어 있습니다. 브라우저 호환성 문제나 다이얼로그의 예기치 못한 상태 오류(예: 중복 오픈 시도 등)로 인해 `showModal`이 런타임 에러를 던질 경우, 스레드 중단으로 인해 하단에 위치한 142-143행의 잠금 해제 코드(`setShortcutLock(false)`, `parent.setBusy("")`)에 도달하지 못해 화면이 영구 잠금 상태로 굳어지게 됩니다.
- **근거**: `uiMovePosition.js:135-144`; 프로젝트 규칙 `code.md` (busy on 걸면 모든 종료 분기에서 off 짝 필수).

## 확인된 정상 항목

- **UI5 의존성 전면 제거**: 원본의 `loadLibrary("sap.m")` 및 `sap.m.Dialog` 호출을 HTML5 dialog 컴포넌트로 완벽히 전환하여 호환성 Stub 예외를 원천 차단했습니다.
- **잠금(Busy) 대칭성 보완**: 메뉴 선택으로 켜진 호스트 잠금(`parent.setBusy("X")`)을 다이얼로그가 화면에 출력된 직후(143행)에 바르게 걷어냄으로써, 잠금 덮개 레이어가 다이얼로그를 덮어 마우스 클릭이 차단되던 먹통 현상을 올바르게 해결했습니다.
- **콜백/시그니처 계약 1:1 보존**: `uiMovePosition` 함수 시그니처와 확정 시 0-based 대상 index를 콜백에 넘겨 기존 `contextMenuUiMove` 로직을 타게 하는 계약 흐름이 완벽히 유지되었습니다.
- **디자인 마크(위험 함수) 제거**: 런타임에 미로드되는 `designMoveMark` 함수 호출을 완벽하게 제거하여 슬라이더나 입력값을 변경할 때 발생할 수 있는 2차 크래시 요소를 해결했습니다.
- **취소 사양 보존**: 취소 시 `001 Cancel operation` 메시지를 올바르게 호출하며 단축키 잠금을 해제하는 로직이 원본과 동일하게 유지되었습니다.
- **공통 자산 및 반응형 수용**: 다이얼로그의 리사이즈/리센터 기능 제공, CSS 테마 토큰 사용, 모바일 대응용 너비 한계값(`min(92vw, 360px)`) 설정 등 공통 디자인 사양을 성실히 이행했습니다.

## 제안

1. **`showModal` 예외 보호**:
   - `oDlg.showModal()`을 `try/catch` 블록 내부에 배치하고, 예외 발생 시 에러 로그를 출력하면서 `lf_close()`를 호출해 잠금을 확실히 풀고 복귀하도록 예외 처리를 감싸 주시기 바랍니다.

2. **동일 위치 선택 시 최적화 (선택)**:
   - 현재 코드는 원본 1:1 준수를 위해 현재 인덱스와 동일한 인덱스를 선택하고 확인을 눌러도 콜백을 무조건 실행(no-op 왕복 갱신)합니다. 자매 팝업(`_moveUIPosition`)의 방식처럼 `iTarget === iCur`일 때 조기 반환(`lf_close()` 후 return)하도록 가드 코드를 추가하면 불필요한 갱신 네트워크 연산을 차단하는 최적화를 달성할 수 있습니다.
