# BR39 검수 결과 반영·해명 (03)

두 검수(코덱스 통과 / 안티 수정필요) 종합: **두 검수 모두 코드는 정확·완벽하다는 데 일치**한다.
유일한 쟁점은 요청서(01)·코드 주석의 문구 **"오류 UI로 복귀 시 다시 표시"** 가 원본 계약과 다르다는 점이다.
- 코덱스: 통과. 최초 P2 철회. 요청서 1(b)·주석은 원본보다 넓은 부정확한 설명 → **문구 정정 권고**(제품 동작 변경 불필요).
- 안티: 수정필요. 요청서의 "복귀 시 재표시"를 필수요구로 보면 상태 유실 결함. 단 권고안 (a) = "이동 시 이전 오류 폐기가 실제 요구면 문서/주석만 정정".

## 원본 재확인 (소스 근거)
`design/js/uiAttributeArea.js:7462` `setUIInfo` — UI 선택마다 `var ls_uiinfo = {}` 를 **새로** 만들고 `OBJID_stat` 을 **넣지 않는다**. 입력필드 valueState 는 `/uiinfo/OBJID_stat` 바인딩 → 새 uiinfo 에 오류상태 없음 → 자동 None(빨간 해제).
- 잘못 입력한 OBJID 는 트리에 커밋되지 않으므로(이슈 본문도 "기존 OBJID 유지" 명시), A(오류)→B→A 재선택 시 A 의 새 uiinfo 는 저장된 정상 OBJID 를 담고 오류표시 없음.
- **결론: 원본은 "다른 UI 이동 시 이전 오류 폐기"가 계약이며, "복귀 시 재표시"는 원본에 없다.** 이슈 기대결과도 "새 UI 에 오류 없으면 이전 빨간 테두리·오류 제거"만 요구(재표시 요구 없음).
