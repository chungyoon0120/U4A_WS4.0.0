# BR33 검수 결과 반영·해명 (03_response)

두 검수(코덱스·안티)를 모두 읽고 소스로 대조했다.

## 종합 판정

- **코덱스: 통과 / 안티: 통과. 두 검수 모두 필수 지적 0건.**
- **반영할 코드 수정 없음.** 원본(`uiAttributeArea.js:3089 attrDblClickServerEvent`) 3개 가드
  (이벤트행·값 존재·trial)와 `execControllerClass(UIATV)` 호출을 1:1로 이식했고, 값칸 한정 위임으로
  이벤트명 링크·서버이벤트 생성 아이콘·클라이언트 이벤트 등록 아이콘이 자연 제외됨을 두 검수가 확인.

## 지적 통합 표

| # | 검수자 | 지적/평가 | 판정 | 근거·조치 |
|---|---|---|---|---|
| 1 | 코덱스·안티 | 원본 3개 가드·`execControllerClass(UIATV)` 1:1, 원본에 없는 UX 미추가 | 통과(합격) | 조치 없음 |
| 2 | 코덱스·안티 | 값칸 한정 위임(`.u4aWs20AttrRowVal`)으로 링크·아이콘 셀 제외, 렌더 반복 중복 배선 방지(`__bwpDblWired`), 커스텀 드롭다운 더블클릭 정상 버블 | 통과(합격) | 조치 없음 |
| 3 | 코덱스·안티 | 예외를 삼키지 않고 `console.error`로 표면화(오류 삼킴 금지 준수) | 통과(합격) | 조치 없음 |

## 정정 (코덱스 섹션 4 사실관계)

코덱스 상세 4번은 "위임 진입에서 원본과 같이 busy lock을 켜고 말미에서 해제한다"고 기술했으나,
**현행 더블클릭 위임은 화면잠금(busy)을 켜지 않는다**(ws_html5_ws20_attr.js 주석 5874~5878이 명시).
- 원본 디스패처(`attrDblclickEvent`:2956)도 더블클릭 **진입 시 busy를 켜지 않는다**. 초기 return 가드의
  `parent.setBusy("")`는 "해제"용 방어일 뿐이다.
- CSS 편집기(BR32)는 편집기 여는 함수가 **자체 수명주기로 잠금**을 관리하고,
  서버이벤트 이동(BR33)의 `execControllerClass`는 **자체 대기 다이얼로그(IPC)**를 띄운다.
- 따라서 더블클릭 경로에서 busy를 미리 걸면 오히려 중복·고착 위험이 있어 걸지 않는 것이 옳다.
- 이 정정은 **판정(통과)에 영향 없음** — 필수 결함이 아니라 검수 기술의 부정확이므로 코드 변경 없음.

## 잔여 참고 (반영 대상 아님)

1. **실환경 확인 필요**: SAP GUI 이동 완료 여부는 서버 연결·멀티 로그인·IPC 수신 환경에 의존.
   정적 검수는 `execControllerClass(UIATV)` 진입과 공용 함수 전달 계약까지 확인. → 실화면 조작 검증 권고.
2. **공용 함수 엣지(코덱스·안티 공통 제기)**: `execControllerClass` 내부에서 비동기 멀티 로그인 점검
   Promise 진입 '직전'에 동기 예외가 나면 SAPGUI 대기 다이얼로그가 고착될 잠재 가능성.
   → 이는 **공용 함수 자체 사안이며 BR33 이식 범위 밖**. 공용 함수의 자체 catch가 대기 표시를 닫는다는 것이
   코덱스 평가. 별도 참고로만 남김(BR33 결함 아님).
3. **bindField 더블클릭 미변환**: 원본 디스패처의 바인딩필드 더블클릭(서버 위치 조회) 갈래는 요청서에
   명시한 별도 미변환 범위. BR33 결함으로 판정 안 함.
