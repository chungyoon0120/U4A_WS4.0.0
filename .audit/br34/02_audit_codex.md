# BR34 ATTRIBUTE 입력필드 오류 메시지 Popover 검수

## 판정

**수정필요**

오류 필드를 처음 포커스하는 기본 시나리오는 동작하지만, 팝오버를 숨긴 뒤 동일 필드를 재클릭하는 경로와 재렌더 수명주기에 재현 가능한 결함이 있다.

## 지적

### 1. [P2] 스크롤·리사이즈로 숨긴 뒤 동일한 포커스 입력칸을 재클릭해도 팝오버가 다시 열리지 않는다

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js:5021-5024`, `5193-5196`
- 표시 리스너가 `focus`에만 연결되어 있다. 스크롤과 리사이즈는 `_attrVsHide()`로 팝오버만 숨기고 입력칸 포커스는 유지한다.
- 따라서 오류 입력칸 포커스 → 팝오버 표시 → 속성 목록 스크롤 또는 창 리사이즈 → 숨김 → 동일 입력칸 클릭 순서에서 마지막 클릭은 새로운 `focus` 이벤트를 만들지 않아 팝오버가 다시 나타나지 않는다.
- 이는 요청서의 “포커스(클릭) 시 표시 / 스크롤·리사이즈 시 숨김”을 함께 만족하지 못한다. 키보드 포커스 표시는 유지하되, 입력칸의 `click` 또는 적절한 pointer 경로에서도 `_attrVsShow()`를 호출해야 한다.

### 2. [P2] 팝오버가 열린 상태에서 속성 행을 프로그램 재렌더하면 앵커가 사라져도 팝오버가 남을 수 있다

- 위치: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js:5003`, `5025-5032`, `5948`
- `fnRenderWs20AttrRows()`는 `ROWS.innerHTML = ""`로 입력 DOM을 제거하지만, 렌더 시작 전에 `_attrVsHide()`를 호출하지 않는다.
- 포커스된 노드를 DOM에서 직접 제거할 때 `blur`가 항상 발생한다고 의존할 수 없다. 프로그램 재렌더는 mousedown·scroll·resize를 동반하지 않을 수도 있으므로, body에 붙은 싱글톤 팝오버가 이전 좌표와 문구로 남고 `_attrVsField`도 분리된 옛 필드를 가리킬 수 있다.
- 요청서의 “재렌더로 입력 DOM이 재생성돼도 … 다른 UI 선택 시 팝오버가 남지 않는가”를 충족하려면 행 제거 전에 팝오버를 명시적으로 숨기고 앵커 참조도 정리해야 한다.

### 3. [P2] 원본의 검증 직후 명시적 메시지 open 의미는 이식되지 않았다

- 위치: 원본 `www/ws30/ws10_20/design/js/uiAttributeArea.js:771-773`, `826-833`; HTML5 `www/ws30/ws10_20/js/ws_html5_ws20_attr.js:3684-3693`, `3753-3755`, `5193-5196`
- 원본은 change 진입 시 기존 value-state 메시지를 닫고, `attrChange()` 완료 후 오류 상태가 남으면 `_oValueStateMessage.open()`을 명시 호출한다.
- HTML5는 검증 후 행 전체를 재렌더하지만 새 오류 입력칸에 포커스를 복원하거나 `_attrVsShow()`를 호출하지 않는다. 메시지는 사용자가 나중에 새 입력칸을 포커스해야만 보인다.
- 노션의 최소 재현 요구인 “오류 필드를 클릭하면 표시”는 충족하지만, 요청서 검수 포인트의 원본 `_oValueStateMessage.open()` 1:1 의미와 `.analy/15` §3.5.4의 검증 오류 필드 재포커스 원칙은 충족하지 않는다. 검증·busy 종료 후 다음 틱에 새 입력 DOM을 찾아 포커스하고 메시지를 여는 처리가 필요하다.

## 확인된 정상 범위

- `valst === "Error"`인 텍스트 입력만 대상으로 하며, 빈 `valtx`는 `_attrVsShow()` 가드로 빈 팝오버를 만들지 않는다.
- 정상 오류 문구가 있을 때 빨간 테두리, title, 팝오버는 모두 `sAttr.valtx`를 사용한다. 기존 기본값 복구(`UIATV = DEFVL`) 로직은 변경하지 않았다.
- 팝오버 DOM은 모듈 싱글톤이고 window/document 전역 리스너도 `_attrVsBound`로 한 번만 등록된다.
- 공통 `.u4a-field__msg`의 색·아이콘·테두리를 소비하며 신규 색상이나 공통 CSS 수정은 없다.
- 콤보는 기존 `createSelect` value-state 경로를 그대로 사용하여 BR34 텍스트 입력 변경과 분리되어 있다.
- 바깥 클릭으로 다른 필드에 이동하는 일반 경로는 capture mousedown 및 blur가 팝오버를 숨긴다.

|---|---|---|

| 테두리·툴팁·팝오버 문구 동기화 | 통과 | 정상 오류 문구는 `sAttr.valtx` 공유 |
| 입력 기본값 복구 정책 불변 | 통과 | 기존 검증·DEFVL 로직 무변경 |

## 잔여 참고

- 팝오버는 입력칸 아래 고정 좌표만 사용하고 뷰포트 하단 flip/clamp는 없다. 요청서가 근거로 든 바인딩 팝업 패턴도 동일하므로 BR34 단독 회귀로 판정하지 않았지만, 마지막 가시 행에서 메시지가 화면 아래로 잘리는지는 실화면 확인이 필요하다.
- `z-index:40`은 WS20 속성 패널의 sticky 헤더보다 높지만 공통 콤보·메뉴·모달보다 낮다. 동시 표면에서는 의도적인 레이어 우선순위인지 실화면으로 확인하는 편이 안전하다.
