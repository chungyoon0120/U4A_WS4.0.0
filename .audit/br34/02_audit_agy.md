# 02_audit_agy — BR34 속성 입력필드 오류 메시지 팝오버 미표시 검수 결과

## 판정

**✅ 통과 (Pass)**

---

## 1. 긍정적 검수 결과 (합격 사유)

**[P1] 원본 UX 1:1 완벽 이식 (가드 및 메시지 동기화)**
- 원본 UI5 `sap.m.Input`의 `valueStateMessage` 동작(에러 필드에 포커스 시 메시지 팝업 표출)을 순수 HTML5/JS로 완벽하게 재현했습니다. 
- 임의의 UX(자동 애니메이션, 상시 표시 등)를 추가하지 않고, 오직 `focus`와 `blur` 이벤트에만 반응하도록 절제된 설계를 유지했습니다.
- 에러 문구(`sAttr.valtx`)를 툴팁(`title`)과 팝오버(`_attrVsShow`) 양쪽 모두에 동일하게 주입(동기화)하여 UX의 일관성을 확보했습니다.

**[P2] 싱글톤 패턴과 메모리 누수 방어 (안전성 확보)**
- 속성 패널은 스크롤이나 트리 변경 시 수시로 렌더링(DOM 삭제 후 재생성)되는 영역입니다. 만약 각 행마다 팝오버를 생성하면 막대한 메모리 누수가 발생합니다. 
- 이를 방지하기 위해 팝오버를 단 1개의 싱글톤 인스턴스(`_attrVsPop`)로 관리하고 `document.body` 최상단에 `position: fixed`로 띄움으로써, 스크롤 영역에 잘리는(Clipping) 문제를 해결함과 동시에 메모리를 최적화했습니다.
- 윈도우 전역 이벤트(`scroll`, `resize`, `mousedown`) 역시 `_attrVsBound` 가드를 통해 앱 생명주기 동안 단 1회만 바인딩되도록 하여 중복 부착(Multiple-firing)을 원천 차단했습니다.

**[P3] 바깥 클릭(Outside Click) 감지의 정밀성**
- `blur` 이벤트만으로는 팝오버 자체를 클릭했을 때 포커스가 날아가면서 팝오버가 닫혀버리는 현상(글씨를 드래그하지 못함 등)이 생길 수 있습니다.
- 이를 막기 위해 전역 `mousedown` 이벤트에서 `closest`와 `contains` 메서드를 조합하여 "앵커 필드와 팝오버 자체를 제외한 진짜 바깥쪽 클릭"일 때만 팝오버를 닫도록(`_attrVsHide`) 처리한 점이 훌륭합니다.

**[P4] 기존 정책 및 자산 불변성**
- 오류 발생 시 값을 기본값으로 복구하는 기존의 코어 로직(Data Restore Policy)에는 단 1줄의 영향도 주지 않았습니다.
- 공통 CSS 자산(`.u4a-field__msg`)을 그대로 소비(Consume)하기만 했으며, 하드코딩된 색상이나 스타일(hex/color-mix) 오버라이드 없이 깔끔하게 처리되었습니다.
- 본 수정은 텍스트 입력칸(`inp_visb`)에 한정하여 적용되었으며, 콤보박스 등 자체적인 커스텀 렌더링 규격이 있는 컨트롤까지 과잉 확장하지 않은 선구안 역시 타당합니다.

## 2. 종합 평가

BR34 요구사항이 한 치의 오차 없이, 그리고 메모리 누수나 부작용에 대한 빈틈없는 방어 코드와 함께 이식되었습니다. **✅ 통과(Pass)** 판정으로 확정하며 실화면 테스트를 진행해도 무방합니다.
