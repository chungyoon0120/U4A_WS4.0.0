## 1. 조사 결과 — 실행 점검이 "실제로" 터질 수 있는 자리

실행(Activate)·신텍스체크가 부르는 점검 경로 전체를 소스로 따라가, **방어 없이 바로 파고드는 참조**를 전수 확인했다. 아래는 모두 **지금 실행되는 코드**다.

| 코드 | 위치 | 터지는 조건 | 원본에도 동일? |
|---|---|---|---|
| E1 | `design/js/checkAppData/designTreeData.js:281` `oAPP.attr.prev[_sTree.OBJID]._T_0015` | 트리에 노드가 있는데 그 노드의 미리보기 항목(`prev`)이 없음 | 예(원본 사본 그대로) |
| E2 | 같은 파일 `:283` `_aT0015.length` | `prev` 항목은 있으나 `_T_0015` 가 없음 | 예 |
| E3 | 같은 파일 `:143` `oAPP.attr.S_CODE.UA050.filter` | 라이브러리 코드(T_9011)에 `UA050` 행이 한 건도 없으면 키 자체가 없어 undefined | 예 |
| E4 | 같은 파일 `:157`·`:165` `_sTree.zTREE.findIndex` | 자식 필수 UI 노드에 `zTREE` 가 없음 | 예 |
| E5 | `js/ws_html5_ws20_attr.js:515`·`:539` `oAPP.attr.prev[...]._T_0015` | E1 과 동일(sap.ui.table.Table / Column 노드) | 예(원본 `design/js/main.js` 1371 chkExcepUiTable 1:1) |
| E6 | `js/ws_html5_ws20_attr.js:461` `parent.require(PATH.join(designRootPath,…))` | 점검 모듈 파일 없음 / 경로 미설정 | 예 |
| E7 | `chkExcepionAttr` 진입부 `attrClearErrorField()` · `oAPP.attr.oModel.refresh()` | 둘 중 하나라도 미정의 | 예 |

### 1-1. 도달 가능성 (근거 있는 것만)

**E1·E2·E5 (미리보기 항목 없음) — 도달 가능. 근거 3가지**
1. `prev` 항목을 만드는 곳은 **미리보기 iframe** 뿐이다(`design/preview/index.js` 5028~5069 `new sap.ui.core.Element()` / `new l_class(...)`).
2. 내 쪽에서 미리보기를 부르는 창구(`_prev`, `js/ws_html5_ws20_edit.js` 231~237)는 **미리보기 iframe 이 없으면 아무 말 없이 건너뛴다**(`if (w && typeof w[fnName] === "function")`). 즉 미리보기가 안 떠 있거나 다시 로드 중이면 노드는 트리에만 생기고 `prev` 항목은 안 생긴다.
3. 되돌리기 복원(`_restoreSnap`, 같은 파일 459행)은 **스냅샷에 담긴 키만** `prev` 를 되살린다. 스냅샷(`_snapshot`, 176~178행)은 **`_T_0015` 가 있던 키만** 담는다 → 속성을 한 번도 안 건드린 노드는 스냅샷에 없다. 그 노드를 지웠다가 되돌리면 `prev` 항목 복구는 오로지 미리보기 재생성(2번 창구)에 의존한다.

**E3 (UA050 코드 없음) — 도달 가능성 있음(서버 데이터라 확정 불가, 미확인)**
- `S_CODE` 는 라이브러리 표를 코드별로 모아 만든다(`ws_html5_ws20_attr.js:265~289`, 원본 `main.js:1243` 1:1). `UA050` 행이 없으면 **키 자체가 안 생긴다**.
- 내 다른 코드는 이미 "없을 수 있다"는 전제로 방어돼 있다(`ws_html5_ws20_edit.js:244` `oAPP.attr.S_CODE && oAPP.attr.S_CODE.UA050`).
- 실제 서버 라이브러리에 항상 `UA050` 행이 있는지는 서버 데이터라 **여기서 확인 불가 → 미확인**.

**E4 (zTREE 없음) — 현재 코드에서 재현 경로 미발견**
- 서버 로드는 모든 노드에 배열을 넣는다(`ws_html5_ws20_data.js:93~113` `setTreeData`, 원본 `main.js:394` 1:1 — `e[treePath] = c[h]`).
- 추가 경로들도 전부 `[]` 로 채운다(`ws_html5_ws20_dnd.js:395`·`1124`·`1386`, `ws_html5_ws20_edit.js:1421`·`1453`).

**오해 배제(확인 완료)**
- `parseTree2Tab` 은 `JSON.parse(JSON.stringify(...))` 로 **깊은 복사한 뒤에** `zTREE` 를 지운다(`ws_html5_ws20_prev.js:389~401`, 원본 `main.js:270` 1:1) → 실제 모델을 훼손하지 않는다. 뒤이어 도는 자식필수 점검이 이것 때문에 터지는 일은 없다.
- `checkPropertyValue` 의 점검 스크립트 실행은 `try/catch` 로 감싸져 있어(`designTreeData.js:110~114`) 점검 스크립트 오류로는 안 터진다. **대신 조용히 삼킨다 — 원본 결함, 이번 범위 밖(별건 보고)**.

### 1-2. 왜 점검부를 직접 고치지 않았나
E1~E7 은 **전부 원본과 동일**하다(designTreeData.js 는 원본 사본, chkExcepUiTable/chkExcepionAttr 는 원본 `main.js` 1:1 이식본). 원본은 손대지 않는다는 최우선 규칙에 따라 **점검부 안에 방어를 넣지 않고, 부르는 쪽에서 잡아 크리티컬로 드러내는 방식**을 택했다.

## 2. 보완 — 크리티컬 오류 공통 처리 (장군님 지시 2026-09-01)

`www/ws30/ws10_20/js/ws_events.js` 에 공통 함수 `_ws20CriticalError(코드, 예외, 자식창회수여부)` 추가(1552행~). **프로젝트 기존 크리티컬 전례를 그대로 따랐다.**

| 단계 | 내용 | 참고한 기존 전례 |
|---|---|---|
| ① | 콘솔에 구간 추적 코드 + 예외 원문 (`console.error`) | `ws_common.js:4011` `fnJsonParseError` |
| ② | 화면 잠금 해제 — `fnSetBusyLock("")` + `parent.setBusy("")` | `ws_common.js:4017~4020` |
| ③ | 자식창 잠금 회수 — `oMainBroad BUSY_OFF`(이미 `BUSY_ON` 을 방송한 구간에서만) | `fnDialogPopupOpener.js:121` 등 |
| ④ | 작업표시줄 깜빡임 | `usp/ws_usp.js:4052` `fnCriticalErrorWs30` |
| ⑤ | 공통 오류 팝업 `showMessage(null, 20, "E", …)` — 문구 = **기존 키** `/U4A/MSG_WS 192`("Fatal Error! Please contact your system administrator.") + `[추적코드] 예외원문` | `ws_common.js:4025`, `ws_usp.js:4057~4059` |
| ⑥ | 호출측은 곧바로 `return` → **다음 처리 진행 안 함**(fail-closed) | — |

- KIND 20 = 공통 오류 팝업(OK 1버튼)이며 **내부에서 오류음까지 낸다**(`resources/index.js:293~298`) → 소리를 따로 내지 않는다(중복 방지).
- **세션 전체 창을 닫는 `fnCriticalError` 콜백은 붙이지 않았다.** WS20 은 저장 안 한 앱 설계가 메모리에 있어 강제 로그오프하면 작업분이 사라진다. → **장군님 판단 대기**.
- 메시지는 **기존 키만** 사용(임의 문구·키 생성 금지 규칙 준수).

### 적용한 자리 4곳

| 추적 코드 | 자리 | 무엇을 막나 |
|---|---|---|
| `WS20ACT-CHK01` | 실행(Activate) — 점검 호출 | 점검이 터지면 활성화 중단(서버 전송 안 함) |
| `WS20ACT-CHK02` | 실행(Activate) — 오류 목록 창 열기 | 창 열기가 터지면 잠금 회수 + 알림 |
| `WS20SYN-CHK01` | 신텍스체크 — 점검 호출 | **신규**. 종전엔 감싸지 않아, 점검이 터지면 안내 없이 화면이 잠긴 채 멈췄다 |
| `WS20SYN-CHK02` | 신텍스체크 — 오류 목록 창 열기 | **신규**. 같은 이유 |

> 신텍스체크 쪽은 원본이 감싸지 않는 자리다. 원본대로 두면 "점검이 터지면 안내 없이 화면 잠긴 채 멈춤"이 그대로 남으므로, **이번 지시(비정상 종료 시 크리티컬 처리)에 따라 실행(Activate) 과 같은 방식으로 맞췄다.** 정상 동작은 변함 없음(아래 실행 검증 A·D).
