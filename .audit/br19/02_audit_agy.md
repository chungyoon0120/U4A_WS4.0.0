# 02_audit_agy — BR19 UI 추가 팝업 BUSY 미해제

## 판정

**수정필요**

미리보기 영역 우클릭에서 "오브젝트 삽입" 선택 시 발생하는 화면 영구 잠김 현상을 해결하기 위해, 조기 반환 경로 및 오픈 완료 시점에 맞춰 Busy/단축키 잠금을 끄는 헬퍼(`_releaseBusyLock`)를 배치한 구조적 방향은 타당합니다.
그러나 팝업 빌드 중 발생하는 런타임 오류 상황에 대한 예외 처리 안전망이 누락되어 있고, 페인트 완료를 보장하는 잠금 해제 타이밍 및 조용한 catch 사용 측면에서 보완이 요구됩니다.

## 지적

### 1. 팝업 구성 및 렌더링 구간의 예외 처리 누락과 조용한 catch 사용

- **위치**: `www/ws30/ws10_20/js/ws_html5_ws20_edit.js:1192-1195`, `1205-1552`
- **문제**: 
  1. Aggregation 검증을 마친 후 다이얼로그 구조 빌드, 백드롭 생성, DOM 첨부 및 `lf_renderTable()` 연산이 수행되는 전 구간이 `try-catch` 보호를 받지 않습니다. 해당 구간에서 런타임 에러(TypeError 등)가 발생할 경우 실행이 즉시 중단되어 1558행의 잠금 해제 예약 코드에 도달할 수 없으므로, 우클릭 진입 단계에서 설정된 화면 잠금과 단축키 락이 풀리지 않는 영구 락 상태가 재발합니다.
  2. `_releaseBusyLock` 헬퍼 함수 내에 오류를 아무 기록 없이 삼켜버리는 빈 `catch(e) {}` 블록이 사용되고 있습니다.
- **근거**: `ws_html5_ws20_edit.js:1192-1195`, `1205-1558`; 프로젝트 규칙 `code.md` (on 걸면 오류를 포함한 모든 종료 분기에서 off 짝 필수, 조용한 catch 금지).

### 2. 단일 `requestAnimationFrame` 사용으로 인한 페인트(Paint) 완료 보장 미흡

- **위치**: `www/ws30/ws10_20/js/ws_html5_ws20_edit.js:1558`
- **문제**: `requestAnimationFrame` 콜백은 다음 갱신의 Paint(페인트) 동작이 수행되기 직전 프레임에 실행됩니다. 따라서 현재의 단일 rAF 예약 구조는 `lf_renderTable()`에 의해 구성된 DOM 및 데이터를 웹 브라우저가 화면에 완전히 그리기도 전에 잠금을 해제해 버릴 위험이 있습니다. 이는 렌더 및 포커스가 완전히 끝난 후 잠금을 해제해 연타 꼬임을 방지하려는 WP1 규칙("렌더 완료 시점 해제")에 부합하지 않습니다.
- **근거**: `ws_html5_ws20_edit.js:1558`; 프로젝트 규칙 `code.md` (로딩표시 busy는 화면 렌더·데이터 구성 등이 완전히 끝난 뒤에 끈다 - WP1 방식).

## 확인된 정상 항목

- **조기 종료 경로 보완**: `!is_tree` 분기(1196행) 및 Aggregation 없음 분기(1201행)에서 조기 종료 시 락 해제 코드를 성실히 배선하여 원본 UI5 `uiDesignArea.js` 및 `insertUIPopop.js` 사양에 대응했습니다.
- **진입/수렴 경로 멱등성**: 트리 영역의 추가 버튼 클릭을 통해 Busy ON 없이 진입하더라도, `_releaseBusyLock`에 의한 해제(Busy OFF)가 멱등적으로 수행되어 타 UI 구성에 오작동을 유발하지 않음을 확인했습니다.
- **별창 잠금 채널과의 격리**: 확정 시 실행되는 별창 갱신 잠금 채널(`_broadBusy`)과 이번 수정 대상인 로컬 잠금 해제 흐름 간에 기능적 충돌이 없습니다.
- **구문 정상**: 대상 스크립트는 `node --check` 검사를 오류 없이 정상 통과했습니다.

## 제안

1. **팝업 생성 과정의 try-catch 보호 및 복원 코드 구성**:
   - Aggregation 확인 이후부터 다이얼로그 오픈 및 테이블 렌더에 이르는 본문 전체를 `try-catch` 블록으로 감싸주십시오.
   - `catch` 블록에서는 에러 로그를 명확히 출력(표면화)하고 `_releaseBusyLock()`을 호출하여 영구 락을 예방하며, 부분적으로 추가되다가 에러가 난 다이얼로그나 백드롭 DOM 요소가 있다면 `remove()`하여 화면을 원래대로 복원하도록 만드십시오.
   - `_releaseBusyLock` 내부의 빈 catch 블록도 에러 로깅을 명시하도록 수정해 주십시오.

2. **이중 `requestAnimationFrame` 또는 포커스 완료 후 해제 (WP1 보장)**:
   - 다음 페인트 프레임이 완전히 반영된 시점을 확실하게 대기할 수 있도록 이중 rAF 패턴(`requestAnimationFrame(() => requestAnimationFrame(() => _releaseBusyLock())))`을 적용하거나, 혹은 포커스 완료 지연 함수 내부에서 안전하게 잠금 해제가 순차 처리되도록 개선해주십시오.
