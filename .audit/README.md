# 검수 왕복 규약 (SSOT)

코딩은 **Claude**, 검수는 **Codex** / **Antigravity(안티)**.
세 도구가 같은 프로젝트 폴더를 보면서 이 규약대로 `.audit/` 폴더에 md 파일을 주고받는다.

이 문서가 유일한 규칙이다. 트리거 문구를 받으면 먼저 이 문서를 읽고 그대로 따른다.

---

## 1. 폴더/파일 규약

검수 대상 기능마다 폴더 하나를 만든다. 검수할 기능이 많으므로 **전체 진행 현황은 `.audit/00_현황판.md` 한 장**으로 관리한다.

```
.audit/
  00_현황판.md           ← 전체 기능 목록 + 각 기능 진행 상태 (한눈에)
  <기능명>/
    01_request.md        ← Claude 작성: 검수 요청(대상·범위·확인 포인트)
    02_audit_codex.md    ← Codex 작성: 검수 결과
    02_audit_agy.md      ← Antigravity 작성: 검수 결과
    03_response.md       ← Claude 작성: 반영/반론
    04_final.md          ← 마무리 검증 결과
```

- `<기능명>`은 화면/기능을 알아볼 수 있는 이름(예: `bind-popup`, `ws20-tree-dnd`).
- 검수자가 코덱스·안티 둘 다면 `02_audit_codex.md`, `02_audit_agy.md`를 각각 쓴다. 한쪽만이면 그 파일만.
- 번호 순서(01→02→03→04)를 지킨다. 기존 파일은 덮지 말고 다음 번호로 이어간다.
- **어떤 파일을 새로 만들거나 상태가 바뀌면, 그 도구가 `.audit/00_현황판.md`의 해당 기능 행도 같이 갱신한다.**

---

## 1-1. 전체 현황판 (`.audit/00_현황판.md`)

기능이 많아 어디까지 됐는지 한눈에 보기 위한 목록. 새 기능 검수를 시작하면 맨 위에 행을 추가한다.

형식:

```
| 기능명 | 검수요청(01) | 검수-코덱스(02) | 검수-안티(02) | 보완·해명(03) | 최종(04) | 비고 |
|---|---|---|---|---|---|---|
| bind-popup | ✅ | ✅ | ✅ | ✅ | ☐ | 반론 1건 |
| ws20-tree-dnd | ✅ | ☐ | ☐ | ☐ | ☐ | 검수 대기 |
```

- 칸 표시: `☐` 아직 / `✅` 완료 / `❌` 문제있음.
- **검수는 코덱스·안티 둘 다** 받는다. 두 칸이 모두 `✅` 돼야 Claude가 보완(03) 단계로 간다.
- 각 도구는 자기 단계가 끝나면 자기 칸만 갱신한다(순서·행 위치는 바꾸지 않는다).

---

## 1-2. 역할 경계 (강제 — 반드시 지킨다)

각 도구는 **자기 역할·자기 소유 파일만** 다룬다. 남의 역할을 대신하지 않는다.

| 도구 | 쓰는 파일(소유) | 절대 금지 |
|---|---|---|
| **Claude** | `01_request.md`, `03_response.md`, `04_final.md` + 코드 | ❌ `02_audit_*.md`를 **직접 쓰지 않는다**. ❌ 검수를 대신하려고 `codex`·`agy` CLI를 **돌리지 않는다**(`codex-agent`·`agy-agent` 스킬도 이 검수 왕복에선 쓰지 않음). 검수는 장군님이 그 도구에서 직접 시킨다. |
| **Codex** | `02_audit_codex.md` | ❌ 코드 수정·`01`·`03`·`04` 작성 안 함. ❌ 안티 파일(`02_audit_agy.md`) 안 건드림. |
| **Antigravity** | `02_audit_agy.md` | ❌ 코드 수정·`01`·`03`·`04` 작성 안 함. ❌ 코덱스 파일(`02_audit_codex.md`) 안 건드림. |

- **Claude가 "검수 자료 작성해"를 받으면**: 검수를 *하는* 게 아니라, 코덱스·안티가 검수*하도록* `01_request.md`(검수 요청서)만 쓴다. 여기서 멈춘다. 절대 검수 결과를 스스로 만들지 않는다.
- 검수 결과(`02_*`)는 오직 장군님이 코덱스/안티 세션에서 직접 시켜야 생긴다.

## 2. 도구별 트리거와 할 일

| 도구 | 장군님이 던지는 말 | 할 일 |
|---|---|---|
| **Claude** | "검수 자료 작성해" | 대상 기능 폴더에 `01_request.md` 작성 |
| **Claude** | "검수내용 확인해" | `02_audit_codex.md` + `02_audit_agy.md` **둘 다** 읽고, 지적을 합쳐 `03_response.md` 작성(반영/반론) |
| **Codex** | "검수자료 확인해서 검토해" | `01_request.md` 읽고 `02_audit_codex.md` 작성 |
| **Antigravity** | "검수자료 확인해서 검토해" | `01_request.md` 읽고 `02_audit_agy.md` 작성 |

## 3. 파일별 작성 형식

### 01_request.md (Claude)
- **검수 대상**: 파일 경로·함수명·기능 이름
- **변경 요약**: 무엇을 왜 바꿨나 (원본 대비)
- **검수 포인트**: 꼭 봐달라는 항목(정확성 버그, 원본 1:1 여부, 공통 자산 소비, 반응형 등)
- **근거**: `.analy` 절 번호 / 원본 파일 경로

### 02_audit_codex.md / 02_audit_agy.md (검수자)
- **판정**: 통과 / 수정필요 / 보류
- **지적**: 항목별로 `파일:라인` + 문제 + 근거
- **제안**: 있으면 (강요 아님)

### 03_response.md (Claude)
- **코덱스·안티 두 검수 결과를 모두 읽고** 지적을 한 표로 합친다.
- 지적 항목별 **어느 검수자 / 반영함 / 반론(이유)** 표. 같은 지적이면 합쳐서 한 줄.
- 반영한 커밋·수정 위치

### 04_final.md
- 남은 항목 0 확인, 최종 판정

---

## 4. 원칙
- 이 프로젝트의 정답은 항상 **원본(as-is) + `.analy` SSOT**. 검수도 이 기준으로 한다.
- 임의 창작·원본에 없는 UX 추가 금지. 이상하면 지적만, 반영은 장군님 지시가 있을 때.
- 노션 이슈DB 상태는 장군님이 직접 바꾼다. 검수 결과로 상태를 임의 변경하지 않는다.
