## 1. 지적 사항 (세션 경계 가상 스크롤 키 초기화 누락)

- **문제점 파악**
  - 공통 가상 스크롤에 추가된 `_vs.setSel(sKey)` 로직은 화면 밖으로 스크롤이 나갔다 들어올 때 과거 선택 행을 안전하게 복원해주는 핵심 유틸로서 완벽히 구현되었습니다. (비가상 스크롤 부작용 0% 확인)
  - **그러나 바인딩 팝업(`fnBindPopupOpen.js`)의 생명 주기(세션) 관리 측면에 심각한 맹점이 있습니다.**
  - 팝업을 열거나 데이터를 새로고침할 때, 이전 팝업 세션에서 클릭했던 가상 선택 키(`_vs.selKey`)가 메모리에서 초기화되지 않은 채 잔존합니다.
  - 이로 인해, 팝업을 닫고 **다른 속성의 바인딩 팝업을 다시 열었을 때**, 이전 팝업에서 눌렀던 키와 우연히 매칭되는 자식 키가 있다면 **엉뚱한 행에 시각적 강조(`aria-selected="true"`)가 되살아나는(고스트) 치명적 회귀 버그**가 발생합니다.

- **원인**
  - 기존 비가상 스크롤 체제에서는 데이터를 로드할 때 DOM을 통째로 파괴하고 재생성하므로 시각적 강조(`aria-selected`)가 자연스레 소멸했습니다.
  - 하지만 BR27에서 "가상 스크롤"로 전환하며 **선택 상태 영속화**를 구현했으므로, 팝업 인스턴스(또는 `oUI.tree`)를 재사용할 경우 **개발자가 명시적으로 선택 생명주기를 끝내야 하는 새로운 계약**이 발생했습니다. 이 계약(초기화)이 누락되었습니다.

---

## 2. 권장 수정 방안

팝업을 새롭게 오픈하거나 데이터를 로드하기 직전(세션 경계)에 이전 세션의 가상 선택 키를 명시적으로 지우는 코드를 삽입하십시오.

**수정 제안 위치**: `fnBindPopupOpen.js` 내부에서 데이터를 받아 렌더링을 준비하는 곳(예: `lf_renderTree` 내부 혹은 트리 객체 재사용 직전)
```javascript
// 트리가 이미 존재하고 재사용되는 경우, 이전 가상 스크롤의 잔존 선택 키(고스트)를 명시적으로 해제.
if (oUI.tree) { 
    oUI.tree.selectByKey(null, false); 
}
```
위와 같은 명시적 초기화 로직을 통해 이전 세션의 가상 선택이 완전히 제거된 백지상태에서 새로운 데이터 바인딩을 반영하도록 보완 후 다시 검수를 요청하십시오.

## 3. 종합 평가

서브에이전트 2기를 동원한 코드/구문 분석상 `fnBindPopupOpen.js`와 `u4a-ui.js` 간의 방어 로직과 가상 스크롤 구현 자체는 완벽했습니다. 하지만 **Codex 에이전트**의 지적처럼 **팝업 생명주기 및 세션 경계(데이터 재로드)에서의 가상 스크롤 초기화 누락**은 치명적인 시각적 오류를 일으키는 맹점이므로, 최종 판정을 ❌ 수정필요로 번복합니다. 해당 초기화 로직을 보완해주십시오.
