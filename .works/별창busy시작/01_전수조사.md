## 1. 창이 뜰 때 실제 순서 (소스 기준)

별창 하나가 뜨는 과정은 두 쪽으로 나뉜다.

**opener 쪽** (창을 만드는 부모 화면)
1. `oAPP.common.fnSetBusyLock("X")` — **부모 창**의 busy 를 켠다. 자식 창과 무관.
2. `new REMOTE.BrowserWindow(...)` — 창 생성.
3. `loadURL(...)` — 페이지 로드 시작.
4. `ready-to-show` → `WSUTIL.setParentCenterBounds(...)` 로 위치만 잡는다. (여기서 창을 띄우지는 않는다)
5. `did-finish-load` → 자식에게 IPC 로 데이터 전송.

**페이지 쪽** (새 창 안)
6. `window.addEventListener("load", ...)` → 헤더 그리기, 이벤트 배선
7. `CURRWIN.show()` ← **여기서 창이 화면에 나타난다**
8. IPC 로 온 데이터가 도착 → 본문 렌더 → `_finishOpen()` 에서 busy off

**문제는 7번 시점이다.** 이때 화면에 그려져 있는 것은 타이틀바 + 빈 본문뿐이고,
busy 오버레이는 꺼져 있다. 다크 테마면 그 빈 본문이 검정이다.

## 2. 원인 두 가지

### 원인 A — HTML 첫 페인트에 busy 가 꺼져 있다 (주원인)

공통 busy 오버레이 마크업이 HTML 에 `data-busy` 없이(=꺼짐) 들어가 있고, JS 가 나중에 켠다.
창 페이지 **21곳 중 첫 페인트부터 켜져 있는 곳은 3곳뿐**이다.

`❌` 7곳(현재 앱 기술 문서·MIME·편집기·Error Page 편집기·Version Management·Snippet·테마 디자이너)은
주석에 "busy 는 여기서 끄지 않는다 — **opener 가 켠 부모 창 busy 를 유지**한다" 라고 적혀 있다.
즉 **부모 창에만 busy 가 있고 새로 뜬 창에는 없다.** 새 창을 보고 있는 사용자에겐 빈 창이다.

관련 소스
- 정상 예 : `www/ws30/ws10_20/Popups/ui5CssPopup_v2/main/frame.html:78` (`data-busy="true"`)
- 안 켜는 예 : `www/ws30/ws10_20/Popups/docPopup/frame.js:883~907` (load → show, busy 호출 없음)
- 부모 busy 만 믿는 주석 : `www/ws30/ws10_20/Popups/versionMng/versionMngFrame.js:1132`

### 원인 B — 공통 busy 에 0.3초 지연이 걸려 있다

`www/ws30/ws10_20/theme/shell.css:1019`

```
/* 표시를 0.3s 지연 → 짧은 busy(빠른 on/off)는 화면에 나타나지 않아 깜빡임 없음 */
.u4a-busy[data-busy="true"] {
    transition: opacity 0.18s linear 0.3s, visibility 0s linear 0.3s;
}
```

JS 로 켜면 **0.3초 기다렸다가 0.18초 동안 서서히** 나타난다. 그래서 위 표의 `⚠️` 창들은
busy 를 켜긴 켜는데 화면에는 0.3~0.5초 뒤에 나타난다. 그 사이가 검은 화면이다.

이 지연은 원래 "짧은 busy 가 깜빡이지 않게" 넣은 것이라 평상시엔 필요하다.
**HTML 에 `data-busy="true"` 로 박아두면 첫 렌더라서 transition 자체가 안 걸린다** — 즉시 보인다.
이게 `✅ 정상` 3곳이 멀쩡한 이유다.

## 4. 고치는 법 (제안 — 아직 안 함)

1. **HTML 에 busy 를 켠 채로 박는다.** 모든 별창 페이지의 busy 마크업을
   `<div class="u4a-busy" id="..." data-busy="true">` 로. 첫 페인트부터 보인다.
   busy 요소가 아예 없는 창(옵션·Text Search)은 마크업을 넣는다.
   `<dialog class="u4a-busy">` 로 된 창(Data Monitor·Snippet·테마 디자이너·Shortcut Creator)은
   `<dialog>` 가 `showModal()` 전엔 안 보이므로 **처음 표시용 `<div>` 를 따로** 둔다.
2. **끄는 곳을 한 군데로 모은다.** 각 창의 `_finishOpen()`(없으면 새로 만든다) 한 곳에서만 끄고,
   데이터 도착 실패·오류 분기에서도 반드시 지나가게 한다(지금 있는 20초 안전장치는 유지).
3. **opener 는 전부 `show:false` + `backgroundColor = BGCOL`** 로 맞추고,
   네이티브 투명도 페이드(`opacity 0 → setBrowserOpacity`)는 걷어낸다.
4. **로그**를 같이 넣는다(장군님 지시 2026-09-10) — 창 뜸 / busy on / busy off / 안전장치 발동.
