## 2. ResponsiveGridLayout 컬럼·레이블 속성 검증 추가

### 적용 위치

- 파일: /www/ws30/ws10_20/design/js/checkAppData/designTreeData.js
- 검사 함수: oCheckFunc.validResponsiveGridLayoutColumns
- 검사 진입점: module.exports.checkPropertyValue
- 설정: UW09 공통코드

### 적용 내용

UW09 공통코드에 sap.ui.layout.form.ResponsiveGridLayout의
점검 대상 프로퍼티와 검사 처리 내용을 설정하고,
기존 공통코드 기반 검사 흐름을 통해 검증한다.

validResponsiveGridLayoutColumns를 UW09 검사보다 먼저 직접 호출하는 방식이 아니다.

### 처리 흐름

1. checkPropertyValue에서 바인딩 여부와 프로퍼티 유형을 확인한다.
   - ISBND === "X"인 바인딩 항목은 제외한다.
   - UIATY !== "1"인 항목은 제외한다.
2. UW09 공통코드에서 해당 UI와 프로퍼티의 활성 검사 설정을 조회한다.
3. UW09에 설정된 검사 처리 내용을 실행하여
   validResponsiveGridLayoutColumns를 통해 입력값을 검사한다.
4. 검사 결과의 RETCD와 RTMSG를 호출부에 반환한다.
5. 호출부에서 오류 표시와 입력값 복원 등 후속 처리를 수행한다.

### 점검 대상과 허용값

| 속성 | UIATK | 허용값 |
| --- | --- | --- |
| labelSpanXL | AT000012666 | -1 또는 1~12의 정수 |
| columnsXL | AT000012675 | -1 또는 1~12의 정수 |
| labelSpanL | AT000012667 | 1~12의 정수 |
| labelSpanM | AT000012668 | 1~12의 정수 |
| labelSpanS | AT000012669 | 1~12의 정수 |
| columnsL | AT000012676 | 1~12의 정수 |
| columnsM | AT000012677 | 1~12의 정수 |

### 오류 처리

- 빈 문자열, 숫자로 변환할 수 없는 값, 정수가 아닌 값은 오류로 반환한다.
- 정수여도 속성별 허용 범위를 벗어나면 오류로 반환한다.
- 오류 여부는 RETCD = "E", 오류 메시지는 RTMSG에 설정한다.
- 숫자·정수 조건 위반 메시지: ZMSG_WS_COMMON_001 / 372
- 허용 범위 위반 메시지: ZMSG_WS_COMMON_001 / 226

### 유지보수 시 주의사항

- 검사 함수의 존재만으로 모든 대상 속성이 자동 검사되는 것으로 해석하지 않는다.
  UW09의 대상 프로퍼티 및 검사 처리 설정이 전제다.
- UW09보다 앞에서 대상 UIATK를 검사하고 결과를 바로 반환하는
  별도 우선 검사 분기를 다시 추가하지 않는다.
- XL 속성의 허용값은 "-1 또는 1~12"이며, 0은 허용하지 않는다.
- 검사 함수는 오류 결과를 반환하고, 입력 필드의 오류 표현은 호출부에서 처리한다.

## 3. 속성 검증 오류 시 ComboBox 표시값 동기화

### 적용 위치

- 파일: /www/ws30/ws10_20/design/js/uiAttributeArea.js
- 함수: oAPP.fn.attrChangeProc

### 적용 내용

프로퍼티 검증 오류로 입력값을 기본값으로 복원할 때,
ComboBox의 value에 바인딩된 comboval도 같은 값으로 설정한다.

### 처리 흐름

1. designTreeData.js의 checkPropertyValue(is_attr)를 호출한다.
2. RETCD === "E"이면 오류 상태를 설정한다.
   - is_attr.valst = "Error"
   - is_attr.valtx = 반환된 RTMSG
3. T_0023에서 동일한 UIATK의 DEFVL을 조회하여 UIATV에 설정한다.
   - 실제 대입식은 조회한 DEFVL || ""이다.
4. uityp === "DDLB"이면 다음 동기화를 수행한다.
   - is_attr.comboval = is_attr.UIATV
5. 기존 속성 반영, 라인 스타일, 미리보기 및 모델 갱신 흐름을 유지한다.

### 적용 범위

- ResponsiveGridLayout만의 전용 처리가 아니다.
- attrChangeProc에서 검증 오류가 발생한 DDLB 입력에 공통 적용된다.
- 이번 보완의 핵심은 기존 기본값 복원 흐름에 comboval 동기화를 추가한 것이다.

## 4. uploadUrl 기본 URL 매핑 필드 수정

### 적용 위치

- 파일: /www/ws30/ws10_20/design/js/uiAttributeArea.js
- 함수: oAPP.fn.attrUploadUrlException

### 대상 UI

| UI | UIOBK | uploadUrl UIATK |
| --- | --- | --- |
| sap.m.UploadCollection | UO00469 | AT000006316 |
| sap.ui.unified.FileUploader | UO01180 | AT000013501 |

### 적용 내용

기본 URL을 잘못된 UIAT 필드에 매핑하던 코드를 수정하여,
실제 속성값 필드인 UIATV에 설정한다.

- 이전: ls_0015.UIAT = 기본 URL
- 현재: ls_0015.UIATV = 기본 URL
- 기본 URL: "/zu4a_srs/" + 현재 APPID의 소문자 값

다음 두 조건의 기존 수집 데이터에 적용된다.

1. uploadUrl의 UIATV가 빈 문자열인 경우
2. U4A 기본 URL에 포함된 APPID가 현재 APPID와 다른 경우

### 관련 보완 및 유지 조건

- 기본 URL 여부는 대소문자를 구분하지 않고
  "/ZU4A_SRS/" 접두어로 시작하는지 검사한다.
- 값이 존재하면서 ISBND === "X"이면 변경하지 않는다.
- U4A 기본 URL 접두어로 시작하지 않는 사용자 지정 URL은 유지한다.
- 수집 데이터가 없으면 기존 생성 경로에서 UIATV에 기본 URL을 설정하고
  대상 UI의 _T_0015에 추가한다.

여기서 기본값 설정은 _T_0015의 UIATV에 기본 URL을 넣는 의미다.
라이브러리 T_0023의 DEFVL을 수정하는 로직은 아니다.

## 5. 허용되지 않는 부모 Aggregation 안내 방식 변경

### 적용 위치

- 파일: /www/ws30/ws10_20/design/js/uiDesignArea.js
- 함수: oAPP.fn.designChkFixedParentUI

### 기존 판단 기준

- UW03에서 대상 UI의 UIOBK와 일치하고 FLD06 !== "X"인 규칙을 조회한다.
- 제한 규칙이 없으면 검사에 의한 차단 없이 반환한다.
- 규칙의 부모 UI 키와 Aggregation이 전달받은 PUIOK, UIATT와

### 변경 내용

허용되지 않는 부모 Aggregation에 추가하려는 경우,
기존 MessageToast 대신 정보 유형 팝업으로 안내한다.

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| showMessage 인자 | 10, "E" | 20, "I" |
| 표현 방식 | MessageToast | 정보 유형 팝업 |
| 메시지 | /U4A/MSG_WS / 306 | ZMSG_WS_COMMON_002 / 005 |

허용 위치는 "부모 UI 정보(FLD04) - Aggregation(FLD05)" 형식으로 구성한다.
대상 UI가 추가될 수 있는 부모 UI와 Aggregation 목록을 줄별로 안내한다.

### 유지되는 제어 흐름

- 허용 불가 시 true를 반환하는 동작은 유지한다.
- 호출부는 true 반환 시 후속 처리를 중단한다.
- 이번 변경은 허용 규칙 자체가 아닌 메시지 표현 방식과 문구의 변경이다.
- 확인된 호출부인 drop_cb, designAddUIObject, lf_aggrPopup_cb에
  동일한 안내 방식이 적용된다.

## 6. 미리보기 오류 처리를 공통 모듈로 연결

### 적용 위치

- 파일: /www/ws30/ws10_20/design/preview/index.js
- 대상:
  - 공통 오류 모듈 초기화
  - window.onerror
  - window.addEventListener("unhandledrejection", ...)
  - sap.ui.core.UIArea.rerenderControl

### 공통 모듈 초기화

미리보기 초기화 시 다음 호출을 수행한다.

parent.require(parent.PATHINFO.WSTRYCATCH)(window, document, console);

require로 모듈을 가져오는 것에 그치지 않고,
반환된 초기화 함수에 미리보기의 window, document, console을 전달하여 실행한다.

### 기존 직접 처리 비활성화

다음 미리보기 전용 직접 처리 블록은 주석 상태로 유지한다.

- 기존 window.onerror 처리
- 기존 unhandledrejection 이벤트 처리
- 위 처리에서 직접 호출하던 parent.parent.showCriticalErrorDialog(...)
- rerenderControl 내부의 기존 try/catch 오류 처리

addEventListener 변경 대상은 unhandledrejection 처리다.
다른 미리보기 이벤트 리스너 전체를 비활성화한 것은 아니다.

### 렌더링 예외 처리

- rm.render(oControl, oParentDomRef) 호출은 유지한다.
- 렌더 예외를 기존 지역 catch에서 직접 처리하지 않는다.
- 외부로 전파되어 미처리 오류가 된 예외가 공통 오류 처리 경로로
  전달되도록 구성한다.
- 상위 호출부에서 처리된 예외까지 모두 공통 팝업으로 표시된다고 단정하지 않는다.

### 연결된 공통 모듈의 기존 동작

- 파일: /www/ws30/ws10_20/js/ws_trycatch.js
- window.onerror와 unhandledrejection 처리기를 등록한다.
- 오류 로그를 출력하고 Electron 오류 대화상자를 표시한다.
- 플래그로 중복 오류 처리를 제한한다.
- 대화상자 종료 후 WSLOG.openLOG(true)를 호출하고 APP.exit()를 수행한다.

이는 연결된 공통 모듈의 기존 정책이며,
이번 변경으로 공통 모듈 자체에 새로 추가한 기능은 아니다.

### 유지보수 시 주의사항

- 주석 처리된 직접 오류 처리 블록을 임의로 다시 활성화하지 않는다.
- 기존 직접 처리와 공통 처리를 동시에 활성화하지 않는다.
- 기존 직접 처리에 있던 디자인 잠금 해제나 ERROR UI ID 추가가
  공통 모듈에서도 동일하게 수행된다고 가정하지 않는다.
- 공통 오류 처리에는 앱 종료 경로가 있으므로 단순 안내 팝업 교체로만 해석하지 않는다.

## 7. imageCompressSettings 기존 기능 설명 및 WS 4.0 이식 기준

### 7.1. 설명 추가 배경과 이식 목적

imageCompressSettings는 이번에 수정된 기능이 아니다.
WS 4.0 작업 과정에서 해당 기능에 대한 설명이 존재하지 않아
기존 기능의 공통코드 기반 표현·호출 방식과 데이터 처리 규칙을 추가로 기록한다.

WS 3.0 → WS 4.0 업그레이드 과정에서 누락된 imageCompressSettings 설정 기능은
기존 공통코드 처리 흐름에 연결하는 것을 기준으로 한다.

이 기능은 특정 UI 이름이나 프로퍼티 이름을 조건문으로 검사하여
별도로 버튼을 만들고 모듈을 호출하는 방식으로 구현하지 않는다.

속성 표현은 공통코드 UW11을 따르고,
버튼 선택 시 모듈 호출은 공통코드 UW13을 따른다.

아래 내용은 이식 시 확인하고 보존할 기준이며,
WS 4.0의 실제 연결 상태나 이식 완료를 의미하지 않는다.

### 7.2. UW11과 UW13의 역할

| 공통코드 | 역할 |
| --- | --- |
| UW11 | Attribute 영역에서 해당 속성을 버튼으로 표현하는 기준 |
| UW13 | 해당 버튼을 선택했을 때 호출할 모듈을 결정하는 기준 |

전체 흐름:

대상 UI의 속성 정보 조회
→ UW11에 정의된 기준으로 속성 편집 UI 구성
→ 버튼으로 표현된 속성을 사용자가 선택
→ UW13에서 해당 속성에 대응하는 모듈 설정 확인
→ 공통 모듈 호출 절차에 따라 설정된 모듈 실행
→ 선택한 속성의 설정값 조회·편집·적용

imageCompressSettings는 이 공통 처리 흐름을 사용하는 속성 중 하나다.

### 7.3. 제공된 UW13 설정 정보

아래 표는 사용자가 제공한 UW13 설정 정보다.
구현 코드에 고정해서 넣을 호출 조건이나 별도 매핑 테이블이 아니다.

| UIATK | UIATT | UIFND | module path1 | module function name |
| --- | --- | --- | --- | --- |
| AT000043275 | imageCompressSettings | SAP.UI.UNIFIED.FILEUPLOADER | ./imageCompress.js | imageCompress |
| AT000043276 | imageCompressSettings | SAP.UI.COMMONS.FILEUPLOADER | ./imageCompress.js | imageCompress |
| AT000043277 | imageCompressSettings | SAP.M.UPLOADCOLLECTION | ./imageCompress.js | imageCompress |

공통코드 조회 조건, 모듈 경로 해석, 함수명 처리 방식은
기존 UW13 호출 구현을 확인하여 같은 계약을 따른다.

특히 UW13의 module function name 값만 보고
ES module의 named export를 직접 호출한다고 가정하지 않는다.

제공된 WS 3.0 소스 확인 내용에 따르면 imageCompress.js의 진입점은
default export이므로, 기존 공통 호출부에서 이 정보를 어떻게 사용하는지 확인해야 한다.

### 7.4. 폐기된 UI에 관한 해석

UW11과 UW13에는 SAP.UI.COMMONS.FILEUPLOADER 설정도 존재하지만,
사용자 설명에 따르면 해당 UI는 폐기되어 사용할 수 없다.

이 사실은 다음 작업을 요구하는 것이 아니다.

- imageCompressSettings 호출부에 해당 UI의 제외 조건 추가
- 특정 UI 이름을 이용한 허용 목록 작성
- 공통코드에서 해당 행 삭제
- 폐기 UI의 신규 지원 또는 사용 가능 상태 복구

폐기 UI의 사용 가능 여부는 기존 UI 제공 정책에 맡긴다.
이번 이식에서는 UW11·UW13에 따른 공통 처리 흐름을 보존한다.

현재 사용할 수 있는 SAP.UI.UNIFIED.FILEUPLOADER와
SAP.M.UPLOADCOLLECTION은 기능 확인 대상이며,
공통 호출 로직의 하드코딩 조건이 아니다.

### 7.5. WS 4.0에서 확인하고 연결할 부분

1. UW11 정보가 WS 4.0의 Attribute 영역 구성에 반영되는지 확인한다.
2. UW11의 버튼 표현 기준에 따라 imageCompressSettings가 표시되는지 확인한다.
3. 해당 버튼의 공통 선택 이벤트가 UW13 조회 경로로 연결되는지 확인한다.
4. UW13에서 결정된 모듈을 로드하고 실행하는 기존 절차를 확인한다.
5. imageCompress 설정 모듈이나 연결 경로 중 누락된 부분만 보완한다.
6. 선택한 속성의 정보가 모듈에 전달되고, 적용 결과가 같은 속성에 반영되는지 확인한다.

UW11·UW13의 실제 필드 매핑과 조회 조건은 기존 소스로 확인한다.
이 문서에 없는 필드명이나 호출 규약을 임의로 만들지 않는다.

### 7.6. 호출되는 imageCompress 모듈의 책임

WS 3.0 기준 원본:

- 파일: /www/ws30/ws10_20/design/attributesArea/imageCompress.js

모듈은 다음 기능을 담당한다.

- 전달받은 속성값에서 설정 읽기
- 압축 사용 여부와 품질 편집 UI 제공
- 입력값 검증
- 설정값 저장
- 속성 변경 후처리 연결

설정 항목:

| 항목 | 형식 | 기본값 | 허용값 |
| --- | --- | --- | --- |
| enabled | Boolean | false | true 또는 false |
| quality | Number | 0.5 | 0.01 이상 1 이하 |

보존할 데이터 규칙:

- WS 3.0은 sAttr.UIATV에 JSON 문자열로 설정을 저장한다.
- 빈 속성값이면 기본 설정으로 시작한다.
- 누락된 설정 항목이 undefined이면 기본값을 보충한다.
- 현재 정의된 설정 항목이 모두 기본값이면 빈 문자열로 저장한다.
- 기본값과 다른 설정이 있으면 JSON 문자열로 저장한다.
- quality는 검증 후 숫자로 저장한다.
- enabled=false여도 quality를 초기화하지 않는다.
- enabled=false여도 적용 시 quality 검증은 수행한다.
- 취소하면 기존 속성값을 유지한다.
- 조회 모드에서는 설정을 변경하거나 적용할 수 없어야 한다.

설정 예:

압축 사용, 품질 0.8:
{"enabled":true,"quality":0.8}

압축 해제, 품질 0.8 유지:
{"enabled":false,"quality":0.8}

이 모듈은 설정 편집 기능이다.
실제 이미지 압축 및 업로드 구현과는 책임을 구분한다.

### 7.7. 구현 시 금지할 접근

- UI 이름이 FileUploader 또는 UploadCollection이면 무조건 버튼 생성
- 속성명이 imageCompressSettings이면 UW11과 무관하게 버튼 생성
- 버튼 선택 시 UW13을 거치지 않고 imageCompress.js 직접 지정
- UW13의 설정 내용을 공통 코드 내부의 고정 매핑으로 복제
- SAP.UI.COMMONS.FILEUPLOADER를 위한 별도 제외 분기 추가
- 기능 복구를 이유로 무관한 속성 편집 로직까지 변경

UW11·UW13 처리 기능이 이미 존재한다면 이를 재사용한다.
공통 처리부 수정이 필요할 때만 관련 호출처와 영향 범위를 확인하고,
다른 공통코드 기반 속성 버튼의 기존 동작을 보존한다.

### 7.8. 이식 완료 검증 기준

아래 항목은 이식 작업 시 확인할 기준이며, 검증 완료 결과가 아니다.

- UW11 기준으로 속성이 버튼 형태로 표현된다.
- 버튼 선택 시 UW13에 정의된 모듈이 실행된다.
- 특정 UI 이름이나 속성 키를 새로 하드코딩하지 않는다.
- 선택한 UI와 속성의 설정값이 정확하게 전달된다.
- 기본값, 기존값 조회, 검증, 적용, 취소, 조회 모드가 유지된다.
- 저장 후 다시 열어도 설정값이 유지된다.
- 기존 공통코드 기반의 다른 속성 버튼이 정상 동작한다.
- 폐기 UI의 사용 정책이나 공통코드 데이터를 임의로 변경하지 않는다.
- 설정 팝업 검증과 실제 압축·업로드 검증 결과를 구분한다.

### 7.9. 근거 구분

- UW11의 버튼 표현 역할: 사용자 제공 설명
- UW13의 호출 기준과 등록 내용: 사용자 제공 설명 및 설정 표
- 폐기 UI의 사용 가능 여부: 사용자 제공 설명
- imageCompress 모듈의 진입점과 설정·검증·저장 규칙:
  사용자가 제공한 WS 3.0 소스 확인 정리
- WS 4.0의 실제 누락 위치와 공통 호출 구현: 이식 작업 시 확인 필요

이번 문서 통합에서는 제공된 설명을 추가했으며,
imageCompress 모듈 소스나 UW11·UW13의 실제 등록 데이터를 재검증하지 않았다.
