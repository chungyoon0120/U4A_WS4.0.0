### D04 — sap.ui.table.Table / TreeTable 의 columns 에 Drop 시 template 기준 판정

> **원본 문서 근거** — `WS 3.0 변경사항.md` › 2. design › [Aggregation 및 Drag & Drop]
> "**sap.ui.table.Table의 column Aggregation에 UI를 Drop할 때 template Aggregation을 기준으로 N건 바인딩 여부를 판단하도록 변경**"
>
> 고친 파일: `js/ws_html5_ws20_dnd.js` 1419~1428행(끌어온 쪽 경로 계산 뒤 · 놓는 쪽 경로 계산 앞).
> 원본 근거: `U4A_WS_DESIGN\design\js\uiDesignArea.js` 3438행.
> 무엇이 달라지나 — Table/TreeTable 의 `columns` 로 UI를 옮길 때, 놓는 쪽 N건 바인딩 판정을 `template` aggregation 기준으로 한다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| D04-T1 | 같은 Table 의 columns 안에서 Column 을 옮기면 바인딩이 유지된다 | ① WS20 디자인 화면에서 `sap.ui.table.Table` 을 넣고 `rows` 에 N건 바인딩을 건다 ② Column 을 2개 이상 만들고 각 Column 의 `template` 에 UI(예: Text)를 넣어 속성 바인딩을 건다 ③ UI 트리에서 Column 하나를 같은 Table 의 `columns` 안 다른 위치로 끌어다 놓는다 ④ 옮긴 Column 안 UI의 **바인딩이 그대로 남아 있는지** 확인 |✅ O |
| D04-T2 | 다른 Table 의 columns 로 옮기면 바인딩이 풀린다 | ① `sap.ui.table.Table` 을 하나 더 넣고 **다른 경로**로 N건 바인딩을 건다 ② 첫 Table 의 Column 을 두 번째 Table 의 `columns` 로 끌어다 놓는다 ③ 옮긴 Column 안 UI의 **바인딩이 풀렸는지** 확인 |✅ O |
| D04-T3 | TreeTable 에서도 같다 | ① `sap.ui.table.TreeTable` 로 D04-T1 · D04-T2 를 같은 방법으로 해 본다 |✅ O |
| D04-T4 | (회귀) Column 안 UI를 Table 밖으로 옮기면 바인딩이 풀린다 | ① Column 의 `template` 안 UI(예: Text)에 속성 바인딩이 걸린 상태를 만든다 ② 그 UI를 Table 밖 다른 부모(예: Panel)로 끌어다 놓는다 ③ 옮긴 UI를 클릭해 속성 목록에서 **바인딩이 풀려 있는지** 확인 |✅ O |
| D04-T5 | (회귀) Table 과 무관한 UI 이동은 아무 영향 없다 | ① 바인딩이 없는 일반 UI(예: Button)를 다른 부모로 끌어다 놓는다 ② 정상적으로 옮겨지고 오류 안내가 안 뜨는지 확인 ③ 옮긴 UI의 속성이 그대로인지 확인 |✅ O |

### D25 — 오브젝트 삽입 팝업: 검색어를 지우면 정렬·컬럼 필터까지 초기화 ✅ 전 항목 통과 (2026-09-01)

> **원본 문서 근거** — `WS 3.0 변경사항.md` › 2. design › [Insert UI Popup]
> "**검색어를 Clear Icon으로 초기화하면 결과 목록 필터도 해제되도록 변경**"
>
> 고친 파일: `js/ws_html5_ws20_edit.js` 2184행 부근(검색 input 처리).
> 원본 근거: `U4A_WS_DESIGN\design\insertUIPopop\index.js` 608행 + 본체 `design\js\main.js` 1841행.
> 무엇이 달라지나 — 검색어가 **빈 값이 되는 순간** 결과 목록의 정렬과 컬럼 필터가 모두 풀린다.
> ★원본 조건은 지우기(X) 아이콘만이 아니라 **백스페이스로 다 지운 경우도 포함**이다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| D25-T1 | 지우기(X)로 검색어를 비우면 정렬·컬럼 필터가 풀린다 | ① UI 트리에서 UI 하나를 우클릭 → **오브젝트 삽입** ② 결과 목록의 컬럼 머리를 눌러 **정렬**을 걸고, 다른 컬럼에 **필터**도 건다 ③ 검색칸에 글자를 넣어 목록을 좁힌다 ④ 검색칸 오른쪽 **지우기(X)** 를 누른다 ⑤ 정렬 표시와 필터 표시가 **모두 풀리고** 목록이 처음 상태로 돌아오는지 확인 |✅ O |
| D25-T2 | 백스페이스로 다 지워도 같다 | ① 같은 팝업에서 정렬·필터를 걸고 검색어를 넣는다 ② 백스페이스로 검색어를 **한 글자씩 다 지운다** ③ 다 지워지는 순간 정렬·필터가 풀리는지 확인 |✅ O |
| D25-T3 | 검색어가 남아 있는 동안에는 정렬·필터가 유지된다 | ① 정렬·필터를 건 뒤 검색어를 넣는다 ② 검색어를 **일부만** 지운다(빈칸 아님) ③ 정렬·필터가 **그대로 유지**되는지 확인 |✅ O |
| D25-T4 | (회귀) 검색 자체는 평소대로 된다 | ① 검색칸에 UI 이름 일부를 넣는다 ② 결과 목록이 그 이름으로 걸러지는지 확인 ③ 목록에서 UI를 하나 골라 **확인**으로 추가되는지 확인 |✅ O |
| D25-T5 | (회귀) aggregation 을 바꿀 때 초기화는 전과 같다 | ① 팝업 위쪽 **Aggregation Name** 을 다른 값으로 바꾼다 ② 정렬·필터가 풀리고 목록이 새로 그려지는지 확인 |✅ O |
