# 한 장 요약 — 지금 상황 (2026-08-31 기준)

## 1. 무슨 일이 있었나
- 원작 개발자가 **2026-08-16 원본을 갱신**하고 변경 내용 문서를 줬다(`WS 3.0 변경사항.md`).
- 그 문서를 **35줄로 쪼개** 원본 코드 어디가 바뀌었는지 전수 확인했다.
- 우리 화면(HTML5)에 어떻게 옮길지 계획을 짜고, **다른 눈으로 8번 교차검증**했다.
- **코드는 아직 한 줄도 안 고쳤다.** 지금은 "무엇을 어떻게 옮길지" 확정 단계.

## 2. 결론 숫자

## 3. 검증하며 잡아낸 큰 함정 5가지
1. **"넣을 수 있는 자리 따지기"를 바꾸면서 그 답을 쓰는 세 화면을 같이 안 고치면 화면이 그 자리에서 멈춘다.**
   - UI를 다른 UI 위에 끌어다 놓을 때 "어느 자리에 넣을 수 있나"를 따져 주는 공통 처리(원작 개발자 것)를 이번에 통째로 새로 썼다.
   - 예전 = **자리 목록만** 돌려줌 → 이제 = **되나 안 되나 + 안 되는 이유 안내문 + 자리 목록** 세 가지를 한 번에 돌려줌.
   - 그 답을 쓰는 화면이 3곳: ①끌어다 놓을 때 뜨는 "어느 자리에 넣을까요" 고르기 ②화면 만들기 마법사 ③AI로 화면 만들기.
   - 셋 다 지금은 "목록이 비었나?"만 보므로, 같이 안 고치면 바로 다음 줄에서 오류가 나 화면이 멈춘다.
2. **우클릭 안내문은 고쳐도 화면에 안 나온다** — 미리보기를 켜는 순간 원본이 우리 처리를 덮어쓴다.
3. **줄 위치를 하나만 틀리면 멀쩡한 바인딩이 지워진다**(표 열 자리 판정).
4. **미리보기 화면 파일에 우리 수정 6곳**이 있고 그중 2건은 "오류 삼키지 말 것" 지시 → 통째 교체하면 원복된다.
5. **원본끼리도 안 맞는 게 있다** — 예제 별도 창, 화면 마법사 차단 두 가지는 지금 원본에서도 동작하지 않는다.

## 6. 원작 개발자께 요청할 것 4가지
1. 예제를 별도 창으로 여는 함수가 새 지정값을 받도록 수정(지금은 통째로 무시됨).
2. **UI 추가 팝업 새 폴더를 통째로 전달** — 안 오면 그 팝업이 아예 안 열린다.
3. 빠른 검색 기능을 켤지 여부(지금은 부르는 데가 한 곳도 없어 동작 안 함).
4. 화면 마법사 차단이 죽어 있는 것 확인.
