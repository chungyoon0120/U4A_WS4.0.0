## T01 — 끌어놓기로 바인딩+자식 있는 집계에 자식 추가 시 안내 복원 (2026-08-21 통과)

> ★장군님 특별지시. UI 추가 팝업 목록의 UI를 **트리 줄로 끌어놓을 때**, 그 자리가 **바인딩(값 지정)됐고 이미 자식이 1개 있으면** 종전엔 아무 안내 없이(또는 엉뚱한 "이동 가능한 aggregation 없음") 조용히 안 들어갔다.
>
> **원인:** 넣을 자리 후보를 고르는 검사가 옛 판이라 그 자리를 **조용히 후보에서 빼버려**, 안내를 내는 개수 점검까지 가지도 못했다.
> **수정:** 원본 최신은 그 검사를 다시 만들어 **왜 후보가 없는지(바인딩 때문/자리 자체 없음/집계 없음)를 안내 문구와 함께 돌려주도록** 바뀌어 있어 그대로 이식(`ws_html5_ws20_dnd.js` 후보 검사·자리 고르기, `ws_html5_ws20_wizard.js` 사전점검). 팝업 확인 버튼은 집계 이름이 들어간 문구, 끌어놓기는 이름 없는 문구 — 원본 설계 그대로.
> **검수:** `.audit/t01/` 코덱스·안티 둘 다 수정필요 → 03 에서 반영 2(옛 AI 생성 모듈의 옛 방식 호환, 데이터 미로드 방어가드)·반론 3(원본 부재 주장=저장소 밖 SSOT에 실재 / 꽉 찬 한 개짜리 자리 노출=최신 원본이 의도적으로 제외 삭제 / 문구 폴백=소비부에 이미 있음).

## A — 미리보기 임시 자식 정리(destroyExcepChild) 원본 대비 누락 복원 (2026-08-18 통과)

**무엇을 고쳤나**: "자식이 꼭 있어야 하는 UI"는 자식이 없을 때 미리보기에 임시 자식을 그려 준다. 원본은 그 자리에 **진짜 자식을 넣으면 임시 자식을 지우는데**, UI 추가 팝업 경로에 그 지우는 동작이 빠져 있어 **임시 자식이 유령으로 남았다**(원본 대비 누락 감사에서 발견).

- 발견: BR45 계기 "원본 대비 누락 없으리란 보장 없다"는 지시로 UI 추가 팝업 경로 전체를 원본과 라인 대조 → 임시 자식 지우는 동작 누락 1건 확인.
- 실증(살아있는 앱, 디버그): BreadCrumbs(`sap.uxap.BreadCrumbs`)에 진짜 링크 넣은 뒤 링크 자리 = **2개**(진짜 + 고유 ID 없는 유령), 화면엔 화살표 2개.
- 이식: `ws_html5_ws20_edit.js` 에 `oAPP.fn.destroyExcepChild` 정의(원본 `uiDesignArea.js`:5167 1:1, 존재·미리보기 부재 가드) + 삽입 루프 종료 후 재렌더 직전 호출(원본 5647 순서). node --check 통과.
- 검증(재시작 후 디버그 실측): 같은 조작 → 링크 **1개**(진짜만), 유령 사라짐. A1 통과.
- 남은 후속(미착수): B(안내 문구 옛 버전) · C(넣는 위치 계산) · D(미세 조작감) — `.works/UI추가팝업/01_원본대비_누락감사.md`.

## DROP-BUSY — 팝업 목록 UI를 트리에 끌어 놓아 "넣을 수 없음"이 나올 때 화면 잠금이 안 풀리던 문제 (2026-08-18 통과)

**증상(장군님 발견)**: UI Object Select 팝업 목록의 FlexItemData를, 이미 layoutData 자리가 꽉 찬 FlexItemData 줄 위로
끌어다 놓으면 안내 토스트는 뜨는데 **화면 로딩 표시(스피너)가 안 꺼지고 남았다**.

**원인**: 트리에 끌어 놓으면 화면 잠금·단축키 잠금을 켜는데, 넣을 자리 후보가 1개라 자동 선택되는 경로의 마무리에서
**다른 창 방송 잠금만 풀고 화면 잠금·단축키 잠금을 안 풀어** 스피너가 남았다(자리 꽉 참으로 내부 검사가 조기 취소될 때 노출).
원본은 모든 조기취소 분기에서 세 잠금(방송·화면·단축키)을 다 풀었음 → 그대로 복원(마무리를 3종 해제로 통일).

- 파일: `ws_html5_ws20_dnd.js`(끌어놓기 추가 마무리 `lf_setChild`를 3종 해제 공통함수로). 백업 `_ws_html5_ws20_dnd.js.busyleakbak`.

## BR37 — 집계 이름과 무관하게 Generated Cnt 가 계속 보이던 문제 (2026-08-16 통과, 노션=수정완료)

**무엇을 고쳤나(쉽게)**: UI 추가 팝업에서 **Aggregation Name** 을 여러 개 넣을 수 있는 집계(예: content)로 골랐을 때만
그 아래 **Generated Cnt**(넣을 개수) 줄이 보여야 하는데, 집계를 안 골랐거나 공백/한 개짜리(예: customHeader)를
골라도 **계속 보였다**. 표시를 켜고 끄는 판단 자체는 이미 원본과 같았으나, 그 줄을 **가로로 나란히 배치하는 화면 규칙이
"숨김" 지정을 이겨** 항상 보이던 것이 원인. 화면 CSS에 **"숨김 지정된 줄은 실제로 숨긴다" 한 줄**을 덧대 원본 의도를 복원했다.

- 파일: `WS10/css/ws20.css` (`.u4aWs20InsRow[hidden] { display: none; }` 1줄). 백업 `_ws20.css.br37bak`.
- 표시 판단 로직(`ws_html5_ws20_edit.js`)은 원본 1:1이라 무수정.
- 검수: `.audit/br37/` 코덱스·안티 둘 다 통과·지적 0.
