# UI 추가 팝업 — 원본(as-is) 대비 누락 전수 감사 (2026-08-14, 2차 확정)

> 서브에이전트 1차 3기 + 2차 심층 4기(반증 포함)로 원본 UI5 vs HTML5 이식본 전 구간 대조. **수정 안 함, 보고만.**
> 대상 원본: `insertUIPopop.js`(팝업 본체) + `uiDesignArea.js` `designAddUIObject`(5009~5467)·`designUIAdd`(6570) + 드롭경로.
> 대상 이식: `ws_html5_ws20_edit.js`(`_showInsertPopup`·`designAddUIObject`·카탈로그) / 검사함수 `ws_html5_ws20_dnd.js` / 드롭 `dnd.js`.
> 2차에서 1차 지적 전부 라인 근거로 **CONFIRMED**(반박 0). 검사 함수 6종 본문은 원본과 1:1(필드·플래그·반환값·메시지키 일치) — 조용한 오이식 없음.
> 문제는 전부 "원본에 있는 단계가 팝업 확정/드롭 경로에서 빠졌거나 시점이 다름". BR14·BR35와 같은 계열.

## C. 동작이 원본과 다름(결함 아닐 수 있음 — 되돌릴지 장군님 판단)

- **검색칸 Enter**: 원본=검색어로 거르기 / 이식=**바로 추가(확정)**. → 줄 골라둔 채 Enter 치면 **의도치 않은 추가** 위험(이건 되돌림 권장).
- 검색 방식(이식=타이핑 실시간·UI명+라이브러리명 / 원본=Enter 제출·UI명만), 결과 정렬순서(이식=이름순 / 원본=목록순), 컬럼 거르기(이식=여러 개 동시 / 원본=하나만), ESC 닫을 때 취소 안내 뜸, 방향키로 줄 이동(이식=불가). → 상당수는 이식본이 더 편의적. 원본대로 되돌릴지는 지시 필요.
- 확인 버튼: 원본=항상 눌리고 미선택 시 "선택된 라인 없음" 안내 / 이식=선택 전 비활성(결과 동일, 방식만 다름).

## 결론·다음
- **원본 로직 누락으로 데이터/기능이 달라지는 진짜 결함 = A의 1·2·3·4.** 핵심은 **A-1·A-2**(둘 다 확정 함수에 원본 검증·제한 복원으로 해결).
- **검사 함수 본문은 건전**(6/6 1:1). 잠금 새는 곳 없음.
- 규칙대로 **수정은 지시 시**. 권장: A-1·A-2·A-3·A-4를 **버그 등록 후 순차 수정**(A-1·A-2는 원본 `designAddUIObject` 검증체인 복원 한 건으로 묶임), C의 Enter는 별도 판단.
- 유지보수 참고: 같은 검사 함수가 edit.js 사본과 원본 exceptionUI.js 두 곳에 존재(동작 동일).
