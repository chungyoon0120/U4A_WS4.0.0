# WS20 디자인 트리 — 깊이가 깊어지면 [+][삭제] 가 같이 밀리는 현상 (분석만)

> 조사 2026-10-06 14:5x · 장군님 지시 「분석부터 해봐, 고치라는 말은 아니다」
> **소스만 읽었다. 앱은 실행하지 않았고 코드도 고치지 않았다.**

## 0. 한 줄 결론

**[+][삭제] 가 「행 안의 내용물」로 들어가 있어서다.** 들여쓰기를 **행 전체의 왼쪽 여백**으로 주기 때문에,
여백이 커지면 그 안에 든 버튼까지 같이 오른쪽으로 밀린다.
원본(as-is)은 **별도 컬럼(폭 60px 고정)** 이라 깊이와 무관하게 안 움직인다. 장군님 말씀이 맞다.

## 1. 원본(as-is)은 어떻게 돼 있나 — 확인함

원본 = `sap.ui.table.TreeTable`, 컬럼 **2개**다. (`U4A_WS_DESIGN` 의 디자인 영역 소스, 203·253행)

| 컬럼 | 들어 있는 것 | 폭 |
|---|---|---|
| 1 (트리 컬럼) | 체크박스 · UI 아이콘 · UI 이름 · 부모 aggregation 표시 | 가변(autoResizable) |
| 2 | **[+] 추가 · [삭제]** (편집 모드일 때만 보임) | **60px 고정** |

- 트리가 들여쓰기하는 것은 **1번 컬럼 안**뿐이다. 2번 컬럼은 표의 컬럼이므로 **깊이와 아무 상관이 없다.**
- 즉 원본에서 「고정」은 별도 장치가 아니라 **표 구조 그 자체**였다.

## 2. 지금 HTML5 는 어떻게 돼 있나 — 확인함

컬럼이 없다. **행 하나짜리 flex** 로 만들고, 그 안에 왼쪽부터 오른쪽까지 다 넣었다.

| 무엇 | 어디 | 내용 |
|---|---|---|
| 들여쓰기 | 공통 트리 CSS | 행 전체에 `padding-left: 0.375rem + 깊이 × 1rem` |
| [+][삭제] | WS20 트리 JS 의 trailing 슬롯 | **행의 내용물**로 들어간다 |
| 「고정」 장치 | WS20 트리 CSS | `position: sticky; right: 0.5rem` — 2026-07-10 에 **바로 이 증상** 때문에 넣은 보완책 |
| 가로 스크롤 | 트리 스크롤 영역 | `overflow-x: hidden` (가로 스크롤 없음 = 넘치면 그냥 잘림) |

## 3. 왜 보완책(sticky)이 끝까지 못 버티나

행 안에서 **더 이상 줄어들 수 없는 것들**의 폭 합계가 있다.

| 줄어드는 것 | 줄어들지 않는 것 |
|---|---|
| UI 이름(0까지 줄고 … 로 잘림) · aggregation 표시 | 토글 20px · 체크박스 · UI 아이콘 · **[+][삭제] 52px** · 항목 간격 |

- 들여쓰기(`깊이 × 16px`)가 커질수록 **행이 쓸 수 있는 폭이 그만큼 줄어든다.**
- 줄어들 것이 다 줄어든 뒤에도 모자라면 내용이 행 밖(오른쪽)으로 넘친다.
- `sticky` 는 **자기 자리(행의 안쪽 영역) 안에서만** 되돌릴 수 있다. 들여쓰기가 그 안쪽 영역을
  거의 다 먹어버리면 되돌릴 여지가 없어져 그대로 밀리고, 가로 스크롤이 없으니 **잘려서 사라진다.**
- 캡처에서 아래쪽 깊은 줄만 `+` 가 오른쪽으로 가고 삭제 버튼이 안 보이는 것이 이 모양이다.
- **「몇 번째 깊이부터 깨지나」는 알아도 쓸 데가 없다**(2026-10-06 장군님 지적). 패널 폭·이름 길이에
  따라 달라지고, 더 깊은 구조가 나오면 또 깨진다. **특정 깊이가 문제가 아니라 「깊이에 비례해
  공간을 뺏는 구조」가 문제다.** 그래서 깊이 실측은 하지 않는다.

## 4. 이미 프로젝트 안에 있는 「제대로 된 구조」

공통 컴포넌트에 **컬럼 트리**(여러 컬럼 + 우측 고정)가 이미 있다. 바인딩 팝업 등에서 쓴다.

| 차이 | 지금 WS20 트리 | 공통 컬럼 트리 |
|---|---|---|
| 들여쓰기를 주는 곳 | **행 전체**의 왼쪽 여백 | **토글(펼침 화살표)** 에만 |
| 오른쪽 영역 | 행의 내용물 + sticky 보완 | **폭이 정해진 별도 칸** |
| 깊이 영향 | 받는다 | **안 받는다** |

→ 원본의 「컬럼 2개」와 구조가 같다.

## 5. 고친다면 — 구조를 바꾸는 것 하나뿐 (아직 아무것도 안 함)

**조건: 깊이가 얼마든 액션 자리가 안 움직여야 한다.** 들여쓰기가 액션 자리를 건드릴 수 없는
구조여야 그 조건이 성립한다. 깊이 상한을 두거나 여백을 줄이는 식의 임시방편은 **같은 문제가
더 깊은 구조에서 또 터지므로 선택지에서 뺀다**(2026-10-06 장군님 지적).

| 방법 | 내용 | 깊이 무관? |
|---|---|---|
| **공통 컬럼 트리로 교체** | 이름 칸(여기서만 들여쓰기) + 액션 칸(폭 고정). 원본 TreeTable 과 같은 구조 | **된다** (구조상 불가능해짐) |
| ~~들여쓰기 최대값~~ | ~~깊이가 깊어도 일정 이상 안 밀리게~~ | ❌ 증상만 가림 — **뺌** |
| ~~sticky 보완 강화~~ | ~~지금 방식을 더 손봄~~ | ❌ 여전히 남는 폭에 의존 — **뺌** |

### 손댈 범위 — 실제로 세어 보니 2곳 (2026-10-06 확인)

처음에 「붙은 기능이 많아 범위가 크다」고 적었는데, **세어 보니 그렇지 않다.** 트리를 통째로
갈아끼울 필요가 없다. 공통 컬럼 트리가 쓰는 방법이 **행을 만든 뒤 토글·체크박스·아이콘·이름을
「이름 칸」 하나로 묶는 것**인데, WS20 트리에도 그 처리를 하는 자리(행 후처리 함수)가 이미 있다.

| # | 어디 | 무엇 |
|---|---|---|
| 1 | WS20 트리 JS — 행 후처리 함수 | 토글 · 체크박스 · UI 아이콘 · 이름을 **「이름 칸」 하나로 묶는다**(공통 컬럼 트리와 같은 방식, 몇 줄) |
| 2 | WS20 트리 CSS | 들여쓰기를 **행 여백 → 토글**로 옮기고, 이름 칸에 「남는 폭 다 쓰고 넘치면 … 로 자름」 규칙. 지금의 sticky 보완책은 필요 없어진다 |

- **공통 자산(공통 트리 CSS·JS)은 안 건드린다.** WS20 안에서만 끝난다.
- 검색 하이라이트 · 드래그&드롭 · 우클릭 메뉴 · 가상 스크롤 · 체크박스 연동 · 펼침맵은
  **행 자체와 노드 데이터로만 동작**한다 — 행 안쪽 자식 순서를 뒤지는 코드가 **0건**이다
  (WS20 트리 · 드래그&드롭 · 우클릭 메뉴 파일 전부 확인). 그래서 묶어도 깨지지 않는다.
