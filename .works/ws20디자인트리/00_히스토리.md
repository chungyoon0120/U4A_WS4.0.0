# 히스토리 — WS20 디자인 트리

## TC 그룹 — [+][삭제] 를 트리 깊이와 무관하게 고정 (2026-10-06 전 항목 통과)

| 코드 | 동작 | 조작·확인 포인트 | O/X |
|---|---|---|---|
| TC1 | ★깊이가 깊어도 [+][삭제] 가 안 움직인다 | ① WS20 편집화면을 연다 ② 왼쪽 UI 트리에서 **가장 깊은 가지까지 전부 펼친다** ③ 맨 윗줄의 **+ 버튼**과 **휴지통 버튼**이 있는 가로 위치를, 가장 깊은 줄의 같은 버튼 위치와 **눈으로 맞춰 본다** ④ 깊이가 달라도 **같은 세로선 위**에 있으면 통과 | ✅ O |
| TC2 | ★패널을 좁혀도 안 움직인다 | ① 트리와 가운데 미리보기 사이의 **세로 분할선을 왼쪽으로 끌어** 트리를 좁힌다 ② 깊은 줄의 [+][삭제] 가 **잘리거나 사라지지 않는지** 본다 ③ 이름만 잘려서 보이면 통과 | ✅ O |
| TC3 | 들여쓰기가 그대로 보인다 | ① 트리를 펼친 상태에서 ② 자식 줄이 부모 줄보다 **오른쪽으로 들여써져 보이는지** 본다 ③ 깊이가 한눈에 구분되면 통과 | ✅ O |
| TC4 | 체크박스·아이콘·이름 자리 | ① 편집 모드에서 체크박스가 보이는 줄을 본다 ② **체크박스 → UI 아이콘 → 이름** 순서로 붙어 있고 들여쓰기를 따라가는지 ③ 이름이 길면 **… 로 잘리는지** 본다 | ✅ O |
| TC5 | 버튼이 그대로 동작한다 | ① 아무 줄의 **+ 버튼**을 누른다 → UI 추가 팝업이 뜨는지 ② 닫고 **휴지통 버튼**을 누른다 → 삭제 확인이 뜨는지 ③ 줄을 클릭하면 선택(파란 줄)이 되는지 | ✅ O |
| TC6 | 드래그&드롭·우클릭이 그대로다 | ① 줄 하나를 끌어 다른 줄 위로 옮겨 본다(드롭 표시가 보이는지) ② 줄에서 **마우스 오른쪽 버튼**을 눌러 메뉴가 뜨는지 | ✅ O |
| TC7 | 찾기 표시가 그대로다 | ① 트리 위 **돋보기**로 UI 이름을 찾는다 ② 찾은 줄에 **노란 표시**가 그대로 보이는지 | ✅ O |
| TC8 | 세로 구분선 위치 | ① [+][삭제] 왼쪽에 있는 **세로 구분선**을 본다 ② 그 선이 버튼 칸 경계에 맞게 **한 줄로 쭉 이어지는지** 본다(어긋나면 ❌ 로 적어 주신다) | ✅ O |

> 지시 = 장군님 2026-10-06. 「트리 깊이가 길면 우측 추가·삭제 버튼이 같이 이동한다.
> 여기는 깊이에 상관없이 무조건 고정이어야 하는 영역이다.」
>
> **원인** — 공통 트리는 들여쓰기를 「행 전체의 왼쪽 여백」으로 준다. 깊어질수록 행이 쓸 수 있는
> 폭이 줄고, 더 줄일 것이 없으면 우측 액션까지 행 밖으로 밀려 잘렸다(가로 스크롤 없음).
> 2026-07-10 에 넣었던 「오른쪽 고정」 보완책은 남는 폭이 있을 때까지만 버틴다.
>
> **원본(as-is)** — `sap.ui.table.TreeTable` 컬럼 2개. [트리 컬럼][액션 컬럼 width 60px] 이라
> 들여쓰기는 트리 컬럼 안에서만 일어나고 액션 컬럼은 깊이와 무관했다.
> (`U4A_WS_DESIGN` 의 `design/js/uiDesignArea.js` 203 · 253행)
>
> **고친 방법** — 공통 컬럼 트리가 쓰는 것과 같은 방식.
> - WS20 트리 JS : 행을 만든 뒤 [토글 + 체크박스 + UI 아이콘 + 이름] 을 「이름 칸」 하나로 묶는다.
>   토글·이름을 못 찾으면 묶지 않고 종전 모양 유지 + `GUARD_EXIT` 로그 1회(행마다 찍으면 로그 폭주).
> - WS20 트리 CSS : 들여쓰기를 행 왼쪽 여백 → **토글의 왼쪽 여백**으로 옮기고, 이름 칸이 남는 폭을
>   전부 가져가게 했다(넘치면 … 로 자름). 깊이는 이름 칸 안에서만 자리를 먹어 액션 칸 폭을 못 건드린다.
> - **공통 자산(공통 트리 JS·CSS)은 건드리지 않았다.** WS20 안에서만 끝냈다.
> - 깊이 상한을 두는 식의 임시방편은 더 깊은 구조에서 또 터지므로 선택지에서 뺐다(장군님 지적).
>
