# 개발표준 — 오류 처리 (전 프로젝트 공통)

> 장군님 지침 2026-07-30. UI5→HTML5 전환 및 신규/수정 코드 전반에 적용.
> 목적: 오류를 **조용히 삼키지 말고 표면화**해, 현장에서 코드만 캡처→SR→즉시 원인 특정.

---

## 1. 대원칙
- **필수(required)** 로직/의존성이 없거나 터지면 = **버그** → 삼키지 말고 **오류 코드를 담아 표면화**.
- **선택(optional)** = 없어도 정상인 것(부트 이전·미구현 기능·부가 DOM 효과)만 가드/`console.warn`.
- `try/catch` 는 **진짜 예외 복구·정리(cleanup)·외부(서버/파일/DOM) 실패 대응**에만. "혹시 몰라 감싸기" 금지.

## 2. 표면화 방법 (새 인프라 없음 — 기존 재사용)
각 창은 이미 **`ws_trycatch.js`**(= `WSERR(window,document,console)`)로 전역 감시 설치됨:
`window.onerror` + `unhandledrejection` → `console.error`(→electron-log 로그파일) + 네이티브 크리티컬 다이얼로그 → 닫으면 로그폴더 열고 `APP.exit()`.

**→ 필수 오류는 코드 담아 `throw` 하면 이 감시가 다 처리한다.**
```js
// ❌ 삼킴(금지)
if (typeof X === "function") { try { X(); } catch (e) { } }

// ✅ 표준: 필수면 코드 담아 던진다
if (typeof X !== "function") { throw new Error("[BWP-MF-001] X 미정의"); }
X();
```
### 화면 메시지 형태 (장군님 지침 2026-09-01)
- 사용자에게 보이는 문구는 **`[코드] 사용자 친화 문구`** 형태로 만든다.
  예) `[WSEV-003] 알 수 없는 오류가 발생하였습니다. 다시시도 하시거나, 문제가 지속될 경우 U4A 솔루션 팀에 문의 하세요.`
- 문구는 **기존 메시지 키만** 쓴다(임의 문구 생성 금지):
  `ZMSG_WS_COMMON_001` **314**(알 수 없는 오류가 발생하였습니다.) + **290**(다시시도 하시거나, 문제가 지속될 경우 U4A 솔루션 팀에 문의 하세요.)
- **예외 원문·스택은 화면에 노출하지 않는다** — 콘솔에만 남긴다(`[코드] 어느 자리인지 + 예외 원문`).
- 저장·실행처럼 **반드시 성공해야 하는 프로세스**는, 전송 前 구간에서 하나라도 터지면
  **서버로 보내지 않고 중단**한다(오류난 데이터를 저장하느니 저장을 안 한다).
  저장이 끝난 뒤 구간은 되돌릴 수 없으므로 코드만 드러낸다.

- 공통 헬퍼(선택): `raiseCritical(code, detail)` = `console.error("["+code+"] "+detail)` + `throw new Error("["+code+"] "+detail)`.
- 이미 명시 함수가 있는 창은 `showCriticalErrorDialog("[코드] …")` 를 직접 불러도 됨(메인 창 방식).

## 3. 오류 코드 체계 (A안 — 파일별 유일 접두 + 파일 내 로컬 번호)
- **형식**: `<접두>-<3자리>` 예) `BWP-MF-001`.
- **접두 = 파일(영역)마다 유일**하게 배정 → 다른 파일과 **절대 중복 안 됨**. 번호는 **그 파일 안에서만** 증가(그 파일 하나만 보면 됨).

## 4. 필수 vs 선택 판정 (판단 가이드)
- **필수**: 정상 흐름상 반드시 존재/성공해야 하는 함수·데이터·요소. 없으면 화면/기능이 깨짐. → 코드 throw.
- **선택**: 없어도 흐름이 정상. 예) 부가 애니메이션, 툴팁, 부트 이전 조기호출, 미구현 옵션 기능. → `console.warn` 또는 가드.
- 애매하면 **필수로 취급**(표면화가 삼킴보다 안전).

## 5. 적용 범위·순서 (한 번에 전수 X)
