## BR60 — 레이아웃 변경 팝업, 원본과 다르던 동작 4가지 복원 (전부 통과, 2026-08-21)

원인: 원본(UI5)과 다르게 변환된 4가지 — ① 타일 끌어 옮기기가 '맞바꿈'이 아니라 '밀어넣기'
② 닫기·취소로 닫을 때 취소 안내 없음 ③ 저장하는 동안 화면 잠금(로딩 표시) 없음 ④ 저장 중 단축키 잠금 없음.
수정: ①은 원본대로 끌던 타일과 놓인 타일의 자리를 서로 맞바꾸게 복원(가운데 타일은 그대로).
②는 우상단 X·하단 닫기·ESC 로 닫을 때 취소 안내를 띄우고, 저장으로 닫힐 때만 생략.
③④는 저장 확정 시 화면·단축키를 잠그고, 미리보기가 다시 다 뜬 뒤에 푼다.
검수(코덱스·안티) 지적 3건 반영: 잠금이 곧바로 풀리던 것·두 번 풀리던 것 제거, 차례를 안 바꾼 저장은
미리보기 쪽이 이미 가진 잠금 관리에 넘기고 단축키만 완료 신호를 받아 해제, 오류 삼킴 제거.
상세 = `.audit/br60/03_response.md`

> 코드반영은 **앱을 껐다 켜야** 보인다(새로고침 아님).
> 공통 진입: ① WS20 Design 화면에 들어간다. ② 화면 왼쪽 위 '레이아웃 변경' 버튼을 누른다.
> ③ 레이아웃 변경 팝업이 뜬다(디자인 트리·미리보기·속성 3개 타일이 가로로 놓임).

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR60-1 | 양 끝 타일을 끌면 **두 개만 자리 맞바뀜** | ① 팝업을 연다. ② 맨 왼쪽 타일을 맨 오른쪽 타일 위로 끌어다 놓는다. ③ 팝업 안 타일 차례가 **양 끝 두 개만 바뀌고 가운데 타일은 그대로**인지 본다. ④ 하단 '저장' 버튼을 누르고, 뜨는 확인 창에서 '예'를 누른다. ⑤ 화면 3분할 차례도 **양 끝만 맞바뀐** 모양인지 확인 | ✅ O |
| BR60-2 | 이웃 타일끼리 끌기도 정상 | ① 팝업을 연다. ② 맨 왼쪽 타일을 **바로 오른쪽 옆** 타일 위로 끌어다 놓는다. ③ 두 타일 자리가 서로 바뀌었는지 본다. ④ '저장 → 예'를 누르고 화면 3분할도 같은 차례인지 확인 | ✅ O |
| BR60-3 | 하단 '닫기' 버튼으로 닫으면 **취소 안내가 뜸** | ① 팝업을 연다. ② 타일 차례를 아무거나 바꾼다. ③ 하단 '닫기' 버튼을 누른다(★하단 '저장' 버튼과 다른 버튼). ④ 팝업이 닫히면서 **작업을 취소했다는 안내**가 뜨는지 확인. ⑤ 화면 3분할 차례는 **바뀌지 않고 그대로**인지 확인 | ✅ O |
| BR60-4 | 우상단 X 로 닫아도 취소 안내가 뜸 | ① 팝업을 연다. ② 팝업 **오른쪽 위 X 표시**를 누른다. ③ 취소했다는 안내가 뜨는지 확인 | ✅ O |
| BR60-5 | 키보드 ESC 로 닫아도 취소 안내가 뜸 | ① 팝업을 연다. ② 키보드 ESC 키를 누른다. ③ 취소했다는 안내가 뜨는지 확인 | ✅ O |
| BR60-6 | **저장**으로 닫힐 때는 취소 안내가 **안 떠야** 함 | ① 팝업을 연다. ② 타일 차례를 바꾼다. ③ 하단 '저장' 버튼을 누르고 확인 창에서 '예'를 누른다. ④ 팝업이 닫힌 뒤 **취소했다는 안내가 뜨지 않는지** 확인(저장 관련 안내만 정상) | ✅ O |
| BR60-7 | 저장 확인 창에서 '아니오'면 아무 일 없음 | ① 팝업을 연다. ② 타일 차례를 바꾼다. ③ 하단 '저장' 버튼을 누른다. ④ 뜨는 확인 창에서 '아니오'를 누른다. ⑤ 팝업이 그대로 열려 있고 화면이 잠기지 않고 정상 조작되는지 확인 | ✅ O |
| BR60-8 | 저장하는 동안 **화면이 잠김**(로딩 표시) | ① 팝업을 연다. ② 타일 차례를 바꾼다. ③ '저장 → 예'를 누른다. ④ 미리보기가 다시 뜨는 동안 **화면에 로딩 표시가 덮여 클릭이 안 먹는지** 확인. ⑤ 미리보기가 다 뜬 뒤에는 **로딩 표시가 사라지고** 정상 조작되는지 확인 | ✅ O |
| BR60-9 | 저장이 도는 동안 **단축키가 안 먹음**(+ 자물쇠 표시) | ① 팝업을 연다. ② 타일 차례를 바꾼다. ③ '저장 → 예'를 누른다. ④ 미리보기가 다시 뜨는 동안 **미리보기 제목 옆에 자물쇠 표시가 나타나는지** 본다(단축키 잠김 표시). ⑤ 그동안 되돌리기 단축키 **Ctrl+Shift+Z**를 눌러 본다 → **안 먹어야 정상**. ⑥ 미리보기가 다 뜬 뒤 **자물쇠 표시가 사라지고**, 다시 Ctrl+Shift+Z 를 누르면 **정상 동작**하는지 확인 | ✅ O |
| BR60-10 | 차례를 **안 바꾸고** 저장해도 잠금이 제대로 풀림 | ① 팝업을 연다. ② 아무것도 바꾸지 않고 바로 '저장 → 예'를 누른다. ③ 미리보기가 다시 뜨는 동안 화면이 잠기는지 본다. ④ 다 뜬 뒤 **로딩 표시가 사라지고** 클릭·단축키가 모두 정상인지 확인 | ✅ O |
| BR60-11 | 반복 저장해도 화면이 잠긴 채 멈추지 않음 | ① '레이아웃 변경'을 열어 차례를 바꾸고 '저장 → 예'. ② 같은 동작을 **5번 이상 반복**한다(매번 차례를 바꿔서). ③ 매번 미리보기가 정상으로 다시 뜨고, **로딩 표시가 남아 화면이 멈추는 일이 없는지** 확인. ④ 'Critical Error' 문구가 뜨지 않는지 확인 | ✅ O |
| BR60-12 | 기본값 되돌리기 후 저장도 정상 | ① 팝업을 연다. ② 하단 '기본값' 버튼(되돌리기 모양)을 누른다(★'저장'·'닫기'와 다른 버튼). ③ 타일 차례가 처음 배치로 돌아오는지 본다. ④ '저장 → 예'를 누르고, 화면 3분할이 처음 배치로 돌아오며 로딩 표시가 정상적으로 사라지는지 확인 | ✅ O |

## BR49 — 레이아웃 반복 저장 시 Critical Error(instanceof 형변환) 차단 (2026-08-20 통과, 노션=수정완료)

| 코드 | 동작 | 조작·확인 포인트 | O/X |
|---|---|---|---|
| BR49-1 | 순서 바꿔 저장을 반복해도 오류 안 뜸 | ① WS20 Design 화면에서 좌측 위 '레이아웃 변경' 버튼을 누른다. ② 팝업에서 타일 하나를 다른 자리로 끌어 순서를 바꾼다. ③ 하단 '저장'을 누르고 확인 창에서 '예'를 누른다. ④ 팝업이 닫히고 미리보기가 정상적으로 다시 그려지는지 본다. ⑤ 다시 '레이아웃 변경'을 열어 순서를 또 바꾸고 '저장→예'를 누른다. ⑥ 이 열기·바꾸기·저장을 5번 이상 반복한다. ⑦ 'Critical Error' 문구가 한 번도 안 뜨고, 매번 미리보기가 정상으로 다시 뜨는지 확인 | ✅ O |
| BR49-2 | 기본 배치로 되돌려 저장 반복해도 오류 안 뜸 | ① '레이아웃 변경'을 연다. ② 하단 '기본값' 버튼(되돌리기 모양)을 눌러 기본 배치로 되돌린다. ③ '저장→예'. ④ 다시 순서를 바꿔 저장한 뒤, 또 '기본값→저장→예'. ⑤ 되돌리기·저장을 몇 번 반복해도 'Critical Error' 없이 미리보기가 정상인지 확인 | ✅ O |
| BR49-3 | 순서 안 바꾸고 저장해도 정상 | ① '레이아웃 변경'을 연다. ② 아무것도 안 바꾸고 바로 '저장→예'를 누른다. ③ 미리보기가 그대로 정상 유지되고 오류가 없는지 확인 | ✅ O |

> 수정: `ws_html5_ws20.js`(내 파일, design 폴더 무수정). 순서 바뀐 저장 시 옛 미리보기 참조 먼저 제거(원본 재현)+중복 재로드 제거, 배선 예외에도 재부착 사실 보존(P1), 재로드 진행 중 중복 그리기 차단(P2). 원본 저장중 화면잠금·단축키잠금 등 나머지 원본 대비 차이 4건은 BR60으로 분리.
