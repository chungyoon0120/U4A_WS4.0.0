# `getAppInfo()` 전역 함수 — 사용처 전수 조사

> 대상 = 작업 폴더 `www/ws30` 전체(백업 폴더 `_` 접두 제외) · 원본 대조 = `C:\Users\socce\Documents\Github\U4A_WS3.0.0`

## 0. 결론 — 장군님 보신 게 맞았다

- `getAppInfo()` 는 **읽기만** 한다. 값을 넣는 것은 짝인 `setAppInfo()` 다.
- **값을 채우는 자리는 WS20 쪽뿐이었다.** USP(WS30) 진입은 모델 `/WS30/APP` 만 채우고 전역은 비워 둔 채 지나갔다 — 원본도 똑같다(원본 `ws_fn_02.js` USP 분기 221~241줄).
- 그래서 WS10 첫 화면과 USP 화면에서는 `getAppInfo()` 가 **`undefined`** 였다.
- **2026-10-06 장군님 지시로 USP 진입에도 넣게 고쳤다**(`ws_html5_shell.js` USP 분기). 이 문서 2절의 표는 고치기 전 상태를 그대로 적고, 바뀐 줄만 따로 표시했다.

## 1. 함수 자체

| 무엇 | 어디 | 하는 일 |
|---|---|---|
| `getAppInfo()` | `www/ws30/resources/index.js` 1575 | 저장해 둔 앱 정보를 돌려준다. **없으면 `undefined`**(값이 없을 때 `return;` 만 한다) |
| `setAppInfo(o)` | 같은 파일 1570 | 저장한다. `undefined` 를 주면 지운다. 변경 표시가 `X` 면 상태를 Inactive 로 바꾸고, WS20 페이지일 때만 모델 `/WS20/APP` 도 같이 갱신 |
| `setAppChange('X'/'')` | 같은 파일 1875 | `getAppInfo()` 를 읽어 변경 표시만 바꿔 다시 저장. 에디터·CSS/JS 링크·보안 설정 팝업들이 저장 성공 뒤 부른다 |

### 3-2. WS10·USP 등 화면과 무관하게 돌던 자리

| 어디 | 무엇에 쓰나 | 값이 없을 때 |
|---|---|---|
| `js/ws_events.js` Logout | 로그아웃할 때 서버에 앱 이름 보내기 | 모델 `/WS30/APP` 로 **대체**해 읽는다 — 그래서 USP 에서도 정상 동작했다 |
| `js/ws_main.js` 창 닫기 전 처리 | 세션 종료에 앱 이름 보내기 | 같다(모델로 대체) |

## 4. 이번 수정이 건드리지 않는 것 (근거)

| 걱정 | 왜 괜찮은가 |
|---|---|
| USP 화면에서 WS20 용 기능이 깨어날까 | WS20 쪽 읽는 자리들은 WS20 을 그릴 때만 불린다. 단축키도 화면별로 걸고 떼므로 USP 화면에서는 WS20 단축키가 없다 |
| 컨트롤러(클래스 빌더) 실행이 달라질까 | USP 는 앱 정보를 인자로 직접 넘기고, 그 값이 전역보다 우선한다 |
| 로그아웃·창 닫기 때 서버에 다른 값이 갈까 | 두 곳 모두 **앱 이름만** 쓴다. 앱 이름은 진입 뒤 바뀌지 않는다 |
| 전역 값이 낡을까 | 낡는다 — USP 가 모드 전환·저장 응답으로 앱 정보를 **새 객체로 갈아끼우기** 때문이다. 다만 USP 화면 자체는 전부 모델 `/WS30/APP` 를 읽으므로 화면 동작에는 영향이 없다. (현황판 「정해 주실 것 1번」) |
