## 새로 찾은 문제

### DM1 — WS10 이 `IS_DEV` 를 코드에 박아뒀다 — **고침 완료 2026-09-10**

**원본**은 로그인 때 서버가 준 `IS_DEV` 를 읽어(`/USERINFO/USER_AUTH/IS_DEV`) 값이 `"D"` 가 아니면

| 잠금 | 원본 위치 |
|---|---|
| **만들기·바꾸기·지우기·복사** 버튼을 **안 보이게** 함 | 원본 `ws_fn_01.js` 1357~1370행 |
| 메뉴의 **패키지 변경**·**앱 가져오기** 를 **회색으로 만들어 못 누르게** 함 | 원본 `ws_fn_01.js` 1095~1108행 |

**지금** WS10 은 서버 값을 안 읽고 코드에 `IS_DEV: "D"` 를 박아뒀다 → [ws10_html.js:65](../../www/ws30/ws10_20/js/ws10_html.js)
- 버튼 감추기 판단 → [ws10_html.js:1163](../../www/ws30/ws10_20/js/ws10_html.js)
- 단축키 판단 → [ws10_html.js:1489](../../www/ws30/ws10_20/js/ws10_html.js)
- 원본의 메뉴 회색 처리 함수(`ws_fn_01.js` 1117행)는 **아예 부르지 않는다**

**서버 값은 제대로 받아오고 있다** — 로그인 시 저장(`Login/Login.js` 1515행). **WS20 화면과 USP 화면은 그 값을 제대로 쓴다**(`ws_html5_ws20.js` 489행 · `usp/ws_html5_usp.js` 2043행). **WS10 만 안 쓴다.**

> **`IS_DEV` 의 뜻은 아직 미확정.** 원본 주석이 자리마다 다르다 — 로그인 쪽은 "개발서버 여부 개발서버 : D / (조회만 가능)", WS20 버튼 쪽은 "개발자 권한이 없거나". 값을 만드는 로직은 서버 안에 있어 여기 소스로는 확정 불가. **다만 뜻이 무엇이든 고치는 방법은 같다** — 서버가 준 값을 읽으면 된다.

### DM2 — WS10·WS20·WS30 이 `fnIsStaff` 를 안 부른다 — **고침 완료 2026-09-10**

**원본**은 세 화면 모두 Test 메뉴를 보일지 `fnIsStaff()` 로 판정한다. 주석은 세 곳 다 **"U4A R&D 일 경우에만 Test Menu를 보여준다"**.
원본 `ws_fn_01.js` 1321행(WS10) · 2856행(WS20) · `usp/ws_usp.js` 602행(WS30)

**지금**은 메뉴바를 그리는 부품이 **세 화면 공용**인데, 그 한 곳에서 코드에 박아둔 `true` 를 본다.

| 무엇 | 어디 |
|---|---|
| 판정하는 곳(공용, 여기 한 곳) | [ws10_html.js:936](../../www/ws30/ws10_20/js/ws10_html.js) |
| 박아둔 값 | [ws10_html.js:66](../../www/ws30/ws10_20/js/ws10_html.js) |
| WS10 Test 묶음 | [ws10_html.js:195](../../www/ws30/ws10_20/js/ws10_html.js) |
| WS20 Test 묶음 | [ws_html5_ws20.js:110](../../www/ws30/ws10_20/js/ws_html5_ws20.js) |
| WS30 Test 묶음 | [usp/ws_html5_usp.js:224](../../www/ws30/ws10_20/js/usp/ws_html5_usp.js) |

판정 함수는 HTML5 에도 **살아 있고 정상 동작**한다(`ws_fn_03.js` 279행, 접속 아이디를 정해진 목록과 대조). 덧씌운 것도 원본을 먼저 부른다(`ws_html5_shell.js` 338행). **부르지를 않을 뿐이다.**

**위험** — Test 메뉴 안에 **Busy 강제실행 · Busy 강제종료 · 세션 끊기 · 잘못된 서버 호출** 이 있다. 일반 사용자가 누르면 화면이 멈추거나 접속이 끊긴다.

> 그 안의 **개발툴** 하나는 별도 잠금이 있다 — 권한 파일을 풀어 **서버의 SYSID·인스턴스 번호·유효기간**을 대조한다([ADMIN/DevToolsPermission/index.js:161](../../www/ADMIN/DevToolsPermission/index.js)). **이건 원본에 없던 것**(원본은 아무 확인 없이 바로 연다). 나머지 Test 항목은 이 보호를 못 받는다.

### DM3 — AI 연결 버튼이 절반만 옮겨졌다 — **보류**(장군님 지시 2026-09-10)

> **보류.** 손대지 않는다. 버튼은 화면에서 숨겨져 있어 지금 드러나지 않는다.
> 다시 꺼낼 때 아래 3가지를 함께 처리해야 한다.


**원본**은 머리 줄의 스위치를 켜고 끄면
① 화면을 잠그고 자식 창들에도 잠금 신호를 보냄 → ② AI 서버에 연결/해제 요청 → ③ **실패하면 스위치를 도로 끄고** 안내를 띄움 → ④ 잠금·자식 창 잠금 해제.
스위치 겉모습이 `/UAI/state` 와 한 몸으로 묶여 있어 실패하면 저절로 꺼진다.
원본 `ws_common.js` 3186행 · `ws_fn_05.js` 103행·145행

**지금** 버튼을 누르면 세 줄이 전부다 — 표시 뒤집기 / 다시 그리기 / 실제 처리 호출 시도.

| 빠진 것 | 내용 |
|---|---|
| ① 실제 처리 미연결 | 부를 수 있는 것 10개 목록에 AI 처리가 **없다.** "로직 연결 진행 중" 안내만 뜨고 끝. 담당 함수는 [ws_fn_05.js:145](../../www/ws30/ws10_20/js/ws_fn_05.js) 에 살아 있는데 아무도 안 부른다 |
| ② 겉모습과 실제 상태가 따로 놈 | 버튼은 화면 전용 값만 본다. 실제 결과는 `/UAI/state` 에 쌓인다. **실패해도 "연결됨"으로 남는다** |
| ③ 화면 잠금·자식 창 신호 없음 | 원본이 하던 잠금 처리가 통째로 빠졌다 |

버튼은 장군님 지시로 **화면에서만 감춰둔 상태**다 — [ws10_html.js:979](../../www/ws30/ws10_20/js/ws10_html.js). 그 한 줄을 지우면 다시 나타나고 위 3가지가 바로 드러난다.

**DM1·DM2 와 성격이 다르다.** 저 둘은 잠금이 풀린 것이고, 이건 **아직 옮기다 만 것**이다.

## 어떻게 조사했나

이번 앱 이름 문제와 같은 병을 찾았다. 병의 모양은 두 가지다.
1. 원본에서 **화면 요소와 공용 보관함이 한 몸으로 묶여 있던 자리**가 HTML5 에서 끊긴 것
2. 원본에서 **공용 보관함을 보고 판단하던 잠금**을 HTML5 가 코드에 값을 박아 무력화한 것

1번은 원본 두 폴더에서 해당 자리를 **전부** 뽑아(6묶음) 하나씩 대조했고, 2번은 WS10·WS20·WS30 의 판단 근거를 전부 대조했다.
