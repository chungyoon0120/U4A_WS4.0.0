## 3. SP10 ★★★ — 화면 나누는 막대 등록 목록 (83.6%)

### 실측된 붙잡는 경로

```
GC 뿌리
  → 전역
  → 공통 컴포넌트(U4AUI)
  → 화면 나누는 막대 등록 목록 (_SPLIT_REGISTRY)
  → 목록의 [3]번 항목
  → 그 항목이 들고 있는 화면 조각 (el)
  → 그 조각의 자식 → 자식 → 자식 … (20단계 넘게 줄줄이)
```

**목록에 매달린 화면 조각 하나가, 그 아래 화면 전체를 통째로 끌고 남습니다.**

### 소스에서 확인한 원인

`www/ws30/ws10_20/theme/u4a-ui.js`

| 줄 | 내용 |
|---|---|
| 1110 | 등록 목록을 만든다 |
| 1308~1312 | 막대를 배선할 때 **목록에 없으면 새로 등록**한다 |
| — | **목록에서 빼는 코드가 파일 전체에 한 줄도 없다** (찾은 결과 0건) |

- 편집 화면을 나갈 때 화면 내용을 통째로 지우면 그 막대도 화면에서 사라집니다.
- **하지만 목록은 그 조각을 계속 붙잡습니다.**
- 다시 들어가면 **새 막대가 만들어지고, 목록에서 같은 것을 못 찾으니 또 등록**됩니다.
- → 왕복마다 항목이 쌓이고, **각 항목이 버려진 화면 전체를 붙잡습니다.**

### 고치는 방법 (승인 주시면 진행)

**막대를 등록할 때, 이미 화면에서 빠진 항목들을 목록에서 빼 준다.** (한 줄)

- ※ 공통 자산이라 원칙상 직접 수정을 피해야 하지만, **이건 공통 자산 자체의 결함**이라
  화면별로 덧대는 방식으로는 고칠 수 없습니다. **공통 파일 수정 승인이 필요합니다.**
- 화면 동작은 바뀌지 않습니다(창 크기 변경 시 다시 맞추는 기능은 그대로).

## 5. 이번 증상과 맞아떨어지는가

| 관찰된 사실 | 설명되는가 |
|---|---|
| 하루 돌렸을 때 죽음 | ✅ 왕복 3초 × 하루 ≈ 2만 8천 번. 그만큼 버린 화면이 쌓임 |
| 제목 줄까지 화면 전체가 검정 | ✅ 메모리가 바닥나 화면 그리는 일꾼이 통째로 사라짐 → 창 바탕색만 남음 |
| **기록 파일에 오류가 하나도 없음** | ✅ 메모리 고갈은 **기록을 남길 틈이 없음** |
| 3대 중 1대만 죽음 | ✅ 램이 적거나 다른 프로그램이 많던 PC가 먼저 한계 |
| 왕복만 반복했는데 죽음 | ✅ 왕복 그 자체가 누수를 만듦 |

## 6. 아직 검증하지 못한 것 (정직하게)

- **"고치면 안 늘어난다"를 아직 확인하지 못했습니다.** 이것이 마지막 결정적 검증입니다.
  → 승인 주시면 고친 뒤 **같은 도구로 다시 재서** 안 늘어나는 것까지 확인해 보고드리겠습니다.
- 실제로 죽은 그 PC에서 **이것 때문에 죽었다는 직접 증거는 없습니다.**
  기록이 안 남았기 때문이며, 정황(위 5장)은 전부 일치합니다.
- 하루 2만 8천 번은 **이 PC 기록 파일의 왕복 간격(3초)**으로 환산한 값입니다.
  그 PC 자동화 속도가 같은지는 미확인입니다.
