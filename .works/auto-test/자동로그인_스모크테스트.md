# 자동 로그인 스모크 테스트 (실행→인트로→서버리스트→UHA→청윤 로그인)

Electron 앱을 **실제로 실행**해서 로그인 흐름까지 자동 재현하고 성공 여부를 판정하는 방법.
코드 수정 후 "껐다 켜서 로그인까지 되는지"를 사람 없이 한 번에 검증한다.

- 드라이버: [`login-smoke.js`](login-smoke.js)
- 방식: **CDP(원격 디버깅) 프로그래밍 조작** — 픽셀 클릭이 아니라 렌더러에 직접 명령. 수초 내 완료.

---

## 1. 한 줄 실행

```bash
node .works/auto-test/login-smoke.js --fresh
```

- `--fresh` : 이 프로젝트 electron 을 종료 → CDP 완전 다운 확인 → **새로 실행** → 접속 → 청윤 로그인 → 판정.
  코드 수정 검증은 **항상 `--fresh`** 를 쓴다(반영은 앱 재시작이라야 되므로).
- 성공 시 종료코드 `0`, 실패 시 `1`.

성공 출력 예:
```
[smoke] --fresh: 기존 프로젝트 electron 종료
[smoke] 종료 확인(CDP down). 새로 실행합니다.
[smoke] 서버리스트 창 확인: U4A Workspace #ServerList
[smoke] 접속 트리거: 1. [UHA] U4A 개발 서버 → 테스트모드 자동로그인(soccerhs)
[smoke] PASS ✅  #Main 세션 확립
[smoke]    SYSID = UHA   OBJTY = MAIN   session = qnGdZZDEiP3u…   loginForm gone = true
```

### 다른 서버·다른 스태프
```bash
node .works/auto-test/login-smoke.js --fresh --server U4E --staff shhong
```
`--server` 는 서버 카드/행 텍스트 부분일치, `--staff` 는 자동 로그인 스태프 ID.
스태프 목록: 영선(yshong) · 성호(shhong) · 은섭(pes) · 청윤(soccerhs) — `Login.js` `fnGetStaffList` 참조.

### 로그인 + 편집(Change) 모드 진입까지 검증
```bash
node .works/auto-test/login-smoke.js --fresh --app YLCY_TEST2142
```
`--app` 지정 시 로그인 후 **앱 이름 입력 → 편집(Change) 진입**까지 검증한다.
PASS 예: `편집모드 PASS ✅ WS20 진입 / APPID=YLCY_TEST2142 / IS_EDIT=X / APPTY=M`.

### 로그인 + 편집 + 바인딩 팝업 실행까지 검증
```bash
node .works/auto-test/login-smoke.js --fresh --app YLCY_TEST2142 --bind
```
`--bind` 지정 시 편집 진입 후 **디자인트리 노드 선택 → 바인딩 가능 속성 행의 바인딩 아이콘 버튼
(`.u4aWs20AttrIcBtn`) 실제 클릭 → 바인딩 팝업(`dialog.u4aBindDlg`) 개방**까지 검증한다.
PASS 예: `바인딩팝업 PASS ✅ / 헤더=데이터 바인딩/바인딩 해제 - 속성 : title`.

> ★ **앱 편집 락 주의**: 편집 진입 시 앱은 `LCKFL`(사용자/SSID 소유 배타락)에 잠긴다.
> 앱을 **강제종료(`--fresh` kill)** 하면 락이 정상 반납되지 않고 **누수**되어, 이후 같은 앱
> 편집 시 `IS_EDIT=''`(표시모드 강등, "App … is locked by <me>")로 막힌다.
> - 하네스는 편집 획득 세션에서 **종료 전 `ajax_unlock_app` 로 락을 반납**(누수 예방)하고,
>   강등 감지 시 **unlock+재시도 1회** 자가치유를 시도한다.
> - 단, **죽은 세션이 소유한 배타락은 새 세션이 못 푼다**(SSID 게이트). 이 경우 원 소유 세션
>   종료 후 백엔드 세션 reap(수 분) 또는 관리자 강제해제(SM12류) 필요.

## 2. 전제 조건 (왜 되는가)

1. **비패키지(dev) 모드** — `npm start`. 패키지 빌드본에는 자동 로그인 장치가 없다.
2. **원격 디버깅 포트** — `electron/main.js:109 configureRemoteDebuggingPort()` 는
   환경변수 `WS_REMOTE_DEBUG_HOST` 가 있을 때만 `remote-debugging-port` 를 연다.
   드라이버는 실행 시 `WS_REMOTE_DEBUG_HOST=http://127.0.0.1:9222` 를 **명시 주입**한다.
3. **테스트 모드 자동 로그인** — `ServerList.js:2756`. `oAPP.attr._testMode=true` + `_testId`(스태프ID)를
   세팅하고 접속하면, 로그인 창이 일치하는 스태프 버튼을 **자동 클릭**한다
   (비밀번호는 앱이 `Login.js fnStaffLogin` 의 자체 목록에서 채움 → AI 가 자격증명을 타이핑하지 않음).
   이 자동 로그인 버튼/토글은 **RND 서버(`isU4A_RND_SERVER`)** 에서만 노출된다.

## 3. 동작 흐름

| 단계 | 하는 일 | 근거 |
|---|---|---|
| ① 종료·재기동 | `--fresh` 시 이 프로젝트 electron 만 종료(경로 `*U4A_WS4.0.0*` 필터) → CDP 다운 확인 → `npm start` | 재시작해야 코드 반영 |
| ② 서버리스트 대기 | CDP `/json/list` 에서 `#ServerList` 페이지 등장까지 폴링 | 인트로 자동 통과 |
| ③ 접속 트리거 | 서버리스트 페이지에 `oAPP.attr._testMode=true; _testId=STAFF` 세팅 후, `--server` 텍스트를 가진 카드/행에 `dblclick` 디스패치(=`fnPressServerListItem`) | `ServerList.js:1429/2715` |
| ④ 로그인 판정 | 새 `#Main` 창 URL 에 `sessionKey` + `OBJTY=MAIN` 이 뜨고 로그인 폼(`#ws_pw`)이 사라지면 **PASS** | `fnLoginPage` 결과 |

**로그인 판정(PASS)**: `#Main` 창 URL 에 유효 `sessionKey` 존재 + `OBJTY=MAIN` + 로그인 폼 소멸.
매 실행마다 `sessionKey` 가 달라지는 것으로 "실제 새 로그인" 을 교차 확인한다.

### 편집(Change) 모드 진입 (`--app` 지정 시)

| 단계 | 하는 일 | 근거 |
|---|---|---|
| ⑤ WS10 렌더 대기 | 로그인 직후엔 `#AppNmInput` 미존재 → `getCurrPage()==='WS10'` + 입력칸 + `ev_AppChange` 준비까지 폴링 | 메뉴 비동기 렌더 |
| ⑥ 편집 트리거 | `#AppNmInput.value=<APP>` 세팅 후 `oAPP.events.ev_AppChange()` 호출(=ISEDIT "X") | `ws_html5_shell.js:495` |
| ⑦ 편집 판정 | `getCurrPage()` 가 `WS20`(USP는 `WS30`) + `getAppInfo().APPID`=대상 + `IS_EDIT="X"` 이면 **PASS** | `fnOnEnterDispChangeMode` |

**편집 판정(PASS)**: 페이지가 WS20/WS30 로 이동 + APPID 일치 + `IS_EDIT="X"`.
- 앱이 서버에 없으면 `MSGTY="N"`(msg 007) → **FAIL**.
- 잠금/버전관리/비Admin+Admin앱이면 `IS_EDIT=""`(표시모드 강등) → **FAIL** 로 구분 보고.
- **주의**: 상태 판독은 `getAppInfo()`·`getCurrPage()` **window 전역**으로 한다.
  `APPCOMMON` 은 window 전역이 아니라 CDP 에서 호출 불가.

## 4. 무결성 주의 (거짓 PASS 방지)

- 로그인 후에도 **서버리스트 창은 닫히지 않고 `#Main` 창이 별도로 생긴다.**
  따라서 종료 없이 재실행하면 이미 로그인된 `#Main`(옛 세션)에 걸려 **거짓 PASS** 가 날 수 있다.
- 드라이버는 `--fresh` 에서 **CDP 가 완전히 내려간 것을 확인한 뒤에만** 재기동한다.
  종료가 안 되면(`CDP 살아있음`) 그 자리에서 **중단(FAIL)** 시킨다. → 항상 `--fresh` 권장.
- `--fresh` 없이 실행했는데 서버리스트 없이 `#Main` 만 있으면 드라이버가 명시적으로 FAIL 시킨다.

## 5. 다른 화면 검증으로 확장

로그인 이후 특정 메뉴·조건·결과 검증을 붙이려면, `runFlow` 의 PASS 지점 다음에 `#Main`(또는
열리는 팝업/별창) 페이지를 대상으로 `evalOnPage(page, "…판정식…")` 를 추가한다.
- 대상 창은 `/json/list` 의 `title`(`#Main`, `#ServerList`, 팝업별 타이틀)로 고른다.
- 조작은 실제 클릭 핸들러가 클로저로 물고 있으므로, **DOM 요소에 이벤트 디스패치**(`dispatchEvent`)로
  트리거하는 것이 내부 함수 직접호출보다 안전하다(핸들러 배선까지 함께 검증됨).
