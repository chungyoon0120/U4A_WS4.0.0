# 🛠️ 버그리포트 작업 지침서 (새 창용)

> 이 문서 하나로 **새 채팅창의 클로드가 버그리포트의 한 항목을 처음부터 끝까지** 조사·수정·검수하도록 안내한다.
> 장군님은 새 창에서 **이 파일과 `00_버그리포트.md`를 읽으라 한 뒤, 고칠 코드(예: "BR7")만** 주면 된다.

---

## 0. 최우선 규칙 (어떤 스킬·판단보다 위)

- **정답은 항상 원본(as-is) + `.analy` 문서 세트다.** 원본에 있는 속성·동작·구조를 그대로 이식한다.
- **원본에 없는 UX·요소·옵션·레이아웃을 임의로 추가·변경하지 않는다.** 좋아 보여도 만들지 말고 **보고만** 한다.
- **화면 위치·의도가 조금이라도 애매하면, 고치기 전에 장군님께 먼저 묻는다.** (추측 수정 금지)
- 폴더명이 **`_`(언더바)로 시작하면 백업·구버전**이니 현행 근거로 인용하지 않는다. (`bindPopup-origin`은 `_` 아님 = 원본 참조본, 사용 가능)

## 1. 전체 흐름 (한눈에)

```
① 항목 파악  →  ② (필요시) 그림 1장 뽑아 보기  →  ③ 원본 대조 조사
   →  ④ 애매하면 질문  →  ⑤ 수정(원본 1:1) + node --check
   →  ⑥ 검수 도장(원본대조·코덱스·안티)  →  ⑦ 테스트 체크리스트  →  ⑧ 상태 갱신
```

## 2. 단계별 지침

### ① 항목 파악
`00_버그리포트.md`의 접수 목록에서 장군님이 준 코드(예: BR7) 줄을 찾아 **화면·슬라이드 번호·지적 내용·분류(기능/UX)**를 읽는다.

### ② 그림이 필요하면 그 슬라이드 1장만 뽑기
글 설명은 이미 목록에 있다. **배치·색·위치처럼 눈으로 볼 게 있을 때만** 그림을 본다. 전 슬라이드를 미리 뽑지 말 것(용량·토큰 낭비).
```bash
cd .works/버그리포트
python extract_slide.py <슬라이드번호>     # 예: BR7~9는 8p → python extract_slide.py 8
```
출력된 **이미지 경로를 Read**로 연다.
- ★참고: PPT는 압축 꾸러미라 Read로 바로 못 연다. 이 도구가 그 슬라이드 그림을 임시 파일로 꺼내 준다.
- ★그림은 **캡처 원본 크기**로 나온다(파워포인트에서 작게 줄여도 저장본은 원본). 원본 PPT는 실시간 갱신되는 읽기 전용 파일이다.

### ③ 원본(as-is) 대조 조사 — 가장 중요
현행 소스와 **원본**을 나란히 놓고, 무엇이 원본과 달라졌는지 찾는다.
- **바인딩 팝업** 화면: 현행 `www/ws30/ws10_20/Popups/bindPopup/` ↔ 원본 참조본 `www/ws30/ws10_20/Popups/bindPopup-origin/`
- **다른 화면**(CTS 팝업·Application 생성 팝업·UI 추가 팝업 등): 그 화면의 현행 소스를 찾고, 짝이 되는 원본(UI5)을 찾아 대조한다. 원본 위치를 모르면 **찾은 뒤** 진행하고, 못 찾으면 장군님께 보고.
- **화면 UX 표준**: `.analy/` 문서 세트. MCP 도구 `analy_index`(무슨 문서 볼지) → `analy_get_doc`/`analy_search`. 설계 근거는 **문서 절 번호**로 댄다.

### ④ 애매하면 질문
증상이 어느 화면·어느 요소인지, 원본에 원래 있던 동작인지 불확실하면 **수정 전에 장군님께** 후보를 정리해 묻는다.

### ⑤ 수정 (저장 직전 체크)
- **원본 1:1.** 원본에 없는 동작·옵션 추가 금지.
- 공통 자산(shell.css·bootstrap-skin.css·u4a-ui.js·tokens.css) **직접 수정 금지** → 스코프 override.
- 하드코딩 색(hex) 금지, `color-mix` 금지(구형 브라우저). 색은 의미 토큰만.
- 메시지 문구는 **원본 키 참조**. 새 문구 임의 생성·메시지 DB 직접 수정 금지(문구는 장군님이 넣음, 나는 키 번호만 배선).
- 비동기·화면전환·로딩표시(busy)는 **완료된 뒤** 끄기(중간에 끄면 연타로 꼬임).
- 저장 후 **`node --check <파일>`**. 오류 조용히 삼키기 금지.

### ⑥ 검수 도장 (통과할 때까지)
1. **서브에이전트 원본 대조**: 원본 파일을 직접 열어 함수·라인 단위로 대조, 회귀 영향까지 점검.
2. **코덱스 검수**: `codex-agent` 스킬(읽기 전용). 대상·원본 기준·검증 질문을 명확히 준다.
3. **안티 검수**: `agy-agent` 스킬(읽기 전용). 동일하게.
- **실패하면 그냥 넘기지 말고**, 지적을 항목별로 쪼개 재수정·재검수해 **반드시 통과**를 받는다.

### ⑦ 테스트 체크리스트
- 테스트할 게 생기면 그 **화면 작업폴더의 `00_현황판.md`** 맨 위에 그룹으로 표를 만든다:
  `| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |`, 조작은 ①②③, 버튼·영역은 화면에 적힌 이름 그대로, 쉬운 말.
- 실제 화면 조작으로 재현되는 것만. 코드 반영은 **앱을 껐다 켜야** 보인다.
- 그룹의 전 항목이 통과(✅ O)되면 그 폴더 `00_히스토리.md`로 **그룹째** 이관.

### ⑧ 상태 갱신
`00_버그리포트.md`의 그 코드 줄 **상태**를 접수→수정중→테스트대기→✅ 완료로 갱신한다.
