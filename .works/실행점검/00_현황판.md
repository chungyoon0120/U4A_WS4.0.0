## 지금 할 것 (미테스트)

### BR55 추가 — 신텍스체크(Syntax Check) 버튼도 같은 방식으로 맞춤 (2026-09-01 추가)

> 점검이 도중에 터지면 종전엔 **안내도 없이 화면이 잠긴 채 멈췄다**. 실행(Activate) 버튼과 같은 방식으로 맞췄으므로, **정상 동작이 안 깨졌는지** 확인하는 항목이다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR55-5 | 오류 없는 앱에서 신텍스체크가 그대로 된다 | ① WS20 편집화면에서 오류가 없는 앱을 연다. ② 위쪽 도구모음에서 **체크 표시 두 개가 겹친 모양 버튼**(마우스를 올리면 끝에 "(Ctrl+F2)" 가 보임)을 누른다. ③ 화면이 잠시 잠겼다가 풀리고, 아래쪽에 오류 없다는 안내가 뜨는지 본다. ④ 빨간 오류 팝업이 뜨지 않는지 확인 | ☐ |
| BR55-6 | 오류가 있으면 신텍스체크에서 오류 목록 창이 뜬다 | ① 왼쪽 UI 트리에 **sap.ui.table.Table** 을 하나 넣고 그 아래 **Column** 도 하나 넣는다. ② 트리에서 그 **Table** 을 고르고 오른쪽 **Attribute** 목록의 **autoColumnResize** 를 **true** 로 바꾼다. ③ 트리에서 그 **Column** 을 고르고 **autoResizable** 은 그대로 둔다(비워둠). ④ **체크 표시 두 개가 겹친 모양 버튼**(마우스 올리면 "(Ctrl+F2)")을 누른다. ⑤ 별도 창으로 **오류 목록 창**이 뜨는지 확인. ⑥ 그 창을 오른쪽 위 **X** 로 닫은 뒤, 뒤에 있던 편집화면이 잠긴 채 멈춰 있지 않고 바로 눌리는지 확인 | ☐ |

## 통과 (그룹 전부 통과 시 히스토리 이관)

### BR55 — 실행 전 오류 점검이 실패해도 그냥 통과하던 문제 (2026-09-01 전 항목 통과)

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR55-1 | 오류 없는 앱은 그대로 실행(활성화)된다 | ① WS20 편집화면에서 오류가 없는 앱을 하나 연다. ② 위쪽 도구모음에서 **마법사 지팡이 모양 버튼**(마우스 올리면 "Activate (Ctrl+F3)")을 누른다. ③ 화면이 잠시 잠겼다가(흐려짐) 활성화가 끝나고 다시 풀리는지 본다. ④ 오류 목록 창이 뜨지 않고, 빨간 오류 안내나 영문 추적 코드 글자가 뜨지 않는지 확인 | ✅ O |
| BR55-2 | 오류가 있으면 실행이 막히고 오류 목록 창이 뜬다 | ① WS20 편집화면 왼쪽 UI 트리에서 **sap.ui.table.Table** 을 하나 넣고, 그 아래 **Column** 도 하나 넣는다. ② 트리에서 그 **Table** 을 고르고, 오른쪽 **Attribute** 목록에서 **autoColumnResize** 값을 **true** 로 바꾼다. ③ 트리에서 그 **Column** 을 고르고, **autoResizable** 은 손대지 않고 그대로 둔다(비워둠). ④ 위쪽 도구모음의 **마법사 지팡이 모양 버튼** 을 누른다. ⑤ 별도 창으로 **오류 목록 창**이 뜨고 표 설정 관련 오류 한 줄이 보이는지 확인. ⑥ 활성화가 진행되지 않았는지(성공 안내가 안 뜸) 확인 | ✅ O |
| BR55-3 | 오류 목록 창이 뜬 뒤 화면 잠금이 안 남는다 | ① BR55-2 를 그대로 해서 오류 목록 창을 띄운다. ② 오류 목록 창 오른쪽 위 **X** 를 눌러 닫는다. ③ 뒤에 있던 WS20 편집화면이 흐려진 채 멈춰 있지 않고 바로 눌리는지 확인(트리에서 다른 UI 를 골라본다). ④ 다시 **마법사 지팡이 모양 버튼** 을 눌렀을 때 또 오류 목록 창이 정상으로 뜨는지 확인 | ✅ O |
| BR55-4 | 오류를 고치면 그대로 실행된다 | ① BR55-2 상태에서 트리의 **Column** 을 고른다. ② 오른쪽 **Attribute** 목록에서 **autoResizable** 값을 **true** 로 바꾼다. ③ 위쪽 도구모음의 **마법사 지팡이 모양 버튼** 을 누른다. ④ 오류 목록 창이 뜨지 않고 활성화가 정상으로 끝나는지 확인 | ✅ O |

> 참고: 점검 자체가 터졌을 때의 처리(화면 잠금 풀고 공통 오류 팝업 띄우고 다음 처리 중단)는 점검 함수에 **일부러 오류를 집어넣어야** 도달하는 갈래라 실화면 항목에 넣지 않았다. 대신 함수를 직접 실행하는 방식으로 4가지 경우를 검증했다 — 결과는 `.audit/br55/04_final.md` 3장.
