## BR55 — Activate 전 오류 점검이 실패해도 그냥 통과하던 문제 (2026-09-01 전 항목 통과, 노션=수정완료)

| 코드 | 동작 | 조작·확인 포인트 | O/X |
|---|---|---|---|
| BR55-1 | 오류 없는 앱은 그대로 Activate 된다 | ① WS20 편집화면에서 오류가 없는 앱을 하나 연다. ② 위쪽 도구모음에서 **Activate** 버튼(마우스를 올리면 "활성화 (Ctrl+F3)")을 누른다. ③ 화면이 잠시 잠겼다가(흐려짐) 활성화가 끝나고 다시 풀리는지 본다. ④ 오류 목록 창이 뜨지 않고, 빨간 오류 안내나 영문 추적 코드 글자가 뜨지 않는지 확인 | ✅ O |
| BR55-2 | 오류가 있으면 Activate 가 막히고 오류 목록 창이 뜬다 | ① WS20 편집화면 왼쪽 UI 트리에서 **sap.ui.table.Table** 을 하나 넣고, 그 아래 **Column** 도 하나 넣는다. ② 트리에서 그 **Table** 을 고르고, 오른쪽 **Attribute** 목록에서 **autoColumnResize** 값을 **true** 로 바꾼다. ③ 트리에서 그 **Column** 을 고르고, **autoResizable** 은 손대지 않고 그대로 둔다(비워둠). ④ 위쪽 도구모음의 **Activate** 버튼을 누른다. ⑤ 별도 창으로 **오류 목록 창**이 뜨고 표 설정 관련 오류 한 줄이 보이는지 확인. ⑥ 활성화가 진행되지 않았는지(성공 안내가 안 뜸) 확인 | ✅ O |
| BR55-3 | 오류 목록 창이 뜬 뒤 화면 잠금이 안 남는다 | ① BR55-2 를 그대로 해서 오류 목록 창을 띄운다. ② 오류 목록 창 오른쪽 위 **X** 를 눌러 닫는다. ③ 뒤에 있던 WS20 편집화면이 흐려진 채 멈춰 있지 않고 바로 눌리는지 확인(트리에서 다른 UI 를 골라본다). ④ 다시 **Activate** 버튼을 눌렀을 때 또 오류 목록 창이 정상으로 뜨는지 확인 | ✅ O |
| BR55-4 | 오류를 고치면 그대로 Activate 된다 | ① BR55-2 상태에서 트리의 **Column** 을 고른다. ② 오른쪽 **Attribute** 목록에서 **autoResizable** 값을 **true** 로 바꾼다. ③ 위쪽 도구모음의 **Activate** 버튼을 누른다. ④ 오류 목록 창이 뜨지 않고 활성화가 정상으로 끝나는지 확인 | ✅ O |
| BR55-5 | 오류 없는 앱에서 Syntax Check 가 그대로 된다 | ① WS20 편집화면에서 오류가 없는 앱을 연다. ② 위쪽 도구모음에서 **Syntax Check** 버튼(마우스를 올리면 "구문 검사 (Ctrl+F2)")을 누른다. ③ 화면이 잠시 잠겼다가 풀리고, 아래쪽에 오류 없다는 안내가 뜨는지 본다. ④ 빨간 오류 팝업이 뜨지 않는지 확인 | ✅ O |
| BR55-6 | 오류가 있으면 Syntax Check 에서 오류 목록 창이 뜬다 | ① 왼쪽 UI 트리에 **sap.ui.table.Table** 을 하나 넣고 그 아래 **Column** 도 하나 넣는다. ② 트리에서 그 **Table** 을 고르고 오른쪽 **Attribute** 목록의 **autoColumnResize** 를 **true** 로 바꾼다. ③ 트리에서 그 **Column** 을 고르고 **autoResizable** 은 그대로 둔다(비워둠). ④ **Syntax Check** 버튼(마우스를 올리면 "구문 검사 (Ctrl+F2)")을 누른다. ⑤ 별도 창으로 **오류 목록 창**이 뜨는지 확인. ⑥ 그 창을 오른쪽 위 **X** 로 닫은 뒤, 뒤에 있던 편집화면이 잠긴 채 멈춰 있지 않고 바로 눌리는지 확인 | ✅ O |

> 수정: `ws_events.js`(내 파일, design 폴더 무수정).
> ① Activate 전 오류 점검이 도중에 터지면 종전엔 「오류 0건」으로 치고 그대로 활성화됐다 → 활성화를 막고 공통 오류 팝업으로 드러냄.
> ② 오류 목록 창 열기가 실패하면 화면 잠금이 안 풀리던 것 → 본 화면·자식 윈도우 잠금 회수 + 공통 오류 팝업.
> ③ Syntax Check 버튼도 같은 방식으로 맞춤(종전 무방비 → 점검이 터지면 안내 없이 화면 멈춤).
> 조사·검증 상세 = `.audit/br55/04_final.md`.

## CE 그룹 — Activate·Save 오류 코드 부여 후 정상 동작 회귀 (2026-09-01 전 항목 통과, 노션=수정완료)

| 코드 | 동작 | 조작·확인 포인트 | O/X |
|---|---|---|---|
| CE1 | Save 가 예전처럼 그대로 된다 | ① WS20 편집화면에서 앱을 하나 열고 오른쪽 **Attribute** 목록에서 아무 속성 값을 하나 바꾼다. ② 위쪽 도구모음의 **Save** 버튼(마우스를 올리면 "저장 (Ctrl+S)")을 누른다. ③ 화면이 잠시 잠겼다가 풀리고, 화면 **맨 아래에 가로로 긴 띠**가 뜨면서 **「저장 완료」** 라고 보이는지 확인(그 띠는 10초 뒤 저절로 사라진다). ④ 빨간 오류 팝업이 안 뜨는지 확인. ★앱 이름 옆 **활성/비활성** 글자는 여기서 보지 않는다(CE10 에서 따로 본다) | ✅ O |
| CE2 | Save 후 Undo·Redo 버튼이 꺼진다 | ① CE1 을 끝낸 상태에서 **왼쪽 UI 트리 바로 위 도구모음**을 본다(펼침·접음·돋보기 등이 있는 줄). ② 거기서 **Undo** 버튼(↶ 모양, 마우스를 올리면 "실행취소 (Ctrl+Shift+Z)")이 저장 전엔 눌렸는데 저장 뒤엔 **꺼져 있는지** 확인. ③ 그 옆 **Redo** 버튼(↷ 모양, "재실행 (Ctrl+Shift+X)")도 꺼져 있는지 확인 | ✅ O |
| CE3 | 뒤로가기 → 저장 → 이동이 예전처럼 된다 | ① 앱을 열고 **Attribute** 목록에서 속성 값을 하나 바꾼다. ② 화면 위쪽 앱 이름 **왼쪽의 뒤로가기 화살표**를 누른다. ③ **「앱이 변경되었습니다. / Editor를 종료하기 전에 저장하시겠습니까?」** 창이 뜨고 버튼이 **Yes / No / Cancel** 세 개인지 확인. ④ **Yes** 를 누른다. ⑤ 저장이 끝나고 앱 목록 화면으로 넘어가는지 확인(빨간 오류 팝업 없음) | ✅ O |
| CE4 | 뒤로가기 창에서 **Cancel** 을 누르면 별도 창이 다시 보인다 | ① 앱을 열고 위쪽 도구모음의 **Binding Popup** 버튼으로 별도 창을 하나 띄운다. ② 편집화면으로 돌아와 속성 값을 하나 바꾼다. ③ **뒤로가기 화살표**를 누른다(이때 별도 창이 잠시 안 보이게 된다). ④ 뜨는 창에서 **Cancel** 을 누른다. ⑤ 아까 띄운 **별도 창이 다시 보이는지** 확인(안 보이면 실패) | ✅ O |
| CE5 | Activate 가 예전처럼 그대로 된다 | ① 오류가 없는 앱을 연다. ② 위쪽 도구모음의 **Activate** 버튼(마우스를 올리면 "활성화 (Ctrl+F3)")을 누른다. ③ 화면 **맨 아래 띠**에 **「액티브 성공」** 이 보이는지 확인. ④ 화면 **위쪽 앱 이름 옆** 글자가 **「활성」**(영문 접속이면 Active)으로 바뀌는지 확인. ⑤ 빨간 오류 팝업이 안 뜨는지 확인 | ✅ O |
| CE6 | 별도 창을 띄워 놓고 Save 해도 창이 다시 보인다 | ① 앱을 열고 위쪽 도구모음의 **Binding Popup** 버튼으로 별도 창을 하나 띄운다. ② 편집화면으로 돌아와 속성 값을 하나 바꾸고 **Save** 버튼을 누른다. ③ 저장이 끝난 뒤 그 별도 창이 **다시 보이는지** 확인(숨은 채로 남으면 실패) | ✅ O |
| CE7 | 오류가 있으면 오류 목록 창이 뜨고 Activate 가 막힌다 | ① 왼쪽 UI 트리에 **sap.ui.table.Table** 을 하나 넣고 그 아래 **Column** 도 하나 넣는다. ② 트리에서 그 **Table** 을 고르고 **Attribute** 목록의 **autoColumnResize** 를 **true** 로 바꾼다. ③ 트리에서 그 **Column** 을 고르고 **autoResizable** 은 비워 둔다. ④ **Activate** 버튼을 누른다. ⑤ 별도 창으로 **오류 목록 창**이 뜨고 표 설정 관련 오류 한 줄이 보이는지 확인. ⑥ 활성화가 진행되지 않았는지(「액티브 성공」 이 안 뜸) 확인 | ✅ O |
| CE8 | 오류 목록 창을 닫으면 화면이 다시 눌린다 | ① CE7 을 그대로 해서 오류 목록 창을 띄운다. ② 그 창 오른쪽 위 **X** 를 눌러 닫는다. ③ 뒤에 있던 편집화면이 흐려진 채 멈춰 있지 않고 바로 눌리는지 확인(트리에서 다른 UI 를 골라본다). ④ 다시 **Activate** 를 눌렀을 때 또 오류 목록 창이 정상으로 뜨는지 확인 | ✅ O |
| CE9 | 오류를 고치면 Activate 가 된다 | ① CE7 상태에서 트리의 **Column** 을 고른다. ② **Attribute** 목록의 **autoResizable** 을 **true** 로 바꾼다. ③ **Activate** 버튼을 누른다. ④ 오류 목록 창이 안 뜨고 **「액티브 성공」** 이 보이는지 확인 | ✅ O |
| CE10 | 앱 이름 옆 **활성/비활성** 글자가 규칙대로 바뀐다 | ① 이미 **활성** 인 앱을 편집으로 연다(화면 위쪽 앱 이름 옆에 **「편집」 「활성」** 이라고 보임). ② 오른쪽 **Attribute** 목록에서 아무 속성 값을 하나 바꾼다. ③ 그 글자가 **「비활성」** 으로 바뀌는지 확인(바꾼 게 있으면 비활성으로 보인다). ④ **Save** 버튼으로 저장한다. ⑤ 그 글자가 다시 **「활성」** 으로 돌아오는지 확인 — **Save 는 「바꾼 게 있음」 표시만 지우고 활성 상태 자체는 안 바꾸므로** 원래 값으로 돌아온다. ⑥ ★**비활성 앱**으로 같은 걸 해 보면 저장해도 계속 **「비활성」** 이다 — 그게 정상이다. **「활성」 으로 만드는 건 Activate 뿐**(CE5) | ✅ O |

> 수정 범위: `ws_events.js`(Activate·Save·Syntax Check 구간별 오류 코드 WSEV-001~017)
> · `fnDialogPopupOpener.js`(오류 목록 창 띄우기 실패 회수 FDPO-001~004)
> · `design/js/checkAppData/designTreeData.js`(값 검사 방어·삼킴 제거 DCHK-001~004).
> 처리 방식 = 콘솔에 [코드]+위치 → 화면 잠금 해제 → 별도 창 잠금 회수·다시 보이기 →
