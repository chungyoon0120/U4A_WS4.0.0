# WS10 앱 검색 팝업 — 기본 최대 조회수 500건이 「어떤 500건」인가

> 2026-09-21 · 장군님 물음: 「WS10 앱 검색 팝업이 기본 500건으로 조회되는 것 같은데, 그 500건이 최근 날짜 기준이 아닌 것 같다」
> **소스만 읽었다. 코드는 한 줄도 안 고쳤다.** 앱 실행 없음.

---

## 0. 결론 먼저

| 물음 | 답 |
|---|---|
| 기본 500건이 맞나 | **맞다.** WS10 화면이 팝업을 열 때 최대 조회수 `500` 을 기본값으로 넣는다. **원본도 500** (§1) |
| 최근 날짜 기준으로 500건을 가져오나 | **아니다 — 클라이언트는 날짜를 한 글자도 안 보낸다.** 보내는 조건은 패키지·생성자·앱 ID·앱 이름·앱 타입·최대 조회수뿐이다. 정렬 조건도 안 보낸다 (§2) |
| 그럼 어떤 500건인지는 누가 정하나 | **서버(ABAP)** 가 정한다. 서버 소스는 이 저장소에 없어 **어떤 순서로 자르는지는 미확인** (§3) |
| 화면에 보이는 순서는 | 받은 뒤 **앱 ID 오름차순**으로 다시 정렬해 보여 준다. **원본도 같다** — 그래서 화면 순서만 보면 최신순이 아니다 (§2) |
| 클라이언트에서 고칠 수 있나 | **없다.** 500건을 고르는 일이 서버에서 끝나서, 잘려 나간 최근 앱은 화면에 아예 안 온다 (§4) |

---

## 1. 500 은 어디서 정해지나 (원본 대조)

| 자리 | 현행 | 원본(`U4A_WS3.0.0`) |
|---|---|---|
| WS10 화면에서 앱 검색 팝업을 열 때 넘기는 기본 조건 | `ws_html5_shell.js` 521~527줄 — 최대 조회수 `500`, 생성자 = 내 SAP 계정, 앱 타입 = 직전 선택값, 호출 화면 = WS10 | `ws_events.js` 1010~1021줄 — **똑같다** |
| 팝업 입력칸 기본값 | `fnAppF4PopupOpen.js` 418줄 — 넘어온 값이 없으면 `500` | 원본도 같은 파일에서 모델 값으로 표시 |
| 다른 곳에서 여는 앱 검색 팝업(바인딩 팝업·속성 영역 등) | 전부 `500` | 전부 `500` |

→ **500 이라는 숫자 자체는 원본 그대로**다.

## 2. 서버에 보내는 것 · 받은 뒤 하는 것 (원본 대조)

**보내는 것** (`fnAppF4PopupOpen.js` 666~676줄 → 서버 주소 `…/getappsearch`)

| 보내는 값 | 무엇 |
|---|---|
| PACKG · ERUSR · APPID · APPNM · APPTY | 패키지 · 생성자 · 앱 ID · 앱 이름 · 앱 타입 |
| HITS | **최대 조회수(기본 500)** |
| EXPAGE | 어느 화면에서 열었는지(WS10) |

- **날짜 조건 없음. 기간 조건 없음. 정렬 조건 없음.** 원본(`fnAppF4PopupOpen.js` 2246~2249줄)도 **같은 값만** 보낸다.

**받은 뒤 하는 것**
- 현행 677~680줄: 받은 목록을 **앱 ID 오름차순으로 정렬**해서 화면에 그린다.
- 원본 2264~2274줄: **똑같이 앱 ID 오름차순 정렬.**
- 즉 화면에 최신 앱이 위로 오지 않는 것은 **원본과 같은 동작**이다(정렬은 컬럼 머리를 눌러 바꿀 수 있다).

## 3. 「어떤 500건인가」 는 서버가 정한다 — 미확인

- 자르는 일은 서버 쪽 `getappsearch` 에서 끝난다. 그 서버 소스(ABAP)는 이 저장소·원본 저장소 **어디에도 없다** → **정렬 기준을 소스로 확인할 방법이 없다.**
- 클라이언트가 날짜·정렬을 안 보내므로, 서버가 따로 정렬하지 않으면 보통 **앱 ID 순서로 앞에서 500건**이 잘린다. 그러면 **뒤 글자로 시작하는 최근 앱은 영영 안 나온다.** 장군님이 느끼신 현상과 맞는다(다만 **서버 소스로 확인한 것은 아니다**).

## 4. 지금 상태에서 장군님이 확인해 보실 수 있는 것

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| AS1 | 500건에서 잘리는지 본다 | ① WS10 화면에서 앱 검색 팝업을 연다 ② **최대 조회수** 칸을 `500` 그대로 두고 검색한다 ③ 결과 건수를 적어 둔다 ④ **최대 조회수**를 `99999` 로 바꾸고 다시 검색한다 ⑤ 건수가 늘면 **500 에서 잘리고 있는 것**이다 | ☐ |
| AS2 | 잘린 쪽에 최근 앱이 있는지 본다 | ① AS1 ④ 상태(큰 조회수)에서 **생성일** 또는 **변경일** 컬럼 머리를 눌러 **내림차순** 정렬한다 ② 맨 위에 뜨는 최근 앱들이 AS1 ②(500건) 결과에도 있었는지 본다 ③ 없으면 **500건이 최근 날짜 기준이 아니다** 가 확정된다 | ☐ |

⚠ **생성일·변경일 컬럼은 권한이 있는 계정에만 보인다**(`fnAppF4PopupOpen.js` 464~472줄 — 원본도 같은 권한 게이트). 컬럼이 안 보이면 AS2 는 못 한다.

## 5. 앱 검색 팝업이 쓰는 서버 경로 (2026-09-21 장군님 물음)

| 무엇 | 경로 | 보내는 것 |
|---|---|---|
| **앱 목록 검색** (팝업 첫 번째 탭, 「검색」) | `{프로토콜}://{호스트}:{포트}/zu4a_wbc/u4a_ipcmain/getappsearch` | `APPINFO` = 검색 조건 JSON (PACKG·ERUSR·APPID·APPNM·APPTY·**HITS**·EXPAGE) |
| 패키지 계층 트리 (팝업 두 번째 탭) | 같은 앞부분 + `/getapplhierarchydata` | — |

- 앞부분(`{프로토콜}://{호스트}:{포트}`)은 **로그인한 서버 정보**에서 만든다(`ws30/resources/index.js` 401~434줄). 서버마다 다르다.
- **원본도 같은 경로**다 — 원본 `fnAppF4PopupOpen.js` 2246줄(`/getappsearch`) · 2150줄(`/getapplhierarchydata`), 앞부분도 같은 자리에서 만든다.
- 500건을 자르는 곳 = 위 **`/getappsearch`** 를 받는 서버(ABAP) 쪽이다.

## 6. 정해 주실 것

| 번호 | 물음 | 제 생각 |
|---|---|---|
| 1 | AS1·AS2 로 「500 에서 잘린다」 가 확인되면, **서버(ABAP) 쪽에 최근 날짜 기준으로 잘라 달라고 요청**할까 | **그게 맞다.** 클라이언트는 날짜를 안 보내고 자르지도 않아서, 여기서는 못 고친다. 서버가 변경일 내림차순으로 500건을 주면 그대로 해결된다 |
| 2 | 그때까지 **팝업의 기본 최대 조회수(500)를 더 크게** 바꿀까 | **바꾸지 않는 쪽**이다. 원본이 500 이고, 크게 하면 서버·화면이 느려진다. 급하면 장군님이 팝업에서 숫자만 바꿔 검색하시면 된다 |
| 3 | 팝업에 **기간(생성일/변경일) 검색칸**을 넣을까 | **넣지 않는 쪽**이다. 원본에 없는 UX 이고, 서버가 그 조건을 받는지도 모른다. 서버 쪽 확인이 먼저다 |
