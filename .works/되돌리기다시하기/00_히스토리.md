# 되돌리기·다시하기(BR62) — 히스토리 (통과 이관)

## BR62 (A·C) — 되돌린 뒤 선택되는 UI 교정 (2026-09-02 통과)

> **무엇을 고쳤나**
> - **A(이름 변경)** — 이름을 바꾼 뒤 되돌리면 선택이 **부모(PAGE1 등)로 튀던** 것 → 그 UI에 그대로 남게.
> - **C(삭제)** — 지운 것을 되돌리면 **되살아난 UI가 선택**되게(원본과 동일). 전에는 지우기 전에 눌러 둔 딴 줄이 선택됐음.
>
> ★ **삭제는 반드시 트리 줄 오른쪽 끝의 빨간 휴지통 아이콘으로** 하십시오.
> 우클릭 메뉴의 삭제는 우클릭 순간 그 줄이 선택돼 버려서, 고치기 전후 차이가 안 보입니다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR62-1 | **이름 변경 되돌리기** — 선택이 그 UI에 남는지 | ①트리에서 UI 하나(예: 어떤 버튼)를 왼쪽 클릭해 고른다. ②오른쪽 맨 위 **UI 오브젝트 ID** 칸의 이름을 다른 정상 이름으로 바꾸고 Enter를 누른다. ③상단 **되돌리기**를 누른다. ④**이름이 옛 이름으로 돌아오면서, 트리 선택 표시(파란 줄)가 그 UI에 그대로 있는지** 확인(전에는 부모 줄로 튀었음). 오른쪽 속성 영역도 그 UI를 계속 보여주는지 함께 확인. | ✅ O |
| BR62-2 | **이름 변경 다시하기** — 같은 UI가 선택되는지 | ①BR62-1 상태에서 상단 **다시하기**를 누른다. ②이름이 바꿨던 새 이름으로 돌아가고, **같은 그 UI가 선택된 채**인지 확인. | ✅ O |
| BR62-3 | 자식 **펼쳐 둔 채** 이름 변경 → 되돌리기 | ①자식이 있는 UI(예: 표, 상자)를 트리에서 **펼친다**. ②그 UI의 이름을 바꾼다. ③**되돌리기**를 누른다. ④**펼친 상태가 그대로 유지되고** 선택도 그 UI에 남아 있는지 확인(전에는 도로 접혔음). | ✅ O |
| BR62-4 | 이름 변경 되돌리기·다시하기 시 **화면이 튀지 않는지** | ①BR62-1·2를 하면서 오른쪽 속성 영역을 본다. ②**위쪽 요약 영역이 저절로 접히거나**, 특정 **속성 줄로 화면이 끌려가는 일이 없어야** 정상(원본도 이 경우엔 화면을 안 옮긴다). | ✅ O |
| BR62-5 | 이름을 **연속 두 번** 바꾼 뒤 되돌리기 두 번 | ①UI 하나의 이름을 A→B로 바꾼다. ②이어서 B→C로 한 번 더 바꾼다. ③**되돌리기** → 이름이 **B**가 되고 그 UI가 선택돼 있는지 확인. ④**되돌리기** 한 번 더 → 이름이 **A**가 되고 역시 그 UI가 선택돼 있는지 확인. | ✅ O |
| BR62-6 | ★**휴지통 아이콘 삭제** 되돌리기 — 되살아난 UI가 선택되는지 | ①트리에서 아무 줄이나 왼쪽 클릭해 선택해 둔다. ②**그와 다른** UI 줄의 오른쪽 끝 **빨간 휴지통 아이콘**을 눌러 지운다(확인 창이 뜨면 예). ③상단 **되돌리기**를 누른다. ④**되살아난 그 UI가 선택**돼 있는지 확인(전에는 ①에서 눌러 둔 줄이 선택됐음). | ✅ O |
| BR62-7 | 위 상태에서 **다시하기**(다시 삭제) | ①BR62-6 상태에서 상단 **다시하기**를 누른다. ②그 UI가 다시 지워지고, 선택은 **지워진 UI의 부모**로 가는지 확인. | ✅ O |
| BR62-8 | **여러 개 체크 삭제** 되돌리기 — ★기대값 정정됨(재테스트) | ★먼저 앱을 **완전히 종료했다 다시 실행**한다. ①한 부모 밑에 **서로 같은 기승의 형제 UI 2개**를 만든다(예: 버튼 두 개, 위쪽이 A · 아래쪽이 B). ★**부모–자식 관계로 묶지 말 것** — 부모를 체크하면 자식이 함께 켜져 차이가 안 보인다. ②트리에서 **또 다른 줄**을 왼쪽 클릭해 선택해 둔다. ③A와 B의 **체크박스 둘 다** 켜고 상단 **삭제**(빨간 휴지통) 버튼으로 지운다. ④상단 **되돌리기**를 누른다. ⑤둘 다 되살아나고, **아래쪽이던 B 가 선택**되는지 확인(A 가 선택되면 실패). 근거: 원본은 체크건을 트리 순서로 모은 뒤 **마지막** 것을 고른다(원본 소스 확인 2026-09-02). | ✅ O |

## BR62 (B·D) — 되돌릴 때 미리보기를 "바뀐 부분만" 다시 그리기 + 검수 지적 반영 (2026-09-02 통과)

> **무엇을 고쳤나**
> - 전에는 되돌리기 한 번에 **미리보기 전체를 지웠다 다시 그렸다** — 화면이 깜빡이고, 보던 자리가
>   선택된 UI 쪽으로 끌려가고, 화면이 클수록 느렸다.
> - 이제 **바뀐 UI와 그 부모만** 다시 그린다(원본과 같은 방식). 화면이 통째로 다시 그려지지 않는다.
> - 검수에서 잡힌 것도 함께 고쳤다 — ① **자리 옮기기를 되돌릴 때** UI가 옛 자리에서 안 떨어져
>   **두 군데 남을 수 있던 것** ② 미리보기 쪽이 실패해도 **모른 척 넘어가던 것**(이제 실패하면
>   안전하게 전체 다시 그리기로 넘어감) ③ **되돌리는 동안 화면이 안 잠겨** 그 사이 다른 편집이
>   끼어들 수 있던 것 ④ 전체 다시 그리기로 넘어갔을 때 **보던 자리 복원이 무시되던 것**.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR62-9 | 되돌려도 미리보기에서 **보던 자리가 유지**되는지 | ① 미리보기에 세로 스크롤이 생길 만큼 UI가 많은 앱을 연다(없으면 UI를 여러 개 추가해 길게 만든다). ② 미리보기를 **아래로 스크롤**해 중간쯤을 보고 있는 상태로 둔다. ③ 트리에서 UI 하나를 골라 오른쪽 속성 값 하나를 바꾼다(예: 글자 값). ④ 상단 **되돌리기**를 누른다. ⑤ **화면 전체가 지워졌다 다시 그려지는 깜빡임이 없고**, 보고 있던 스크롤 자리가 그대로인지 확인. | ✅ O |
| BR62-10 | 페이지가 여러 개인 앱에서 **보던 페이지가 유지**되는지 | ① 페이지가 2개 이상인 앱을 연다. ② 첫 페이지가 아닌 **다른 페이지**의 UI를 트리에서 골라 속성 값을 바꾼다. ③ 상단 **되돌리기**를 누른다. ④ 미리보기가 **첫 페이지로 갔다가 돌아오는 일 없이**, 보던 그 페이지에 그대로 있는지 확인. | ✅ O |
| BR62-11 | ★**같은 부모 안에서 자리 옮기기** 되돌리기 — UI가 두 개로 늘지 않는지 | ① 한 부모 밑에 형제 UI가 2개 이상 있게 만든다(예: 버튼 2개). ② 그중 하나를 **우클릭** → 메뉴에서 **위 화살표가 붙은 이동 항목(Up)** 을 눌러 자리를 올린다. ③ 미리보기에서 순서가 바뀐 것을 확인한다. ④ 상단 **되돌리기**를 누른다. ⑤ **미리보기에서 그 UI가 원래 자리로 돌아오고**, 같은 UI가 **두 군데 겹쳐 보이거나 하나 더 생기지 않는지** 확인. | ✅ O |
| BR62-12 | ★**다른 부모로 옮기기(끌어놓기)** 되돌리기 — 옛 자리에 안 남는지 | ① 상자·페이지처럼 자식을 담을 수 있는 UI를 2개 만든다. ② 한쪽에 있는 UI를 **끌어서** 다른 쪽 안으로 놓는다. ③ 미리보기에서 옮겨간 것을 확인한다. ④ 상단 **되돌리기**를 누른다. ⑤ **원래 부모 자리로 돌아오고**, 옮겼던 쪽에 **그대로 남아 있지 않은지**(같은 UI가 두 군데 보이지 않는지) 확인. | ✅ O |
| BR62-13 | **되돌리는 동안 화면이 잠기는지** | ① 트리에 UI가 여러 개 있는 앱을 연다. ② 아무 편집이나 한 번 한다(예: 속성 값 변경). ③ 상단 **되돌리기**를 누르고 **곧바로** 트리의 다른 줄을 클릭하거나 줄 오른쪽 `+` 버튼을 눌러 본다. ④ 되돌리기가 끝날 때까지 **화면이 잠겨 클릭이 안 먹고**, 끝난 뒤에는 **정상적으로 다시 클릭이 되는지**(계속 잠겨 있으면 안 됨) 확인. | ✅ O |
| BR62-14 | 속성 값 되돌리기에서 **그 UI만** 바뀌는지 | ① 미리보기에 UI가 여럿 보이는 상태로 둔다. ② 그중 한 UI의 속성 값을 바꾼다(예: 글자 값). ③ 상단 **되돌리기**를 누른다. ④ **바꿨던 그 UI의 값만 원래대로 돌아오고**, 다른 UI들은 다시 그려지며 깜빡이지 않는지 확인. ⑤ 상단 **다시하기**를 눌러 값이 다시 바뀌는지도 확인. | ✅ O |

## 되돌린 뒤 "그 작업이 건드린 UI" 재선택 배선 (2026-08-21 통과)

원본 되돌리기는 **모든 작업이 그 작업의 대상 UI를 다시 선택**한다(이동=옮긴 UI / 추가·붙여넣기=만들어진 UI /
끌어놓기=끌었던 UI / 속성값=값 바뀐 UI와 그 속성 줄 / 삭제만 예외로 선택 유지→부모→최상위).
HTML5 는 되돌릴 때 트리를 통째로 갈아끼우므로 "무엇을 다시 선택할지"를 정해야 하는데,
그 대상을 한 번도 기록하지 않아(기록 조건이 막혀 있어 사문화) **편집 직전에 선택돼 있던 줄**로 돌아갔다.
→ 각 편집 경로가 자기 대상 UI를 기록하도록 배선. 이름이 편집 도중 만들어지는 경로(추가·붙여넣기·패턴 적용·
마법사)는 이름이 정해진 뒤 **자기 기록에 직접** 새긴다(중간에 화면 그리기 대기가 있어 남의 기록에 새겨지는 것 방지).

- 반영: `ws_html5_ws20_edit.js`, `ws_html5_ws20_dnd.js`, `ws_html5_ws20_attr.js`,
  `ws_html5_ws20_attr_ctxmenu.js`, `ws_html5_ws20_wizard.js`, `fnBindPopupOpen.js`, `fnSameAttrSyncPopupOpen.js`
- 원본 참조: `design/undoRedo/undoRedo.js` 작업별 처리, `design/js/callDesignContextMenu.js` 이동 처리
- 곁들여: 되돌리기 시 속성 줄의 파란 선택 강조 제거(장군님 지시 — 원본과 의도적으로 다름),
  이름 바꿀 때 트리 선택·펼침 상태 유실 수정
- 선택 대상 판정 규칙 7가지 상황 자체 검증 전건 통과. 문법 검사 통과.
- ※ 아래 항목은 BR59 작업 중 함께 확인돼 옛 번호(BR59-10~16)로 통과했다. 범위가 달라 BR62 로 귀속한다.
