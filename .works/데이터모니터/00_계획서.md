## 1. 목적

장군님은 "화면에서 이 값을 바꾸면 내부 오브젝트 어디어디가 바뀌어야 한다"를 이미 알고 계신다.
**실제로 그렇게 도는지 눈으로 확인**하기 위한 개발자 전용 도구.

- 도구는 **옳고 그름을 판정하지 않는다.** 실제로 바뀐 것만 빠짐없이 보여준다.
- 최근 화면 값과 내부 값이 어긋난 사례가 있었고, 내부가 안 보여 원인 추적이 오래 걸렸다.

## 2. 확정된 것 (실측 근거)

### 2.1 감시 범위

| 대상 | 포함 |
|---|---|
| `oAPP.attr` | **공통코드(`S_CODE`) 만 빼고 전체** |
| `oAPP.DATA` | **라이브러리 원장(`LIB`) 만 빼고 전체** |

뺀 두 개는 **서버에서 받아 앱 여는 동안 안 바뀌는 것**이고 덩치가 크다(공통코드 133만자 · 라이브러리 원장 919만자).
체크로 켤 수 있게만 만들어 두고 **기본은 꺼둔다**(장군님 지시 2026-09-09).

### 2.2 감지 방식 = 사진 두 장 비교

1. 조작(클릭·값바뀜·키 뗌·끌어놓기)이 들어오면
2. 앱 처리가 끝나도록 **한 박자 미룬 뒤**
3. 대상을 다시 떠서 **직전 사진과 재귀 비교**
4. 다른 자리만 화면에 뿌리고, 새 사진으로 갈아끼움

**앱 코드는 0줄 고친다.** 감시 껍데기(Proxy)도, 감시문(defineProperty)도 안 쓴다.

### 2.3 실측치 (2026-09-09 · 원격 디버그 9222 · 설치본 `com.u4a_ws3.app` 3.6.4 · WS20 앱 1건 연 상태)

| 감시 범위 | 사진 글자수 | 사진 1회 | 비교 | **총 왕복** |
|---|---|---|---|---|
| `attr` 전체 + `DATA` 전체 (아무것도 안 뺌) | 11,016,658 | 24~30ms | 57.5ms | **81.6ms** |
| `attr` 전체 + `DATA`(라이브러리 제외) | 1,821,377 | 6~8ms | 10ms | 16.1ms |
| **`attr`(공통코드 제외) + `DATA`(라이브러리 제외)** ← 채택 | **485,783** | **2~4ms** | **6.6ms** | **8.4ms** |

아무것도 안 뺐을 때 대비 **사진 크기 23분의 1, 시간 10분의 1**.

같은 상태끼리 비교 시 차이 0건 — 비교 로직 정상 동작 확인.

`oAPP.attr` 안 덩치 순: `S_CODE` 133만자 · `prev` 38만자 · `UA015UI` 31만자 · `ui` 13만자 · `popup` 9.4만자 · `oModel` 9.3만자 · 나머지 27칸은 각 1.2만자 이하.

`oAPP.DATA.LIB` = 658,419칸 / 919만자 / 24ms → **뺀 이유.** 앱 여는 동안 안 바뀐다.

### 2.4 베끼기·비교 규칙 (그대로 구현)

```js
function snap(v, d, seen) {
    if (v === null || typeof v !== "object") { return v; }
    if (typeof v === "function") { return undefined; }       // 함수는 버림
    if (d > 12) { return "[깊이초과]"; }
    if (seen.has(v)) { return "[이미본것]"; }                 // 빙빙 도는 참조 막기
    if (v.nodeType || v.window === v) { return "[화면요소]"; } // 화면·창은 안 담음
    seen.add(v);
    var o = Array.isArray(v) ? [] : {};
    var ks = Object.keys(v);                                  // ★ 자기 것만 (물려받은 것 제외)
    for (var i = 0; i < ks.length; i++) {
        try { o[ks[i]] = snap(v[ks[i]], d + 1, seen); }
        catch (e) { o[ks[i]] = "[읽기실패]"; }
    }
    return o;
}
```

★ `Object.keys` 가 핵심. 처음에 `for...in` 으로 짰더니 물려받은 것까지 담아 변경 원장이 83,732칸으로 부풀었다.
`Object.keys` 로 바꾸니 17,731칸. **5배 차이.**

`JSON.parse(JSON.stringify(...))` 는 안 쓴다 — 빙빙 도는 참조에서 터지고 화면 요소를 못 다룬다.

### 2.5 별도 창 구조 (P1 = ① 일 때)

별창은 부모 창의 `oAPP` 을 직접 못 읽는다(별창은 신호로 데이터를 받는 구조 — `webContents.send`, [monacoThemeDesign/index.js:120](../../www/ws30/ws10_20/Popups/monacoThemeDesign/index.js)).

따라서:

- **사진 뜨기·비교는 부모 창에서 한다** (거기 데이터가 있으니까)
- **결과(바뀐 것 목록)만 별창에 신호로 보낸다** — 사진 자체(182만자)는 보내지 않는다
- **화면 부품 안은 우리가 만든 칸만 본다**(장군님 지시 2026-09-10).
  `oAPP.attr.prev` 는 UI ID 마다, `oAPP.attr.ui` 는 화면 짜임 그대로 **같은 부품을 두 군데**에 들고 있다.
  그 안의 밑줄 칸 대부분은 UI5 가 자기용으로 쓰는 것이라 걸러내지 않으면 잡음이 두 배가 된다.
  **우리 칸은 그대로 두므로 두 군데가 같이 바뀌는 것은 계속 보인다**(그게 맞는 동작 — 장군님 확인 2026-09-10).
  가르는 법 = 자기 칸에 `mProperties` 와 `mAggregations` 가 있고 UI5 물건 표시가 있으면 화면 부품.
  **모델은 이 칸이 없어 안 걸린다** — 모델 안(`oData`)은 지금처럼 다 본다(실측 확인).
  실측 2026-09-10 = 부품 하나당 밑줄 칸 16~33개 중 앱 소스에 나오는 것은 5~6개뿐.
  나머지는 화면을 다시 그릴 때마다 값이 바뀌어 누를 때마다 쓸데없는 줄만 쏟아진다.
  **보는 칸** = `_T_0015` · `_MODEL` · `_BIND_AGGR` · `_OBJID` · `__PARENT` · `_EMBED_AGGR` · `__UIFND`.
  `__PARENT` 는 윗 부품이 통째로 들어 있어 그 UI ID 만 남긴다(안 그러면 그 부품 속이 다 딸려 온다).
  UI ID 자체는 비어 있어도 남겨 UI 가 생기고 없어진 것은 계속 잡는다.
  → 사진 크기 **48만자 → 10만자**(2026-09-10 실측).
- **지운 것은 두 뷰 모두 화면에 안 띄운다**(장군님 결정 2026-09-10).
  리스트 뷰·트리 뷰는 같은 것을 보는 두 방식이므로 동작이 달라선 안 된다.
  트리 뷰는 지금 모습을 그리는 것이라 지워지면 줄이 사라지는 것으로 충분하고, 리스트 뷰도 그에 맞춘다.
  → **줄을 안 쌓고, 종류 걸러내기에서도 `없어짐` 을 뺀다.**
  단 **받아 둔 덩어리에는 그대로 반영한다** — 안 빼면 트리가 지워진 값을 계속 들고 있어 어긋난다.
- **트리 뷰용 덩어리는 처음 한 번만 통째로 받는다**(장군님 지시 2026-09-10).
  그 뒤로는 바뀐 것 목록에 실린 **자리 조각 + 진짜 새 값**으로 창이 그 자리만 덮어쓴다.
  통째로 다시 받는 것은 두 경우뿐 — 바뀐 곳이 너무 많아 목록이 잘렸을 때, 값을 창끼리 못 넘겼을 때.

## 5. 안 하는 것 · 못 하는 것

| 항목 | 이유 |
|---|---|
| 감시 껍데기(Proxy) | 앱이 그 자리를 통째로 갈아끼우는 곳이 있어 감시가 끊긴다(변경 원장 8군데·APP 정보 5군데·서버 원자료 2군데). 껍데기는 한 겹만 잡고, 깊은 곳을 잡으려면 자식까지 감싸야 해 앱이 쥐는 값이 전부 바뀐다. APP 정보 세 곳이 같은 물건을 가리켜야 정상인 구조가 깨진다 |
| 감시문(`defineProperty`) | 배열에 줄이 새로 들어오는 걸 못 잡는다. 보고 싶은 것 상당수가 배열 안 |
| 조작 없이 저 혼자 바뀌는 값 | 조작으로 안 잡힌다 → **[지금 비교] 버튼**으로 확인 |
| 미리보기 안 · 별창 안 데이터 | 다른 문서라 조작이 안 올라온다. 필요해지면 그때 붙인다 |
| 되돌리기 쌓인 장수 | 파일 안에 숨어 있어 밖에서 못 본다([ws_html5_ws20_edit.js:184](../../www/ws30/ws10_20/js/ws_html5_ws20_edit.js)). 보시려면 그 파일에 내보내는 줄 하나 여는 별도 작업 필요 — **지시 주시면 그때** |
| 라이브러리 원장 · 공통코드 | 기본 꺼둠(장군님 지시 2026-09-09). 서버에서 받아 앱 여는 동안 안 바뀌는데 둘이 사진의 대부분을 차지한다. 체크로 켤 수 있게만 |
