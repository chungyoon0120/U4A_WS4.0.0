# 3.0 에서 4.0 으로 보내기 — 그 자리에서 돌릴 코드

작성 2026-09-11 · 갱신 2026-09-11 (심을 파일 한 덩이로 정리)
설계 = [01_버전간_데이터비교_설계.md](01_버전간_데이터비교_설계.md)

## ★ 이 화면은 무엇을 하는 것인가

**3.0 과 4.0 에서 같은 조작을 했을 때, 두 프로그램이 들고 있는 데이터 구조가 같은지 다른지 눈으로 맞대 보는 것.**

| 뷰 | 무엇을 보나 | 감시 시작 |
|---|---|---|
| **리스트 뷰** | 4.0 에서 조작할 때마다 바뀐 자리가 줄줄이 쌓인다 | **필요함** |
| **트리 뷰** | 4.0 의 데이터 전부를 펼쳐 보고, 바뀐 자리에 표시 | **필요함** |
| **비교 뷰** | **3.0 것(좌) ↔ 4.0 것(우)** 을 나란히 놓고 다른 자리를 찾는다 | **필요 없음** |

### ★ 비교 뷰에서는 **감시 관련 조작이 아예 안 보인다**

- **감시 시작**은 "조작할 때마다 뭐가 바뀌었나" 를 쌓는 것이다 — 리스트 뷰·트리 뷰용이다.
- 비교 뷰는 **버튼을 누른 그 순간의 데이터 구조**를 통째로 떠서 맞대 본다. 쌓아 둔 것이 필요 없다.
- 4.0 쪽은 **[4.0 지금 담기]**, 3.0 쪽은 **[3.0 → 4.0 보내기]** — 둘 다 **누른 그 순간**을 뜬다.
- 그래서 비교 뷰로 가면 **[감시 시작]·[지금 비교]·[기록 지우기]·감시 상태 글자·감시 범위 체크가 전부 숨는다.**
  남는 것 = **뷰 전환 3개 · [4.0 지금 담기] · [다른 것만]** 뿐이다.
- 감시 범위(공통코드·라이브러리)도 숨긴다 — 비교 뷰에서 범위를 넓히면 **4.0 쪽만 커져** 3.0 에 없는 자리가 전부 다름으로 나온다.

## ★ 하는 순서 (비교 뷰)

| # | 어디서 | 할 것 |
|---|---|---|
| ① | 4.0 | **테스트 메뉴 > 데이터 모니터** 를 열고 **비교 뷰** 를 누른다 |
| ② | 4.0 | **오른쪽 끝**에 **9999 열림 - 3.0 에서 보내십시오** 가 보이는지 확인 (안 보이면 자리를 못 연 것) |
| ③ | 3.0 | WS10 화면까지 간 뒤 **[03_3.0에_심을_수집코드.js](03_3.0에_심을_수집코드.js)** 를 심는다 |
| ④ | **양쪽** | **같은 조작**을 각각 한다 (예: 앱이름 작성 후 편집모드 진입) |
| ⑤ | 3.0 | **3.0 → 4.0 보내기** 를 누른다 |
| ⑥ | 4.0 | 왼쪽에 3.0 것이 뜬다. **오른쪽(4.0)도 그때 같이 담긴다** |
| ⑦ | 4.0 | **다른 것만** 을 켠다 → 어긋난 자리만 남는다 |

### 다시 해 볼 때

- 양쪽에서 **다음 조작**을 한 뒤, 3.0 에서 **보내기**만 다시 누르면 양쪽이 새로 담긴다.
- 4.0 쪽만 다시 담고 싶으면 **[4.0 지금 담기]** 를 누른다.

### 오른쪽 끝 글자가 알려 주는 것

| 글자 | 뜻 |
|---|---|
| **9999 열림 - 3.0 에서 보내십시오** | 받을 준비됨. 아직 3.0 것이 안 왔다 |
| **어긋난 자리 N곳** | 양쪽 다 담겼고, 다른 자리가 N곳이다. **0곳이면 구조가 같다** |
| **9999 을 못 열었습니다** | 자리를 못 열었다. 다른 것이 그 번호를 쓰고 있는지 본다 |

### 좌우 머리 글자

| 표시 | 뜻 |
|---|---|
| **3.0 · 받음 시각 / 뿌리 N개** | 3.0 것이 그 시각에 도착했다 |
| **4.0 · 담음 시각 / 뿌리 N개** | 4.0 것을 그 시각에 떴다 |

### ★ 어긋난 자리로 바로 가기

어긋난 자리가 수천 곳이라 손으로 훑을 수 없다. 위쪽 줄의 단추로 **한 곳씩 옮긴다.**

| 조작 | 하는 일 |
|---|---|
| **아래 화살표** 단추 / **F3** | 다음 어긋난 자리로. 끝나면 처음으로 돈다 |
| **위 화살표** 단추 / **Shift+F3** | 이전 어긋난 자리로 |
| 그 옆 숫자 | 지금 **몇 번째 / 모두 몇 곳** |
| **모두 접기** | 좌우를 전부 접는다 |

- **좌우가 같은 자리에 함께 선다.** 가는 길도 자동으로 펼쳐진다.
- 한쪽에만 있는 자리면 그 쪽만 선다.
- 이동 목록에는 **어긋남의 꼭대기만** 들어간다 — 한쪽에만 있는 큰 덩어리의 자손까지 넣으면 수천 번 눌러야 다음 덩어리로 간다.

### 오른쪽 끝 숫자

**다름 N · 3.0만 N · 4.0만 N (총 N곳)** — 종류별로 몇 곳인지 바로 보인다.

### 펼침 규칙

| 때 | 어떻게 |
|---|---|
| 담은 직후 | **전부 접힘** (뿌리까지) |
| **다른 것만** 켬 | **어긋난 것이 아래에 있는 자리까지** 펼쳐진다. 어긋난 자리 자체는 안 펼친다. **좌우가 똑같이** 펼쳐진다(같은 어긋남 목록을 보므로) |
| **찾기** 켬 | **걸린 자리까지 길을 전부 연다.** [다른 것만] 보다 **먼저** 먹는다 |

★ 걸러내기를 건드리면(찾기 글자를 치거나 **다른 것만**을 켜고 끄면) **손으로 접어 둔 기록을 비운다.**
안 비우면 접어 둔 자리 아래에 찾은 것이 있어도 안 보인다.
**Enter 를 치면 글자가 그대로여도 다시 걸린다** — 중간에 접어 둔 것이 있어도 그때 다시 펼쳐진다.

### 좌우 각각 찾기

각 쪽 머리줄 오른쪽에 **찾기 (이름·값)** 칸이 있다. **그 쪽만** 좁혀진다(반대쪽은 그대로).

- **이름과 값을 모두 본다. 깊이 제한 없다** — 담아 온 데이터 전부를 본다.
- **걸린 줄은 색으로 표시된다.** 머리줄에 **찾음 N곳** 이 나온다.
- 걸린 자리와 **거기까지 가는 길**이 남고, **걸린 자리 아래는 통째로** 보인다.
- **다른 것만** 과 같이 켜면 **둘 다 만족하는 자리**만 남는다.
- 칸 오른쪽 **X** 를 누르면 지워진다.

### 좌우 펼침은 따로 움직인다

왼쪽을 펼쳐도 오른쪽은 그대로다. **누른 쪽만** 펼쳐지고 접힌다.

### 수집에서 아예 빼는 것

| 뺀 것 | 왜 |
|---|---|
| `APPID` · `GUINR` | 앱마다·열 때마다 값이 달라 늘 「다름」으로 나온다. 그것 때문에 진짜 어긋난 자리가 묻힌다. **깊이와 상관없이** 이 이름이면 안 담는다 |

### ★ 차이로 나와도 「잘못」이 아닌 자리 (소스로 확인, 2026-09-11)

| 자리 | 왜 늘 다른가 |
|---|---|
| `oAPP.attr.ui` | **3.0 은 UI5 부품**을 담고, **4.0 은 화면 요소**(`document.getElementById` 로 잡은 것)를 담는다. 담는 물건 자체가 다르다 — HTML5 로 바꾸면서 그렇게 된 것이고 앱 로직 잘못이 아니다 |
| `DnDRandKey` | 그때그때 새로 만드는 값이라 누를 때마다 다르다 |
| `oCore` · `oArea` | UI5 가 들고 있는 물건이라 담기는 내용이 양쪽에서 다를 수 있다 |
| 줄 **순서** | 왼쪽·오른쪽 줄 순서가 달라도 **차이가 아니다.** 비교는 **이름으로** 견주지 순서를 안 본다 |

### ★★ 먼저 볼 것 — 두 쪽이 **같은 앱**을 연 것이 맞는가

`APPID` 가 서로 다르면 **그 아래가 전부 다르게 나온다.** 어긋난 자리가 수천 곳이면
거의 이 경우다. 양쪽에서 **같은 앱 이름**으로 들어갔는지부터 본다.

### 줄 색

| 색 | 뜻 |
|---|---|
| 노란 띠 | **값이 서로 다른 자리** |
| 붉은 띠 | **한쪽에만 있는 자리** |

## 심을 것 = 파일 하나

**[03_3.0에_심을_수집코드.js](03_3.0에_심을_수집코드.js)** — 이 파일 하나면 끝이다.

- 앞부분 = **4.0 의 수집 코드 그대로.** 글자 하나 안 고쳤다(대조 확인함).
  수집 규칙이 조금이라도 다르면 두 프로그램을 비교하는 뜻이 없어진다.
- 뒷부분 = **보내는 부분**(3.0 전용).

### 심는 방법 — 둘 중 하나

**① 붙여 넣기 (지금 바로)**
3.0 의 WS10/WS20 화면에서 개발자 도구 Console 을 열고, 위 파일 내용을 **통째로 복사해 붙여 넣는다.**

**② 파일로 얹기 (계속 쓸 때)**
3.0 의 파일 로드 목록(`www/ws30/ws10_20/js/library-preload.js`) **맨 뒤**에 이 파일을 더한다.
목록 형식은 4.0 과 같다(주소 + 종류). 맨 뒤에 두는 이유는 앞에 두면 이 파일이 없을 때 뒤따르는 파일이 안 실려 화면이 통째로 죽기 때문이다.

### 심고 나면

- 화면 오른쪽 아래에 **3.0 → 4.0 보내기** 단추가 생긴다.
- 콘솔에 `[DM30] INFO READY` 가 찍힌다.
- **★ 감시는 켜지지 않는다.** 3.0 은 **부르는 그 순간**의 데이터 구조를 떠서 보내기만 한다.
  조작할 때마다 3.0 안에서 비교를 돌릴 필요가 없다.

### 콘솔에서 쓰고 싶을 때

| 적을 것 | 하는 일 |
|---|---|
| `DM30.send()` | **그 순간**의 데이터 구조를 떠서 4.0 으로 보낸다 |

바깥에 여는 것은 **이 하나뿐**이다.

### 무엇을 보내나

**데이터 구조 한 벌 전체** — 그것뿐이다. 비교 화면이 그리는 것이 이것이다.
3.0 에서만, 앱 모델 `oData` 에 UI5 Core 모델 `oData` 를 합쳐서 보낸다
(4.0 은 하나로 들고 있어 그래야 모양이 같아진다). 겹치는 이름은 **앱 모델 값이 이긴다**.

|---|---|
| 단추를 눌러도 **보내기 실패** | 4.0 데이터 모니터 창이 떠 있는지. 그 창 개발자 도구에 `COMPARE_PORT_LISTEN_FAILED` 가 있으면 9999 을 이미 다른 것이 쓰고 있다 |

| 4.0 화면에 아무 변화 없음 | 4.0 창 개발자 도구에 `SNAPSHOT_FROM_3_0 received` 가 찍히는지 본다 |
