## 3. 소스로 확인한 사실 (2026-09-11 조회)

### 3.1 유리한 점

| # | 사실 | 어디서 |
|---|---|---|

| F2 | 3.0 에도 **같은 형식의 파일 로드 목록**이 있다 → 감지 파일을 목록 맨 뒤에 얹는 방식 그대로 쓸 수 있다 | 3.0 `library-preload.js` |
| F3 | **express 5.2.1 이 3.0·4.0 양쪽에 이미 들어 있다** → 새로 설치할 것 없음 | 양쪽 `package.json` |

| F6 | 감지 파일은 **파일 하나**에 모여 있고 **앱 코드를 한 줄도 안 고친다**(snapshot 두 장 재귀 비교) | 파일 머리말 |
| F7 | 감지 대상 = `oAPP.attr`(공통코드 제외) + `oAPP.DATA`(라이브러리 원장 제외). 실측 snapshot 약 **48만자 / 한 번 왕복 8.4ms** | 파일 상수 · 계획서 §2.3 |
| F8 | 조작 감지는 document 에 **DOM event 30개**를 걸고, 조작 뒤 **200ms → 800ms 두 번** 비교한다 | 파일 상수 |

| **F10** | 감지가 넘겨주는 한 묶음에는 **번호 · 시각 · 언제 · 조작 · 걸린시간 · 잘림 · 변경 목록**이 들어 있고, 변경 한 줄에는 **자리 · 종류 · 이전 값 · 새 값**이 들어 있다 | 감지 파일 |
| **F11** | 그 묶음은 이미 안전하게 다듬어진 값이라 **글자로 바꿔 보내는 데 문제 없다.** 다만 한 줄마다 원래 값을 통째로 물고 있는 칸이 있어 **보내기 전에 그 칸은 빼는 편이 좋다**(덩치) | 감지 파일 |

## 4. 지금까지 잡힌 흐름

```
[3.0]  실행 중인 WS10·WS20 화면에서
        └ 감지 코드를 그 자리에 붙여 돌림  →  감시 켬  →  보내기 버튼도 그 자리에 만듦
             │
             │  조작 (예: WS10 에서 앱이름 작성 후 편집모드 진입)  →  변경 내용이 쌓임
             │
             │  [보내기] 누름
             ▼
           HTTP  localhost:9999
             │
             ▼
[4.0]  데이터 모니터 창 열기  →  9999 열림  →  3.0 것 받아서 담아 둠
        같은 조작을 4.0 에서도 수행  →  4.0 것이 쌓임
             │
             ▼
        3.0 것 ↔ 4.0 것 비교  (같은 path 가 같은 종류로 생기고·바뀌고·없어졌나)
             │
             ▼
   화면:  [ 좌 = 3.0 JSON viewer ] │ [ 우 = 4.0 JSON viewer ]
                  차이분이 없는지 확인
```

**3.0 쪽에 만드는 것 = 없다.** 소스도 안 고치고 파일도 안 만든다. 그 자리에서 돌릴 코드 한 덩이면 된다.

**4.0 쪽에 만드는 것 = 셋뿐이다.**

| # | 만들 것 | 어디에 |
|---|---|---|
| 1 | 9999 을 여는 부분 (데이터 모니터 창 열 때 같이 올린다) | 4.0 |
| 2 | 받은 것을 담아 두는 부분 | 4.0 |
| 3 | 좌우 비교 화면 (좌 3.0 · 우 4.0, JSON viewer) | 4.0 데이터 모니터 창 |
