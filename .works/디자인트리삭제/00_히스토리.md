# Design Tree UI 삭제 — 완료 히스토리

## 2026-08-17 — BR40 UI 삭제 시 설명글(Description·T_DESC) 잔존 (전 항목 통과)

UI 를 클릭하면 오른쪽 속성 정보 영역에 뜨는 **Description** 입력칸에 설명글을 적고 그 UI 를 지우면,
화면 트리·미리보기·내부 속성목록에서는 지워지는데 **설명 저장소(`oAPP.DATA.APPDATA.T_DESC`)** 에는
지운 UI(및 함께 지워진 자식 UI)의 설명이 남던 문제.

원본 UI5 삭제 함수(`uiDesignArea.js:6651`·`4375`)가 노드마다 설명 지우는 처리(`delDesc`)를 부르는데,
이 함수가 HTML5(UI5 전용 파일 미로드)에 이식 누락돼 있었음. 함수를 원본 1:1(`uiAttributeArea.js:7783`)로
이식하고, 삭제 공통 정리 두 곳(본인 `_removeNodePreview`·자식 재귀 `_purgePrevSubtree`)에 배선 —
단건·여러 개(체크) 삭제 모두, 상위+하위 전부 정리, 무관 UI 유지.

수정 파일: `js/ws_html5_ws20_attr.js`(신규 `delDesc` 이식), `js/ws_html5_ws20_edit.js`(삭제 2경로 배선).
백업: `_ws_html5_ws20_attr.js.br40bak`, `_ws_html5_ws20_edit.js.br40bak`.
검수: 코덱스·안티 둘 다 P1 하나 동일(함수 본체 부재)로 지적했으나, 재확인 결과 함수는 현재 파일에 정상 존재
(검수본은 병행세션이 일시 되돌린 옛 상태). 나머지(재귀 커버리지·삭제 경로 한정·되돌리기·멱등·원본 1:1·메모리 무위험) 양측 통과.

| 코드 | 동작 | O/X |
|---|---|---|
| DD1 | 설명글 적은 UI 를 지우면 그 설명이 저장소에서 사라짐 | ✅ O |
| DD2 | 부모 UI 를 지우면 함께 지워진 자식 UI 의 설명도 저장소에서 사라짐 | ✅ O |
| DD3 | 삭제한 UI 와 무관한 다른 UI 의 설명은 그대로 남음 | ✅ O |
| DD4 | 여러 개(체크) 한꺼번에 삭제해도 각 UI 의 설명이 저장소에서 사라짐 | ✅ O |

## 2026-08-17 — BR41 UI 삭제 시 클라이언트 이벤트·HTML 내용(T_CEVT) 잔존 (전 항목 통과)

UI 이벤트에 클라이언트 이벤트 코드(JavaScript)를 넣거나 `sap.ui.core.HTML` UI 의 내용(content)을 넣은 뒤
그 UI 를 지우면, 화면 트리·미리보기·내부 속성목록에서는 지워지는데 **이벤트·내용 저장소(`oAPP.DATA.APPDATA.T_CEVT`)**
에는 지운 UI 정보(이벤트 `JS`·내용 `HM`)가 남던 문제. 부모를 지워 자식이 함께 지워질 때 자식 정보도 남았음.

원본 UI5 삭제 함수(`uiDesignArea.js:2034` `delUiClientEvent`)가 노드마다 T_CEVT 를 정리하는데, 이 함수가
HTML5(UI5 전용 파일 미로드)에 이식 누락돼 있었음. 함수를 원본 1:1 이식하고 삭제 공통 정리 두 곳(본인·자식 재귀)에
배선 — 단건·여러 개(체크) 삭제 모두, 상위+하위 전부 정리, 무관 UI 유지. 내부 속성목록(`_T_0015`) 참조라 그 목록
삭제 전에 부르도록 순서 맞춤(원본과 동일).

수정 파일: `js/ws_html5_ws20_edit.js`(신규 `delUiClientEvent` 이식 + 삭제 2경로 배선). 백업: `_ws_html5_ws20_edit.js.br41bak`.
검수: 코덱스·안티 둘 다 통과·필수지적0. 안티 제안2(삭제 호출부 조용한 catch→오류 표면화)만 반영, 제안1·3은 반론.

| 코드 | 동작 | O/X |
|---|---|---|
| DE1 | 클라이언트 이벤트(JavaScript) 넣은 UI 를 지우면 그 이벤트 정보가 저장소에서 사라짐 | ✅ O |
| DE2 | 부모 UI 를 지우면 함께 지워진 자식 UI 의 이벤트 정보도 저장소에서 사라짐 | ✅ O |
| DE3 | `sap.ui.core.HTML` UI 의 내용(content)을 넣고 지우면 그 내용 정보가 저장소에서 사라짐 | ✅ O |
| DE4 | 여러 개(체크) 한꺼번에 삭제해도 각 UI 의 이벤트·내용 정보가 저장소에서 사라짐 | ✅ O |

## 2026-08-13 — BR26 부모 UI 삭제 시 하위 UI 정보(oAPP.attr.prev) 잔존 (전 항목 통과)

부모 UI(예: HBOX3)를 지우면 화면·미리보기에선 하위 버튼까지 사라지나, 내부 저장정보(`oAPP.attr.prev`)엔
하위 버튼과 각 속성정보가 남아 화면과 내부 상태가 어긋나던 문제.

원본 단건 삭제 함수(`uiDesignArea.js` `designUIDelete`의 재귀 정리부)가 자식부터 재귀로 내부 저장정보를
모두 지우는데, HTML5는 삭제한 최상위 하나만 지웠던 것. 자식 재귀 정리(`_purgePrevSubtree`)를 신규 추가해
단건 삭제·여러 개(체크) 삭제 두 경로에 배선.

수정 파일: `js/ws_html5_ws20_edit.js`(신규 `_purgePrevSubtree` + 단건·멀티 삭제 배선). 백업: `_ws_html5_ws20_edit.js.br26bak`.
검수: 안티 지적(멀티 경로 배선) 반영 / 코덱스 P1(이벤트·설명·바인딩·팝업 수집정보 정리)은 선재·광범위 결손이라 반론→별도 이슈 권고.

| 코드 | 동작 | O/X |
|---|---|---|
| DT1 | 우클릭 "삭제"로 자식 있는 부모를 지우면 하위 UI 정보도 콘솔에서 사라짐 | ✅ O |
| DT2 | 3단 이상 깊은 구조도 손자까지 정보가 안 남음 | ✅ O |
| DT3 | 트리 위 휴지통 버튼으로 체크 삭제해도 하위 정보가 안 남음 | ✅ O |
