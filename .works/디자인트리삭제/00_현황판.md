# Design Tree UI 삭제(BR26) — 테스트 현황판

> 코드 반영은 **앱을 껐다 켜야** 적용됩니다(새로고침 아님).
> BR26은 화면·미리보기엔 안 보이고 **내부 저장 정보**에만 남던 문제라, 확인은 **개발자도구(F12) 콘솔**에서
> `oAPP.attr.prev` 를 조회해 삭제한 UI가 목록에 남아 있는지로 판정합니다(테스터 계측과 동일 방식).

## 지금 할 것 — BR26 부모 UI 삭제 시 하위 UI 정보 잔존

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| DT1 | 우클릭 "삭제"로 자식 있는 부모를 지우면 하위 UI 정보도 함께 사라짐 | ① WS20에서 UI를 추가/삭제할 수 있는 편집 상태로 둔다. ② 왼쪽 Design Tree의 PAGE 아래에 HBox 3개를 추가한다. ③ 그 중 세 번째 HBox(HBOX3) 아래에 Button 3개를 추가한다. ④ 각 Button을 골라 text(글자)를 아무거나 다르게 바꾼다. ⑤ 트리에서 HBOX3 줄을 **우클릭** → 뜨는 메뉴에서 **"삭제"**(휴지통 그림)를 누른다. ⑥ 확인 창이 뜨면 **예/OK**를 누른다. ⑦ 트리·오른쪽 미리보기에서 HBOX3과 그 아래 Button 3개가 모두 사라졌는지 본다. ⑧ **F12**로 개발자도구 → **Console** 탭에서 `oAPP.attr.prev` 입력 후 Enter. ⑨ 목록에 삭제한 **BUTTON1·BUTTON2·BUTTON3 항목이 없어야** 한다(전에는 남았음). | ☐ |
| DT2 | 3단 이상 깊은 구조도 손자까지 정보가 안 남음 | ① 편집 상태에서 PAGE 아래 HBox 1개(HBOX1)를 추가한다. ② HBOX1 아래에 HBox 1개(HBOX2)를 추가한다. ③ HBOX2 아래에 Button 2개를 추가한다. ④ 트리에서 **HBOX1**을 우클릭 → **"삭제"** → 확인 창 **예/OK**. ⑤ 트리·미리보기에서 HBOX1·HBOX2·Button들이 모두 사라졌는지 본다. ⑥ 개발자도구 Console에서 `oAPP.attr.prev` 조회 → 삭제한 **HBOX2와 그 아래 Button 항목이 없어야** 한다(손자까지 정리). | ☐ |
| DT3 | 체크로 여러 개 삭제해도 하위 정보가 안 남음(정상 삭제 회귀 확인) | ① 편집 상태에서 PAGE 아래 HBox 1개(HBOX1)를 추가하고, HBOX1 아래에 Button 2개를 추가한다. ② 트리 각 줄 왼쪽 **체크상자**에서 **HBOX1**을 체크한다(체크하면 그 아래 Button도 같이 체크됨). ③ 트리 위 **도구모음의 휴지통 그림 버튼**(안내문구 "Delete")을 누른다. ★줄을 우클릭해 나오는 "삭제"와는 다른, 트리 상단 버튼이다. ④ 확인 창이 뜨면 **예/OK**. ⑤ 트리·미리보기에서 HBOX1과 Button들이 사라졌는지 본다. ⑥ 개발자도구 Console에서 `oAPP.attr.prev` 조회 → 삭제한 **HBOX1·Button 항목이 없어야** 한다. | ☐ |
