### 그룹 BR64 — 잘못된 Conversion Routine 이 D&D 바인딩에 적용되던 것 차단
> 대상 = **바인딩 팝업**. 없는 Conversion Routine(예: 한글)을 넣어 입력칸이 빨갛게 오류 난 상태에서
> **바인딩 필드 리스트**의 필드를 **메인 ATTRIBUTE**(WS20 속성) 프로퍼티에 끌어놓으면, 종전엔 그 잘못된 값이 그대로 바인딩됐다.
> 이제 **메인 ATTRIBUTE 드롭은 막고 안내 문구**를 띄우며 **기존 바인딩은 유지**한다.
> ★BR64-4 는 반대로 **막히면 안 되는** 경우(별창 안쪽 Design Tree 드롭 = 추가속성 자체가 안 붙는 경로)이니 헷갈리지 마십시오.
> ★앱을 껐다 켠 뒤 테스트(코드 반영은 재시작 필요).
>
> **【준비】** ⓐ WS20 상단 툴바에서 **바인딩 팝업**을 연다. ⓑ 별창 **바인딩 추가속성** 영역의 **Conversion Routine** 칸에 **한글**(없는 값)을 입력하고 칸 밖을 클릭한다. ⓒ 그 칸이 **빨간 오류 표시**가 되는지 확인한다.

### 그룹 BR65 — Aggregation 바인딩 변경 확인 팝업 취소 후 BUSY 미해제
> 대상 = **Binding Popup**(바인딩 팝업 별창)의 **Design Tree**(가운데 트리).
> 이미 바인딩된 Aggregation 에 **바인딩 필드 리스트**의 테이블 항목을 드롭하면
> `Change the model, the binding that exists in the child is initialized. Do you want to continue?`
> 확인 팝업이 뜬다. 종전엔 이 확인 팝업에서 **취소**를 선택하면 **Main(WS20)과 Binding Popup 의 BUSY 가 해제되지 않아**
> 이후 화면을 조작할 수 없었다.
> 확인 팝업 버튼은 라벨 없이 **아이콘만** 표시된다 — **체크 아이콘 = 확인**, **X 아이콘 = 취소**(마우스 오버 시 라벨 표시).
> ★앱 재시작 후 테스트(코드 반영은 재시작 필요).
>
> **【준비】 아래 항목은 모두 이 상태에서 시작한다.**
> ⓐ WS20 Design 화면 **좌측 UI 트리**에서 **목록형 UI**(예: `LIST1`)를 클릭한다.
> ⓑ WS20 상단 **바인딩 팝업** 버튼을 눌러 **Binding Popup**(별창)을 연다.
> ⓒ 별창 가운데 **Design Tree** 가 보이는 상태로 둔다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR65-1 | ★핵심 — 확인 팝업 **취소** 후 Main·Binding Popup BUSY 가 모두 해제 | ① WS20 Design 화면 좌측 UI 트리에서 목록형 UI(예: `LIST1`)를 선택한다. ② WS20 상단 **바인딩 팝업** 버튼을 눌러 Binding Popup 을 연다. ③ Binding Popup 가운데 **Design Tree** 에서 **이미 바인딩된 Aggregation 행**(예: `items` — 값칸에 바인딩 경로가 있고 바인딩 아이콘이 켜진 행)을 찾는다. ④ Binding Popup 좌측 **바인딩 필드 리스트**에서 **테이블 항목**(예: `GT_LIST`)을 드래그해 ③의 행에 드롭한다. ⑤ 확인 팝업이 표시되는지 확인한다. ⑥ 확인 팝업의 **X 아이콘(취소)** 을 선택한다. ⑦ **확인**: 확인 팝업이 닫히면서 **Binding Popup 의 BUSY 가 해제**되는지. ⑧ **확인**: **Main(WS20)의 BUSY 도 해제**되는지. ⑨ **확인**: 즉시 다음 조작이 되는지 — Binding Popup 의 Design Tree 행 클릭 선택, WS20 좌측 UI 트리 행 클릭 선택이 모두 되는지. | ✅ O |
| BR65-2 | 취소를 눌렀으니 **아무것도 안 바뀌어야** 함 | ① Binding Popup 가운데 **Design Tree** 에서 **이미 바인딩된 Aggregation 행**을 하나 고른다 — 값칸에 **테이블 이름이 적혀 있고 사슬(바인딩) 표시가 켜진** 행(예: `items`). ② 그 값칸에 적힌 **테이블 이름을 적어 둔다**(뒤에서 비교할 것). ③ 그 행 앞의 **펼침 화살표**를 눌러 안에 든 UI 들을 펼친다. 그중 **값칸에 사슬 표시가 켜진 줄**이 있으면 그 줄 이름과 값도 적어 둔다(그런 줄이 하나도 없으면 이 항목은 ⑥만 확인하고 ⑦은 건너뛴다). ④ Binding Popup **왼쪽 바인딩 필드 리스트**에서 **②와 다른 테이블 항목**을 끌어 ①의 행에 놓는다(손 뗌) → **확인 팝업**이 뜬다. ⑤ 확인 팝업의 **X 아이콘(취소)** 을 누른다. ⑥ **확인**: ①의 행 값칸이 **②에 적어 둔 이름 그대로**인지 (④에서 끌어온 테이블 이름으로 바뀌었으면 **실패**). ⑦ **확인**: ③에 적어 둔 하위 줄들의 **값과 사슬 표시가 그대로** 남아 있는지 (값이 비었거나 사슬 표시가 꺼졌으면 **실패**). | ☐ |
| BR65-3 | 확인 팝업을 **ESC** 로 닫아도 두 화면 잠금이 풀림 | ① 【준비】 를 마친 상태에서, 가운데 **Design Tree** 의 **이미 바인딩된 Aggregation 행**을 고른다 — 값칸에 **테이블 이름이 적혀 있고 사슬(바인딩) 표시가 켜진** 행(예: `items`). ② 그 값칸에 적힌 **테이블 이름을 적어 둔다**. ③ 별창 **왼쪽 바인딩 필드 리스트**에서 **②와 다른 테이블 항목**을 끌어 ①의 행에 놓는다(손 뗌) → **확인 팝업**이 뜬다. ④ 키보드 **ESC** 를 누른다. ⑤ **확인**: 확인 팝업이 닫히는지. ⑥ **확인**: **별창과 WS20 본화면 둘 다** 회색 덮개가 걷히고 바로 조작되는지 — 별창의 Design Tree 행 클릭, WS20 좌측 UI 트리 행 클릭이 **모두** 되는지. ⑦ **확인**: ①의 행 값칸이 **②에 적어 둔 이름 그대로**인지(바뀌었으면 **실패**). | ☐ |
| BR65-4 | ★되돌아감 확인 — 확인 팝업에서 **확인**을 누르면 정상으로 다시 바인딩됨 | ① 【준비】 를 마친 상태에서, 가운데 **Design Tree** 의 **이미 바인딩된 Aggregation 행**을 고른다(값칸에 테이블 이름 + 사슬 표시 켜짐, 예: `items`). ② 그 행 앞의 **펼침 화살표**를 눌러 안에 든 UI 들을 펼친다. 그중 **값칸에 사슬 표시가 켜진 줄**이 있으면 그 줄 이름과 값을 적어 둔다(없으면 ⑥은 건너뛴다). ③ 별창 **왼쪽 바인딩 필드 리스트**에서 **다른 테이블 항목**을 끌어 ①의 행에 놓는다(손 뗌) → **확인 팝업**이 뜬다. ④ 확인 팝업의 **체크 아이콘(확인)** 을 누른다. ⑤ **확인**: ①의 행 값칸이 **③에서 끌어온 테이블 이름으로 바뀌는지**. ⑥ **확인**: ②에 적어 둔 하위 줄들의 **값이 비고 사슬 표시가 꺼지는지** — ★여기서는 **지워지는 것이 정상**이다(확인 팝업 문구가 '안에 걸린 바인딩이 초기화된다'고 알려 준 대로). ⑦ **확인**: 처리가 끝나면 **별창과 WS20 본화면 둘 다** 회색 덮개가 걷히고 바로 조작되는지. | ☐ |
| BR65-5 | ★되돌아감 확인 — 아직 바인딩 안 된 곳은 **확인 팝업 없이** 바로 걸림 | ① 【준비】 를 마친 상태에서, 가운데 **Design Tree** 에서 **아직 바인딩되지 않은 Aggregation 행**을 찾는다 — **값칸이 비어 있고 사슬(바인딩) 표시가 꺼진** 행. ② 별창 **왼쪽 바인딩 필드 리스트**에서 **테이블 항목**을 끌어 ①의 행에 놓는다(손 뗌). ③ **확인**: **확인 팝업이 뜨지 않고** 바로 값칸에 그 테이블 이름이 들어가고 **사슬 표시가 켜지는지**(확인 팝업이 뜨면 **실패**). ④ **확인**: 처리가 끝나면 **별창과 WS20 본화면 둘 다** 회색 덮개가 걷히고 바로 조작되는지. | ☐ |

### 그룹 BR63 — 필드를 WS20 속성 값칸에 끌어놓아도 오른쪽 추가속성 값이 안 지워짐
> 대상 = **대형 바인딩 팝업 별창**의 **오른쪽 표**(칸 이름 `Property` / `Value`).
> 종전엔 팝업 왼쪽 필드를 WS20 속성 값칸에 끌어놓을 때마다 이 표의 값이 **처음 상태로 되돌아갔다**(빈 값 / `false`).
> 원본은 이 경우 값을 건드리지 않는다 → 원본대로 되돌림. **BR63-3 은 반대로 값이 지워져야 정상**이니 헷갈리지 마십시오.
> ★앱을 껐다 켠 뒤 테스트(코드 반영은 재시작 필요).

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR63-1 | 끌어놓아 바인딩해도 오른쪽 추가속성 값이 그대로 남음 | ① WS20 본화면 왼쪽 화면 트리에서 UI 하나를 클릭한다(오른쪽에 `Attribute` 목록이 뜸). ② WS20 위쪽 **바인딩 팝업** 버튼을 클릭한다 → 큰 별창이 뜬다. ③ 별창 **오른쪽 표**에서 `Property` 칸이 **Conversion Routine** 인 줄을 찾아, 그 줄 `Value` 칸에 **ALPHA** 를 입력하고 **다른 줄을 한 번 클릭**해 입력을 끝낸다. ④ 별창 **왼쪽 오브젝트 이름 목록**에서 값 필드 하나(예: F01)를 마우스로 누른 채 끌어, WS20 본화면 오른쪽 `Attribute` 목록의 **Properties 묶음에 있는 빈 값칸**(예: title 오른쪽 칸)에 놓는다(손 뗌). ⑤ 확인: 그 속성 값칸에 필드 경로가 들어가고 **사슬(바인딩) 표시가 켜지는지**. ⑥ 확인: 별창 **오른쪽 표의 Conversion Routine 값이 여전히 ALPHA 인지**(빈 칸이 되면 실패). | ☐ |
| BR63-2 | 다시 입력하지 않고 연달아 바인딩됨 | ① BR63-1 을 마친 상태 그대로 둔다(오른쪽 표에 ALPHA 남아 있음). ② 별창 **왼쪽 오브젝트 이름 목록**에서 **다른 값 필드**를 끌어, WS20 오른쪽 `Attribute` 목록의 **또 다른 빈 값칸**에 놓는다(손 뗌). ③ 확인: 두 번째 속성에도 바인딩이 걸리는지. ④ 확인: 오른쪽 표의 **Conversion Routine 값이 계속 ALPHA 인지**. ⑤ 확인: 두 번 다 **ALPHA 를 다시 입력하지 않아도** 됐는지. | ☐ |
