# 📚 대형 바인딩 팝업 — 작업 히스토리 (완료 이관)

## BR65 — Aggregation 바인딩 변경 확인 팝업 취소 후 BUSY 미해제
> 대상 = **바인딩 팝업**(별창) 가운데 트리.
> 이미 바인딩된 Aggregation 줄에 왼쪽 목록의 테이블을 드롭하면 확인 팝업이 뜬다 —
> `Change the model, the binding that exists in the child is initialized. Do you want to continue?`
> 종전엔 이 확인 팝업에서 **취소**를 선택하면 **Main(WS20)과 바인딩 팝업의 BUSY 가 해제되지 않아** 이후 조작이 불가능했다.
>
> **화면 읽는 법** (아래 조작에서 계속 쓰임)
> - 가운데 트리 컬럼 = `오브젝트 이름` / `바인딩 경로` / `MPROP`.
> - UI 줄 아래에 `Properties : <UI이름>` 과 `Aggregations : <UI이름>` 두 묶음이 있다.
> - `Aggregations : <UI이름>` 아래의 `items` 같은 줄이 **Aggregation 줄**. 바인딩되면 `바인딩 경로` 칸에 테이블 이름이 뜨고 줄 오른쪽 끝에 **끊어진 사슬 아이콘**(바인딩 해제)이 생긴다.
> - ★**Aggregation 줄에는 펼침 화살표가 없다.** 그 Aggregation 에 들어 있는 UI(예: `STANDARDLISTITEM…`)는 **바로 아래 같은 단계의 줄**로 나오고, 그 UI 의 `Properties : …` 안 속성들이 하위 바인딩 대상이다.
> - 확인 팝업 버튼은 **라벨 없이 아이콘만** — **체크 아이콘 = 확인**, **X 아이콘 = 취소**(마우스를 올리면 라벨이 뜬다).
>
> ★앱 재시작 후 테스트(코드 반영은 재시작 필요).

## 2026-09-03 · BR63 — 필드를 WS20 속성 값칸에 끌어놓으면 오른쪽 추가속성 값이 지워지던 것 — 전 항목 통과

> **증상**: 바인딩 팝업 오른쪽 추가속성 표에 값(예: `Conversion Routine` = `ALPHA`)을 넣어 둔 뒤, 왼쪽 필드를 WS20 속성 값칸에 끌어놓으면 바인딩은 걸리지만 **오른쪽 표의 값이 처음 상태(빈 값 / `false`)로 되돌아갔다.** 같은 추가속성으로 연달아 바인딩하려면 매번 다시 입력해야 했다.
> **원인**: 원본 `broadcastChannelBindPopup.js` 는 이 경로에서 추가속성 관련 3줄(289 목록 재구성, 269 선택 비우기, 307 값 새로고침)을 **모두 주석 처리**해 두었다 — 즉 **일부러 건드리지 않는다.** 변환 때 이를 "안 불리는 죽은 코드"로 오판하고 목록 재구성을 **되살려 놓은 것**이 원인. 매 드롭마다 오른쪽 8행이 기본형으로 새로 만들어졌다.
> **수정**: `Popups/bindPopup/wsDesignHandler/bindBroadcast.js` — 재구성 콜백에서 **추가속성 목록 재구성 호출을 제거**(원본 289 주석 1:1, 근거 주석 남김). 백업 `_bindBroadcast.js.br63bak`. `node --check` 통과.
> **검수(코덱스·안티)**: C1(위 제거)은 양쪽 **정상·원본 1:1** 판정. 곁들여 넣었던 **오른쪽 바인딩 버튼 켜기(C2)는 양쪽 지적 → 제거**(원본은 가운데를 트리로 되돌린 뒤에야 버튼을 켜는 순서인데 그 앞 단계가 없어, 동일속성 화면이 잠가 둔 버튼을 전환 도중 남이 풀어버림). 안티가 제안한 "되돌리기 복원"은 **화면이 멈추는 위험**이 있어 반론·반려(전환 함수가 진행 중 예약을 취소만 하고 끝났다는 신호를 안 보냄). 취합 = `.audit/br63/03_response.md`.
> **BR63-3 으로 판별한 것**: "WS20 UI 를 팝업 가운데로 끌어놓기"는 **원본대로 초기화되는 쪽**이 맞음이 실화면에서 확인됐다(소스 주석이 서로 달라 정적으로 못 가렸던 부분). 추가 보완 불필요.

### 그룹 BR63 — 필드를 WS20 속성 값칸에 끌어놓아도 오른쪽 추가속성 값이 안 지워짐
