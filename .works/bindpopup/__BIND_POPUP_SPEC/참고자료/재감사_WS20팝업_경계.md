## A. 아키텍처 (확정됨)

- 바인딩 팝업 = **별도 BrowserWindow(별창)** — `fnBindWindowPopupOpener`가 `REMOTE.BrowserWindow`로 연다.
  팝업↔WS20 통신 = **BroadcastChannel**(`${browserkey}_ws20_bindpop`). (frame.js:5/19/326, fnBindPopupOpen.js:198)
- WS20 코드 두 세트: **UI5**(`design/js/main.js`→`uiAttributeArea.js`/`uiDesignArea.js`) = **원본 참고용** /
  **HTML5**(`ws_html5_ws20_*`, library-preload) = **live**. (WS20 트리가 ws_html5_ws20_tree.js 로 그려짐이 확정 — 장군님)

**★핵심 귀결**: 팝업이 별창이므로 **HTML5 네이티브 드래그(dataTransfer)는 창 경계를 넘지 못한다.**
좌측 필드 드래그(prc001)는 **팝업 자기 창 안(중앙 디자인 트리)에만** 드롭 가능. **WS20 캔버스로는 물리적으로 드롭 불가.**
→ 원본(인-윈도우 UI5 다이얼로그)에서 가능했던 "팝업 필드→WS20 캔버스 드롭"은 **이 구조에서 성립 불가.**

## E. ★R2 판단 (장군님)

- R2(ERROR-ADDIT-DATA 수신부)는 원본 1:1 이식이나, **트리거(크로스-윈도우 드롭)가 별창 구조상 불가** → **작동할 일 없음(死 코드)**.
- MPROP 유효성은 **팝업측에서 적용 전 검증**(chkAdditBindData/chkPossibleAdditBind)으로 이미 차단 → WS20 재검사는 원본에서도 2차 방어였고, 별창 구조에선 불필요.
- **옵션**:
  - (a) **그대로 둔다**(무해·원본 충실, 언젠가 인-윈도우 회귀 대비) — C-2 는 "재현 불가/N-A"로 확인목록에서 내림.
  - (b) **제거**(死 코드 정리) — bindBroadcast.js 의 ERROR-ADDIT-DATA case/핸들러 삭제.
- 권장: **(a)** — 무해하고 계약 흔적 유지. C-2 만 목록에서 N/A 처리.

## D. 남은 점검 (2026-07-24 완료)
1. **A 아키텍처 확정** — ✅ 별창+BroadcastChannel 확정(장군님 승인). F-3 판정 전제 성립.
2. WS20측(live) 팝업행 **다른 스텁/미호출** 색출 — ✅ **F-1 외 없음.**
   - prev.js:808~822 `designTreeDragStart`/`designDragEnd`/`UIDrop` 스텁은 **WS20 캔버스 내부용**(팝업 경계 아님)이고, 전부 `if (typeof … !== "function")` 가드라 **실제 dnd.js:761 UIDrop(무가드 재정의)이 항상 이김** → 클로버 없음.
3. `setBindPopupDesignAppData`/`setBindPopupDragAppData` **live 정합성** — ✅ **확정.**
   - `pathInfo.bindPopupBroadCast` = `design/bindPopupHandler/broadcastChannelBindPopup.js`(full-impl) 로 해석됨(ws_html5_ws20_prev.js:172 / main.js:66). F-1 이 **죽은 모듈이 아니라 이 실모듈**을 부름.
   - 이 모듈이 쓰는 함수 전부 HTML5 실존: `getTreeData`/`setUIPOSIT`/`parseTree2Tab`/`crtStru0014`/`crtStru0015`/`getParentAggrBind`/`setSelectTreeItem`/`previewUIsetProp`(prev.js), `crtStru0015`/`setChangeFlag`/`setShortcutLock`(attr.js), `oAPP.attr.prev`(data.js). BUSY 경로(oMainBroad/fnSetBusyLock)는 undoRedo 가 이미 상시 사용 중 → 검증됨.
4. 팝업 최초 적재(SEND-APP-DATA)·ROOT_OBJID 타이밍 — ✅ **정상.**
   - SEND-APP-DATA = opener 가 넘긴 최초 페이로드 passthrough(모듈 878행). 팝업이 트리 최초 빌드 시 `setDesignTreeData`→`sendRootObjid`(R3)로 `ROOT_OBJID` 반송 → WS20 `updateRootObjectID` 가 `DESIGN_ROOT_OBJID` 채움(360행) → 이후 WS20 편집의 `updateBindPopupDesignData` 가 이 값 기준 T_0014/0015/CEVT 구성. 순서 건전(팝업 미오픈 시 `isCreateChannel` no-op).
