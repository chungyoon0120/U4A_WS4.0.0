# 바인딩 팝업 트리 가상 스크롤 전환 — 조사 결론 + 실행계획 (2026-07-30)

> **For agentic workers:** 테스트 게이트로 진행(코드 → `node --check` → 장군님 재시작 확인). 상태 SSOT = `../00_현황판.md`.

**배경:** 원본 UI5 `sap.ui.table.TreeTable`은 **가상**(visibleRowCount만 DOM). WS20 본체 디자인 트리·USP·MIME도 이미 `virtual:true`(수만 노드 대비). **바인딩 팝업 두 트리만 비가상** → UI 3만 개 앱에서 DOM 3만 행 → 스크롤·드래그 버벅임. **원본 대비 성능 회귀** 복원.

**Goal:** 좌측 모델필드·가운데 디자인 트리를 `virtual:true`로 전환해 대용량에서 뷰포트만 렌더.

**Architecture:** 공통 `makeColumnTree` 가상 모드는 **이미 검증**(WS20/USP/MIME). 화면은 `virtual:true` 주입 + 비가상 전제로 짠 스크롤 2곳만 고치면 됨. 공통 자산 무수정.

## 조사 결론 (서브에이전트 3 + 직접 재검증)

**공통 트리 = 가상 준비 완료** — flat+windowed 렌더, rowHook은 window 진입 행마다 재실행(강조/배지/`__bwpNode` 자동 복원), 행높이 `--u4a-vsrowh` 고정, 격자·sticky 액션컬럼 가상 대비 완료, `scrollContainer`=host 자동 지정.

**이미 가상 친화(수정 불필요):** rowHook 배지·오류행·체크박스(노드 데이터 재계산) · 드래그드롭(좌측 요소가드+rowHook 재빌드 / 가운데 host 위임+`closest`) · R4 필터 · 격자/행높이/빈트리 · autofit 호출 빈도(스크롤/rerender마다 안 불림, 데이터로드·버튼·더블클릭만) · 드롭 타겟(`_dropNodeOf` closest).

**★심층 재검증(2차, 직접 확인) — "그냥 켜면 회귀". 완화 선행 필수:**
- **B1 [높음] 선택 강조 소실** — 가상에서 클릭 강조(`selectByKey`가 `aria-selected`를 DOM에 직접, u4a-ui.js:1633)가, 이후 스크롤/스플리터 조작으로 그 행이 재생성되면 **사라진다**(`_render`는 내부 `selKey`로만 재적용하나 createTree가 `selKey` 미동기 — u4a-ui.js:2119 직접 확인). WS20은 rowHook에서 화면소유 선택키로 aria-selected 재적용해 우회(tree.js:595). → **Task 0** (rowHook 강조, 공통 무수정).
- **B3 [높음] off-window 스크롤 실패** — 선택동기/오류라인이 `querySelectorAll+scrollIntoView`라 화면 밖 행 못 감. → **Task 1**.
- **A3 [중간] MutationObserver 동기 폭주** — 가상 스크롤 프레임마다 `_fixEmpty` 발화. → **Task 2** rAF 게이트.

**성능 역설 [선결 판단]:** 가상은 스크롤마다 window(수십 행)를 **통째 재생성**(노드 재활용 없음, u4a-ui.js:2114-2125) → **수백 행이면 오히려 비가상보다 느리다.** 수천~수만 행일 때만 이득. 3만 UI 앱엔 필수지만 소형 앱엔 역효과 → 실제 데이터 규모/임계값 판단 필요.

**정책 [수용]:** autofit "보이는 행만" 측정 — 원본 UI5도 동일(`setUiTableAutoResizeColumn`) → 원본 재현. 단 현행 비가상 대비 **초기 컬럼폭 과소** 가능(C3) — 데이터 전량 측정으로 바꾸려면 별도 수정.

## Global Constraints
- 공통 자산(u4a-ui.js/shell.css) 직접수정 금지 — `virtual:true` 옵션 소비만.
- 원본우선: 가상=원본 재현. 원본에 없는 동작 추가 금지.
- 기능 회귀 0: 선택동기·오류라인 이동·드래그드롭·펼침·컬럼폭·WS20↔팝업 동기 전부 유지.

### Task 1: virtual 켜기 + 선택 스크롤 2곳 수정 (한 묶음 — 켜면 2곳 동시 깨짐)

**Files:** Modify `modelFieldArea/modelFieldArea.js`(94) · `designArea/designArea.js`(1069, 1006-1012, 430-435)

**핵심:** `selectKey(CHILD, true)`는 공통 `scrollToKey`를 태워 **가상=off-screen reveal / 비가상=findRow.scrollIntoView** 양쪽을 처리한다([u4a-ui.js:1626,1639](../../../www/ws30/ws10_20/theme/u4a-ui.js)). 따라서 화면의 `querySelectorAll+scrollIntoView` 수동 스크롤을 이걸로 교체하면 비가상에서도 회귀 없고 가상 준비됨.

- [ ] **Step 1: 좌측 트리 virtual 켜기** — `modelFieldArea.js:94` `U4AUI.makeColumnTree(oM.host, { ... })`에 `virtual: true,` 추가
- [ ] **Step 2: 가운데 트리 virtual 켜기** — `designArea.js:1069` cfg에 `virtual: true,` 추가(autofit 옆)
- [ ] **Step 3: `selectDesignNodeByObjid` 스크롤 교체** (designArea.js:1003-1012)

```js
// 선택 강조 + off-screen reveal — 공통 selectKey(key,true)가 scrollToKey 로 처리(가상/비가상 공통).
//   (원본 setSelectedIndex+setFirstVisibleRow 대응. 가상 전환으로 수동 querySelectorAll+scrollIntoView 제거.)
if (typeof oD.ctrl.selectKey === "function") { oD.ctrl.selectKey(oNode.CHILD, true); }
oAPP.fn.bindPossibleRecompute(oNode);
// (기존 var oRow = ... querySelectorAll 루프 + oRow.scrollIntoView 블록 삭제)
```

- [ ] **Step 4: `focusErrorDesignLine` 스크롤 교체** (designArea.js:428-435) — `_refreshDesignTree()` 후 수동 스크롤 블록을 아래로:

```js
_refreshDesignTree();
// 해당 행으로 스크롤(원본 setFirstVisibleRow 대응) — 가상/비가상 공통 selectKey(key,true).
if (oD.ctrl && typeof oD.ctrl.selectKey === "function") { oD.ctrl.selectKey(LINE_KEY, true); }
// (기존 querySelectorAll 루프 + scrollIntoView 삭제)
```

> ★착수 시 확인: `selectByKey(sKey, bReveal)`가 bReveal=true에서 비가상일 때도 `scrollToKey`(→findRow.scrollIntoView)를 부르는지 [u4a-ui.js:1626] 실측. 만약 비가상 경로가 스크롤을 안 하면, 교체 대신 "가상일 때 selectKey(,true) / 비가상일 때 기존 방식" 분기 유지.
