# 대형 바인딩 팝업 — 화면 동작 흐름 분석 계획서 (2026-07-24)

## 0. 왜 (배경)
지금까지 잔여 결함(R1·R2)을 고치며 **화면 흐름을 부분적으로만** 봤다. 그 결과 우측 "추가 속성 바인딩"
영역이 **버튼으로 적용**되는 구조인데도 "옵션 선택+드래그로 적용"으로 오해했다(장군님 지적).
→ **잔여(R2~S5)를 더 건드리기 전에, 3영역과 영역 간 흐름을 원본 소스 기준으로 전면 재분석**해
   틀린 이해를 바로잡고, 이후 작업의 단일 근거로 삼는다.

- **SSOT = 원본 UI5 소스**(현행 런타임 미사용 = 참고 원본). 추측 금지, 모든 흐름에 `파일:라인` 근거.
- 코드는 **손대지 않는다**. 이 단계는 **읽기·문서화만**.

## 2. 분석 단위 (장군님 지시 순서 — 한 번에 하나씩)

**STEP 1 → 좌측 영역** → **STEP 2 → 가운데 영역** → **STEP 3 → 우측 영역** → **STEP 4 → 영역 간 흐름**

각 STEP 완료 시 **장군님 확인 후** 다음 STEP 착수(몰아서 금지). 확인에서 틀린 부분은 그 자리서 정정.

---

## 3. 각 STEP 공통 분석 템플릿 (뽑을 항목 A~F)

- **A. 화면 구성요소**: 이 영역에 뭐가 있나(트리/컬럼/버튼/입력칸/툴바). 각 요소의 원본 위치.
- **B. 사용자 액션 → 결과**: 클릭·더블클릭·드래그·버튼·우클릭 각각 무엇이 일어나나(화면 관점).
- **C. 함수 흐름**: 액션 → 핸들러 → 내부 함수 체인 (원본 `파일:라인`). "무엇을 하는 함수"까지.
- **D. 데이터**: 이 영역이 읽고/쓰는 데이터(T_0014/T_0015/UA028/MPROP/S_ 구조 등)와 의미.
- **E. 영역 간 신호**: 이 영역이 다른 영역·WS20에 보내는 것(방송 PRCCD·이벤트·직접호출)과 받는 것.
- **F. 다이어그램**: mermaid 순서도(flowchart/sequence)로 A~E를 시각화.

## 4. STEP별 세부 범위 (착수 전 확정용)

### STEP 1 — 좌측 "모델 필드" 영역
- 대상: `index.js` 의 `oModelFieldTree` 계열(생성·행선택·펼침·컬럼맞춤·참조필드 연동).
- 핵심 질문: 좌측 트리는 뭘 보여주나(구조/필드) / 행 선택 시 무슨 일(우측·가운데 연동?) / 드래그 출발점인가.

### STEP 2 — 가운데 "디자인 트리" 영역
- 대상: `uiModule/designTree.js` 전체.
- 핵심 질문: 무엇이 그려지나(바인딩된 UI 트리) / 드롭 받는 곳인가 / 선택·펼침 / MPROP·바인딩 결과가 여기 stamp 되나 / WS20 방송 송수신.

### STEP 3 — 우측 "추가 속성 바인딩" 영역 ★(오해 지점)
- 대상: `uiModule/bindAdditInfo.js` 전체.
- 핵심 질문: **상단 버튼들이 뭐고 각각 언제 눌러 뭐가 적용되나** / 옵션(Bind type 등) 입력은 어디에 쌓이고(스테이징) **언제 확정되나(버튼?)** / MPROP 은 언제·어떻게 구성되나 / 좌·가운데와 어떻게 연결.

### STEP 4 — 영역 간 & WS20 처리 흐름
- 대상: 방송 양측 + `uiAttributeArea.js` 의 드롭 수신/검사/반송.
- 핵심 질문: **좌→가운데→우 데이터가 어떤 순서로 흐르나** / WS20으로 가는 트리거는 정확히 무엇(드래그? 버튼?) / `PRC001`·`UPDATE-DESIGN-DATA`·`ERROR-ADDIT-DATA` 각 방송이 어떤 액션에서 발생 / MPROP 이 WS20까지 실려가는 정확한 경로(=R2 오류가 실제로 나는 조건).

## 6. 방법·원칙
- 원본 파일 **정독**(그 STEP 대상 파일 끝까지). 함수 존재/이름 매칭이 아니라 **본문 로직+호출 배선까지**.
- 모든 흐름에 원본 `파일:라인` 근거. 문서에 없거나 불명확하면 **추측 말고 "미확인"으로 표기 후 보고**.
- HTML5 현행과의 차이는 **STEP마다 "원본 vs HTML5 차이" 한 줄**로 병기(단, 이번 단계에서 코드 수정은 안 함).
- 큰 파일은 영역별로 나눠 정독하되, **한 STEP = 한 영역 = 장군님 확인 게이트**.
