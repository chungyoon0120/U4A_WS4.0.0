## ⏳ 확인 대기 (현재 2건)

### [C-6] WS20 변경(특히 삭제) → 팝업 트리 반영 (변환 누락 스텁 연결)
- **어디**: 바인딩 팝업을 **연 상태에서** 부모 화면(WS20)에서 UI를 **삭제/추가/이동/붙여넣기**
- **증상(수정 전)**: WS20→팝업 반영 함수(`updateBindPopupDesignData`)가 **빈 스텁**이라 반영이 원천적으로 안 됨. 삭제는 아예 호출조차 없었음(단일·멀티 둘 다).
- **원인/수정**:
  - WS20 `ws_html5_ws20_dnd.js` 스텁 → **원본(uiDesignArea.js:1266)대로 방송(`UPDATE-DESIGN-DATA`) 연결**. WS20 방송모듈이 `DESIGN_ROOT_OBJID` 기준으로 `T_0014/0015/CEVT` 구성 → 팝업에 `UPDATE_DESIGN_DATA` 전송 → 팝업 트리 재빌드.
  - 삭제 2경로(`ws_html5_ws20_edit.js` `_deleteUI`·`designTreeMultiDeleteItem`)에 호출 추가(원본 4546행).
  - **전제**: 팝업이 열려 `ROOT_OBJID`(R3/C-5)를 전달해야 `DESIGN_ROOT_OBJID`가 채워짐. 팝업 미오픈이면 no-op(안전).
- **확인 시나리오**
  1. 바인딩 팝업을 연다(가운데 트리에 UI가 뜬 상태).
  2. 부모 화면에서 **UI 하나 삭제** → 팝업 가운데 트리에서도 **그 UI가 사라진다**.
  3. 부모에서 **UI 추가/이동/붙여넣기** → 팝업 트리에도 반영된다.
  4. busy(빙글빙글) 안 남음.
- **관련 파일**: `js/ws_html5_ws20_dnd.js`(스텁→실제), `js/ws_html5_ws20_edit.js`(삭제 2경로)
- **상태**: 🔷 코드완료 — 재시작 후 확인 대기 (2026-07-24)

### [C-5] R3 — 트리 ↔ 캔버스 선택 따라가기(양방향)
- **어디**: 바인딩 팝업 가운데 트리 ↔ WS20 부모 화면 캔버스
- **증상(수정 전)**: 팝업 트리에서 UI 줄을 클릭해도 부모 캔버스는 따로 놀았음. 반대도 안 됨.
- **확인 시나리오**
  1. 팝업 가운데 트리에서 **UI 오브젝트 줄(맨 위 UI 계층)** 클릭 → **부모 화면 캔버스에서 같은 UI가 선택**된다.
  2. 반대로 **부모 캔버스에서 UI 선택** → 팝업 트리가 **그 줄로 이동·선택**된다(안 보이면 스크롤). ★1차 테스트서 스크롤 미동작 발견 → 공통 selectKey 가 비가상 트리서 스크롤 안 함(u4a-ui.js:1630) 확인, 행 DOM 직접 scrollIntoView 로 수정(2026-07-24 재테스트 필요).
  3. 왔다갔다 반복해도 **무한 튐/깜빡임 없음**(에코 없음), busy 안 남음.
- **주의**: UI 줄(계층 최상위/컨트롤)만 동기화. 속성(Properties/Aggregations) 줄은 대상 아님(원본과 동일).
- **관련 파일**: `wsDesignHandler/bindBroadcast.js`(송신 2개+수신), `designArea/designArea.js`(onSelect 송신·selectDesignNodeByObjid·setDesignTreeData ROOT 통지)
- **상태**: 🔷 코드완료 — 재시작 후 확인 대기 (2026-07-24)
