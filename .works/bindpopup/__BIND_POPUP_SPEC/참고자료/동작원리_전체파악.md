# 🧭 대형 바인딩 팝업 — 동작 원리 관통 파악 (2026-07-30)

> 원본(UI5) 소스를 영역별로 정독해 **화면에서 무슨 일이 벌어지는지**를 관통 정리한 문서.
> 상태는 이 문서가 소유하지 않음(상태 SSOT = `00_현황판.md`). 이 문서는 **동작 이해용 동결 스냅샷**.
> 근거: 원본 `index.js` + `uiModule/*`, 이식본 `modelFieldArea/` `designArea/` `additInfoArea/` `wsDesignHandler/bindBroadcast.js`.

## 1. 화면 4영역 한눈에

| 영역 | 위치 | 무엇인가 | 사용자가 하는 일 |
|---|---|---|---|
| **① 바인딩 필드** | 왼쪽 | 이 앱에 **바인딩할 수 있는 원본 데이터 필드** 목록(트리) | 필드 **클릭**(선택) / 오른쪽으로 **드래그** |
| **② DESIGN TREE** | 가운데 | 현재 화면의 **UI 오브젝트 + 그 속성** 계층 | 필드를 속성에 **드롭**해서 바인딩 / 체크해서 일괄 / 경로 링크 클릭 |
| **③ 추가 속성 바인딩** | 오른쪽 | **"앞으로 만들 추가속성"을 담는 빈 입력폼**(스테이징) | 값 채워서 드래그·일괄적용에 실어 보냄 |
| **④ 추가속성 적용** | 가운데 아래 | **이미 바인딩된 한 줄**의 추가속성 열람/수정 (평소 숨김) | 파란 경로 클릭 시 나타남 → 고쳐서 적용 |

**③과 ④는 서로 다른 저장소다.** ③=`additRows`(스테이징), ④=`additRowsSel`(선택 1행). 원본은 둘 다 `T_MPROP`란 같은 이름을 다른 객체에 둬서 헷갈렸고, HTML5는 이름을 갈라놨음.

## 2. DESIGN TREE 줄의 3종류 (★체크박스 오해 주의)

가운데 트리 한 줄은 셋 중 하나:
1. **UI 오브젝트 줄** (예: `TITLE3`) — 실제 컨트롤 이미지 아이콘. **체크박스 없음.**
2. **그룹 헤더 줄** (`Properties : TITLE3`, `Aggregations : TITLE3`) — 단순 구분선. **체크박스 없음.**
3. **속성/애그리 줄** (예: `text`) — **체크박스 있음.** ← "속성 여러 개 체크"는 **이 줄들**을 켜는 것.

판별 필드: `DATYP`(01=UI / 02=속성·애그리 / 03=그룹), `UIATY`(1=프로퍼티 / 2=이벤트 / 3=애그리게이션). 체크박스는 `_check_visible`=속성·애그리 줄만 true.

## 3. 데이터 한 바퀴 (로드 → 선택 → 바인딩 → 방송 → 재구성)

```
[새로고침] loadBindData
  → 서버 /getBindAttrData (CLSNM, APPID)
  → 좌측 필드 트리 그림 + 바인딩 가능표시(녹색체크 등) 계산
  → 첫 행 자동선택 → 참조필드 목록 1차 구성

[좌측 필드 클릭]  onSelect
  → 그 필드를 "현재 선택"으로 → 오른쪽 참조필드 목록 재계산(setRefFieldList)

[좌측→가운데 드롭]  dropDesignArea → _setBindAttribute → attrSetBindProp
  → 그 속성줄에 경로(UIATV) 기록 + ISBND="X"
  → attrChange → WS20로 방송(UPDATE-DESIGN-DATA, 하이픈) + 로컬 busy ON

[WS20가 모델 반영 후]  UPDATE_DESIGN_DATA(밑줄) 수신
  → 트리 통째 재구성 → busy OFF → WS20에 BUSY_OFF 되쏨
```

**busy는 스스로 안 푼다** — 부모(WS20) 응답이 와야 풀림(불변 계약).

## 4. ★참조필드(Reference Field name)가 뜨는/안 뜨는 정확한 규칙

목록 기준 = **"가운데 체크한 바인딩 줄" + "좌측 선택 필드"** 둘을 합쳐서 판정. (좌측만이 아님)

1. 가운데 체크된 줄들 중 **바인딩된 것**의 파생 원본 필드를 모음 (미바인딩·프로퍼티 아닌 줄이 섞이면 목록 비움)
2. 거기에 **좌측 선택 필드의 부모**를 더함
3. 모은 게 **한 구조로 모이면** → 그 구조 안의 **통화(CUKY)/단위(UNIT) 필드**를 목록에 채움
4. **두 구조 이상 섞이거나 / 통화·단위 필드가 없으면** → 목록을 **비우고 잠금**

**재계산되는 순간**: 좌측 클릭 · 초기 로드 · 체크 토글 · 선택 전체해제 · 단건 해제 · 멀티 해제 · 드롭. (멀티 바인딩은 체크 시점에 이미 돌아서 따로 안 부름)

> ⚠ 그래서 "해제/선택해제하면 오른쪽 목록이 바뀐다"가 맞다 — 체크 상태가 목록 산정에 들어가기 때문. 다만 좌측 선택이 그대로면 눈에 안 띌 수 있음.

## 5. 바인딩 4경로 + MPROP(추가속성) 비대칭

네 경로 모두 **단일 진입점 `attrSetBindProp`**(쓰기)로 수렴 → 결과 일관성 보장.

| 경로 | 트리거 | 추가속성(MPROP) 함께? |
|---|---|---|
| (a) 드래그 드롭 | 좌측 1필드 → 속성줄에 놓기 | **안 넘김** (드롭 직전 강제 비움) |
| (b) 멀티 바인딩(파랑) | 체크 N줄 + 좌측 1필드 → 버튼 | **안 넘김** (모델 원시노드엔 MPROP 없음) |
| (c) 동일속성 바인딩(녹색) | 바인딩된 1줄 → 별도 화면서 일괄 | **넘김** (기존 행 MPROP 전파) |
| (d) 해제 | 행 버튼 / 멀티 해제(빨강) | 해당없음 |

즉 **추가속성을 바인딩과 함께 전파하는 건 "동일속성 일괄적용"뿐**(원본 의도). 드롭·멀티는 사후 "추가 속성 바인딩"/"추가속성 적용" 버튼으로 따로 stamp.

**검증 게이트 = all-or-nothing**: 멀티 시 실패 줄이 하나라도 있으면 **전부 차단**(부분 성공 없음).
