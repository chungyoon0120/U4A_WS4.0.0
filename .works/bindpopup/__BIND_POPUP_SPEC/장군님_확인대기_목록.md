### [C-4] ΔC1 — 디자인트리 임베디드 속성 배지(EMATT) 렌더 복원
- **어디**: 가운데 디자인 트리 **Object Name 칸 우측**
- **증상(수정 전)**: 원본은 UI 오브젝트 행 이름 오른쪽에 임베디드 속성 배지(아이콘+속성명)를 표시하는데, HTML5는 값 계산만 하고 **화면에 안 떴음**.
- **원본 근거**: designTree.js:4093 `ObjectStatus{text:EMATT, icon:EMATT_ICON}`. 아이콘 0:1=color-fill / 0:N=dimension.
- **수정**: designArea.js `_ematBadge` + rowHook 에서 이름칸에 `.u4aBwpEmatt` 배지 덧댐(공통 미수정, frame.css 스코프). 아이콘/색/크기 = **WS20 UI 트리와 완전 동일**(js/ws_html5_ws20_tree.js:193): 0:1=`fa-regular fa-square` / 0:N=`fa-regular fa-clone`, 색 --accent(13/11px, clip).
- **참고**: WS20 UI 트리 실렌더 = `js/ws_html5_ws20_tree.js`(HTML5). `design/js/uiDesignArea.js`(sap)는 원본 UI5 참고용(현행 아님). attrPresetPopup 은 자기 관례(fill-drip/cubes) 별개 — 손대지 않음.
- **확인 시나리오**
  1. 임베디드 속성을 가진 UI(예: 특정 컨트롤)를 WS20에서 바인딩 팝업으로 가져온다.
  2. → 가운데 트리에서 그 **UI 행 이름 오른쪽**에 배지(아이콘+속성명)가 뜬다. 이름이 길면 이름은 …로 줄고 배지는 유지.
  3. 임베디드 속성 없는 행에는 배지 없음(원본과 동일).
- **관련 파일**: `designArea/designArea.js`(_ematBadge/rowHook), `frame.css`(.u4aBwpEmatt)
- **상태**: 🔷 코드완료 — 재시작 후 확인 대기 (2026-07-24)

### [C-2] R2 — WS20 반송 추가속성 오류 → 오류 팝오버
- **어디**: 바인딩 팝업 → 필드+추가속성을 **WS20 캔버스(디자인 영역)에 드롭**할 때
- **트리거(원본 attrCheckDropMPROP)**: 추가속성이 붙은 필드를 드롭했는데 타입이 안 맞음.
  대표 케이스 = **P타입 아닌 필드(예: STRING F01)에 `Bind type`(P04) 설정 후 드롭** → 오류 093 "Bind type은 ABAP TYPE이 P 유형만 가능".
- **확인 시나리오**
  1. 좌측에서 **P타입 아닌 필드**(STRING/CHAR 등) 선택
  2. 우측 "추가 속성 바인딩"에서 **Bind type** 설정
  3. 그 필드를 **WS20 캔버스에 드래그&드롭**
  4. → 우측 "추가 속성 바인딩" 패널 옆에 **오류 목록 팝오버**가 뜬다 (예전엔 조용히 무시)
  5. **"오류 위치 확인" 링크** 클릭 → 우측 추가속성의 **해당 행(P04)으로 이동/강조**
  6. 팝오버 닫으면 강조 해제 / busy 안 남음
- **★재현 전제**: 이 오류는 **드롭이 추가속성(MPROP)을 같이 실어보낼 때만** WS20이 검사·반송한다. MPROP 캐리 드롭이 안 되는 상황이면 오류 자체가 안 오므로(=R2 결함 아님), 그때는 별도로 보고.
- **관련 파일**: `wsDesignHandler/bindBroadcast.js`(`_responseAdditError`+case), 재사용=`showMessagePopoverOppener`/`newBindError`/`focusErrorAdditLine`
- **상태**: 🔷 코드완료 — 재시작 후 확인 대기 (2026-07-24)
