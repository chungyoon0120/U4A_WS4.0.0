## 1. 목표
원본 UI5 3분할 바인딩 팝업의 **데이터 구조·상태·동작을 1:1로** 보존한 채, 창 크롬/렌더만 공통 HTML5(frameless + `.u4a-*` 공통 컴포넌트)로 교체한다. 새로 짜지 않고 **공통을 소비**하며, 동일 레이아웃(WS20 유사)에서 이미 해결된 패턴을 **레퍼런스로 베낀다**.

## 6.5 이식하지 말 것 (데드/비활성 — §11, 혼동 방지)
- `designArea/sendAppData.js` = **데드코드**(호출부 없음, `oAPP.broadcast` 미초기화). 라이브 경로는 `broadcastChannelBindPopup.js` `updateBindPopupDesignData`.
- 드래그 레이아웃 스냅샷/복원(`captureBindFieldDragLayout`/`scheduleRestoreBindFieldDragLayout`/`rebuildMainSplitterLayoutFromSnapshot`) = **호출부 주석처리(비활성)**. 이식 대상 아님.
- `setTreeDrag()`(native draggable 토글) = 정의만, **비활성**. 실제 드래그는 선언적 DnD.
- `CS_BIND_MODE.DEFAULT("01")` = **미사용**. **BULK("02") 기준으로만** 구현.

## 6.6 메시지 키 (§10, no-invented-messages)
- 전 문구는 `ZMSG_WS_COMMON_001` 키만 사용(하드코딩 금지). 각 단계 착수 시 **필요 키가 WS4 DB에 존재하는지 확인**, 없으면 **임의 생성 금지 → 누락 키 목록으로 수집·보고**.
