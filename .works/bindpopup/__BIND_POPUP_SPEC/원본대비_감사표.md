## 3. ❌ 진짜 누락 (3건 — 조치 필요)

### N1. `attrChgAttrVal` 체인 통째 누락 — **중대**
- **원본**: `index.js:7434 attrChangeProc` → `attrChgAttrVal(7449)` → 내부 `lf_add_T_0015` / `crtStru0015(7677)` / `moveCorresponding(7689)`
- **하는 일**: 바인딩·해제할 때마다 `oAPP.attr.prev[OBJID]._T_0015` 에 결과(`UIATV`/`ISBND`/`MPROP`/`ADDSC`/`ISWIT`/`ISSPACE`)를 **기록**하고, 해당 속성 줄이 없으면 **새 줄을 생성해 넣는다**(APPID/GUINR/UILIK 채움 포함).
- **HTML5 현재**: `bindWrite.js:61 attrChange` 가 `setDesignTreeEnableButton` + `bindPossibleRecompute` + `designBroadcastUpdate` 만 한다. `_T_0015` 기록·신규생성이 **없다**. MPROP 만 `designArea.js:331/642/660` 에서 직접 손댄다.
- **영향**: `bindBroadcast.js:57 _setPrevData()` 가 `oUi._T_0015` 를 **그대로** WS20 으로 보낸다(보정 없음) → **옛 바인딩 상태가 전송될 수 있다.** N건 바인딩 판정(`_T_0015.findIndex(a=>a.ISBND==="X"…)`, `bindWrite.js:80/116`)도 옛 데이터로 한다.
- **조치**: `attrChgAttrVal` 를 `bindWrite.js` 에 이식하고 `attrChange` 맨 앞에서 호출.

### N2. `setConvNameUpperCase` 누락
- **원본**: `index.js:5427`, 호출 `index.js:5242` · `bindAdditInfo.js:407`
- **하는 일**: 추가속성 입력 시 **Conversion Routine 이름을 대문자로 자동 변환**
- **영향**: 소문자로 입력하면 원본과 다른 값이 저장/검증된다.

### N3. `expandModelFieldTree` / `scheduleExpandModelFieldTree` 누락
- **원본**: `index.js:2691/2708`, 호출 `index.js:2410`(레이아웃 재구성) · `3020`(커스터마이징 Apply)
- **하는 일**: 화면 커스터마이징 적용 후 **좌측 모델필드 트리를 전체 펼침**(MODEL 영역이 켜져 있을 때만)

## 6. 감사의 한계 (정직 기록)

- 이름이 매칭된 131개 중 **본문까지 대조한 것은 위 표의 핵심 7건**이다. 나머지는 "대응 함수 존재"까지만 확인했다.
- 표본이 전부 1:1 통과했으므로 전체 품질은 양호하다고 판단하나, **개별 스텝 착수 시 그 영역 함수는 다시 본문 대조**한다.
- UI 생성 코드(원본 `designView`/`designControl` 계열)는 화면 구조로 대체되므로 함수 단위 대조 대상이 아니다 — 화면 자체를 눈으로 확인하는 방식(스텝계획서)으로 검증한다.
