## 0. 왜 다시 쪼개나

기존 계획은 **기능 단위**(P4=동일속성, P5=비모달…)라 스텝 하나가 너무 크다.
이 프로젝트는 Electron 프리뷰가 불가해 **스텝이 끝날 때마다 앱을 재시작해 장군님이 눈으로 확인**하는 구조다.
따라서 분할 기준을 바꾼다:

> **스텝 하나 = 앱 재시작 1회 = 화면에서 확인할 것 1개**

기능이 반쪽이어도 **그 스텝의 확인 항목은 완결**되어야 한다.

## 1. 진행 원칙

1. 스텝 착수 전 원본 함수를 끝까지 읽고, 코드 주석에 `§조항` / 원본 `파일:라인`을 남긴다.
2. **★테스트 게이트(장군님 지시 2026-07-23)** — 한 항목을 끝내면 아래 순서를 지킨다. **여러 항목을 몰아서 만들지 않는다.**
   1) 코드 작성 → 소스 대조 + `node --check`(+ 가능하면 자체 하네스)
   2) **테스트 케이스 제시** — 장군님이 화면에서 밟을 절차(번호), 기대 결과, 실패 시 증상
   3) 장군님이 **앱 재시작 후 테스트** → 결과 회신
   4) 통과해야 **다음 항목 착수**. 실패면 그 자리에서 고친다.
3. 체크박스는 **장군님 통과 확인 후**에만 `완료`. 그전엔 `코드완료·테스트대기`.
4. 원본에 없는 UX는 만들지 않는다. 이상하면 **보고만** 하고 지시를 기다린다.
5. 공통 자산(`shell.css`/`u4a-ui.js`/`tokens.css`)은 직접 고치지 않는다 — `frame.css` 스코프 override.
