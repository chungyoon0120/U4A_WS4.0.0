# 필드 → WS20 속성 값칸 드래그 바인딩 복원 — 실행계획 (2026-08-11)

> **실행 방식:** 항목별 테스트 게이트(이 프로젝트 규칙) — Task 하나 구현 → `node --check` → 현황판 테스트 항목으로 장군님 실물 확인 통과 → 다음 Task. 몰아서 금지.
> **정답 = 원본(as-is) + `.analy` SSOT.** 임의창작 금지, 이상하면 보고만.

**목표:** 바인딩 팝업 왼쪽 "모델 필드"를 WS20 본화면 오른쪽 "속성(Properties)" 값칸에 끌어놓으면 그 속성이 그 필드로 바인딩되는 **원본 기능을 복원**한다. 현행에 통째로 빠진 "받는 부분(드롭 수신 → 검증 → 적용 호출)"을 WS20 속성패널에 신설한다.

**접근:** 발신(팝업 필드 끌기)·적용 함수·창끼리 신호·세션 도장은 **현행에 이미 존재 → 재사용**. **신설 = WS20 속성 값칸의 끌어놓기 받기 + 원본 검증·타입분기 이식 함수 1개**뿐이다.

**대상 런타임:** Electron 렌더러(별창 = 바인딩 팝업 / 본창 = WS20). 브라우저 자체 끌어놓기가 창 경계를 넘어 전달(원본이 이 방식으로 동작). 단위테스트 프레임워크 없음 → 검증 = `node --check` + 장군님 실물 테스트.

## 부록 B — 심층 본문 대조 발견 (2026-08-11, 서브에이전트 3종 교차검증)

> "함수 이름만 보고 재사용 판단하지 말고 본문·데이터구조까지" (장군님 지시) 반영해 원본↔현행을 줄 단위로 대조한 결과.

### B-1. ★크래시 (해소 완료 — 안전 종료로) 
- 원본 attrDrop 의 N건(트리/집합) 경로계산은 **살아있는 UI5 컨트롤 인스턴스**의 `prev[OBJID]._MODEL[…]`·`.__PARENT._MODEL[…]` 에서 경로를 읽는다.
- 현행 HTML5 `prev` 는 라이브 인스턴스가 아니라 **평면 데이터(`_T_0015`만 보유)** — `_MODEL` 자체가 없다(`_ensurePrev` ws_html5_ws20_attr.js:2170~. `setAggrBind`(prev.js:665)는 정의만 있고 호출 0곳).
- → 원본 코드를 그대로 복사한 트리/집합/markCellColor/rowAction 분기가 **`undefined._MODEL` 크래시**. (일반 property 는 이 구간 미진입이라 무관.)
- **조치(완료)**: `_prevOf`/`_modelOf` 안전 접근으로 감싸 없으면 `undefined` → `l_isTree && !l_path` 게이트로 "바인딩 불가(214)" 안전 종료. **크래시 제거 + 일반 property 정상.** 단 **트리/집합 바인딩 기능 자체는 아직 재현 못 함(아래 B-2).**

### B-2. 트리/집합(N건) 경로 — 현행 데이터 기준 재작성 필요 (미완)
- 현행엔 라이브 `_MODEL` 이 없으므로, N건 바인딩 경로를 **현행 데이터(`_T_0015`/T_0014/트리 노드)** 에서 얻도록 재작성해야 트리·집합 속성 바인딩이 실제로 된다.
- 소형 바인딩 팝업(사슬 아이콘) 경로가 현행에서 집합 바인딩을 어떻게 처리하는지(라이브 전용인지, 데이터 기반인지) 선(先)조사 후 설계.

### B-3. `attrCheckDropMPROP`(추가속성 점검) — 완전 누락
