# 크리티컬 오류 — 「팝업 띄우고 앱 강제 종료」 원칙이 지켜지는가 (원본 대조)

> 2026-09-21 · 장군님 물음: 「`ws_html5_shell.js` 99~107줄이 크리티컬 오류 팝업인데 왜 방어로직으로만 되어 있냐, 원본과 비교해 맞는지 분석해라」
> **소스만 읽었다. 코드는 한 줄도 안 고쳤다.** 앱 실행 없음.

---

## 0. 결론 먼저

| 물음 | 답 |
|---|---|
| 크리티컬 오류 원칙(오류창 → 앱 종료)이 지금 지켜지나 | **지켜진다.** 실제로 도는 감시견은 `ws_trycatch.js` 이고, **오류창 → 로그 폴더 열기 → `APP.exit()`** 로 원본과 같다(§2). 장군님이 겪으신 컨트롤러 크리티컬 오류도 이 길로 떴다 |
| `ws_html5_shell.js` 의 크리티컬 함수는 방어로직뿐인가 | **아니다.** 그 함수도 오류창 → 로그 폴더 → `APP.exit()` 까지 한다(§3). 다만 **원본에는 없는 함수이고, 지금 이걸 부르는 곳이 한 곳도 없다**(§3) |
| 99~107줄이 그 함수인가 | **아니다.** 그 줄은 `sap` 안전 스텁의 꼬리(메시지박스 상수 목록)다(§1). 크리티컬 함수는 **126~183줄** |

## 2. 실제 크리티컬 오류 흐름 — 원본과 같다

**감시견 = `www/ws30/ws10_20/js/ws_trycatch.js`** (원본에도 같은 파일)

| 자리 | 하는 일 |
|---|---|
| `ws_trycatch.js` 끝부분 | `window.onerror` 등록 + `unhandledrejection` 등록 |
| 오류가 잡히면 | 콘솔에 남기고 `showCriticalErrorDialog` 호출 |
| `showCriticalErrorDialog` (현행 100~141줄) | 같은 오류창 두 번 안 뜨게 막고 → **윈도우 네이티브 오류창**(제목 `[Critical Error]: Please contact the solution team.`) → 닫으면 **로그 폴더 열기** → **`APP.exit()`** |

**이 감시견을 켜는 창** (원본·현행 같은 방식 — `WSERR(window, document, console)` 호출이 있어야 켜진다)

| 창 | 현행 자리 | 원본 자리 |
|---|---|---|
| WS30 본체(장군님이 쓰시는 편집 화면) | `www/ws30/resources/index.js` 1494~1495줄 | 같은 파일 1406~1407줄 |
| 로그인 창 | `Login/Login.html` 43~45줄 | 같은 파일 202~204줄 |
| 서버 목록 창 | `ServerList_v2/ServerList.js` 62줄 | 같은 파일 146줄 |
| 미리보기 iframe · 각종 별창 | 각 파일에서 직접 호출(개수는 원본·현행 모두 다수) | 같음 |

**원본과 현행 `ws_trycatch.js` 차이** (diff 로 확인)
- 2026-09-08 추가분뿐이다: 오류가 날 때마다 **로그를 남기고 앱 본체로 전송**(첫 1건 제한 없이). 오류창은 여전히 **한 번만** 뜬다.
- **오류창 → 로그 폴더 → 앱 종료** 부분은 원본 그대로다. 즉 **원칙이 바뀐 적 없다.**

## 3. `ws_html5_shell.js` 의 크리티컬 함수(126~183줄)

**무엇인가** — `window.showCriticalErrorDialog` 라는 **전역 함수**. 하는 일은 감시견과 같다:
같은 오류창 두 번 방지 → 네이티브 오류창 → 로그 폴더 열기 → `APP.exit()`. 오류창을 못 만드는 상황이면 **그래도 종료**한다.
→ **「방어로직으로만」 은 아니다.** 앱을 끝내는 것까지 들어 있다.

**다만 세 가지가 걸린다 (보고만 — 고치라는 지시 없음)**

| # | 확인한 것 |
|---|---|
| 1 | **원본에는 이 전역 함수가 없다.** 원본 `ws_trycatch.js` 의 같은 이름 함수는 파일 안에서만 쓰는 함수라 밖에서 못 부른다 |
| 2 | **지금 이 함수를 부르는 곳이 한 곳도 없다.** 미리보기 쪽 호출 3곳(`design/preview/index.js` 900·930·5890줄)은 **현행도 원본도 전부 주석 처리**돼 있다 |
| 3 | 감시견(`ws_trycatch`)이 이미 WS30 본체 창에 걸려 있으므로, 이 창에서 나는 스크립트 오류는 **이 함수를 안 거치고** 감시견이 처리한다 |

### 3-1. 미리보기 오류는 어느 길로 가나 (2026-09-21 장군님 지적 「미리보기에서 나는 오류를 그 함수로 쓰길래」)

**지금은 그 함수를 안 쓴다. 원본도 안 쓴다.** 원본(`U4A_WS3.0.0`)과 현행이 같다.

| 자리 | 원본 | 현행 |
|---|---|---|
| `design/preview/index.js` 8줄 | 미리보기 iframe 이 **공통 감시견(`ws_trycatch`)을 자기 창에 직접 건다** (2026-08-19, 다른 개발자 `pes` 작업) | 같음 |
| 같은 파일 880~902줄 (`window.onerror`) | **전부 주석** — 주석 안에 `parent.parent.showCriticalErrorDialog(...)` 가 있다 | 같음 |
| 같은 파일 910~931줄 (`unhandledrejection`) | **전부 주석** | 같음 |
| 주석 사유(원본 주석 글) | "미리보기 영역에서 오류가 발생하는 경우 **공통 오류 처리 모듈**을 통해 오류 메시지를 처리하도록 로직 보완" | 같음 |

→ 미리보기에서 나는 오류는 **미리보기 창에 걸린 공통 감시견**이 받아 **오류창 → 로그 폴더 → 앱 종료** 로 간다(§2 와 같은 동작).
→ 그래서 `ws_html5_shell.js` 의 전역 크리티컬 함수(126~183줄)는 **아무도 안 부르는 죽은 코드**다. 그 함수 위에 제가 적어 둔 주석("미리보기 iframe 이 이 전역을 부른다")은 **2026-08-19 원본 변경 이후로는 사실이 아니다** — 제 주석이 묵었다.

## 4. 크리티컬을 「안 띄우게」 만든 자리 (원본에 없는 것 — 보고만)

| # | 자리 | 무엇을 하나 | 원본 |
|---|---|---|---|
| 1 | `js/usp/ws_html5_usp.js` 37~46줄 | `window.onerror` 를 한 번 감싸서 **`ResizeObserver loop` 로 시작하는 메시지만** 삼키고 나머지는 원래 감시견으로 넘긴다 | 원본에 없음(원본엔 이 화면 자체가 UI5) |
| 2 | `ServerList_v2/ServerList.js` 22~29줄 | 같은 `ResizeObserver loop` 경고를 창에서 가장 먼저 가로채 무시 | 원본에 없음 |
| 3 | `ServerList_v2/ServerList.js` 59~66줄 | 감시견 켜는 줄을 `try` 로 감싸고, 실패하면 그냥 `console` 로 대체 | 원본은 감싸지 않음 — 실패하면 그 창은 **감시견 없이** 돈다 |
| 4 | `ws_html5_shell.js` 45~109줄 (sap 스텁) | UI5 가 없어 생길 `ReferenceError`(원본엔 없던 오류)를 미리 막는다. 크리티컬 경로를 끄는 것이 아니라 **원본과 같은 상태로 되돌리는** 성격 | 원본은 UI5 실물이 있어 필요 없음 |

1·2 는 브라우저가 내는 무해한 경고를 막는 것이고, **3 은 실패하면 그 창만 감시견이 없어지는** 구조다.

## 5. 정해 주실 것

| 번호 | 물음 | 제 생각 |
|---|---|---|
| 1 | 장군님이 보신 99~107줄이 **다른 파일/다른 사본**인가? 지금 작업 폴더 파일에서는 그 줄이 메시지박스 상수 목록이다 | 제가 본 파일이 맞다면 **고칠 것 없다**. 다른 파일을 보고 계셨다면 파일 이름을 알려 주시면 그걸로 다시 본다 |
| 2 | `ws_html5_shell.js` 의 **부르는 곳 없는 전역 크리티컬 함수(126~183줄)** 를 어떻게 할까 | **지금은 그대로 둔다.** 원본에 없고 아무도 안 부르지만, 미리보기 쪽 주석을 나중에 살릴 수 있다. 지우는 것도 지시 주시면 한다 |
| 3 | §4-3 **서버 목록 창의 감시견이 실패해도 조용히 넘어가는 것**을 원본처럼 되돌릴까 | **되돌리는 쪽이 맞다고 본다.** 감시견이 안 걸리면 그 창은 크리티컬 오류가 나도 안 죽고 계속 조작된다 — 원칙과 어긋난다. 다만 지시 주시면 한다 |
