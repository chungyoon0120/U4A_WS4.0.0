## BR29 — autoGrowing=true 시 초기화 확인 창·이벤트 잠금 누락 (2026-08-13 통과)

**무엇을 고쳤나(쉽게)**: 표(sap.ui.table.Table)의 **"자동 늘어남(autoGrowing)"을 켬(true)으로** 바꾸면,
원본은 **"이전에 걸어둔 서버/클라이언트 이벤트가 초기화됩니다. 진행?" 확인 창**을 띄우고 → **예**를 누르면
**firstVisibleRowChanged** 이벤트를 비우고 그 줄을 **잠근다**. 그런데 현행은 확인 창도 안 뜨고 이벤트도
그대로 남고 입력도 계속 됐다. 이제 원본대로 확인 창이 뜨고, **예**면 이벤트 비우고 잠금, **아니오/취소**면
자동 늘어남을 도로 끔으로 되돌린다. 표를 다시 열어도 잠금이 유지되고, 되돌리기 한 번으로 값·이벤트가
함께 복원된다.

| 코드 | 동작 | 조작·확인 포인트 | O/X |
|---|---|---|---|
| BR29-1 | autoGrowing 을 true 로 바꾸면 초기화 확인 창이 뜬다(이벤트 등록 안 해도) | 표(sap.ui.table.Table) 선택 → 속성 목록 **autoGrowing** 줄 드롭다운 열어 **true** → "이전 이벤트가 초기화됩니다. 진행?" 확인 창이 뜬다(이벤트 없어도) | ✅ O |
| BR29-2 | 확인 창 "예" → 등록된 이벤트 비워지고 그 줄 잠김 | **firstVisibleRowChanged** 에 서버 이벤트(예: EV_TEST1) 등록 → autoGrowing **true** → 확인 창 **예** → firstVisibleRowChanged 값 **빈칸**+**흐리게(비활성)**, 이벤트 아이콘 사라짐 | ✅ O |
| BR29-3 | 확인 창 "아니오/취소" → autoGrowing 도로 false, 이벤트 유지 | firstVisibleRowChanged 에 이벤트 등록 → autoGrowing **true** → 확인 창 **아니오/취소** → autoGrowing 다시 false, firstVisibleRowChanged 값 그대로+손댈 수 있음 | ✅ O |
| BR29-4 | autoGrowing 켠 상태에선 대상 이벤트 목록 못 엶 | BR29-2 상태에서 firstVisibleRowChanged 드롭다운 클릭 → 안 열림, 서버 조회도 없음 | ✅ O |
| BR29-5 | 다른 UI 갔다 와도 잠김 유지 | BR29-2 상태 → 다른 UI 클릭 → 원래 표로 복귀 → firstVisibleRowChanged 여전히 흐리게+빈칸 | ✅ O |
| BR29-6 | 되돌리기(Undo)로 autoGrowing 끔+이벤트 복원 한 번에 | 이벤트 등록 후 autoGrowing true(예)로 값 비움 → 되돌리기(↶) 한 번 → autoGrowing 다시 false+이벤트값 재출현+손댈 수 있음 | ✅ O |

### 수정 위치
- `www/ws30/ws10_20/js/ws_html5_ws20_attr.js` — 원본에서 빠졌던 두 함수를 1:1 이식(초기화·잠금 실행부 `attrSetAutoGrowingException`, 확인 창 호출부 `attrChangeAutoGrowingProp`) + 값 변경 진입부(`fnWs20AttrChange`)에 게이트 연결(재진입 인자 `bSkipAutoGrow` 로 확인 창 무한 재호출 방지). 확인 콜백은 트리 갱신 완료를 기다리게(원본 await 계약 재현).
- 원인: 원본 값 변경 처리 안의 autoGrowing 예외처리가 HTML5 이식 때 통째로 누락. 로드 시 잠그는 함수도 이름만 불릴 뿐 본체가 없어(조용히 건너뜀) 잠금 미동작. 원본 UI5(`uiAttributeArea.js`, KEEP-UI5)는 무수정.
- 검수: `.audit/br29/` — 코덱스·안티 둘 다 통과·필수 지적 0. 공통 잔여 참고(확인 콜백 트리 갱신 완료 대기) 반영. 노션=수정완료.
- 형제 기능: `.works/속성dropAble연동/` (dropAble ↔ DnDDrop, BR31).
