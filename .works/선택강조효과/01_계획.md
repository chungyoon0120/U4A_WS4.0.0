# 옵션 팝업 "선택 강조 효과 설정" 화면 이식 계획 (정밀판)

> **작업자용:** 원본(as-is)=`optionPopup-origin/selectionEffect` + `.analy` SSOT가 정답. 임의창작 금지.
> 진행: 계획(이 문서) → 구현(단계별) → 검증(항목별 테스트 게이트). 단계 하나 끝나면 테스트 통과 후 다음.
> 소스 5개 파일 완전 정독 근거 반영(원본 화면 html/js/css, 데이터/색창/팝업, 소비처 미리보기, 현행 공통 API).

**목표:** 현행 옵션 창(`optionMain.js`)에 "선택 강조 효과 설정" 화면을 한 개 추가한다. 트리/목록/컨텍스트 메뉴에서 고른 항목을 테두리·채움·빗금(사선)·네온빛으로 강조하는 프리셋을 만들고 저장하는 화면.

**아키텍처:** 현행 옵션 창은 왼쪽 메뉴 + 우측 콘텐츠 + 확장지점(`SECTIONS`)을 갖는다(현재 "테마" 1개). 여기에 "선택 강조 효과" 섹션을 추가하고, 원본 화면의 **기능·데이터·신호 계약을 1:1로 이식**하되 **팝업/색/글자/테마는 현행 공통 자산으로 재배선**한다.

**기술 스택:** Electron 렌더러(Node 통합), `better-sqlite3`(로컬 저장), 공통 자산(`shell.css`·`bootstrap-skin.css`·`u4a-ui.js`·`tokens.css`), 공통 메시지(`oAPP.common.fnGetMsgClsText` / `WSUTIL.getWsMsgClsTxt`).

## 공통 대체 매핑 (원본 자체구현 → 현행 공통)

| 원본(optionPopup-origin) | 현행 공통 대체 | 비고 |
|---|---|---|
| `OptionPopupPopup.confirm({okText,cancelText,primaryFirst})` (Promise) | `U4AUI.confirm({buttons,onClose})` | ★현행은 **콜백형**(Promise 아님) → **Promise 어댑터**로 감싸 원본 `await` 흐름 유지 |
| `OptionPopupPopup.prompt({value,placeholder,maxLength,validate})` (Promise) | **통짜 없음** → `<dialog class="u4a-dialog">` + `U4AUI.createField({clear,maxLength:40})` + `setValueState`로 **조립** | Promise 어댑터로 반환. 이름 필수/40자/중복 검증 배선 |
| `OptionPopupPopup.toast(msg,ms)` | `parent.showMessage(null,10,TYPE,MSG)` 또는 현행 옵션 창 `_toast` 재사용 | 정중앙 싱글톤 3초 |
| `OptionPopupColorPalette.open({r,g,b,a})` (Promise) | 색창 본체는 **이식**(공통에 색 고르기 없음), 창 뼈대만 `.u4a-dialog`+`makeDialogRecenter/Resizable` | `input type=color`+고정 색칩+HEX+투명도 유지. EyeDropper 금지(Chromium 93) |
| `OptionPopupUtil.getMsgClsText` | `oAPP.common.fnGetMsgClsText(cls,no,...)` | 현행 옵션 창이 이미 사용 |
| `OptionPopupUtil.getP13nRoot/getPath/getFs/requireModule` | 현행 `optionMain.js`의 `REMOTE/FS/PATH/USERDATA` 패턴 | iframe 상위탐색 래퍼 불필요 |
| `window.parent.OptionPopupMain.setBusy` | 현행 옵션 창 `_setBusy` | 원본은 iframe 전제 → 현행은 같은 문서라 직접 호출 |
| `window.postMessage(THEME_CHANGE/SELECTION_EFFECT_CHANGE)` 수신 | 테마는 현행이 이미 IPC로 수신. 선택효과 외부 동기화는 **선택 구현**(4단계, 우선순위 낮음) | 원본 postMessage는 iframe shell→자식용. 현행엔 shell 없음 |
| 아이콘 `data-sap-icon` + `iconFont.js`(자체 폰트) | **현행 Font Awesome로 그림**(원본 아이콘 시스템 안 가져옴) | 매핑 1:1 확정: 펜/되돌리기 화살표/스포이드/세로 그립/물음표 동그라미/체크/휴지통. 물음표·휴지통은 외곽선(regular) 스타일 |
| 라벨 채우기 `applyText`(data-opt-msg-* 훑기) | **화면 그릴 때 현행 메시지 함수로 직접 채움**(문구 이미 DB에 있음). 속성 훑기 방식이 필요하면 얇게 이식 | 원본 로컬 문구표는 안 씀 |
| 원본 CSS의 `--opt-*` 자체 색 변수 | **현행 공통 의미 토큰으로 직접 치환**(브리지 아님, 자체 변수 흔적 제거) | 테마 원본 금지 지시 반영 |
| 도움말 버튼(`WLO` 조건 표시 + 문서 열기) | **이식 가능**: 조건 판정 = 현행 `checkWLOListAsync(SYSID,"C","UHAK901435")`, 문서 열기 = `fnU4AHelpDocuPopupOpener({startMenuId:"000280"})`. 조건 충족 시만 표시(원본대로) | 현행에 함수 다 있음. busy 이중 주의 |

**어댑터 요지:** 현행 `U4AUI.confirm`은 결과를 콜백으로 준다. 원본 화면 로직은 `const ok = await confirm(...)` 패턴이므로, `function confirmP(opts){return new Promise(res=>U4AUI.confirm({...opts,onClose:act=>res(act==="YES"||act==="OK")}));}` 같은 얇은 Promise 래퍼를 두고 원본 흐름을 그대로 살린다. prompt도 동일하게 조립+Promise.

## ★ 알려진 차이 — 미리보기 vs 실제 강조 (보고, 지시 대기)

원본 자체에 **설정 화면 미리보기**와 **디자인 영역 실제 강조** 사이 렌더 차이가 있음(둘 다 저장소 내 HTML5 코드, 원본 UI5 정답은 미확인):
- **빗금(사선) 간격:** 미리보기는 "간격" 값을 줄 사이 전체 폭으로, 실제 강조는 빈칸 하나 폭으로 해석 → **실제 빗금이 미리보기보다 2배 이상 성기게** 보임(기본값 기준 32px vs 72px 피치).
- **네온:** 미리보기는 가만히 있는 발광, 실제 강조는 번짐 크기가 다르고 **깜빡임(맥동) 있음**.
- 테두리·채움은 일치.

**처리 방침 = 원본대로 재현(장군님 확정 2026-08-13).** 원본 설정 화면 미리보기 공식을 **1:1 그대로 이식**하고, 읽는 쪽(디자인 미리보기)은 **손대지 않는다.** 따라서 이 빗금·네온 차이도 원본과 동일하게 그대로 재현된다. 억지로 맞추지 않는다.
