## 3. 조사 결과 (근거)

### 3-A. 편집 화면(WS20)에서 아예 안 되는 단축키 7개

앱에서 직접 확인: 이 처리기들은 옛 방식으로 화면 버튼을 찾아 누르는데, **버튼 찾기 함수가 항상 빈 값을 돌려주는 껍데기**입니다 (`function () { return null; }` — 실측).

| 키 | 화면 기능 | 마우스 버튼 |
|---|---|---|
| Ctrl+F2 | 구문 검사 | 정상 동작 |
| Ctrl+F12 | 컨트롤러(클래스 빌더) | 정상 동작 |
| F12 | U4A DEV Browser | 정상 동작 |
| Ctrl+F5 | 앱 멀티 미리보기 | 정상 동작 |
| Ctrl+Shift+F10 | 아이콘 목록 | 정상 동작 |
| Shift+F1 | 이벤트 메서드 추가 | 정상 동작 |
| F9 | 런타임 클래스 탐색기 | 정상 동작 |

**단축키만 죽어 있고 마우스는 됩니다.** 단축키 목록 팝업에는 그대로 표시돼 사용자가 있는 줄 알고 누릅니다.
USP 코드 편집 화면(WS30)은 11개 전부 정상입니다.

### 3-B. 앱 목록 화면(WS10) — 죽은 중복 8개

어플리케이션 생성 / 변경 / 삭제 / 복사 / 조회 / 실행 / 예제 열기 / 앱 멀티 미리보기.

이 8개는 **진짜 처리기가 따로** 있어(`ws10_html.js:1451`) 기능은 멀쩡합니다. 단축키 목록에 등록된 같은 8개는 죽은 그림자이고, 키를 누를 때마다 뒤따라 돌면서 **"처리중이라 불가" 로그를 찍습니다.**

★ 앱 목록 화면에서 "정상적으로 찍힌다"고 본 그 로그가 이 죽은 쪽에서 나온 것입니다. **진짜로 일하는 쪽은 로그를 안 남깁니다** — 흐림 상태면 조용히 그냥 나갑니다(`ws10_html.js:1460`). 즉 앱 목록 화면도 편집 화면과 똑같이 조용했고, 죽은 코드의 로그가 그걸 가려 주고 있었습니다.

그 진짜 처리기는 **흐림·메뉴 열림·이동중 검사를 안 합니다** — 다른 화면과 다릅니다.

### 3-C. 키 감지기 누수 (실측)

WS20 단축키 목록에 **어플리케이션 실행(F8)이 두 번** 들어 있습니다 (`ws_common.js:1553` 변환된 것 / `:1660` 옛 UI5 것).
단축키 라이브러리는 **키 하나당 하나만 기억**하므로(`shortcut.js:198`), 뗄 때 하나만 떼고 나머지는 영구히 남습니다(`:209~221`).

| 확인 방법 | 결과 |
|---|---|
| 앱 목록↔편집 화면 왕복 3번 | 감지기 106 → 107 → 108개 (왕복마다 +1) |
| 화면 이동 없이 걸고 떼기 — 편집 화면 | 걸기 20개 / 떼기 19개 → **찌꺼기 1개** |
| 같은 방법 — USP 코드 편집 화면 | 걸기 11개 / 떼기 11개 → 찌꺼기 0개 |
| 같은 방법 — 앱 목록 화면 | 걸기 10개 / 떼기 10개 → 찌꺼기 0개 |

조사 시점에 켜져 있던 앱에 이미 **108개**가 쌓여 있었습니다.
남은 찌꺼기는 첫 줄에서 **다른 감지기를 전부 끊는 호출**을 조건 없이 먼저 합니다(`ws_common.js:1557`). 그래서 일반 앱을 한 번 열었다 나온 뒤 USP 화면에서 **F8이 죽습니다**(소스 근거, 실물 재현 미확인).

### 3-D. ★ 다른 키를 눌렀는데 엉뚱한 기능이 도는 조합 7개

단축키 라이브러리가 **F키·숫자패드 키의 번호를 그대로 글자로 바꿔** 비교합니다(`shortcut.js:46`, `:167`). F8의 키 번호는 글자 'w'와 같습니다.

| 실제로 누르는 키 | 도는 기능 | 어디에 등록 |
|---|---|---|
| **Ctrl+F8** | **창 닫기** | 창 공통 |
| Ctrl+F4 | 저장 | WS20·WS30 (★이미 임시로 막아둠 — `ws_common.js:1503`) |
| Ctrl+Shift+F11 | 되돌리기 | WS20 |
| Ctrl+Shift+F9 | 다시 실행 | WS20 |
| Ctrl+숫자패드6 | 찾기 | WS20 |
| Ctrl+Shift+숫자패드6 | 텍스트 검색 | 전 화면 |
| Ctrl+숫자패드. | 새 창 | 창 공통 |

**Ctrl+F8이 가장 위험합니다** — 편집 화면에서 F8이 "어플리케이션 실행"이라 Ctrl을 같이 누르는 실수가 쉬운데, 그러면 **창이 닫힙니다**.

이 문제는 예전에 이미 발견돼 **Ctrl+F4 하나만 임시로 막아 뒀습니다**(소스 주석에 "shortcut library bug"라고 적혀 있음). 뿌리를 안 고쳐서 나머지 6개가 남아 있습니다.

또 하나: **전체화면 키(F11)가 보정키를 안 봅니다**(`electron/main.js:404`). 그래서 **Shift+F11(어플리케이션 복사)이 화면에 도달하지 못하고 전체화면만 토글**됩니다. 단축키 목록과 버튼 툴팁에는 "Shift+F11"로 안내돼 있습니다.

### 3-E. 나오기와 들어가기가 서로 다르게 만들어져 있음

| 경로 | 떠나는 키 떼기 | 새 키 걸기 |
|---|---|---|
| 편집 화면 들어가기 | 서버 응답 뒤 (`ws_html5_shell.js:974`) | 화면 그린 뒤 (`:987`) — 정상 |
| USP 화면 들어가기 | 서버 응답 뒤 (`:943`) | 화면 그린 뒤 (`ws_html5_usp.js:2614`) — 정상 |
| 편집 화면 나오기 | **서버 부르기 전** (`ws_fn_02.js:534`) — 어긋남 | 화면 그린 뒤 (`:603`) |
| USP 화면 나오기 | **서버 부르기 전** (`ws_html5_usp.js:375`) — 어긋남 | 화면 그린 뒤 (`:429`) |

**실측** — 편집 화면에서 뒤로가기 키를 0.1초 간격 12번:

| 누른 횟수 | 그 키가 걸려 있나 | 로그 |
|---|---|---|
| 1번째 | 있음 → 누른 직후 **없어짐** | 1줄 |
| 2~12번째 | **없음** | **0줄** |

같은 방법으로 앱 목록 화면에서 12번 → 키가 계속 살아 있어 **12줄** 쌓임.

되돌아가기가 서버 오류로 실패하면 **키를 다시 거는 줄에 영영 도달하지 못합니다**(서버 응답 대기가 안 풀림 — `ws_fn_02.js:560~576`, `ws_html5_usp.js:398~409`). 그 화면 단축키가 전부 죽은 채 남습니다.

|---|---|
| 라이브러리 조회 거절 | `ws_html5_ws20_attr.js:2260` |
| 가운데 미리보기가 끝까지 안 뜸 | `ws_html5_ws20_prev.js:1834` — **주석엔 60초 안전장치라 적혀 있으나 코드에 없음** |
| USP 되돌아가기 중 오류 | `ws_html5_usp.js:384`, `:438` |

그 밖에: USP 되돌아가기 "아니오" → 흐림 없이 서버 왕복(`:526`) / 화면이 옆에서 미끄러져 들어오는 0.4초 동안 흐림이 먼저 풀림(`ws_html5_shell.js:1046`).

### 3-G. 이동중 잠금

- **8초 뒤 저절로 풀립니다**(`ws_common.js:692`). USP 확인창을 10초만 붙들고 `No`를 누르면 **되돌아가기가 두 번 실행**되고 서버에 앱 잠금해제가 두 번 나갑니다.
- USP 저장 실패 갈래 3개에서 잠금을 안 풉니다(`ws_html5_usp.js:760~777`) → 8초간 화면이 죽은 것처럼 됨.
- 편집 화면 되돌아가기 화살표에는 **잠금 검사가 없습니다**(`ws_html5_ws20.js:718`). 지금 안 터지는 건 흐림 처리가 마우스를 막아 주기 때문 — 흐림을 손대면 바로 뚫립니다.
- 편집 화면 → 앱 목록 마무리 구간에 **오류처리가 없습니다**(`ws_fn_02.js:542~626`). 한 번 터지면 흐림도 안 풀리고 키도 죽습니다.

**결함 없음으로 확인**: 새 화면 키 등록이 잠금 해제보다 항상 먼저입니다(세 경로 전부).

### 3-H. 작은 창·말풍선의 감시 쌓임

- 속성 설명글 작은 창: 다시 열 때 정리 함수를 안 불러 이전 감시가 쌓임 (`ws_html5_ws20_attr.js:6818`)
- 옆메뉴 "System Information" 말풍선: 같은 문제 (`ws_html5_ws20.js:1268`)
- 별도 창(옵션·화면녹화·값도움 등)은 창이 통째로 사라져 문제 없음

### 3-I. 등록표에 "어느 화면 것인지"가 없음 (구조)

등록표는 **키 이름 하나로만** 기억합니다. A 화면 키가 살아 있는 상태에서 B 화면 키를 걸면, **공유 키가 B 것으로 덮이고** 나중에 B를 뗄 때 **A 것까지 사라집니다.**
조사 중 실제로 재현됐습니다(앱 목록 화면 키 6개가 통째로 사라짐 → 바로 복구함).
**지금 앱 흐름에서는 안 터집니다** — 전환할 때 항상 "이전 것 떼고 → 새 것 걸기" 순서라서. 다만 순서를 하나만 바꿔도 조용히 6개가 죽는 구조입니다.

### 3-J. 빌드된 앱에서는 앱 로그가 전부 꺼짐

앱의 로그 함수 세 개(일반·오류·경고)가 **첫 줄에서 "빌드판이면 그냥 나감"** 입니다(`ws_trycatch.js:201`, `:217`, `:231`). 조사에 쓴 앱은 **빌드판이 아니라서** 로그가 보였습니다.

**자동 테스트는 빌드된 앱이 대상이므로 앱 로그로 판정하면 안 됩니다.** 도구는 화면 이름·흐림 여부·걸린 키 목록을 직접 물어보는 방식으로 이미 만들어져 있습니다.

또한 공통 단축키 검사 4줄이 **예외를 통째로 삼킵니다**(`ws_common.js:674~678`). 여기서 터지면 흔적이 0입니다.

### 3-K. 결함 없음으로 확인된 것

- 로그인·로그아웃·세션만료 후 재진입 — 창을 통째로 닫고 새로 시작하므로 두 번 등록되는 길 없음
- 창 공통 단축키(새 창·창 닫기·배율 되돌리기) — 부팅 시 1회만 등록, 창을 여러 개 띄워도 문제 없음
- USP 코드 편집 화면 단축키 11개 — 전부 정상 변환, 중복·누수 없음
- 확인창은 버튼을 누르면 창을 닫고 곧바로 다음 처리를 부름 — 중간에 키가 낄 틈 없음
