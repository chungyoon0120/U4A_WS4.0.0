## A. 당장 고칠 것

### A-1. Ctrl+F8 을 누르면 창이 닫힌다

**현상**
편집 화면에서 Ctrl 을 누른 채 F8 을 누르면 **창이 닫힌다.** F8 이 "어플리케이션 실행"이라 Ctrl 을 같이 누르는 실수가 잦다.

**재현**
① 아무 화면에서 ② Ctrl 을 누른 채 F8 ③ 창이 닫힘

**원인**
단축키 라이브러리가 **키 번호를 그대로 글자로 바꿔서** 비교한다 (`www/js/shortcut.js:46`, 판정부 `:167`).
F8 의 키 번호는 글자 `w` 와 같다. 그래서 `Ctrl+F8` 이 `Ctrl+W`(창 닫기)로 인식된다.
창 닫기 등록 위치: `www/ws30/ws10_20/js/ws_common.js:2883` (`fnSetCommonShortcut` 안)

**이 문제로 실제로 오작동하는 조합 전체** (앱에 등록된 것과 대조해 뽑은 실측 목록)

| 누르는 키 | 실제로 도는 것 | 지금 상태 |
|---|---|---|
| **Ctrl+F8** | 창 닫기 | **안 막힘 — 고칠 것** |
| Ctrl+F4 | 저장 | 이미 막아둠 (`ws_common.js:1504`, `:2116`) |
| Ctrl+Shift+F9 | 다시 실행 | 이미 막아둠 (`ws_common.js:2923`) |
| Ctrl+Shift+F11 | 되돌리기 | 지금은 A-2 버그가 가려줌 → **A-2 를 고치면 드러난다. 같이 막을 것** |
| Ctrl+숫자패드6 | 찾기 | 안 막힘 (숫자잠금 켠 상태에서만. 실기 확인 안 함) |
| Ctrl+Shift+숫자패드6 | 텍스트 검색 | 안 막힘 (같음) |
| Ctrl+숫자패드. | 새 창 | 안 막힘 (같음) |

**고치는 법**
라이브러리를 고치지 말고, **같은 키를 "아무것도 안 하는 흡수용"으로 먼저 등록**한다. 이 프로젝트에 이미 쓰고 있는 방식이다 — `ws_common.js:1504` 의 저장키 막이를 그대로 따라 하면 된다.

핵심은 **등록 순서**다. 흡수용이 **먼저** 등록돼야 뒤에 등록된 진짜 키를 막을 수 있다.

- `Ctrl+F8` 은 창 닫기(창 공통)와 부딪히므로, **`fnSetCommonShortcut` 안에서 창 닫기 등록보다 앞줄에** 흡수용을 넣는다.
  - 위치: `www/ws30/ws10_20/js/ws_common.js` 의 `fnSetCommonShortcut`(:2858) 시작 직후, 새 창 등록(:2863)보다 앞
- `Ctrl+Shift+F11` 은 되돌리기(WS20 목록)와 부딪히므로, **WS20 목록 안에서 되돌리기 항목보다 앞에** 흡수용 항목을 넣는다.
- 숫자패드 3건은 라이브러리가 숫자패드 이름을 모른다. **키 번호로 직접 잡아야** 하므로 별도 방식이 필요하다 → **이번 범위에서 제외**, 별도 지시 대기.

흡수용은 이렇게 생긴 것이다(기존 저장키 막이와 동일 형태):
- 아무 동작도 하지 않는다
- 첫 줄에서 `e.stopImmediatePropagation()` 을 부른다
- 단축키 목록 팝업에 안 뜨게 `VISIBLE: false` 를 준다(목록에 넣는 경우)

**주의**
- 흡수용을 **뒤에** 등록하면 아무 소용이 없다. 반드시 앞이어야 한다.
- 흡수용을 넣으면 그 조합은 앞으로 **아무 일도 안 하게** 된다. 그게 맞는 동작이다.

**확인**
① Ctrl+F8 → 창이 안 닫혀야 함 ② Ctrl+W → 창이 닫혀야 함(원래 기능 살아 있는지) ③ F8 단독 → 어플리케이션 실행이 되어야 함

### A-2. 어플리케이션 복사(Shift+F11)가 아예 안 된다

**현상**
개발자 권한 계정으로 앱 목록 화면에서 Shift+F11 을 눌러도 복사가 안 되고 **전체화면만 켜졌다 꺼진다.** 단축키 목록과 버튼 설명글에는 "Shift+F11" 이라고 안내돼 있다.

**재현**
① 개발자 권한 계정으로 앱 목록 화면 ② 앱 이름 입력 ③ Shift+F11 ④ 복사 안 되고 전체화면만 토글됨

**원인**
앱 바깥층에서 F11 을 가로채 전체화면을 켜는데, **보정키(Shift·Ctrl·Alt)를 안 본다.**
위치: `electron/main.js:404`

```
if (input.type === 'keyDown' && input.code === 'F11' && !input.isAutoRepeat) {
```

그 다음 줄에서 키를 화면으로 못 가게 막아버린다(`:405`). 그래서 Shift+F11 이 화면까지 도달하지 못한다.

**고치는 법**
그 조건에 **보정키가 하나도 안 눌린 경우만** 걸리도록 추가한다. 이 자리에서 쓸 수 있는 값은 `input.shift`, `input.control`, `input.alt`, `input.meta` 다.

**주의 — A-1 과 엮여 있다**
이걸 고치면 **Ctrl+Shift+F11 이 화면까지 도달**하게 되고, 그 순간 A-1 의 판정 결함 때문에 **되돌리기가 실행된다.** 그러니 A-1 의 `Ctrl+Shift+F11` 흡수용을 **같이** 넣어야 한다. 둘을 따로 고치면 안 된다.

**확인**
① Shift+F11 → 복사 창이 떠야 함 ② F11 단독 → 전체화면 토글이 되어야 함 ③ Ctrl+Shift+F11 → **아무 일도 안 일어나야 함**

## B. 흐림 · 누수

### B-1. 편집 화면 실행 단축키가 두 번 등록돼 키 감시가 무한히 쌓인다

**현상**
앱 목록 화면 ↔ 편집 화면을 왕복할 때마다 문서에 키 감시가 **1개씩 영구히 쌓인다.** 조사 시점 앱에 이미 108개가 쌓여 있었다.
또한 그 찌꺼기 때문에, 일반 앱을 한 번 열었다 나온 뒤 **USP 코드 편집 화면에서 F8(어플리케이션 실행)이 죽는다**(소스 근거. 실물 재현은 안 해봄).

**실측**

| 확인 방법 | 결과 |
|---|---|
| 왕복 3번 | 감시 106 → 107 → 108개 |
| 화면 이동 없이 걸고 떼기 — 편집 화면 | 걸기 20개 / 떼기 19개 → 찌꺼기 1개 |
| 같은 방법 — USP 화면 | 11 / 11 → 0개 |
| 같은 방법 — 앱 목록 화면 | 10 / 10 → 0개 |

**원인**
편집 화면 단축키 목록에 **어플리케이션 실행(F8)이 두 번** 들어 있다.
- `www/ws30/ws10_20/js/ws_common.js:1553` — HTML5 로 변환된 것 (**살릴 것**)
- `www/ws30/ws10_20/js/ws_common.js:1660` — 옛 UI5 것 (**지울 것**)

단축키 라이브러리는 키 하나당 하나만 기억하므로(`shortcut.js:198`), 뗄 때 하나만 떼고 나머지는 영구히 남는다(`:209~221`).

**고치는 법**
`ws_common.js:1660` 의 F8 항목(옛 UI5 것) **하나를 통째로 지운다.** `:1553` 은 그대로 둔다.
- 지우는 항목이 맞는지 확인법: 그 항목 안에 `sap.ui.getCore().byId(` 가 있으면 옛 UI5 것이다.

**확인**
① 앱 목록 ↔ 편집 화면을 5번 왕복 ② 자동 테스트 도구로 키 감시 개수가 **안 늘어나는지** 확인 ③ 편집 화면에서 F8 → 어플리케이션 실행이 되어야 함 ④ 일반 앱을 열었다 나온 뒤 USP 앱을 열고 F8 → 실행되어야 함

### B-2. 가운데 미리보기가 끝까지 안 뜨면 흐린 화면이 영영 안 풀린다

**현상**
앱을 편집 화면으로 열었는데 가운데 미리보기가 안 그려지면 **화면이 흐린 채로 멈춘다.** 아무 버튼도 안 먹는다.

**원인**
흐림을 끄는 자리가 "미리보기가 다 떴다"는 신호 하나뿐인데, 그 신호를 못 보내고 빠져나가는 갈래가 여러 개 있다.
그리고 **주석에는 "60초 안전장치가 돈다"고 적혀 있으나 실제 코드에 그런 시간 재기가 없다.**
위치: `www/ws30/ws10_20/js/ws_html5_ws20_prev.js:1834` 부근(흐림 끄기·켜기 함수), 주석은 `:1958` 부근

**고치는 법**
흐림을 켤 때 **시간 안전장치를 같이 건다.** 정한 시간 안에 완료 신호가 안 오면 흐림을 풀고 로그를 남긴다.
- 예약한 시간 재기는 **반드시 핸들을 저장**하고, 완료 신호가 오면 **먼저 취소**한다(안 그러면 나중에 엉뚱한 때 풀린다).
- 시간 값은 장군님께 확인받는다. 주석에 적힌 값은 60초.

**확인**
① 가운데 미리보기가 안 그려지는 앱을 편집 화면으로 엶 ② 정한 시간 안에 흐림이 풀리고 조작이 되는지 ③ 정상 앱에서는 미리보기가 뜬 뒤 **바로** 풀리는지(안전장치가 정상 흐름을 방해하면 안 됨)

## C. 되돌아가기 계열 (연타 테스트 대응)

### C-1. 되돌아가기가 서버 부르기 전에 단축키를 떼어버린다

**현상**
편집 화면에서 뒤로가기 키를 연타해도 **두 번째부터는 앱에 아무 기록이 안 남는다.** 눌러도 받는 데가 없기 때문이다.
그리고 되돌아가기가 서버 오류로 실패하면 **그 화면 단축키가 전부 죽은 채로 남는다.** 나가는 키도 죽어서 마우스로만 빠져나갈 수 있다.

**실측** — 편집 화면에서 뒤로가기 키 0.1초 간격 12번

| 누른 횟수 | 그 키가 걸려 있나 | 앱 기록 |
|---|---|---|
| 1번째 | 있음 → 누른 직후 없어짐 | 1줄 |
| 2~12번째 | 없음 | **0줄** |

같은 방법으로 앱 목록 화면에서 12번 → 키가 계속 살아 있어 **12줄** 쌓임.

**원인 — 들어가기와 나오기가 서로 다르게 만들어져 있다**

| 경로 | 떠나는 키 떼기 | 새 키 걸기 |
|---|---|---|
| 편집 화면 들어가기 | 서버 응답 뒤 (`ws_html5_shell.js:974`) | 화면 그린 뒤 (`:987`) — 정상 |
| USP 화면 들어가기 | 서버 응답 뒤 (`:943`) | 화면 그린 뒤 (`ws_html5_usp.js:2614`) — 정상 |
| 편집 화면 나오기 | **서버 부르기 전** (`ws_fn_02.js:534`) — 어긋남 | 화면 그린 뒤 (`:603`) |
| USP 화면 나오기 | **서버 부르기 전** (`ws_html5_usp.js:375`) — 어긋남 | 화면 그린 뒤 (`:429`) |

**고치는 법**
나오기 두 곳의 **"키 떼기"를 맨 뒤로 옮긴다** — 새 화면 키를 거는 줄 바로 앞으로.
- `www/ws30/ws10_20/js/ws_fn_02.js:534` → `:603` 바로 앞
- `www/ws30/ws10_20/js/usp/ws_html5_usp.js:375` → `:429` 바로 앞

**주의 — 왜 지금 앞에 있는지**
그 자리 주석에 "연타로 다시 나가는 것·화면 깨짐을 막으려고 일부러 맨 먼저 떼도록 바꿨다"고 적혀 있다.
그 걱정은 **"이동 중" 잠금이 대신 막는다.** 되돌아가기 시작할 때 이미 걸고(`ws_fn_02.js:526`, `ws_html5_usp.js:465`), 단축키 검사가 그걸 본다(`ws_common.js:714`).
그러니 옮겨도 안전하다. **다만 옮긴 뒤 반드시 아래 확인을 통과해야 한다.**

**확인**
① 편집 화면에서 뒤로가기 키를 0.1초 간격 연타 → 앱 기록에 "처리중이라 불가" 또는 "페이지 이동 중이라 불가"가 **누를 때마다 한 줄씩** 쌓이는지

③ 앱 목록 화면에 도착한 뒤 뒤로가기 키가 **안 남아 있는지**
④ USP 화면에서도 ①~③ 동일하게

### C-3. 편집 화면 되돌아가기에는 "이동 중" 잠금 검사가 없다

**현상**
지금 두 번 실행되지는 않는다. 다만 **막고 있는 게 잠금이 아니라 "흐림 처리가 마우스를 꺼주는 것"** 이라, 흐림 쪽을 조금만 손대면 바로 뚫린다.

**원인**
- 되돌아가기 화살표: `www/ws30/ws10_20/js/ws_html5_ws20.js:718` — 검사 없이 바로 실행
- 되돌아가기 본체: `www/ws30/ws10_20/js/ws_events.js:1232` — 첫머리에 검사 없음, 잠금 걸기도 없음

- 비교 대상: USP 화면은 함수 첫머리에서 직접 검사한다(`ws_html5_usp.js:464`)

**고치는 법**
USP 화면과 같은 모양으로 맞춘다.
- 되돌아가기 본체(`ws_events.js:1232`) 첫머리에서 **이동 중이면 그냥 나간다**
- 흐림을 켜는 줄 뒤에 **잠금도 같이 건다**
- 확인창에서 **취소**를 고르면 **잠금을 푼다**(`ws_events.js:1282` 자리). USP 쪽이 이미 그렇게 한다(`ws_html5_usp.js:501`)

**확인**
① 편집 화면에서 되돌아가기 화살표를 빠르게 두 번 클릭 → 한 번만 돌아야 함
② 확인창에서 취소 → 그 뒤 뒤로가기 키·다른 단축키가 정상으로 먹어야 함

### C-4. "이동 중" 잠금이 8초 뒤 저절로 풀린다 → 되돌아가기가 두 번 실행됨

**현상**
USP 코드 편집 화면에서 **확인창을 10초만 붙들고 있다가 "아니오"를 고르면, 되돌아가기가 두 번 실행된다.** 서버에 앱 잠금해제가 두 번 나간다.

**재현**
① USP 코드 편집 화면을 수정 모드로 열고 코드를 고침 ② 되돌아가기 화살표 ③ "저장하고 나갈까요?" 창을 **10초 이상 그대로 둠** ④ `No` ⑤ 곧바로 되돌아가기 화살표를 다시 누름

**원인**
잠금에 **8초 뒤 저절로 풀리는 시한**이 걸려 있다 — `www/ws30/ws10_20/js/ws_common.js:692`.
게다가 이 갈래는 **흐림도 안 켠다**(C-5) → 잠금도 풀리고 흐림도 없으니 아무것도 안 막는다.

**고치는 법 (장군님 결정 필요)**
- 안: 사람 응답을 기다리는 동안에는 그 시한을 **멈춘다**(확인창 띄우기 전에 잠금 해제 시한을 끄고, 답을 받은 뒤 다시 건다)
- 또는: 시한 값을 늘린다
- 또는: C-5 를 고쳐 흐림으로 막는다
→ **어느 쪽으로 갈지 먼저 물어볼 것.** 시한 자체를 없애면 서버가 죽었을 때 영구히 잠기므로 없애면 안 된다.

**확인**
위 재현 순서대로 했을 때 되돌아가기가 **한 번만** 도는지

### D-1. 편집 화면 단축키 7개가 아무 동작도 안 한다

**현상**
아래 7개는 눌러도 **아무 일도 안 일어나고 오류도 안 난다.** 같은 기능의 화면 버튼을 마우스로 누르면 정상 동작한다.
그런데 단축키 목록 팝업에는 그대로 표시돼 사용자가 있는 줄 알고 누른다.

**원인**

각 키가 눌러야 할 실제 화면 버튼·동작 함수는 그 화면의 버튼 배선에서 찾는다.

**확인**
편집 화면에서 7개를 하나씩 눌러 각 기능이 뜨는지. 같은 기능의 마우스 버튼과 결과가 같아야 한다.

### D-2. 앱 목록 화면에 죽은 중복 단축키 8개가 등록돼 있다

**현상**
기능은 멀쩡하다(진짜 처리기가 따로 있다). 다만 **같은 키가 두 벌 등록돼 있고**, 죽은 쪽이 키를 누를 때마다 뒤따라 돌면서 **헷갈리는 기록을 남긴다.**

★ 지금까지 앱 목록 화면에서 "정상적으로 기록이 남는다"고 본 그것이 **이 죽은 쪽이 남긴 것**이다. 진짜로 일하는 쪽은 기록을 안 남긴다.

**대상 8개**: 어플리케이션 생성 / 변경 / 삭제 / 복사 / 조회 / 실행 / 예제 열기 / 앱 멀티 미리보기

**고치는 법**
죽은 8개를 목록에서 **뺀다.**

**주의**
- 죽은 쪽은 첫 줄에서 **다른 감시를 전부 끊는 호출**을 조건 없이 한다. 지금은 등록 순서 덕에 무해하지만, 순서가 한 번만 바뀌면 8개가 통째로 죽는다. 그래서 빼는 게 맞다.
- 빼면 단축키 목록 팝업에서도 사라질 수 있으니, **팝업에 계속 보여야 하는지 확인**하고 필요하면 목록용 정보만 남긴다.

**확인**
앱 목록 화면에서 8개를 하나씩 눌러 **전과 똑같이 동작**하는지. 그리고 누를 때 헷갈리는 기록이 **안 남는지.**

### D-3. 앱 목록 화면 단축키가 공통 검사를 안 거친다

**고치는 법**

**확인**

## E. 정리 · 구조

### E-1. 작은 창을 다시 열 때 이전 키 감시가 안 떨어진다

**현상**
같은 작은 창을 여러 번 열면 감시가 쌓인다. 남은 감시가 Esc 를 가로채 다른 창의 Esc 가 안 먹을 수 있다.

**대상 2곳**
- 속성 설명글 작은 창: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js` — 거는 곳 `:6933`, 떼는 곳 `:6912`, **안 부르는 자리 `:6818`**
- 옆메뉴 "System Information" 말풍선: `www/ws30/ws10_20/js/ws_html5_ws20.js` — 거는 곳 `:1342`, 떼는 곳 `:1331`, **안 부르는 자리 `:1268`**

**고치는 법**
다시 열기·닫기 경로에서 **정리 함수를 부른 뒤** 새로 걸도록 한다.

**확인**
① 편집 화면 속성 영역에서 속성 이름을 클릭해 설명글 창을 엶 ② Esc 말고 다른 속성 이름을 클릭 ③ 5번 반복 ④ 그 뒤 Esc 로 창이 **한 번에** 닫히는지

### E-2. 빌드된 앱에서는 앱 기록이 전부 꺼진다 (정책 결정 필요)

**사실**
앱의 기록 함수 세 개(일반·오류·경고)가 **첫 줄에서 "빌드판이면 그냥 나감"** 이다.
위치: `www/ws30/ws10_20/js/ws_trycatch.js:201`, `:217`, `:231`

조사에 쓴 앱은 빌드판이 아니어서 기록이 보였다. **빌드된 앱에서는 한 줄도 안 남는다.**

**왜 문제인가**
자동 테스트는 **빌드된 앱**이 대상이다. 앱 기록으로 판정할 수 없다.
(자동 테스트 도구는 이미 화면 이름·흐림 여부·걸린 키 목록을 직접 물어보는 방식으로 만들어져 있어 영향 없음.)

**결정할 것**
빌드판에서도 **오류만은** 남길지. → 장군님 결정 대기. 지시 없으면 손대지 말 것.

---

### E-3. 단축키 검사가 예외를 통째로 삼킨다

**현상**
공통 단축키 검사 4줄이 예외를 잡고 아무것도 안 남긴다. 여기서 터지면 흔적이 0이다.
위치: `www/ws30/ws10_20/js/ws_common.js:674~678`

**고치는 법**
프로젝트 예외처리 규칙대로, **오류코드를 붙여 드러낸다.** 화면에는 예외 원문·스택을 노출하지 않는다.

- 창 공통 단축키(새 창 / 창 닫기 / 배율 되돌리기) — 부팅 시 1회만 등록, 창 여러 개 띄워도 문제 없음
- USP 코드 편집 화면 단축키 11개 — 전부 정상 변환, 중복·누수 없음
- 확인창 — 버튼을 누르면 창을 닫고 곧바로 다음 처리를 부름. 중간에 키가 낄 틈 없음
- 새 화면 키 등록이 잠금 해제보다 항상 먼저 — 세 경로 전부 순서 정상

## G. 참고 — 확인에 쓸 도구

`test/cdp-auto-test/` — 켜져 있는 앱에 붙어 화면에 따라 단축키를 0.1초 간격으로 계속 누른다.

- `node edit-back-loop.js --help` 로 사용법
- 누를 때마다 직전 누름과의 간격이 기록됨
- 그 화면에 필요한 키가 앱에 안 걸려 있으면 `※앱이 이 키를 안 듣고 있음` 표시
- 흐림이 1분 넘게 안 풀리면 기록 남기고 전체 종료
- 오류 원문은 `logs/run_*_errors.jsonl` 에 한 줄에 하나씩

**앱을 미리 켜고 로그인해서 앱 목록 화면에 둔 뒤** 실행한다.

전체 조사 결과·테스트 체크리스트는 같은 폴더의 `00_현황판.md` 참고.
