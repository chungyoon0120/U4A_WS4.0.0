## 무엇을 고쳤나 (2026-09-14)

**증상**: "아이콘 즐겨찾기 항목" 창에서 아이콘 이름 복사 버튼을 눌러도 붙여넣기가 안 된다. 그런데 "복사되었습니다" 안내는 정상으로 떴다.

**원인**: 셸의 공통 복사 함수(`www/ws30/resources/index.js` 의 `setClipBoardTextCopy`)는 원본 그대로 임시 `<textarea>` 를 `document.body` 에 붙이고 `document.execCommand('copy')` 를 부른다. 이 창은 HTML5 변환 때 native `<dialog>` + `showModal()` 로 바뀌었는데, **모달이 열려 있으면 같은 document 의 dialog 바깥이 전부 inert** 라 그 textarea 를 `select()` 할 수 없다. 복사되는 내용이 없는데 **`execCommand` 는 `true` 를 돌려주므로** 아무도 실패를 모른다.

원본(UI5)에서는 이 창이 `sap.m.ResponsivePopover` 였다 — native 모달이 아니라 inert 가 안 걸렸다.

**왜 다른 창은 멀쩡한가** (전수 조사):

| 방식 | 쓰는 곳 | 모달 열린 상태 |
|---|---|---|
| Electron `clipboard` 모듈 | 소스 패턴 창, 글꼴 마법사, 이미지 아이콘 창, USP 주소 복사 | 정상 |
| textarea + `execCommand` + 성공확인 + `navigator.clipboard` fallback | 에디터, 런타임 클래스 창, WS20 속성 영역 | fallback 이 받는다 |
| textarea + `execCommand` 만, 반환값 안 봄 | 셸 공통 복사 함수 ← 즐겨찾기 팝업이 이걸 썼다 | **조용히 실패** |

**고친 내용**:
1. `www/ws30/resources/index.js` — 공통 복사 함수를 **Electron `clipboard` 우선 + 기존 textarea 방식 fallback** 으로 바꿨다. fallback 은 `execCommand` 반환값만 믿지 않고 **selection length 까지** 봐서 진짜 성공을 판정한다. 함수가 **성공 여부(true/false)를 돌려준다.** 실패하면 오류코드 `RSRC-007` 로 표면화 + 로그.
2. `www/ws30/ws10_20/js/fnFavIconPopupOpen.js` — 복사가 실제로 성공했을 때만 "복사되었습니다" 안내를 띄운다. 실패하면 오류코드 `FFIP-001` 로 표면화 + 로그(성공 안내 안 띄움).

**실측 검증** (실제 소스에서 함수를 그대로 뽑아 Electron 14.2.9 / Chromium 93 에서 실행):

| 경우 | 반환 | 실제 clipboard |
|---|---|---|
| 모달 없음 | true | `sap-icon://account` ✅ |
| **모달 열림** | **true** | **`sap-icon://favorite`** ✅ (고쳐지기 전에는 안 바뀜) |
| 문자열 아닌 값 | false | — |
| Electron clipboard 못 쓰는 창 + 모달 없음 | true | fallback 으로 복사됨 ✅ |
| Electron clipboard 못 쓰는 창 + 모달 열림 | **false** | 복사 안 됨 — **실패를 정직하게 알린다** |
| 임시 textarea 뒷정리 | 실패 경로에서도 body 에 남지 않음(0개) | ✅ |

**아직 안 한 것 / 보고**
- 실제 앱을 띄워 손으로 눌러 본 확인은 **미완** — 위 테스트 표가 그것이다.
- 복사 **실패 전용 메시지 키가 없어** 실패해도 화면 안내는 하지 않는다(콘솔 오류코드 + 로그만). 화면에도 알리려면 메시지가 하나 필요하다 — 장군님이 넣어 주시면 배선하겠다.
- `www/ws30/ws10_20/js/ws_html5_ws20_attr.js` 의 자체 복사도 fallback 쪽에서 `execCommand` 결과를 안 보고 성공으로 처리한다. 지금은 모달 안에서 쓰지 않아 증상이 없어 **손대지 않았다.**

## 추가 수정 (2026-09-14) — 복사한 값으로 검색이 안 되던 것

**장군님 지적**: 검색 기능을 넣었으면 **복사 버튼으로 복사한 값**으로도 찾아져야 한다.

**전에는**: 즐겨찾기 창 검색이 **화면에 보이는 이름만**(예: `account`) 봤다. 복사되는 값은 `sap-icon://account` 라서 붙여넣으면 0건이었다.

**지금은**: 이름 + `sap-icon://...` 값을 함께 본다. 같은 앱의 **아이콘 뷰어** 검색도 `sap-icon://...` 값을 대상으로 쓴다 — 그 기준에 맞췄다.

**실측** (실제 소스의 필터 코드를 그대로 뽑아 Electron 14.2.9 에서 실행, 타일 4개):

| 검색어 | 결과 |
|---|---|
| `sap-icon://account` (복사한 값) | 1 / 4 ✅ (전에는 0건) |
| `account` (이름) | 1 / 4 ✅ |
| `SAP-ICON://BELL` (대문자) | 1 / 4 ✅ |
| `address` (일부만) | 2 / 4 ✅ |
| `zzzz` (없는 값) | 0 / 4 + "결과 없음" ✅ |
| 빈칸 | 4 (전체) ✅ |

**아직 안 한 것**: 즐겨찾기 파일에는 낱말 목록(`KEYWORD_STRING`, 예 `user|arrow|door|visit|login|entry|`)도 함께 저장돼 있고 **아이콘 뷰어는 그것으로도 검색**한다. 이번엔 장군님이 말씀하신 **복사한 값까지만** 넣었다 — 낱말 검색도 맞추려면 지시 주시면 붙인다.
