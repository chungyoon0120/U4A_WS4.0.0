## 1. 지금 상태 (소스 실측 2026-10-08)

- 공통 테마 토큰에 `"72", "72full", Arial, Helvetica, sans-serif` 라고 **이름만** 적혀 있다.
- **글꼴 파일도, `@font-face` 선언도 프로젝트 안에 없다**(전수 grep 0건).
  들어 있는 글꼴 파일은 **아이콘 글꼴 3개(woff2)뿐**이고 나머지는 Monaco·Ace 같은 라이브러리 안 것.
- 따라서 PC 에 `72` 가 깔려 있지 않으면 실제로는 **Arial → Helvetica → 시스템 sans-serif** 로 떨어진다.
- 한글은 Arial 에 없으므로 **Windows 가 알아서 고른 한글 글꼴**(맑은 고딕 등)로 그려진다
  → **PC 설정에 따라 모양이 달라진다.**

## 2. ★SAP 72 에는 한글이 없다 (파일 크기로 확정)

OpenUI5 가 함께 배포하는 글꼴 파일 크기를 실제로 재 보았다(GitHub API, 2026-10-08):

| 파일 | 크기 |
|---|---|
| 72 Regular (작은 판) | 약 23 KB |
| 72 Regular (full 판) | 약 58 KB |

한글은 조합된 글자가 **11,172자**다. 한글이 들어간 글꼴은 **1 MB 를 넘는다**
(Pretendard Regular woff2 가 1 MB 대). **58 KB 에는 한글이 들어갈 수 없다.**
`full` 이라는 이름은 「한글까지」가 아니라 **라틴·그리스·키릴 확장**을 뜻한다.

SAP 공식 Typography 문서도 72 뒤에 **Arial·Helvetica·시스템 글꼴**을 두고,
「특수 문자는 시스템 글꼴이 받는다 · 시스템 글꼴은 SAP 이 지원하는 모든 언어에 있다」고만 적어 두었다.
**CJK(한·중·일) 전용 글꼴을 지정하는 문장은 없다.**

→ **72 를 넣어도 화면의 한글은 하나도 안 바뀐다.** 영문·숫자만 SAP 모양이 되고
한글은 PC 글꼴로 남아 **두 글꼴이 섞인다.**

## 2-1. ★장군님 지적 2건 — 둘 다 맞습니다 (확인 2026-10-08)

**① 「bootstrap 에 KO 로 지정하면 한글도 잘 나오던데?」 · ② 「기본 i18n 텍스트도 잘 나오던데?」**

둘 다 맞습니다. 다만 **두 가지가 서로 다른 층**입니다.

| 무엇 | 하는 일 | 글꼴과 관계 |
|---|---|---|
| bootstrap 의 language 지정 | UI5 라이브러리의 **한국어 번역 묶음**을 받아 온다 + 날짜·숫자 형식을 한국 방식으로 | **없다.** 글자 모양을 바꾸지 않는다 |
| 글꼴 설정 | 그 글자를 **어떤 모양으로 그릴지** | 이것이 글꼴 |

**그래서 UI5 에서 한글이 잘 보이는 까닭** = 72 가 한글을 그려서가 아니라,
**72 뒤에 적힌 시스템 글꼴이 받아 주기 때문**입니다.

### ★결정적 근거 — UI5 가 실제로 쓰는 글꼴 줄을 받아서 확인했다

OpenUI5 가 서비스하는 테마 설정값 파일에서 글꼴 항목을 직접 받아 봤다(2026-10-08):

```
"72","72full",Arial,Helvetica,sans-serif
```

**우리 WS4.0 토큰에 적힌 것과 글자 하나까지 똑같다.**
→ **WS4.0 은 이미 SAPUI5 와 같은 글꼴 줄을 쓰고 있다.** 72 파일만 안 들어 있는 것이고,
한글은 UI5 에서도 우리에서도 **똑같이 Windows 한글 글꼴**이 그리고 있다.

### SAP 공식 문서도 언어별로 다른 글꼴을 쓴다고 적어 두었다

SAP Typography 문서에 **언어별 대체 글꼴 표**가 있다(검색 결과로 확인, 페이지 직접 열기는 403 으로 막힘 — 미확인):

| 언어 | SAP 이 쓰는 글꼴 |
|---|---|
| 한국어 | **Microsoft Malgun Gothic**(맑은 고딕) |
| 일본어 | Yu Gothic Medium |
| 중국어(간체) | Microsoft YaHei |
| 중국어(번체) | Microsoft JhengHei |
| 아랍어·히브리어 | Arial |

그리고 **「72 는 모든 문자를 담고 있지 않다 · 일반적으로 라틴과 키릴을 담당한다」**고 적혀 있다.

→ **SAP 방식을 그대로 따라가면 한글은 맑은 고딕이 된다** = 지금 WS4.0 상태와 사실상 같다.

## 3. 72 를 쓸 수 있나 — 라이선스가 확실하지 않다

- SAP 내려받기 페이지: **「72 는 SAP 고유(proprietary) 글꼴」**이라고 하면서
  같은 페이지에서 **「내려받기는 Apache 2.0 으로 제공한다」**고 적었다. 두 문장이 서로 어긋난다.
- `72 Brand` 판은 **브랜딩·마케팅 전용**이라고 따로 못박혀 있다(제품 화면용이 아니다).
- **SAP 제품이 아닌 곳에서 써도 되는지**를 명확히 허용·금지한 문장은 **찾지 못했다**(미확인).
- 운영상 길은 하나 더 있다 — 이 앱은 **서버가 주는 UI5 주소**(미리보기용으로 이미 쓰고 있다)를
  알고 있어, 그 주소 아래 글꼴 파일을 `@font-face` 로 가리키면 **파일을 안 넣고도** 쓸 수 있다.
  단 **로그인 전 화면·서버 끊긴 상태에서는 안 나온다.**

→ **쓰려면 SAP 쪽 서면 확인이 필요하다.** 제가 정할 일이 아니다.

## 4. open source 추천 — 자세한 비교는 01 번 파일

| | **Pretendard** (추천) | **IBM Plex Sans KR** |
|---|---|---|
| 라이선스 | SIL Open Font License 1.1 — 상업 사용·수정·재배포 가능(글꼴만 따로 파는 것은 금지) | SIL Open Font License 1.1 (IBM, 2018) — 상업 사용 가능. 「Plex」 이름은 상표로 예약 |
| 한글 | ⭕ 있음 (Source Han Sans Korean 기반) | ⭕ 있음 |
| 영문 | **Inter 기반** — 화면용으로 만들어진 글꼴이라 작은 글자·숫자가 또렷하다 | IBM Plex Sans |
| 느낌 | 반듯하고 중립적. 국내 솔루션에서 가장 많이 쓰인다 | 더 기업용·공학적. 한글 자형이 조금 더 딱딱하다 |
| 굵기 | 9가지 + 가변 글꼴(variable) 지원 | 8가지 |
| 파일 | woff2 · 가변 woff2 · 쓰는 글자만 받는 판(dynamic subset) 있음 | OTF · TTF (woff2 는 공식 배포본에서 확인 필요 — 미확인) |
| 설치 | 파일을 프로젝트에 넣고 `@font-face` 한 번 | 같음 |

**왜 Pretendard 인가**
1. 이 앱은 **Electron 이라 인터넷 없이도 떠야 한다** → 파일을 프로젝트에 넣는 방식이어야 한다.
   둘 다 가능하지만 Pretendard 는 **woff2 와 가변 글꼴을 공식으로 배포**해 파일 수가 적다.
2. 화면에 **숫자·코드·영문 이름**(앱 ID·패키지 이름·T-CODE)이 아주 많다 → 영문 바탕이
   화면용으로 만들어진 Inter 인 쪽이 또렷하다.
3. 한글·영문이 **한 벌**이라 지금처럼 섞이지 않는다.

**넣을 때 손댈 곳은 한 곳뿐**
공통 테마 토큰의 글꼴 한 줄 + `@font-face` 선언 한 덩어리.
화면 CSS 는 전부 그 토큰을 쓰고 있으므로 **화면 파일은 하나도 안 고친다.**

## 5. 아직 확인 안 한 것 (미확인)

- IBM Plex Sans KR 의 **woff2 공식 배포 여부** — 검색 결과에 OTF/TTF 만 나왔다.
- 글꼴을 바꾸면 **글자 폭이 달라져** 좁은 칸·툴바에서 줄바꿈이 생기는지 — 넣어 보고 눈으로 확인해야 한다.
- Monaco(코드 편집기) 안쪽은 **고정폭 글꼴**을 따로 쓴다 → 이 작업 범위에 넣을지 정해야 한다.
