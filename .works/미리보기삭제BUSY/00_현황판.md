# 🐞 BR16 — 미리보기 우클릭 삭제 시 확인창 먹통(클릭 안 됨)

> 화면: WS20 **미리보기** / 원본(as-is) 1:1 수정
> 실제 수정 파일: `www/ws30/ws10_20/js/ws_html5_ws20_edit.js` (`_deleteUI`)
> 백업: `js/_ws_html5_ws20_edit.js.br16bak2`

## ★ 정정 — 첫 수정은 헛짚었음
- 처음엔 `uiDesignArea.js` / `callDesignContextMenu.js`를 고쳤으나, **WS20 미리보기의 실제 삭제 함수는 그게 아니라 `ws_html5_ws20_edit.js`의 `_deleteUI`**였다. 처음 고친 파일은 WS20에서 **안 불리는 죽은 코드**라 화면에 반영 0 → 그래서 재시작해도 그대로였다.
- 그 두 파일은 **원래대로 되돌렸고**, 진짜 함수만 고쳤다.

## 무엇을 고쳤나 (쉬운 말)
- 미리보기 UI를 우클릭 → **삭제**를 고르는 순간, 메뉴 처리기가 **메인 화면 전체를 클릭 못 하게 잠근다**.
- 그런데 삭제 함수가 확인창을 띄우기 **전에 그 잠금을 안 풀어서**, 확인창이 들어 있는 화면 영역 전체가 클릭을 못 받아 확인·취소가 안 눌리는 먹통이 됐다.
- **수정**: 확인창을 띄우기 **직전에 그 메인 잠금을 풀도록** 한 줄 넣었다(원본 UI5도 확인창 직전에 풀던 것 그대로 복원). 트리에서 삭제할 때는 이 잠금을 애초에 안 거쳐서 정상이었다 → 원인·차이 일치.

## 원인·수정 근거 (소스 확인)
- 잠금 켜는 곳: `design/js/callDesignContextMenu.js` 메뉴 선택 처리기 `parent.setBusy("X")` → 메인 셸 body를 클릭 불가로 잠금(그 아래 iframe 전체 상속).
- 실제 삭제: `js/ws_html5_ws20_edit.js` `_deleteUI` — 확인창(`fnConfirmBox`) 띄우기 전 메인 잠금 해제가 **누락**돼 있었음.
- 수정: `_deleteUI`의 확인창 직전에 `parent.setBusy("")` 한 줄 추가(원본 `uiDesignArea.js` 확인창 직전 처리 1:1). 트리 경로는 이 잠금을 안 거쳐 무해.
