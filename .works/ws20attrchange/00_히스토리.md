## BR42 — 속성 초기화(Reset) 후 되돌리기 한 번에 전부 복원 (2026-08-18 통과, 노션=수정완료)

속성 초기화(Reset)로 여러 값(글자·너비·아이콘 등)을 한꺼번에 지운 뒤 되돌리기(Undo)를 하면, 한 번에 안 돌아오고 값이 하나씩 순차 복원되던 문제. 원인=초기화 루프가 값 하나 바꿀 때마다 공통 변경 함수를 호출해 되돌리기 기록이 값마다 1건씩 쌓임. 수정=원본(uiAttributeArea.js:2168~2173 RESET_ATTR 1스텝)대로 첫 실제 변경 직전에 되돌리기 기록을 딱 1회만 남기고, 각 값 변경은 개별 기록을 막음(빈 초기화면 기록 안 남김). → 초기화 후 되돌리기 한 번에 전부 복원(WS3.0 동일).

검수 P1(코덱스·안티 동일)=원본 초기화 루프는 값 변경 직후 펼침목록(autoGrowing)·끌어놓기(dropAble)에 딸린 연동 이벤트 데이터까지 함께 지우는데 현행이 이 두 줄을 빠뜨림 → 원본(2222·2225) 1:1 복원. 두 예외처리 함수는 내부에서 되돌리기 기록을 안 쌓아 "되돌리기 한 번" 원칙 유지(되돌리기 한 번에 값+연동 이벤트 함께 복원).

- 반영: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js` `attrResetAttr`(되돌리기 1회 병합 + 개별 변경 skip + dropAble/autoGrowing 예외처리 복원)
- 원본 참조: `design/js/uiAttributeArea.js` `attrResetAttr`(2138·2168~2173·2222·2225)
- 검수 `.audit/br42/`(코덱스·안티 동일 P1 반영, 반론 0). node --check 통과.

## BR34 — 속성 값칸 오류 안내문구(원본 말풍선) + 실행 시 정리 (2026-08-18 통과)

속성 값칸에 잘못된 값 확정 시 원본 UI5의 오류 말풍선(valueStateMessage) 재현(빨간 테두리 + 값칸 아래 오류 안내문구 자동표시, 포커스/클릭 표시, 스크롤·창크기·딴곳클릭 시 숨김, 마우스올림=값 / 클릭=오류내용). 기본값 복구·지우기(X)는 원본 그대로. 값 변경 후 재렌더로 포커스 입력칸 제거 시 dirty change 동기 재발화→중첩 재귀로 방금 세운 오류가 초기화되던 것 → 진입부 동기 재진입 방지.

★진짜 원인(실측): 실행(액티브)·체크가 부르는 오류 점검 함수 두 개가 HTML5 런타임에 아예 없었음(원본은 UI5 미리보기 메인 안에서 정의, HTML5는 그 부분 미실행). 그래서 실행 시 점검을 통째로 건너뛰고(오류 지움도 그 안이라 미호출) 빨간 잔존 + 검증 없이 "액티브 성공". 체크 버튼은 그 함수를 가드 없이 불러 로딩표시 멈춤. → 두 점검 함수 + 그 안에서 부르는 오류구조 생성기까지 원본(WS_DESIGN design/js/main.js:1315·1371·175) 1:1 이식. CDP 실측 재검증: 오류 데이터 1→0, 화면 빨간 1→0. 부수효과: 실행이 이제 진짜 검증(잘못된 값·필수자식 누락 시 활성화 막고 오류목록).

- 반영: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js`(오류 말풍선 `_attrVsShow/_attrVsHide/_attrVsRefocus`, 진입부 재진입 방지, `chkExcepionAttr`·`chkExcepUiTable`·`crtErrorSyntaxStru` 이식), 값칸 `onEnter` 확정
- 원본 참조: `design/js/uiAttributeArea.js`(736·831·6345 등), `design/js/main.js`(1315·1371·175), `design/js/checkAppData/designTreeData.js`

## BR39 — UI Object ID 오류 표시 잔존 + 미리보기 식별자 동기화 (2026-08-14 통과, 노션=수정완료)

UI Object ID 입력칸에 잘못된 값(빨간 오류) 상태에서 다른 UI를 고르면 이전 빨간 표시가 안 지워지던 것 → 헤더 다시 그릴 때(`_renderAttrHeader`) 지금 선택된 UI의 오류 상태에 맞춰 빨간 표시를 켜고 끔(원본 UI5의 자동 연결을 명시 재현). 원본은 UI를 고를 때마다 정보를 새로 만들어 오류상태를 남기지 않으므로 "다른 UI로 가면 이전 오류는 폐기"가 원본 계약(복귀 시 재표시는 원본에 없음). 더불어 이름을 정상 변경할 때 내부값(`_OBJID`)만 바꾸고 미리보기 부품의 식별용 값(`.data("OBJID")`)은 옛 값으로 두던 결함 → 함께 갱신(미리보기 클릭→트리 선택 어긋남 해소). 검수 `.audit/br39/`(코덱스 통과, 안티 수정필요→문구정정으로 해소).

- 반영: `www/ws30/ws10_20/js/ws_html5_ws20_attr.js` (`_renderAttrHeader` 오류표시 동기화 / `attrChnageOBJID` 미리보기 식별자 갱신)
