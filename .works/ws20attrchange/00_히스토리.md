## BR52 — 오류 항목으로 데려갈 때 위 영역 접기·이동·커서 (2026-08-30 종결, 노션=수정완료)

원본은 특정 속성으로 화면을 데려갈 때 ①위쪽 영역(`UI Object ID`·`Description` 입력칸) 접기 ②그 줄 선택 표시 ③부드러운 스크롤 ④값칸에 커서 를 한다. HTML5 는 스크롤만 하고 있어 나머지를 이식했다.

**★선택 표시는 최종 철회(장군님 결정 2026-08-30).** 원본은 속성 목록이 "줄 클릭 선택이 켜진 표"라 그 기본 성질이 그대로 보인 것뿐이고, **선택 결과를 읽어 쓰는 곳이 원본 전체에 0곳**(전수 확인). 즉 화면상 쓰임새 없는 표시이며, 오류 인지는 값칸 빨간 테두리+안내 문구로 충분하다는 판단. → 넣었던 선택 표시를 코드·화면규칙에서 모두 걷어냄(BR53 것도 함께). 되돌리기 경로용 `bNoRowSelect` 옵션도 불필요해져 제거.

실화면 테스트 항목 0 — 남은 동작이 전부 고치기 전/후 구분 불가로 확인됐다:
- **위 영역 접힘** = 이 화면의 접힘은 스크롤로 위 영역이 밀려 사라지는 것과 같은 일. 데려갈 수 있는 속성(스타일클래스·이벤트·바인딩)이 전부 목록 아래쪽이라 스크롤만으로 같은 결과(장군님 지적, 소스 확인).
- **부드러운 스크롤** = 접기가 먼저 화면을 순간 이동시켜 이동량 0 → 애니메이션 비가시(원본도 같은 순서).
- **값칸 커서** = 데려가는 경로 3개(Find 창·오류 목록 창·"UI5 미리 정의된 CSS" 팝업)가 전부 별창이고 그 창이 앞에 남아 뒤쪽 커서가 안 보임(원본도 같은 구조).
- **정보(I)·경고(W) 표시** = 이 경로로 안 와 무증상. 코드만 원본 4종과 일치시킴.

- 원본 참조: `design/js/uiAttributeArea.js` setAttrFocus 8186~8360(선택 8279 / 접힘 8338 / 스크롤 8346 / 커서 8355), 표 정의 319행
- 검수 `.audit/br52/`(코덱스·안티 P2 3건 전부 반영 후, 선택 표시분은 위 결정으로 철회). node --check 통과. 백업 `_ws_html5_ws20_attr.js.br52selrmbak` 등.

★별건 보고(미반영): 원본은 속성 값 변경을 **되돌리면 그 속성 줄로 화면을 데려가는데**, HTML5 는 되돌리기 기록에 "어느 속성이 바뀌었는지"를 안 넘겨(호출 43곳 전부 인자 없음) 그 이동이 통째로 불발. 원본 대비 누락.

## BR53 — 등록 안 된 서버이벤트일 때 그 줄 선택 표시 (2026-08-30 통과, 노션=수정완료)

검수 취합(`.audit/br53/03_response.md`): 코덱스 P2 1건 + 안티 P2 2건 → 겹치는 것 합쳐 **2건 전부 반영, 반론 0**.

- **P2-2**(스크롤 멎기 대기의 상한이 프레임 횟수뿐이라 창을 최소화·가리면 영영 안 끝날 수 있음) = **실제 경과시간 상한(800ms) 병행**으로 반영. P2-1 반영 후엔 이 대기가 화면잠금을 쥐므로 위험도가 올라가 코덱스가 하향한 항목도 채택.

## BR42 — 속성 초기화(Reset) 후 되돌리기 한 번에 전부 복원 (2026-08-18 통과, 노션=수정완료)

속성 초기화(Reset)로 여러 값(글자·너비·아이콘 등)을 한꺼번에 지운 뒤 되돌리기(Undo)를 하면, 한 번에 안 돌아오고 값이 하나씩 순차 복원되던 문제. 원인=초기화 루프가 값 하나 바꿀 때마다 공통 변경 함수를 호출해 되돌리기 기록이 값마다 1건씩 쌓임. 수정=원본(uiAttributeArea.js:2168~2173 RESET_ATTR 1스텝)대로 첫 실제 변경 직전에 되돌리기 기록을 딱 1회만 남기고, 각 값 변경은 개별 기록을 막음(빈 초기화면 기록 안 남김). → 초기화 후 되돌리기 한 번에 전부 복원(WS3.0 동일).

## BR34 — 속성 값칸 오류 안내문구(원본 말풍선) + 실행 시 정리 (2026-08-18 통과)
