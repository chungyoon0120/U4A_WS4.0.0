# WS20 속성값 변경 — 현황판

## 지금 할 것 (미테스트)

### BR34 — 속성 값칸 오류 안내문구(원본 말풍선) + 실행 시 정리 (장군님 지시 2026-08-14)

> 준비: ①왼쪽 트리에서 **잘못된 값을 점검하는 값칸이 있는 UI**를 하나 고른다(예: 달력 계열 `CALENDAR1`).
> ②오른쪽 속성 영역에서 점검되는 값칸을 찾는다(예: `months` — 1~360 범위). 아래 "오류 값칸"은 이 칸.
> ★원본대로: 오류 나면 빨간 테두리 + **오류 안내문구가 값칸 아래에 뜬다**(마우스 올리면 나오는 설명이 아님). 값은 기본값(1)으로 되돌아간다. 지우기(X)는 그대로 보인다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR34-1 | 오류값 확정 시 안내문구 저절로 뜸 | ①점검되는 값칸(예 `months`)에 잘못된 값(예 `400`)을 입력한다. ②Enter를 누른다(또는 값칸 밖 빈 곳을 클릭). ③값이 **1로 되돌아가고** 빨간 테두리가 생기며, **클릭 안 해도** 값칸 바로 아래에 오류 안내문구가 **저절로** 뜨는지 확인. | ☐ |
| BR34-2 | 딴 곳 눌러 문구 닫은 뒤 그 칸 다시 클릭 | ①BR34-1 상태에서 화면 빈 곳을 한 번 클릭해 안내문구를 사라지게 한다. ②빨간 테두리가 있는 그 값칸을 한 번 클릭한다. ③값칸 아래에 안내문구가 다시 뜨는지 확인. | ☐ |
| BR34-3 | 스크롤/창크기 바꾼 뒤 같은 칸 다시 클릭 | ①안내문구가 뜬 상태에서 속성 목록을 마우스 휠로 스크롤한다(또는 창 크기를 바꾼다) → 문구가 사라지는지 본다. ②같은 빨간 값칸을 한 번 더 클릭한다. ③안내문구가 다시 뜨는지 확인. | ☐ |
| BR34-4 | 다른 UI 선택 시 옛 문구 안 남음 | ①안내문구가 뜬 상태에서 왼쪽 트리에서 **다른 UI**를 클릭한다. ②바뀐 화면에 이전 안내문구가 남아 둥둥 떠 있지 않은지 확인. | ☐ |
| BR34-5 | 마우스 올림=값 / 클릭=오류내용 | ①빨간 값칸에 마우스를 올려 잠시 기다렸을 때 나오는 설명이 그 칸의 **값**인지 본다. ②같은 칸을 클릭했을 때 뜨는 안내문구가 **오류 내용**(예: "1~360 사이 값을 입력…")인지 확인(둘이 서로 다름 = 원본대로). | ☐ |
| BR34-6 | ★실행(액티브) 후 오류 표시 사라짐 | ①BR34-1로 빨간 테두리·안내문구가 뜬 상태를 만든다(값은 1). ②상단 **실행** 버튼을 누른다(하단에 "액티브 성공"이 뜬다). ③실행 뒤 그 값칸의 **빨간 테두리·오류 안내문구가 사라졌는지** 확인(값 1은 정상이라 오류가 남으면 안 됨). | ☐ |

### BR39 — UI Object ID 오류 표시 잔존 + 미리보기 식별자 동기화 (검수: `.audit/br39/`)

> 화면: WS20 Design 화면, Attribute 영역 맨 위 **UI Object ID** 입력칸. 준비: Design Tree에 버튼 등 UI를 2개 이상 두고 시작(예: BUTTON16, BUTTON17). 표기: ☐ 미테스트 / ✅ O 통과 / ❌ X.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR39-1 | 잘못된 값의 빨간 오류 표시가 다른 UI 선택 시 사라짐 | ① Design Tree에서 UI 하나(예: BUTTON16)를 클릭 ② Attribute 영역 맨 위 UI Object ID 입력칸에 `123` 입력 후 Enter(또는 다른 곳 클릭) ③ 입력칸에 빨간 테두리 오류가 뜨는지 확인 ④ Design Tree에서 **다른 UI**(예: BUTTON17)를 클릭 ⑤ 새 UI의 UI Object ID 입력칸에 **빨간 테두리가 남아있지 않은지** 확인 | ☐ |
| BR39-2 | 다른 UI 갔다 돌아오면 저장된 정상 이름·오류 없음 | (BR39-1에 이어서) ① 다시 처음 UI(BUTTON16)를 Design Tree에서 클릭 ② UI Object ID 입력칸에 **원래 정상 이름(BUTTON16)** 이 그대로 보이고 빨간 테두리가 없는지 확인 (잘못 친 `123`은 저장 안 됨 = 원본 그대로) | ☐ |
| BR39-3 | 정상 이름 변경 시 미리보기 클릭→트리 선택이 새 이름으로 맞음 | ① Design Tree에서 UI 하나를 클릭 ② UI Object ID 입력칸에 허용되는 새 이름(예: `MYBTN`) 입력 후 Enter ③ Design Tree·미리보기에 새 이름이 반영되는지 확인 ④ 오른쪽 **미리보기 화면**에서 그 부품을 클릭 ⑤ Design Tree에서 **바뀐 새 이름(MYBTN)** 행이 선택 표시되는지 확인(옛 이름으로 어긋나지 않음) | ☐ |
| BR39-4 | 이름 변경 후 되돌리기(Undo)/다시하기(Redo) 정상 | (BR39-3에 이어서) ① 되돌리기 단축키(Ctrl+Z)로 이름 변경 취소 ② 미리보기 부품 클릭 시 Design Tree에서 **되돌린 옛 이름** 행이 선택되는지 확인 ③ 다시하기(Ctrl+Y)로 재적용 ④ 미리보기 부품 클릭 시 **새 이름** 행이 선택되는지 확인 | ☐ |

> ※ "다른 UI로 갔다가 오류 UI로 돌아오면 빨간 표시가 다시 뜬다"는 **원본에 없는 동작**이라 테스트 항목에서 제외(원본은 이동 시 이전 오류 폐기).
