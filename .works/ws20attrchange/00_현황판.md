# WS20 속성값 변경 — 현황판

## 지금 할 것 (미테스트)

### BR53 — 등록 안 된 서버이벤트일 때 그 줄 선택 표시 (2026-08-21 수정)

이벤트 값칸을 눌렀을 때 그 값이 서버에 등록돼 있지 않으면 **그 줄에 선택 표시**가 붙는다(원본 동작 이식).
곁들여 **선택 표시(왼쪽 파란 세로줄) 결함**을 고쳤다 — 종전엔 마우스를 올렸을 때만 파란 줄이 나타났다가 떼면 사라졌다. 이제 마우스와 상관없이 항상 보인다. (속성 줄 전체 공통 → 아래 BR52 에도 적용)

사전준비: 앱을 껐다 다시 켠다. **값이 서버에 등록돼 있지 않은 이벤트 줄**이 있는 앱을 편집 가능 상태로 연다(그 값칸을 펼쳤다 닫으면 테두리·글자가 빨갛게 남는 줄).

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR53-1 | 그 줄에 선택 표시가 붙고, 마우스를 치워도 남는다 | ① 왼쪽 'Design Tree'에서 **등록 안 된 이벤트 값을 가진 요소**를 클릭한다 ② 오른쪽 'Attribute' 목록을 내려 'Events' 묶음에서 그 이벤트 줄을 찾는다 ③ 그 줄의 값칸을 **한 번 클릭**한다 ④ 확인: 그 줄 **맨 왼쪽에 파란 세로줄**이 생기는지 ⑤ 마우스를 **그 줄 밖으로 완전히 치운다** ⑥ 확인: 파란 세로줄이 **그대로 남아 있는지**(사라지면 실패) | ☐ |

### BR52 — 오류 항목으로 이동 시 상단 접기 + 그 줄 선택 표시 (2026-08-21 수정)

수정 내용: 특정 속성으로 화면을 데려갈 때 원본처럼 ①`UI Object ID`·`Description` 입력칸이 있는 위쪽 영역이 접히고 ②그 속성 줄에 선택 표시(왼쪽 파란 세로줄 + 파란 배경 + 굵은 글자)가 붙는다. 선택 표시는 화면이 다시 그려져도 유지되고, 다른 UI를 고르면 사라진다.

**소스 확인 결과 — 테스트 범위를 이렇게 잡은 이유:**
- 속성으로 데려가는 처리가 실제로 도는 경로는 **Find 창 / 오류 목록 창 / "UI5 미리 정의된 CSS" 팝업 셋뿐이고 전부 별창**이다. 그중 재현이 확실한 **Find 창**으로 테스트한다(오류 목록 창은 서버 점검 설정에 걸리는 값이 있어야만 떠서 재현을 장담 못 함).
- **커서(포커스) 이동은 어느 경로로도 눈으로 확인할 수 없다** — 별창이 계속 앞에 떠 있어 뒤쪽 WS20 커서가 안 보인다(원본도 같은 구조). → 테스트 항목에서 제외.
- **되돌리기(↶)로는 이 동작이 아예 안 일어난다** — 되돌리기 기록을 남기는 호출 43곳이 전부 "어느 속성이 바뀌었는지"를 안 넘겨서, 되돌린 뒤 속성으로 데려가는 처리가 첫 줄에서 끝난다. → 테스트 경로로 쓸 수 없음(원본엔 있는 동작이라 **별건 누락**으로 보고).
- **★정정(2026-08-21)**: 종전엔 "값이 바뀐 줄은 '변경됨' 표시가 선택 표시를 덮으니 값을 지워서 확인하라"고 적었는데, **그게 아니라 선택 줄 그리는 방식이 잘못돼 있었다**(움푹한 표시와 같은 자리에 그려서, 마우스를 올렸을 때만 파란 줄이 나타났다 떼면 사라짐). BR53 에서 **줄을 따로 그리도록 고쳐 마우스와 상관없이 항상 보이게** 했다. → 값을 지울 필요 없이 **그대로 확인**한다.

사전준비: 앱을 껐다 다시 켠다(코드 반영은 재시작해야 적용). CALENDAR1 있는 앱을 편집 활성 상태로 연다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| BR52-1 | 속성으로 데려갈 때 위쪽 영역이 접힘 | ① 왼쪽 'Design Tree'에서 CALENDAR1 클릭 ② 오른쪽 'Attribute'에서 styleClass 값칸에 abc 입력 후 Enter ③ 오른쪽 'Attribute' 목록을 **맨 위까지 스크롤해 올려** `UI Object ID`·`Description` 입력칸이 보이는 상태로 만든다 ④ 화면 왼쪽 위 앱 이름 줄("YLCY_TEST2142 편집 비활성")에서 '비활성' 바로 오른쪽의 쌍안경 모양 버튼(마우스 올리면 "Find UI (Ctrl+F)")을 눌러 'Find' 창을 연다 ⑤ 뜬 'Find' 창을 **옆으로 끌어 옮겨** 뒤쪽 WS20의 오른쪽 'Attribute' 영역이 보이게 한다 ⑥ 'Find' 창 왼쪽 메뉴에서 'CSS Style Class Where to Use'를 클릭 ⑦ 오른쪽 표에서 CALENDAR1 줄의 UI 오브젝트 ID 링크(파란 글씨)를 클릭 ⑧ 뒤쪽 WS20 'Attribute'에서 확인: `UI Object ID`·`Description` 입력칸 영역이 **접혀 사라지고** 화면이 styleClass 줄 위치로 이동했는지 | ☐ |
| BR52-2 | 그 줄에 선택 표시가 붙고, 마우스를 치워도 남는다 | ① BR52-1 직후, 뒤쪽 WS20 'Attribute'의 styleClass 줄을 본다 ② 확인: 그 줄 **맨 왼쪽에 파란 세로줄**이 있는지 ③ 마우스를 **그 줄 밖으로 완전히 치운다**(WS20 창을 앞으로 가져와도 됨) ④ 확인: 파란 세로줄이 **그대로 남아 있는지**(사라지면 실패) ※ 값이 바뀐 줄이라 "변경됨" 움푹한 표시가 같이 보이는 것은 정상 | ☐ |
| BR52-3 | 다른 UI 고르면 선택 표시가 사라짐 | ① BR52-2 상태(styleClass 줄에 파란 세로줄)에서 왼쪽 'Design Tree'의 다른 요소(예: BUTTON1) 클릭 ② 오른쪽 'Attribute'가 그 요소 속성으로 바뀌고, 파란 세로줄이 남아 있지 않은지 확인 | ☐ |
