# 로그 설계 표준 — 일반 시스템 기법을 이 앱에 맞춘 것

> 작성 2026-09-08. **장군님 최종 목표**: 원본과 다르더라도, **일반적인 시스템에서 쓰는 로그 기법**을
> 충분히 참고해 **오류 수집 흐름을 탄탄하게** 만든다. 그래야 **나중에 고객이 쓰다 문제가 나도
> 로그만 보고 원인을 유추해 고칠 수 있다.** 이것이 이 작업의 최종 목표다.
>
> 근거 자료(2026-09-08 조회): 아래 「참고한 자료」 절.

---

## 0. 이 표준이 지키는 다섯 가지 (일반 기법에서 가져온 것)

| 코드 | 일반 기법 | 이 앱에 어떻게 적용하나 |
|---|---|---|
| **S1** | **줄 하나를 정해진 모양으로 남긴다**(기계도 읽을 수 있게) | 항목 이름을 고정하고 순서를 지킨다. 사람이 읽는 글이되 **자리마다 뜻이 정해져 있게** |
| **S2** | **등급을 정해 놓고 일관되게 쓴다** | 알림 / 주의 / 오류 / 치명 — 네 단계만. 운영에서는 알림 이상만 남긴다 |
| **S3** | **한 작업에 추적 ID를 붙여 끝까지 따라간다** | 버튼 하나 누른 것부터 서버 다녀오고 화면 넘어가 오류 나기까지 **같은 표**를 붙인다 |
| **S4** | **오류는 짧은 문구만 남기지 말고 난 자리 전체를 남긴다** | 첫 줄만 남기면 못 고친다. 부른 쪽까지 통째로 |
| **S5** | **누구·무엇에 대한 일인지 식별자를 항상 붙인다** | 창 / 화면 / 대상 이름 / 앱 버전·빌드. 단 **개인정보는 빼고** |

---

## 1. 줄 하나의 정해진 모양

```
[시각] [등급] [창] [화면] [추적ID] 무슨 일 | 대상 | 결과 | 걸린 시간
```

| 자리 | 무엇 | 예 |
|---|---|---|
| 시각 | 연월일 시분초, 1000분의 1초까지 | `2026-09-08 14:21:03.412` |
| 등급 | 네 단계 중 하나 | `알림` `주의` `오류` `치명` |
| 창 | 어느 창인지(창마다 다른 이름) | `메인` `바인딩 팝업` |
| 화면 | 그 창 안에서 지금 화면 | `화면 편집` |
| 추적ID | 그 작업을 시작할 때 만드는 짧은 값 | `A7F3` |
| 무슨 일 | 한 일 | `눌렀음` `보냈음` `열림` `실패` |
| 대상 | 무엇에 대고 | `저장` `트리 항목: 버튼1` |
| 결과 | 어떻게 됐는지 | `성공` `실패: 서버가 거절` |
| 걸린 시간 | 오래 걸리는 일만 | `0.8초` |

- **항목 이름과 순서를 절대 바꾸지 않는다.** 바뀌면 모아서 비교할 수 없다.
- 사람이 그냥 읽어도 뜻이 통해야 한다.

---

## 2. 등급 네 단계

| 등급 | 언제 | 운영에서 남기나 |
|---|---|---|
| **알림** | 정상 흐름의 주요 지점 — 앱 시작, 접속, 화면 열림, 저장 시작·끝 | **남긴다** |
| **주의** | 정상은 아닌데 계속 진행 가능 — 값이 없어 기본값으로 감, 다시 시도해 성공 | **남긴다** |
| **오류** | 기능이 실패 — 저장 실패, 서버가 거절, 화면 코드가 터짐 | **남긴다** |
| **치명** | 앱을 더 못 씀 — 앱 본체가 터짐, 창이 죽음 | **남긴다** |

- **속을 들여다보는 잔 기록은 등급을 두지 않고 아예 안 남긴다.** 필요하면 그때만 켠다.
- 운영에서 기본은 **알림 이상 전부**. 테스트 기간에는 더 촘촘히 남겨도 된다.

## 3. 추적 ID — 이 표준의 핵심

> 일반 시스템에서 요청 하나에 표를 붙여 끝까지 따라가는 방식과 같은 것이다.
> 이 앱은 **창이 여럿이고 작업이 중간에 끊겼다 이어진다.** 그래서 이게 없으면 못 따라간다.

| 규칙 | 내용 |
|---|---|
| **T1** | **사용자가 뭔가 시작할 때 표를 하나 만든다** — 버튼을 누른 그 순간 |
| **T2** | 그 작업이 하는 모든 일에 **같은 표를 붙인다** — 서버에 보내고 받는 것, 화면 넘어가는 것, 팝업 여는 것 |
| **T3** | **창을 넘어가도 표를 그대로 들고 간다** — 다른 창에 신호를 보낼 때 표도 같이 넘긴다 |
| **T4** | **오류가 나면 그 표를 오류 줄에도 적는다** |
| **T5** | 작업이 끝나면 **끝났다는 줄**을 남긴다. 끝 줄이 없으면 **중간에 멈춘 것** |

**이게 있으면 이렇게 읽힌다**

```
14:21:01.100 [알림] [메인] [화면목록] [A7F3] 눌렀음 | 편집 | 화면 이동 시작
14:21:01.180 [알림] [메인] [화면목록] [A7F3] 보냈음 | 화면정보 조회 | 서버로
14:21:01.910 [오류] [메인] [화면목록] [A7F3] 받았음 | 화면정보 조회 | 실패: 항목 없음 | 0.7초
14:21:01.930 [오류] [메인] [화면 편집] [A7F3] 터짐 | 없는 값을 꺼내 씀: 화면정보
```

→ **표 하나로 "편집 눌렀다 → 서버가 빈 것을 줬다 → 그래서 터졌다"가 한 줄기로 읽힌다.**
표가 없으면 이 네 줄이 서로 남남이 된다.

---

## 4. 오류를 남길 때

| 코드 | 규칙 |
|---|---|
| **E1** | **난 자리 전체를 남긴다.** 부른 쪽까지. 첫 줄만 남기면 진짜 범인을 못 찾는다 |
| **E2** | **없어진 값의 이름을 그대로** 적는다 |
| **E3** | 우리가 일부러 터뜨린 오류는 **어느 자리에서 무엇이 없었는지**를 문구에 넣는다 |
| **E4** | 서버가 거절하면 **서버가 준 사유를 그대로** 남긴다 |
| **E5** | 같은 오류가 반복되면 **묶어서 횟수만** 센다 |
| **E6** | 오류 줄에는 **그때 상태**를 같이 — 로딩 표시 켜짐 여부, 떠 있던 창, 골라져 있던 것 |

---

## 5. 파일 앞머리에 한 번 남기는 것

앱을 켤 때 **한 번만** 남긴다. 매 줄에 넣으면 파일만 커진다.

| 무엇 | 왜 |
|---|---|
| 앱 버전 **+ 빌드 구분(빌드 시각 또는 소스 판 번호)** | 같은 버전 번호로 여러 번 빌드하므로, **그 시점 소스를 정확히 열기 위해** |
| 윈도우 종류·버전, 32/64비트, 메모리, 화면 크기·배율·개수 | 특정 환경에서만 나는 오류를 가리기 위해 |
| 접속한 서버, 접속 방식 | 서버마다 다른 오류를 가리기 위해 |
| 화면 언어, 테마 | 언어·테마 때문에 나는 오류가 있다 |
| 포장 안 경로가 저장소의 어디에 해당하는지 한 줄 | AI가 파일을 바로 열 수 있게 |

---

## 6. 남기지 않을 것

| 안 남길 것 | 비고 |
|---|---|
| 비밀번호, 접속 열쇠, 인증 표 | 새어 나가면 그 자체로 사고 |
| 사람 이름·연락처·신원 정보, 윈도우 로그인 계정 | 개인정보 |
| 앱 로그인 아이디 | 2026-09-08 확정 |
| 사용자가 입력칸에 친 값 | 2026-09-08 확정. **칸 이름만** |
| 화면 그림, 파일 내용, 서버가 준 자료 통째 | 파일이 터진다. **모양과 개수만** |

## 7. 파일 관리

| 항목 | 정한 값 |
|---|---|
| 위치 | 지금 쓰는 기록 폴더(앱 사용자 데이터 폴더 아래) |
| 나누기 | 날짜별 한 개 |
| 한 개 크기 상한 | **없음**(2026-09-08 확정) |
| 오래된 것 지우기 | **이미 있음** — 앱 켤 때 3개월 지난 것 삭제. 손대지 않는다 |
| 크래시 리포트 | 같은 폴더에 다른 이름으로. 다음 실행 때 옮겨 담는다 |
| 잘림·유실 | 그런 일이 있으면 **그 사실을 한 줄로** 남긴다 |

## 8. 이 표준이 지켜졌는지 보는 법

| 코드 | 확인 방법 | 통과 기준 |
|---|---|---|
| **V1** | 아무 기능이나 한 번 써 보고 기록 파일을 연다 | 무슨 일이 있었는지 **순서대로 읽힌다** |
| **V2** | 일부러 오류를 낸 뒤 그 기록을 AI에게 준다 | **"어떻게 접속해서 어디 들어가 뭘 눌렀고 무엇을 하다 났는지"** 를 말한다 |
| **V3** | 추적 ID 하나로 걸러 본다 | 그 작업의 **시작부터 오류까지가 한 줄기**로 나온다 |
| **V4** | 오류 줄만 떼어 본다 | 파일과 줄 번호로 **그 자리를 바로 열 수 있다** |
| **V5** | 개인정보로 걸러 본다 | 비밀번호·아이디·입력값이 **한 건도 없다** |

## 8-1. 새 도구를 써도 되는가 — **된다**(장군님 지시 2026-09-08)

> "로그를 남기는 데 필요하면 새 도구를 들여도 된다. **다만 최종 목표는 로그를 남기고 보내는 것.**"

### 판단 기준

| 코드 | 기준 |
|---|---|
| **N1** | **지금 쓰는 기록 라이브러리로 되는 일이면 새로 들이지 않는다.** 파일에 쌓기·날짜별 나누기·등급은 이미 된다 |
| **N2** | 새로 들이는 것은 **지금 것으로 안 되는 일**일 때만 — 그때도 **하나만**, 쓰임을 문서에 적는다 |
| **N3** | 들이기 전에 **장군님께 무엇을 왜 들이는지 먼저 보고**한다(설치는 지시 뒤에) |
| **N4** | **앱 크기·시작 속도에 눈에 띄는 부담을 주면 안 된다** |

### 지금 것으로 되는 일 / 안 되는 일 (판단)

| 필요한 것 | 지금 것으로 되나 | 새 도구 필요 |
|---|---|---|
| 파일에 쌓기, 날짜별 나누기, 등급 | **된다** | 불필요 |
| 줄 모양 정해서 남기기 | **된다**(우리가 문자열을 만들면 됨) | 불필요 |
| 추적 ID 붙이기 | **된다**(우리가 값을 넘기면 됨) | 불필요 |
| 오래된 파일 지우기 | **이미 있다** | 불필요 |
| **텔레그램으로 파일 붙여 보내기** | 앱이 올라탄 바탕에 보내는 기능이 **이미 들어 있다**(따로 안 들여도 될 가능성 큼 — **착수 때 확인**) | **아마 불필요.** 필요하면 그때 보고 |
| **죽는 순간 잡기** | 앱이 올라탄 바탕에 **기본으로 들어 있다** | 불필요 |
| 크래시 리포트 파일 다루기(옮기기·이름 바꾸기) | **된다** | 불필요 |

**지금 판단: 새로 들일 것이 없어 보인다.** 착수하다 막히면 그때 무엇이 왜 필요한지 보고드린다.

### 그래도 잊지 말 것

- **도구가 목표가 아니다.** 목표는 **① 원인을 짚을 수 있는 기록을 남기고 ② 그것을 보내는 것.**
- 도구를 늘리면 **끄기 어려워진다.** 텔레그램 보내는 부분은 테스트가 끝나면 통째로 막아야 하므로,
  **되도록 우리 코드로 얇게** 만든다.
