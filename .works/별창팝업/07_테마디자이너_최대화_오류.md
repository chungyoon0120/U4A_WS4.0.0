## 1. 원인 — 확정

`ResizeObserver` 콜백 **안에서 크기를 읽고, 그 자리에서 레이아웃을 바꾼다.**
브라우저는 콜백을 다 돌린 뒤 크기를 다시 모으고, 또 변했으면 다시 돌린다 →
정해진 횟수를 넘으면 `loop limit exceeded`. **layout thrashing 이다.**

`Popups/monacoThemeDesign/Popup/js/wizardNav.js`

| 자리 | 콜백이 읽는 것 | 같은 콜백 안에서 바꾸는 것 |
|---|---|---|
| 가로줄 접기 (설치 57줄 / 본문 126줄) | `clientWidth` · `scrollWidth` | `is-collapsed` class 토글 → 접은 줄 `innerHTML` 통째 재생성 → **넘칠 때까지 `while` 로 다시 그림(최대 2N 번)** → 음수 `marginLeft` |
| 아래 여백 (설치 361줄 / 본문 342줄) | `clientHeight` · `offsetHeight` | `style.height` 설정 |

창 최대화는 폭·높이가 한꺼번에 크게 변해 이 되돌이가 길어진다.

## 3. 고침

콜백 본문을 `requestAnimationFrame` 으로 다음 프레임에 1회 coalescing + 재진입 가드.
`ResizeObserver` 가 콜백을 돌리는 그 라운드 안에서 레이아웃을 건드리지 않게 된다 →
브라우저가 다시 모을 변경이 없어 **되돌이가 성립하지 않는다.**

| 근거 |
|---|
| `.analy/16 §3.4.2` — `ResizeObserver` 를 계속 붙여둬야 하면 `rAF` 로 미룬다 |
| 공통 `attachOverflow` 의 `_scheduleReflow` 가 같은 방식 |

★`onError` 에서 삼키는 가드는 넣지 않았다(2026-07-10 장군님 금지).
