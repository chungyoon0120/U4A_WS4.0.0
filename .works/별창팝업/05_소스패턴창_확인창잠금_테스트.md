## ✅ 테스트 결과 — PL1~PL5 전부 통과 (2026-10-12 장군님)

앱을 껐다 켜고(dev mode) **「옵션」 창을 하나 먼저 열어 둔다**(WS10/WS20 메뉴 시스템 > 옵션).
그 다음 **WS10/WS20 메뉴 유틸리티 > 소스 패턴** 을 연다.

| 코드 | 동작 | 조작·확인 포인트 | O/X(☐) |
|---|---|---|---|
| PL1 | 목록에서 삭제 — 확인창 동안 잠금 | ① 소스 패턴 창 왼쪽 커스텀 패턴 목록에서 줄 하나를 우클릭한다 ② 삭제를 누른다 ③ 「정말 삭제하시겠습니까」 창이 뜬 동안 **옵션 창과 WS20 화면이 로딩 표시로 잠겨 조작이 안 된다** ④ NO 를 누른다 ⑤ 옵션 창과 WS20 화면의 잠금이 풀린다 | **✅ O** (2026-10-12) |
| PL2 | 목록에서 삭제 — 확인까지 | ① 같은 자리에서 삭제를 누른다 ② 「정말 삭제하시겠습니까」에서 YES 를 누른다 ③ 패턴이 지워지고 「삭제되었습니다」 알림이 뜬다 ④ 옵션 창과 WS20 화면 잠금이 풀린다 | **✅ O** (2026-10-12) |
| PL3 | 수정 창 안에서 삭제 — 확인창 동안 잠금 | ① 커스텀 패턴 줄을 우클릭해 수정(변경)을 누른다 ② 뜬 창에서 삭제를 누른다 ③ 「정말 삭제하시겠습니까」 창이 뜬 동안 **옵션 창과 WS20 화면이 잠겨 조작이 안 된다** ④ NO 를 누른다 ⑤ 잠금이 풀리고 수정 창은 그대로 남아 있다 | **✅ O** (2026-10-12) |
| PL4 | 수정 창 안에서 삭제 — 확인까지 | ① 같은 자리에서 삭제 → YES ② 수정 창이 닫히고 패턴이 지워진다 ③ 옵션 창과 WS20 화면 잠금이 풀린다 | **✅ O** (2026-10-12) |
| PL5 | 확인창 동안 이 창 자신 | ① PL1 의 ③ 상태에서 소스 패턴 창 자신에는 **로딩 덮개가 없다**(확인창만 보인다) | **✅ O** (2026-10-12) |

**표시**: ☐ 미테스트 · ✅ O 통과 · ❌ X 실패

| 확인창 열린 채 이 창이 닫힐 때 잠금 풀기 | `Popups/patternPopup/frame.js` 창 닫기 길목 |

## 원본에서 확인한 순서 (근거)

원본 커스텀 패턴 삭제는 이 순서다. 그대로 옮겼다.

| 순서 | 원본 처리 |
|---|---|
| 1 | 삭제 누르는 즉시 **자기 창 로딩 ON** (형제 별창도 같이 잠김) |
| 2 | 확인창을 띄운 **직후 자기 창 로딩만 OFF** — 형제 별창은 잠긴 채 둔다 |
| 3 | NO 면 **자기·형제 둘 다 OFF** |
| 4 | YES 면 **자기·형제 다시 ON** → 지우고 파일 쓰기 → **끝난 뒤에만 OFF** |

## 같이 본 것 — 코드는 안 고침 (보고만)

**원본에는 삭제 확인창이 한 곳뿐이다** — 목록 우클릭 삭제. **수정 창 안의 삭제 버튼은 원본에 없다**
(원본 수정 창에는 닫기 버튼만 있다). HTML5 에 새로 생긴 것으로 보이는데, 지시가 없어 **버튼을
없애지 않았고** 잠금 처리만 목록 삭제와 같은 짝으로 넣었다. 어떻게 할지는 장군님 지시 대기.
