# UI 개인화 팝업 — 느림·크래시 (2026-10-13)

## 크래시 원인 — 확정: WS4.0 공통 커스텀 tooltip

WS3.0(UI5)에는 없고 **WS4.0 에만 있는 공통 기능**이 범인이다.
공통 UI 유틸(`u4a-ui.js`)이 문서 전역 `mouseover` 를 받아, 공통 표의 칸에 마우스가 닿으면:

| 번호 | 그 순간 하는 일 | 이 줄에서는 |
|---|---|---|
| 1 | 칸의 `title` 을 `data-tip` + `aria-label` 로 **복사**하고 `title` 제거 | 866,250 글자 × 2벌 |
| 2 | `title` 이 없으면 **칸의 글자(`textContent`)를 통째로 읽어** `data-tip` 으로 넣음 | 866,250 글자 |
| 3 | 350ms 뒤 그 글자를 **tooltip 요소에 넣고 폭·높이를 잰다** | 아래 참조 |

tooltip 상자는 **`max-width: 24rem` + 줄바꿈 허용(`white-space: normal`·`overflow-wrap: anywhere`)** 이다.
→ 866,250 글자를 폭 384px 안에서 **전부 줄바꿈 계산**해야 한다(수만 줄·높이 수십만 px). 여기서 renderer 가 죽는다.

**원본(UI5)은 native `title` 그대로 둔다** — OS tooltip 은 앞부분만 보여주므로 글자가 아무리 길어도 비용이 없다.

### 실측 4건이 전부 이 설명과 맞는다

| 번호 | 조작 | 결과 | 왜 |
|---|---|---|---|
| 4 | 코드로 줄 클릭(hover 없음) | 안 죽음 | `mouseover` 가 안 뜬다 |
| 5 | 마우스 hover | **0.55초 뒤 사망** | 350ms 지연 + 측정 |
| 6 | `title` 만 비우고 hover | 사망 | 위 2번이 칸 글자로 `data-tip` 을 만든다 |
| 7 | 칸 글자 + `title` 둘 다 비우고 hover | 살아남음(heap 43MB) | 넣을 글자가 없어 tooltip 을 안 만든다 |

메모리 고갈이 아니다 — 죽기 직전 heap 43MB(한도 3,586MB) · JS 오류 0건.

### 고칠 곳 (지시 대기)

공통 tooltip 에 **글자 수 상한**을 둔다(넘으면 앞부분만). 공통 자산(`u4a-ui.js`)이라 지시 받고 고친다.
※ 이 결함은 UI 개인화 팝업만이 아니라 **공통 표를 쓰는 모든 화면**에 해당한다.
