> **전부 훑었고 전부 반영했습니다.** 아래가 그 근거입니다.

## ✅ 구멍 2개도 고쳤습니다 (2026-10-09 장군님 지시 「메인이 없는데 자식이 있을수는 없다」)

| | 무엇이었나 | 어떻게 고쳤나 |
|---|---|---|
| **①** | 별창이 **「처리 중」이면 로그오프해도 안 닫혔다** | 메인 창이 죽는 자리에서만 **차단을 안 타고 없앤다.** 뒤로가기·모드 전환은 종전 그대로 |
| **②** | **메인 창이 비정상으로 죽으면**(화면이 터짐 · 강제 종료) **별창이 남았다** | **앱 바깥쪽(앱을 띄우는 파일)에 그물을 한 겹** 쳤다. 메인 창이 사라지면 같은 브라우저키 별창을 없앤다 — **누가 만들었든 어떤 경우든 걸린다** |

**②를 거기에 둔 까닭** — 메인 창은 서버 목록 창에서도, 「새 창」으로도 열린다. 어느 쪽이 열었든
**창이 만들어지는 길목 한 곳**에서 보면 전부 걸린다. 화면 코드가 아예 안 도는 경우도 여기서만 잡힌다.
다른 메인 창은 건드리지 않고(브라우저키가 창마다 다르다), 메인 창이 아니면 아무 일도 하지 않는다.

## 2. ★모든 길이 네 곳으로 모인다 — 네 곳 다 고쳤다

| | 어디로 모이나 | 그리로 가는 길 | 조치 |
|---|---|---|---|
| ① | **로그오프 처리** | 타이틀바 전원 아이콘 · 메뉴 로그오프 · **창을 닫을 때 같은 세션 창이 나뿐이면 여기로 온다** | ✅ 예외 없이 전부 닫기 |
| ② | **창 닫기 마무리 처리** | 메인 창 X · 메뉴 「창 닫기」(WS10·WS20) · 단축키 · 다른 창이 보낸 종료 요청 · 서버 목록 창의 전체 종료 | ✅ 예외 없이 전부 닫기 |
| ③ | **세션 종료 처리** | 세션 타임아웃 확인창 OK · 서버가 세션을 끊었을 때 · 강제 로그오프 · 로그인 화면 복귀 | ✅ 예외 없이 전부 닫기 |
| ④ | **「전부 닫기」 함수** | 같은 로그인의 다른 창들이 전부 로그오프됐을 때 | ✅ ②③ 과 같은 기준으로 맞춤 |

**①②③ 은 서로 겹친다** — 창 X 로 닫으면 ② 로 가다가 ① 로 넘어가기도 한다. 어느 쪽으로 가도 닫히게 **셋 다** 넣었다.

## 5. 확인했지만 손댈 것이 없던 것

- **서버 왕복이 실패해도** 전부 닫기는 돈다 — 그 통신 함수는 실패 여부와 무관하게 **0.5초 뒤 반드시** 뒷처리를 부른다(소스 확인).
- **치명적 오류로 앱이 끝날 때**는 프로세스가 통째로 죽어 **OS 가 모든 창을 닫는다.**
- **시작 화면·서버 목록 창**을 닫는 코드는 메인 창이 아니다.

## 6. 아직 못 한 것

- **앱이 그냥 죽는 경우**(크래시)는 코드로 막을 수 없다 — OS 가 프로세스를 정리한다.
- 실제 화면 확인은 **장군님 테스트**(LO1~LO4)로만 가능하다. 제가 앱을 못 띄운다.

## 7. ★구멍 ① — 별창이 「처리 중」이면 안 닫힌다

**사실(소스 확인)**: 별창 여러 개가 **「처리 중일 때는 창을 닫지 못하게」** 스스로 막고 있다
(UI 찾기 · 대형 바인딩 · 기술 문서 · 소스 편집기 · 오류 페이지 에디터 등).
제가 쓰는 공통 닫기는 **일반적인 닫기 요청**이라 **그 차단에 걸린다.**

**그래서 생기는 일**
- 별창 안에서 서버 조회가 도는 중에 **세션 타임아웃**이 터지면 → 메인 창은 죽고 **그 별창만 화면에 남는다.**
- 로그오프를 눌렀을 때도 마찬가지다(메인 창이 한가해도 별창은 따로 바쁠 수 있다).

**고치는 법** — 메인 창이 죽는 자리에서만 **차단을 안 타는 방식으로 없앤다.**
앱이 끝나는 자리라 정리 코드를 못 돌려도 문제가 없다. **뒤로가기·모드 전환은 지금 방식 그대로 둔다.**

## 8. ★구멍 ② — 메인 창이 비정상으로 죽으면 별창이 남는다

지금 고친 것은 전부 **앱 안(화면 코드)** 에서 도는 처리다. 그래서 **그 코드가 아예 안 도는 경우**는 못 막는다:
화면이 터져 죽을 때 · 작업 관리자로 강제 종료할 때 · 전원이 꺼질 때.

종전에는 parent 가 있어 **OS 가 같이 닫아** 줬다. parent 를 빼면 그 그물이 사라진다.

**고치는 법** — **앱 바깥쪽(메인 프로세스)** 에서 메인 창이 없어지는 것을 보고 같은 브라우저키 별창을 없앤다.
화면 코드가 안 돌아도 걸리므로 **어떤 경우에도 남지 않는다.** 이게 가장 튼튼한 그물이다.
※ 이건 화면 코드가 아니라 **앱을 띄우는 쪽 파일**을 고치는 일이라 따로 지시를 받아야 합니다.
