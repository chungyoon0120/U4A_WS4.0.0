## 1. 지금 무슨 일이 일어나나

| 끝내는 방법 | 별창을 닫는가 |
|---|---|
| **로그오프** (타이틀바 전원 아이콘 · 메뉴 시스템 > 로그오프) | **안 닫는다** — 아래 2절 |
| **창을 X 로 닫기** | **안 닫는다** — 같은 자리를 지난다 |
| 뒤로가기(←, F3) | 닫는다 (브라우저키 기준 일괄 닫기 · 예외 3개 제외) |

**parent 가 있을 때는 문제가 안 보였다** — 메인 창을 닫으면 **OS 가 자식 창을 같이 닫아** 줬기 때문이다.
**parent 를 뺀 창은 OS 가 안 닫는다.**

→ 지금 영향받는 창 = **1번 옵션** · **7번 UI 찾기** (parent 를 뺀 2곳).
  앞으로 8~26번을 고칠 때마다 **그대로 늘어난다.**

## 2. 소스 근거 — 로그오프가 실제로 하는 일

로그오프 확인창에서 「예」를 누르면 순서대로:

1. **아이콘 미리보기 · 일러스트 메시지 미리보기 2종만** 닫는 함수를 부른다 (`ws_fn_04.js` 의 `closeAllCurrWinDependentPopups`).
   그 안에 닫을 창 이름이 **2개만** 박혀 있다. 다른 별창은 대상이 아니다.
2. 다른 **메인 창**(같은 세션키·다른 브라우저키)을 정리하는 IPC 를 보낸다 — **별창과 무관**하다.
3. 서버에 로그오프를 보내고 **메인 창을 닫는다**(`top.window.close()`).

**→ 어디에도 「내 별창을 닫아라」가 없다.**

창을 X 로 닫을 때도 3번과 같은 자리를 지난다(`ws_main.js` 의 `fnBeforeunload`) — **같은 문제.**

## 3. 이미 쓸 수 있는 것

뒤로가기 때 쓰는 **브라우저키 기준 일괄 닫기**(`ws_fn_02.js` 의 `fnChildWindowClose`)가 있다.
2026-10-07 에 parent 기반에서 브라우저키 비교로 이미 바꿔 뒀다.

**다만 그대로는 못 쓴다** — 그 함수에는 **안 닫는 예외 3개**가 들어 있다
(화면 녹화 · 소스 패턴 · 예제 열기, + 2026-10-07 에 추가한 옵션 · 아이콘 목록).
뒤로가기는 앱이 계속 도니까 남기는 게 맞지만, **로그오프는 앱이 끝나는 자리라 전부 닫아야** 한다.

→ **예외를 건너뛰고 전부 닫는 길**이 필요하다(지금 함수에 그 선택지가 없다).

## 4. 아직 확인 안 한 것 (미확인)

- **세션 타임아웃**으로 끝날 때도 같은 문제인지 — 안 봤다.
- **critical error 오류창**에서 로그오프할 때 같은 자리를 지나는지 — 안 봤다.
- 1번 옵션 창은 **로그오프 테스트를 안 하고 통과**시켰다(테스트 4가지에 로그오프가 없었다).
  → 고친 뒤 **1번도 다시 테스트**해야 한다.
