**console.error 와 이번에 넣으라는 한 줄의 차이 (소스 확인):**

| | 이미 있는 `console.error` | 넣으라는 `U4ALOG.caught(e)` |
|---|---|---|
| 테스터가 받는 위치 | **catch 가 있는 줄** — 테스터가 콘솔 줄마다 호출 위치 2개를 기록한다([cdp-client.js:416-426](D:/workspace/u4a-ws-cdp-tester/lib/cdp-client.js:416)) | **오류가 실제로 터진 줄** — `e.stack` 에서 뽑는다([ws_html5_logger.js:277](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_html5_logger.js:277)) |
| 차이가 나는 경우 | catch 가 다른 함수를 부르고 그 **안에서** 터졌을 때 — console.error 는 catch 자리만 알려 준다 | 안쪽 함수의 파일·줄까지 나온다 |

- **지침서가 고치자고 한 이유**([지침서 §1](D:/workspace/ws4-auto-fix-daemon/.docs/handoff/ws40-work-order.md)): ① 테스터는 판단 능력이 없고, WS4.0 이 콘솔에 찍은 것과 CDP 가 주는 것만 가진다 ② 오류 분석 문서 2개가 똑같이 「앱 속성 dump 와 UI5 stack trace 가 없어서」 확신도 medium 에서 멈췄다 ③ Chrome 은 콘솔 메시지에 stack 을 안 실어 준다(실제 사고의 raw event 에 `type·args·executionContextId·timestamp` 4개뿐) ④ 그래서 `U4ALOG.caught` 를 안 부르는 catch 는 밖에서 영원히 안 보인다.
- **지침서에 없는 것**: 이미 `console.error` 를 찍는 catch 를 따로 따져 본 내용은 **없다.** 「`U4ALOG.caught` 가 없으면 대상」 한 가지 기준으로만 셌다.
- 확인한 raw event([incident_20260918_071802 raw.json](D:/workspace/ws4-auto-fix-daemon/test/_log_samples/logs/test/incident_20260918_071802_console_error_from_the_app/raw.json))는 electron-log 모양의 글자 한 줄이고 위치가 없다 — 지침서 ③ 과 맞다. 다만 이것이 앱 코드가 직접 부른 `console.error` 인지, 로그 파일 기록이 콘솔로 되돌아온 것인지는 **미확인**.
- 지침서는 「콘솔 줄에는 위치가 안 실려 온다」고 했지만, 테스터 소스에는 콘솔 줄의 호출 위치를 담는 코드가 있다(2026-09-28 실측이라는 주석). **둘 중 어느 쪽이 맞는지는 미확인**이다.
- 내 생각: **이미 `console.error` 로 남기는 570곳은 고치지 않는다.** 기록이 아예 없는 **59곳**과 경고만 남기는 곳 가운데 필요한 곳만 한다. 지침서가 원한 「밖에서 안 보이는 catch 를 없애기」에는 이것으로 충분하다고 본다. **지침서 쪽(테스터 담당)에 이렇게 줄인다고 알려야 한다.**

### `U4ALOG.caught` 가 하는 일 (소스 확인 2026-09-29)

소스 = [ws_html5_logger.js:849](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_html5_logger.js:849)

1. 같은 오류 메시지가 몇 번째인지 센다 → 4번째부터는 500번마다 1번만 남긴다([858–870](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_html5_logger.js:858))
2. `e.stack` 에서 로그 파일 자신을 뺀 **첫 번째 자리**를 뽑는다 = 오류가 실제로 터진 `파일:줄 함수()`([_crashSite 277](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_html5_logger.js:277))
3. 한 줄로 만들어 `참고` 등급 = `console.log` 로 찍는다([897](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_html5_logger.js:897)). 줄 모양 = `[등급] [창 이름] [화면 이름] [추적 번호] 잡고 넘어감 | 오류 메시지 | thrown at 파일:줄 함수()`

`console.error(e)` 와 다른 점: ① 창 이름·화면 이름·추적 번호가 같은 줄에 붙는다 ② 터진 자리가 글자로 한 줄에 박힌다(콘솔 줄만 받는 쪽도 읽을 수 있다) ③ 반복되면 줄인다 ④ 등급이 `오류` 가 아니라 `참고` 다(빨간 줄이 아님).

(참고) `caught` 자기 안의 catch 에서도 `U4ALOG.caught` 를 다시 부른다([901](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_html5_logger.js:901)) — 로그 쓰기 자체가 계속 실패하면 자기를 계속 부를 수 있다. 보고만, 안 고침.

### `console.error` vs `U4ALOG.caught` — 실제로 어디에 무엇이 남나 (소스 확인 2026-09-29)

예: 표 칸 그리기 catch — `console.error("[U4AUI][makeDataTable] cell error:", e)` 와 `U4ALOG.caught(e)` 를 비교한다.

**앱이 두 가지 모드로 돈다** — 빌드된 exe 일 때만 `console` 을 로그 라이브러리(electron-log 4.4.8)로 바꿔 끼운다([ws_log.js:150-155](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_log.js:150)).

| | `console.error("…", e)` | `U4ALOG.caught(e)` |
|---|---|---|
| **등급** | error (빨간 줄) | `참고` = `console.log` (info) |
| **exe — 로그 파일** | 남는다. 오류 객체는 **stack 통째(여러 줄)** 로 풀려 들어간다([electron-log object.js:109-110](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/node_modules/electron-log/src/transform/object.js:109)) | 남는다. `thrown at 파일:줄 함수()` **한 줄** |
| **exe — 콘솔(= 테스터가 받는 곳)** | 나온다. 콘솔 출력 등급이 `error` 로 묶여 있어 error 는 통과([ws_log.js:104](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/js/ws_log.js:104)). 글자 한 줄에 stack 이 들어 있다 | **안 나온다** — info 는 콘솔 출력 등급(`error`)에 걸려 버려진다([electron-log log.js:37](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/node_modules/electron-log/src/log.js:37)). **테스터는 못 본다** |
| **개발 모드 — 콘솔(테스터)** | 브라우저 원래 console. 테스터는 호출 위치(= catch 줄)를 받는다([cdp-client.js:416](D:/workspace/u4a-ws-cdp-tester/lib/cdp-client.js:416)). 오류 객체는 요약된 글자로 바뀌어 stack 이 잘릴 수 있다(**미확인**) | 나온다. 「터진 줄」이 글자에 박혀 있다 |
| **추가 정보** | 없음 | 창 이름 · 화면 이름 · 추적 번호 · 몇 번째인지 |
| **반복** | 매번 찍힌다 | 3번 뒤로는 500번마다 1번 |

**정리**
- 둘 다 **흐름은 안 바꾼다**. 차이는 로그에 남는 모양뿐이다.
- `console.error(메시지, e)` 처럼 **오류 객체 `e` 를 같이 넘기는 경우**는 exe 로그 파일에 stack 이 통째로 남는다 — `U4ALOG.caught` 보다 정보가 **더 많다**.
- 반대로 exe 에서는 `U4ALOG.caught` 의 `참고` 줄이 **콘솔로 안 나가서 테스터에 안 닿는다.** 지침서의 예시 줄은 개발 모드에서 받은 것으로 보인다 — **테스터가 exe 를 돌리는지 개발 모드를 돌리는지 미확인.**
- `console.error` 가 `e.message` 만 넘기는 곳(예: [u4a-ui.js:2422](C:/Users/socce/Documents/Github/CHUNGYOON0120/U4A_WS4.0.0/www/ws30/ws10_20/theme/u4a-ui.js:2422))은 stack 이 없다 — 여기만 `U4ALOG.caught` 가 더 낫다.
